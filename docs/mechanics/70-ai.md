## 0. 為什麼這份文件優先度最高

玩家扮演的是**軍師，不是君主**。這代表：

1. **自己這一方的君主是 AI。** 玩家提建議，君主決定接不接受——
   那個「接不接受」的判斷是程式在做。這在一般 SLG 裡不存在。
2. **戰術可以委任。** 委任時整場戰鬥由 AI 指揮，而說明書明說
   「委任するのであれば統率力の高い武将を使った方が良い」——
   **統率力直接餵進 AI 的指揮品質**（§3.1）。
3. 敵對勢力的政略、外交、出兵全是 AI。

remake 要能玩、要能調難度、要做強化 AI，都得先知道原版怎麼判斷。

## 1. 君主對軍師建議的採納判斷

**這是本作最特別的一塊，說明書第 3.9 節把它整套講完了**（PDF p.16–18）。

### 1.1 君主的性格只有一個維度：好戰等級

> 君主の性格とは、**好戦レベル**という戦争のしやすさのレベルで設定されています。
> レベルが高いほど好戦的で低いほど消極的となります。
> **これは数値として表示されていません**ので、プレーヤーが進言を拒否されながら
> 予測するしかありません。

| 事實 | 等級 |
|---|---|
| 君主性格 ＝ 單一數值「好戰等級」 | 說明書 |
| **存在 `SINARIO.DAT` 勢力記錄的 `+0x28`，值域 0–15** | **confirmed** |
| **同一位君主在所有劇本裡是同一個值** | **confirmed** |
| **這個值不顯示給玩家** | 說明書 |
| 好戰等級高 → 敵對進言容易過；低 → 停戰／協力容易過 | 說明書 |
| **對手國**的好戰等級低 → 對方比較願意接受停戰／協力 | 說明書 |

「不顯示」是刻意的設計：玩家只能靠被拒絕的次數去推。
remake 若把它做成可見數值，會拿掉本作的一個核心玩法。

### 三條獨立證據

1. **說明書點名的兩個例子完全對上。**
   > 例えば、**呂布**などの場合は特に悪くない状態でも説得可能ですし、
   > **劉備**などの場合は逆にかなり悪くならないと説得できません。

   呂布 ＝ 15（全體最高），劉備 ＝ 4（偏低）。

2. **同一位君主跨劇本是常數。** 曹操在劇本 1／2／3 都是 14，
   劉備都是 4，孫權都是 7，劉璋都是 2，張魯都是 3。
   **這是個人特質該有的行為**，不是隨劇本調整的平衡值。

3. **機器碼把它當 0–15 的量表用。**
   `sub_1699E` 裡有 `mov al, 0Fh` / `sub al, [si+28h]`
   ——用 15 減它，證實上限就是 15。

排序本身也符合史觀：呂布、曹操、孫策在最上面，
劉表、劉璋、張魯、王朗在最下面，**劉禪是 0**。

### 機器碼裡的兩處用法

**`sub_1699E`**（進言指令的處理常式之一）：

```asm
mov  al, 0Fh
sub  al, [si+28h]        ; 15 − 好戰等級
shl  ax, 1 / shl ax, 1   ; ×4
mov  bx, [si+21h]        ; 資金 >> 8
cmp  bh, 80h / jnb …     ; 資金為負就跳過
and  bh, 7Fh
cmp  bx, ax / jnb …
mov  dl, 1               ; 資金 < (15 − 好戰等級) × 4 → 設旗標
```

**好戰等級越低，需要越多錢才不會被設旗標。** 消極的君主更在意國庫。

**`sub_157FE`**（在月結 `sub_15358` 裡呼叫）：

```asm
mov  ax, [bx+21h]
cmp  ah, 80h / jb ret    ; 資金 ≥ 0 → 什麼都不做
neg  ax
cmp  ax, 27h / jb ret    ; 負得不夠深 → 不做
call sub_1ECE0           ; 亂數
and  al, 0Fh             ; 0–15
cmp  al, [bx+28h] / jnb ret
…觸發事件…
```

**每月一次、資金深度赤字時、以 `好戰等級 / 16` 的機率觸發某個事件。**
事件內容（`sub_12FBF`，參數 `ax=0Dh`、`dx=196h`）還沒解，
但方向很清楚：**好戰的君主對財政崩壞更沒耐性。**

### 1.2 說服流程

1. 進言（敵對提案／停戰提案／協力外交）→ 君主可能當場同意，也可能拒絕
2. 拒絕後進入說服，**畫面上永遠給 5 個選項**
3. 玩家挑「符合當下狀況」的理由，一個一個講，直到君主同意

| 結果 | 信賴度 |
|---|---|
| 選到**不符合狀況**的理由 → 說服失敗 | **下降** |
| 說服成功 | **上升** |
| 符合的都講完了君主還是不點頭 → 用「進言撤回」收手 | **不變** |

> 最後に、ここで成功しても、**外交が成功するとは限りません**

**君主同意 ≠ 外交成功。** 這是兩段獨立的判定：
先過自家君主這關，再過對方勢力那關。

### 1.3 ⭐ 九個說服理由與各自的判定條件

這一節是整份文件裡**唯一有明確門檻**的部分，直接可實作：

| 理由 | 可用條件 | 受君主性格影響 |
|---|---|---|
| **交友關係惡い** | 勢力一覽的交友關係差 | ✅ 好戰等級高的君主門檻寬（呂布不太差就能說服，劉備要相當差才行） |
| **交友關係良い** | 上一項的相反狀態 | 同上 |
| **我が国有利** | 自勢力國力 > 對方 | ✅ 好戰等級高時，據點數少一些也算有利 |
| **敵国強大** | 交戰對手國力 > 自勢力 | ✅ 同「我が国有利」 |
| **敵が他国侵攻中** | 對象正在侵攻**第三方**勢力 | — |
| **我が国防戦中** | 正在被選定的對象侵攻 | — |
| **敵が疲弊中** | 對象處於疲弊狀態 | — |
| **我が国疲弊** | 自勢力處於疲弊狀態 | — |
| **協力国強大** | 協力勢力國力 > 自勢力 | — |
| **侵攻国強大** | 侵攻勢力國力 > 自勢力 | — |
| *進言撤回* | 隨時可用，中止說服 | 不損信賴度 |

（表列 10 項＋撤回；每次只會從中挑 5 個當選項，依指令類型而定。）

### 1.4 ⭐⭐ 兩個可直接寫成程式的定義

說明書把兩個關鍵詞用**可計算的方式**定義了，這在同類遊戲的說明書裡很少見：

> **国力の基準は拠点数からチェックされ**、好戦レベルが高い場合は
> 多少拠点数が少なくとも有利とみなします。

> **疲弊状態とは資金がマイナスの状態を指している**ため、損害の大きい軍団が
> 首都上に多数駐留している場合や、軍団の動きが少なくなった場合などから
> 予測できます。

| 名詞 | 定義 | 等級 |
|---|---|---|
| **國力** | **據點數**（不是兵力、不是資金） | 說明書（欄位 ＝ 勢力記錄 `+0x23`，confirmed） |
| **疲弊** | **資金 < 0** | **confirmed**——資金是勢力記錄 `+0x20` 的有號 24 位元，程式用 `cmp ah,80h` 檢符號位（`docs/formats/08` §1.5） |

兩條都是 remake 可以直接照抄的判定式。
「國力＝據點數」尤其重要——它決定了 AI 怎麼看待強弱，
如果 remake 改用兵力或綜合評分，整個外交行為會偏掉。

「好戰等級高時據點數少一些也算有利」是說：
比較式不是 `我方據點 > 對方據點`，而是 `我方據點 + f(好戰等級) > 對方據點`。
`f` 的實際值未知 → **反組譯的目標**。

### 1.6 原本的線索（保留）

已知的線索：`TALK.DAT` 裡有大量君主回應軍師的台詞，而且**同一個情境有多個變體**
（`docs/reference/02` §3 的 `#190`–`#198` 就是「拒絕停戰」與「准許停戰」
各三四個講法）。變體之間的差異可能對應不同的判斷分支。

已抽出的相關台詞（`translations/extract/talk-{dosv,pc98}.json`）：

| 索引 | 情境 | 內容 |
|---|---|---|
| #190–#192 | 拒絕：沒有交戰 | 「正和他國交戰？我可沒接到那種報告啊！」 |
| #193–#195 | 同意停戰 | 「現在停戰的話，就能賣個人情給{3}吧」 |
| #196–#198 | 拒絕：建議觀望 | 「若是正在和他國交戰的話，暫且再觀望一下不是比較好嗎？」 |
| #199 | 拒絕：國力充足 | 「你在說什麼！我國財政與國力都十分充足啊！」 |
| #254–#256 | 拒絕協力 | 「和{3}交戰根本不需要協助！」 |
| #257–#259 | 同意協力 | 「的確，只靠我國的話，似乎是會有些苦戰吧」 |
| #260–#262 | 猶豫 | 「軍師所言倒也有理，不過．．．」 |

**推論（假說）**：君主的回應分成「同意／拒絕／猶豫」三類，
而拒絕又依理由分支（沒有交戰、國力充足、建議觀望）。
台詞索引的分組本身就洩漏了判斷樹的形狀。

**怎麼驗**：找 `KI.EXE` 裡誰決定要顯示哪一則訊息——
把訊息索引的計算反追回去，判斷條件就在旁邊。
這是 `docs/formats/01` §7「訊息索引與遊戲事件的對應」那一項的延伸。

## 2. 外交 AI

### 2.1 停戰判定（說明書）

> 通常停戦など滅多に成功しません。これは、領地を奪うために攻め込んでいるのに
> 停戦に応じるわけは無いからです。
> そこで、他の勢力に協力してもらい、交戦中の勢力を攻めてもらいます。
> 協力が成功すれば、交戦中の勢力の侵攻が停止し、このときに停戦外交をすれば
> 成功させることも可能です。

讀出來的 AI 規則：

| 規則 | 等級 |
|---|---|
| **正在進攻中的勢力幾乎不接受停戰。** 判斷依據是「它正在為了奪取領地而進攻」 | 說明書 |
| **侵攻停止**是停戰能成功的前置狀態，不是機率修正 | 說明書 |
| 讓第三方去打它，可以使其侵攻停止 | 說明書 |

**這代表 AI 有一個「侵攻中／非侵攻中」的狀態**，而且它是停戰判定的閘門。
找出這個狀態存在哪個欄位，是解外交 AI 的入口。

### 2.2 協力判定（說明書）

> 協力外交は比較的簡単です。交友関係が良好であれば可能です。
> ただし、都合の良いときだけ外交官を送って交友関係を良くしようとしても、
> 簡単に良くなるはずがありません。
> おおよそ、半年から1年ぐらい前から準備するようにしてください。

| 規則 | 等級 |
|---|---|
| 協力的判定依據是**交友關係**（勢力對勢力的數值） | 說明書 |
| **交友關係是累積值**，外交官要駐紮半年到一年才有效 | 說明書 |
| 臨時派外交官沒有用 → 每回合的增量很小 | 強證據（由上一條推得） |

**未解**：交友關係的實際範圍、每月增量、協力成功的門檻值。

## 3. 戰術 AI（委任時）

### 3.1 統率力 ＝ AI 的指揮品質（說明書，重要）

> 基本的には、武術と統率はその合計が同じであれば強さは同じです。
> しかし、プレーヤーが戦術を指揮するのであれば武術の高い武将が良いでしょう。
> また、委任するのであれば、統率力の高い武将を使った方が良いかと思われます。
> これは、戦術では、プレーヤーの指揮次第で統率力をカバー出来るのに対し、
> 武術は武将個人の強さのため指揮ではどうにもならないからです。

| 規則 | 等級 |
|---|---|
| **武術 ＋ 統率的「和」決定基礎強度**，兩者可互換 | 說明書 |
| 玩家親自指揮 → 統率力的作用被玩家的操作取代 | 說明書 |
| **委任 → 統率力決定 AI 指揮的好壞** | 說明書 |
| 武術是武將個人戰力，指揮不能彌補 | 說明書 |

> **這一條對 remake 的 AI 設計是直接的規格**：委任 AI 的行為品質要隨統率力變化，
> 不能寫成一個固定強度的 AI。**統率力低的武將委任時應該打得比較差**，
> 這是原版明講的設計意圖。
>
> **但「怎麼變差」還完全未解。** 是決策頻率、判斷正確率、還是可用戰術的多寡？
> 反組譯時要特別找統率力這個欄位被讀取的地方。

### 3.2 敵方 AI 的部署習慣（說明書）

> **中央突破**：これは、統率力の高い武将に対抗する方法です。
> 統率力の高い武将は武将自身はあまり強くありません。
> ですから、**通常後方に待機しています**。これを直撃し退却させるのがねらいです。

| 規則 | 等級 |
|---|---|
| **統率力高的武將，AI 通常部署在後方待機** | 說明書 |
| 主將被直擊 → 退卻 | 說明書 |

這是 AI 部署規則的直接描述：**依統率／武術的高低決定站位**。

### 3.3 陣形命令的 AI 行為（說明書）

> 陣形命令では、**接した敵しか攻撃しません**ので、
> 陣形のまま迎え打つと各個撃破されてしまいます。

| 規則 | 等級 |
|---|---|
| 下「陣形」命令時，部隊**只攻擊已接觸的敵人**，不會主動接敵 | 說明書 |
| 因此純守陣形會被各個擊破 | 說明書 |

這是玩家指令的語意，但同一套邏輯很可能也用在 AI 部隊上。**未驗。**

### 3.4 其他戰術判定（說明書）

| 項目 | 內容 | 等級 |
|---|---|---|
| 突擊時機 | 與敵衝突的**直後**是攻擊時機 | 說明書 |
| 陣形有利不利 | 敵方兵力集中於一處時，其**正面若薄弱**就容易被擊破 | 說明書 |
| 擊破狀態 | 突進到對方畫面端的狀態。此時**敵方新手出陣後會立刻被攻擊**，兵力急遽減少 | 說明書 |
| 中央突破戰法 | 取窄陣形 → 配合敵方攻擊把陣形線改到最上方 → 少數兵可從敵陣間穿過 | 說明書 |

## 3.5 ⭐ 說明書第 11 章順帶暴露的戰術 AI 行為

攻略章教玩家怎麼贏，而每一條「怎麼贏」都建立在
**AI 會做某件可預測的事**上。這是目前對戰術 AI 最扎實的一批線索：

| AI 行為 | 出處 | 玩家怎麼利用 |
|---|---|---|
| **疲勞到一定程度就後退，然後重新擺陣** | 11.5 追擊 | 趁它重整陣形前壓上去 |
| **把高統率武將放在後方** | 11.4 中央突破 | 用窄陣形＋陣形線拉到最上方鑽過去直取主將 |
| **會主動前進壓迫** | 11.6 回り込み | 在反方向擺同寬窄陣，等它前進時交換位置關係 |
| **城牆守軍會朝射擊來源集中** | 11.7 誘餌 | 弓隊留一側吸引，步兵從另一側登牆 |

前三條合起來描述了一個**有明確狀態機**的戰術 AI：

```
壓迫前進 → 接戰 → 疲勞累積 → 後退 → 重新擺陣 → 壓迫前進
```

**這個循環有一個固定的空窗期**（後退到重新擺好陣形之間），
而說明書直接把它當成教學內容寫出來。
remake 若要做「忠實的原版 AI」，這個循環就是骨架；
若要做「強化 AI」，第一件事就是消掉這個空窗。

第四條（守軍朝射擊來源集中）是**沒有全局視野的證據**：
AI 對威脅的反應是局部的、反應式的，不會判斷「這是誘餌」。

### 這也給了 AI 強度的量尺

說明書 10.5 節說玩家的指揮可以「cover 統率力」，
而委任時要用統率高的武將（`60-personnel.md` §2）。
換句話說：**原版承認 AI 指揮 ≈ 某個等效統率值**。
用委任 vs 玩家指揮打同一場戰鬥，就能量出那個值。→ 可驗證的實驗設計

## 3.9 ⭐ 在野武將的仕官邏輯（confirmed，`sub_15899`）

這是目前**唯一一條完整讀出來的政略 AI 規則**，而說明書一個字都沒提。

每個月，每個在野武將（所屬勢力欄位 ＝ `0xFF`）都會考慮投靠：

| 規則 | 證據 |
|---|---|
| 優先投靠**武將數最少**的勢力 | 掃 22 個勢力找 `[di+18h]` 最小者 |
| 投靠玩家勢力的條件：**玩家武將數 < 據點數 ÷ 4 + 1** | `mov al,[bx+23h]` / `shr` ×2 / `inc al` / `cmp al,[bx+18h]` |
| 加入玩家勢力時會跳訊息 | `sub_18810(al=93h, cx=29h)` |

**它同時是兩件事**：

1. **扶弱的平衡機制**——武將少的勢力優先補人，防止強者恆強。
2. **對玩家的節流閥**——據點少的時候招不到人（4 個據點才准多一個武將），
   逼玩家先擴張再談養士。

remake 若把它做成「隨機投靠」或「投靠最強者」，
中後期的勢力分佈會完全不同。

## 3.10 AI 的募兵節制（`sub_15456`）

月結時，AI 勢力會把自己所有軍團的兵力加總，與當月收入比較，
超過就**停止募兵**（`docs/re/07` §8）。

AI 也不使用稅率欄位，收入固定除以 2（等於稅率 50%），
而且**稅率對上昇值的修正只套用在玩家的據點**——
所以 AI 的據點不會因為稅率而荒廢。**這是原版給 AI 的一層簡化**，
remake 若要做「公平的 AI」得自己補上這一塊。

## 3.11 ⭐ 財政撐不住就自動取消侵攻（confirmed）

每小時輪到一個勢力時（`docs/re/08` §1）：

```
若 資金 >> 8 < 據點數 × 8 + 24  →  侵攻目標（勢力 +0x19）設成 0xFF
```

**這是原版政略 AI 的一條硬性煞車**，而且門檻與**據點數**掛鉤——
地盤越大，維持一場侵攻需要的最低資金越高。

它同時解釋了說明書那幾個說服理由為什麼有用：

| 說服理由 | 底層是什麼 |
|---|---|
| 敵が他国侵攻中 | 查對方的 `+0x19` 指向第三方 |
| 我が国防戦中 | 查對方的 `+0x19` 指向我方 |
| **敵が疲弊中** | 對方資金 < 0 → **早就低於門檻，侵攻已經自己停了** |

所以「趁敵人疲弊時提停戰」不只是說明書的建議，
**是因為疲弊的敵人在機制上已經停止侵攻**，而停戰的成立條件正是
「對方沒有正在侵攻我方」（`50-diplomacy.md` §8）。三條規則咬在一起。

## ⭐ 侵攻的循環：每月 25% 起意，每小時檢查養不養得起

兩端都在機器碼裡讀出來了：

| 階段 | 位置 | 規則 |
|---|---|---|
| **起意** | `sub_12D3A`（月結，`docs/re/07` §20） | 勢力**沒有**侵攻目標（`+0x19 == 0xFF`）時，`rand(0..255) < 64` → **25%** 機率發事件 8 |
| 選目標 | `sub_12E33`／`sub_13526`／`sub_135AB` | 把目標勢力編號填進 `+0x19` |
| **取消** | `sub_13E11`（每小時，`docs/re/08` §1） | `資金 >> 8 < 據點數 × 8 + 24` → `+0x19` 清回 `0xFF` |

所以 AI 的侵攻是一個**起意／破產**的循環，而不是一次性的決定。

### 這解釋了說明書的「敵が疲弊中」

說明書把「敵人疲弊中」列為提停戰的好時機。機制上的理由是：

**疲弊（資金為負）的敵人剛被取消侵攻，而且要等到下個月結才有 25% 的機會再起意。**
換句話說那是一個有明確長度的空窗，不是模糊的「他比較弱」。

⚠ 起意的機率是**每月每勢力**，不是每天。22 個勢力全部沒有目標時，
一個月期望有 5.5 個勢力起意。

## ⭐⭐ 交友度的每月漂移：世界會慢慢與玩家為敵

`sub_12D58`（月結，每勢力跑一次）的第一步就分岔：

```asm
cmp si, cs:word_10CFD     ; 這個勢力是玩家所仕的嗎
jz  .player
call sub_12DB8            ; 其餘勢力
jmp .rest
.player:
call sub_12DF3            ; ★ 玩家的勢力走另一支
```

兩支的行為**不對稱**，而且不對稱的方向對玩家不利。

### AI 之間：`sub_12DB8`

拿 `sub_1310A` 取得交友度[si][di] 的位址（它把 `sub_13119` 呼叫兩次並互換
si／di，所以 `bx` 是我方看對方、`dx` 是對方看我方），然後：

| 狀態 | 變化 | 邊界 |
|---|---|---|
| **和平**（最高位元 1） | 每月 **−2** | 下限 **20** |
| **交戰**（最高位元 0） | 每月 **+1** | 上限 **50**，且**對象是玩家時不加** |

> 交戰反而讓交友度上升，看起來反直覺，但那正是**厭戰**：
> 打久了雙方都比較願意接受停戰。配上「和平會衰減」，
> 兩者一起產生**戰和交替的循環**，而不是一鎖定就永久不變。

### 對玩家：`sub_12DF3`

```asm
mov di, es:[di] / cmp di, 0FFFFh / jz .1     ; 這個月評估的對象
mov al, 1 / call sub_130F0                   ; 交友度 −1
cmp bh, 80h / jnb .1
mov al, 7 / call sub_130F0                   ;   若交戰中，再 −7
.1:
mov di, cs:word_10CFD                        ; di ← 玩家勢力
mov si, 0 / mov cx, 16h
loop: cmp si, di / jz .next
      cmp byte ptr [si], 80h / jb .next
      mov al, 1 / call sub_130F0             ; ★ 每個勢力對玩家 −1
.next: add si, 40h / loop
```

**每個月，所有活著的勢力對玩家的交友度都 −1**（`sub_130F0` ＝ 交友度減 N、
保留和戰旗標、下限 0）。與交戰中的對象另外再 −7。

| | AI ↔ AI | 任何人 → 玩家 |
|---|---|---|
| 和平時 | −2（下限 20） | **−1，無下限（到 0）** |
| 交戰時 | **+1**（上限 50） | **不加**，而且再 −7 |

**所以世界會單調地與玩家為敵。** 玩家沒有「打久了對方就願意談」這條路，
只能靠外交官把交友度推回去（`sub_13E8E`，每小時 12.5% 動作率、
成功條件 `rand(0..15) ≤ 政治`）。

> 這解釋了說明書為什麼把外交官講得那麼重要，也解釋了停戰與協力
> 都要求「該勢力裡有我方外交官」——**沒有外交官的話，
> 交友度只會往下走**。

### 國力評分：`sub_13091`

```asm
ax = ([bx+4] + [bx+6] + [bx+8]) >> 2        ; 預備兵三種各 ÷4 再相加
cmp ah, [bx+23h] / jb .1 / mov ax, 7D0h     ; 與據點數比較
.1: cmp ax, 7D0h / jbe .2 / mov ax, 7D0h    ; 上限 2000
.2: cmp word ptr [bx+21h], 13h              ; 與資金 >> 8 比較
```

**國力 ＝ 預備兵（騎馬＋弓兵＋步兵）÷ 4，上限 2,000**，再依據點數與資金修正。
`sub_12E89` 拿它逐一比對候選對象——**AI 挑侵攻目標是比國力的**，
細節（挑最強還是最弱）還沒讀完。

## ⭐⭐ AI 什麼時候求和：鄰居的合計國力超過自己

`sub_12D58` 的最後一段（`sub_12E89`）。**玩家的勢力直接跳過**（`cmp si, word_10CFD / jz`）。

### 第一步：建鄰接勢力清單（`sub_12C52` → `sub_12CDF`）

掃 192 個據點，對屬於自己的每一個，用據點記錄的
`+0x00` 低 4 位 ＋ `+0x1C`–`+0x1F`（`docs/formats/08` §4.1）
查出四個鄰接據點各屬於誰，**去重**後寫進該勢力那塊 0x30 的緩衝區：

```
+0      有中立鄰居時寫 0x600（＝ 勢力 24 ＝ 中立的記錄位址）
+2 起   鄰接勢力的記錄位址（勢力編號 × 64），0xFFFF 結尾
```

### 第二步：累減國力（`sub_12E89`）

```asm
call sub_13091 / mov dx, ax        ; dx ← **自己**的國力
mov cl, 15h                        ; 最多 21 個鄰居
.loop:
  bx = es:[di]
  cmp bx, 0FFFFh / jz 結束          ; 清單到底
  cmp bh, 80h / jb 結束              ; 沒有標記的不處理
  and bh, 7Fh / call sub_13091      ; ax ← 這個鄰居的國力
  sub dx, ax                        ; ★ 累減
  jbe .撐不住                        ; ★ 減到 ≤ 0
  di += 2 / dec cl / jnz .loop
.撐不住:
  對**剩下的每一個**鄰居發事件 3
```

**判準不是「誰比我強」，是「他們加起來比我強」。** 這是很關鍵的差別——
單一鄰居再強都可能忍，但被三家包夾就會開始求和。

### 第三步：事件 3 ＝ 停戰提案

事件 3 的處理端是 `sub_13262`（`funcs_131E8[2]`，`docs/re/07` §18）。
對象是玩家時顯示訊息 `0x2B` ＝ **43**：

> 「{3}との停戦交渉の結果、無条件で成立しました。」
> 「與{3}停戰交涉的結果，無條件地達成了。」

**訊息文字直接把事件 3 定名為停戰。** 這比從程式流程推更硬——
`docs/formats/08` 的事件代碼表可以補上這一列。

### 國力的定義（`sub_13091`）

```
國力 = (預備兵騎馬 + 預備兵弓兵 + 預備兵步兵) ÷ 4，上限 2,000
       再依據點數（+0x23）與資金（+0x21）修正
```

⚠ **是預備兵不是總兵力**——已經編成出陣的軍團不算。
所以一個把兵全部編出去打仗的勢力，在 AI 眼中會顯得很弱。

### 還沒讀的

`es:[di]` 的最高位元（`cmp bh, 80h`）是誰設的。`sub_12CDF` 存進去的是
乾淨的 `勢力編號 × 64`（`bh` 只有 0–5），所以**標記是後面某一支加上的**——
`sub_12E33`／`sub_12E89` 之間還有一段沒追。

## ⭐⭐ AI 什麼時候找玩家協力：`sub_12E33` 的四道閘

同樣在 `sub_12D58` 的鏈上，發的是**事件 2**。四道閘全過才發：

```asm
dh = [si+19h]                    ; 這個勢力的侵攻目標
cmp dh, 0FFh      / jz ret       ; ① 沒有侵攻目標 → 不做
cmp dh, byte_10CFF/ jz ret       ; ② 目標就是玩家所仕的勢力 → 不做
ax = word_10CFD                  ; 玩家的勢力記錄
.find: cmp ax, es:[di] / jz .ok  ; ③ 玩家**在不在**這個勢力的鄰接清單裡
       cmp es:[di], 0FFFFh / jz ret     ;    不在 → 不做
       di += 2 / jmp .find
.ok:
di = ax / call sub_130CB
cmp al, 80h  / jb ret            ; ④a 交友度[AI][玩家] 的**和平位元**要設著
si = 侵攻目標 / call sub_130CB
cmp al, 0A3h / jb ret            ; ④b 交友度[目標][玩家] ≥ 0xA3
mov al, 2 / call sub_12FB1       ; 發事件 2
```

`sub_130CB` ＝ `sub_13119` ＋ `mov al, [bx]`，取的就是交友度矩陣的那一格
（`docs/formats/08` §1.55），**最高位元 1 ＝ 和平**。所以：

| 閘 | 條件 |
|---|---|
| ① | AI 已經有侵攻目標 |
| ② | 那個目標**不是**玩家 |
| ③ | 玩家與這個 AI **相鄰**（在 `sub_12CDF` 建的鄰接清單裡） |
| ④a | AI 與玩家**和平中** |
| ④b | **侵攻目標**與玩家和平中，且交友度 **≥ 35**（`0xA3` ＝ `0x80 | 35`） |

### 事件 2 ＝ 協力要請

處理端 `sub_13220`（`funcs_131E8[1]`），對玩家顯示訊息 `0x2F` ＝ **47**：

> 「{3}との協力交渉の結果、無条件で成立しました。」
> 「與{3}的合作交涉的結果，無條件成立了。」

**又是訊息文字定名。** 兩個事件用同一招定下來（事件 3 ＝ 停戰、事件 2 ＝ 協力），
而且與說明書 §7 列的三個外交指令對得上。

### ⚠ 第 ④b 道閘的意圖沒解

它要求**被打的那一方與玩家關係好**（≥ 35 且和平）才會來找玩家協力。
直覺上反過來比較合理（找你打你討厭的人）。可能的讀法：

- 找你去背刺一個對你友善的對象，本來就是這個系統要製造的兩難；
- 或者「目標與玩家關係好」代表玩家對它有影響力，拉進來才有價值。

**兩種都沒有證據。** 機制照抄，意圖標未解——
與 `seg000:B5B7` 那個「語意存疑但機制確定」同一種處理
（`internal/rules/tactical/structure.go`）。

## ⭐⭐⭐ 那個 0x8000 標記 ＝ 交戰中，而且鄰接清單是**排序過的**

`docs/re/07` §20 記著一個懸案：鄰接清單裡 `es:[di]` 的最高位元標記是誰設的
（`sub_12CDF` 存進去的是乾淨的 `勢力編號 × 64`）。答案在 `sub_12C52` 的後半段
——**它不只是建清單，還把清單排序**。

```asm
bx = si>>2 ; ax = bx ; bx >>= 1 ; bx += ax ; bx += 600h
                                 ; bx ← 0x600 + 勢力編號 × 24（交友度矩陣的第 si 列）
bp = 清單起點 ; cx = 1515h        ; cl = ch = 21（最多 21 個鄰居）
.外圈:
  cmp word ptr es:[bp], 0FFFFh / jz 結束
  si = bp ; dl = 0FFh            ; dl ← 目前掃到的**最小**交友度
  .內圈:
    di = es:[si]
    cmp di, 0FFFFh / jz .下一輪   ; 清單到底
    ax = di & 0x7FFF ; ax <<= 2 ; al = ah    ; al ← 勢力編號
    xlat                                     ; al ← 交友度[自己][該勢力]
    cmp dl, al / jbe .繼續        ; 不比目前的小 → 跳過
    dl = al
    cmp al, 80h / jnb .不打標記
    or  di, 8000h                ; ★ 交友度 < 0x80 → **打上交戰標記**
  .不打標記:
    xchg di, es:[bp]             ; 換到清單最前面
    if si != bp: es:[si] = di
  .繼續: si += 2 / dec cl / jnz .內圈
  dec ch / bp += 2 / cl = ch / cmp ch,1 / jnz .外圈
```

兩件事一次解掉：

1. **`0x8000` ＝ 與這個鄰居交戰中。** 判準就是交友度的最高位元沒設
   （`< 0x80`），與 `sub_130CB` 那一套一致。標記是在排序時順手打上的。
2. **這是一個選擇排序，key 是交友度，由小到大** ——
   **最敵對的鄰居排在清單第一筆**。

`sub_12E89`（求和）先前記著「`cmp bh, 80h / jb 結束` ——沒有標記的不處理」，
現在知道那句話的意思是**只把交戰中的鄰居算進威脅總和**，
而且因為清單已排序，交戰中的一定聚在前面，`jb` 一碰到和平的就可以收工。
**那不是提前結束的最佳化，是正確性的一部分。**

### 侵攻目標每小時被重新檢查一次

`sub_12D58` 的尾段（`docs/re/07` §20 沒讀完的那一段）：

```asm
cmp byte ptr [si+19h], 18h / jz .清掉    ; 目標是中立 → 交給 sub_12F71 那條路
mov ax, es:[di]                          ; ★ 排序後的**第一筆**
cmp ah, 0FFh / jz .清掉                  ; 清單空
cmp ah, 80h  / jb .清掉                  ; ★ 第一筆沒有交戰標記
and ah, 7Fh / shl ax,1 / shl ax,1
cmp ah, [si+19h] / jz ret                ; 第一筆的勢力 == 侵攻目標 → 保留
.清掉: mov byte ptr [si+19h], 0FFh
```

**AI 的侵攻目標必須是「排序後最敵對的那個鄰居」，否則每小時就被作廢一次。**
換句話說 AI 不會記仇記到別人身上——它永遠打當下交友度最低的鄰居。

> ⚠ 對 remake 的意義：目標選擇**不能做成持久狀態**。
> 存起來的 `+0x19` 只是快取，真正的判準是「每小時重算一次的最敵對鄰居」。

## ⭐⭐ AI 什麼時候決定出兵：三道閘（`sub_12EFB`）

排在求和之後跑，對象就是清單第一筆（最敵對的鄰居）。

```asm
ax = es:[di] & 0x7FFF ; ax <<= 2
cmp ah, [si+19h] / jz 不做           ; 已經在打它了 → 什麼都不用做
ax = [si+23h] << 4 + 40h             ; 據點數 × 16 + 64
cmp ax, 61Ah / jbe .1 / ax = 61Ah    ; 上限 1562
.1: cmp ax, [si+21h] / jge 不做      ; ① 資金閘
bl = [si+28h] ; bl += bl>>1 ; bl += 14h ; bl |= 80h
call sub_130CB / cmp al, bl / ja 不做 ; ② 交友度閘
call sub_13091(自己) → cx
call sub_13091(對方) → ax ; ax -= ax>>2
cmp cx, ax / jb 不做                  ; ③ 國力閘
發事件 1（dl ＝ 目標勢力編號）
```

| 閘 | 條件 | 用到的欄位 |
|---|---|---|
| ① 資金 | `資金 >> 8` **＞** min(據點數 × 16 ＋ 64, 1562) | `+0x20` i24 資金、`+0x23` 據點數 |
| ② 交友度 | 交友度[我][它] **≤** `0x80` ＋ 20 ＋ 好戰等級 × 1.5 | `+0x28` 好戰等級 0–15 |
| ③ 國力 | 自己的國力 **≥** 對方國力 × 3/4 | `sub_13091` |

⭐ **好戰等級直接放寬交友度閘。** 好戰 0 的君主要交友度 ≤ 20 才出兵，
好戰 15 的要 ≤ 42（`0x80 + 20 + 22`）——**好戰的君主連關係普通的鄰居都打**。
這是 `+0x28` 迄今最具體的一條效果。

⭐ **③ 不是「比對方強」，是「不比對方弱太多」。** 打八折的門檻代表
AI 願意打一場國力相當、甚至略遜的仗。配合「國力只算預備兵」
（已編成出陣的不算），**一個把兵派出去的鄰居在 AI 眼中會突然變成軟柿子**。

### 打不成勢力，才考慮打中立（`sub_12F71`）

`sub_12EFB` 用 CF 回報：成功發事件回 `clc`，`sub_12D58` 就 `jnb` 跳過中立那條路。
**打勢力的優先度高於併吞中立據點。**

```asm

cmp word ptr es:[di-2], 0FFFFh / jz .清掉  ; 緩衝區 +0 ＝ 有沒有鄰接中立據點
ax = [si+23h] << 4 + 60h ; 上限 6DDh
cmp ax, [si+21h] / jge .清掉               ; 資金閘（門檻比打勢力**高**）
cmp byte ptr [si+19h], 18h / jz ret        ; 已經在打中立 → 不重複發事件
發事件 1（dx ＝ 0FF18h，目標 ＝ 24 ＝ 中立）
```

**打中立的資金門檻比打勢力高**（`+0x60` vs `+0x40`，上限 1757 vs 1562）。
反直覺——無主據點理應更便宜——但兩個常數都是直接讀出來的，**照抄不修正**。
（緩衝區 `+0` 的 `0x600` 旗標是 `sub_12CDF` 寫的，見上一節。）

## 事件 1 ＝ 宣戰／設定侵攻目標

## ⭐⭐ `sub_16A3D` ＝ 選新首都，事件 8 ＝ 遷都

先前把事件 8 記成「該挑侵攻目標了」。**錯了**，而且錯在同一個老地方：
`cmp al, [si+1]` 比的是**據點的擁有者**，掃的是**自己的據點**，
不是候選目標。（`+0x01` ＝ 所屬勢力，`docs/formats/08` §1.6。）

```asm
cx = 192 ; si = 840h（據點表）; dx = 0 ; bl = 0FFh ; bh = 0 ; di = 0FFFFh
.loop:
  cmp al, [si+1]      / jnz .next     ; 只看自己的據點
  ah = [si+16h] & 0Fh
  cmp bl, ah          / jb  .next     ; ★ 取**最小**的據點類型
  cmp dx, [si+0Eh]    / ja  .next     ; ★ 取**最大**的生產力
  and bh, bh / jnz .測旗標
  bl = 類型 ; dx = 生產力 ; di = si   ; 先無條件記下
.測旗標:
  test byte ptr [si], 1Fh / jnz .next ; 鄰接遮罩要是 0
  bh = 1 ; bl = 類型 ; dx = 生產力 ; di = si
.next: si += 20h / loop
回傳 ax = 據點記錄位址，CF ＝ 一個都沒有
```

⚠ **不要把它讀成「先比類型再比生產力」的排序。**
兩個條件是**同時**檢查的，而且門檻邊掃邊更新——
一個生產力很高的小城會把它**後面**所有大城擋掉（大城過得了類型那關，
過不了生產力那關）。同一組據點換個順序，結果會不一樣。

寫成 Go 時這件事差點被「整理」掉：測試
`TestPickKindWinsOnlyWhenProductionAlsoWins` 用兩組只差順序的資料
把它釘住了（`internal/rules/capital`）。第一版的測試名字叫
「小城生產力再高也贏不了大城」，**跑出來是反的**——
那是我對演算法的期待，不是演算法。

### 事件 8 ＝ **主動**遷都，而且處理端是掉進去的

（`0x000`–`0x3FF`，4 B 一筆）找有沒有「玩家勢力 → 這個目標」的事件 1；
有的話代表**自家勢力的 AI（`sub_12EFB`）早就決定要打它了**，
所以君主才說「我也有同樣的想法」。**這不是巧合，是同一個變數的兩端。**

### 反應碼 2：君主問「理由是什麼」，而理由要**符合事實才能選**

`dl` 用 `or dl, 10h` ＋ `shr dl, 1` 各四次組出四個位元，
順序正好是訊息 #102 那個選單的前四項：

```
外交關係惡劣 │ 我國較有利 │ 敵正侵攻他國 │ 敵勢力疲乏 │ 撤回進言
```

| 位元 | 選項 | 可用條件 |
|---:|---|---|
| 0 | 外交關係惡劣 | 交友度 < 好戰等級 ＋ 15 |
| 1 | 我國較有利 | **玩家據點數 × (好戰 ＋ 20) > 目標據點數 × 25**（`sub_16A28`） |
| 2 | 敵正侵攻他國 | 目標的 `+0x19` 不是 `0xFF`、也不是玩家 |
| 3 | 敵勢力疲乏 | 目標的資金 < 0（疲弊狀態） |

**軍師不能亂講。** 四個理由都是對客觀狀態的斷言，不成立的選項不會給你選。

> ⭐ 好戰等級在這一條鏈上出現**三次**，係數各不相同：
>
> | 用途 | 式子 | 出處 |
> |---|---|---|
> | AI 自己決定出兵 | 交友度 ≤ `0x80` ＋ 20 ＋ 好戰 × 1.5 | `sub_12EFB` |
> | 君主接受進言 | 交友度 < 好戰 × 2 ＋ 20 | `sub_16475` |
> | 「我國較有利」成立 | 我方據點 × (好戰 ＋ 20) > 敵方據點 × 25 | `sub_16A28` |
>
> 第三條的平衡點在**好戰 ＝ 5**：低於 5 的君主覺得自己比較弱。
> 劉禪 0、劉表 1、劉備 4 都在平衡點以下，曹操 14、呂布 15 遠在其上。

## 宣戰的收尾：兩支先前只知道名字的常式

### `sub_13639` ＝ 開戰時交友度怎麼算

```asm
cmp al, 18h / jz ret ; cmp ah, 18h / jz ret   ; 任一方是中立 → 不做
call sub_13697                                 ; 取兩個方向的位址
cl = [si+600h]                                 ; 交友度 A→B
ch = [bx+600h]                                 ; 交友度 B→A
cmp cl, ch / jbe .1 / cl = ch                  ; ★ 取**較小**的那一個
.1: and cl, 7Fh                                ; ★ 清掉和平位元 → 進入交戰
    shr cl, 1                                  ; ★ 砍半
    [si+600h] = cl / [bx+600h] = cl            ; ★ 兩個方向寫成同一個值
```

三件事：

1. **交戰狀態是對稱的。** 交友度平時有方向性（`docs/mechanics/50-diplomacy.md`），
   但開戰那一刻兩邊會被寫成同一個值。
2. **關係差的那一方決定結果**（取 min）。
3. **開戰讓交友度砍半**，而月結的厭戰每月只 +1
   ——**戰爭造成的裂痕要幾十個月才補得回來**。

順帶：`+600h` 這個立即值**獨立確認了交友度矩陣的基址是段內 `0x600`**，
與從 `sub_12C52` 的 `xlat` 表基底推出來的一致（兩條路殊途同歸）。

### `sub_135AB` ＝ 被打的一方會不會回頭打你

```asm
cmp dl, byte_10CFF / jz ret     ; 目標是玩家 → 不做
cmp dl, 18h        / jz ret     ; 目標是中立 → 不做
ah = [目標+19h]                  ; 目標**現在**的侵攻目標
cmp ah, 24h / jnb .設定          ; 0FFh（無目標）→ 直接設定
cx = sub_13091(我)               ; 我的國力
ax = sub_13091(它現在的目標)
cmp ax, cx / jnb ret             ; ★ 它現在的目標**不比我弱** → 不換
.設定: [目標+19h] = 我的勢力編號
```

**AI 被宣戰時會回頭把你設成侵攻目標——除非它手上的獵物更軟。**
軟柿子先吃。

> ⚠ `cmp ah, 24h` 的 `0x24` ＝ 36 這個門檻沒解。有效勢力編號是 0–21，
> 中立是 24（`0x18`），兩者都 < 36 → **中立會走進國力比較**，
> 而中立沒有真正的勢力記錄（`24 × 64 = 0x600` 正好是交友度矩陣的起點），
> 於是 `sub_13091` 會把交友度那幾個 byte 當成預備兵讀。
> **這是原版的越界讀**，行為固定但沒有意義。remake 照抄會很奇怪，
> 這一格標成 remake 差異：中立不參與這個比較。

### `sub_14502` ＝ 遷都時同步軍團的欄位

兩個遷都路徑（`sub_14DF0` 與事件 8）都在寫回首都之後呼叫它。
掃 127 支軍團，只動屬於這個勢力、而且存在旗標 ≥ `0x80` 的：

```asm
cmp ah, [si+20h] / jnz .next     ; 軍團 +0x20 ＝ 舊首都？
mov [si+20h], al                 ; → 改成新首都
cmp [si+14h], cx / jnz .next     ; 軍團 +0x14（目標×8）＝ **新**首都×8？
mov [si+14h], dx                 ; → 改成**舊**首都×8
or  byte ptr [si], 2             ; 設旗標 bit 1
```

第一段語意清楚：**軍團的本據地（`+0x20`，編成時寫的就是首都）跟著遷都走**。

> ⚠ **第二段的方向是反的，沒解。** 第一段把舊換成新，第二段卻是
> 「目標是新首都的，改成舊首都」。單一次的暫存器對調，
> 是真 bug 最常見的形狀——但也可能有意圖（把正要去新首都的軍團叫回去？）。
> **沒有證據，兩種都不排除。** remake 先照抄，並在這裡留記號。
