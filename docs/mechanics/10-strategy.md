### 1.1 指令列的幾何與點選機制（confirmed）

指令列是八個等距的按鈕，第 n 個（n 由 0 起）的左上角 x ＝ `24 + 48n`，
寬 40、高 16，整條佔 x 24–408。畫面是 640×400。

點選不靠鍵盤，也不是逐一比對按鈕矩形：遊戲維護一張**熱區圖**，
每個 8×8 像素格對應一個 byte，記著「這一格屬於哪個可點區域」。
按下左鍵時用游標座標查這張圖拿到熱區編號，再減去該畫面的基底當索引分派。
指令列則另走一條更省的路——直接把游標的 x 減 24 再除以 48。

這解釋了兩件事：

- **整個戰略層沒有鍵盤路徑。** `KI.EXE` 在沒有滑鼠驅動時直接報
  `ERROR: Mouse driver not install ?` 就是這個緣故，與說明書「只寫左鍵右鍵」
  和 oracle 實測「對話框完全不吃鍵盤」（`docs/playtest/04`）三者一致。
- **視窗可以任意重疊而不必重算命中判定**，因為判定的真相在熱區圖上，
  畫面重繪時一併更新即可。

八個指令各自的分派路徑、子選單項數與狀態列提示訊息，
見 [`../re/22-strategy-command-tree.md`](../re/22-strategy-command-tree.md)。

> remake 目前用鍵盤操作戰略層（`A` 編成、`M` 選軍團、`=` 行軍）。
> 這是既有的 **remake 差異**，不是原版行為。

## 2. 進言（玩家不是君主）

**臥龍傳的玩家扮演軍師。** 戰略指令不是直接執行，
而是「向君主提議」，君主可能拒絕。被拒絕後可以說服。
說服系統的完整規則與判定門檻見 `70-ai.md` §1。

| 指令 | 說明 | 前置條件 |
|---|---|---|
| **敵對提案** | 從一覽表選要敵對的勢力 | — |
| **停戰提案** | 與現在敵對中的勢力停戰 | **該勢力裡要有我方外交官** |
| **協力要請** | 選協力勢力，再選要它去打的勢力 | 目標須與自勢力交戰中；不可與協力勢力交戰中；**協力國裡要有我方外交官** |
| **遷都** | 更換首都據點 | **只能遷到生產力比現在高的據點** |
| **君主出陣依賴** | 請君主親自出陣 | 君主出陣期間**所有進言指令都不能用** |

「君主出陣中不能進言」是一個明確的取捨：
派君主上前線換取戰力，代價是整個外交與政略停擺。

## 3. 其餘七個指令

### 人事

| 內政官任命 | 先選據點，再選武將 |
| 內政官解任 | |
| 外交官任命 | 先選勢力，再選武將。停戰與協力都靠它 |
| 外交官解任 | |

**外交官是派駐到「勢力」的，內政官是派駐到「據點」的。**

### 財政

視窗裡四個綠色按鈕，用小算盤輸入數值，由上而下：

1. **稅率**
2. **騎馬募兵數**
3. **弓兵募兵數**
4. **步兵募兵數**

> ここにセットされた値は**来月末**より使用されます

**設定值延遲到次月末才生效**（`15-realtime.md` §4）。

視窗同時顯示資金、收入、支出，以及「今月末」與「來月」兩欄對照。

### 編成

選武將 → 出現部隊編成視窗 → 用綠色按鈕設定各部隊兵種 → 決定。

| 事實 | 等級 |
|---|---|
| **每支部隊固定 1000 人** | 說明書 |
| 預備兵不足時**自動平均分配** | 說明書 |
| 編成好的軍團出現在**首都上** | 說明書 |

編成視窗顯示：將軍、總兵力、士氣值、六個編成位置、三種預備兵數。

#### 六個編成位置（confirmed，PDF p.13 以 400 dpi 重掃判讀）

| 位置 | 日文 |
|---|---|
| 1 | **大將** |
| 2 | **先鋒** |
| 3 | **左翼** |
| 4 | **右翼** |
| 5 | **左備** |
| 6 | **右備** |

是日式陣形的標準六位編制。每格各放一支 1000 人的部隊，
所以滿編 ＝ 6 × 1000 ＝ **總兵力 6000**（截圖上的許褚正是滿編）。

每格左邊有一個兵種圖示，玩家用綠色按鈕切換該格的兵種
——**編成 ＝ 決定六個位置各放哪一種兵**。
說明書第 11.2 節「陣形の有利不利」講的就是這六格的配置優劣，
那一節還沒讀。

截圖上士氣值 ＝ 200（滿編 6000 人時），預備兵三種分別 1000／3000／7000。

## 4. 軍團移動

1. 游標對準軍團左鍵
2. 若在據點上，會先問「要選據點還是軍團」
3. 從該座標的軍團一覽選一支
4. 點目的地據點 ——「**此狀態下除了縮小地圖以外都不能點**」
5. 出現目的地名稱與兩個選項：

| 選項 | 意思 |
|---|---|
| **戰鬥指揮** | 進戰術畫面，玩家親自指揮 |
| **委任** | 自動打完，不進戰術畫面 |

6. 目的地是首都時多一個「**解體**」，可解散軍團
7. 下完一支會回到一覽表，可連續對其他軍團下令；要結束就在一覽表狀態取消

## 5. 一覽表的通用操作

所有一覽表共用**同一個引擎**，只換四個 callback：清單有五種（軍團、據點、
武將、勢力、開局選勢力），視窗一律開在 `(24, 88)`、384×176 像素
（`../re/26` §2）。指令列的「武將」「勢力」與人事／外交用的是同一種清單的
**兩種取法**——前者是看（顯示表上沒列的參數），後者是選。

五種清單的欄位（取自 `KI.EXE` 的標題字串，`../re/26` §4.1）：

| 清單 | 欄位 |
|---|---|
| 軍團 | 武將名／總兵數／士氣值／現在位置／目標據點 |
| 據點 | 據點名／生產力／上昇率／防災／城兵／內政官 |
| 武將 | 武將名／武術／統率／政治／勢力／身分 |
| 勢力 | 勢力名／武將／據點／首都／外交／外交官 |
| 開局選勢力 | 勢力名／軍師名／武將／據點／首都 |

**每頁十列**，列高 16 像素。

共用的操作：

| 操作 | 效果 |
|---|---|
| 點畫面上方的欄位名 | **依該欄排序** |
| 左側 ▲▼ | 上下捲動；中間的 bar 可拖曳 |
| 左鍵第一次 | 選取（該列反白） |
| 左鍵第二次 | 決定 |
| 右鍵 | 取消（反白狀態下退回選取） |

> 排序狀態以**視窗種類**為單位記住，不必每次重排。
> 機器碼側對上了：四種清單各有一個 byte 的持久狀態，進選取迴圈前讀出、
> 回來後寫回（`../re/26` §5）。**只有「選武將」例外——它每次都從第一列開始。**

**這個介面是純滑鼠的**，三條獨立證據：說明書從頭到尾只寫左鍵／右鍵；
oracle 實測「對話框完全不吃鍵盤」（`docs/playtest/04`）；
機器碼裡每個分派點都走「等按鍵 → 查熱區圖 → 分派」，沒有鍵盤分支（§1.1）。
