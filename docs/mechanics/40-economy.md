## 1. 資金

> プレーヤー勢力の国庫にある金額です。
> **月末に拠点の生産力と税率に合わせて収入**があります。
> 行軍、内政、外交に使用することで随時減少していきます。
> 月末には**予備兵にも支払われる**ため、**これがマイナスになると予備兵が減少**します。

| 規則 | 等級 |
|---|---|
| 收入在**月末**結算，由**據點生產力 × 稅率**決定 | 說明書 |
| 支出：行軍、內政、外交（隨時扣） | 說明書 |
| 月末還要**付預備兵的維持費** | 說明書 |
| **資金為負 → 預備兵開始減少** | 說明書 |

### 這條是死亡螺旋

資金為負 ＝「疲弊狀態」（`70-ai.md` §1.4 的定義），而疲弊會

1. 讓預備兵減少 → 補不了前線 → 更容易丟據點
2. 丟據點 → 生產力下降 → 收入更少
3. **被 AI 看見**——「敵が疲弊中」是敵國君主可用的說服理由，
   等於在你最弱的時候招來更多敵人

**remake 必須完整保留這個回饋迴路**，它是本作經濟壓力的來源。

## 2. 預備兵

> その勢力が保有している**編成可能な兵力**です。
> 月末に拠点の生産力と募兵数にあわせて増加します。
> もちろん、予備兵にも**月単位で経費**がかかり、月末に支払われます。
> **騎馬、弓兵、歩兵の3種類**があります。なお、**解雇はできません**。

| 規則 | 等級 |
|---|---|
| 預備兵 ＝ 還沒編成的可用兵力 | 說明書 |
| 月末依**據點生產力**與**募兵數設定**增加 | 說明書 |
| 每月要付維持費 | 說明書 |
| 三種：**騎馬 / 弓兵 / 步兵** | 說明書 |
| **不能解雇** | 說明書 |

「不能解雇」讓募兵數變成一個**不可逆的承諾**：
募多了就得一直養，養不起就資金轉負，轉負又開始扣兵。
玩家調財政那四個數字時是在下長期賭注，這是設計而不是疏漏。

## 3. 月結的完整順序（推定）

把 §1、§2 與 `15-realtime.md` §4 拼起來：

```
月末：
  1. 收入  ← 各據點生產力 × 稅率
  2. 支出  ← 預備兵維持費（三兵種）
  3. 募兵  ← 依生產力與募兵數設定增加預備兵
  4. 若資金 < 0 → 預備兵減少
  5. 下個月起改用新設定的稅率與募兵數（設定時延遲一期）
```

⚠ **步驟順序是推定的**，說明書沒明講先扣錢還是先募兵。
`假說`，反組譯月結程式時要驗。

### ⭐ 月結順序已定案（confirmed，不再是假說）

反組譯 `sub_15358`（`docs/re/07` §1）讀出來的實際順序：

```
① 先扣本月累計支出       （sub_1563B，下限 −655,000）
② 據點結算               （sub_153C6）
     收入 = Σ(生產力 ÷ 距離除數) × 稅率 ÷ 100
     募兵 = min(可募量, 募兵數設定)   ← 設定是上限不是目標
     據點數重算並寫回
③ 收入入帳               （sub_15609，上限 +655,000）
④ 累計支出歸零
⑤ 資金為負 → 扣預備兵     （sub_15828）
```

**募兵在 ② 發生，在赤字懲罰之前**——赤字的月份是「先募到再被扣掉」。

### ⭐ 三條說明書沒寫的公式

| 公式 | 內容 |
|---|---|
| **距離衰減** | 據點對首都的**切比雪夫距離** ≤80／≤200／更遠 → 收入除以 2／3／4。**遠方據點只值一半** |
| **募兵地域配比** | 依據點的 **Y 座標**分三區（門檻 80、150）：北方騎馬 59%、中部步兵 75%、南方弓兵 50% |
| **赤字懲罰** | 每個兵種每月扣 `\|資金\| / 16 + rand(0..31)`，**三個兵種各扣一次** |

距離衰減那條讓「遷都」不只是說明書寫的「往生產力更高處」——
**把首都移到領土重心可以整體提升收入**，這在說明書裡完全沒提。

AI 勢力不使用稅率欄位，收入固定除以 2（等於稅率 50%）。

### ⭐ 「次月末生效」的實作找到了

## 4. 據點參數（說明書 5.4）

### 生產力

> その拠点の繁栄を表します。大きい方が収入が大きく、**兵の集まりも良く**なります。
> この値は、月末に**上昇値の割合に応じて変化**します。
> このため**大きい数値の方が変化が大きく**なります。
> **拠点ごとに上限値が決まっている**ため、一定値以上は上がりません。

### 上昇值 ＝ 成長率（可以是負的）

> この値は、月末に生産力を上昇させる値で **0 の時変化無し**でプラスの場合は上昇、
> **マイナスで下降**します。
> **戦争の後や、災害の後などこの値が大きく落ち込み**、
> そのままにしておくと**生産力が 0 になってしまいます**。

**公式已經從 `sub_15695` 讀出來了**（`docs/re/07` §11），比原本推的更精確：

```
有效上昇值 r = 上昇值 − (稅率 − 30)      ← 稅率修正只套用在玩家的據點
d = (生產力 >> 8) × r                    生產力 >> 8 為 0 時當 1

r ≥ 0 :  生產力 ← min(生產力 + d/2, 該據點上限)
r < 0 :  生產力 ← max(生產力 − |d|, 0)

上昇值 ← clamp(r − rand(0..15), −100, +100)
```

⚠ 注意**不對稱**：上昇值為正時只加 `d/2`，為負時扣**全額** `|d|`。
**掉得比長得快一倍。**

據點的生產力上限存在據點記錄 `+0Ch`（值域 300–42,800），
上昇值存在 `+10h`（實際值 ＝ 存值 − 100，範圍 −100…+100）。

| 事實 | 等級 |
|---|---|
| 上昇值是**成長率**，不是增量 | 說明書 |
| 變化量**與生產力本身成正比** | 說明書 |
| 上昇值可為負 → 生產力會一路掉到 0 | 說明書 |
| 每個據點有**各自的生產力上限** | 說明書 |
| 戰爭與災害都會讓上昇值**大幅下跌** | 說明書 |

**這是複利模型，不是線性模型**（變化量乘了 `生產力 >> 8`）。
大據點成長快、崩得也快；上昇值轉負而不處理，據點會指數衰減到 0。
攻略章第 10.3 節的結論正是「基本就是**別讓上昇值變成負的**」。

### 城兵數

> その拠点に配置している**守備の兵士**の人数です。拠点により違いがあり、
> **戦術では門の固さと比例**します。
> **自然に回復**しますが、**内政官を任命すると回復率が良く**なります。
> 特に**武術の高い武将**を配置すると効果があります。

| 事實 | 等級 |
|---|---|
| 城兵數 ∝ **戰術上的門強度** | 說明書 |
| 會自然回復 | 說明書 |
| 派內政官加快回復 | 說明書 |
| **武術**高的內政官效果更好 | 說明書 |

「守城要派武術高的人當內政官」是很不直覺的一條，
但它讓武術高／政治低的猛將在承平期也有用途。

### 防災值是**開關**，不是減傷

> 災害を受けたときに生産力や上昇値の受ける被害を押さえます。
> **この数値が 1 でもあると他への被害はいっさいありません。**
> しかし、この数値自身が下がるため、0 になった場合は注意が必要です。

| 事實 | 等級 |
|---|---|
| 防災值 **≥ 1 → 其他參數完全不受損** | 說明書 |
| 災害只扣防災值本身 | 說明書 |
| 防災值 **＝ 0 時**，災害才開始扣生產力／上昇值／城兵數 | 說明書 |

**不是按比例減傷，是二元的護盾。** remake 若做成「防災值越高減傷越多」
會完全改變玩家的維護策略——原版只要維持在 1 以上就夠。

### 四個參數總表

| 參數 | 作用 |
|---|---|
| **生產力** | 決定收入與募兵量；遷都只能往更高的據點；有上限 |
| **上昇值** | 生產力的**成長率**，可負 |
| **防災值** | ≥1 就完全擋住災害；歸 0 才會出事 |
| **城兵數** | 據點守軍，**決定戰術上的門強度** |

## 4.1 內政是全權委任

> このゲームの内政は**全て武将の委任**となっていますので、
> **直接城兵を増やせとか、防災値をあげろとかの命令はできません**。
> それに加えて、拠点のパラメータの変化が非常に大きいため、
> **生産力が一気に落ちて収入が半減する場合があります**。

玩家能做的只有「派誰去哪個據點」，**不能指定做什麼**。
這讓人事（`10-strategy.md` §3）成為內政的唯一操作介面。

攻略章 10.3 的建議：

> 通常は**税率を下げるだけで、内政の必要はありません**。
> ただし、国境で取り合いになった後など、生產力がほとんど 0 の状態の場合、
> このときだけは一時的に内政官を派遣し、上昇値をあげておいてください。
> **基本は、上昇値がマイナスにならないように注意することです。**

## 4.2 稅率的雙重作用

> 各拠点の収入の**何割を徴収するか**を表します。
> **高いほど拠点が荒廃していき、低いほど繁栄していきます。**

### ⭐ 中性點是 30%（confirmed）

`sub_15695` 裡的 `sub ax, 1Eh` 把稅率換算成上昇值的修正量：

| 稅率 | 對上昇值的影響 |
|---:|---|
| **< 30%** | **加**（據點繁榮） |
| ＝ 30% | 無 |
| **> 30%** | **減**（據點荒廢） |

而且這個修正**寫回上昇值本身**，不只影響當月計算——所以高稅率是
**累積**的，越拖越糟。

### ⭐ 真正的平衡點是 22.5%

上昇值每月還會自然衰減 `rand(0..15)`（期望 7.5），所以：

```
上昇值的月變化期望 = 30 − 稅率 − 7.5 = 22.5 − 稅率
```

**稅率低於 22.5% 時上昇值會自己長回來。**
這就是攻略章 10.3 那句話的機制：

> 通常は**税率を下げるだけで、内政の必要はありません**。

調低稅率本身就是內政。說明書截圖上的預設稅率是 25%——
略高於平衡點，**所以放著不管會慢慢惡化**，這是設計好的溫水壓力。

⚠ 稅率修正**只對玩家的據點生效**。AI 的據點不受稅率影響，
與「AI 收入固定除以 2」是同一種簡化。

**這是本作經濟的核心取捨**，而且因為生產力是複利模型（§4），
高稅率的代價是**指數性**的，不是線性的。

## 4.3 募兵是上限不是保證，而且有地域偏差

> 予備兵として雇う兵数です。集まった兵数がこれに満たない場合など、
> **必ず集まるとは限りません**。が、**これを越えることはありません**。
> **騎馬は北方でよく集まり、弓は南方でよく集まります。**

| 事實 | 等級 |
|---|---|
| 募兵數設定是**上限**，實際募到可能更少 | 說明書 |
| 實際募到量取決於據點生產力 | 說明書 |
| **騎馬在北方好募，弓兵在南方好募** | 說明書 |

**地域決定兵種。** 佔北方的勢力天然是騎兵國，南方是弓兵國——
而騎兵**不能登城牆**、在海戰幾乎無用（`30-combat.md`），
所以「北方勢力攻南方城池」在機制上就是吃虧的。
這一條把地圖與兵種綁在一起，remake 不能省。

## 4.4 行軍費用是啟動成本

> 軍団が**停止している場合、費用は予備兵と大差ありません**。
> しかし、**移動を始めると即座に大きな経費**がかかります。

| 事實 | 等級 |
|---|---|
| 駐紮中的軍團花費 ≈ 同等預備兵 | 說明書 |
| **一開始移動就立刻產生大筆支出** | 說明書 |

⭐ **機器碼是每天照收，不是啟動成本**（`sub_12600`，[`../re/09`](../re/09-combat.md) §9）：

| 位置 | 每天的軍費 | 士氣 |
|---|---|---|
| 據點或道路上 | 兵力 ÷ 32 ＋ 1 | **+10**，上限 ＝ 勢力基準 |
| **野外** | **兵力 × 3/4** | 不回復 |

野外一天的軍費是駐紮的 **24 倍**，這就是說明書那句「即座に大きな経費」。
從那句話推「啟動成本」是合理的讀法，但**一天一收**才是實際行為——
所以久拖的遠征比反覆改目的地更貴。

⭐ 這筆錢**當場從資金扣**（`sub_1562B`），不進「本月支出」累加器；
那一格只有預備兵維持費在寫（`sub_13E65`）。差別見
[`../spec/50`](../spec/50-corps-upkeep-charges-funds.md) §2。

## 5. 災害

三種：**暴風雨、火災、暴動**（說明書第 9 章）。

> 被害がでると、まず**防災値**が下がっていき0になると、
> 生産力、上昇値、城兵数がそれぞれ減少します。
> なお、**軍団への影響はありません**。

| 規則 | 等級 |
|---|---|
| 先扣防災值 | 說明書 |
| 防災值歸零後才扣生產力、上昇值、城兵數 | 說明書 |
| **軍團不受影響** | 說明書 |

**這在所有中文攻略裡都沒被提到。**

### ⭐ 三種災害的觸發公式（confirmed，`docs/re/07` §17–18）

說明書第 9 章各給了一句描述，反組譯出來的實際公式是：

```
火災   P = (24/256) × max(0, 64 − 防災值) / 64            每據點每月
暴動   P = (24/256) × max(0, 64 − 上昇值存值) / 64        每據點每月
暴風雨 P = 1/2 × 3/4 × (1 靠海 ／ 1/2 內陸)               每月最多一次，全地圖
```

單一據點單月的災害機率上限是 **9.4%**（24/256），在該參數歸零時達到。
火災先判、暴動後判，**同一據點同一月不會同時發生兩種**。

### ⭐ 免疫門檻是 64，說明書把安全區講小了

比較用的亂數是 `and al, 3Fh` ＝ **0–63**，所以：

| 參數 | 完全免疫 | 開局值 |
|---|---|---|
| 防災值 | **≥ 64** | 100（全部 192 個據點） |
| 上昇值存值 | **≥ 64**，即實際上昇值 **≥ −36** | 100 附近 |

說明書寫「上昇値がプラスの場合は発生しません」——**正確但保守**。
實際上昇值掉到 −36 之前都還是完全免疫的。

這也修正了本文件先前的寫法：暴動不是「上昇值 < 0」的布林閘門，
而是「上昇值存值 < 64 之後才開始有機率」。
`internal/rules/economy` 的 `RollCityDisaster` 照公式實作。

### ⚠ 暴風雨的「靠海」判定是原版的 bug

程式比的是 **X 座標的低位元組**（`cmp byte ptr [bx+848h], 0C0h`），
但 X 的值域是 4–370。結果：

| 條件 | 據點數 |
|---|---:|
| 程式判定為靠海（`X mod 256 ≥ 192`） | **52** |
| 真正的東半部（`X ≥ 192`） | 101 |
| 其中 `X ≥ 256` 被判成內陸 | **49**（最東邊、最靠海的那些） |

說明書寫「発生率は海側がわずかに高くなっています」，
可見原意是東部加成。remake **預設照抄這個 bug**，
並在 `IsCoastalForStorm` 註明怎麼改回來。

暴風雨會在中選據點周圍圈出 **11 × 11 格**的區域，
而且**不分勢力**——它挑的是全地圖的據點。

三種災害都只回報自勢力的據點，**敵國遭災玩家看不到**。

### ⭐ 災害 marker 的持久效果（confirmed）

事件 11／12 的處理端先把城市 runtime record `+0x15` 寫成 marker；
這不是只供繪圖的旗標。`sub_13EFD` 在每次據點輪轉中，於內政官
`sub_14194` 之後呼叫 `sub_14269`（IDA 線性位址 `00014269`）：

```
marker ≤ 防災值：防災值 -= marker
marker > 防災值：
  deficit = marker − 防災值；防災值 = 0
  上昇值存值 = max(上昇值存值 − deficit, 0)
  生產力 = 生產力 − ((deficit × 生產力高 byte) >> 2)（u16 減法）
  城兵 = max(城兵 − (deficit >> 1), 0)
```

事件 12 的火災／暴動 marker 是 4–11；暴風雨 marker 則是強度減去
城市到中心距離的一半。marker 由後續的高 byte 0 清除事件歸零；
在清除前，每次輪到該據點都會再套用一次。直接證據是
`sub_13EFD` 的 `00013F5A` 呼叫鏈與 `sub_14269` 的 `00014269`；
輸入為 DOS/V `KI.EXE`，雜湊與 IDA Pro 9.4 工具契約記在
`RESEARCH-LOG.md` 最新災害勘誤段。

## 5.1 內政官實際做什麼（說明書 8.2）

> 任命された内政官は**上昇値、防災値、城兵数**のパラメータを上昇させます。
> この中の**城兵数のみは、その武将の武術値により上昇率が変化**します。
> なお、実際に内政官が内政を始めるのは**必要な金額を要求してきてから**となります。
> また、金額を多く与えても**要求間隔が長くなるだけ**で、一気に上がるわけではありません。

| 事實 | 等級 |
|---|---|
| 內政官同時提升**上昇值、防災值、城兵數**三項 | 說明書 |
| **只有城兵數的成長率受武將的武術影響** | 說明書 |
| 內政官要先開口要錢才開始做事 | 說明書 |
| **給多的錢只是拉長下次要錢的間隔**，不會加快成長 | 說明書 |

⚠ 與外交官不同：外交官是「給多一點浪費比較少」（`50-diplomacy.md` §9），
內政官是「給多一點只是比較久不用再給」。**兩者的金錢模型不一樣。**

而內政官提升的三項正好對應三種災害的防線：
上昇值擋暴動、防災值擋火災與暴風雨的損害、城兵數是戰術上的門強度。
