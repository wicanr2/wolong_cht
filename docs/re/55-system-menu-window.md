# 55 — 系統選單視窗，以及 `op 08` 屬性的真正編碼

**狀態：視窗矩形、六列版面、六個熱區、⭐ 中間四列的設定值與選項字串

## 1. 視窗與熱區

```asm
sub_160CC:
  al = 1Fh / dx = 0Dh / bx = 5 / cx = 0C0Dh
  sub_1895D                        ; 框 (208, 112) 208×192
  al = 2 / dx = 0D8h / bx = 78h
  sub_10337                        ; 場景 2，原點 (216, 120)
  cx = 6 / bp = 98h
  al = 20h
  loop: sub_1E3D7(al, bx=bp, dx=160h, cx=206h)   ; (352, 152 + 24k) 48×16
        bp += 18h / al++
```

**六個熱區 `0x20`–`0x25`，列距 24**。

⚠ **這是原版。** remake 在後面加了第七列「主君編成」（開關，
[`../spec/76`](../spec/76-lord-not-in-formation.md)），視窗因此從 192 高變成 216。
原版那六列的座標一格都沒動——新列只加在下面。

**值格只有框沒有底**——底色由字串自己帶（§3）。

## 3. ⭐ `op 08` 的 `arg2`：高 byte 是「背景<<4 ｜ 前景」

十個場景用到的值只有五種，分佈立刻說明了編碼：

| `arg2` | 前景 | 背景 | 低 byte | 用在哪 |
|---|---:|---:|---:|---|
| `0F03` | `F` | `0` | 03 | 一般白字標籤 |
| `0903` | `9` | `0` | 03 | 次要標籤（稅率、徵兵數、六個編成位置…）|
| `0003` | `0` | `0` | 03 | **所有按鈕的字**：確定／自定／重來／繼續／ＹＥＳ／ＮＯ |
| `5001` | `0` | `5` | 01 | 系統選單的「 ＯＫ 」|
| `0F01` | `F` | `0` | 01 | 場景 9 的注音聲母列 |

⭐ **按鈕的字是黑的**（前景 `0`），畫在 `op 03` 填出來的色 `7` 底上。
先前 [`48`](48-window-display-list.md) §2 把高 byte 記成「調色盤索引」，
那對前四個值剛好說得通，但 `5001` 的 `0x50` 超出 0–15 —— **取樣不足的老問題**。

低 byte 的兩個值：`03` 只畫字，`01` 連背景一起填。
「 ＯＫ 」要自己帶綠底、注音列要蓋掉底下色 `9` 的選字區，兩者都需要填背景。
**這是強推論**——`sub_106F5` 的實作沒逐行讀，但兩個用例都只有這個讀法說得通。

## 4. ⭐ 中間四列的值：一個 4 byte 的設定表

設定值本身是 `ds:0CF8h` 起**一列一個 byte**；每一列的「有幾個選項、
選項字串在哪」寫在 `ds:5FF2h` 起、每筆 4 byte 的表裡。

```asm
sub_16062:                       ; 點一下 → 換下一個選項
  si = bx − 1 / di = si × 4
  ah = [di + 5FF4h]              ; ★ 那一列的選項數（表 +2）
  al = [si + 0CF8h] / inc al
  cmp al, ah / jb .存 / xor al, al    ; 到頂繞回 0
.存: [si + 0CF8h] = al

sub_16106:                       ; 重畫四列的值
  cx = 4 / bx = 0B0h / bp = 5FF2h / di = 0CF8h
.列: al = [di] / ah = 7 / mul ah      ; ★ 每個選項字串固定 7 byte
     ax += ds:[bp+0]                  ; ★ 表 +0 ＝ 該列的字串表基址
     si = ax / dx = 160h / ax = 5001h ; (352, bx) 黑字綠底
     call sub_106F5
     bx += 18h / di++ / bp += 4 / loop
```

`bx` 從 `0B0h` ＝ 176 起、步進 24，正好是**第 2 到第 5 列**的值格
（§2 的 `152 + 24k`，k ＝ 1..4）。第 1、6 列不在迴圈裡，
所以它們的「 ＯＫ 」是顯示清單裡寫死的。

| 位址 | 設定 | 字串表 | 選項數 | 選項 |
|---|---|---|--:|---|
| `ds:0CF8h` | 畫面模式 | `ds:6002h` | **2** | 「１６色」／「 液晶 」|
| `ds:0CF9h` | 音　　效 | `ds:6010h` | 5 | ＯＦＦ／TYPE 1／2／3／4 |
| `ds:0CFAh` | 戰略速度 | `ds:6033h` | 5 | 最高速／ 高速 ／ 普通 ／ 低速 ／最低速 |
| `ds:0CFBh` | 戰術速度 | `ds:6033h` | 5 | 同上（兩列共用同一張字串表）|

⭐ 「畫面模式」的兩個選項是**１６色**與**液晶**——
這正是 `GAMEPAL.BRG` 那 8 個 bank 分成兩組的原因，
`sub_16097` 把設定值當組號載入（[`02`](02-palette-routine.md) §6.2）。
說明書 3.5 節的「類比彩色 ↔ 8 階調液晶」對上了。

⚠ 兩個速度共用字串表，但**值的語意不同**：戰略速度直接當等待量、
戰術速度要 ×16（[`61`](61-timer-tick-source.md) §4）。

## 5. 六個 handler：分派表在 `ds:6056h`

```asm
sub_15FAA:
  al = 熱區碼 / sub al, 20h / jb 重來
  bx = al
  and bx,bx / jz .不換值            ; 第 1 列（資料儲存）不是設定
  cmp bx, 0Ah / jz .不換值
  call sub_16062                     ; 先換值
.不換值:
  shl bx,1 / call word ptr [bx+6056h]   ; ★ 再叫 handler
```

| 列 | handler | 做什麼 |
|--:|---|---|
| 1 資料儲存 | `0x6084` | 未讀 |
| 2 畫面模式 | `sub_16097` | `al = ds:0CF8h` → `sub_109AF` 換調色盤組 → `sub_19336` 重送硬體 |
| 3 音　　效 | `sub_160A1` | `sub_102D0`：0 送 `INT 61h AH=8`（停），1–4 送 `AH=0Bh, AL=(值−1)×4` ＝ **四段主衰減**（[`81`](81-sound-type-attenuation.md)）|
| 4 戰略速度 | `0x5FF1` | **就是一個 `retn`**——只改值，沒有副作用 |
| 5 戰術速度 | `sub_160A5` | `ds:0CFCh = ds:0CFBh << 4`（[`61`](61-timer-tick-source.md) §4）|
| 6 遊戲結束 | `0x60B4` | 未讀 |

⇒ **兩個速度列的差別全在 handler**：戰略只存值，戰術要換算。
`0x5FF1` 那個 `retn` 是 `sub_15FAA` 前面那一支的收尾，被當成空 handler 借用。
