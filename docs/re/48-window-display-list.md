## 1. `sub_10337(al = 場景編號)`

```asm
sub_10337 → sub_1E9C1:
  lds si, cs:dword_1EAE9        ; 清單起點
skip:
  cmp byte ptr [si], 0          ; 記錄的第一個 byte ＝ 0 是場景分隔
  jnz next
  and al, al / jz  → run        ; 數到第 al 個分隔就開跑
  dec al
next:
  add si, 0Ch / jmp skip
run:
  add si, 0Ch
  bl = [si] / and bl,bl / jz → 結束
  bx = (bl − 1) × 2
  call word ptr [bx-15F3h]      ; opcode 分派
  jmp run
```

**每筆記錄 12 bytes ＝ 六個 word**：

```
op  X  Y  arg1  arg2  色
```

`X`／`Y` 是**相對於呼叫端傳進來的原點**（`sub_10337` 的 `dx`／`bx`）。

⭐ **第六個 word 是顏色，不是保留欄位**（§2.1）：`op 01`–`op 04` 的 handler
第一句就是 `mov ah, [si+0Ah]`（`op 04` 是 `mov ax`），把它餵給繪圖常式。
`op 05`–`op 09` 不讀它，那幾筆記錄裡它才是 0——**只看那幾筆會以為它恆為 0**。

清單本身在 `cs:0E16`（檔案位移 `0x1016`），由 `sub_1030F` 在 `start` 裡登記：

```asm
dx = cs / ax = 0E16h / bx = cs / cx = cs:word_10D50
sub_1E993                       ; dword_1EAE9 ← cs:0E16、word_1EAEF ← 圖庫段
```

`word_10D50` 就是 `sub_15A3A` 畫縮小地圖時用的那個圖庫段——
**opcode `09` 的圖形來源是它**，它是什麼見 §6。

## 2. opcode：值域 1–9

分派表在 `cs:EA0D`，`bx = (op − 1) × 2`。表的前九筆落在
`cs:EA1F`–`cs:EAB3` 這一段連續的 handler 裡，第十筆起指到別的地方——
**所以 opcode 只有 1–9**，不必猜。

| op | handler | 參數 | 用途 | 證據 |
|---:|---|---|---|---|
| `01` | `cs:EA1F` | `ah` ＝ 色；**座標不展開** | **直線** | 目標 `cs:EDFE` 是 Bresenham：`di−bx` 與 `si−dx` 各取絕對值、比大小選主軸、必要時交換端點（§2.2）|
| `02` | `cs:EA26` | `ah` ＝ 色，左上／右下 | **矩形**（`sub_1F020`）| 那支另有五個呼叫者，全在戰術區段；[`18`](18-tactical-button-glyphs.md) §4 已證實它是「EGA 矩形／遮罩繪製」，戰術命令列的選取 overlay 用它畫兩層 |
| `03` | `cs:EA30` | `arg1`／`arg2` ＝ 右下角 | 填矩形 | 場景 0 的兩筆剛好是信賴度量條的槽與資金區的黑底 |
| `04` | `cs:EA3A` | `ax` ＝ **兩個顏色**，右下角 | **立體框**：四條線，低 byte 畫上邊與左邊、高 byte 畫下邊與右邊 | 目標 `cs:F465` 把矩形拆成兩次水平線 ＋ 兩次垂直線，**呼叫的正是 `05`／`06` 的同兩支**，而且每次之前 `xchg ah, al`（§2.1）|
| `05` | `cs:EA44` | `arg1` ＝ 長度、`arg2` ＝ 顏色 | **水平線**（`06` 的橫版）| 場景 6 唯一一筆 `(0,23)` 長 287 色 `0x0F`，橫跨整個視窗內框，落在標題與第一個槽之間 |
| `06` | `cs:EA5A` | `arg1` ＝ 長度、`arg2` ＝ 顏色 | **垂直線** | 場景 0 的 (560,208) 長 48 色 `0x0F`，正好是原版「君主／首都／軍師」與名字之間那條白線，涵蓋三列 |
| `07` | `cs:EA70` | 右下角 | 場景範圍，每個場景的第一筆 | 場景 0 是 `(0,0)–(191,191)`，正好是視窗內框 |
| `08` | `cs:EA96` | `arg1` ＝ 字串位址、`arg2` ＝ **背景<<12 ｜ 前景<<8 ｜ 模式** | 畫字串 | 十個場景只用五種值，`5001`（黑字綠底）與 `0003`（黑字）逼出這個讀法（[`55`](55-system-menu-window.md) §3）|
| `09` | `cs:EAB3` | `arg1` ＝ 圖庫位移、`arg2` ＝ 高<<8｜寬 | 貼圖 | 場景 0 的四筆是 24×16，位置正好在資金／預備兵四列的左邊 |

`08` 與 `09` 的 handler 只差一個段：

```asm
op 08:  mov ds, cs:word_1EAED    ; ＝ cs，字串在程式段裡
op 09:  mov ds, cs:word_1EAEF    ; ＝ word_10D50，圖庫段
```

兩個段都由 `sub_1030F` 在 `start` 裡經 `sub_1E993` 一次寫好。

### 2.0 ⭐ `op 08` 的顏色也不是單一索引

`arg2` 的高 byte 拆成兩個 nibble：**高 4 位背景、低 4 位前景**。
所有按鈕的字都是 `0003` ——**黑字**，畫在 `op 03` 填出來的色 `7` 底上。
完整的五個值與證據見 [`55`](55-system-menu-window.md) §3。

### 2.1 ⭐ 第六個 word 是顏色，十個場景只用了兩套配色

`op 03` 讀它的低 byte 當填色，`op 04` 讀整個 word 當兩個顏色。
把十個場景的值攤開來看，只有兩種組合：

| 控制項 | 底（`03`）| 外圈（`04`）| 內圈（`04`）| 用在哪 |
|---|---:|---|---|---|
| **凹槽** | `5` | 上左 `2`／下右 `0` | 上左 `D`／下右 `4` | 四槽視窗的日期欄、ＹＥＳ／ＮＯ 的兩格 |
| **按鈕** | `7` | 上左 `9`／下右 `6` | — | 「確定」「自定」「重來」「繼續」|

其餘的 `03` 都是色 `0`（黑底的值框），場景 9 的選字區是色 `9`。

**`op 04` 只用一筆就能做出立體感**（四條邊兩色），成對出現是為了疊兩圈。

### 2.2 `op 01` 是直線

`cs:EDFE` 在 IDA 影像裡沒有被認成函式（只被間接呼叫），要從原始 bytes 讀：

```asm
push ds / push cx / push bp
mov cx, 0A0C8h / mov ds, cx      ; VRAM 段
… 設 EGA GC：mode 3、set/reset ＝ ah、bit mask FFh …
add dx, 8000h / add si, 8000h / add bx, 8000h / add di, 8000h
mov ax, di / sub ax, bx / jnb → / xchg dx,si / xchg bx,di / neg ax
mov bp, si / sub bp, dx / jnb → / neg bp
cmp bp, ax / …                    ; 比 |dx| 與 |dy| 決定主軸
```

**取兩軸差的絕對值、比大小選主軸、必要時交換端點** ——Bresenham 的標準開頭。

⚠ 但 `op 01` 的 handler **不展開座標**（沒有呼叫 `cs:EAD0`），
所以端點來自前一筆 handler 留在暫存器裡的值。十個場景一次都沒用到它，
**它預期怎麼被使用無法從資料驗證**。

### 2.3 `cs:EAD0`：`02`／`03`／`04` 共用的座標展開

```asm
dx = [bp+0] + [si+2]     ; 原點X ＋ X
bx = [bp+2] + [si+4]     ; 原點Y ＋ Y
cx = [bp+0] + [si+6]     ; 原點X ＋ arg1
di = [bp+2] + [si+8]     ; 原點Y ＋ arg2
si = cx
```

**這證實 `arg1`／`arg2` 是右下角**，而且是相對原點的——與場景資料的讀法一致。

## 5. 為什麼這件事重要

先前 remake 把「君主／首都／軍師」這些標籤當成自己排版的文字，
座標是照參考影片估的。**它們其實是原版資料裡的字串 ＋ 座標**，
可以逐項對齊而不必猜。

同一支直譯器有 11 個呼叫端（各視窗的建構常式），所以其他視窗的內部
版面也在同一份清單裡——**要解某個視窗的內部排版，不必再讀組語，
把它的場景編號印出來就好**。

## 6. op `09` 的圖庫段是什麼

### 6.1 圖庫段 ＝ `ICONGRF` 段 3 ＋ `0x9A0`

換算鏈只有兩步，兩步都是立即值：

```asm
sub_1006B:  dx = 0D64h 那張檔名表 → "ICONGRF.DAT"
            ax = 9700h            ; 檔案位移 ＝ 段 3 的起點
            bx = word_10D48       ; 目的段
            sub_1E38C             ; 讀檔

sub_100DF:  … ax += 524h → word_10D48
                ax += 6Ch  → word_10D4A
                ax += 18h  → word_10D54
                ax += 0Bh  → word_10D4C
                ax += 0Bh  → word_10D50      ; 合計 +9Ah 段
```

`0x9A` 段 ＝ **`0x9A0` byte**，所以

```
word_10D50:X  ＝  ICONGRF 段 3 的 (X + 0x9A0)
```

三個內容檢查同時成立，都不必碰模擬器：

| 顯示清單／呼叫端要的 | 換算後的段 3 位移 | 解出來是什麼 |
|---|---|---|
| 場景 0 的 `0x1200`–`0x1440`（4 張 24×16）| `0x1BA0` 起 | **天秤／馬／弓／步**，與說明書主畫面圖那一直排逐張相符 |
| 場景 1 第二欄的 `0x1500`–`0x1740` | `0x1EA0` 起 | 同樣四張的**綠色版**——財政視窗「今月底」用紅、「次月」用綠 |
| `sub_17D0D` 的 `0x0600`（96×64）| `0x0FA0` | **完整數字鍵盤**：7 8 9 ◀ 取消／4 5 6 0 最大／1 2 3 00 決定 |

> `docs/formats/03` §5.4.1 原本把數值面板記在段 3 的 `0x14A0`。
> 那個位址解出來只看得到幾個數字、其餘錯位；`0x0FA0` 才是完整的鍵盤。
> 差的正是 `0x500`——**當時是用另一組指標湊出來的差值，不是這條換算鏈**。

紅、綠兩組**不是同一張圖換色**：綠色那組多一圈邊框，剪影逐像素比不相等。
`internal/assets/gfx` 的測試只驗位址與「不是一整片單色」，
不驗兩組相同——驗一個不成立的性質會讓測試在正確的資料上失敗。

## 8. 財政視窗（場景 1）的完整版面

`sub_1678D` ＝ 建構（`sub_168C3`）＋ 互動迴圈 ＋ 擦除（`sub_168FA`）。
狀態列提示是 TALK #16（[`22`](22-strategy-command-tree.md) §3）。

```asm
sub_168C3:
  sub_1895D(al=1Fh, bx=3,   dx=1,    cx=0A15h)   ; 框 (16, 80, 336, 160)
  sub_10337(al=1,   bx=58h, dx=18h)              ; 場景 1，原點 (24, 88)
  al=20h / si=0A0h / di=4
  loop:  sub_1E3D7(al, bx=si, dx=100h, cx=203h)  ; 熱區 (256, 160+16n, 24, 16)
         inc al / si += 10h / dec di
```

框 (16,80,336,160) 扣掉 8 px 外框 ＝ 內框 (24,88)–(343,231)，
**與場景 1 的 `07` 記錄 `(0,0)–(319,143)` 換算後完全相同**——
兩個獨立來源給同一個矩形。

|---|---|---|
| 視窗 | (16, 80, 336, 160) | `sub_1895D` |
| 「資金」「收入」「支出」 | (32,96)／(200,96)／(200,112) | 場景 1 op 08 |
| 「今月底」「次月」 | (48,136)／(208,136) | 場景 1 op 08 |

| 「％」×2 | (160,160)／(320,160) | 場景 1 op 08 |
| 圖示欄（紅）| (96, 160/176/192/208) | 場景 1 op 09，段 3 `0x1BA0` 起 |
| 圖示欄（綠）| (256, 160/176/192/208) | 場景 1 op 09，段 3 `0x1EA0` 起 |
| **四個熱區 `0x20`–`0x23`** | (256, 160/176/192/208) 24×16 | `sub_168C3` 的迴圈 |

⭐ **熱區與綠色圖示欄逐格重合**：可點的是「次月」那一欄的四列
