# 48 — 視窗內容是一份顯示清單，不是一張圖

**狀態：清單的位置、記錄格式、場景切分、opcode 值域（1–9）與十個場景
全部解出來了。每個場景對到哪個視窗由字串內容認定。`04`／`05`／`06` 的
精確語意與 op `09` 的圖庫來源未解（§6）。**

- 日期：2026-08-15
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：**IDAPython** `tools/ida_dump.py`、`tools/ida_data_writers.py`、`tools/ida_range.py`；
  清單內容由 `tools/displaylist.py`（新增）直接從 `KI.EXE` 原始 bytes 解
- 位址空間：IDA DOS/V linear address；`cs:XXXX` 的檔案位移 ＝ `cs` ＋ `0x200`

[`47`](47-main-screen-window-registry.md) §4.2 把自勢力情報視窗的
底圖記成「`sub_10337` 貼一張圖」。**那是一支直譯器，不是一次 blit。**

## 1. `sub_10337(al = 場景編號)`

```asm
sub_10337 → sub_1E9C1:
  lds si, cs:dword_1EAE9        ; 清單起點
skip:
  cmp byte ptr [si], 0          ; 記錄的第一個 byte ＝ 0 是場景分隔
  jnz next
  and al, al / jz  → run        ; 數到第 al 個分隔就開跑
  dec al
next:
  add si, 0Ch / jmp skip
run:
  add si, 0Ch
  bl = [si] / and bl,bl / jz → 結束
  bx = (bl − 1) × 2
  call word ptr [bx-15F3h]      ; opcode 分派
  jmp run
```

**每筆記錄 12 bytes ＝ 六個 word**：

```
op  X  Y  arg1  arg2  0
```

`X`／`Y` 是**相對於呼叫端傳進來的原點**（`sub_10337` 的 `dx`／`bx`）。

清單本身在 `cs:0E16`（檔案位移 `0x1016`），由 `sub_1030F` 在 `start` 裡登記：

```asm
dx = cs / ax = 0E16h / bx = cs / cx = cs:word_10D50
sub_1E993                       ; dword_1EAE9 ← cs:0E16、word_1EAEF ← 圖庫段
```

`word_10D50` 就是 `sub_15A3A` 畫縮小地圖時用的那個圖庫段——
**opcode `09` 的圖形來源是它**。

## 2. opcode：值域 1–9

分派表在 `cs:EA0D`，`bx = (op − 1) × 2`。表的前九筆落在
`cs:EA1F`–`cs:EAB3` 這一段連續的 handler 裡，第十筆起指到別的地方——
**所以 opcode 只有 1–9**，不必猜。

| op | handler | 參數 | 用途 | 證據 |
|---:|---|---|---|---|
| `01`／`02` | `cs:EA1F`／`EA26` | — | 十個場景都沒用到 | — |
| `03` | `cs:EA30` | `arg1`／`arg2` ＝ 右下角 | 填矩形 | 場景 0 的兩筆剛好是信賴度量條的槽與資金區的黑底 |
| `04`／`05` | `cs:EA3A`／`EA44` | 右下角 | 線／框（未定）| 成對出現且座標相差 1 px，像是立體邊 |
| `06` | `cs:EA5A` | `arg1` ＝ 寬、`arg2` ＝ 高 | 未解 | — |
| `07` | `cs:EA70` | 右下角 | 場景範圍，每個場景的第一筆 | 場景 0 是 `(0,0)–(191,191)`，正好是視窗內框 |
| `08` | `cs:EA96` | `arg1` ＝ 字串位址、`arg2` 低 byte ＝ 屬性 | 畫字串 | 解出來是「君主」「首都」「軍師」…… |
| `09` | `cs:EAB3` | `arg1` ＝ 圖庫位移、`arg2` ＝ 高<<8｜寬 | 貼圖 | 場景 0 的四筆是 24×16，位置正好在資金／預備兵四列的左邊 |

`08` 與 `09` 的 handler 只差一個段：

```asm
op 08:  mov ds, cs:word_1EAED    ; ＝ cs，字串在程式段裡
op 09:  mov ds, cs:word_1EAEF    ; ＝ word_10D50，圖庫段
```

兩個段都由 `sub_1030F` 在 `start` 裡經 `sub_1E993` 一次寫好。

## 3. 十個場景各是哪個視窗

`sub_10337` 有 11 個呼叫端而清單只有 10 個場景——**有兩個呼叫端共用**
（哪兩個未查）。場景的身分由字串內容認定，不靠呼叫端反推：

| 場景 | 視窗 | 認出來的關鍵字串 |
|---:|---|---|
| 0 | 自勢力情報 | 君主／首都／軍師／信賴度／資金／預備兵 |
| 1 | 財政 | 資金／收入／支出／今月底／次月／稅率／徵兵數／％ |
| 2 | 系統選單 | 系 統 選 單／資料儲存／畫面模式／音效／戰略速度／戰術速度／遊戲結束 |
| 3 | 據點情報 | 城兵數／生產力／上昇值／防災值 |
| 4 | 軍團編成 | 將軍／君主／首都／總兵力／主將／前鋒／左翼／右翼／左備／右備 |
| 5 | 軍團詳細 | 將軍／總兵力／士氣值／六個位置／預備兵數／確 定 |
| 6 | 讀取／儲存四槽 | 「年　月　日」×4 |
| 7 | ＹＥＳ／ＮＯ 對話框 | ＹＥＳ／Ｎ　Ｏ |
| 8 | 君主選擇 | 君主／軍師／首　都／武將數／據點數／自定／確定 |
| 9 | **軍師命名（注音輸入）** | 軍師名／別　號／重來／繼續／確定／上一頁 ▲／注音符號表 |

場景 9 的注音符號表是**松崗中文版特有的**——日文原版那一頁是漢字輸入
（說明書 2.3）。

> 清單**沒有結束標記**，後面接的是 Big5 字串資料。
> `tools/displaylist.py` 用「opcode > 0x0F 就停」擋住讀過頭——
> 少了這道閘會多解出一個場景，內容是文字被當成記錄讀的亂碼，
> 而那看起來像「還沒解開的場景」，不像讀過頭。

與說明書主畫面圖上那一直排小圖示相符。

## 5. 為什麼這件事重要

先前 remake 把「君主／首都／軍師」這些標籤當成自己排版的文字，
座標是照參考影片估的。**它們其實是原版資料裡的字串 ＋ 座標**，
可以逐項對齊而不必猜。

同一支直譯器有 11 個呼叫端（各視窗的建構常式），所以其他視窗的內部
版面也在同一份清單裡——**要解某個視窗的內部排版，不必再讀組語，
把它的場景編號印出來就好**。

### 6.1 圖示本身找到了，但接不回顯示清單

`ICONGRF` 段 3（檔案 `0x9700`）**開頭就是一排 24×16 的圖示**，
用 4bpp plane-major 解出來目視清楚：

| 段 3 位移 | 內容 |
|---|---|
| `0x0000` | 紅底的城門狀物 |
| `0x00C0` | 長槍 |
| `0x0180` | 紅旗 |
| `0x0240` | 城牆紋理 |
| `0x0300` | 弩／機械 |
| `0x03C0` | 白旗 |
| **`0x0480`** | **馬頭（橙框）** |
| **`0x0540`** | **弓兵（橙框）** |
| **`0x0600`** | **步兵（橙框）** |

後三張與說明書主畫面圖上「予備兵」那一直排的下三格逐一相符
（[`../reference/01`](../reference/01-jp-manual.md) 的第 6 頁截圖：
天秤／馬／弓／步）。**天秤那一張在段 3 裡找不到**，
所以四張不是連號的一組。

而顯示清單要的是連號的四張（`0x1200` 起、每張差 `0xC0`）。
兩件事湊不起來，代表**緩衝裡的排列與 `ICONGRF` 段 3 不同**——
中間有一層搬運，而那一層還沒找到。在找到之前：

- 圖示的**內容**已知（目視 ＋ 說明書截圖對照，強證據）
- 圖示在緩衝裡的**位址**已知（顯示清單，confirmed）
- 兩者之間的對應**未知**

remake 因此先用同位置同尺寸的色塊佔位，不拿段 3 那幾張直接貼——
**位置對、圖不對**比留白更難發現。
