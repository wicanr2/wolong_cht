# 48 — 視窗內容是一份顯示清單，不是一張圖

**狀態：清單的位置、記錄格式、場景切分與五個 opcode 的用途 confirmed。
自勢力情報視窗（場景 0）的每一個元件座標都讀出來了。opcode 的完整值域
與 `06`／`07` 的精確語意未解（§5）。**

- 日期：2026-08-15
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：**IDAPython** `tools/ida_dump.py`、`tools/ida_data_writers.py`；
  清單內容直接從 `KI.EXE` 原始 bytes 取
- 位址空間：IDA DOS/V linear address；`cs:XXXX` 的檔案位移 ＝ `cs` ＋ `0x200`

[`47`](47-main-screen-window-registry.md) §4.2 把自勢力情報視窗的
底圖記成「`sub_10337` 貼一張圖」。**那是一支直譯器，不是一次 blit。**

## 1. `sub_10337(al = 場景編號)`

```asm
sub_10337 → sub_1E9C1:
  lds si, cs:dword_1EAE9        ; 清單起點
skip:
  cmp byte ptr [si], 0          ; 記錄的第一個 byte ＝ 0 是場景分隔
  jnz next
  and al, al / jz  → run        ; 數到第 al 個分隔就開跑
  dec al
next:
  add si, 0Ch / jmp skip
run:
  add si, 0Ch
  bl = [si] / and bl,bl / jz → 結束
  bx = (bl − 1) × 2
  call word ptr [bx-15F3h]      ; opcode 分派
  jmp run
```

**每筆記錄 12 bytes ＝ 六個 word**：

```
op  X  Y  arg1  arg2  0
```

`X`／`Y` 是**相對於呼叫端傳進來的原點**（`sub_10337` 的 `dx`／`bx`）。

清單本身在 `cs:0E16`（檔案位移 `0x1016`），由 `sub_1030F` 在 `start` 裡登記：

```asm
dx = cs / ax = 0E16h / bx = cs / cx = cs:word_10D50
sub_1E993                       ; dword_1EAE9 ← cs:0E16、word_1EAEF ← 圖庫段
```

`word_10D50` 就是 `sub_15A3A` 畫縮小地圖時用的那個圖庫段——
**opcode `09` 的圖形來源是它**。

## 2. 五個 opcode

| op | 參數 | 用途 | 證據 |
|---:|---|---|---|
| `03` | `arg1`／`arg2` ＝ 右下角 | 填矩形 | 場景 0 的兩筆剛好是信賴度量條的槽與資金區的黑底 |
| `06` | `arg1` ＝ 寬、`arg2` ＝ 高 | 未解（尺寸像是一條分隔線）| — |
| `07` | `arg1`／`arg2` ＝ 右下角 | 場景範圍，每個場景的第一筆 | 場景 0 是 `(0,0)–(191,191)` ＝ 192×192，正好是視窗內框 |
| `08` | `arg1` ＝ 字串位址、`arg2` 低 byte ＝ 屬性 | 畫字串 | `cs:16DCh` 起解出來是「君主」「首都」「軍師」「信賴度」「資金」「預備兵」 |
| `09` | `arg1` ＝ 圖庫位移、`arg2` ＝ 寬<<8｜高 | 貼圖 | 場景 0 的四筆是 24×16，位置正好在資金／預備兵三列的左邊 |

## 3. ⭐ 場景 0 ＝ 自勢力情報視窗的內部

`sub_15E2D` 呼叫 `sub_10337(al=0, X=440, Y=200)`，所以下表的「絕對」
＝ 原點 (440, 200) ＋ 記錄裡的相對座標：

| 3 | 03 | (8,104)–(183,183) | (448,304)–(623,383) | **資金／預備兵的黑底**（176×80）|
| 4 | 06 | (120,8) 48×15 | (560,208) | 未解 |
| 5 | 08 | (72,8) | (512,208) | 「君主」 |
| 6 | 08 | (72,24) | (512,224) | 「首都」 |
| 7 | 08 | (72,40) | (512,240) | 「軍師」 |

**與 [`47`](47-main-screen-window-registry.md) §4.2 的動態欄位逐列對上**：
「君主」標籤在 (512,208)、君主名在 (576,208)；「資金」在 (456,312)、
資金數字在 (560,312)；「預備兵」在 (456,328)，三個數字在 (568, 328/344/360)。
**兩份資料來源不同（一份是顯示清單、一份是繪製常式的立即值）而座標對得上**，
所以兩邊都沒讀錯。

四張 24×16 圖形排在資金列與三個預備兵列的左邊，
與說明書主畫面圖上那一直排小圖示相符。

## 4. 為什麼這件事重要

先前 remake 把「君主／首都／軍師」這些標籤當成自己排版的文字，
座標是照參考影片估的。**它們其實是原版資料裡的字串 ＋ 座標**，
可以逐項對齊而不必猜。

同一支直譯器有 11 個呼叫端（各視窗的建構常式），所以其他視窗的內部
版面也在同一份清單裡——**要解某個視窗的內部排版，不必再讀組語，
把它的場景編號印出來就好**。
