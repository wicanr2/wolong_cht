## 驗證契約

- 原版先以獨立模型驗證，再比對原生 C 的完整 RAM、VGA 四 plane、暫存器、FLAGS、SS frame 與裝置軌跡。
- O0／O2 各跑同一固定矩陣；另編譯有意錯誤的 C，確認比較器拒絕它。
- 財政四編輯入口只驗明示輸入路徑，不自動推論所有玩家操作。
- INT61/AH0A 的回覆為明示受控平台條件；不代證原 TSR、音效波形或硬體時間。
- 場景圖使用獨立 E000 scratch，不覆蓋 MDL；隊列 D000 固定 0x400 bytes。
- 拒絕場景涵蓋信賴度恰好減到零。減法借位時，`sub_13DC9` 改用訊息 19E 並呼叫 `sub_11CB1`，恢復啟動堆疊；此非區域跳出不屬於本輪正常返回矩陣，未以 RET 夾具代證。

已證實的跳出定位：`0x13DD2` 扣信賴度，借位後 `0x13DD9` 設零、`0x13DDF` 改 CX=19E；
`0x13DE7` 的 CX=FFFF 分支跳過通知與跳出。通知後信賴度為零才在 `0x13E04` 呼叫 `sub_11CB1`。
`0x11CB1`／`0x11CB6` 從 CS:9903／9901 恢復 SS／SP；保存端為主循環 `0x11BEC`／`0x11BF1`。
定位與原始 bytes 可回查[版控組語](../../tools/c_recovery/KI.code.S)及[整檔收據](assembly-code-verification.json)。
孤立拒絕場景的原版診斷確實在 dosgolem 執行期 CS:IP=`0110:1CB1` 將 SS 從 F000 恢復為原檔初值零；
因此矩陣以 trust=20 取代拒絕場景的 trust=0，保留其他接受、撤回及無效結果的 trust=0。

## 驗證結果

- O0／O2 各 3,348 組，所有 29 原入口均實際執行，十六個實編譯錯版全被拒絕。
- 原版先經獨立模型驗返回值及狀態；C 再比完整 RAM／VGA 四 plane／暫存器／FLAGS／SS frame／IN／OUT／DOS／font／mouse／sound 軌跡。
- 兩側缺字零。INT61/AH0A 回覆使用明示受控條件，不代證原 TSR 音效或硬體時間。
- 負對照分為十五個狀態不符及一個原生除法保護中止；第九錯版另驗固定退出碼、精確 assertion／SIGABRT 訊息及編譯來源，不以任意異常代證。
- [版控收據](c-strategy-verification.json)、[原檔指令與 MZ](c-strategy-code.json)、[Go 冷測](c-strategy-go-verification.json)保存範圍與來源；重跑 `bash tools/c_recovery_strategy.sh`。
- 934 指令／2,184 bytes 全已有組語覆蓋，六筆 MZ 反向重定位與獨立重組通過，新增組語零條。
