## 已證實的流程與定位

| 原始入口 | 原始契約與呼叫 |
|---|---|
| `sub_16C5E` | `sub_17663` 選未編成武將；成功進 `sub_16C92`，退出後 `sub_15E80(AL=8)` 重畫並再選。清單取消才返回上層。 |
| `sub_16C92` | 武將 BX 映射軍團 SI、勢力池 DI；初始化、分兵、畫框、輪詢、切兵種、確定或取消。 |
| `sub_16D56` | 僅寫六槽 type `1,1,3,3,2,2`，不清兵數或其他 bytes。 |
| `sub_16D6F` | 三個預備兵池與軍團總兵力乘 10 後，交原數字 renderer。 |
| `sub_16DA8` | 六個原始兵種圖塊與槽兵數；保存槽 SI，再切 DS 至圖庫。 |
| `sub_16DFD` | 原框、場景 5、肖像、姓名、勢力士氣與六槽／確定熱區。 |
| `sub_16E80` | 關閉原編成框。 |

以上七個函式共 247 指令／561 bytes。依固定輸入 bytes 與 IDA xref 已證實。
共用規則、清單、滑鼠、TALK、字型及 VGA 沿用既有唯一 C 實作。

## 保留的原版邊界

- `0x16CF6` 先呼叫 `sub_14717` 全退六槽，再把所選 type 加一；`>=4` 回到 1，交 `sub_14698` 重分。
- `0x16D14` 只檢查主將槽 `+29h`。0 顯示 TALK #62 並重畫；非 0 交 `sub_16F26` 建立軍團。
- `0x16D42` 取消退兵後不呼叫 `sub_16FD2`。軍團 `+4` 等派生值可能留在退兵前狀態。
- `sub_155EC` 退回預備兵以 `0xFFDC` 飽和，超過上限會截斷。
- 熱區 AL 只排除 `<3Eh`，特判 `44h`；沒有 `>44h` 保護。驗證使用原合法熱區。
- 完整入口採未編成且槽兵數為 0 的合法初始狀態；直接初始化另用非零欄位驗證不清除。
