## 1. 整條生命週期

AI 的軍團只有一個迴圈，每次**走到目標**時由 `sub_14325` 依 `+0x23` 分派：

```
        ┌─────────────────────────────────────────────┐
        ↓                                             │
   Stage 0 ── 到了，據點威脅沒有具體目標 ──→ Stage 1 ──┤
   （移動）                                （在據點決策）│
        ↑                                    │  │  │   │
        │                                    │  │  └───┴→ Stage 9（首都補兵）
        │                                    │  └──────→ Stage 10（走回首都）
        │                                    └─────────→ Stage 2（挑新目標）
        │                                                      │
        └──────────────── 挑到目標 ←───────────────────────────┘
                                                       挑不到 → Stage 11（解體）

   Stage 9 ──補兵──→ Stage 3 ──六槽都 ≥ 300 人──→ Stage 8（等士氣）──→ Stage 1
                        └──任一槽 < 300 人──→ Stage 11（解體）
   Stage 10 ──走到首都──→ Stage 9
   Stage 11 ──走到首都──→ 解散（[`64`](64-corps-arrival-state-machine.md) §3）
```

**四個出口只有兩種：再出擊，或拆回預備兵。** AI 不會讓殘兵在地圖上晃。

## 2. Stage 0（`sub_1439D`，18 B）：到了就換檔

```asm
bx = ax                      ; 目標據點記錄
call sub_14548 / jnb retn    ; CF=0 ⇒ 還沒走到，什麼都不做
test byte [bx], 40h / jnz retn   ; 據點 +0x00 位元 6 ＝ 威脅有具體目標
mov byte [si+23h], 1         ; 否則 → Stage 1
```

據點 `+0x00` 的位元 7 ＝ 受威脅、位元 6 ＝ 威脅有具體目標
（[`40`](40-garrison-relief-request.md) §2）。**位元 6 還亮著就留在 Stage 0**——
這一格還在被盯上，軍團原地駐守。

## 3. Stage 1（`sub_143AF`，96 B）：站在據點上決定下一步

```asm
cmp word [si+0Eh], 800h / jnb → Stage 0    ; 現在節點 ≥ 256：不是據點，繼續走
cmp word [si+4], 12Ch   / jbe → Stage 10   ; 兵力 ≤ 300 點（3,000 人）→ 回首都補兵
bx = ax
test byte [bx], 40h     / jnz → Stage 0    ; 威脅有具體目標 → 駐守
cmp  byte [bx], 80h     / jb  → 出擊       ; 位元 7 沒亮 ＝ 不受威脅
cmp  byte [di+18h], 2   / jbe → 留守       ; ⚠ 見 §3.2
出擊:
    call sub_1ECE0 / al &= 7 / inc al
    [si+0Bh] = al                          ; 延遲 1–8 tick
    [si+23h] = 2
留守:
    cmp word [si+4], 258h / jnb retn       ; 兵力 ≥ 600 點（滿編）→ 不補
    di = 勢力記錄
    cmp ah, [di+3] / jnz retn              ; 這裡不是首都 → 不補
    [si+23h] = 9                           ; → Stage 9 補兵
```

### 3.1 兩個兵力門檻

| 門檻 | 值 | 行為 |
|---|---:|---|
| `0x12C` | 300 點 ＝ 3,000 人 | **以下**就放下手邊的事回首都補兵（Stage 10）|
| `0x258` | 600 點 ＝ 6,000 人 | **以上**視為滿編，站在首都也不補 |

600 點 ＝ 六槽 × 100（[`49`](49-corps-formation-window.md) §5），
與玩家那一側 `sub_14370` 用的是同一個常數（[`64`](64-corps-arrival-state-machine.md) §2.2）。

### 3.2 ⚠ `cmp byte [di+18h], 2`：`di` 沒設就用

`sub_143AF` 從進入到這一行**沒有寫過 `di`**。唯一會走到這裡的呼叫路徑是
`sub_12662` → `sub_128F4` → `sub_14325`，而 `sub_128F4` 的第一件事是
`di = [si+0Eh] × 4` ＝ **現在節點 × 32**。據點記錄在 `0x840 + 編號 × 32`，
所以 `[di+18h]` 落在**據點記錄前面 `0x840` 個 byte** ——那裡是勢力表
（22 × 64 B）與其後未解的 704 B（[`../formats/08`](../formats/08-sinario-save.md) §1.5）。

同一家族的 `sub_1440F` 開頭就是 `mov di, ax`，之後用 `[di+18h]` 讀
**據點 `+0x18`（停在該格的軍團數）**——兩支的指令編碼一模一樣
（`80 7D 18 02` 與 `80 7D 18 01`，檔案位移 `0x45D3`／`0x461B`）。

⭐ **意圖是據點 `+0x18`，寫出來的是別的位址。** 照意圖讀，這一段是
「受威脅、但這一格已經有超過兩支軍團 → 分一支出去打」，語意通順；
照實際位址讀，分支由不相干的資料決定。

**remake 的處置**：實作意圖版（據點 `+0x18` > 2 才出擊），
在 [`../spec/40`](../spec/40-ai-march-decision.md) 標成 remake 差異。
理由是原版讀到的位址在乾淨重寫裡不存在，沒有「照抄」這個選項。
（對照 [`40`](40-garrison-relief-request.md) §4 的位移不對稱——**那一處照抄不修正**，
因為它讀的是有效欄位，只是算式不對稱。**兩者的差別是「算錯」與「讀錯地方」**。）

## 4. Stage 2（`sub_1440F`，87 B）：挑下一個目標

```asm
di = ax                                    ; 目標據點記錄
test byte [di], 40h / jnz → Stage 1        ; 威脅有具體目標
cmp  byte [di], 80h / jb  → 挑目標
cmp  byte [di+18h], 1 / ja → 挑目標        ; 這一格軍團數 > 1
[si+23h] = 1 / retn                        ; 受威脅且只有這一支 → 回 Stage 1
挑目標:
bx = 勢力記錄
test byte [bx], 40h / jnz → 只看求援       ; 勢力 +0x00 位元 6 ＝ 資金吃緊（§6）
al = 0FFh / xchg al, [bx+17h]              ; 取走「被佔走的據點」並清成 FF
cmp al, 0FFh / jnz → 有目標
只看求援:
al = 0FFh / xchg al, [bx+16h]              ; 取走「最近求援的據點」並清成 FF
cmp al, 0FFh / jz → 沒目標
有目標:
cmp [si+20h], al / jz → 略過改寫
    [si+20h] = al / or byte [si], 2        ; 改目標據點
[si+23h] = 0 / dec byte [di+18h] / retn    ; → Stage 0 出發
沒目標:
cmp byte [di], 80h / jnb retn              ; 現在這一格受威脅 → 留著
[si+23h] = 0Bh / dec byte [di+18h] / retn  ; → 解體
```

### 4.1 ⭐ 勢力層的兩個待辦欄是佇列，取一次就清掉

| 欄位 | 內容 | 誰寫 |
|---|---|---|
| 勢力 `+0x17` | **被別人佔走的據點編號** | `sub_13EFD`（[`44`](44-threat-and-reinforcement-ai.md) §1）|
| 勢力 `+0x16` | **最近一次求援的據點編號** | `sub_140B3`（[`44`](44-threat-and-reinforcement-ai.md) §3）|

`xchg al, [bx+17h]`（`al` 先填 `0xFF`）是**取值 ＋ 清空**一步完成，
所以**同一件待辦只會派出一支軍團**。優先序寫死：先奪回失土，再去救援。

**資金吃緊的勢力（勢力 `+0x00` 位元 6）跳過失土那一欄**，只接求援——
沒錢就不主動反攻，這與 §6 的門檻互相呼應。

### 4.2 `dec byte [di+18h]` 是離場的即時扣減

據點 `+0x18` 是**每 tick 從佔用圖抄回來的快取**
（[`../formats/08`](../formats/08-sinario-save.md) §1.6）。軍團決定離開時
先手動減一，同一個 tick 裡後面才被處理的軍團才看得到「這一格少了一支」。
**`sub_125A3` 每 tick 只處理 16 支軍團**，先後順序本來就會影響決策。

## 5. Stage 3（`sub_14466`，29 B）：補完兵的體檢

```asm
al = 1Eh / cx = 6 / bx = si + 29h
loop: cmp al, [bx] / ja → 解體    ; 30 > 該槽兵力
      bx += 4 / loop
[si+23h] = 8 / retn               ; 六槽都 ≥ 30 → Stage 8 等士氣
解體: [si+23h] = 0Bh
```

`si + 0x29` 起、間隔 4 ＝ **六個部隊槽的 `+1` 兵力欄**
（[`../formats/08`](../formats/08-sinario-save.md) §1.7）。

⭐ **任何一槽不到 30 點（300 人）就整團解散。** 補過兵還湊不齊六槽的軍團，
AI 不留——這是「殘兵回收成預備兵」的機制，也解釋了為什麼原版打久了
AI 的軍團數會上下跳。

## 6. `sub_13E11` 是勢力層的資金體檢，不是軍團欄位

`si` 是**勢力記錄**：從 `cs:word_10D1C` 起、每次 `+0x40`、`0x580` 繞回，
＝ 22 × 64 B（[`../formats/08`](../formats/08-sinario-save.md) §1.5）。
機制本身 [`08`](08-hourly-update.md) §1 早就讀過了，remake 也已經照著實作
（`internal/rules/diplomacy` 的 `CanSustainInvasion`）；
這裡重列是因為位元 6 的**消費端**到這一輪才找到（§4.1）。

```asm
si = cs:word_10D1C / ds = cs:word_10D52
cmp byte [si], 80h / jb → 跳過        ; 勢力不存在
and byte [si], 0BFh                   ; 先清位元 6
ax = [si+23h] × 8 + 18h               ; 據點數 × 8 + 24
cmp ax, [si+21h] / jl → 跳過          ; 有號比較；[si+21h] ＝ 資金 >> 8
mov byte [si+19h], 0FFh               ; ★ 取消侵攻目標
ax >>= 1
cmp ax, [si+21h] / jl → 跳過
or byte [si], 40h                     ; ★ 設位元 6
```

| 條件（`資金 >> 8` 與門檻比）| 效果 |
|---|---|
| `資金>>8 ≤ 據點數×8 + 24` | 勢力 `+0x19` ＝ `0xFF`：**放棄侵攻目標** |
| `資金>>8 ≤ (據點數×8 + 24) ÷ 2` | 勢力 `+0x00` 位元 6：**資金吃緊** |

換算成資金本身：**門檻 ＝ 據點數 × 2,048 ＋ 6,144**。
`+0x21` 是 24 位有號資金的高兩個 byte，不是獨立欄位
（[`../formats/08`](../formats/08-sinario-save.md) §1.5），
所以 `jl`（有號）能正確處理疲弊（負資金）。

⭐ 位元 6 的**消費端就是 §4.1** ——沒錢的勢力不反攻失土。
`and byte [si], 0BFh` 每輪先清，代表它是**每次重算的派生旗標，不是狀態**。

**每「時」只檢查一個勢力**（游標 `cs:word_10D1C`），22 個勢力要 22 個「時」轉一圈。
