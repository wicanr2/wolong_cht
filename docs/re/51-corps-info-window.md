⭐ 這個視窗畫空槽時會取到**綠色組的第一張（天秤）**——越界一張，
是原版的顯示瑕疵（§4）。**

## 1. 進入：`sub_17F90`

```asm
sub_12078 / sub_101B4
ds = cs:word_10D52 / si += 2240h        ; → 軍團記錄
sub_1807B                                ; 框 ＋ 場景 4 ＋ 上半（§2）
sub_1812A                                ; 六個槽（§3）
al = cs:byte_10CFF / cmp al, [si+1]      ; ← 這支軍團是玩家的嗎
jnz → 別人的:
  sub_17FDB                              ; 指令輸入（行軍／委任…）
  sub_14325
  or byte ptr [si], 2                    ; 標記「已下指令」
  jmp → 收尾
別人的:
  sub_18853(cx=4)                        ; 狀態列 #4
  sub_121E7                              ; 等右鍵
收尾:
  sub_1817D / sub_18853(cx=0FFFFh) / sub_120D6
```

**同一個視窗兩種行為**：自己的軍團接著開指令流程，別人的只是看。
呼叫者是 `sub_11E46`（地圖上點軍團）與 `sub_1628F`（指令列「軍團」）。

## 2. `sub_1807B`：框、上半與總兵力

```asm
al = 1Fh / dx = 1Bh / bx = 0Ah / cx = 0D0Dh
sub_1895D                        ; 框 (432, 192) 208×208
al = 4 / dx = 1B8h / bx = 0C8h
sub_10337                        ; 場景 4，原點 (440, 200)
```

**矩形與自勢力情報視窗完全相同**（[`47`](47-main-screen-window-registry.md) §4）
——它就是畫在右下那一格，蓋掉自勢力情報。

| 元件 | 座標 | op／來源 |
|---|---|---|
| 底框 | (456, 272) 160×112 | 03 |
| 垂直線 | (560, 208) 長 48 | 06，色 `0x0F` |
| 「將軍」「君主」「首都」 | (512, 208／224／240) | 08，色 `0x0F` |
| 「總兵力」 | (464, 272) | 08，色 `0x0F` |
| 「／」 | (568, 272) | 08，色 `0x0F` |
| 「主將」…「右備」 | (464, 288 + 16k) | 08，色 `0x09` |
| 主將頭像 | (440, 200) | `sub_107D2`，軍團 `+0x02` → 武將 `+0x01` |
| 主將名 | (576, 208) | 軍團 `+0x02` |
| 君主名 | (576, 224) | 該勢力 `+0x01` |
| 首都名 | (576, 240) | 該勢力 `+0x03` 的據點名 |
| 總兵力 | (536, 272) 4 位，色 `0x0F` | 軍團 `+0x04` **× 10** |
| 士氣值 | (584, 272) 3 位，色 `0x0F` | 軍團 `+0x06` |

「總兵力 6000／200」是**一列**：值、斜線、士氣。斜線的 x=568 正好接在
4 位數（536–568）之後，士氣接在斜線（16 px）之後。

⭐ 這裡的士氣讀的是**軍團 `+0x06`**，與編成畫面讀勢力 `+0x1D` 不同
（[`49`](49-corps-formation-window.md) §4）——編成當下軍團還不存在。

## 3. `sub_1812A`：六個槽

與編成畫面的 `sub_16DA8`（[`49`](49-corps-formation-window.md) §3）是同一段程式，
三個立即值不同：

| | `sub_16DA8`（編成）| `sub_1812A`（情報）|
|---|---|---|
| `di` | `3C1Dh` → (232, 192) | `5A48h` → **(576, 288)** |
| 圖示 `bx` | `di − 4` → (200, 192) | `di − 7` → **(520, 288)** |
| 圖庫基底 | `15C0h`（綠色組）| **`12C0h`（紅色組）**|

所以一列是**標籤 (464) → 圖示 (520) → 兵力 (576)**，每列 `+0x500` ＝ 16 px，
兵力 4 位、色 `0x09`、同樣 **× 10**。

## 4. ⭐ 空槽在這個視窗會畫出天秤

圖庫位移是 `基底 + (兵種 − 1) × 0xC0`，而兵種 4 ＝ 空槽
（[`30`](30-corps-formation-ui.md) §4）。兩個視窗算出來的位置不一樣：

| 視窗 | 基底 | 兵種 4 的位移 | 段 3 位移 | 那裡是什麼 |
|---|---|---|---|---|
| 編成 | `15C0h` | `1800h` | `0x21A0` | **全 0 的空白**（[`49`](49-corps-formation-window.md) §3）|
| 情報 | `12C0h` | `1500h` | `0x1EA0` | **綠色組的第一張 ＝ 天秤** |

紅色組只有四張（`0x1BA0`–`0x1DEC`），第五張已經是綠色組的開頭。
**編成畫面那一組後面剛好留了一張空白，情報畫面這一組沒有。**

所以原版在軍團情報裡看到空的編成位置時，那一格畫的是財政視窗的天秤圖示。
這是**越界一張的顯示瑕疵**，不是另一種語意——同一段程式、同一個算式，
只是兩個基底後面接的東西不同。
