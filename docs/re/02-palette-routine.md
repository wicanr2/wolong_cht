## 1. 為什麼不用截圖也能定案

`.BRG` 的通道順序原本是假說（「副檔名可能就是 B,R,G」），
本來打算靠 DOSBox 截圖比對。**結果不需要**——
兩版的調色盤常式各自把檔案位元組直接寫進硬體埠，
而那些埠的語意是公開規格。程式碼自己說了答案。

## 2. DOS/V：VGA DAC

`sub_109D0`（淡入）與 `sub_10A1C`（淡出）是讀 `.BRG` 的迴圈：

```asm
loc_109F3:
        mov     bh, cs:[si]         ; 檔案 +0
        mov     dl, cs:[si+1]       ; 檔案 +1
        mov     dh, cs:[si+2]       ; 檔案 +2
        mov     al, ch              ; 色號
        mov     bl, cl              ; 亮度
        call    sub_1EBDC
        add     si, 3
        inc     ch
        cmp     ch, 10h             ; ← 每組 16 色
        jb      short loc_109F3
```

`sub_1EBDC` 把三個值寫進 VGA DAC：

```asm
        mov     cx, dx              ; ch←dh, cl←dl
        mov     dx, 3C8h
        out     dx, al              ; DAC 寫入索引 = 色號
        mov     dx, 3C9h
        …bh 縮放→bh   ch 縮放→ch   cl 縮放→al…
        out     dx, al              ; DAC 第 1 個 = 紅  ← cl ← 原 dl ← 檔案 +1
        mov     al, ch
        out     dx, al              ; DAC 第 2 個 = 綠  ← ch ← 原 dh ← 檔案 +2
        mov     al, bh
        out     dx, al              ; DAC 第 3 個 = 藍  ← bh ←        檔案 +0
```

VGA DAC 的寫入順序固定是 R、G、B。**所以檔案是 B、R、G。**

寫入前會等兩個完整的垂直空白期（`in al, 3DAh` / `test al, 8` 四段），
避免換色時畫面撕裂。

## 3. PC-98：類比調色盤

`sub_1EF24` 是同一件事的 PC-98 版：

```asm
sub_1EF24:
        out     0A8h, al            ; 色號
        …bh 縮放→bh   dl 縮放→dl   dh 縮放→al…
        out     0AAh, al            ; 綠  ← dh
        mov     al, dl
        out     0ACh, al            ; 紅  ← dl
        mov     al, bh
        out     0AEh, al            ; 藍  ← bh
```

PC-98 類比調色盤埠：`0A8h` 色番号、`0AAh` 緑、`0ACh` 赤、`0AEh` 青。

> **⚠ IDA 把 `0A8h` 註解成「Interrupt Controller #2, 8259A」。那是 PC/AT 的
> 埠對照表，套在 PC-98 上是錯的。** IDA 的自動註解不是 oracle，
> 平台不同就不能信。

**兩版的暫存器→通道對應完全相同**（`bh`＝藍、`dl`＝紅、`dh`＝綠），
而 DOS/V 側的呼叫端明寫 `bh←檔案+0`、`dl←檔案+1`、`dh←檔案+2`。
兩條獨立的證據鏈指向同一個結論。

## 4. 亮度縮放（淡入淡出）

兩版共用同一條式子：

```
al = v << 4                    ; v 是檔案裡的 4 bit 通道值
ax = al * bl                   ; bl = 亮度 0–16
ax = ax + 0x80                 ; 四捨五入
取 ah                          ; = ((v<<4) * bl + 128) >> 8
```

- PC-98 到此為止，`ah` 就是 4 bit 的類比調色盤值。
- DOS/V 再 `shl ah,1` 兩次 → 6 bit 的 VGA DAC 值。

代入 `v=15, bl=16`：PC-98 得 15、DOS/V 得 60。
**兩邊是同一個顏色，只是硬體位寬不同**（PC-98 類比調色盤 4 bit／通道，
VGA DAC 6 bit／通道）。

亮度範圍由呼叫端決定：`sub_109D0` 從 `cl=0` 往上（淡入），
`sub_10A1C` 從 `cl=10h` 往下（淡出）。**所以 `bl` 的滿值是 16，不是 255。**

## 5. 顯示模式：兩版都是 16 色 planar

| 版本 | 證據 |
|---|---|
| DOS/V | `mov dx, 3CEh`（Graphics Controller）35 次、`3C4h`（Sequencer）21 次 → **EGA/VGA 4 平面 16 色**，不是 mode 13h chunky |
| PC-98 | `out 7Ch`（GRCG 模式）53 次、`out 7Eh`（GRCG tile）55 次、`mov cx, 0A800h`（VRAM 段）→ **GRCG 4 平面 16 色** |

**所以 `*GRF.DAT` 的圖像是 4 bpp。** 這是解圖像格式的前提。

一次只有 16 色進硬體，`.BRG` 裡的多組色是**分組切換**用的（§6）。

## 6. `GAMEPAL.BRG` 的 8 組是什麼

| 組 | 與 bank 0 的差異 |
|---|---|
| 0–3 | **只有色號 14 不同**，其餘 15 色完全一樣 |
| 4–7 | 色號 1–14 全換，只有 0（黑）與 15（白）保持 |

### 6.1 banks 0–3 是四季（強證據）

色號 14 在四組裡是：

| 組 | 值 | 顏色 |
|---|---|---|
| 0 | B=6 R=8 G=10 | `#88aa66` 灰綠 |
| 1 | B=1 R=5 G=10 | `#55aa11` 鮮綠 |
| 2 | B=0 R=13 G=8 | `#dd8800` 橙褐 |
| 3 | B=15 R=15 G=15 | `#ffffff` 雪白 |

灰綠 → 鮮綠 → 橙褐 → 雪白，就是**春夏秋冬**。
社群資料說「大地圖風光會隨四時季節變化，北方冬季白茫茫一片」，對上了。

**整個季節效果只換一個顏色。** 這是 1994 年 16 色機器上很經濟的做法：
地表植被統一畫成色號 14，換調色盤就換季。
**remake 要照做**——如果改成四套素材，季節切換的瞬間行為就不一樣了。

### 6.2 ⭐ banks 4–7 ＝ 第二種「畫面模式」的四季

特徵是高飽和純色（青、白、藍、黑、綠、紅、黃、洋紅），色 0 與色 15 固定。

選組的邏輯在載入端，不在送硬體端：

```asm
sub_109AF:                     ; 調色盤載入
  dx = 0D58h                   ; 檔名
  bx = cs / si = 18A4h         ; 目的緩衝區
  ah = 0C0h / mul ah           ; ★ ax ＝ al × 0xC0
  di = 0C0h                    ; ★ 一次載 0xC0 ＝ 192 bytes ＝ **4 個 bank**
  call sub_1E38C

sub_16097:
  al = ds:0CF8h                ; ★ 系統設定的第一個 byte
  call sub_109AF
  call sub_19336
```

`GAMEPAL.BRG` 是 384 bytes ＝ 8 個 bank ＝**正好 2 組**，而 `al` 是
系統選單「畫面模式」那一列的值——它的選項數在設定表 `ds:5FF4h` 裡
寫著 **2**（§6.3）。兩邊對得上：

| al | 載入的 bank | 是什麼 |
|--:|---|---|
| 0 | 0–3 | **「１６色」**的四季（`sub_1006B` 開機時傳的就是 0）|
| 1 | 4–7 | **「 液晶 」**的四季 |

所以 §6.1 的「只換色號 14」對兩組**各自**成立：一組 4 個 bank，
組內是四季、組間是畫面模式。

⭐ **兩個模式的名字在選項字串表裡**（`ds:6002h`，
[`55`](55-system-menu-window.md) §4）：**「１６色」與「 液晶 」**。
說明書第 3.5 節的「類比彩色 ↔ 8 階調液晶」對上了，
而 banks 4–7 那組高飽和純色正是**給 8 階調液晶用的**——
液晶分不出鄰近色階，就改用互相分得最開的純色。

「勢力識別色」那個假說**推翻**：切換是整組 16 色一起換，而縮小地圖
只需要幾個色號，不會為它換掉整個畫面的色盤。

### 6.3 選組的值來自系統選單

`ds:0CF8h` 是系統選單第 2 列（畫面模式）的設定值，
`sub_16062` 點一下就 +1、到選項數就繞回 0。
設定表、選項字串與另外三列見
[`55`](55-system-menu-window.md) §4——**那份是這一組欄位的單一出處**，
這裡只用到「選項數 ＝ 2」這一格。
