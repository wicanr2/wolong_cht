## 1. 選單的選列是「帶狀」不是「絕對座標」

`sub_10414`（IDA `0x10414`）是選單的等待迴圈：

```asm
loc_1044C:
    mov ax, 3 / call sub_20000        ; 取游標與鍵狀態
    test bx, 1 / jnz → 左鍵：AX=5,BX=0，按下次數 ≠ 0 就回 al = [bp+0Eh]（選中的列）
    test bx, 2 / jnz → 右鍵：AX=5,BX=1，按下次數 ≠ 0 就 stc（取消）
    cmp dx, 83h / ja  → 往下
    cmp dx, 64h / jae → 回 loc_1044C   ; 64h ≤ y ≤ 83h：留在原地
往上: mov ax,4 / xor cx,cx / mov dx, 83h / call sub_20000   ; 游標拉回 y=83h
      call 0x1074D                                          ; 選擇往上一格
      jmp loc_1044C
往下: mov ax,4 / xor cx,cx / mov dx, 64h / call sub_20000   ; 游標拉回 y=64h
      call 0x1079B                                          ; 選擇往下一格
      jmp loc_1044C
```

也就是

| 游標 y | 行為 |
|---|---|
| `64h`–`83h`（100–131）| 什麼都不做，繼續等 |
| `> 83h`（> 131）| **選擇下移一格**，游標被設回 `83h` |
| `< 64h`（< 100）| **選擇上移一格**，游標被設回 `64h` |

**這是一個滾輪，不是一張熱區圖。** 選單畫在哪裡與怎麼選列**無關**——
帶的位置是寫死的 `64h`/`83h`，跟選單的 `dx` 位置
（[`../spec/126`](../spec/126-command-popup-menus.md) 的 `40Ch` 那種）沒有關係。

> ⚠ **這解釋了為什麼「點第二列」一直失敗。** 之前的作法是把游標移到第二列
> 的畫面座標再按——而那個 y（95）落在 100 以下，於是迴圈**把選擇往上推**，
> 永遠停在第 0 列。[`../playtest/54`](../playtest/54-menu-second-row-tap.md)
> 量到「5–60 ms 的瞬按都只開選單、不選走第一列」是對的，但那一份沒有再往下
> 走到「選第二列」；[`../playtest/40`](../playtest/40-tactical-parity.md) §1.2
> 記的「框外游標被夾到列 0」是同一件事的表象。

實跑驗證（dosgolem）：開「軍團」選單之後把游標移到 `y=200`（> 131），
第二列「行軍指示」立刻反白；原地按下去，狀態列出現
**TALK #2「請選擇進行行軍指示之軍團。」**——與 [`22`](22-strategy-command-tree.md) §3.3
記的 `al = 1 → 行軍指示：sub_18853(cx=2)` 對上。

## 2. 大地圖上，滑鼠座標就是世界座標

`sub_11F7F` → `loc_11FD0`（IDA `0x11FD0`）：

```
畫面座標 ＝ 滑鼠座標 − 捲動原點      （畫面座標夾在 0..27Fh × 0..18Fh）
畫面座標 < 0    → 原點 += 差值，游標貼到 0
畫面座標 > 27Fh → 原點 += 超出量，游標貼到 27Fh
原點在 ds:9882 / ds:9884，算出來的畫面座標在 ds:9886 / ds:9888
```

關鍵是**滑鼠驅動的範圍不是畫面大小**。實測（讀 `int 33h AX=7`／`AX=8` 設的值）：

| 場景 | 驅動範圍 |
|---|---|
| 大地圖 | **0–6143 × 0–4127** |
| 彈出選單開著 | 0–639 × 0–399 |

6144 × 4128 就是世界地圖的像素尺寸。⇒ **滑鼠座標是世界座標，
而「捲動原點」就是鏡頭的左上角**：

```
畫面座標 ＝ 世界座標 − 鏡頭
鏡頭會自己跟著跑：把滑鼠移到鏡頭視野外，鏡頭就被拖過去
```

實測：載入存檔之後鏡頭在 `(2976,1632)`、滑鼠在 `(3296,1856)`，
畫面游標正好是 `(320,224)`。把滑鼠移到 `(3071,1677)`，
鏡頭變成 `(2432,1278)`、畫面游標貼到 `(639,399)`——`3071 − 639 = 2432` ✔。

> ⚠ **這一條會反咬清單視窗。** 清單開著時滑鼠仍然是世界座標，
> 所以「點清單第一列 `(150,112)`」會把鏡頭拖到世界原點 `(150−150, 112−112)`
> ＝ 地圖左上角的沙漠。症狀是「選完軍團之後畫面跑到沒有城的地方」，
> 而那看起來像遊戲自己捲走了。

## 3. 對 remake 的影響

| 項目 | 處置 |
|---|---|
| 彈出選單選列 | remake 用鍵盤（上下鍵），**行為等價**；原版的帶狀滾輪是滑鼠專屬的操作手感，不影響規則。記在這裡是為了對拍時能走到那些畫面 |
| 鏡頭 | remake 的鏡頭是獨立狀態，不跟滑鼠綁。**這是 remake 差異**（原版沒有「鏡頭」這個獨立概念，鏡頭就是游標推出去的副產物）|
