# 34 — 軍團記錄 `+0x00` 的位元圖，與改用 IDAPython 之後的掃法

**狀態：位元 1／2 的設定端、清除端與語意 confirmed
（位元 1 ＝ 下一步要重算、位元 2 ＝ 委任）。
位元 0／4／5 找到成對的設定與清除點，語意為強證據。位元 3 未見。**

- 日期：2026-08-14
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`

- 位址空間：IDA DOS/V linear address，segment base `0x10000`

[`32`](32-strategy-detail-panels.md) §1.1 找到三處**設定** `+0x00` 位元的地方，
但清除點一處都沒有。要回答「誰清它」必須掃全庫，而這正是 IDC 做不好的事——
所以先換工具（§3）。

## 1. 掃法：解碼運算元，不比對反組譯文字

```python
insn = ida_ua.insn_t()
ida_ua.decode_insn(insn, ea)
d, s = insn.ops[0], insn.ops[1]
mem = d.addr if d.type == ida_ua.o_displ else (0 if d.type == ida_ua.o_phrase else None)
if mem == 0 and s.type == ida_ua.o_imm and insn.get_canon_mnem() in WRITE:
    ...
```

兩個細節決定成敗：

1. **`[si]` 與 `[si+0]` 是不同的運算元型別**（`o_phrase` 對 `o_displ`），
   但語意相同。用文字比對 `+0]` 會漏掉整批 `[si]` 形式——
   而軍團記錄的 `+0x00` 幾乎全是那種寫法。
2. **要篩助憶碼。** 不篩的話 `cmp word ptr [bp+0], 0` 也會被算成「寫入」。
   `WRITE = {mov, and, or, xor, add, sub, adc, sbb}`。

全庫掃出 **133 處**對 `[reg+0]` 寫立即值。以下只取軍團記錄那一批。

## 2. 位元圖

軍團記錄在 `ds:2240h`，127 筆 × 64 B。表裡的函式**已由既有文件確認操作對象是軍團**
的標 ✅；同區但尚未逐支確認的標「候選」。

| 位元 | 設定 | 清除 | 語意 |
|---:|---|---|---|
| 6＋7 | `sub_16F26` 寫 `0xC0` ✅ | `sub_14651` 寫 `0`（候選）| **存在**。建立軍團時整個欄位寫 `0xC0` |
| 0 | `sub_12459`／`sub_126FF`（候選）| `sub_12533`（候選）| 未定 |
| **1** | `sub_142AB` ✅（下行軍令）、`sub_14502` ✅（遷都同步）、`sub_17F90` ✅（玩家點自己的軍團）、`sub_1474A`、`sub_1440F` ✅（AI 挑到新目標）、`sub_144A9`／`sub_144D6` ✅（Stage 10／11 校正成首都）、`sub_14DA4` | **`sub_12662` ✅**（`0x126A5`）| **下一步要重算**（§2.1）|
| **2** | `sub_16E8F` ✅（AI 編成）、`sub_17FDB` ✅ | `sub_1699E` ✅（§2.4）、`sub_17FDB` ✅ | **委任**（交給電腦指揮，§2.2）。`sub_17FDB`（下行軍指令）先 `and 0FBh` 再 `or 4`，是「重設」不是「累加」 |
| 4 | `sub_12B3C`（候選）| `sub_12BA8`（候選）| 未定。`sub_12B3C` 呼叫 `sub_15D19`（小地圖畫點）|
| 5 | `sub_12831` ✅ | `sub_125A3` ✅ | 未定。`sub_125A3` 是**每 tick 只更新 16 支軍團**的那一支，所以位元 5 的生命週期是「一個 tick 內」|

> `sub_12880` 也有 `or byte ptr [si], 20h`，但它碰的是**據點表**（§2.4）。
> **同一個位元值出現在兩張表上，語意無關。**

### 2.1 位元 1 ＝「下一步要重算」

設定端的共通點是**目標變了**：

- `sub_142AB`：玩家下行軍令時寫 `+0x14`／`+0x20`（[`27`](27-list-row-fields.md) §7）
- `sub_14502`：遷都後把掛舊首都的軍團改掛新首都（[`../formats/08`](../formats/08-sinario-save.md)）
- `sub_17F90`：玩家在軍團面板點自己的軍團之後（[`32`](32-strategy-detail-panels.md) §1.1）
- `sub_1440F`：AI 從勢力層的待辦領到新目標（[`65`](65-ai-march-decision-chain.md) §4）
- `sub_144A9`／`sub_144D6`：Stage 10／11 把目標校正成首都（[`64`](64-corps-arrival-state-machine.md) §2）

清除端只有一處，而且**在「還沒到站」那條路上**：

```asm
00012662  bx = [si+0Eh] / cmp bx, [si+14h]
00012668  jnz → 12675            ; ← 沒到站走這邊
0001266A  [si+8] = 4 / sub_128F4 / sub_14325 / retn   ; 到站
…
000126A0  test byte [si], 2
000126A3  jz → 126B4
000126A5  and byte [si], 0FDh    ; ★ 唯一的清除點
000126A8  call sub_147BB         ; 重查道路表，決定下一格
```

`sub_147BB` 拿現在節點與目標節點查道路表（`es = cs:word_19874`），
寫回步進量 `+0x0A`、下一格 `+0x0C`／`+0x0E`。
**所以位元 1 是「路線髒了」的旗標**：設在目標改變的當下，
在下一個移動 tick 重算完就清掉，與到站無關。

### 2.2 位元 2 ＝「委任」（交給電腦指揮）

語意見 [`45`](45-corps-command-mode.md)：玩家在軍團面板下完目標之後，
選單「戰鬥指揮／委任／解體」（`TALK.DAT` #76）決定這一位，
而求援只調得動**委任中**的軍團。下面這一段是它的寫法。

#### 設定與清除擠在同一支

```asm
sub_17FDB:                    ; 下行軍指令
  …
  and byte ptr [si], 0FBh     ; 先清位元 2
  or  byte ptr [si], 4        ; 再設位元 2
```

先清再設看起來多餘，但 `and`／`or` 中間隔了幾條指令（`0x18028` 與 `0x1802D`）。
**這是「無論之前是什麼狀態都重設成 4」的寫法**，不是位元運算的冗餘。
remake 若把它寫成 `flags |= 4` 會在「重複下令」時漏掉中間那段的副作用。

### 2.3 一個沒被用到的位元

位元 3（`0x08`）在 133 處掃描裡**沒有出現**在軍團那一批
（`sub_12977` 的 `mov byte [si], 8` 是整個欄位覆寫，不是位元操作，
而且該支是否操作軍團未確認）。
**沒有出現不等於不存在**——間接寫入（`ptr = &corps; *ptr |= 8`）這種形式，
本掃描抓不到，與 `CLAUDE.md` §4.1 第 4 條講的 xref 盲區同源。

### 2.4 表歸屬是函式層級的，不是指令層級的

`tools/ida_tables.py` 掃每支函式用到的表基址立即值（`0x2240` 軍團、
`0x4240` 武將、`0x840` 據點…），輸出「這支函式碰哪幾張表」。
它替位元圖擋掉兩個誤判：

- `sub_12880` 的 `or [si], 20h` → **據點表**，不是軍團。
- `sub_144A9`／`sub_144D6` 的 `or [si], 2` → **據點表**。

但同一份輸出也差點造成第三個誤判：`sub_1699E` 標成「武將表」，
而它的 `and byte ptr [di], 0FBh` **確實是軍團**——因為
`sub_16E8F` 結尾有 `mov di, si`（`si` 是它算出來的軍團記錄），
`di` 是跨函式帶回來的。那支函式裡的 `add bx, 4240h` 是給訊息用的武將位址。

> **規則：表歸屬只說「這支函式碰過那張表」，不說「這條指令在動那張表」。**
> 一支函式可以同時動三張表（`sub_16F26` 就同時碰軍團、武將職務與據點），
> 而暫存器可以跨函式帶著走。**命中是候選，要配該函式的反組譯才算數。**

## 3. 工具：IDAPython 優先，IDC 當退路

`tools/ida.sh script` **依副檔名選 image**：`.py` 走
`ida-pro-9.4-idapython:py312-v1`，`.idc` 走基底。
**基底 image 跑 IDAPython 是零輸出的靜默失敗**，所以找不到那顆 image 時要停下來建它，
不要退回基底重試——退回去只會得到一份空檔案。

寫 IDC 的代價是**它缺一半內建函式**（`get_func_qty()` 就不存在），
而**缺函式在 headless 底下是靜默中止**：已寫進 `fopen` 緩衝的內容一起消失，
`idat` 的 exit code 仍然是 0。輸出看起來就像「跑完了，沒有命中」。
規則見 [`30`](30-corps-formation-ui.md) §8——**掃描腳本一律帶正對照**。

### 3.1 兩個仍然成立的坑

1. **輸出不進 stdout。** `print` 在 `idat -A` 底下看不到，一律寫檔，
   而且要在檔案裡放 **probe**（函式數、輸入檔 SHA-256）。
   沒有 probe 就分不出「沒找到」與「沒跑到」。
2. **容器的 locale 不是 UTF-8。**
   `open(p, "w")` 配 `json.dump(..., ensure_ascii=False)` 會在寫到第一個中文字時炸，
   而**前面已經寫出去的幾十 KB 會留在磁碟上**——看起來像「輸出被截斷」。
   所有寫檔明寫 `encoding="utf-8"`。
