# 44 — 威脅偵測與 AI 出兵：據點每 tick 掃一次

**狀態：整條鏈逐行讀完。三件事定案：據點 `+0x18` 是佔用圖讀回來的軍團數、
`+0x00` 低 4 位是「哪幾個鄰居是敵方」（不是「哪幾個方向有鄰接」，§5 訂正）、
AI 的軍團數上限 ＝ `max(5, 資金 ÷ 8192)`。**

- 日期：2026-08-14
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：**IDAPython** `tools/ida_dump.py`、`tools/ida_disp_users.py`（新增）
- 位址空間：IDA DOS/V linear address；`si` 是**據點位移**（編號 × 32），
  所以 `[si+840h]` ＝ 據點 `+0x00`、`[si+858h]` ＝ `+0x18`

[`40`](40-garrison-relief-request.md) 把求援鏈讀完時留了三支未讀
（`sub_13FA9`／`sub_140B3`／`sub_14575`）。這一份收掉那三支，
順帶解出它們踩到的四個欄位。

## 1. `sub_13EFD`：每 tick 處理一個據點

`sub_11CD0` 每 tick 呼叫一次，`word_10D1E` 是游標，處理完 `si += 0x20`，
到 `0x1800`（192 × 32）繞回 0。**192 個 tick 掃完一輪全圖。**

```asm
cmp byte [si+857h], 0 / jz +2 / dec byte [si+857h]   ; 求援冷卻 −1
bh = [si+85Ah]                       ; +0x1A 作者填的所屬勢力
cmp bh, [si+841h] / jz 跳過           ; 與執行期所屬勢力相同就沒事
  bx = bh × 64                       ; 原主的勢力記錄
  [bx+17h] = 據點編號                 ; ← 勢力 +0x17
ax = [si+84Ah] × 24 + cs:word_19872  ; 佔用圖：Y × 24 paragraph ＝ Y × 384 B
es = ax
bx = [si+848h]                       ; X
al = es:[bx] & 7Fh
[si+858h] = al                       ; ← 據點 +0x18
cmp byte [si+841h], 18h / jz 跳過     ; 中立據點不做威脅判斷
  sub_13F74                          ; 威脅偵測 ＋ 求援（`40`）
sub_14194 / sub_14269
```

兩個欄位就此定案：

| 欄位 | 內容 | 憑什麼 |
|---|---|---|
| 據點 `+0x18` | **停在該據點那一格的軍團數**（佔用圖的值去掉 bit 7）| `word_19872` 是 98,304 B 的單位佔用圖，每格是計數器（[`08`](08-hourly-update.md) §5：軍團出發 `dec`、到站 `inc`）。這裡每 tick 把它抄進據點記錄 |
| 勢力 `+0x17` | **被別人佔走的據點編號**（原主是自己、現在不是）| 上面那三行；`+0x1A` 是作者填的所屬勢力，`+0x01` 是執行期的 |

> **`+0x18` 是快取不是狀態。** 它每 tick 被佔用圖覆寫一次，
> remake 若把它當獨立欄位維護會漂掉——**要重算，不要記帳**。

## 2. `sub_13FA9`：把鄰居掃成一份威脅清單

`sub_13F74` 先在堆疊上開 16 B 全填 `0xFFFF`，再呼叫這一支填它。

```asm
xor ch, ch
cmp byte [si+85Bh], 0 / jz → retn     ; +0x1B ＝ 0：沒有敵方鄰居，直接回
dl = [si+841h]                        ; 自己的勢力
bx = dl × 64 → dh = [bx+19h]          ; 勢力 +0x19 ＝ 侵攻目標勢力
di = dl × 24                          ; 交友度表的列位址
si += 85Ch                            ; ← +0x1C 起的四個鄰接據點編號
cl = 4
loop:
  bh = [si] / cmp bh, 0FFh / jz 結束   ; 0xFF ＝ 沒有這個鄰居
  bx = bh × 32                        ; 鄰居的據點記錄
  al = [bx+841h]                      ; 鄰居的勢力
  cmp dl, al / jz 下一個                ; 自己的據點
  cmp al, 18h / jz .主要敵人           ; 中立：不算威脅，但仍比對侵攻目標
    di += al
    cmp byte [di+600h], 80h / jnb 下一個 ; ← 交友度：bit 7 ＝ 和平 → 不算威脅
    [bp+0] = 0FEh                      ; 有威脅，但不是侵攻目標
    ch += [bx+858h]                    ; 累加鄰居的軍團數
  .主要敵人:
  cmp dh, al / jnz 下一個               ; 鄰居屬於侵攻目標勢力？
    [bp+0] = 鄰居據點編號
    [bp+1] = 鄰居勢力
    [bp+2] = 鄰居軍團數 ＋ 1
    bp += 4
  下一個: si++ / dec cl / jnz loop
```

回到 `sub_13F74` 之後 `[si+854h] = ch`——**據點 `+0x14` ＝ 鄰接敵方據點的軍團數總和**，
也就是「周邊威脅量」。

### 2.1 那 16 B 是四筆 4 B 的槽，第一個 byte 分三種

`40` §2／§3 用 `cmp [bp+0], 0FEh` 的三個分支判斷，語意現在清楚了：

| `[bp+0]` | 意思 |
|---|---|
| `< 0xFE` | **有具體目標**：那是侵攻目標勢力的據點，編號就寫在這裡 |
| `= 0xFE` | 有威脅，但不是侵攻目標（交戰中的其他勢力，或中立） |
| `= 0xFF` | 初值沒被動過 ＝ **沒有威脅** |

> **分野是「有沒有具體目標」，不是遠近。** `0xFE` 這個哨兵夾在中間，
> 三個分支剛好對應 `jb`／`jz`／`ja`——用一個位元組同時表達「有沒有」與「是不是主要敵人」。

### 2.2 交友度的 bit 7 在這裡再驗一次

`cmp byte [di+600h], 80h / jnb 下一個`：最高位元是 1 就**不算威脅**。
[`../formats/08`](../formats/08-sinario-save.md) §1.55 從資料判定
「最高位元是和平不是交戰」，這裡的用法完全吻合——**和平的鄰居不是威脅**。
兩條獨立證據指向同一個極性。

在記憶體裡這張表在 `ds:0600h`，每列 24 B、22 列（`勢力 × 24 + 對方勢力`）。

## 3. `sub_140B3`：求援之後在勢力記錄裡留一筆

```asm
bx = [si+841h] × 64                   ; 所屬勢力記錄
ax = si × 8 → ah = 據點編號
[bx+16h] = ah
```

**勢力 `+0x16` ＝ 最近一次求援的據點編號。**
劇本檔裡開局全 `FF`，因為那時還沒有人求過援——**「開局是哨兵值」不代表欄位沒用**，
據點 `+0x17`（求援冷卻）也是同一個形狀。

## 4. `sub_14575`：AI 要派幾支軍團

被 `sub_140C9` 的非玩家分支呼叫，此時 `si` 已經換成**勢力記錄**
（`sub_140C9` 在 `00014115` 做 `mov si, bx`），`ch` ＝ 求援的據點編號、
`cl` ＝ 想派幾支。

```asm
bl = 5
ax = [si+21h]                     ; 資金（i24 在 +0x20）的高 16 位 ＝ 資金 >> 8
cmp ax, 0A0h / jle .小
  ax <<= 3 / add bl, 2 / bl = ah  ; ← add bl,2 立刻被覆蓋，是死碼
.小:
bl -= [si+14h]                    ; 減掉現有軍團數
jbe → CF=1 結束                    ; 額度用完，不派
cl = min(cl, bl)
loop:
  al = 勢力編號 (si ÷ 64)
  sub_145C1                       ; 挑人 ＋ 編成 → di
  jb 結束
  ah++ / [di+20h] = ch            ; 軍團 +0x20 ＝ 目標據點
  [di+23h] = 0
  dec cl / jnz loop
一支都沒編成 → CF=1
```

### 4.1 軍團數上限

```
資金 >> 8 ≤ 0xA0（＝ 資金 ≤ 40,960）  →  上限 5
否則                                  →  上限 ＝ 資金 >> 13 ＝ 資金 ÷ 8,192
```

**兩段在交界處連續**：資金 40,960 時 `40960 ÷ 8192 = 5`。
所以整條規則就是 **`上限 = max(5, 資金 ÷ 8192)`**，
而 `add bl, 2` 那一行下一個指令就把 `bl` 覆蓋掉，對結果沒有影響。

> 上限扣掉的是**現有軍團數**（勢力 `+0x14`），不是這次要派的數量——
> 也就是「還能新編幾支」。

### 4.2 `sub_145C1`：挑無職武將裡武力最高的

```asm
di = 4240h / cx = 7Fh              ; 武將表 128 筆 × 32 B
loop:
  cmp al, [di+1Ch] / jnz 下一個      ; +0x1C ＝ 所屬勢力
  cmp byte [di+17h], 0 / jnz 下一個  ; +0x17 ＝ 職務，0 ＝ 無職
  cmp ah, [di+11h] / jnb 下一個
  ah = [di+11h] / si = di           ; ← 取 +0x11（武力）最大的
  下一個: di += 20h / loop
ah == 0 → CF=1（沒人可用）
否則 sub_16E8F                       ; AI 側的編成
```

**AI 派將的規則就是這一行**：自己勢力裡**職務為「無」且武力最高**的那一個。
不看統率、不看智力、不看忠誠——只看武將記錄 `+0x11`。

> 迴圈掃 `0x7F` ＝ 127 次而武將表有 128 筆，**最後一筆掃不到**。
> 這與軍團表 127 筆的上限是同一個模式（[`../formats/08`](../formats/08-sinario-save.md)），
> 照抄。

## 5. ⚠ 訂正：據點 `+0x00` 低 4 位是「哪幾個鄰居是敵方」

`sub_1890A`（由 `sub_188CC` 每個鄰接槽呼叫一次）是這幾位的**寫入端**：

```asm
di = bx + 85Ch / dh = 1 / cx = 4
找出 ah 是第幾個鄰接槽，dh = 1 << 槽號
cmp al, [bx+841h] / jz .同勢力
  test [bx+840h], dh / jnz 跳過
  inc byte [bx+85Bh] / or [bx+840h], dh    ; ← 設位元、+0x1B 加一
  （對另一側的據點記錄做對稱的一份）
.同勢力:
  test [bx+840h], dh / jz 結束
  dec byte [bx+85Bh] / and [bx+840h], ~dh  ; ← 清位元、+0x1B 減一
```

**位元在鄰居屬於別的勢力時設、屬於同一勢力時清**，
並且 `+0x1B` 同步加減——所以：

| 欄位 | 內容 |
|---|---|
| `+0x00` 低 4 位 | 四個鄰接槽裡，**哪幾個目前屬於別的勢力** |
| `+0x1B` | **那幾位的個數**（相鄰敵方據點數）|

「哪幾個方向**有**鄰接」是 `+0x1C`–`+0x1F` 的 `0xFF` 哨兵在管，不是這四個位元。

**動態取樣裁決過了**（[`../playtest/21`](../playtest/21-dosboxx-bridge-sampling.md) §4.1）：
在跑著的 PC-98 原版裡讀回 192 筆據點記錄，全部符合這個讀法；
而「哪幾個槽有鄰居」只對 12 筆，**兩個讀法在 180 筆上給不同答案**。

> **欄位語意要在寫入端定，不在讀取端。**
> `sub_12CDF` 只**讀**這四位（`shr al,1` 逐位測，命中就去看那個鄰居的勢力），
> 而「有沒有鄰接」與「是不是敵方」兩種解讀都能讓那段程式碼說得通——
> **讀取端相容於多種解讀，寫入端只相容於一種**。
> 同一條規則在 [`34`](34-corps-status-bits.md) §2.4 也適用。

`sub_12CDF` 本身是消費者：對每個「敵方鄰居」位元，取那個鄰居的勢力編號，
中立（`0x18`）寫 `600h`，否則把 `勢力 × 24` 追加進一份不重複的清單
（`es:[di]` 掃到 `0xFFFF` 才寫）——**那是在收集「這個據點鄰接哪幾個敵對勢力」**。

## 6. remake 的接線

規則層在 `internal/rules/threat`（純邏輯，不認識 World），
狀態層在 `internal/state` 的 `refreshCityThreat`，接在既有的據點輪轉
（`tickCity`）後面——**節奏照抄：每 tick 只處理一個據點，192 tick 一輪**。
AI 的反應速度是被這個掃描週期限制的，不是被判斷邏輯限制的。

| 原版 | remake |
|---|---|
| 佔用圖 `word_19872` | `occupancyAt(x, y)` 直接數軍團。**佔用數是導出值，記帳會漂** |
| `sub_13FA9` 的威脅掃描 | `threat.Scan`；`City.Threat`／`EnemyNeighbours` 每輪重算 |
| `sub_1890A` 的位元設清 | `threat.EnemyMask` 由現況算，結果相同而且不會因為漏掛 hook 而失同步 |
| `sub_14575` 的軍團額度 | `threat.Budget`；`formAICorps` 的門檻**從「只能有一支」改成上限制** |
| `sub_145C1` 的挑人 | 既有的 `formAICorps`（無職、武力最高）已經是對的 |

求援本身也接上了（[`40`](40-garrison-relief-request.md) §4–§5）：

| 原版 | remake |
|---|---|
| `sub_140C9` 玩家分支 | `requestRelief` 發 `TalkNotice{Index: 38}`，冷卻寫 `亂數(0–15)＋24` |
| `sub_140C9` AI 分支 | 依額度呼叫 `formAICorpsTo(勢力, 求援據點)`，冷卻寫離首都的距離（上限 30，含 §4.1 的位移不對稱）|
| `sub_140B3` | `Faction.ReliefSite` |
| `sub_14155` | `dispatchGarrison` → `threat.Dispatch` |
| `+0x17` 每輪 −1 | `refreshCityThreat` 的第一件事 |

**玩家的據點只從「貼身威脅」那一條收到訊息**——機率路徑的求援分支
原版明確排除玩家（`cmp cl, [si+841h] / jz 結束`），照抄。

還沒接的是喇叭聲（`sub_10CDE`），那是呈現層。
