## 1. 它是誰、什麼時候跑

`KI.EXE` 存活勢力數減到 1 時以離開碼 2 結束，`YNVSHELL.COM` 接著跑這一支
（[`59`](59-game-over-exit-codes.md)）。它只做一件事：把 `END_S1`–`END_S12`
依序放完，中間疊一段逐字打出來的結尾文字，最後停在畫面上等滑鼠。

## 3. 播放順序

`sub_1033D(al)` 是唯一的載圖入口：`al × 13 + 0x554` 是檔名表
（每筆 13 byte，`END_S1  .DAT` 這種 8.3 補空格格式），載進 `word_1053B`。

```
start:
  sub_10443            配 0x5F5E 段的堆積，切成三塊（調色盤/BGM、影像）
  sub_104C7            INT 33h 開滑鼠（結束條件）
  sub_10468            掛 INT 1Ch（計時 ＋ 每次檢查滑鼠鍵）
  sub_1041E            ENDPAL.BRG（段內 0x53E）
  sub_10500            ENDBGM.DAT（段內 0x549）→ INT 61h 播放
  sub_10094            ★ 第一幕：END_S1 ＋ 逐字文字（§4）
  delay(0xC8)
  ax = 1..10: sub_10293   ★ END_S2 … END_S11，一幕一張
  sub_1033D(11)           ★ END_S12（最後一張）
  … 兩段 sub_1178A 貼圖 …
  cx = 0..0x10: sub_1035F(ah=cx) + delay(8)   ★ 17 階淡入
  jmp $                   ★ 停住；INT 1Ch 看到滑鼠鍵才跳去收尾
收尾 loc_1007A: 淡出 → 關 INT 1Ch → INT 10h AH=0 AL=3 → INT 21h AH=4Ch
```

⭐ **結束條件是滑鼠鍵，不是按鍵**——`sub_104C7` 只開了 INT 33h，
而 INT 1Ch 的處理常式每次都問 INT 33h AX=5 的兩顆鍵。

### 3.1 `sub_10293`：第 2–11 幕的節拍

```asm
00010293  push ax
00010294  call sub_1033D            ; 載 END_S(n+1)
00010297  call sub_10335
0001029A  ds = word_1053B / si = 0     / bx = 0     / ax = 0C828h / call sub_1178A
000102AA  ds = word_1053B + 0FA0h / si = 0 / bx = 3E80h / ax = 0C828h / call sub_1178A
000102BE  bx = 幕序 − 2 / jb → 沒有字幕
000102C7  si = cs:[bx*2 + 780h]     ; ★ 每幕的字幕描述子
000102D0  cx = [si]                 ; 筆數
  loop:   dx = [si+2] / bx = [si+4] / ...  ax = 0F01h / call sub_115DE   ; 逐筆畫字串
000102E4  ax = 32h  / call sub_104B5   ; ★ 停 0x32
000102EB  cx = 0..10h：sub_1035F(ah=cx) + delay(2)     ; 17 階淡入
00010302  ax = 320h / call sub_104B5   ; ★ 停 0x320
00010309  cx = 10h..0：sub_1035F(ah=cx) + delay(2)     ; 17 階淡出
```

一幕的節拍是**貼兩半 → 畫字幕 → 停 `0x32` → 淡入 → 停 `0x320` → 淡出**。
以 §4 的單位（1/4 BIOS tick、18.2 Hz）換算：

| 參數 | 單位 | 秒 |
|---:|---:|---:|
| `0x32` | 50 | ≈ 0.69 |
| `0x320` | 800 | ≈ 11.0 |

⭐ **每一幕都有字幕，而且是資料不是程式**：`cs:0x780` 起是一張以幕序索引的
描述子表（幕序 2 起才有，所以第一幕由 `sub_10094` 自己處理），
每筆的開頭是筆數，後面每筆三個 word 交給 `sub_115DE` 畫。
`ax = 0F01h` 與 [`46`](46-strategy-chrome-cell-layer.md) §1 的字串繪製屬性同一組編碼。

## 4. 第一幕的節拍（`sub_10094`）

```
淡出到黑 → 載 END_S1 → 貼上半 (sub_1016D) ＋ 下半 (sub_101B5)
17 階淡入，每階 delay(0x0A)
0xC8 次：delay(0x12) ＋ sub_10238    ★ 逐字打字，一次一個全形字
再貼一次 → 17 階淡出，每階 delay(0x07)
sub_10204 換整頁 → 一邊 si -= 0x50、一邊 dx += 0x50 的捲動，每步 delay(1)
17 階淡入（delay 0x0A）→ delay(0x258) → 17 階淡出（delay 0x0E）
```

`sub_104B5(ax)` 等到 `word_10466 ≥ ax`，而 INT 1Ch 的處理常式**一次加 4**——
所以一個單位是四分之一個 BIOS tick。以未改頻的 18.2 Hz 算：

| 參數 | 單位 | 秒 |
|---:|---:|---:|
| `0x0A` | 10 | ≈ 0.14 |
| `0x12` | 18 | ≈ 0.25 |
| `0xC8` | 200 | ≈ 2.7 |
| `0x258` | 600 | ≈ 8.2 |

打字段落 200 字 × 0.25 s ≈ **50 秒**。

⚠ **「18.2 Hz 未被改頻」是這一段唯一的假設**，還沒實跑量過；
相對比例（第 18 格是第 10 格的 1.8 倍）不受它影響。

## 5. `END_S*.DAT` 的三個 consumer

三支常式讀同一個緩衝區的不同段：

| 常式 | 來源 | 平面 | 幾何 |
|---|---|---|---|
| `sub_1016D` | `si`（呼叫端給，第一幕是 `0x3E80`）| 0、1 交錯 | 400 列 × 每平面 40 B ＝ 320 px 寬 |
| `sub_101B5` | 段 `+0xBB8` ＝ 47,744 B | 2 | 280 列 × 40 B |
| `sub_10204` | 段 `+0xE74` ＝ 59,072 B | 3 | 32,000 B 整頁 |
| **`sub_1178A`** | 0 與 64,000 | 0–3 依序 | **兩半各 200 列的完整 640 × 400**（第 2–12 幕走這一支）|

⭐ 那些位移**指的是解壓後的緩衝區**——這正是先前把格式判成未解的原因：
`0xE74 × 16 + 32,000 = 91,072` 比 `END_S1.DAT` 的 40,999 B 大得多。
解壓之後 `END_S1` 剛好 91,118 B，**多出來的 46 B 是尾巴**。

格式本身見 [`../formats/09`](../formats/09-cutscene-images.md)。
