# 80 — 原版的尋路是反應式的：一條全域佇列，每幀只算兩個兵

**狀態：confirmed。** 全庫**只有一處**呼叫尋路（`loc_1BD46`），
在 `sub_1AED2` 裡；而 `sub_1AED2` 是一條 128 格環狀佇列的消化端，
**每幀最多處理兩筆**。兵平常不尋路——直接朝目標三軸試走，
**走不動才把自己排進佇列**。四個入隊點全部找到了。

## 1. 每幀的順序

```asm
sub_1ADC8:                      ; 戰術層每一幀（seg000:A0A7／A0BB 兩個呼叫點）
        mov cs:word_1D31A, 0
        mov cs:word_1D31C, 0
        mov ds, word_1D30E      ; 兵記錄段
        call sub_1AE56          ; 大將體力／全軍退卻判定
        call sub_1AED2          ; ⭐ 消化尋路佇列（最多兩筆）
        ...逐兵迴圈（sub_1AF69 移動）...
```

**尋路在逐兵迴圈之前**，所以這一幀排進去的請求最快也要下一幀才算得到。

## 2. 佇列本體

| 東西 | 位址 | 說明 |
|---|---|---|
| 寫入游標（尾） | `word_1D34E`（`0001D34E`）| `sub_1C653` 推進 |
| 讀取游標（頭） | `word_1D350`（`0001D350`）| `sub_1AED2` 推進 |
| 元素陣列 | `CS:0xD352`（`0001D352`）| `cs:[di-2CAEh]`，di 從 0 起 ⇒ 基址 `0xD352` |

⭐ **陣列大小獨立佐證**：IDA 在 `word_1D350` 之後印的是
`db 100h dup(0)`——**剛好 256 byte ＝ 128 筆 × 2 byte**，
與游標的 `and di, 0FFh` 完全吻合。兩邊各自算出同一個數字。

`sub_19A33`（開場初始化）把兩個游標都清成 0 ⇒ 空佇列。

### 2.1 入隊：`sub_1C653`

```asm
sub_1C653:
        test byte ptr [si], 10h / jnz .done   ; ⭐ 已經在佇列裡就不重複排
        or   byte ptr [si], 10h               ; 兵記錄 +0x00 bit 4 ＝ 排隊中
        mov  di, cs:word_1D34E
        mov  cs:[di-2CAEh], si                ; 存的是**兵記錄的段內位址**
        inc di / inc di / and di, 0FFh
        mov  cs:word_1D34E, di
.done:  retn
```

⭐ **bit 4 是去重旗標**，所以在飛的請求最多 96 筆（兵的上限），
永遠塞不滿 128 格——這就是佇列做 128 格的理由。

### 2.2 出隊：`sub_1AED2`

```asm
sub_1AED2:
        di = cs:word_1D350
        if di == cs:word_1D34E: retn          ; 空
        cx = 2                                ; ⭐ 每幀最多兩筆
.loop:  si = cs:[di-2CAEh]
        [si]    &= 0EFh                       ; 清 bit 4（不再排隊中）
        [si+16h] = 0                          ; ⭐ 繞路點游標歸零
        [si+12h] = [si+0Ah]                   ; 目標 Z ＝ 目前 Z
        [si+10h] = ([si+6], [si+8])           ; 目標 ＝ 目前座標（先歸位）
        if [si+1Eh] != 0: ...改用高平面的地面層取 Z...
        dx = [si+14h]                         ; 最終目的地
        bx = si*4 + 1800h                     ; 這個兵的繞路點清單（§5.8k）
        bp = 1 / cl = 0EBh                    ; 爬得上去（自我修改碼的開關）
        if [si+4] > 12h:                      ; 兵種／大將閘
            cl = 74h
            if [si+1Ah] != 5: bp = 0          ; 不是退卻中就不准爬
        [si] &= 0FBh                          ; 清 bit 2
        call loc_1BD46                        ; ⭐ 全庫唯一的尋路呼叫
        if !CF:
            [si+17h] = al                     ; 繞路點數
            call sub_1B00D                    ; 取第一個點當這一步的目標
        di += 2 / di &= 0FFh
        if di == 尾 or --cx == 0: break
        cs:word_1D350 = di
```

## 3. ⭐ 四個入隊點，一個都不是「每幀」

`call sub_1C653` 全庫**只有四處**：

| 位置 | 什麼時候 |
|---|---|
| `sub_1AAED`（`0001AB23`）| **下退卻命令**（命令碼 5）。設好邊界目標（側 0 → X=1、側 1 → X=0x3E，Y 夾在 `0x10`–`0x2F`）之後排一次 |
| `sub_1AF69` 的 `loc_1AFD0`（`0001AFD1`）| **三軸都走不動，而且已經試過下一個繞路點**（`ah` 第一趟是 1，`sub_1B00D` 取到下一個點才會歸零重試；第二趟還是不動就排隊）|
| `sub_1B1B1` 的 `loc_1B221`（`0001B221`）| **目標格地形不通**：自己那一層之上有實心、或那一格根本沒有地面（`es:[di+7000h] == 0`）|
| `loc_1B612`（`0001B613`）| 碰撞處理的尾段（撞到人之後）|

⭐ **所以原版預設不尋路。** 兵每幀直接比 `[si+6]/[si+8]/[si+0Ah]`
與 `[si+10h]/[si+11h]/[si+12h]`，朝三軸各試一步；
**只有動不了才會去要一條路**。這與 `sub_1AF69` 的形狀完全一致——
它整支就是三個「大於就往回、小於就往前」的分支。

⚠ **撞到人與撞到地形是分開的兩條路**（[`11`](11-tactical-battle.md) §5.16）：
撞到自己人先試對調，撞到敵人就打；只有這兩條都不成立才輪到重排。

## 4. 這與「每個兵 30 幀一次」不是同一件事

remake 目前用的是**每個兵各自的計時器**
（`replanInterval = 30`，`internal/rules/tactical/soldier.go`）。
兩者的形狀不同：

| | 原版 | remake（改之前）|
|---|---|---|
| 預算 | **全域**每幀 2 次 | 每個兵每 30 幀 1 次 |
| 順序 | FIFO，先卡住的先算 | 沒有順序，同一幀可以有很多個 |
| 去重 | 兵記錄 bit 4 | 靠時間間隔 |
| 最壞情況 | 96 個兵全卡住 ⇒ 每個兵約 48 幀輪到一次 | 同一幀最多 96 次波前擴散 |

⚠ **`docs/re/11` §5.15 的那句「原版沒有這個節流」與
`soldier.go` 的註解「它是在命令生效那一刻算一次」都不對**：
原版有節流，而且不是在命令生效時算——**是走不動的時候排隊**。
兩處已改（推翻紀錄在 `CONTEXT.md`）。
