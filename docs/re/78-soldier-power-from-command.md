## 1. 布陣：`sub_19AF4` 一次擺滿兩側

```asm
sub_19AF4:
        ds = word_1D30A        ; 兩側的戰場摘要，一側 0x20 B
        bx = 0 / di = 0 / si = 0 / cx = 6
  .a:   call sub_19B6D         ; ★ 一個編成位置 ＝ 8 個兵
        si += 4 / di += 100h   ; 8 × 32 B ＝ 256
        loop .a
        bx += 20h / si = 0 / cx = 6
  .b:   call sub_19B6D         ; 另一側六個位置
        …
        di = 0  / bx = 0  / call sub_19B40    ; ★ 覆蓋第 0 號兵 ＝ 大將
        di += 600h / bx += 20h / call sub_19B40
```

一側 **6 個位置 × 8 個兵 ＝ 48 個兵**（`0x600` ＝ 48 × 32），
第 0 號被 `sub_19B40` 再蓋一次，那就是大將。

## 2. `sub_19C13`：取主將的武力、統率與適性

```asm
sub_19C13:                      ; bx ＝ 側摘要記錄
        bh = [bx+2]             ; 軍團編號
        bl = 0 / shr bx,1 ×3    ; × 32
        bx += 4240h             ; ⭐ 武將記錄（軍團 n 的主將是武將 n）
        dl = [bx+11h]           ; 武力
        dh = [bx+12h]           ; 統率
        bl += cs:byte_1D34B     ; ⭐ 戰場類別選三個適性欄的哪一個
        ch = [bx+0Eh] >> 4      ; 適性（0–10）
```

`sub_19A33` 把 `byte_10D34` 分三段寫進 `byte_1D34B`：

| `byte_10D34`（**戰場編號**）| `byte_1D34B` | 適性欄 | 側欄標題 |
|---|---:|---|---|
| `< 0xC0` | 0 | `+0x0E` 攻城 | 據點名 |
| `0xC0`–`0xD0` | 1 | `+0x0F` 陸戰 | 「陸上」|
| `≥ 0xD1` | 2 | `+0x10` 海戰 | 「海上」|

### 2.1 ⭐ 那三段是什麼：原版自己的字是「陸上」與「海上」

⛔ **`byte_10D34` 是戰場編號，不是大地圖圖塊值。** 兩條路寫進去的都是編號：

| 路徑 | 寫進去的是 | 值域 |
|---|---|---|
| 攻城（`0001441E` 一帶）| `(di − 840h) × 8` 的高 byte ＝ **據點編號** | 0–191 ＝ `0x00`–`0xBF` |
| 野戰（`sub_14A7B` → `sub_14B63`）| **算出來的戰場編號** | `0xC0`–`0xD5` |

野戰那一路取五格的地形類型（`sub_14C4C` 查 `cs:982Fh` 的 14 筆範圍表），
中心格的類型決定走哪一條：類型 0 → 平原配對表 `0xC0 + 偏移`、
類型 1–7 → `0xCE + 類型` ＝ `0xCF`–`0xD5`、類型 8／9 → `sub_14C1A`
（橋那一支是亂數 `0xD1`–`0xD4`）。完整的表在
[`05`](05-battle-selection.md) 與 [`58`](58-bgm-scene-mapping.md) §4。

⭐ **語意由原版自己的字串定案。** `sub_1C955` 用 `byte_1D34B` 選側欄標題
的第一段（[`60`](60-tactical-sidebar.md) §11）：

```
類別 0 → 據點名（攻城，畫「<城名> 作戰」）
類別 1 → CS:0xD45E ＝「陸上　」
類別 2 → CS:0xD464 ＝「海上　」
```

`CS:0xD46A` 起就不是字串了，所以那張表就兩筆。
「陸上作戰」也在實機截圖上看得到（[`../playtest/43`](../playtest/43-field-battle-parity.md)
的 `sb-title` 逐像素 PASS）。

⇒ **`+0x0E`／`+0x0F`／`+0x10` ＝ 攻城／陸戰／海戰適性**，三格都 confirmed。
與 [`../formats/08`](../formats/08-sinario-save.md) §3 由 `sub_152D7`
定出來的「`+0x0E` ＝ 攻城適性」一致，兩條獨立的路指到同一格。

⭐ **海戰適性在 DOS/V 是到得了的**：橋（圖塊 `0xCA`）的戰場編號就落在
`0xD1`–`0xD4`。[`../formats/08`](../formats/08-sinario-save.md) §3 的
「沒有可達的呼叫點」只涵蓋 `sub_152D7`（委任的自動判定）那一側。

> **教訓寫成規則**：**「值域看起來對得上」不是對映。** 這一節第一版拿
> 大地圖的圖塊分布去湊那三段，數字看起來很合（道路 `0xC0`–`0xD0` 佔
> 4,993 格），結論也剛好對——**但中間那一步是錯的**，而錯的那一步
> 被 remake 照抄成「拿圖塊比門檻」，於是橋上的野戰取到陸戰適性
> （[`../spec/115`](../spec/115-soldier-power.md) §3.1）。
> 分類的表就在 `sub_14C4C`，`05` 早就標成 confirmed 了。

## 3. ⭐ 一般部隊：`sub_19B6D`

```asm
        ah = [bx+6]                     ; 側摘要 +6 ＝ 軍團士氣
        al = [bx+si+0Ah]                ; 這個位置的兵種 k
        call sub_19C13                  ; dl=武力 dh=統率 ch=適性
        dh += ch                        ; 統率 ＋ 適性
        bx = k − 1
        dl = dh; dl = dl*2 + dh         ; ×3
        dl += cs:[bx-63F1h]             ; ★ 每兵種係數
        dl >>= 2                        ; ÷4
        …
        cx = 8
  .fill: es:[di+3]  = ah                ; 體力 ← 士氣
         es:[di+4]  = al                ; 兵種 × 18
         es:[di+18h] = dl               ; ⭐ 戰力
         es:[di+19h] = 80h              ; 餘力滿
         es:[di+1Ah] = 1（word）
         di += 20h / loop
```

**每兵種係數在 `seg000:9C0F`，原始 bytes `1E 04 0C 00`：**

| 兵種 `k` | 係數 |
|---:|---:|
| 1 | **30** |
| 2 | **4** |
| 3 | **12** |
| 4 | 0（沒有第四種）|

所以

```
戰力 = ((統率 + 適性) × 3 + 兵種係數) ÷ 4
```

### 3.1 ⭐ 騎兵的戰場修正是死碼

```asm
        mov bl, al          ; bl ＝ 兵種 k（設了之後沒有人讀）
        shl al,1 / mov cl,al / shl al,1 / shl al,1 / shl al,1 / add al,cl
                            ; al ＝ k × 18
        cmp al, 1           ; ⭐ 永遠不成立
        jnz  loc_19BBA
        cmp cs:byte_1D34B, 1
        jb   loc_19BBA
        ja   loc_19BB2
        shl dl, 1           ;   類別 1：戰力 ×2
        jmp  loc_19BBA
loc_19BB2:
        shr dl,1 ×3 / inc dl ;  類別 2：戰力 ÷8 ＋ 1
```

`al` 在比較之前已經被換成「兵種 × 18」，所以 `cmp al, 1` 恆為假，
**底下那兩條修正一次都跑不到**。原始 bytes 是 `3C 01`（`cmp al, 1`），
不是 `80 FB 01`（`cmp bl, 1`）——交叉解碼過，不是 IDA 讀錯，
也沒有人寫 `cs:[19BA1]`。

⭐ **`mov bl, al` 設了 `bl` 之後沒有任何指令讀它**，而那正是這個比較
應該用的暫存器。**強證據：原版打算比兵種，寫成了比 `al`。**
照抄原版就是「這兩條修正不存在」。

## 4. ⭐ 大將：`sub_19B40`

```asm
        call sub_19C13
        al = dl                         ; 武力
        dl = dl*2 + ch                  ; 武力 × 2 ＋ 適性
        dl <<= 1                        ; ×2
        es:[di+18h] = dl                ; ⭐ 大將的戰力
        es:[di+4]   = 0                 ; 兵種 0 ＝ 大將
        al = al*4 + 32h                 ; 武力 × 4 ＋ 50
        al = al × es:[di+3] / 64h       ; × 士氣 ÷ 100
        if al < 46h: al = 46h           ; 下限 70
        es:[di+3] = al                  ; ⭐ 大將的開場體力
```

```
大將戰力   = (武力 × 2 + 適性) × 2
大將開場體力 = max(70, (武力 × 4 + 50) × 軍團士氣 ÷ 100)
```

⚠ **大將的開場體力不等於軍團士氣。** 一般兵是（[`../spec/61`](../spec/61-soldier-initial-hp-from-morale.md)），
大將這一格被 `sub_19B40` 蓋掉了。

## 5. ⭐ 近戰怎麼用戰力：`sub_1B6BC`

**分工在 `loc_1B5A1`**（[`11`](11-tactical-battle.md) §5.16–§5.17）：
擋路的對方**不是大將就走 `sub_1B618`**（一般近戰），**是大將就走這一支**。
remake 兩支都接了——`internal/rules/tactical/damage.go` 的 `attackCollision`
照同一個判準分流（`meleeHit`／`hitGeneral`）。

`si` ＝ 攻方，`di` ＝ 守方：

```asm
        cmp [di+3], 1 / jbe  .miss      ; 守方體力 ≤ 1
        al = [di+1Ah] ; ==0 或 ==5 → .miss   ; 守方沒有生效命令
        rand; if al < 19h → .hit        ; ⭐ 25/256 ≈ 9.8% 必中
        rand2
        ah = 攻方[+18h] − 守方[+18h]，負數取 0
        if ah > 18h: ah = 18h           ; 上限 24
        if (rand2 & 7Fh) >= ah → .miss  ; ⭐ 命中率 ＝ ah / 128
.hit:   守方 [+1]=2（被打中）、[+2] 設 bit 4、[+5]=0、[+0] 設 bit 6
        傷害 = max(1, 攻方[+18h] >> 3)
        守方[+3] −= 傷害，下限 1
```

| 量 | 算式 |
|---|---|
| 命中率 | `9.77% + (1 − 9.77%) × min(24, max(0, 攻 − 守)) ÷ 128` |
| 傷害 | `max(1, 攻方戰力 ÷ 8)` |

⭐ **戰力同時決定命中率與傷害**，而戰力來自統率（一般兵）或武力（大將）。
