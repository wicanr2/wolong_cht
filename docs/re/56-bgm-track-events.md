## 1. 怎麼找到播放引擎的

[`23`](23-bgm-resource-format.md) 解出資源 parser 會把六個聲軌指標存進
`cs:09E6h + si`（`si` ＝ `0x10`…`0x1A`），也就是實際落在
**`cs:09F6h`–`cs:0A00h`**；另有六個狀態 word 在 `cs:0A02h`。

**播放引擎一定要讀寫這兩塊**，所以直接掃 COM 裡的立即值：

| 立即值 | 命中 |
|---|---|
| `09E6` | 1 處（parser，已知）|
| `0A02` | 4 處：`023C`（parser）、**`032F`／`03F3`／`0426`** |
| `099A` | 4 處：`0227`、**`0283`／`0554`／`0622`** |

三個新命中就是引擎。

⚠ **IDA 對這個 COM 只認出 5 支函式**，其餘整片是 `db`——
`tools/ida_range.py` 對資料項只印得出一行，看起來就像「那裡沒有程式碼」。
所以新增了 `tools/ida_decode.py`：`del_items` ＋ 逐位址 `create_insn` 強制解碼。

## 2. ⭐ 事件是 2 bytes 一筆

INT 8 的 ISR 在 `0x103AC`（換 stack），主體 `0x103DE`：

```asm
ds = cs / es = [0992h]           ; 資源段
bx = 0                           ; 聲軌編號
loop:
  byte [0A4Ah] = 0
  si = bx << 1
  dec word [si+0A02h]            ; ⭐ 這一軌的倒數計數器 −1
  jg → 下一軌                     ; 還沒歸零就什麼都不做
  di = [si+09F6h]                ; 目前的事件指標
  ax = es:[di]                   ; ⭐ 讀 2 bytes
  cmp al, 80h / jnb → 控制事件（§5）
  test ah, 80h / jnz → 跳過 key-off
    ah = bl / call 106BFh        ; 先 key-off
    byte [0A4Ah] = 1
  and ah, 7Fh
  bl = ah / al = [bx+0AB0h]      ; ⭐ 長度表
  [si+0A02h] = ax                ; ⭐ 寫回倒數計數器
  test al, 0Fh                   ; 低 byte 的低 4 位
  jz  → ah = bl / call 106BFh    ; ＝ 0：休止（key-off）
  jnz → ah = bl / call 1069Eh    ; ≠ 0：設音高
        若剛才 key-off 過，再 call 106BFh（cl = bl | 0F0h）
  di += 2 / [si+09F6h] = di      ; ⭐ 指標前進 2
  bx++ / cmp bl, [0A4Ch] / jb loop
```

| byte | 位元 | 意義 |
|---|---|---|
| 低（`al`）| 0–3 | **音名 1–12**，`0` ＝ 休止 |
| | 4–6 | **八度** |
| | 7 | 設起來就是**控制事件**，整筆改走另一條路（§5）|
| 高（`ah`）| 0–6 | **長度索引** → 查 `0AB0` 得 tick 數 |
| | 7 | **連音**：不先 key-off |

## 3. 三張查表在 TSR 裡，不在資料裡

### 3.1 長度表 `0AB0`（32 筆）

```
C0 60 30 18 0C 06 03 00   00 90 48 24 12 09 00 00
80 40 20 10 08 04 02 01   C0 60 30 18 0C 06 03 00
```

`C0 60 30 18 0C 06 03` ＝ 192／96／48／24／12／6／3 ——**每次減半**，
所以全音符 ＝ 192 tick。`90 48 24 12 09` ＝ 144／72／36／18／9 ＝
**附點**（192 × 0.75 ＝ 144 ✓）。第三列 `80 40 20 …` 是另一組基底。

### 3.2 ⭐ 音高：`0AD0` ＋ `0B50` 就是 OPL 的 `B0`／`A0`

```asm
1069Eh:  bl = al / ch = [bx+0AD0h]     ; 整個低 byte 查表
         bl &= 0Fh / cl = [bx+0B50h]   ; 低 4 位查表
         ch |= 20h                     ; ⭐ key-on 位元
         [bx+0A0Eh] = cx               ; 存成這一軌的待寫值

106BFh:  cx = [bx+0A0Eh]
         cmp ah, 0F0h / jnb → 保留；否則 cx = 0   ; ⭐ 清零 ＝ key-off
         dx = [097Ch]                  ; OPL 基底埠
         cmp ah, 3 / jnb → ah −= 3, dx += 2      ; ⭐ 聲軌 3–5 走第二組埠
         al = ah + 0A0h / ah = cl / call 10890h  ; ⭐ 暫存器 A0+n
         al += 10h      / ah = ch / call 10890h  ; ⭐ 暫存器 B0+n
```

`A0+n` ＝ F-Number 低 8 位、`B0+n` ＝ key-on ｜ block ｜ F-Number 高 2 位
——**這是 OPL 的標準暫存器對**。

| 表 | 筆數 | 索引 | 內容 |
|---|---:|---|---|
| `0B50` | 16 | 低 byte 的**低 4 位**（音名）| `00 55 6B 81 98 B0 CA E5 02 20 41 63 87` ＋ 三個 0 |
| `0AD0` | **128** | **整個**低 byte | 每 16 格一個八度，值是 `block << 2 ｜ F-Num 高 2 位` |

⚠ **`0AD0` 是 128 筆不是 32 筆。** 表的邊界是 `0x0AD0` 到 `0x0B50`，
中間沒有別的東西；`1069E` 用整個低 byte（`bl = al`）當索引，
所以八度 0–7 各佔 16 格。只讀前 32 筆的話八度 2 以上會全部退回低音域——
**而聽起來仍然是同一首曲子，只是低了幾個八度**（§4）。

**驗算**：音 1 的 F-Number ＝ `(01 << 8) ｜ 55` ＝ 341，
音 8 ＝ `(02 << 8) ｜ 02` ＝ 514。514 ÷ 341 ＝ **1.507**，
而七個半音是 2^(7/12) ＝ **1.498** ✓
音 12 ＝ 647，647 ÷ 341 ＝ 1.897，十一個半音是 1.888 ✓

換成實際頻率（`f = fnum × 2^block × 49716 ÷ 2^20`）：
**八度 4 的 A ＝ 437.7 Hz**，標準音 A4 是 440——差 0.5%，就是 F-Number 的量化。
八度 0 的 C ＝ 16.2 Hz、八度 7 的 A ＝ 3,501.7 Hz，
整張表覆蓋 16 Hz–4 kHz。

## 4. 拿真實資料驗

`tools/bgmdump.py` 對 `BGM.DAT` 第 1 曲（`dosv`）：

```
聲軌 1：音量15 音色0 旗標0 休/3 記號 速度184 音量11 音色1 … A1/72  E2/72  D2/24
聲軌 2：…                                                  D4/48  A3/24  A4/48  E4/24
聲軌 3：…                                                  A3/48  D4/24  E4/48  A4/24
聲軌 4：…                                                  F5/24 ×6
```

**三件事同時成立才算解對**：音名落在 1–12、八度分層（聲軌 1 低音、
2–3 中音、4 高音）、時值是 24／48／72 這種二分與附點。

⭐ **再往前一步是拿原版錄音當對照組**（`docs/playtest/25` 錄的開場曲）：
把 `internal/audio` 渲染出來的 `OPENBGM.DAT` 與那份錄音各取同一段做頻譜，
**前十個峰值有七個落在同一個頻率格**（A5 877.5、C6 1033.6、E7 2621.7、
A7 3504.5、G5 780.6、D7 2293.3、G7）。
⚠ 這個檢查也是「128 筆」那個錯**唯一**被抓到的地方：
音色編號範圍、十二平均律比值、音域分層三個檢查**全部照樣通過**，
因為它們都只碰得到表的前 1/4。**能通過的檢查沒有覆蓋到的地方，錯誤就住在那裡。**
兩版都解得通，`pc98` 的差別在音色編號與用幾軌，
與 [`23`](23-bgm-resource-format.md) §4 記的「兩版音樂資料有實質差異」一致。

## 5. ⭐ 控制事件：低 byte ≥ `0x80`

分派在 `0x1045B`：指標**先前進 2**，再用 **bit 4–6** 查 `cs:0473h` 的八格跳表。
**控制事件不佔時間**——處理完 `jmp 0x103FB` 直接讀下一筆，所以可以一串接一串。

| 低 byte | handler | 高 byte 的意義 |
|---|---|---|
| `80`–`8F` | `0x10483` | **音量 0–15**（加上這一軌的漸變偏移後夾在 0–15），套用方式見 [`57`](57-opl3-register-map.md) §4 |
| `90`–`9F` | `0x1049E` | **音量漸變**：低 byte 的 bit 0 ＝ 方向（0 漸強／1 漸弱）；高 byte 高 nibble ＝ 次數、低 nibble × 4 ＝ 每步幾個 tick。每 tick 由 `0x1075E` 推進 |
| `A0`–`AF` | `0x104CA` | **音色編號**，立刻把整組 operator 參數重寫一次 |
| `B0`–`BF` | `0x104D4` | **速度**：`分頻 = (255 − 值) × 11 ÷ 8`（[`57`](57-opl3-register-map.md) §5）|
| `C0`–`CF` | `0x104DA` | **跳轉**：`C1` 迴圈回跳（次數遞減，歸零就往下走）、`C2` 呼叫子段、`C3` 子段返回、其餘 ＝ 無條件跳到記號 |
| `D0`–`DF` | `0x10512` | **設記號**：`D1` 迴圈起點（高 byte ＝ 次數）、`D2` 子段入口、其餘 ＝ 無條件跳的目標 |
| `E0`–`EF` | `0x10537` | 只有一個 `retn`，**無作用** |
| `F0`–`FF` | `0x10538` | 高 byte 存進 `cs:0999h` ＝ **給遊戲讀的同步旗標**（INT 61h `AH=0x0A`）|

`C` 族靠堆疊換掉呼叫端的 `di`（`pop dx` 取回返位址、`pop di` 取回指標，
改完再 `push` 回去），所以**跳轉是真的改讀取位置**，不是設旗標。

⭐ 每首曲子每一軌的開頭都是同一組：`音量15`、`音色0`、`旗標0`、`休止 3 tick`、`設記號`。
`音色0` 是靜音 patch（TL 全滿），等於**先把這一軌歸零再開始**。
