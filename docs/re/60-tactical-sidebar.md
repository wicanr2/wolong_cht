## 0. 兩條讀這一份要先知道的換算

**繪圖與熱區常式的參數是 `dx` ＝ X、`bx` ＝ Y**（[`46`](46-strategy-chrome-cell-layer.md)）。
`sub_1FA37` 的 `bx` 例外——那是**顯示記憶體的 byte 位移**：

```
位移 = y × 80 + x ÷ 8          （640 px ÷ 8 ＝ 80 bytes／列）
```

`sub_1E3D7`（熱區註冊）的 `cx` 是**以 8 px 為單位的尺寸**：
`ch` ＝ 高 ÷ 8、`cl` ＝ 寬 ÷ 8。命中圖是一張 80 × 50 的 byte 陣列，
每格存一個熱區碼；重疊時回 CF=1。

## 1. 側欄的骨架：`sub_1C7A9`

## 3. 標題格的三段文字

先 `sub_1F1A3` 把 (496,8)-(623,39) 填色 0，再畫。
全部走 `sub_106FD`＝**固定三個全形字**（[`33`](33-shared-draw-helpers.md) §1），
所以每一段就是 48 px 寬，`ah` 是調色盤索引。

| 位址 | 座標 | 內容 | `ah` |
|---|---|---|---:|
| `0001C9A6` | (512, 8) | **戰場地名** | 9 |
| `0001C975` | (560, 8) | `cs:0xD458` ＝「作戰　」 | 9 |
| `0001C9E1` | (512, 24) | **我方君主名** | 11 |
| `0001C966` | (560, 24) | `cs:0xD452` ＝「對　　」 | 11 |
| `0001CA25` | (576, 24) | **對方君主名** | 11 |

兩行讀起來就是：

```
濟陰 作戰
呂布 對曹操
```

「對　　」的後兩個全形空白被隨後畫的對方君主名（x=576）蓋掉——
**繪製順序是版面的一部分**，先畫 `sub_1C955` 再畫 `sub_1C9AB`。

### 3.1 戰場地名的兩條路（`sub_1C955`）

```asm
0001C978  mov al, byte_1D34B          ; 戰場類別
0001C97B  and al, al / jnz .field
          ; 攻城戰
0001C97F  mov si, word_10D32 / add si, 2   ; 據點記錄 +2 ＝ 據點名
0001C986  mov ds, cs:word_10D52
          jmp .draw
.field:   ; 野戰：cs:0xD45E 起每筆 6 B
0001C98D  si = 0xD45E + (al − 1) × 6
.draw:    ax = 0x0901 / dx = 0x200 / bx = 8 / call sub_106FD
```

`cs:0xD45E` 的表**只有兩筆**（`0xD46A` 起就是程式碼）：

| 類別 | 字串 | 戰場編號 | 出處 |
|---:|---|---|---|
| 0 | 據點名（`word_10D32 + 2`）| < `0xC0` | 攻城戰 |
| 1 | 「**陸上　**」 | `0xC0`–`0xD0` | `sub_19A33`（[`58`](58-bgm-scene-mapping.md) §4）|
| 2 | 「**海上　**」 | ≥ `0xD1` | 同上 |

⭐ 這是「戰場類別 2」第一次拿到名字。[`58`](58-bgm-scene-mapping.md) §4 從曲號
把它認成「山地／林地／水域」，畫面上的字是「**海上**」——
兩者不衝突：類別 2 的戰場編號 `0xD1`–`0xD5` 涵蓋山地、林地與水域，
而標題只有兩種字可選，非攻城非平原一律寫「海上」。

## 4. ⭐ 上下兩格分別是誰（`sub_1C9AB`）

```asm
si = (word_10D2E − 0x2240) >> 1      ; 我方（[09](09-combat.md) §2）
f  = [si + 0x425C]                    ; 武將表 +0x1C ＝ 所屬勢力編號
lord = [f × 64 + 1]                   ; 勢力表 +0x01 ＝ 君主的武將編號
畫 武將表[lord] +2 於 (512, 24)，ah = 11
畫 武將表[si]   +2 於 (528, 221)，ah = 15    ; ★ 下面那一格

si = (word_10D30 − 0x2240) >> 1      ; 對方
…同上…
畫 君主名 於 (576, 24)，ah = 11
畫 主將名 於 (528, 52)，ah = 15             ; ★ 上面那一格
```

`f × 64 + 1` 與 `lord × 32 + 0x4242` 兩段和 `sub_188B0` 完全相同
（[`33`](33-shared-draw-helpers.md) §1）——**勢力沒有名字欄位，
畫面上的「勢力名」就是君主的姓名。**

| | `word_10D2E` | `word_10D30` |
|---|---|---|
| 語意 | **我方**（[`09`](09-combat.md) §2）| **對方** |
| 主將名畫在 | (528, **221**) ＝ 下面那一格 | (528, **52**) ＝ 上面那一格 |
| 君主名畫在 | (512, 24) ＝ 左 | (576, 24) ＝ 右 |
| 將旗美術 | 段 1 `0x1000` | 段 1 `0x0800` |

**攻守不決定上下。** `sub_14ED7` 依玩家是攻是守互換這兩個變數
（[`58`](58-bgm-scene-mapping.md) §4），所以側欄永遠是「我方在下、對方在上」。

### 4.1 軍團表的索引就是武將編號（強證據）

`(軍團記錄位址 − 0x2240) >> 1` 直接被當成**武將表的 byte 位移**用，
`sub_1C315` 也做同一件事（`add bx, 4240h`）。軍團記錄 64 B、
武將記錄 32 B，所以這個換算只有在「**軍團 n 的主將就是武將 n**」時成立。
127 × 64 ＝ `0x1FC0`，`0x2240 + 0x1FC0` ＝ `0x4200`，
正好是城兵臨時軍團的基址——邊界對得上。

⚠ 城兵臨時軍團（`0x4200`，n ＝ 127）照這個算式會指到武將表的第 127 筆，
而那一筆在劇本檔裡是全零。守城方的主將名怎麼來的**未解**（§10）。

## 5. 每一格的兩條計量條（`sub_1C6F6`）

`sub_1C6F6` 由 `sub_19946` 與 `0x1A0AA`／`0x1A0BE` 呼叫，是**每幀更新**的那一支。
四條都在 x ＝ 498、2 px 高、總長上限 124 px，未填的部分畫成色 0
（`sub_10AAA` → `sub_10AD9`）。

| y | 格 | 來源 | 算式 | 換算那一支 | 色 |
|---:|---|---|---|---|---:|
| 72 | 上（對方）| `word_1D30A:+0x24` | 值 >> 2 | `sub_1C775` | 12 |
| 75 | 上（對方）| `word_1D30E:+0x603` | 值 × 3 ÷ 4 | `sub_1C78E` | 11 |
| 211 | 下（我方）| `word_1D30A:+0x04` | 值 >> 2 | `sub_1C775` | 12 |
| 214 | 下（我方）| `word_1D30E:+0x003` | 值 × 3 ÷ 4 | `sub_1C78E` | 11 |

兩支換算常式的上限都是 `CH = 0x7C` ＝ **124 px**（remake 的
`battleSideBarMaxLen`）。

- `word_1D30A` 是兩軍的編成摘要，每側 32 B，`+0x04` ＝ **兵力**
  （[`11`](11-tactical-battle.md) §3.9）。側 0 在 `+0x00`、側 1 在 `+0x20`。
- `word_1D30E` 是單位記錄段，每側 `0x600` B
  （[`11`](11-tactical-battle.md) §3.6）。`+0x03` ＝ **體力**，
  開場由 `sub_19B6D` 從士氣複製過來（[`11`](11-tactical-battle.md) §3.9）；
  讀的是每側第 0 個單位，也就是**大將**。

⭐ **側 0 ＝ 我方、側 1 ＝ 對方**：`+0x04`（側 0）畫在下面那一格，
而下面那一格是 `word_10D2E`＝我方（§4）。這也解釋了為什麼戰術腳本 VM
把側別寫死在 1（[`11`](11-tactical-battle.md) §3.5）——**腳本是對方在跑的**。

## 6. 指令面板（y 280–376）

段 1 `0x1800` 的 128×96 面板是**單欄六列**，每列 16 px。
六個文字熱區在 x 496 寬 48，右側另有三個熱區在 x 552 寬 64。

### 6.1 六列指令：讓遊戲自己說

`0x1C1B9` 是六列共用的 handler：`al − 7` ＝ 命令碼，
寫進被選中各隊的單位記錄 `+0x1B`（新下達的命令，每隊 `0x100` B），
再以 `cx = 命令碼 + 0x1B1` 叫出台詞。
索引 ≥ `0x196` 走 ×8 展開（[`25`](25-message-variants-and-personnel.md) §1），
下表是展開後 `ah=0`（說話型 0）的那一句。

| y | 熱區 | 命令碼 | `cx` | 展開後 | 台詞 | 按鈕 |
|---:|---|---:|---|---:|---|---|
| 280 | `0x09` | 2 | `0x1B3` | 638 | 好啊！衝啊！！！ | **突擊** |
| 296 | `0x08` | 1 | `0x1B2` | 630 | 前進！轉為攻擊！ | **攻擊** |
| 312 | `0x07` | 0 | `0x1B1` | 622 | 擺出陣形！！ | **陣形** |
| 328 | `0x0A` | 3 | `0x1B4` | 646 | 登上城壁！ | **城壁** |
| 344 | `0x0B` | 4 | `0x1B5` | 654 | 擺出陣形！！ | **守陣** |
| 360 | `0x0C` | — | `0x1AF` | 606 | 全軍撤退！！ | **退却** |

兩個分支：

- 命令 3（城壁）在 `byte_1AB4F == 0`（野戰，這張圖沒有城）時
  改走 `cx = 0x1AC` →「**這哪裡有城壁啊！！**」，**命令不下達**。
  這與 [`11`](11-tactical-battle.md) §3.7 記的「命令 3 → 命令 1」是**兩條不同的路**：
  §3.7 那一段在腳本指令 3／13 裡，玩家按按鈕走的是這一條。
- 玩家是守方（`byte_10D35 ≥ 0x80`）且 `cx == 0x1B4` 時 `cx += 2` → `0x1B6`
  →「登上城壁！別讓敵人攻下了！」

⭐ 六個按鈕的順序（突擊／攻擊／陣形／城壁／守陣／退却）是**從機器碼推出來的**，
與 [`../playtest/27`](../playtest/27-original-video-frame-parity.md) §7.2 從原版影片讀到的完全一致。

### 6.2 下令對象 ＝ 底列六個 slot 的選取

⭐ **底列不是第二套命令列，是玩家的六個編成位置。**
順序由兩張互為反排列的表決定：

| 表 | 內容 | 值 |
|---|---|---|
| `cs:0xD2E4` | 螢幕格 → 隊編號 | `2 4 0 1 5 3` |
| `cs:0xD2EA` | 隊編號 → 螢幕 X | `160 240 0 400 80 320` |

隊編號是 0 主將／1 前鋒／2 左翼／3 右翼／4 左備／5 右備，
所以畫面由左到右是「**左翼 左備 主將 前鋒 右備 右翼**」——空間排列。
`cs:0xD2EA[cs:0xD2E4[i]] = i × 80` 對六格全部成立。

一格裡有三樣東西：位置名 glyph（格內 (4,6)，段 1 `0x3900 + 螢幕格 × 0xC0`）、
**目前命令的圖示**（格內 (54,6)，`word_10D48` 段的 `命令碼 × 0xC0`
＝ **`ICONGRF` 段 3 的 `碼 × 0xC0`**，六張圖與命令碼逐張相符，
見 [`../spec/33`](../spec/33-squad-selection.md) §1.5）、
**待機兵條**（(格 X ＋ 2, 396)，長上限 `0x4C`，色 12，
值取 `word_1D30A:+0x09 + 4×隊`）。

命令圖示由 `sub_1A8CC` 更新：

```asm
0001A8CC  cmp si, 600h / jnb → retn    ; ★ 只有側 0（玩家）有這一列
0001A8D4  mov bx, si / mov ah, bh      ; 隊編號 ＝ 單位記錄位移 >> 8
0001A8D8  call sub_1C673
```

六個命令 handler 各自傳自己的碼（`sub_1A92E` 0、`sub_1A953` 1、
`sub_1A96D` 2、`sub_1A988` 3、`sub_1A99C` 4、`sub_1A9D0` 的 5 跳過），
前面都有 `cmp al, ah / jz`——**命令沒變就不重畫**。

⭐ `sub_1A96D`（命令 2）在 `byte_1D34B == 0`（攻城）時呼叫 `sub_1B7CB`
把門全開，正是說明書 4.2 的「突擊時守方會開門」。
**這獨立驗證了 §6.1 從 TALK 台詞推出來的命令碼對應。**

選取本身：

```asm
0001C1CE  xchg ah, cs:byte_1D310      ; 取出選取位元圖並清空
0001C1D3  and ah, ah / jnz .1
0001C1D7  mov ah, 0FFh                ; ★ 沒選 ＝ 全隊
.1: cx = 6 / si = 0x1B
    每輪 shr ah,1，進位就寫 [si] = 命令碼；si += 0x100
0001C1F4  call sub_1C6AE              ; 重畫六個 slot 的選取框
```

`byte_1D310` 的位元 0–5 對應**隊編號**（不是螢幕格），由熱區 `0x15`–`0x1A`
切換（handler `0x1C27D`／`0x1C295`／`0x1C2AD`／`0x1C2C5`／`0x1C2DD`／`0x1C2F5`）。
選取框 `sub_1C6BF` 用 `cs:0xD2EA[隊]` 取 X，畫兩個同心矩形——
外框 (X+2, 372)-(X+77, 392)、內框各縮 1 px，選中色 12、取消色 0。

⚠ **熱區碼是「隊編號 ＋ 0x15」，而螢幕格 i 註冊的是 `cs:0xD2E4[i] + 0x15`**，
所以位元圖與畫面順序之間隔著那張表。

### 6.3 右側三格 ＝ 陣線的三個位置

| 熱區 | 矩形 | handler | `word_1D33C` 低 byte ← |
|---|---|---|---:|
| `0x04` | (552, 288, 64×24) | `0x1C165` | `0x30` ＝ 48 |
| `0x05` | (552, 312, 64×32) | `0x1C181` | `0x1C` ＝ 28 |
| `0x06` | (552, 344, 64×24) | `0x1C19D` | `0x05` ＝ 5 |

三個 handler 的形狀相同：值沒變就直接回；變了就先用**舊值**呼叫 `loc_1C5D7`
抹掉小地圖上那條線，寫入新值，再用 `sub_1C5AE` 畫新線（色 11）。
`word_1D33C` 就是側 0 的陣形原點，三個值 48／28／5
與 [`11`](11-tactical-battle.md) §3.10 記的完全相同。

## 7. 小地圖上有四種東西

底圖（地形）已在 [`../playtest/19`](../playtest/19-tactical-minimap.md) 實作：
`sub_1C4FA` 查 `BATTLE.MAP[mapY×64 + mapX]` → `BATTLE.MDL` attribute →
`sub_1C51E` 畫 2×2，

```
screenX = 0x1F0 + 2 × mapY
screenY = 0x50  + 2 × (63 − mapX)
```

⭐ **動態標記的四個 producer 也解出來了**（`sub_1C4FA`／`sub_1C51E` 的呼叫者）：

| 標記 | 誰畫 | 調色盤索引 |
|---|---|---:|
| **部隊點** | `sub_1B240` `0001B284`：`si < 0x600` → `ah=0x0A`；否則 `ah=0x03` | **10（側 0＝我方）／3（側 1＝對方）** |
| 抹除舊位置 | `sub_1B240` `0001B240`–`0001B27A`、`sub_1B3B2` | 還原地形；落在陣形線上 → 11；落在游標十字上 → 0 |
| **陣形線** | `sub_1C5AE`：整條直行 x ＝ `word_1D33C` 低 byte，y 63→0 | 11 |
| **游標十字** | `sub_1C577`：一整行 ＋ 一整列，`al≠0` 畫、`al=0` 還原地形 | 0 |
| **城壁受損** | `sub_1B824`：圖塊值 `< 0xF0` 時 `+0x10`、否則 `+8`，再 `sub_1C4FA` 重畫 | 隨新圖塊 |

`sub_1B824` 是**直接改寫戰場地圖**（`word_1D2F6` 段）那一格的圖塊值——
所以城壁的破損在小地圖與戰場本體上是同一份資料，不是兩套。

小地圖的點擊（熱區 `0x02`，handler `0x1C0C6`）先用舊的
`word_1D32C`／`word_1D32E` 還原十字，再由游標座標算新格：

```
word_1D32A = ((word_1D330 − 0x1F0) >> 1 | 1) − 0x13
word_1D328 = ((0xCF − word_1D332) >> 1 & 0xFE) + 4
```

十字接著由**同一組值加兩個固定偏移**得到（`0001C103`／`0001C106`）：

```
word_1D32E = word_1D32A + 0x13        ; 十字在縮圖上的橫向格
word_1D32C = word_1D328 − 4           ; 縱向格（`add dx, 0FFFCh`）
```

`sub_199F3` 的兩組初值互相印證：鏡頭 `(0x24, 0x0E)` 代進去正好是十字的
`(0x20, 0x21)`。**所以十字的位置反推得回鏡頭**——量到十字在
562–563／142–143 就等於量到 `word_1D32A = 14`
（[`../playtest/40`](../playtest/40-tactical-parity.md) §4.2 用這一條判斷鏡頭沒有移動）。

⚠ `word_1D32A` 是**含表頭那一列**的列號，比地形的列號大 1
（[`../formats/07`](../formats/07-battle.md) §2.1）。

## 8. ⭐ 兩列 × 8 格 ＝ 十六個陣形

熱區 `0x03` (496,248,128×32)，handler `0x1C11A`：

```
col = (word_1D330 − 0x1F0) >> 4          ; 0–7
if (word_1D332 − 0xF8) >= 0x10: col += 8 ; 下面那一列
byte_1D346 = col                          ; 選中的格
word_1D342 = byte_1D346 × 96              ; 側 0 的陣形表偏移
```

選取框由 `sub_1C61F` 畫：格 16×16、起點 (496 + (al&7)×16, 248 + (al&8 ? 16 : 0))，
內縮 1 px 的 14×14 矩形，**取消色 10、選中色 12**。

`(游標X − 0x1F0) ÷ 16` 這個算式 [`11`](11-tactical-battle.md) §3.10 已經記過，
`0x1F0` ＝ 496 正是這一格的左緣——**那 8 × 2 的格子就是十六個陣形**，
與 [`../mechanics/30-combat.md`](../mechanics/30-combat.md) 記的十六張陣形表一一對應。

## 9. `▶▶` 列（熱區 `0x0F`）

handler `0x1C234`／`0x1C260` 是一個**切換**，兩邊都在
(497,377)-(622,390) 畫一個 `sub_1F020` 矩形當作按下狀態：

```asm

          ; 開
0001C23C  mov cs:byte_1A06A, 0EBh                    ; ★ jz → jmp short
0001C24E  ah = 0x0C  → sub_1F020 (497,377)-(622,390)
0001C259  sub_1DC9D(dx=0x80, bx=0x80) ＋ sub_1DDB4    ; 視點回 (128,128)
0001C260: ; 關
0001C260  mov cs:byte_1A06A, 74h                     ; ★ 還原成 jz
0001C266  byte_1D348 = 1
0001C277  ah = 0x0A  → sub_1F020 同一個矩形
```

`byte_1A06A` 在 `loc_1A065` 之內，也就是
[`36`](36-tactical-module-map.md) §6.1 ＋ [`20`](20-ida-re-coverage-audit.md) §2.2
記的**每輪改寫自己的那一段**。機制 confirmed（改的是一個條件跳躍的 opcode），
**它擋掉的是什麼還沒讀**（§10）。

## 10. 熱區碼分派表：左鍵 `cs:0xC048`、右鍵 `cs:0xC086`

**兩張表，各 32 筆 word**（64 B），**索引就是熱區碼**，值是 CS 內的
handler 位移。預設 `0xC01C`（`0x1C01C`）＝ 不做事。

`0x1C01D`（`sub_19FA0` 的右鍵分支）直接寫著第二張表的位址：

```asm
0001C01D  mov bl, al / xor bh, bh / shl bx, 1     ; 熱區碼 × 2
0001C026  mov ax, 2 / call sub_20000              ; 系統服務 2
0001C031  call off_1C086[bx]                      ; ★ 右鍵表
0001C037  mov ax, 1 / call sub_20000
```

⭐ **左鍵表裡 `0x1B`／`0x1C`／`0x1D` 都是預設值**——
點大將或門強度條沒有反應，**要右鍵才有**（`TALK.DAT` #4
「以滑鼠的右鍵回復。」）。右鍵表裡只有這三筆 ＋ `0x1F` 有 handler。

下表是左鍵表。

| 碼 | handler | 誰註冊 | 做什麼 |

## 11. 順帶解掉：攻城的「門強度」條

不在側欄，在戰場區上緣。`sub_1C407`（由 `0x1B60F` 呼叫，`di` ＝ 城門實體記錄）：

第一次進來（`word_1D326 == 0xFFFF`）時建立版面：

| 位址 | 動作 |
|---|---|
| `0001C447` | `sub_1D9D1(dx=0x10, bx=0, cx=0x20E, ah=0)` 佔住顯示清單的格 |
| `0001C453` | `sub_10BCD` → 清 (264,8)-(471,23) |
| `0001C461` | `sub_1E3D7(al=0x1D, dx=0x100, bx=0, cx=0x41C)` ＝ 熱區 (256,0,224×32) |
| `0001C476` | `sub_106FD(si=cs:0xC3FF, dx=0x108, bx=8, ax=0x0F01)` ＝ **「門強度」**於 (264,8)，色 15 |

條本身（`sub_1C4D2` → `sub_10AAA`）：

```
if [di] < 0x80: 長 = 0
else:           長 = min([di+0x18] >> 4, 0x97)
畫 x 320 起、長 0x97 ＝ 151 px、2 px 高：前 長 px 色 11，其餘色 0
```

`320 + 151 = 471`，正好接上「門強度」三個字（264–312）之後填滿整條。
`word_1C405` 記已經畫過的最小值，**只有更小時才重畫**——所以這條只會往下掉。

`[di+0x18]` 就是實體記錄的耐久（[`11`](11-tactical-battle.md) §5.11）：
攻城的城壁 ＝（據點 `+0x13` ＋ 50）× 10、野戰的城壁 300、門 80。
`[di] ≥ 0x80` 是「這一格有實體」——類型碼 `0x0180`／`0x0280` 的低位元組都是 `0x80`。

### 11.1 ⭐ 它是會自己消失的

```asm
0001C48F  mov ax, cs:word_1D318
0001C493  add al, 14h
0001C495  mov cs:word_1D326, ax      ; ★ 到期時刻 ＝ 現在 ＋ 0x14
```

`word_1D318` 是**每幀 +1 的 byte 計數器**，加一那一行在 `0x1A12A`：

```asm
0001A12A  inc byte ptr cs:word_1D318
0001A12F  mov ax, cs:word_1D318
0001A133  cmp cs:word_1D322, ax / jnz .1 / mov cl,0 / call sub_1C3B8   ; 大將名牌 0
0001A13F  cmp cs:word_1D324, ax / jnz .2 / mov cl,1 / call sub_1C3B8   ; 大將名牌 1
0001A14B  cmp cs:word_1D326, ax / jnz ret / call sub_1C4A6             ; ★ 門強度條
```

**三個 UI 都是同一套「到期就收」**：大將名牌 `+0x3C`（60 幀）、
門強度條 `+0x14`（20 幀）。到期或右鍵都走 `sub_1C4A6`，
它把 `word_1D326` 設回 `0xFFFF`，於是下一次挨打時 `sub_1C407`
會重建整個版面（並把 `word_1C405` 的最小值一起重設）。
