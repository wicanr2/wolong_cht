## 1. 為什麼一直找不到：它不在同一個段

`docs/playtest/28` §5.2 掃過全庫，**沒有任何指令用 `+0x7000` 這個位移寫入**，
結論停在「一定有人寫，只是換了寫法」。真正的原因是**換了段**：

| 段變數 | 大小 | 內容 | 誰建 |
|---|--:|---|---|
| `word_1D2FA` | `0x7000` | **七層通行圖**（每層 `0x1000` 格，bit 7 ＝ 擋）| `sub_1BB3C` |
| **`word_1D2FC`** | `0x2000` | ⭐ **兩個平面的地面層表**（低 `0x0000`／高 `0x1000`）| **`sub_1BBA6`** |
| `word_1D2FE` | `0x2000` | **佔用成本表**：有兵站著就是 8。移動落定時寫，尋路擴散時讀 | `sub_1BBA6` 清空 |

三塊連續，所以 `word_1D2FC = word_1D2FA + 0x700`，
於是 `word_1D2FA:[格號 + 0x7000]` ＝ `word_1D2FC:[格號]`。
同理 `word_1D2FA:[格號 + 0x9000]` ＝ `word_1D2FE:[格號]`——
**移動時那幾個 `es:[bx−0x7000]` 寫的是第三塊，不是讀的那一塊**
（`−0x7000` 是 IDA 把位移 `0x9000` 當有號數印出來的樣子）。

⚠ 「段連續」是**強推論**不是 confirmed：段變數由間接寫入填，
沒讀到配置迴圈。但三件事互相扣得死：
`sub_1BB3C` 清的正好是 `0x7000`、`sub_1BBA6` 寫的正好是兩個 `0x1000` 平面、
而 `sub_1B1B1` 讀的正好是那兩個平面的形狀（bit 3 ＋ 低 3 位）。
**讀到的資料如果是第三塊（只有 0 與 8），任何格子都走不動**。

## 2. 地面層怎麼算：`sub_1BCA6`

圖塊屬性表（`word_1D302`）是**每個圖塊 8 byte**：`[0]` 是層數，
`[1..7]` 是由下往上七層的子圖塊編號。判準只有一條：

> **子圖塊 ≥ `0x70` ＝ 可以站的「頂面」，`1`–`0x6F` ＝ 實體，`0` ＝ 空。**

（同一條門檻 `sub_1BB6D` 也在用：`0` 與 `≥ 0x70` 不擋，其餘擋。）

```
bx = 圖塊 × 8 + 1
if 0x680 ≤ bx ≤ 0x700:  bx += 0x80      ; ★ 城壁 0xD0–0xDF 改讀 0xE0–0xEF 的屬性
低平面 = 層 0–3 裡第一個「頂面」的層號         ; 找不到 → 0x80（沒有地面）
if 圖塊 ≥ 0xF0:  高平面 = 8, return            ; ★ 門的特殊標記
高平面 = 層 4–6 裡第一個「頂面」的層號         ; 找不到 → 0x80
```

⭐ **兩個平面就是層 0–3 與層 4–6 的切分。** 低平面是地面，
高平面是城牆頂——沒有更複雜的東西。

## 3. 方向位元：`sub_1BC39` ＋ `sub_1BD07`

每一格的表值不只是高度，還帶**四個方向能不能走**：

```
bit 0–2   地面層
bit 3     這一格是門（`sub_1BCA6` 回 8 時設，兩個平面都設）
bit 4     ← 可走      bit 5  → 可走
bit 6     ↑ 可走      bit 7  ↓ 可走
```

`sub_1BC39` 對每格算完自己的值之後，逐一取四個鄰格算一次，交給 `sub_1BD07`：

```
if 中心高平面 == 8 且 鄰格高平面 ≤ 6:  中心高平面 = 鄰格的       ; 門的高度跟著旁邊的牆頂
低平面：兩邊都有地面，且 |鄰格 − 中心| ≤ 1  → 設方向位元         ; ★ 一步最多差一層
高平面：兩邊都有地面，且 鄰格 == 中心 或 鄰格是門 → 設方向位元    ; ★ 高平面要完全相等
```

### 3.1 高平面最後會被壓成單一高度

`sub_1BBA6` 建完之後還有一段**正規化**，只作用在高平面：

```
統計高平面有地面的格子：層 ≤ 4 的算 dl、層 > 4 的算 dh
多數決 → 目標高度 al ＝ 4 或 5
再掃一遍：高度不等於 al 的，有門旗標就改成 al，沒有就整格清 0
```

⇒ **整面城牆頂是同一個高度（4 或 5）**，所以 §3 那條「高平面要完全相等」
在牆頂上永遠成立。實測三張攻城圖（`BATTLE.MAP` 0／5／20）：
高平面有地面的格子是 40–73 格，**全部落在層 4**，另有 10–18 格是門。

## 4. ⭐ 上下城牆只在門那一格

`sub_1AF69` 是移動分派：先 X、再 Y，**最後才是 Z**，而 Z 那一段有兵種閘：

```asm
0001AF82  cmp byte ptr [si+4], 12h / jbe 跳過   ; ★ 兵種 ≤ 0x12（大將與騎馬）不做 Z 移動
0001AF88  Z < 目標 → sub_1B0D3（上）
0001AF8E  Z > 目標 → sub_1B116（下）
```

而 `sub_1B0D3`（上升）第一件事就是查目前這一格的圖塊：

```asm
0001B0E3  al = 圖塊[格號]
0001B0E7  cmp al, 0F0h / jb 失敗       ; ★★ 圖塊 < 0xF0 → 根本不能往上爬
0001B0EB  al &= 1 / al ^= 1 / al <<= 1 ; 朝向跟著門的奇偶
0001B0F4  bx += 1000h / call sub_1B186 ; 檢查上一層站不站得住
          成功 → Z++、[si+1Eh] = 10h   ; ★ 進高平面
```

下降 `sub_1B116` 同樣要求 `≥ 0xF0`，而且 `bx < 0x1000` 時把 `[si+1Eh]` 清 0。

⇒ **登城 ＝ 走到門那一格 → 往上爬 → 在牆頂水平移動。**
城牆本體（`0xD0`–`0xDF`）不能爬。**橫向要進城就得撞開它**——
城門那一列只有那一格擋人（[`../playtest/28`](../playtest/28-siege-breach-measurement.md) §2）。

### 4.1 門有兩種

`sub_1B1B1` 在高平面上還會擋一次：

```asm
0001B20B  cmp dl, 0F0h / jb 通過        ; 不是門 → 過
0001B210  cmp dl, 0F8h / jb 失敗        ; ★ 0xF0–0xF7：擋
0001B215  cmp byte ptr [si+1Ah], 6 / jz 失敗   ; 命令 6 也擋
```

實測（`BATTLE.MAP` 0／5／20）：

| 戰場 | 圖塊組 | `0xF0`–`0xF7` | `0xF8`–`0xFF` |
|--:|--:|---|---|
| 0 | 0 | `0xF4` ×3，x ＝ 29／32 | `0xFD` ×9，x ＝ 39 |
| 5 | 1 | `0xF4` ×8，x ＝ 40 | `0xFD` ×10，x ＝ 44／45 |
| 20 | 0 | `0xF4` ×2，x ＝ 33 | `0xFF` ×8，x ＝ 39 |

城牆在 x ≈ 35–38（`gateX` 是 36／42／35），所以
**`0xF4` 那幾格在牆外（攻方側）、`0xF8`+ 那幾格在牆內（守方側）**。
兩側都有登城點，差別是牆頂上能不能橫向穿過去。

## 5. 於是 `sub_1B1B1` 整支讀得懂了

```
目標格有單位（任一平面）→ 失敗
dl = 地面層表[格號 | 高平面<<12]
dl == 0 → 失敗（沒有地面，例如城牆本體）
dl &= 7
低平面：目標地面比自己高 → 升一層；低 → 降一層；相等 → 通過
高平面：必須相等，且目標不是未破的門，且命令不是 6
```

⚠ **低平面沒有高度差上限不是漏洞**——上限在 §3 的方向位元裡，
尋路只會沿著 `|Δ| ≤ 1` 的邊走，所以實際走到的那一步一定是 ±1。
remake 若照抄「移動時不檢查」但**尋路不照方向位元**，會走出原版不會走的路。
