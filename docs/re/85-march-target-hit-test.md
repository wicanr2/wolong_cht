# 85 — 行軍目標怎麼判定：一座城只有登記的那一格按得到

**狀態：confirmed（機器碼 ＋ 實跑）。**
`sub_1709E` 有兩道閘：游標所在那一格的**圖塊編號要落在 `0CBh`–`0D3h`**，
而且**據點表登記的 X／Y 要與那一格完全相等**。城的圖形有 4×4 格大，
所以「點圖示中間」有 15/16 的機會落空——這就是
[`../playtest/67`](../playtest/67-dosgolem-popup-menus.md) 記的「按下去沒反應」。
另有一道更早的閘在 `sub_1703C`：**游標壓在熱區上時它根本不會去問那一格**（§3）。

## 1. `sub_1709E`（77 B）：這一格是不是據點

```asm
0001709E  push ds / push ax / push cx
000170A1  mov  ax, cs:word_1989C          ; 游標在第幾列
000170A5  mov  cx, ax
000170A7  shl  ax,1 / shl ax,1 / shl ax,1 ; ×8
000170AD  mov  bx, ax
000170AF  shl  ax,1                       ; ×16
000170B1  add  ax, bx                     ; ×24  ← 一列 384 格 ＝ 24 個節
000170B3  add  ax, cs:word_10D44          ; 地圖圖塊的段基址
000170B8  mov  ds, ax
000170BA  mov  bx, cs:word_1989A          ; 游標在第幾行
000170BF  mov  al, [bx]                   ; 那一格的圖塊編號
000170C1  cmp  al, 0CBh / jb  → stc       ; ← 閘一
000170C5  cmp  al, 0D4h / jnb → stc
000170C9  mov  ds, cs:word_10D52          ; 資料段
000170CE  mov  ax, bx / xor bx, bx
000170D2  cmp  [bx+848h], ax              ; ← 閘二：據點 +0x08 ＝ X
000170D6  jnz  short +8
000170D8  cmp  [bx+84Ah], cx              ;          據點 +0x0A ＝ Y
000170DC  jz   → clc                      ; 找到了，bx 停在該筆的偏移
000170DE  add  bx, 20h / jmp 上一輪        ; 一筆 32 B
```

兩件事因此定案：

| 事實 | 憑什麼 |
|---|---|
| **地圖一列 384 格**，一格一個 byte | `×24` 個節 ＝ 384 B；與 [`../formats/08`](../formats/08-sinario-save.md) §1.6 的「X 值域 4–370，地圖寬 384」互相印證 |
| **圖塊 `0CBh`–`0D3h`（9 種）是據點** | 兩個立即值夾出來的區間；`+0x16` 低 4 位的據點類型有 5 種（大／中／小城、關、戰場），9 種圖塊是它們的外觀變化 |

⚠ **迴圈沒有上界**——`bx` 一路加 32 直到命中。閘一保證了一定命中：
圖塊是據點就一定在表裡。remake 照抄時要注意這個隱含前提。

## 2. 游標的「格座標」是兩次捨去的和

`word_1989A`／`word_1989C` 由 `sub_11F7F` 每圈算好
（[`47`](47-main-screen-window-registry.md) §5.1）。實測三組：

| 捲動原點 | 畫面游標 | 滑鼠（世界）| 遊戲算出來的格 |
|---|---|---|---|
| (2976,1632) | (320,224) | (3296,1856) | (206,114) ＝ 許昌 |
| (2976,1632) | (624,112) | (3600,1744) | (225,107) ＝ 陳留 |
| (2961,1345) | (639,399) | (3600,1744) | **(224,106)** |

第二列與第三列**滑鼠座標完全一樣，格卻差一格**，所以

```
格 ＝ ⌊原點 ÷ 16⌋ ＋ ⌊畫面座標 ÷ 16⌋
```

——兩次無條件捨去**各吃掉一點**。原點是 16 的倍數時兩種算法一致，
不是的時候就差一格。世界 Y 還比第 0 列多兩格（驅動範圍 0–4127 ＝ 258 格，
地圖只有 256 格），所以 `滑鼠 y ＝ 格 y × 16 ＋ 32`。

⇒ **不要自己換算**。dosgolem 那邊做成閉迴路（`wolong.PointAtTile`）：
每一輪讀 `word_1989A`／`word_1989C`，差多少補多少。

## 3. 更早的一道閘：游標不能停在熱區上

`sub_1703C`（[`45`](45-corps-command-mode.md) §5）的迴圈：

```asm
call sub_1E453            ; al = 熱區碼、bx = 1 左鍵／2 右鍵
cmp  bx, 2 / jz → stc     ; 右鍵取消
and  al, al / jz → 地圖分支
…                          ; ← al ≠ 0 就走熱區分支，這一圈不問據點
```

大地圖上滑鼠座標是世界座標（[`84`](84-popup-row-band-and-world-cursor.md) §2），
推到視野外鏡頭就跟過去，**而鏡頭跟到底之後游標會釘在畫面角落**。
右下角是軍團情報視窗的熱區 `#31`（x 432..639 y 192..399），
左下角是訊息窗 `#30`——於是

> 游標**確實**停在城的那一格上，`sub_1709E` 卻一次都沒被呼叫。

實跑攔到的形狀就是這樣：`WOLONG_DOSGOLEM_WATCH=1709E` 完全沒有輸出，
把鏡頭捲到「目標格出現在畫面中央 (320,160)」之後立刻攔到
`#92439805 呼叫 1709E AX=0000 BX=0001`，接著就是 `sub_1804E`（兩項選單）。

⚠ **「熱區碼非 0」與「那一格不是據點」在畫面上完全一樣**：都沒有反應。
分得出來的只有攔函式。

## 4. 走完的流程（實跑）

```
tile:181,127     游標移到宛（據點 90）登記的那一格
press            → TALK #21「向宛　移動下。請下達戰鬥指示。」＋ 兩項選單
press            → 選「戰鬥指揮」；軍團一覽的「目標據點」變成「宛」
```

⭐ **第三個選項「解體」沒有出現**，與 [`45`](45-corps-command-mode.md) §1 的
`cmp [bx+3], [bp+0]`（目標等於勢力首都才有第三項）一致——宛不是曹操的首都。
這是一次**沒有預先安排的正對照**。
