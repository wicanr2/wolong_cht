# 11 — 戰術戰鬥：模組結構與戰場資料模型

**狀態：模組骨架與戰場資料模型已解。戰鬥規則本身還沒解。**

- 日期：2026-08-08
- 輸入：`workplace/ida/dosv/KI.EXE.i64`、`BATTLE.MAP`、`BATTLE.MDL`
- 前置：`docs/re/09`（戰略層的戰鬥）、`docs/formats/07`（`BATTLE.*` 分段）

戰術層是本作最大的一塊未解區域，約 15 KB 的程式碼、上百個函式，
而且用了自我修改碼。這一份不假裝解完了——它做兩件事：
**把模組的骨架畫出來**，讓下一趟不必再從入口摸起；
**把戰場的資料模型解到可以驗證的程度**，那是戰術層一切規則的地基。

## 1. 入口與主迴圈

```asm
sub_11B5A:                    ; 戰略層呼叫這裡（docs/re/09 §10）
  call sub_12078
  mov ax,2 / call sub_20000   ; 滑鼠：隱藏游標
  call sub_10A1C
  call sub_19946              ; ★ 戰場初始化
  call sub_19FA0              ; ★ 主迴圈，回傳 al ＝ 勝方

sub_19FA0:
  mov word_1D340, sp          ; 存 sp —— 結束時用它跳出來，不是正常回返
  mov ax,1 / call sub_20000   ; 滑鼠：顯示游標
  call sub_1A1C5
.loop:
  call sub_1A156              ; 讀滑鼠 → bx ＝ 按鍵
  test bx, 3 / jz .tick
    call sub_1E453
    cmp bx, 1 / jnz .right
    call sub_1BFF2            ; 左鍵
    jmp .tick
  .right: call sub_1C01D      ; 右鍵
.tick:
  call sub_1A426              ; ★ 執行一個腳本指令
  call loc_1A065              ; ★ 每幀更新 ＋ 繪製
  jmp .loop
```

**主迴圈沒有出口。** 結束是把 `word_1D340` 寫回 `sp`——
所以戰鬥的任何一層都能直接跳出來，不必逐層回返。
找「戰鬥怎麼結束」要找 `mov sp, cs:word_1D340`，不是找 `retn`。

### ⚠ `loc_1A065` 有自我修改碼

```asm
loc_1A065:
  cmp byte ptr ds:0D348h, 0
byte_1A06A db 74h              ; ← sub_19A33 執行期寫進來的 `jz`
```

`sub_19A33` 裡有 `mov byte_1A06A, 74h`——它在**執行期**把一個位元組
寫成 `jz` 的機器碼。IDA 靜態看到的是資料，後面幾行整段反編錯。
讀這一段要手動解位元組，**不要相信反編結果**。

## 3. ⭐ 每幀執行一個腳本指令

### 3.1 直譯器：`sub_1A426`

```asm
cmp cs:word_1D313, 0 / jz .run
dec cs:word_1D313 / retn       ; ★ 等待中：這一幀什麼都不做
.run:
mov ds, cs:word_1D30C          ; 腳本緩衝區的段
mov si, cs:word_1D311          ; 讀取位置
mov ax, [si]                   ; 一個 word 就是一個指令
mov bl, al / and bl, 1Fh       ; 低 5 位 ＝ 指令碼（0–18）
shl bx, 1
and al, 0E0h / rol al,1 ×3     ; 高 3 位 ＝ 參數（0–7）
inc si / inc si
call cs:funcs_1A457[bx]        ; 19 個處理常式
mov cs:word_1D311, si
```

```
一個指令 ＝ 2 byte
  byte 0 低 5 位  指令碼 0–18
  byte 0 高 3 位  參數 0–7
  byte 1         運算元
```

### 3.2 ⭐ 腳本來自 `BATTLE.DAT`，而且是**依武將挑的**

`sub_1CBE5` 把 256 byte 讀進 `word_1D30C`：

```asm
mov al, ds:0D34Bh              ; 戰場類別（戰場編號 <0xC0→0、<0xD1→1、否則 2）
inc al
cmp byte ptr ds:0D35h, 80h / jb .1
cmp al, 1 / jnz .1
xor al, al
.1:
mov bx, ds:0D30h / sub bx, 2240h / shr bx, 1   ; 軍團位址 → 武將記錄
mov ds, word ptr ds:0D52h
mov ah, [bx+4256h]             ; ★ 武將 +0x16
shl ah, 1 / shl ah, 1          ; ×4
add ah, al                     ; 段編號 ＝ 武將+0x16 × 4 + 戰場類別
xor al, al                     ; ax ＝ 段編號 × 256 ＝ 檔案位移
mov dx, 0D8Fh                  ; 'BATTLE.DAT'
mov bx, ds:0D30Ch / mov di, 100h
call sub_1E38C
```

```
BATTLE.DAT ＝ 8,192 B ＝ 32 段 × 256 B
段編號 ＝ 武將 +0x16（0–7）× 4 ＋ 戰場類別（0–3）
```

**檔案是不是腳本，用資料就驗得掉**（`tools/battledat.py verify`）：

> 4,096 個 word 的低 5 位**沒有一個 ≥ 19**。
> 位元組若是隨機的，期望會有約 1,664 個超過。

### 3.3 ⭐ 武將 `+0x16` 是戰法性格（0–7）

四個劇本共 508 筆武將記錄，`+0x16` 的值域**正好是 0–7**，
而且與能力值單調對應：

| 腳本 | 人數 | 平均武力 | 平均統率 | 平均政治 | 代表 |
|---:|---:|---:|---:|---:|---|
| **0** | 19 | **13.6** | 6.0 | 2.0 | 呂布 |
| 1 | 34 | 10.7 | 6.5 | 3.5 | 張飛 |
| 2 | 86 | 9.3 | 8.2 | 4.5 | 曹操、關羽、趙雲、劉備 |
| 3 | 116 | 6.6 | 5.7 | 3.2 | 一般武將（最多） |
| 4 | 21 | 5.2 | **10.4** | **11.8** | 諸葛亮 |
| 5 | 66 | 5.0 | 10.2 | 9.8 | — |
| 6 | 21 | 3.0 | 5.4 | 11.8 | — |
| **7** | 18 | **1.5** | 2.2 | 10.6 | 純文官 |

**武力從 13.6 單調降到 1.5。** `docs/formats/08` §3 原本把 `+0x16`
標成「值域 0–7，未解」——它是**這名武將在戰場上跑哪一套腳本**。

說明書第 11 章那些對 AI 行為的觀察（高統率武將待在後方、疲勞就後退
重整陣形、守軍會朝射擊來源集中）**全部是這 32 段腳本跑出來的**。
解讀那 19 個指令，等於把整個戰術 AI 拿到手。

### 3.4 ⭐ 一個指令不一定是兩個 byte

**分支指令後面那個 word 是跳躍目標，不是指令。**

```asm
sub_1A591（指令 10）：
mov bl, al / shl bx, 1 / jmp cs:jpt_1A597[bx]   ; 參數選五種比較之一
  0  無條件
  1  條件 == 運算元
  2  條件 != 運算元
  3  條件 <  運算元
  4  條件 >  運算元
成立 → mov bx, [si]            ; 下一個 word
       and bl, bl / jnz ret    ; 低位元組非 0 就不跳
       mov bl, bh / xor bh,bh / shl bx,1 / mov si, bx   ; ★ si ← 高位元組 × 2
不成立 → cmp byte ptr [si], 0 / jnz ret / inc si / inc si   ; 跳過目標
```

目標 word 長得像「等待」（低位元組 0），所以**照直線每兩個 byte 切一刀
會把 564 個目標誤讀成 564 次等待**。本專案的第一版工具就是這樣算的，
指令 0 的次數從 2,352 掉到 1,788，正好差 564。

兩條驗證，都是零例外：

| 檢查 | 結果 |
|---|---|
| 分支指令後面那個 word 的低位元組是 0 | **564 / 564** |
| 跳躍目標落在**指令邊界**上 | **564 / 564** |

第二條特別硬：指令長度模型只要錯一個地方，後面的邊界就會整段位移，
目標會落在半個指令中間。

### ⭐ 腳本永遠跑在 side 1

四個查詢常式裡的側別是**寫死的**：`sub_1A6CF`／`sub_1A6E8` 用 `mov bx, 600h`、
`sub_1A654` 讀 `word_1D31C+1`、`sub_1A5E1` 讀 `ds:24h`（第二側的欄位）。
指令 2 也只寫 `word_1D33E`（第二側的陣形原點）。

**所以「我方」在腳本裡一律是 side 1，「敵方」一律是 side 0（玩家）。**
指令 4 與 5 查的都是玩家那一側的狀態——`byte_1D346` 是玩家在陣形選單上點的那一格，
`word_1D33C` 是玩家的陣形原點。這不是巧合，是設計：**AI 看得到玩家擺什麼陣、擺在哪裡**。

### 3.9 ⭐ `word_1D30A` 那 64 byte ＝ 兩軍的編成摘要

`sub_1CC31` 只配 4 個 paragraph 給它。開打前 `sub_19E70` 從**軍團記錄**抄進來，
打完 `sub_19EBD` 再抄回去——它是戰略層與戰術層之間的那張表。

每側 32 B，side 0 在 `+0x00`、side 1 在 `+0x20`：

| 偏移 | 內容 | 來源／用途 |
|---|---|---|
| `+0x02` | **武將編號** | `sub_19C13` 拿它 × 32 ＋ `0x4240` 去查武將表 |
| `+0x04` | **兵力**（word） | 開打時 ＝ 軍團 `+0x04`；**每死一個兵 `dec`**；畫在畫面上；指令 11／12 查它 |
| `+0x06` | **士氣** | 開打時 ＝ 軍團 `+0x06`；`sub_19B6D` 把它寫進**每一個兵的 `+0x03`**（＝ 開場體力） |
| `+0x09 + 4k` | 第 k 隊的待機兵數 | 軍團 `+0x28 + 4k` |
| `+0x0A + 4k` | 第 k 隊的**兵種** | 軍團 `+0x29 + 4k`；`sub_19B6D` 寫進兵的 `+0x04` |
| `+0x0B + 4k` | 第 k 隊的**存活數** | 開打時歸零，`sub_19F2C` 在打完時數 |

⭐ **士氣直接變成兵的開場體力。** `sub_19B6D` 的 `mov ah, [bx+6]` ＋
`mov es:[di+3], ah` 就是這一行——士氣高的軍團，每個兵開場血就厚。

⭐ **打完的寫回（`sub_19F58`）比想像的簡單：**

```
新兵力 ＝ Σ（各隊存活數 ＋ 各隊待機數）
新士氣 ＝ 舊士氣 × 新兵力 ÷ 舊兵力
```

士氣是**按兵力比例縮**的，不是另外一條規則。

### 3.10 ⭐ 兩側的陣形原點是分開的兩個變數

| 變數 | 側 | 初值 | 誰改 | 三個值 |
|---|---:|---|---|---|
| `word_1D33C` | 0（玩家） | `0x2005` ＝ (X=5, Y=32) | 選單（`seg000:C168`／`C184`／`C1A0`） | 48／28／5 |
| `word_1D33E` | 1（腳本） | `0x2039` ＝ (X=58, Y=32) | 指令 2（`sub_1A4AB`） | 58／36／16 |

⚠ **兩組不是互相對稱的**（`Width−1−l` 只在「自軍側」那一組碰巧對得上）。
鏡射是靠 `sub_1AA2C` 的 `neg dl` 做的——**把陣形表的 dx 取負**，
所以原點不必對稱。照抄兩組，不要自己算。

`byte_1D346` 是同一個道理：它由**游標座標**算出來
（`(word_1D330 − 0x1F0) ÷ 16`，下排再加 8），也就是玩家在 8 × 2 的陣形選單上
點的那一格；接著 `word_1D342 ← byte_1D346 × 96` 就是 side 0 的陣形表偏移，
與指令 1 對 side 1 做的事完全對稱（`word_1D344 ← 運算元 × 96`）。

### 3.6 ⭐ 單位記錄：`word_1D30E`

指令 3、6、7、13、17、18 都用同一組位址算式，佈局就掉出來了：

```
word_1D30E 段：
  0x0000 – 0x05FF   敵方六隊，每隊 0x100 B
  0x0600 – 0x0BFF   ★ 我方六隊（腳本操作的是這一側）
  0x0C00 – 0x0DFF   16 筆 × 0x20 B 的另一張表（指令 15 掃它）
```

六隊 × 256 B ＝ `0x600`，兩側剛好首尾相接。已解出的欄位：

| 偏移 | 內容 | 出處 |
|---|---|---|
| `+0x00` | 旗標。指令 13 會設 bit 3 | `sub_1A60D` |
| `+0x03` | 未解，指令 18 拿它當條件 | `sub_1A6E8` |
| `+0x1A` | **目前生效的命令** | `sub_1A52E` 讀它 |
| `+0x1B` | **新下達的命令** | `sub_1A4BF` 寫它 |
| `+0x24` | 未解。指令 13 拿 `參數 × 18` 去比對它分組 | `sub_1A60D` |

`+0x1A` 與 `+0x1B` 是兩個不同的欄位——**下令與生效是分開的**，
所以腳本可以「下令之後等幾幀，再問全軍到位了沒」。

### 3.7 命令碼：城壁移動在野戰會自動變成攻擊

指令 3 與 13 都有同一段：

```asm
cmp al, 3 / jnz .1
cmp cs:byte_1AB4F, 0 / jnz .1     ; 城門的 X ＝ 0 → 這張圖沒有城
mov al, 1                          ; ★ 命令 3 → 命令 1
.1:
```

`byte_1AB4F` 是索引第二欄（§4.5），**野戰用的戰場它是 0**。
所以**命令 3 只在攻城戰有意義，野戰時退回命令 1**。
說明書 4.2 的六個戰術指令裡，只有「**城壁移動**」是攻城限定的，
而它的替代品自然是「**攻擊**」。→ **命令 3 ＝ 城壁移動、命令 1 ＝ 攻擊**（強證據）。

命令 5 走另一條路（`sub_1A8F6`），與其他命令不同——待查。

### 3.8 一段腳本長什麼樣

`tools/battledat.py dump 0`（呂布那一型的攻城腳本）：

```
    0  msg 1                     ; 開場訊息
    6  q.rand 5                  ; 擲 0–4
    8  branch != 0 → 38          ; 不是 0 就跳過開場白
   12  msg 9
   16  q.min18                   ; 查那張 16 筆表的最小值
   18  branch != 0 → 36
   22  q.theirs                  ; 敵方全軍在做什麼
   24  branch == 3 → 36          ; 敵人在爬城牆 → 跳
   28  msg 11 / wait 15
   32  branch 無條件 → 146
>  38  set2 0 / set1 5
   42  order 全軍 命令 0          ; ★ 全軍下命令 0
   44  wait 35
   46  q.min18 / branch == 0 → 116
   52  q.theirs / branch != 3 → 96
   58  q.rand 5                  ; 三選一的隨機分支
   60  branch == 0 → 72
   64  branch == 1 → 82
   68  branch 無條件 → 88
```

**擲骰分支、觀察敵方命令、依情況下不同的命令**——
說明書第 11 章那些對 AI 的觀察（「過一陣子敵人會因疲勞後退」、
「守軍會朝射擊來源集中」）就是從這裡跑出來的。

## 4. ⭐ 戰場的資料模型

### 4.1 三層結構

```
BATTLE.MAP  512 B 索引（每筆 2 B）＋ 214 個戰場 × 4,096 B
              每個戰場：64 B 表頭 ＋ 3,968 格（64 × 62）＋ 64 B 尾段
              每一格 ＝ 一個 byte 的**圖塊編號**

BATTLE.MDL  4,096 B 表頭（3 × 256 B 屬性表）＋ 3 個圖塊組 × 63,488 B
              每組前 2,048 B ＝ 256 筆 × 8 B 的**圖塊定義**
              其餘 61,440 B ＝ 像素資料
```

索引的第一欄是圖塊組編號（0–2），第二欄見 §4.4。

### 4.2 ⭐ 一格是一疊圖塊，不是一塊

8 byte 的圖塊定義：

```
[0]        堆疊高度 k（0–7）
[1..k]     由下往上的子圖塊編號
[k+1..7]   0
```

驗過三個圖塊組共 768 筆：**`[k+1..7]` 全為 0，零例外**。
`[1..k]` 之間允許有 0（那一層是空的）。

兩支程式各自印證：

```asm
; sub_19E10：讀「最上層」那一格
mov ah, [bx]        ; 高度 k
add bl, ah
mov al, [bx]        ; ★ [k] ＝ 頂端的子圖塊
sub al, 0BAh / cmp al, 6 / jnb skip    ; 0xBA–0xBF → 生成一個物件

; sub_1BB6D：把七層各自的通行性寫進 7 張 4,096 B 的圖
mov ah, 7
.loop:
  inc bx / mov al, [bx]
  and al, al / jz .block
  cmp al, 70h / jnb .block             ; ★ 0 或 ≥ 0x70 → 該層不可通行
  and byte ptr es:[di], 7Fh / jmp .next
.block: or byte ptr es:[di], 80h
.next: add di, 1000h / dec ah / jnz .loop
sub di, 7000h
```

7 × 4,096 ＝ 28,672 ＝ `ds:0D2FA` 的大小，**完全吻合**。

### 4.3 ⭐ 堆疊高度 ≥ 4 ＝ 站在高處

```asm
; sub_1B240：單位移動後
mov ds, cs:word_1D2F6 / mov bl, [bx]   ; 該格的圖塊編號
cmp bl, 0F0h / jnb .clear
mov ds, cs:word_1D302
shl bx,1 ×3 / mov al, [bx]             ; 堆疊高度
cmp al, 4 / jb .clear
or byte ptr [si], 2                    ; ★ 單位旗標 bit 1
.clear: and byte ptr [si], 0FDh
```

把 214 張戰場依「堆疊高度 ≥ 4」上色，形狀自己說話
（`tools/battlefield.py map 5`）：

```
戰場 5（攻城用）                                戰場 200（野戰・平原＋水域）
 8 .........................OO########OOO######.   ............................
11 .........................###.................   ............................
25 .........................#####...............   ............................
52 .........................######################  ............................
```

**攻城用的戰場長出一圈封閉的城牆。** 這比「看圖塊像什麼」硬得多——
空間關係不是判讀時能安排的。

不過**高處不等於城牆**：野戰用的戰場也有高處，那是山與林。
下一節那張查表給了獨立的佐證。

### 4.4 ⭐ 野戰戰場是依地形組合查表選的

`sub_14BDD` 拿**兩格的地形類型**去查一張 21 筆 × 3 B 的表
（`cs:97F0h`，檔案偏移 `0x99F0`）：

```asm
mov bx, 97F0h / mov cx, 15h        ; 21 筆
.loop:
  mov dl, [bx]
  cmp ax, [bx+1] / jz .hit         ; (類型A, 類型B) 配對
  xchg al, ah / xor dh, 40h        ; ★ 換順序再比一次
  jnz .loop
  add bx, 3 / loop .loop
mov dl, 6                          ; 都不中 → 偏移 6
.hit: mov cx, dx / add cl, 0C0h    ; 戰場編號 ＝ 0xC0 + 偏移
```

⭐ **旋轉旗標就是「配對是換過順序才中的」**：`xor dh, 40h` 設的正是
`byte_10D35` 的 bit 6，而 `sub_1CAEB` 看的也是同一個位元。
戰場轉不轉 180 度，取決於兩格地形誰在前——不是另外算的方向。

地形類型的編號見 `docs/mechanics/30-combat.md` §2
（0 平原、3 山地、4／5 兩種林地、6／7 水域）：

| 戰場 | 地形組合 | 高處格數 |
|---:|---|---:|
| **192** | 山 ＋ 山 | **596** |
| 193 | 山 ＋ 平原 | 284 |
| 194 | 山 ＋ 林5 | 678 |
| 195 | 山 ＋ 水6 | 283 |
| 196 | 山 ＋ 林4 | 247 |
| 197 | 山 ＋ 水7 | 488 |
| **198** | 平原 ＋ 平原、平原 ＋ 林4、平原 ＋ 水7，**以及所有不中的組合** | **10** |
| 199 | 平原 ＋ 林5 | 208 |
| 200 | 平原 ＋ 水6、林5 ＋ 水6 | **0** |
| 201 | 林5 ＋ 林5、林5 ＋ 水7 | 344 |
| 202 | 林5 ＋ 林4 | 103 |
| 203 | 林4 ＋ 林4、林4 ＋ 水7 | **0** |
| 204 | 林4 ＋ 水6 | **0** |
| 205 | 水6 ＋ 水6 | 8 |
| 206 | 水7 ＋ 水7、水6 ＋ 水7 | **0** |

**高處格數是獨立算出來的，沒有進查表。** 而「山 ＋ 山」最多、
「平原 ＋ 平原」幾乎是平的、水與林的組合是零——
兩份互不相干的資料對上了，這張表的判讀可以定案。

另外七張走另一條路：`cl = 地形類型 + 0xCE`，也就是
**207–213 ＝ 地形類型 1–7**（跨水構造、山地、兩種林地、兩種水域）。
`sub_14C1A` 還會在地形類型 8 時從 209–212 隨機挑一張、類型 9 時固定用 213，
所以這五張有兩條來路。

### 4.5 ⭐ 索引第二欄 ＝ 城壁移動的目標 X

> 定案見 §5.8i——它被直接寫進 `mov dl, imm8` 的立即運算元，
> 是命令 3（城壁移動）走過去的那一格的 X。

`sub_1CAEB` 把它讀進 `byte_1AB4F`，而戰場旋轉 180 度時：

```asm
test cs:byte_10D35, 40h / jz skip
cmp cs:byte_1AB4F, 0 / jz .1
mov al, 3Fh / sub al, cs:byte_1AB4F    ; ★ v ← 63 − v
```

`0x3F` ＝ 63 ＝ **寬度 − 1**（戰場是 64 寬 62 高），所以它是 **X 座標**，
不是 Y。統計對得上（`tools/battlefield.py survey`）：

| 檢查 | 結果 |
|---|---|
| 戰場 **192–213**（野戰用）第二欄 | **全為 0**，22 張零例外 |
| 第二欄非 0 的 186 張 | **全部有高處**，零例外 |
| 第二欄 vs 最近的物件格 X | 25 張相同、123 張差 1、29 張差 2 |

戰場 0–191 一一對應 192 個據點——**`docs/re/05`「據點編號直接當戰場編號」
在資料上也成立了**。

### 4.6 物件格：頂層子圖塊 `0xBA`–`0xBF`

`sub_19E10` 掃過全部 3,968 格，替頂層落在這個範圍的格子各生成一個
32 byte 的記錄：

```asm
mov word ptr es:[di], 3C0h
mov es:[di+6], cl / mov es:[di+8], ch     ; X, Y
mov es:[di+0Ah], ah                       ; 堆疊高度
mov dx, 150h
test al, 1 / jz .1 / mov dx, 204h         ; 依子圖塊編號的奇偶二選一
.1: mov es:[di+1Ch], dx
call sub_1ECE0 / and al,3
mov es:[di+1Bh], al                       ; 隨機 0–3
add di, 20h                               ; 記錄 32 B
```

在攻城用的戰場上，這些格子**全部落在城牆線上**：戰場 5 是左牆面
兩段各 4 格、上下牆面各 5 格。說明書 4.4 說「梯子的位置每張地圖是固定的」，
位置對得起來。

⚠ **但不能就這樣定案。** 戰場 209–213（山地、林地、水域）上也各有
19–48 個物件格，而那裡沒有城牆。所以這個範圍是「**會生成互動物件的
子圖塊**」，城門與梯子只是其中一種用途。**用途待驗。**

野戰用的 192–208 一個物件格都沒有。

## 5. ⭐ 每幀更新：戰場其實是 64 × 64 × 7 的立體格

`loc_1A065` 有自我修改碼（§1），手動解位元組之後是：

```asm
cmp byte ptr ds:0D348h, 0
jz  .1                          ; ← 那個被寫進去的 0x74
  mov dx, ds:0D328h / mov bx, ds:0D32Ah
  call sub_1DC9D
  mov byte ptr ds:0D348h, 0
.1:
call sub_1A12A
call sub_1A6FA
call sub_1B941                  ; ★ 實體更新
```

### 5.1 `sub_1B941`：兩張表，每幀各掃一遍

```asm
mov ds, cs:word_1D30E / mov es, cs:word_1D2FA
mov si, 1400h
.a: cmp byte ptr [si], 0C0h / jb .next
    call sub_1B97E / call sub_1BA2E / call sub_1BAB7
.next: add si, 20h / cmp si, 1800h / jb .a
mov si, 0E00h
.b: cmp byte ptr [si], 0C0h / jb .next2
    call sub_1BB10
.next2: add si, 20h / cmp si, 1400h / jb .b
```

`word_1D30E` 的佈局到這裡補齊了：

| 範圍 | 筆數 × 大小 | 內容 |
|---|---|---|
| `0x0000`–`0x0BFF` | 96 × 32 B | **兵士**。`0x01`–`0x2F` 一方、`0x30`–`0x5F` 另一方 |
| `0x0C00`–`0x0DFF` | 16 × 32 B | 指令 15 掃它（§3.5） |
| `0x0E00`–`0x13FF` | 48 × 32 B | 每幀畫一次，`+0x1B` 是 4 幀動畫相位 |
| `0x1400`–`0x17FF` | 32 × 32 B | **飛道具**（箭之類的） |

⭐ **一側 48 個兵，分成 6 隊 × 8 人。** 腳本操作的「六隊」
（`0x600 + k × 0x100`）就是每隊的**第一個兵**——`0x100` ＝ 8 × 32。

說明書 4.1 說戰場上 1 個兵 ＝ 戰略的 10 人，而一個編成位置是 1,000 人
＝ 100 個兵；場上只放得下 8 個，其餘就是那句
「**残りは予備兵として画面外に待機**」。

### 5.2 ⭐ 格子索引是三維的

`sub_1BA2E`（飛道具移動）：

```asm
mov al, [si+5]                  ; 方向
mov bx, [si+10h]                ; 格索引
test al, 1 / jnz .vert
  and al,al / jnz .east
  dec bx / dec byte ptr [si+7]  ; ★ 西：−1，X −1
.east: inc bx / inc byte ptr [si+7]
.vert:
  cmp al,1 / jnz .south
  sub bx, 40h / dec byte ptr [si+9]   ; ★ 北：−0x40，Y −1
.south: add bx, 40h / inc byte ptr [si+9]
```

一列 `0x40` ＝ **64 格**，正是戰場的寬。而 `sub_1BB6D`（§4.2）把七層的
通行性寫在相隔 `0x1000` 的七張圖上，`0x1000` ＝ 4,096 ＝ 64 × 64。

```
格索引 ＝ Z × 0x1000 ＋ Y × 0x40 ＋ X
7 × 4,096 ＝ 28,672 ＝ ds:0D2FA 的大小
```

⭐ **戰場是 64 × 64 × 7 的立體格**，而 §4.2 那個「一格是一疊 1–7 層圖塊」
定義的就是**哪幾層是實心的**。兩件事在這裡接上了：
堆疊高得比較高的地方（城牆），兵站的 Z 就比較高——
說明書的「城壁に登る」在資料上就是換一層 Z。

### 5.3 ⭐ 命中判定：`sub_1B97E`

```asm
mov bx, [si+10h] / mov bh, es:[bx]     ; 那一格的內容
and bh, bh / jz ret                     ; 0 ＝ 空
cmp bh, 80h / jnb .hitWall              ; ≥ 0x80 ＝ 障礙 → 飛道具消失
cmp bh, 60h / ja ret
dec bh                                  ; ★ 格子裡存的是「兵編號 + 1」
cmp word ptr [si+2], 600h / jnb .mine
  cmp bh, 30h / jb ret                  ; 敵方射的，打到 <0x30 是自己人
  jmp .hit
.mine: cmp bh, 30h / jnb ret            ; 我方射的，打到 ≥0x30 是自己人
.hit: xor bl,bl / shr bx,1 ×3           ; ★ 兵記錄 ＝ 編號 × 32
      cmp byte ptr [bx], 80h / jb ret
```

**佔用圖每格存的是「兵編號 + 1」**，`0` 是空格、`≥ 0x80` 是障礙。
編號 `0x01`–`0x2F` 與 `0x30`–`0x5F` 分屬兩軍，**誤傷自己人不判定**。

### 5.4 ⭐ 扣體力

```asm
cmp byte ptr [bx+4], 0 / jz .dmg
cmp byte ptr [bx+3], 64h / jnb .dmg     ; ★ 體力滿 100 → 不觸發下面這段
mov ax, [bx+1Ah]
cmp al,5 / jz .dmg / cmp ah,5 / jz .dmg
cmp al,ah / jz .1 / mov [bx+1Ah], ah
.1: mov byte ptr [bx+1Bh], 5            ; ★ 受傷的兵自己改成命令 5
.dmg:
mov al, [si+4]                          ; 飛道具的威力
cmp byte ptr [bx+4], 36h / jz .quarter
cmp byte ptr [bx+4], 0 / jnz .full
test byte ptr [bx+2], 1 / jz ret        ; 不受傷
.quarter: shr al,1 / shr al,1           ; ★ 威力 ÷ 4
.full:
mov byte ptr [bx+1], 2                  ; 動作 ＝ 被打中
…
sub [bx+3], al / ja .alive              ; ★ 體力 −= 威力
mov byte ptr [bx+3], 1
cmp byte ptr [bx+4], 0 / jz .alive
  and byte ptr [bx], 10h / or byte ptr [bx], 1
  mov byte ptr [bx+1], 4                ; 動作 ＝ 倒下
  mov byte ptr [bx+3], 0                ; ★ 死亡
.alive: mov al, 0Bh / call sub_102F5
```

兵士記錄（32 B）已解出的欄位：

| 偏移 | 內容 |
|---|---|
| `+0x00` | 旗標，`≥ 0x80` 存在；bit 6 這一幀被打中 |
| `+0x01` | 動作：`2` ＝ 被打中、`4` ＝ 倒下 |
| `+0x02` | 旗標，bit 0 決定 `+0x04 == 0` 的兵受不受傷 |
| **`+0x03`** | **體力**，上限 **100** |
| **`+0x04`** | **`0` ＝ 大將**（命令 1 時不攻擊、被打到體力 1 就停住不會倒下）；`0x36` 這種傷害只吃四分之一 |
| `+0x1A` | 生效中的命令 |
| `+0x1B` | 新下達的命令 |

⭐ **受傷的兵會自己把命令改成 5**（體力滿 100 的不會）。
說明書 4.1：「兵士が戦闘して敵にやられると、**画面外に退却**し、
待機中の兵が出陣します」——**命令 5 ＝ 退卻**（強證據）。
指令 3 對命令 5 走另一條路（`sub_1A8F6`）也對得上：退卻不是普通命令。

### 5.5 飛道具會隨高度改變威力

`sub_1BAB7`（畫出來並更新）：

```asm
mov cl, al / xchg cl, [si+0Eh]     ; al ＝ 新的 Z，cl ＝ 舊的 Z
mov ch, [si+4] / shr ch,1 / shr ch,1   ; 威力 ÷ 4
cmp al, cl / jz .same
jb  .down
sub [si+4], ch                     ; ★ 往上飛 → 威力 −25%
jmp .same
.down: inc ch / add [si+4], ch      ; ★ 往下落 → 威力 +25%
```

**箭往上飛威力遞減、往下落威力遞增。** 這解釋了說明書為什麼強調
「城壁に登って攻撃」——站在高處往下射，每一格都在加成。

### 5.6 ⭐ 一隊 ＝ 1 隊長 ＋ 7 隊員，兩者行為不同

```asm
sub_1A754（0x000 側）／sub_1A785（0x600 側）：
.squad:
  cmp byte ptr [si], 80h / jb .noLeader
  call sub_1A85B / call sub_1A7B7      ; ★ 隊長的更新
  jmp .members
.noLeader: call sub_1A83F               ; 隊長不在
.members:
  add si, 20h / mov cx, 7               ; ★ 剩下 7 個
.m: cmp byte ptr [si], 80h / jb .next
    call sub_1A85B / call sub_1A7FD     ; ★ 隊員的更新
.next: add si, 20h / loop .m
  cmp si, 600h（或 0C00h）/ jb .squad
```

**1 ＋ 7 ＝ 8 人一隊，6 隊 48 人**——與 §5.1 從記錄位址推出來的完全一致。

隊長不在時 `sub_1A83F` 做的事只有一件：

```asm
mov cx, 7
.loop: cmp byte ptr [si+1Ah], 5 / jz .next
       mov byte ptr [si+1Bh], 5         ; ★ 全隊改成命令 5
.next: add si, 20h / loop .loop
```

⭐ **隊長倒下 → 全隊退卻。** 說明書 6.1：
「将軍体力…**低於一定值自動退卻**」。

### 5.7 ⭐ 命令是怎麼生效的

```asm
mov ax, [si+1Ah]          ; al ＝ 生效中的命令、ah ＝ 新下達的命令
mov bl, al
cmp al, 5 / jz .run       ; ★ 已經在退卻 → 不理會新命令
cmp al, ah / jz .run      ; 沒有新命令
mov bl, ah
mov [si+1Ah], ah          ; 生效命令 ← 新命令
mov word ptr [si+16h], 0  ; 計時歸零
mov dl, [si+6] / mov dh, [si+8] / mov [si+10h], dx   ; ★ 記下起點 X,Y
mov dl, [si+0Ah] / mov [si+12h], dl                   ; ★ 記下起點 Z
.run: xor bh,bh / shl bx,1 / call cs:funcs_1A7E1[bx]
```

⭐ **退卻一旦開始就不能被新命令打斷。** 說明書 4.2：
「退卻…**一旦執行不能取消**」。

下新命令時會記下當時的位置——**命令是以「從哪裡開始」為基準執行的**，
這正是陣形線那套機制需要的東西。

兵士記錄再補四個欄位：

| 偏移 | 內容 |
|---|---|
| `+0x06`／`+0x08`／`+0x0A` | **X ／ Y ／ Z** |
| `+0x10`／`+0x12` | 下令當時的 X,Y ／ Z |
| `+0x16` | 命令開始後經過的時間 |

### 5.8 ⭐ 十一個命令處理常式，隊長與隊員各一套

```
隊長 funcs_1A7E1（11 筆）：1A92E 1A953 1A96D 1A988 1A99C 1A9D0
                           1AB39 1AA2C nullsub 1A9FB 1AA10
隊員 funcs_1A827（ 9 筆）：1AA2C 1AB9C 1AB7C 1AB39 1ABB2 1AAED
                           1AB39 nullsub nullsub
```

**同一個命令，隊長與隊員跑不同的程式**——這就是「隊員跟著隊長」的機制。

而 `BATTLE.DAT` 的 32 段腳本裡**只出現命令 0–5，正好六個**，
與說明書 4.2 的六個戰術指令數量相同：

| 命令 | 出現次數 | 說明書 4.2 |
|---:|---:|---|
| **0** | 103 | **陣形** |
| **1** | 49 | **攻擊** |
| **2** | 78 | **突擊** |
| **3** | 50 | **城壁移動** |
| **4** | 97 | **守陣** |
| **5** | 35 | **退卻** |

六個全部對上，各自的證據見 §5.8b。

**命令 3 只出現在攻城用的腳本段**（段編號 mod 4 ∈ {0, 1}），
野戰的兩類（2、3）一次都沒有——**零例外**。
這與 §3.7 那段「野戰時命令 3 自動變成 1」是同一件事的兩面：
連腳本作者都知道不該在野戰下這個命令。

命令 6–10 只有隊長那張表有，腳本從不下達——**是內部狀態，不是玩家指令**。

### 5.8b ⭐ 六個命令全部對上說明書了

讀完隊長那六支處理常式，每一個都能用**程式的行為**對上說明書 4.2 的名稱。

#### 命令 0 ＝ 陣形（`sub_1A92E`）

```asm
mov ax, [si+14h]                 ; 陣形指定的座標
cmp al, [si+6] / jnz .move
cmp ah, [si+8] / jnz .move
mov byte ptr [si+1Bh], 7         ; ★ 到位 → 轉成內部狀態 7
mov byte ptr [si+1Ah], 7
.move: call sub_1AA2C            ; 往 +0x14 走
```

**走到指定座標，到了就停。** 說明書 6.1 說疲勞度
「**兵回到陣形的指定位置時最小**」——「到位」正是這個命令的判定點。

#### 命令 1 ＝ 攻擊（`sub_1A953`）

```asm
cmp byte ptr [si+4], 0 / jz .notAttack
call sub_1AB9C / retn            ; 一般兵：攻擊
.notAttack: call sub_1AA2C       ; ★ [si+4] == 0 的不攻擊，只移動
```

說明書 4.2：「**攻擊**：大將以外的兵攻擊」。
→ **`+0x04 == 0` 就是大將**。這一條同時解掉了 §5.4 的傷害分支：

```asm
sub [bx+3], al / ja .alive
mov byte ptr [bx+3], 1
cmp byte ptr [bx+4], 0 / jz .alive   ; ★ 大將不死，體力停在 1
```

**大將被打到體力 1 就停住，不會倒下**——說明書 6.1
「將軍體力…低於一定值**自動退卻**」，退卻不是陣亡。

#### 命令 2 ＝ 突擊（`sub_1A96D`）

```asm
mov al, 2 / call sub_1A8DE / call sub_1A8CC
cmp cs:byte_1D34B, 0 / jnz .1        ; ★ 只有攻城戰
call sub_1B7CB
.1: call sub_1AB7C
```

下這個命令時，**攻城戰會多跑一支 `sub_1B7CB`**。說明書 4.2：

> **突擊**…攻城戰的守方會**開門出擊**，而**開了的門這場戰鬥不能再關**。

#### 命令 3 ＝ 城壁移動、命令 5 ＝ 退卻

已在 §3.7、§5.4、§5.6、§5.7 各自印證。

#### 命令 4 ＝ 守陣（`sub_1A99C`）

```asm
mov bx, [si+1Ch]                 ; 目前鎖定的敵人
mov dl, [bx+6] / mov dh, [bx+8]
sub dl, [si+6] / jnb .1 / neg dl
.1: sub dh, [si+8] / jnb .2 / neg dh
.2: add dl, dh                   ; 曼哈頓距離
    cmp dl, 10h / ja .far
    mov al, 4                    ; ★ 近（≤16）→ 一種行為
.far: （al 維持 0）               ;   遠 → 另一種
```

說明書 4.2：「**守陣**（守備陣形）：擺陣 → **敵人靠近就攻擊** →
**敵人後退就回陣**」。門檻是**曼哈頓距離 16 格**。

#### 對照表

| 命令 | 說明書 4.2 | 證據 |
|---:|---|---|
| **0** | **陣形** | 走到 `+0x14` 指定的座標，到位轉狀態 7 |
| **1** | **攻擊** | `+0x04 == 0`（大將）不攻擊 |
| **2** | **突擊** | 攻城戰時多跑一支 `sub_1B7CB`（開門） |
| **3** | **城壁移動** | 野戰時自動變成 1；腳本只在攻城段下它 |
| **4** | **守陣** | 敵人距離 ≤ 16 換行為 |
| **5** | **退卻** | 受傷自動改成它、隊長倒下全隊改成它、不可打斷 |

命令 6–10 只有隊長那張表有、腳本從不下達——**是內部狀態**。
已知 7 是「陣形已就位」。

### 5.8c 鎖定最近的敵人：`sub_1A85B`

每個兵每幀都跑一次：

```asm
mov ax, 600h / cmp si, ax / jb .1 / mov ah, al   ; ★ 掃敵方那 48 個
.1: mov di, ax / mov bx, ax
mov al, [si+6] / mov ah, [si+8] / mov dl, [si+1Eh]
mov cx, 0FF30h                    ; ch ＝ 目前最小距離、cl ＝ 48 次
.loop:
  cmp byte ptr [bx], 80h / jb .next
  al = |X − [bx+6]| ; ah = |Y − [bx+8]|
  … 依 +0x1E 的高低給 +0x40 的距離懲罰 …
  add al, ah                      ; 曼哈頓距離
  cmp al, ch / jnb .next
  mov ch, al / mov di, bx         ; 記下最近的
.next: add bx, 20h / dec cl / jnz .loop
cmp [si+1Ch], di / jz .same
or byte ptr [si], 8 / mov [si+1Ch], di    ; ★ 換目標時設 bit 3
```

`+0x1C` ＝ **目前鎖定的敵人**（記錄位址），用**曼哈頓距離**挑最近的。
`+0x1E` 不同的一方會被加上 **64 格的距離懲罰**，等於「排到最後才考慮」——
效果像是**打不到的目標**（在牆上／牆下之類），實際語意還沒定。

### 5.8d ⭐ 十六種陣形表

`sub_1AA2C` 是六個命令都會走到的那一支——它算的是**這個兵該站在哪**：

```asm
mov bx, si / shr bx,1 ×4 / and bl, 0FEh   ; ★ 兵編號 × 2
cmp bl, 60h / jnb .other                   ; 0x60 ＝ 96 ＝ 48 × 2
  mov ax, cs:word_1D33C                    ; 陣形線（原點）
  add bx, cs:word_1D342                    ; ＋ 陣形編號 × 96
  mov dx, cs:[bx-331Ch]                    ; ★ 查表
  jmp .place
.other:
  mov ax, cs:word_1D33E
  sub bx, 60h / add bx, cs:word_1D344
  mov dx, cs:[bx-331Ch]
  neg dl                                   ; ★ 另一側左右鏡射
.place:
call sub_1AACF / mov [si+14h], ax          ; 目標座標
```

```
陣形表 ＝ cs:0xCCE4（檔案偏移 0xCEE4）
一個陣形 ＝ 48 組 (dx, dy)，每組兩個有號 byte ＝ 96 byte
共 16 個陣形 ＝ 1,536 byte
```

96 這個數字在別處也出現過：**指令 1（`set1`）就是 `word_1D344 ← 運算元 × 96`**
（§3.5）——所以指令 1 的運算元就是**陣形編號**。腳本裡出現的
`set1 4`／`set1 5`／`set1 6` 是在切換陣形。

而**指令 2（`set2`）寫的 `word_1D33E` 是陣形的原點**，
三個常數 `0x3A`／`0x24`／`0x10`（58／36／16）落在 64 格寬的戰場上——
說明書 4.3：

> **陣形線**：決定在戰場的哪個位置擺陣：**自軍側／中央／敵軍側**三選一。

三個值、三選一、位置由後往前，**完全對上**。

#### 陣形長什麼樣

`tools/formation.py show 5`（★ ＝ 隊長、數字 ＝ 隊編號）：

說明書 11.4 教人怎麼對付高統率的武將：

> 用**窄陣形**＋把陣形線移到最上方，讓幾個兵鑽過敵陣**直取主將**。

⚠ **但這只對陣形 4／5／6 成立。** 本文件初版從陣形 5 的圖推廣成
「所有陣形都把隊長排在後面」——把十六個都算過之後只有那三個是
（`internal/rules/tactical` 的測試就是釘這一條的）。

那三個是同形狀的上／中／下三個位置，也是腳本用得最兇的一組
（陣形 5 出現 29 次、全檔最多）。所以說明書那句觀察在**實戰中大多成立**，
但**不是所有陣形的性質**。

### 5.8e ⭐ 三個兵種各有一支攻擊常式

`+0x04` 決定走哪一支，而且門檻都是 **18 的倍數**：

```asm
mov bl, [si+4]
cmp bl, 24h / jz .arrow    ; 36
ja .infantry               ; > 36
call sub_1ABD2 / retn      ; < 36
.arrow: call sub_1ABFF / retn
.infantry: call sub_1AC55 / retn
```

```
+0x04 ＝ 兵種 × 18
   0  大將      18  騎馬      36  弓兵      54  步兵
```

18 這個倍數在別處出現過：**指令 13（`order.by`）就是拿「參數 × 18」
去比對挑隊**（§3.5）——所以指令 13 是**依兵種下命令**。

| 兵種 | 常式 | 行為 |
|---|---|---|
| 大將 / 騎馬 | `sub_1ABD2` | **目標座標 ← 敵人的座標**，追過去打 |
| **弓兵** | `sub_1ABFF` | **目標 ← 自己的座標**（不動），再依**與敵人的高度差**走不同分支 |
| 步兵 | `sub_1AC55` | 近戰 |

弓兵站著不動、依高度差分支，正是 §5.5 那條「箭往上飛減威力、
往下落加威力」的另一端。而 §5.4 的「`+0x04 == 0x36` 傷害只吃四分之一」
現在也有名字了：**步兵挨箭只吃四分之一**——說明書
「攻城戦では弓兵、**歩兵**が必要です」的數值依據。

### 5.8f ⭐ 疲勞度 ＝ `+0x19`

四處用法拼起來：

| 位置 | 動作 |
|---|---|
| `sub_1AA2C` | 走到陣形指定的座標時 **`+0x19` ← 128** |
| `sub_1AB7C` | 攻擊時 **上限壓到 40**（`cmp 28h / mov 28h`） |
| `sub_1ADC8` | 移動狀態下**每幀 −1** |
| `sub_1ABB2` | 守陣時 **< 16 就把命令改回 0（陣形）** |

說明書 6.1：

> 疲労度は**兵が陣形の指定位置に戻った時に最小**となります。
> 陣形をとらずに行動していると増え続けます。

`+0x19` 是「**餘力**」——數值越高越好，只有**走回陣形位置**能補滿。
說明書 4.2 說「**陣形是唯一能恢復疲勞度的指令**」，機器碼裡就是
只有 `sub_1AA2C` 那一行 `mov byte ptr [si+19h], 80h`。

⭐ **恢復是有移動成本的**：不是下令就補滿，是**走到定位那一刻**才補。

### 5.8g ⭐ 有利／不利是算出來的

每幀掃完全部 96 個兵之後（`sub_1AEA9` 一路累加）：

```
word_1D31C  低位／高位 ＝ 兩軍**場上的兵數**
word_1D31A  低位／高位 ＝ 兩軍**`+0x19` 還沒歸零的兵數**（還有餘力的）
```

然後：

```asm
mov ax, cs:word_1D31A
add ah, 7                  ; ★ 敵方 +7 的讓分
mov bl, 2
sub al, ah / jnb .1
  xor bl, bl / neg al      ; 我方較少 → 0
.1: cmp al, 8 / ja .2
  mov bl, 1                ; ★ 差距 ≤ 8 → 1
.2: mov cs:byte_1D31E, bl
```

```
byte_1D31E ＝ 0 不利、1 普通、2 有利
```

說明書 6.1：

> 疲労度が最大の兵が増えると、**軍団全体が弱くなり**、不利な状態になります。
> …しかし、**敵も同じ状態の場合は通常と変わりません**。

「敵も同じ状態なら通常」＝ **差距 ≤ 8 就判成 1（普通）**，
一字不差地對上。而**指令 8（`q.d31e`）讀的就是這個值**——
AI 會看自己有利還是不利再決定下什麼命令。

### 5.8h ⭐ 大將體力 50 是自動退卻的門檻；攻城方會被計時

```asm
sub_1AE56:
xor di, di
cmp byte ptr [di+3], 32h / jnb .1     ; ★ 0x000 側大將體力 < 50
mov cx, 1B0h / call sub_1A8F6
.1: mov di, 600h
cmp byte ptr [di+3], 32h / jnb .2     ; ★ 0x600 側大將體力 < 50
mov cx, 1B0h / call sub_1A8F6
.2:
cmp cs:byte_1D34B, 0 / jnz ret        ; ★ 只有攻城戰
dec cs:byte_1D321 / jnz ret
mov cs:byte_1D321, 0Ah                ; ★ 每 10 幀
… dec 攻方大將的體力 …
```

說明書 6.1 那兩句在這裡各有一行：

> **将軍体力**…一騎打ち等被打中就減少；**低於一定值自動退卻**。

**門檻是 50，攻城方每 10 幀掉 1。** 攻方不能圍而不攻——這是內建的攻城計時器。

### 5.8i 命令 3（城壁移動）的目標

```asm
loc_1AB39:
test byte ptr [si], 2 / jz .1
cmp byte ptr [si+1Eh], 0 / jz .1
  mov byte ptr [si+1Bh], 6            ; 已經在牆上 → 轉成內部狀態 6
  jmp sub_1AB7C
.1: cmp al, ah / jz ret
    db 0B2h                            ; ★ mov dl, imm8
byte_1AB4F db 1Fh                      ;   ← 立即值就是索引第二欄！
    mov dh, [si+8]
    mov [si+10h], dx / mov [si+14h], dx   ; 目標 ＝ (登城點 X, 自己的 Y)
    bh = dh / bl = 0 / bx >>= 2 / bl += dl / bh |= 10h
    mov es, cs:word_1D2FC
    mov al, es:[bx] / and al, 7
    mov [si+12h], al                      ; 目標 Z
```

⭐ **又一處自我修改碼**：`BATTLE.MAP` 索引的第二欄被 `sub_1CAEB`
直接寫進 `mov dl, imm8` 的立即運算元裡。§4.5 說它「是城門附近的 X」，
現在可以定案了——**它是城壁移動的目標 X（登城點）**。

目標的 Z 從 `word_1D2FC` 的 `0x1000` 起查（`Y × 64 + X`，取低 3 位），
那是**每一格的可站立層**。

### 5.8j ⭐ 移動：三軸依序試，撞到就走繞路點

```asm
sub_1AF69:
mov ah, 1                      ; 「這一幀還沒試著動」
or byte ptr [si], 20h
mov al, [si+6]  / cmp al, [si+10h] / ja → 西 / jb → 東
mov al, [si+8]  / cmp al, [si+11h] / ja → 北 / jb → 南
cmp byte ptr [si+4], 12h / jbe .skipZ    ; ★ 大將與騎馬不做 Z 移動
mov al, [si+0Ah] / cmp al, [si+12h] / jb → 上 / ja → 下
.skipZ:
and ah, ah / jz .blocked       ; 有試過但都被擋
… 已經在目標上 → sub_1B00D 取下一個繞路點 …
```

每個方向一支，長得都一樣（以往西的 `sub_1B047` 為例）：

```asm
mov bx, [si+0Ch]               ; ★ 格索引（Z×0x1000 + Y×0x40 + X）
mov byte ptr [si+5], 0         ; 面向 0 ＝ 西
dec bx
call sub_1B1B1                 ; 那一格站得上去嗎
jb .blocked
  dec byte ptr [si+6] / mov [si+0Ch], bx / clc / retn
```

方向編碼 **0 西、1 北、2 東、3 南**——與飛道具移動 `sub_1BA2E`
的 `test al,1`／`cmp al,1` 完全一致。

⭐ **大將與騎馬（`+0x04 ≤ 18`）不做 Z 移動**——說明書 5.5：
「**騎馬のみの編成では城壁に登れない**ため攻城戦では弓兵、歩兵が必要です」。
爬不上城牆在機器碼裡就是這一行 `cmp byte ptr [si+4], 12h / jbe`。

### 5.8k ⭐ 繞路點清單，與 18,432 B 的緩衝區剛好對齊

```asm
sub_1B00D:
dec byte ptr [si+17h] / jl .done      ; 還剩幾個候選點
mov bx, si / shl bx,1 / shl bx,1      ; ★ 兵記錄位址 × 4 ＝ 兵編號 × 128
add bx, 1800h
add bl, [si+16h]                      ; 讀到第幾個
add byte ptr [si+16h], 2
mov ax, [bx]
cmp al, 80h / jnb .z
mov [si+10h], ax / clc / retn         ; 設成下一個移動目標 (X, Y)
.z: … mov [si+12h], ah …              ; 或設成目標 Z
```

```
繞路點清單 ＝ 0x1800 + 兵編號 × 128
0x1800 ＋ 96 × 128 ＝ 0x4800 ＝ 18,432 ＝ ds:0D30E 的大小
```

**一個 byte 都不多不少。** §5.1 那張佈局表到這裡封口了：

| 範圍 | 內容 |
|---|---|
| `0x0000`–`0x0BFF` | 96 個兵 × 32 B |
| `0x0C00`–`0x0DFF` | 16 × 32 B（門／城壁的耐久） |
| `0x0E00`–`0x13FF` | 48 × 32 B |
| `0x1400`–`0x17FF` | 32 × 32 B（飛道具） |
| **`0x1800`–`0x47FF`** | **96 × 128 B 的繞路點清單** |

`+0x16` 是讀到第幾個、`+0x17` 是還剩幾個。
**路徑是別處算好放進來的**，這一支只負責一個一個取出來用。

### 5.8l 兵士記錄（32 B）目前解出來的欄位

| 偏移 | 內容 |
|---|---|
| `+0x00` | 旗標：`≥0x80` 存在、bit 1 在高處、bit 2 換過目標、bit 3 目標變了、bit 5 移動中、bit 6 這幀被打中 |
| `+0x01` | 動作：`2` 被打中、`4` 倒下 |
| `+0x02` | 旗標，bit 0 決定大將受不受傷 |
| **`+0x03`** | **體力**（上限 100；大將低於 **50** 自動退卻） |
| **`+0x04`** | **兵種 × 18**：0 大將、18 騎馬、36 弓兵、54 步兵 |
| `+0x05` | **面向**：0 西、1 北、2 東、3 南 |
| **`+0x06`／`+0x08`／`+0x0A`** | **X ／ Y ／ Z** |
| **`+0x0C`** | **格索引** ＝ Z×0x1000 ＋ Y×0x40 ＋ X |
| `+0x10`／`+0x11`／`+0x12` | 這一步的移動目標 X／Y／Z |
| **`+0x14`** | **最終目標**（陣形位置或敵人的位置） |
| `+0x16`／`+0x17` | 繞路點清單的游標與剩餘數 |
| **`+0x19`** | **疲勞度（餘力）**，陣形到位補 128、攻擊上限 40、移動每幀 −1 |
| **`+0x1A`／`+0x1B`** | **生效中的命令 ／ 新下達的命令** |
| **`+0x1C`** | **鎖定的敵人**（記錄位址） |
| `+0x1E` | 未解。鎖敵時造成 64 格的距離懲罰 |

### 5.9 ⭐ 勝負條件：先補不出兵的一方輸

```asm
sub_1A6FA:
  cmp byte ptr cs:word_1D31C, 0 / jnz .1
  mov cs:byte_1D349, 1 / call sub_19FDC      ; ★ 低位那一軍沒兵了
.1:
  cmp byte ptr cs:word_1D31C+1, 0 / jnz .2
  mov cs:byte_1D349, 0 / call sub_19FDC      ; ★ 高位那一軍沒兵了
```

`word_1D31C` 的兩個 byte 就是**兩軍的剩餘兵數**（含畫面外待機的），
`byte_1D349` 是勝方。說明書 4.1：

> これを待機している兵がなくなるまで繰り返し、
> その結果**先に兵が足りなくなると負け**となります。

`sub_19FDC` 是結束處理，開頭就是 `mov sp, cs:word_1D340`——
**直接把堆疊指標拉回主迴圈進來時的值**，不逐層回返（§1）。
最後 `mov al, byte_1D349` 把勝方帶回戰略層。

### 5.10 戰術戰鬥對據點的損傷

```asm
mov bx, 32h                     ; 50
cmp cs:byte_1D34B, 0 / jnz .skip    ; ★ 只有攻城戰扣
call sub_1A65D                  ; ax ＝ 0xC00 那張表 [+0x18] 的最小值
xor dx,dx / mov bx, 0Ah / div bx    ; ÷ 10
mov bx, cs:word_10D32           ; 據點記錄
mov dl, [bx+13h]                ; 城兵數
add dx, 32h / sub dx, ax
shr dx,1 ×3                     ; ★ 損傷 ＝ (城兵數 + 50 − 最小值÷10) ÷ 8
sub [bx+10h], dl / sub [bx+11h], dl / sub [bx+13h], dl
```

扣的是同樣那三個欄位（上昇值、防災值、城兵），但**公式與自動判定不同**
（`docs/re/09` §4.1）。而且損傷**隨那張 16 筆表的最小值上升而下降**——
說明書 6.1：

> これに攻撃を受けると戦略に戻ったときに**拠点への被害が大きくなります**。
> つまり、**打って出た方が拠点への被害は小さくなります**。

那張 16 筆表（`0xC00`，指令 15 也掃它）就是**門與城壁的耐久**：
被打得越兇、最小值越低、戰後城市損失越大。詳見 §5.11。

### 5.11 ⭐ 門與城壁是「和兵一樣的實體」，而且是從圖塊值長出來的

`sub_19CB3` 把 `es` 設成 `word_1D30E + 0xC0`，也就是單位記錄區的 `0x0C00`，
然後連著呼叫兩個建立常式。**兵佔 `0x0000`–`0x0BFF`（96 個 × 32 B），
門與城壁接在 `0x0C00`–`0x0DFF`，同樣是 32 B 一筆，兩者共用 16 筆的額度**
（兩個常式都在 `di >= 0x200` 就停）。

建立的來源不是另外一張表，而是**戰場圖塊值本身**：

| 圖塊值 | 是什麼 | 常式 | 類型碼 `[+0x01]` | 耐久 `[+0x18]` |
|---|---|---|---:|---|
| `0xD0`–`0xDF` | **城壁** | `sub_19CE2` | 1 | 攻城：（**城兵數** ＋ 50）× 10；野戰：300 |
| `0xF0`–`0xF7` | **門** | `sub_19DA1` | 2 | 80 |

⭐ **攻城戰的城壁耐久是由守方據點的城兵數決定的**（據點記錄 `+0x13`），
而戰後扣的也是同一個欄位——**守軍越多，城牆越耐打**。

⭐ **一「行連續的城壁圖塊」只產生一筆實體。** 掃描是逐行往下走
（`si` 每次 `+0x40`），`dh` 累計連續長度，遇到非城壁的圖塊才把長度寫進 `[+0x1A]`。
打壞時 `sub_1B824` 拿 `[+0x1A]` 當迴圈次數，**整段一起消失**。

#### 記錄欄位

| 偏移 | 內容 |
|---|---|
| `+0x00` | 旗標：bit 7 ＝ 存在、**bit 0 ＝ 已破壞**（指令 15 檢查的就是 bit 0） |
| `+0x01` | 類型：1 ＝ 城壁、2 ＝ 門 |
| `+0x06`／`+0x08` | X／Y |
| `+0x10` | 格索引（門存的是 Z=2 那一層，`si + 0x2000`） |
| `+0x18` | **耐久**（word） |
| `+0x1A` | 縱向連續幾格 |

#### 打壞的流程

```asm
seg000:B5EB:
  cmp byte ptr [di], 80h / jb .out         ; 已經沒了就跳過
  cmp word ptr [di+18h], 0 / jnz .dec
  call sub_1B799 / and byte ptr [di], 7Fh  ; ★ 耐久 0 → 垮
  jmp .out
.dec:
  dec word ptr [di+18h]                    ; ★ 撞一次掉一點
```

⭐ **`sub_1B799` 垮掉的不只是撞到的那一段**——它掃 16 筆，
把**所有 `[+0x08]`（Y）相同的實體**一起打壞。同一排的城壁是連動的。

垮掉時圖塊值也跟著換：**未滿 `0xF0` 加 `0x10`，否則加 8**
（城壁 `0xD0`–`0xDF` → `0xE0`–`0xEF` 瓦礫，門 `0xF0`–`0xF7` → `0xF8`–`0xFF` 破門），
再重新展開那個圖塊的堆疊（`sub_1BB6D`），於是那一格變得走得過去。

`sub_1B7CB` 是另一條路：突擊（命令 2）時把**所有類型 1 的實體**一次打壞，
對應說明書 4.2 的「守方開門」。

#### ⭐ 那個「一下打穿」的分支：每個運算元都查證過了

```asm
cmp cs:byte_1D34B, 0 / jnz .shared        ; 只有攻城戰
cmp cs:byte_10D35, 80h / jnb .flipped
  cmp si, 600h / jnb .out                 ; ★ 守方直接離開，碰不壞城壁
  cmp byte ptr [si+5], 0 / jnz .shared    ; 攻方面向 −X
  mov word ptr [di+18h], 0                ; ★ 耐久直接歸零
.flipped:
  cmp si, 600h / jb .out
  cmp byte ptr [si+5], 2 / jnz .shared    ; 鏡射過的圖，方向對稱
  mov word ptr [di+18h], 0
```

| 運算元 | 查證 |
|---|---|
| `byte_1D34B == 0` | 攻城戰（§3.2） |
| `byte_10D35` bit 7 | **玩家是守方**——`sub_14E5C` 只在互換 `word_10D2E`／`word_10D30` 的那一支 `or ..., 80h` |
| `si < 0x600` | side 0；配上 bit 7 之後**兩種組合指的都是攻方** |
| `[si+05]` | **面向**——`sub_1B047`／`1B069`／`1B08B`／`1B0AF` 寫 0／2／1／3 的同時各自 `dec [si+6]`／`inc [si+6]`／`dec [si+8]`／`inc [si+8]` |

⭐ **`loc_1B612` 那條路是關鍵**：守方撞上城壁時直接返回，
**碰不壞自己的城牆**。這一點讓整段的語意站得住。

⚠ **語意存疑，但行為照抄。** 186 張攻城圖的城壁一律在 X 33–46，
攻方從 X 5 出發，所以「朝城走」是 East，而條件要的是 West。
又因為**面向只有走成功才更新**（原版寫在移動常式裡），
攻方唯一會面向 West 的時機是**退卻**。兩種鏡射組合下這個不對稱是一致的，
所以機制是確定的；它究竟是設計還是原版的 bug，沒有資料可以判斷。
本專案照抄，並在 `hitStructure` 標明。

#### 用原版資料驗過

| 檢查 | 結果 |
|---|---|
| 186 張攻城戰場都有 `0xD0`–`0xDF` 的圖塊 | ✅ 零例外 |
| 每張圖的「城壁段數 ＋ 門數」 | ✅ 全部 ≤ 16，**正好塞得進那 16 筆**，一張都沒滿 |
| 攻城場的城壁段數 | 1–5 段 |
| 攻城場的門格數 | 2–14 格 |

第二條是最有力的一條：段數的算法（連續合併）如果錯了，
會有圖超出 16 筆的額度——**原版沒有為溢位留後路，所以「剛好塞得下」
本身就是解對了的證據**。

### 5.12 ⭐ 戰場是**等角投影**，不是俯視

`sub_1DAAA` 是把戰場座標換成畫面位置的地方，開頭六行就把整個視角定死了：

```asm
mov si, dx
add dx, bx            ; ★ 欄 ＝ X ＋ Y
sub bx, si            ; bx ＝ Y − X
sar bx, 1             ; ★ 算術右移（負數往下取整）
add bx, 20h
sub bx, ax            ; ★ 列 ＝ (Y−X)÷2 ＋ 32 − Z
sub dx, cs:word_1E160 / jl .out / cmp dx, 1Fh / jge .out   ; 31 欄
sub bx, cs:word_1E162 / jl .out / cmp bx, 18h / jge .out   ; 24 列
```

⭐ **`sar` 不能寫成 Go 的 `/2`**——後者往零取整，在 Y < X 的那半邊會差一列。

| 量 | 值 |
|---|---|
| 可見範圍 | **31 欄 × 24 列** |
| 一欄／一列 | 8 px（子圖塊 16 × 32 ＝ 2 欄寬、4 列高） |
| 原生解析度 | 248 × 192（原版 320 × 200 的戰場區） |
| Z 每加一層 | 往上 8 px |

所以 `+1 X` 是螢幕上的 (+8, −4)、`+1 Y` 是 (+8, +4)——標準的 2:1 等角。
一格的圖塊是一疊 1–7 個子圖塊，第 z 個畫在 `列 − z`，堆起來就是柱子。

後半段那個 32 B × 32 × 24 的緩衝區（`word_1E15C`）是**遮蔽用的顯示串列**：
每格記著誰佔著、深度多少，兵走到高處時才不會被前面的地形蓋掉。

### 5.13 ⭐ 人物圖號是算出來的：`sub_1B240` 的尾段

```asm
mov cl, [si+5]        ; 面向 0–3
shl cl, 1             ; ★ 面向的間隔是 2
mov ch, [si+2]
and ch, 19h           ; ★ 狀態旗標只取 bit 0、3、4
test ch, 10h
jz  .keep
xor cl, cl            ; ★ bit 4 設了 → 面向歸零（一律正面）
.keep:
or  cl, ch
add cl, [si+4]        ; ★ ＋ 兵種（記錄裡已經是 × 18）
xor ch, ch
cmp si, 600h / jb .s0
add cx, 5Ah           ; ★ side 1 ＋ 90
.s0:
shl cx, 1             ; ★ 一張圖 ＝ 2 個 320 B 單位
add cx, 0C0h          ; ★ ＋ 192：人物接在 192 個地形子圖塊後面
call sub_1DA1C        ; 存進顯示串列
...
xor byte ptr [si+2], 1   ; ★ bit 0 每次更新翻面 ＝ 走路的動畫幀
```

⭐ **這一段同時解釋了三件本來各自獨立的事**：

| 常數 | 是什麼 |
|---|---|
| `[si+4]` 直接相加 | **兵種存成「× 18」就是為了當圖號用**（`sub_1AB7C` 的門檻也全是 18 的倍數） |
| `add cx, 5Ah`（90） | 一側 90 張，兩側共 180 張 ＝ `BATTLE.SCH` 的 360 個單位 ÷ 2 |
| `add cx, 0C0h`（192） | **地形與人物在同一張表裡**：前 192 個單位是 `BATTLE.MDL` 的子圖塊（61,440 ÷ 320），後面接 `BATTLE.SCH`。`sub_1CC31` 把兩個緩衝區排在一起就是為了這個 |

取圖的算術在 `sub_1E085`：

```asm
shl ax, 1 / shl ah, 1 / add ch, ah / shl ah,1 / shl ah,1 / add ch, ah
xor ah, ah / shr ax, 1 / xchg al, ah / mov si, ax
shr ax, 1 / shr ax, 1 / add si, ax      ; ★ si ＝ 編號 × 320
```

`k × 256 + k × 64 = k × 320` ——**單位大小 320 B 在這裡是直接寫死的**。
接著讀 64 B 當遮罩（`not` ＋ `and`，所以 **1 ＝ 有畫**）、
再讀 256 B 當四個色平面（`or`），與 docs/formats/07 §9 完全一致。

`sub_1E0E1` 是同一件事但帶垂直位移（`dx` ＝ 0x30 或 0x20）：
它把**後面那一格的下半截**貼進這一格的上半——高的人物會壓到後排，
遮蔽就是這樣處理的。

### 5.14 ⭐ `0x0E00` 那組實體 ＝ 場上插的軍旗

`sub_19CB3` 在城壁與門（`0x0C00`）之後，用 `di = 0x200` 再叫一次
`sub_19E10`，也就是從 **`0x0E00`** 開始建第三類實體：

```asm
bl = [si]                  ; 圖塊值
bx = 圖塊值 × 8
ah = [bx]                  ; 堆疊高度
bl += ah ; al = [bx]       ; ★ 最頂層的子圖塊編號
sub al, 0BAh / jb .skip
cmp al, 6    / jnb .skip   ; ★ 只有 0xBA–0xBF 才建
mov word ptr es:[di], 3C0h ; 旗標 0xC0、類型 3
mov es:[di+6], cl          ; X
mov es:[di+8], ch          ; Y
mov es:[di+0Ah], ah        ; Z ＝ 堆疊高度（站在地面上）
mov dx, 150h
test al, 1 / jz .keep
mov dx, 204h               ; ★ 最頂層子圖塊的最低位決定用哪一個
.keep:
mov es:[di+1Ch], dx
call sub_1ECE0 / and al, 3
mov es:[di+1Bh], al        ; 亂數 0–3
```

⭐ **那兩個常數就是圖號。** 用 §5.13 的換算反推：

	(0x150 − 192) ÷ 2 = 72    ＝ 軍旗那一組的起點
	(0x204 − 192) ÷ 2 = 162   = 72 + 90 ＝ 另一側的軍旗

所以這一類是**旗**，而且**旗色是圖塊編號的最低位選的，與交戰雙方無關**——
它是戰場美術的一部分，不是勢力標記。

拿 214 張戰場驗過：每張 0–48 支，**沒有一張超過 `0x0E00`–`0x1800`
之間放得下的 80 筆**（繞路點區從 `0x1800` 開始，§5.8k）；194 張有旗。
原版沒有為溢位留後路，所以「剛好塞得下」本身就是解對了的證據。

#### ⭐ `+0x1B` 是旗子飄動的相位

`sub_1BB10`（每幀由 `sub_1B941` 叫）：

```asm
mov cl, [si+1Bh] / xor ch, ch
cmp al, 6 / jnz .normal        ; al ＝ Z；最高層用另一組
  add cl, 8 / add cx, [si+1Ch] / mov ah, 1 / jmp .draw
.normal:
  shl cx, 1                    ; ★ 相位 × 2
  add cx, [si+1Ch]             ; ★ 圖號 ＝ 基底 ＋ 相位
.draw:
call sub_1DC03                 ; 登錄進顯示串列
inc byte ptr [si+1Bh]
and byte ptr [si+1Bh], 3       ; ★ 0→1→2→3→0
```

顯示串列的一格是 2，所以「相位 × 2」就是**往後挪一張圖**——
**旗子是四張一循環的動畫**。建立時給亂數 0–3，
是為了讓滿場的旗**不要同步揮舞**。

### 5.15 ⭐ 繞路點是誰算的：`loc_1BD46`

`sub_1AED2` 在命令生效那一刻設好起點終點，然後叫這一支；
回傳的 `al` 是點數，寫進兵記錄 `+0x17`。

**第一段：波前擴散**

```asm
mov cs:byte_1BE33, cl      ; ★ 自我修改碼：0xEB（jmp）或 0x74（jz）
mov es, cs:word_1D300      ; 成本圖
xor di, di / mov cx, 2000h / mov ax, 0FFFFh / rep stosw   ; 全部填 0xFFFF
...
mov word ptr [bx], 1       ; 起點放 1
mov dx, 2                  ; 下一波
```

每一格的四個方向由通行圖的 bit 4–7 決定，各自呼叫
`sub_1BF2A`／`1BF4D`／`1BF70`／`1BF97`。以 −X 那一支為例：

```asm
cmp dx, [bx-2] / jnb ret       ; 已經有更好的值就不動
mov al, es:[bx+2000h]          ; ★ 那一格的**地形成本**
xor ah, ah / add ax, dx        ; ★ 累加的不是 1，是成本
mov [bx], ax
mov [si], bx / add si, 2 / and si, 47FFh   ; 推進環狀佇列
```

⭐ **所以這不是單純的 BFS，是 uniform-cost 搜尋**——地形會拖慢腳步。
成本表在 `es:[bx+2000h]`，也就是 `ds:0D2FE` 那 8 KB（本來標「未解」）。

`test al, 8` 後面緊接著 `byte_1BE33`——**那個自我修改的 byte 就是
「爬不爬得上去」的開關**（`cmp byte ptr [si+4], 12h / jbe` 決定寫哪個）。

**第二段：回溯**

```asm
sub dx, 2
mov cl, 40h                ; ★ 最多 64 個點
.loop:
cmp dx, [bx-2]  / jz .west     ; dec al ; bx -= 2
cmp dx, [bx+2]  / jz .east     ; inc al ; bx += 2
mov ch, 1
cmp dx, [bx-80h] / jz .north   ; dec ah ; bx -= 0x80
cmp dx, [bx+80h] / jz .south   ; inc ah ; bx += 0x80
...
stosw                          ; ★ 只有換軸時才寫（ch 記著上一步是橫是縱）
```

⭐ **只有轉彎才寫一個點**，一個點 2 byte 存 (X, Y)。
`mov cl, 40h` ＝ 64 個點 × 2 byte ＝ **128 byte**，
正好是 `0x1800 + 兵編號 × 128` 那塊的大小（§5.8k）——兩邊對得上。

一列是 64 格 × 2 byte ＝ `0x80`，所以 `±2` 是 X、`±0x80` 是 Y。

#### ⭐ 那張地形成本表**永遠是 0**

`sub_1BBA6` 最後把它整個歸零：

```asm
mov es, cs:word_1D2FE
xor ax, ax / mov di, ax / mov cx, 1000h / rep stosw
```

而**整支程式再也沒有人寫它**——`word_1D2FE` 這個符號全檔只出現兩次
（資料定義 ＋ 上面那一次歸零），從其他基底也搆不到
（`+0x2000`／`+0x3000` 那些寫入的 `ds`／`es` 都是 `word_1D2FA`
的七層通行圖，那是另一塊）。

所以 `[bx] = 地形成本 + dx = dx`，**實際行為就是純 BFS**。
這是一個**配置了、讀了，但沒有人餵資料**的設計——
留著鉤子但沒接上，不是我們沒解出來。

> ⚠ 本專案多加了一個原版沒有的重算節流（`replanInterval`），
> 因為這裡的兵每幀都可能被別人擋住。

### 5.16 ⭐ 撞到人：敵人就打、自己人就**對調位置**

`sub_1B1B1` 是移動前的檢查：`test al, 7Fh` —— 目標格的低 7 位就是
佔用者的編號（bit 7 是地形實心）。**有人就擋，沒有「穿過去」這回事**，
接著把編號交給碰撞處理 `loc_1B533`：

```asm
dec al / mov ah, al / xor al, al / shr ax,1 ×3   ; di ＝ 編號 × 32
cmp di, 0C00h / jnb loc_1B5B7                    ; ★ ≥ 0xC00 → 城壁／門（§5.11）
cmp byte ptr [si+4], 0 / jnz loc_1B559           ; 我是大將 → 另一條
loc_1B559:
cmp si, 600h / jb byte_1B567
  db 81h, 0FFh, 0 / byte_1B562 db 6              ; ★ cmp di, <立即值>
  jb loc_1B5A1                                   ;   敵人 → 打
  jmp loc_1B56D                                  ;   自己人 → 換位置
byte_1B567 db 81h, 0FFh, 0 / byte_1B56A db 6     ; ★ 另一側用的那一條
  jnb loc_1B5A1
```

⭐ **那兩個 `cmp di, imm16` 的立即值是自我修改碼填的**
（`sub_19A33` 的 `mov byte_1B562, dl` ／ `mov byte_1B56A, dh`）——
敵我的分界線直接寫進指令裡。**這是本作第四處自我修改碼**
（另外三處：`byte_1A06A`、`byte_1AB4F`、`byte_1BE33`）。

**敵人擋路**（`loc_1B5A1`）→ 對方不是大將就 `sub_1B618`（打），
是大將就 `sub_1B6BC`；**自己不移動**。

**自己人擋路**（`loc_1B56D`）→ 檢查四條，全過就 `sub_1B732`：

| 條件 | 不換的理由 |
|---|---|
| `[di+04] == 0` | 擋路的是**大將** |
| `[di] & 0x61` | bit 0 ＝ **陣亡**（`sub_1B618` 體力扣到 0 時設）；bit 5 ＝ **正在移動常式裡**（`sub_1AF69` 進出時設／清，重入保護）；bit 6 ＝ **這一幀已經被換過** |
| `[di+02] & 0x10` | **剛剛被打中**（`sub_1B618` 設，同時把面向歸零） |
| `[di+1A] == 5` | 擋路的正在**退卻** |

再分兩種：`[si+1E] == [di+1E]`（**同一個 Z 平面**，那個欄位是平面位址的
高位）→ 直接換；跨平面 → **兩邊都要是弓兵或步兵**
（`cmp [si+4], 12h / jbe` 兩次）——大將與騎馬本來就爬不上城牆。

`sub_1B732` 把 X／Y／Z、格子指標、佔用圖的內容、平面位址全部 `xchg`，
最後 `or byte ptr [di], 40h` 標記被換的那一個；
`sub_1B240` 在那個兵自己更新時 `and byte ptr [si], 0BFh` 清掉。
**這個旗標擋的是「同一幀裡第三個人再來換」**。

> 這一段推翻了本專案原本的作法（「退卻中的兵可以穿過自己人」）。
> 那是在沒解出 `sub_1B732` 之前為了不讓陣線卡死而做的權宜；
> 原版的答案漂亮得多——**陣線是靠互換穿透的**。

### 5.17 ⭐ 撞到敵方**大將**：`sub_1B6BC`

`loc_1B5A1` 分兩支：對方不是大將走 `sub_1B618`（一般近戰），
**是大將就走 `sub_1B6BC`**——大將不是打不到，是要先過一關：

```asm
cmp byte ptr [di+3], 1  / jbe .miss     ; 體力 ≤ 1 → 打不動
mov al, [di+1Ah]
cmp al, 0 / jz .miss                    ; 大將在陣形中 → 打不到
cmp al, 5 / jz .miss                    ; 大將退卻中   → 打不到
call sub_1ECE0 / cmp al, 19h / jb .hit  ; ★ 亂數 < 25/256 ≈ 10% 直接命中
call sub_1ECE0
mov ah, [si+18h] / sub ah, [di+18h]     ; ★ 攻擊者戰力 − 大將戰力
jnb .1 / xor ah, ah                     ;   負的當 0
.1: cmp ah, 18h / jbe .2 / mov ah, 18h  ;   上限 24
.2: and al, 7Fh / cmp al, ah / jnb .miss ;  亂數 & 0x7F < 差值才命中
.hit:
  ...受擊硬直（+0x02 bit 4）＋ 面向歸零...
  mov al, [si+18h] / shr al,1 ×3        ; ★ 傷害 ＝ 攻擊者戰力 ÷ 8
  and al, al / jnz .3 / mov al, 1       ;   至少 1
.3: sub [di+3], al / ja .4
  mov byte ptr [di+3], 1                ; ★ 大將體力最低留 1——打不死
.4: ...
.end:
  and byte ptr [si+2], 1 / or byte ptr [si+2], 8   ; ★ 攻擊者設 +0x02 bit 3
```

⭐ 最後那一行解掉了圖號公式（§5.13）裡剩下的 bit 3：
**打在大將身上會換一張圖**。

⭐ **大將打不死，但打得動**——體力最低留 1，而體力 < 50 就觸發全軍退卻
（§5.8h）。所以「圍毆敵方大將」是一條真的戰術，說明書 11.4 的中央突破
之所以有用就是這個。

> 本專案原本把「撞到敵方大將」實作成「什麼都不做」，
> 結果殘兵繞著對方大將撞到天荒地老、戰鬥永遠打不完——
> 是 `TestBattleTerminates` 把它擋下來的。

## 7. 調色盤：不是變數了

戰場的調色盤與大地圖同源：

```asm
sub_10A1C（淡入）：
mov si, 1964h
.loop: mov bh, cs:[si] / mov dl, cs:[si+1] / mov dh, cs:[si+2]
       mov al, ch / mov bl, cl / call sub_1EBDC     ; cl ＝ 亮度 16→0
       add si, 3 / inc ch / cmp ch, 10h / jb .loop
```

`cs:0x1964` 是**執行期的 16 色調色盤**，由 `cs:0x18D4` 複製過來
（`mov si, 18D4h / mov di, 1964h / mov cx, 18h / rep movsw`，24 word ＝ 48 byte）。
而 `sub_19946`（戰場初始化）開頭那 16 次 `sub_1EBDC` 傳的是全 0——
**那是淡出到黑，不是設定調色盤**。

`GAMEPAL.BRG` 的值域是 **0–15（4 bit）**，`sub_1EBDC` 會把它乘上亮度再
`shl ah,1` 兩次送進 VGA DAC 的 6 bit。

> ⚠ 本專案在探查像素格式時一度把它當成 6 bit 除以 63，畫出來整片死黑，
> 差點把「太暗看不出是什麼」當成「格式解錯」。
> **`internal/assets/palette` 本來就寫對了**（那份註解明說兩者位寬不同），
> 是臨時的探查腳本自己弄錯的。
