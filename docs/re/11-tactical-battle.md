# 11 — 戰術戰鬥：模組結構與戰場資料模型

**狀態：模組骨架與戰場資料模型已解。戰鬥規則本身還沒解。**

- 日期：2026-08-08
- 輸入：`workplace/ida/dosv/KI.EXE.i64`、`BATTLE.MAP`、`BATTLE.MDL`
- 前置：`docs/re/09`（戰略層的戰鬥）、`docs/formats/07`（`BATTLE.*` 分段）

戰術層是本作最大的一塊未解區域，約 15 KB 的程式碼、上百個函式，
而且用了自我修改碼。這一份不假裝解完了——它做兩件事：
**把模組的骨架畫出來**，讓下一趟不必再從入口摸起；
**把戰場的資料模型解到可以驗證的程度**，那是戰術層一切規則的地基。

## 1. 入口與主迴圈

```asm
sub_11B5A:                    ; 戰略層呼叫這裡（docs/re/09 §10）
  call sub_12078
  mov ax,2 / call sub_20000   ; 滑鼠：隱藏游標
  call sub_10A1C
  call sub_19946              ; ★ 戰場初始化
  call sub_19FA0              ; ★ 主迴圈，回傳 al ＝ 勝方

sub_19FA0:
  mov word_1D340, sp          ; 存 sp —— 結束時用它跳出來，不是正常回返
  mov ax,1 / call sub_20000   ; 滑鼠：顯示游標
  call sub_1A1C5
.loop:
  call sub_1A156              ; 讀滑鼠 → bx ＝ 按鍵
  test bx, 3 / jz .tick
    call sub_1E453
    cmp bx, 1 / jnz .right
    call sub_1BFF2            ; 左鍵
    jmp .tick
  .right: call sub_1C01D      ; 右鍵
.tick:
  call sub_1A426              ; ★ 執行一個腳本指令
  call loc_1A065              ; ★ 每幀更新 ＋ 繪製
  jmp .loop
```

**主迴圈沒有出口。** 結束是把 `word_1D340` 寫回 `sp`——
所以戰鬥的任何一層都能直接跳出來，不必逐層回返。
找「戰鬥怎麼結束」要找 `mov sp, cs:word_1D340`，不是找 `retn`。

### ⚠ `loc_1A065` 有自我修改碼

```asm
loc_1A065:
  cmp byte ptr ds:0D348h, 0
byte_1A06A db 74h              ; ← sub_19A33 執行期寫進來的 `jz`
```

`sub_19A33` 裡有 `mov byte_1A06A, 74h`——它在**執行期**把一個位元組
寫成 `jz` 的機器碼。IDA 靜態看到的是資料，後面幾行整段反編錯。
讀這一段要手動解位元組，**不要相信反編結果**。

## 3. ⭐ 每幀執行一個腳本指令

### 3.1 直譯器：`sub_1A426`

```asm
cmp cs:word_1D313, 0 / jz .run
dec cs:word_1D313 / retn       ; ★ 等待中：這一幀什麼都不做
.run:
mov ds, cs:word_1D30C          ; 腳本緩衝區的段
mov si, cs:word_1D311          ; 讀取位置
mov ax, [si]                   ; 一個 word 就是一個指令
mov bl, al / and bl, 1Fh       ; 低 5 位 ＝ 指令碼（0–18）
shl bx, 1
and al, 0E0h / rol al,1 ×3     ; 高 3 位 ＝ 參數（0–7）
inc si / inc si
call cs:funcs_1A457[bx]        ; 19 個處理常式
mov cs:word_1D311, si
```

```
一個指令 ＝ 2 byte
  byte 0 低 5 位  指令碼 0–18
  byte 0 高 3 位  參數 0–7
  byte 1         運算元
```

### 3.2 ⭐ 腳本來自 `BATTLE.DAT`，而且是**依武將挑的**

`sub_1CBE5` 把 256 byte 讀進 `word_1D30C`：

```asm
mov al, ds:0D34Bh              ; 戰場類別（戰場編號 <0xC0→0、<0xD1→1、否則 2）
inc al
cmp byte ptr ds:0D35h, 80h / jb .1
cmp al, 1 / jnz .1
xor al, al
.1:
mov bx, ds:0D30h / sub bx, 2240h / shr bx, 1   ; 軍團位址 → 武將記錄
mov ds, word ptr ds:0D52h
mov ah, [bx+4256h]             ; ★ 武將 +0x16
shl ah, 1 / shl ah, 1          ; ×4
add ah, al                     ; 段編號 ＝ 武將+0x16 × 4 + 戰場類別
xor al, al                     ; ax ＝ 段編號 × 256 ＝ 檔案位移
mov dx, 0D8Fh                  ; 'BATTLE.DAT'
mov bx, ds:0D30Ch / mov di, 100h
call sub_1E38C
```

```
BATTLE.DAT ＝ 8,192 B ＝ 32 段 × 256 B
段編號 ＝ 武將 +0x16（0–7）× 4 ＋ 戰場類別（0–3）
```

**檔案是不是腳本，用資料就驗得掉**（`tools/battledat.py verify`）：

> 4,096 個 word 的低 5 位**沒有一個 ≥ 19**。
> 位元組若是隨機的，期望會有約 1,664 個超過。

### 3.3 ⭐ 武將 `+0x16` 是戰法性格（0–7）

四個劇本共 508 筆武將記錄，`+0x16` 的值域**正好是 0–7**，
而且與能力值單調對應：

| 腳本 | 人數 | 平均武力 | 平均統率 | 平均政治 | 代表 |
|---:|---:|---:|---:|---:|---|
| **0** | 19 | **13.6** | 6.0 | 2.0 | 呂布 |
| 1 | 34 | 10.7 | 6.5 | 3.5 | 張飛 |
| 2 | 86 | 9.3 | 8.2 | 4.5 | 曹操、關羽、趙雲、劉備 |
| 3 | 116 | 6.6 | 5.7 | 3.2 | 一般武將（最多） |
| 4 | 21 | 5.2 | **10.4** | **11.8** | 諸葛亮 |
| 5 | 66 | 5.0 | 10.2 | 9.8 | — |
| 6 | 21 | 3.0 | 5.4 | 11.8 | — |
| **7** | 18 | **1.5** | 2.2 | 10.6 | 純文官 |

**武力從 13.6 單調降到 1.5。** `docs/formats/08` §3 原本把 `+0x16`
標成「值域 0–7，未解」——它是**這名武將在戰場上跑哪一套腳本**。

說明書第 11 章那些對 AI 行為的觀察（高統率武將待在後方、疲勞就後退
重整陣形、守軍會朝射擊來源集中）**全部是這 32 段腳本跑出來的**。
解讀那 19 個指令，等於把整個戰術 AI 拿到手。

### 3.4 ⭐ 一個指令不一定是兩個 byte

**分支指令後面那個 word 是跳躍目標，不是指令。**

```asm
sub_1A591（指令 10）：
mov bl, al / shl bx, 1 / jmp cs:jpt_1A597[bx]   ; 參數選五種比較之一
  0  無條件
  1  條件 == 運算元
  2  條件 != 運算元
  3  條件 <  運算元
  4  條件 >  運算元
成立 → mov bx, [si]            ; 下一個 word
       and bl, bl / jnz ret    ; 低位元組非 0 就不跳
       mov bl, bh / xor bh,bh / shl bx,1 / mov si, bx   ; ★ si ← 高位元組 × 2
不成立 → cmp byte ptr [si], 0 / jnz ret / inc si / inc si   ; 跳過目標
```

目標 word 長得像「等待」（低位元組 0），所以**照直線每兩個 byte 切一刀
會把 564 個目標誤讀成 564 次等待**。本專案的第一版工具就是這樣算的，
指令 0 的次數從 2,352 掉到 1,788，正好差 564。

兩條驗證，都是零例外：

| 檢查 | 結果 |
|---|---|
| 分支指令後面那個 word 的低位元組是 0 | **564 / 564** |
| 跳躍目標落在**指令邊界**上 | **564 / 564** |

第二條特別硬：指令長度模型只要錯一個地方，後面的邊界就會整段位移，
目標會落在半個指令中間。

### 3.6 ⭐ 單位記錄：`word_1D30E`

指令 3、6、7、13、17、18 都用同一組位址算式，佈局就掉出來了：

```
word_1D30E 段：
  0x0000 – 0x05FF   敵方六隊，每隊 0x100 B
  0x0600 – 0x0BFF   ★ 我方六隊（腳本操作的是這一側）
  0x0C00 – 0x0DFF   16 筆 × 0x20 B 的另一張表（指令 15 掃它）
```

六隊 × 256 B ＝ `0x600`，兩側剛好首尾相接。已解出的欄位：

| 偏移 | 內容 | 出處 |
|---|---|---|
| `+0x00` | 旗標。指令 13 會設 bit 3 | `sub_1A60D` |
| `+0x03` | 未解，指令 18 拿它當條件 | `sub_1A6E8` |
| `+0x1A` | **目前生效的命令** | `sub_1A52E` 讀它 |
| `+0x1B` | **新下達的命令** | `sub_1A4BF` 寫它 |
| `+0x24` | 未解。指令 13 拿 `參數 × 18` 去比對它分組 | `sub_1A60D` |

`+0x1A` 與 `+0x1B` 是兩個不同的欄位——**下令與生效是分開的**，
所以腳本可以「下令之後等幾幀，再問全軍到位了沒」。

### 3.7 命令碼：城壁移動在野戰會自動變成攻擊

指令 3 與 13 都有同一段：

```asm
cmp al, 3 / jnz .1
cmp cs:byte_1AB4F, 0 / jnz .1     ; 城門的 X ＝ 0 → 這張圖沒有城
mov al, 1                          ; ★ 命令 3 → 命令 1
.1:
```

`byte_1AB4F` 是索引第二欄（§4.5），**野戰用的戰場它是 0**。
所以**命令 3 只在攻城戰有意義，野戰時退回命令 1**。
說明書 4.2 的六個戰術指令裡，只有「**城壁移動**」是攻城限定的，
而它的替代品自然是「**攻擊**」。→ **命令 3 ＝ 城壁移動、命令 1 ＝ 攻擊**（強證據）。

命令 5 走另一條路（`sub_1A8F6`），與其他命令不同——待查。

## 4. ⭐ 戰場的資料模型

### 4.1 三層結構

```
BATTLE.MAP  512 B 索引（每筆 2 B）＋ 214 個戰場 × 4,096 B
              每個戰場：64 B 表頭 ＋ 3,968 格（64 × 62）＋ 64 B 尾段
              每一格 ＝ 一個 byte 的**圖塊編號**

BATTLE.MDL  4,096 B 表頭（3 × 256 B 屬性表）＋ 3 個圖塊組 × 63,488 B
              每組前 2,048 B ＝ 256 筆 × 8 B 的**圖塊定義**
              其餘 61,440 B ＝ 像素資料
```

索引的第一欄是圖塊組編號（0–2），第二欄見 §4.4。

### 4.2 ⭐ 一格是一疊圖塊，不是一塊

8 byte 的圖塊定義：

```
[0]        堆疊高度 k（0–7）
[1..k]     由下往上的子圖塊編號
[k+1..7]   0
```

驗過三個圖塊組共 768 筆：**`[k+1..7]` 全為 0，零例外**。
`[1..k]` 之間允許有 0（那一層是空的）。

兩支程式各自印證：

```asm
; sub_19E10：讀「最上層」那一格
mov ah, [bx]        ; 高度 k
add bl, ah
mov al, [bx]        ; ★ [k] ＝ 頂端的子圖塊
sub al, 0BAh / cmp al, 6 / jnb skip    ; 0xBA–0xBF → 生成一個物件

; sub_1BB6D：把七層各自的通行性寫進 7 張 4,096 B 的圖
mov ah, 7
.loop:
  inc bx / mov al, [bx]
  and al, al / jz .block
  cmp al, 70h / jnb .block             ; ★ 0 或 ≥ 0x70 → 該層不可通行
  and byte ptr es:[di], 7Fh / jmp .next
.block: or byte ptr es:[di], 80h
.next: add di, 1000h / dec ah / jnz .loop
sub di, 7000h
```

7 × 4,096 ＝ 28,672 ＝ `ds:0D2FA` 的大小，**完全吻合**。

### 4.3 ⭐ 堆疊高度 ≥ 4 ＝ 站在高處

```asm
; sub_1B240：單位移動後
mov ds, cs:word_1D2F6 / mov bl, [bx]   ; 該格的圖塊編號
cmp bl, 0F0h / jnb .clear
mov ds, cs:word_1D302
shl bx,1 ×3 / mov al, [bx]             ; 堆疊高度
cmp al, 4 / jb .clear
or byte ptr [si], 2                    ; ★ 單位旗標 bit 1
.clear: and byte ptr [si], 0FDh
```

把 214 張戰場依「堆疊高度 ≥ 4」上色，形狀自己說話
（`tools/battlefield.py map 5`）：

```
戰場 5（攻城用）                                戰場 200（野戰・平原＋水域）
 8 .........................OO########OOO######.   ............................
11 .........................###.................   ............................
25 .........................#####...............   ............................
52 .........................######################  ............................
```

**攻城用的戰場長出一圈封閉的城牆。** 這比「看圖塊像什麼」硬得多——
空間關係不是判讀時能安排的。

不過**高處不等於城牆**：野戰用的戰場也有高處，那是山與林。
下一節那張查表給了獨立的佐證。

### 4.4 ⭐ 野戰戰場是依地形組合查表選的

`sub_14BDD` 拿**兩格的地形類型**去查一張 21 筆 × 3 B 的表
（`cs:97F0h`，檔案偏移 `0x99F0`）：

```asm
mov bx, 97F0h / mov cx, 15h        ; 21 筆
.loop:
  mov dl, [bx]
  cmp ax, [bx+1] / jz .hit         ; (類型A, 類型B) 配對
  xchg al, ah / xor dh, 40h        ; ★ 換順序再比一次
  jnz .loop
  add bx, 3 / loop .loop
mov dl, 6                          ; 都不中 → 偏移 6
.hit: mov cx, dx / add cl, 0C0h    ; 戰場編號 ＝ 0xC0 + 偏移
```

⭐ **旋轉旗標就是「配對是換過順序才中的」**：`xor dh, 40h` 設的正是
`byte_10D35` 的 bit 6，而 `sub_1CAEB` 看的也是同一個位元。
戰場轉不轉 180 度，取決於兩格地形誰在前——不是另外算的方向。

地形類型的編號見 `docs/mechanics/30-combat.md` §2
（0 平原、3 山地、4／5 兩種林地、6／7 水域）：

| 戰場 | 地形組合 | 高處格數 |
|---:|---|---:|
| **192** | 山 ＋ 山 | **596** |
| 193 | 山 ＋ 平原 | 284 |
| 194 | 山 ＋ 林5 | 678 |
| 195 | 山 ＋ 水6 | 283 |
| 196 | 山 ＋ 林4 | 247 |
| 197 | 山 ＋ 水7 | 488 |

所以這五張有兩條來路。

### 4.5 索引第二欄是城門附近的 X 座標

`sub_1CAEB` 把它讀進 `byte_1AB4F`，而戰場旋轉 180 度時：

```asm
test cs:byte_10D35, 40h / jz skip
cmp cs:byte_1AB4F, 0 / jz .1
mov al, 3Fh / sub al, cs:byte_1AB4F    ; ★ v ← 63 − v
```

`0x3F` ＝ 63 ＝ **寬度 − 1**（戰場是 64 寬 62 高），所以它是 **X 座標**，
不是 Y。統計對得上（`tools/battlefield.py survey`）：

| 檢查 | 結果 |
|---|---|
| 戰場 **192–213**（野戰用）第二欄 | **全為 0**，22 張零例外 |
| 第二欄非 0 的 186 張 | **全部有高處**，零例外 |
| 第二欄 vs 最近的物件格 X | 25 張相同、123 張差 1、29 張差 2 |

戰場 0–191 一一對應 192 個據點——**`docs/re/05`「據點編號直接當戰場編號」
在資料上也成立了**。

### 4.6 物件格：頂層子圖塊 `0xBA`–`0xBF`

`sub_19E10` 掃過全部 3,968 格，替頂層落在這個範圍的格子各生成一個
32 byte 的記錄：

```asm
mov word ptr es:[di], 3C0h
mov es:[di+6], cl / mov es:[di+8], ch     ; X, Y
mov es:[di+0Ah], ah                       ; 堆疊高度
mov dx, 150h
test al, 1 / jz .1 / mov dx, 204h         ; 依子圖塊編號的奇偶二選一
.1: mov es:[di+1Ch], dx
call sub_1ECE0 / and al,3
mov es:[di+1Bh], al                       ; 隨機 0–3
add di, 20h                               ; 記錄 32 B
```

在攻城用的戰場上，這些格子**全部落在城牆線上**：戰場 5 是左牆面
兩段各 4 格、上下牆面各 5 格。說明書 4.4 說「梯子的位置每張地圖是固定的」，
位置對得起來。

⚠ **但不能就這樣定案。** 戰場 209–213（山地、林地、水域）上也各有
19–48 個物件格，而那裡沒有城牆。所以這個範圍是「**會生成互動物件的
子圖塊**」，城門與梯子只是其中一種用途。**用途待驗。**

野戰用的 192–208 一個物件格都沒有。

## 5. ⭐ 每幀更新：戰場其實是 64 × 64 × 7 的立體格

`loc_1A065` 有自我修改碼（§1），手動解位元組之後是：

```asm
cmp byte ptr ds:0D348h, 0
jz  .1                          ; ← 那個被寫進去的 0x74
  mov dx, ds:0D328h / mov bx, ds:0D32Ah
  call sub_1DC9D
  mov byte ptr ds:0D348h, 0
.1:
call sub_1A12A
call sub_1A6FA
call sub_1B941                  ; ★ 實體更新
```

### 5.1 `sub_1B941`：兩張表，每幀各掃一遍

```asm
mov ds, cs:word_1D30E / mov es, cs:word_1D2FA
mov si, 1400h
.a: cmp byte ptr [si], 0C0h / jb .next
    call sub_1B97E / call sub_1BA2E / call sub_1BAB7
.next: add si, 20h / cmp si, 1800h / jb .a
mov si, 0E00h
.b: cmp byte ptr [si], 0C0h / jb .next2
    call sub_1BB10
.next2: add si, 20h / cmp si, 1400h / jb .b
```

`word_1D30E` 的佈局到這裡補齊了：

| 範圍 | 筆數 × 大小 | 內容 |
|---|---|---|
| `0x0000`–`0x0BFF` | 96 × 32 B | **兵士**。`0x01`–`0x2F` 一方、`0x30`–`0x5F` 另一方 |
| `0x0C00`–`0x0DFF` | 16 × 32 B | 指令 15 掃它（§3.5） |
| `0x0E00`–`0x13FF` | 48 × 32 B | 每幀畫一次，`+0x1B` 是 4 幀動畫相位 |
| `0x1400`–`0x17FF` | 32 × 32 B | **飛道具**（箭之類的） |

⭐ **一側 48 個兵，分成 6 隊 × 8 人。** 腳本操作的「六隊」
（`0x600 + k × 0x100`）就是每隊的**第一個兵**——`0x100` ＝ 8 × 32。

說明書 4.1 說戰場上 1 個兵 ＝ 戰略的 10 人，而一個編成位置是 1,000 人
＝ 100 個兵；場上只放得下 8 個，其餘就是那句
「**残りは予備兵として画面外に待機**」。

### 5.2 ⭐ 格子索引是三維的

`sub_1BA2E`（飛道具移動）：

```asm
mov al, [si+5]                  ; 方向
mov bx, [si+10h]                ; 格索引
test al, 1 / jnz .vert
  and al,al / jnz .east
  dec bx / dec byte ptr [si+7]  ; ★ 西：−1，X −1
.east: inc bx / inc byte ptr [si+7]
.vert:
  cmp al,1 / jnz .south
  sub bx, 40h / dec byte ptr [si+9]   ; ★ 北：−0x40，Y −1
.south: add bx, 40h / inc byte ptr [si+9]
```

一列 `0x40` ＝ **64 格**，正是戰場的寬。而 `sub_1BB6D`（§4.2）把七層的
通行性寫在相隔 `0x1000` 的七張圖上，`0x1000` ＝ 4,096 ＝ 64 × 64。

```
格索引 ＝ Z × 0x1000 ＋ Y × 0x40 ＋ X
7 × 4,096 ＝ 28,672 ＝ ds:0D2FA 的大小
```

⭐ **戰場是 64 × 64 × 7 的立體格**，而 §4.2 那個「一格是一疊 1–7 層圖塊」
定義的就是**哪幾層是實心的**。兩件事在這裡接上了：
堆疊高得比較高的地方（城牆），兵站的 Z 就比較高——
說明書的「城壁に登る」在資料上就是換一層 Z。

### 5.3 ⭐ 命中判定：`sub_1B97E`

```asm
mov bx, [si+10h] / mov bh, es:[bx]     ; 那一格的內容
and bh, bh / jz ret                     ; 0 ＝ 空
cmp bh, 80h / jnb .hitWall              ; ≥ 0x80 ＝ 障礙 → 飛道具消失
cmp bh, 60h / ja ret
dec bh                                  ; ★ 格子裡存的是「兵編號 + 1」
cmp word ptr [si+2], 600h / jnb .mine
  cmp bh, 30h / jb ret                  ; 敵方射的，打到 <0x30 是自己人
  jmp .hit
.mine: cmp bh, 30h / jnb ret            ; 我方射的，打到 ≥0x30 是自己人
.hit: xor bl,bl / shr bx,1 ×3           ; ★ 兵記錄 ＝ 編號 × 32
      cmp byte ptr [bx], 80h / jb ret
```

**佔用圖每格存的是「兵編號 + 1」**，`0` 是空格、`≥ 0x80` 是障礙。
編號 `0x01`–`0x2F` 與 `0x30`–`0x5F` 分屬兩軍，**誤傷自己人不判定**。

### 5.4 ⭐ 扣體力

```asm
cmp byte ptr [bx+4], 0 / jz .dmg
cmp byte ptr [bx+3], 64h / jnb .dmg     ; ★ 體力滿 100 → 不觸發下面這段
mov ax, [bx+1Ah]
cmp al,5 / jz .dmg / cmp ah,5 / jz .dmg
cmp al,ah / jz .1 / mov [bx+1Ah], ah
.1: mov byte ptr [bx+1Bh], 5            ; ★ 受傷的兵自己改成命令 5
.dmg:
mov al, [si+4]                          ; 飛道具的威力
cmp byte ptr [bx+4], 36h / jz .quarter
cmp byte ptr [bx+4], 0 / jnz .full
test byte ptr [bx+2], 1 / jz ret        ; 不受傷
.quarter: shr al,1 / shr al,1           ; ★ 威力 ÷ 4
.full:
mov byte ptr [bx+1], 2                  ; 動作 ＝ 被打中
…
sub [bx+3], al / ja .alive              ; ★ 體力 −= 威力
mov byte ptr [bx+3], 1
cmp byte ptr [bx+4], 0 / jz .alive
  and byte ptr [bx], 10h / or byte ptr [bx], 1
  mov byte ptr [bx+1], 4                ; 動作 ＝ 倒下
  mov byte ptr [bx+3], 0                ; ★ 死亡
.alive: mov al, 0Bh / call sub_102F5
```

兵士記錄（32 B）已解出的欄位：

| 偏移 | 內容 |
|---|---|
| `+0x00` | 旗標，`≥ 0x80` 存在；bit 6 這一幀被打中 |
| `+0x01` | 動作：`2` ＝ 被打中、`4` ＝ 倒下 |
| `+0x02` | 旗標，bit 0 決定 `+0x04 == 0` 的兵受不受傷 |
| **`+0x03`** | **體力**，上限 **100** |
| `+0x04` | 類別：`0x36` 這種傷害只吃四分之一；`0` 這種要 `+0x02` bit 0 才受傷 |
| `+0x1A` | 生效中的命令 |
| `+0x1B` | 新下達的命令 |

⭐ **受傷的兵會自己把命令改成 5**（體力滿 100 的不會）。
說明書 4.1：「兵士が戦闘して敵にやられると、**画面外に退却**し、
待機中の兵が出陣します」——**命令 5 ＝ 退卻**（強證據）。
指令 3 對命令 5 走另一條路（`sub_1A8F6`）也對得上：退卻不是普通命令。

### 5.5 飛道具會隨高度改變威力

`sub_1BAB7`（畫出來並更新）：

```asm
mov cl, al / xchg cl, [si+0Eh]     ; al ＝ 新的 Z，cl ＝ 舊的 Z
mov ch, [si+4] / shr ch,1 / shr ch,1   ; 威力 ÷ 4
cmp al, cl / jz .same
jb  .down
sub [si+4], ch                     ; ★ 往上飛 → 威力 −25%
jmp .same
.down: inc ch / add [si+4], ch      ; ★ 往下落 → 威力 +25%
```

**箭往上飛威力遞減、往下落威力遞增。** 這解釋了說明書為什麼強調
「城壁に登って攻撃」——站在高處往下射，每一格都在加成。
