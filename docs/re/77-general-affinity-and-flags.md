## 1. 月結時武將表怎麼走

`sub_1585F`（由 `sub_15358` 的月結呼叫）逐筆掃 127 名武將：

```asm
mov     si, 4240h / mov cx, 7Fh
loop:   cmp  byte ptr [si], 80h   / jb  next    ; bit 7 ＝ 在場
        cmp  byte ptr [si+18h], 0 / jz  +       ; +18h ＝ 倒數計時器
        dec  byte ptr [si+18h]    / jmp next
    +:  cmp  byte ptr [si+1Ch], 0FFh / jnz +    ; 1Ch ＝ 所屬勢力
        call sub_15899            / jmp next    ; ⭐ 在野的走這條
    +:  cmp  byte ptr [si+1Dh], 0FFh / jz  next  ; 1Dh ＝ 捕虜狀態
        call sub_15940                          ; ⭐ 俘虜的走這條
next:   add  si, 20h / loop
```

⭐ **兩條路各自讀 `+0x19`，而且用法一致**：那個欄位記的是
「這名武將心向哪一個勢力」。

## 2. `+0x19` ＝ 心向的勢力

### 2.1 在野：`sub_15899` 的第一條路

```asm
mov     bh, [si+19h]
cmp     bh, 0FFh
jz      loc_158C2               ; 沒有心向的勢力 → §2.3 的隨機投靠
call    sub_1ECE0               ; 亂數
cmp     al, 40h
jnb     locret                  ; ⭐ 75% 什麼都不做
mov     byte ptr [si+19h], 0FFh ; 兌現，欄位清掉
xor     bl, bl / shr bx,1 / shr bx,1    ; bx ＝ 勢力編號 × 64
cmp     byte ptr [bx], 80h
jnb     loc_1591A               ; ⭐ 那個勢力還在 → 出仕過去
test    byte ptr [si], 20h      ; ⭐ 旗標 bit 5
jz      locret
mov     byte ptr [si], 0        ; 勢力已滅 ＋ bit 5 → 整筆歸零，退場
```

`loc_1591A` 是共用的出仕收尾：對象是玩家勢力就跳訊息 `0x29`，
然後 `[si+1Ch] = 勢力編號`、`sub_12AD2` 更新該勢力的武將數。

### 2.2 俘虜：`sub_15940`

```asm
call    sub_1ECE0
cmp     al, 40h / jnb retn      ; 75% 什麼都不做
cmp     al, 20h / jb  逃走
mov     al, [si+1Ch]            ; 現在關押他的勢力
cmp     al, [si+19h]            ; ⭐ 剛好是心向的那一個？
jnz     retn
  歸降： [si+1Dh] = 0FFh（不再是捕虜）、[si+17h] = 0（職務清空）
        sub_12AD2(ah=0FFh)、訊息 42h
逃走： bl = (亂數 & 0Fh) + 8、sub_1301C(al=9)、訊息 41h
        [si+1Ch] = 18h（無所屬）
```

| 亂數 `al` | 機率 | 結果 |
|---|---:|---|
| `< 0x20` | 12.5% | **逃走**（訊息 `0x41`「俘虜的{1}逃走了！」），轉無所屬 |
| `0x20`–`0x3F` | 12.5% | `+0x1C == +0x19` 才**歸降**（訊息 `0x42`「俘虜到的{1}已歸降我軍了」）|
| `≥ 0x40` | 75% | 不動 |

⭐ **歸降不是無條件的**：抓他的勢力必須就是 `+0x19` 記的那一個。

### 2.3 沒有心向勢力時：投靠武將數最少的勢力

`sub_15899` 的第二條路已經寫在
[`../mechanics/70`](../mechanics/70-ai.md) §3.9（掃 22 個勢力找 `+0x18` 最小者、
玩家勢力另有「武將數 < 據點數 ÷ 4 + 1」的閘）。

### 2.4 四劇本的分布支持這個讀法

508 筆（四劇本 × 127）裡 149 筆 `+0x19 != 0xFF`：

| 狀態 | `+0x19` 有值 | `+0x19` ＝ `0xFF` |
|---|---:|---:|
| 在場 ＋ 在野 | **81** | **0** |
| 在場 ＋ 有主 | 67 | 233 |
| 不在場 | 1 | 126 |

⭐ **在場的在野武將 81 人全部有值，一個例外都沒有。** 有主的那 67 人是
被俘之後才會用到（`+0x1D` 開局全是 `0xFF`，沒有人一開始就是俘虜）。
只有 22 筆的 `+0x19` 等於自己現在的 `+0x1C`——所以它不是所屬勢力的第二份。

## 3. 旗標 `+0x00` 的 bit 6 ＝ 主公型

`sub_129C3`（被俘處理）在寫完舊主之後，**不分舊主在不在**：

```asm
loc_12A12:
test    byte ptr [bx], 40h
jz      +
and     byte ptr [bx], 0BFh     ; 清掉 bit 6
add     byte ptr [bx+1Eh], 3    ; ⭐ 說話類型 +3
```

`loc_12A12` 有兩條入邊：舊主還在時 `jnb` 直接跳過來，舊主已滅但沒有
bit 4（不事二主）也落到這裡。只有走自刎那一條會跳過，而自刎的下一步
是整筆歸零。條件因此只有一個：**被俘且沒自刎**
（[`../spec/127`](../spec/127-captured-sovereign-becomes-retainer.md) §1）。

說話類型 **0–2 是主公型、3–7 是臣下型**（[`25`](25-message-variants-and-personnel.md) §4.2），
所以 `+3` 正好把 0／1／2 搬到 3／4／5。分布也對得上：

| | 說話類型 0–2 | 說話類型 3–7 |
|---|---:|---:|
| bit 6 ＝ 1 | **43** | 0 |
| bit 6 ＝ 0 | 2 | 336 |

bit 6 的 43 人**全部有主**，沒有在野的——就是四個劇本的現任君主。
兩個「說話類型 0 而 bit 6 ＝ 0」的是被併吞後轉在野的群雄
（同 [`25`](25-message-variants-and-personnel.md) §4.2）。

## 4. 旗標 `+0x00` 的 bit 5 ＝ 心向的勢力沒了就退場

§2.1 的最後兩行。分布：bit 5 的 68 人**全部 `+0x19` 有值**，
反過來不成立（`+0x19` 有值的 148 人裡 80 人沒有 bit 5）。
所以 bit 5 是 `+0x19` 的修飾詞，不是獨立狀態。

## 5. `+0x14`／`+0x15`／`+0x1B`：全庫掃過，沒有讀取端

方法：`tools/ida_disp_users.py` 掃 `0x00`–`0x1F` 全部位移（5,190 筆），
再與 `tools/ida_tables.py` 的 `tables.json`（每支函式碰哪幾張表）交叉。

| 欄位 | 全庫有這個位移的函式 | 其中碰武將表的 | 逐處判讀 |
|---|---:|---:|---|
| `+0x14` | 31 | 1 | `sub_16F26` 的 `inc [bx+14h]`，而那裡的 `bx` 是**勢力**記錄（`bh` 由 `+0x1C` 換算成 `×64`）|
| `+0x15` | 2 | 0 | — |
| `+0x1B` | 17 | 0 | — |

`4254h`／`4255h`／`425Bh` 這種「基址 ＋ 欄位」的直接常數也是零
（`KI.EXE` 用到的武將表常數只有 `4240`／`4241`／`4242`／`4248`／`424E`／
`4251`／`4252`／`4253`／`4256`／`4257`／`425A`／`425C`／`425E`／`425F`）。

⚠ **這是有界的負證據，不是「證明沒有」。** 讀取端的基址可以由呼叫端傳進來，
而那支函式本身不必出現任何武將表常數——上面的交叉會漏掉這種。
`+0x19` 的九支就是靠逐支讀出來的，不是靠交叉判定的。

`+0x15` 另有一項獨立證據：四劇本 508 筆**全 0**，在場的 381 筆也全 0。
