## 1. `sub_1614A`：指令列 ＝ 一個框 ＋ 一串字

```asm
sub_101B4                        ; 繪圖前後的成對常式
or  ds:98A6h, 1                  ; 標記「指令列已畫」（[`42`](42-leaf-functions.md) §2）
al = 0Bh / dx = 0 / bx = 0 / cx = 21Bh
sub_1895D                        ; ← 框 (0, 32, 432, 32)
si = 6181h / dx = 8 / bx = 28h / ax = 0F01h
sub_106F5                        ; ← 畫變長字串，X=8、Y=40（[`33`](33-shared-draw-helpers.md) §1）
al = 0Ch / bx = 28h / dx = 18h / cx = 230h
sub_1E3D7                        ; ← 登記熱區 0x0C：(24, 40, 384, 16)
sub_101DB
```

**`dx` 是 X、`bx` 是 Y**，證據見 [`47`](47-main-screen-window-registry.md) §1
（三支常式各自的解碼運算元）。`sub_1895D` 的 Y 還要再加 2 個 16 px 粗格，
所以框落在橫幅底下的 `y = 32`。

八個指令名是**文字**，來源 `cs:6181h`，用一般的字串繪製常式畫；
外框由 `sub_1895D` 的樣式 `0x0B` 畫。**沒有任何一次圖庫存取。**

`cs:6181h`（檔案位移 `0x6381`）解出來是**一整串**：

```
　 進言　人事　財政　編成　軍團　據點　武將　勢力 　
```

**兩個字之間沒有空格，詞與詞之間才有一個全形空格。**
所以節距 ＝ 32（詞）＋ 16（全形空格）＝ **48**，起點 8 ＋ 24（開頭的
全形＋半形空格）＝ 第一個字在 32。驗算
`8 + 24 + 8×32 + 7×16 + 24（尾端空白）= 424`，**落在框寬 432 之內**——
起點若讀成 40，尾端會算到 456 而溢出框外，一條算式就分得出兩種讀法。

> 所以 `ICONGRF` 段 1 與指令列無關。段 1 的消費者
> （`sub_1C7F4`／`sub_1C863`／`sub_1CA3B`／`sub_1CAA8`，
> [`../formats/03`](../formats/03-grf-images.md) §5.3）**全部落在
> `0x1C000` 的戰術區段**——那是戰術畫面的底列，不是大地圖的指令列。

## 2. `sub_1895D`：一次呼叫寫三個地方

`sub_1895D(al ＝ 樣式, bx ＝ Y, dx ＝ X, cx ＝ 尺寸)`：

```asm
si = bx / di = dx / bp = cx
ah = 0 ; al == 0 → ah = 1            ; 樣式 0 是「擦除」（[`24`](24-unread-function-catalogue.md) §2.1）
sub_1D5D4                            ; ① 格子屬性表
si += 2
if al != 0: sub_10C14(bx=si,dx=di,cx=bp)   ; ② 框線層
bx = si<<1 / dx = di<<1 / cx = bp<<1
if al != 0: ah = al
sub_189DE                            ; ③ → sub_1E3D7，熱區
```

**三層都不碰圖庫。**

| 層 | 目標 | 形狀 |
|---|---|---|
| ① `sub_1D5D4` | 段 `cs:word_1D84E` | 每格 8 bytes，列距 `0x140`（＝ 40 × 8）→ **40 欄的格子表**。樣式 0 設 `0x10`／清 `0x80`，其餘清 `0x10`／設 `0x60` |
| ② `sub_10C14` | 段 `cs:word_10D4A` | 用 `sub_10C60`（上下邊）與 `sub_10C77`（左右邊）各畫兩次——**四條邊分開畫**，`ax = 0801h` 是樣式參數 |
| ③ `sub_189DE` | `sub_1E3D7` | 座標各再 `<<3`（格 → 像素），登記熱區 |

③ 的 `shl ×3` 說明**①②的座標單位是 8 pixel 的格**，
而 `sub_1895D` 進來時的 `bx`／`dx` 又比它們少一次 `<<1`，
所以呼叫端傳的是**16 pixel 為單位的粗格**。

`si = bx + 2` 只加在 Y 上，等於**每一個用這支畫的框都自動下移 32 px**，
剛好讓開 640×32 的橫幅（[`47`](47-main-screen-window-registry.md) §2）。

以指令列驗算：`bx = 0`（Y）、`dx = 0`（X）、`cx = 0x021B` →
高 byte `0x02`、低 byte `0x1B`（27）。②③ 用的是 `cx<<1` ＝ `0x0436`，
即 4 列 × 54 欄的 8 px 格 ＝ **432 × 32 pixel**，
位置 `(0, (0+2)×16)` ＝ **(0, 32)**，也就是橫幅正下方。

## 3. ⭐ 框線的圖塊就是 `ICONGRF` 段 3，貼法也對上了

②（`sub_10C14`）底下是 `sub_10C60`（上下邊）與 `sub_10C77`（左右邊），
兩支都呼叫 `sub_1F9B0(ax=0801h, si=圖塊位移)`——而 `sub_1F9B0` 設完
EGA 暫存器就 `sub_1FA1B` 搬 bytes 到 VRAM `0A0C8h`。**si 是段內位移，
`ds` ＝ `cs:word_10D4A`。**

四個位移與 [`../formats/03`](../formats/03-grf-images.md) §5.4 逐一對上：

| `si` | 段 3 位移 | §5.4 記的內容 | 用在哪 |
|---:|---|---|---|
| `0x00` | `0x06C0` | 上下邊的 motif（紅框綠心）| `sub_10C60`，上下各鋪一排 |
| `0x20` | `0x06E0` | 邊柱的**柱頭**（金色）| `sub_10C77` 的**第一塊與最後一塊** |
| `0x40` | `0x0700` | 邊柱的**柱身** | 迴圈裡 |
| `0x60` | `0x0720` | 同上（§5.4：柱身垂直同紋，所以兩塊相同）| 迴圈裡 |

`internal/ui/chrome` 的 `Window` 是同一個順序：柱頭在最上與最下、
柱身在中間迴圈、上下邊鋪滿中段。**外框這一項是照原版素材做的，不是自繪。**

> 所以「主畫面不像原版」的原因**不在外框**。版面常數已由
> [`47`](47-main-screen-window-registry.md) §4 從機器碼定死，
> 剩下的候選是自繪的勢力色標（`vector.DrawFilledRect` ＋ 硬寫 RGBA）、
> 底色與各視窗內部的排版——那些要靠同狀態對拍逐項指認。

### 3.1 一個可以直接驗的細節

`sub_10C60` 每次迴圈貼**兩塊**、`bx` 進 2；`cl` 來自 `dl`。
配合 `sub_1895D` 的座標單位（呼叫端 16 px 粗格），
**上下邊是「每個粗格兩塊 8 px 圖塊」**——與 remake 逐 8 px 鋪滿等價。
