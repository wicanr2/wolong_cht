# 32 — 戰略側的兩個詳情面板：據點與軍團

**狀態：兩支面板函式與軍團面板的外層 confirmed，欄位與字串表全部對出。
畫肖像的 `sub_107D2` 見 [`33`](33-shared-draw-helpers.md) §2、`sub_1812A` 見
[`51`](51-corps-info-window.md) §3；只剩收尾的 `sub_1817D` 未讀。**

- 日期：2026-08-14
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：IDA Pro 9.4，`tools/ida_strategy_ui.idc`（唯讀副本，跑完雜湊未變）
- 位址空間：IDA DOS/V linear address；`cs:XXXX` 的檔案偏移 ＝ `cs` ＋ `0x200`

戰略 UI 是覆蓋率最低的模組（[`21`](21-function-census.md) §4）。
這兩支是那一區最大的未讀函式：`sub_17E4A`（208 B）與 `sub_1807B`（175 B）。
兩支都是**詳情面板**——把一筆記錄攤成畫面上的一格一格。

## 1. `sub_1807B`：軍團詳情

`si` 是軍團記錄。五個欄位，順序是：

| 欄位 | 來源 | 位置 | 格式 |
|---|---|---|---|
| 主將名 | 軍團 `+0x02` → 武將記錄 `+0x02` | (0x240, 0xD0) | 三個全形字 |
| 君主名 | 軍團 `+0x01` → 勢力 `+0x01` → 武將 `+0x02` | (0x240, 0xE0) | 三個全形字 |
| 首都名 | 勢力 `+0x03` → 據點 `+0x02` | (0x240, 0xF0) | 三個全形字 |
| 總兵力 | 軍團 `+0x04` **× 10** | `di=5543h` | 4 位數 |
| 士氣值 | 軍團 `+0x06` | `di=5549h` | 3 位數 |

**這五個欄位與 [`../reference/04-first-survey.md`](../reference/04-first-survey.md) §2.4
從 `KI.EXE` 的 Big5 詞表抄下來的那一行順序完全一致**：

```
將軍 君主 首都 總兵力 士氣值
```

當時那是「字串表的排列順序」這種間接證據，現在有畫它的程式碼——
**兩個獨立來源給出同一個順序**。

三次「編號 → 記錄位址」的換算都是同一個形式：

```asm
ah = 編號 / al = 0 / ax >>= 3 / ax += 4242h    ; 武將：×32 ＋ 表基址 ＋ 2
ah = 編號 / al = 0 / ax >>= 3 / ax += 842h     ; 據點：×32 ＋ 表基址 ＋ 2
bh = 編號 / bl = 0 / bx >>= 2                  ; 勢力：×64
```

`+2` 是跳過記錄開頭直接指到名稱欄——**武將與據點的名稱都在 `+0x02`，
而且都是 6 bytes（三個 Big5 字）**，所以同一支 `sub_106FD` 三個欄位通用。

**總兵力顯示時 ×10**：軍團 `+0x04` 存的是「點」，一點 10 人
（[`30`](30-corps-formation-ui.md) §5）。這與據點城兵數 `+0x13` 顯示時 ×10
是同一個約定（[`../formats/08`](../formats/08-sinario-save.md)）。

### 1.1 外層 `sub_17F90`：自己的軍團才能下令

```asm
si += 2240h                            ; 軍團位移 → 軍團記錄
sub_1807B                              ; 畫詳情
sub_1812A
al = cs:byte_10CFF                     ; 玩家勢力編號
cmp al, [si+1] / jnz → 別人的
  sub_17FDB                            ; ← 下行軍指令（見 27 §7）
  sub_14325
  or byte ptr [si], 2                  ; ← 軍團 +0x00 置 bit 1
  jmp →
別人的:
  sub_18853(cx=4)                      ; 「以滑鼠的右鍵回復。」
  sub_121E7                            ; 等右鍵
```

**點自己的軍團可以接著下行軍令，點別人的只能看。**
別人的軍團會把狀態列換成「以滑鼠的右鍵回復。」，等右鍵才離開——
所以原版沒有「這不是你的軍團」這種提示，是用**能不能繼續操作**來表達的。

`or byte ptr [si], 2` 讓軍團 `+0x00` 的位元圖多了一筆：

| 何時 | 動作 |
|---|---|
| 建立（`sub_16F26`）| 寫 `0xC0` |
| AI 編成（`sub_16E8F`）| `or 4` |
| 玩家下完行軍令（`sub_17F90`）| `or 2` |

三處都是「設定」不是「清除」，**清除的地方還沒找到**（§4）。

## 2. `sub_17E4A`：據點詳情

`si` 是據點記錄。

```asm
sub_106FD(si+2, dx=80h, bx=120h)       ; 據點名
bh = [si+1]                            ; 所屬勢力
cmp bh, 18h / jz → 中立
  → 勢力 +0x01 ＝ 君主編號 → 武將名
中立:
  si = cs:7E19h                        ; ← 固定字串
sub_106FD(dx=0C0h, bx=130h)            ; 君主名／「中立」

al = [si+13h] × 10 → sub_1062F(bx=904h)    ; 城兵數，4 位
ax = [si+0Eh]      → sub_1062F(bx=906h)    ; 生產力，6 位
al = [si+10h] − 100→ sub_1062F(bx=904h)    ; 上昇值，4 位；負數 bh=0Ah
al = [si+11h]      → sub_1062F(bx=903h)    ; 防災值，3 位
al = ([si+16h] & 0Fh) × 6
if (si − 840h) >> 3 的高位 == 勢力 +0x03 → al = 1Eh    ; 是首都
sub_106FD(si = cs:7DF5h + al)          ; 規模字串
```

### 2.1 `+0x01 == 0x18` ＝ 中立

據點的所屬勢力欄拿 **`0x18`（24）當「無所屬」的哨兵**，
而勢力表只有 22 筆（0–21）。命中時不查勢力表，直接畫 `cs:7E19` ＝ **「中立　」**
（三個全形字，第三格是空白，湊滿名稱欄的寬度）。

**remake 目前是對的，但理由值得寫清楚**：`internal/state` 把 `+0x01` 原值直通到
`City.Owner`（所以 round-trip 不會動到它），統計時靠
`c.Owner >= 0 && c.Owner < numFactions` 這道範圍檢查把 24 擋在外面。
**它不知道 24 的意思，只是剛好落在範圍外。**
所以：新增任何以 `Owner` 分組、比對或索引的程式碼時，
範圍檢查要一起帶上——`noFaction`（`0xFF`）是武將那一層的在野哨兵，
**據點這一層是 24，兩者不通用**。

### 2.2 規模字串表 `cs:7DF5`：六筆，每筆 6 bytes

| 索引 | ×6 | 字串 | 對應 |
|---:|---:|---|---|
| 0 | 0 | 大都市 | `+0x16 & 0x0F` ＝ 0 |
| 1 | 6 | 中都市 | 1 |
| 2 | 12 | 小都市 | 2 |
| 3 | 18 | 關卡　 | 3 |
| 4 | 24 | 戰場　 | 4 |
| 5 | 30 | 首都　 | **不是類型，是覆蓋** |

前五筆與 [`../formats/08`](../formats/08-sinario-save.md) 由 `sub_16A3D`
定案的「據點類型 0–4」一一對上——**第二個獨立來源**。

**第六筆是覆蓋不是類型**：程式先照 `+0x16 & 0x0F` 算出索引，
再比對「這個據點是不是自己勢力的首都」（據點編號 vs 勢力 `+0x03`），
是的話直接改成 `0x1E`。所以**首都在資料裡仍然是大都市或中都市，
只是顯示成「首都」**——`+0x16` 沒有「首都」這個值。

### 2.3 上昇值為負會換色

```asm
al = [si+10h] / ax −= 64h / cwd
bx = 904h
cmp dh, 80h / jb → 保留
  bh = 0Ah                             ; ← 前景色換成 A
```

`+0x10` 存的是「上昇值 ＋ 100」，減 100 還原成有號值；`cwd` 之後看 `dh`
判斷正負。**負數把前景色從 4 換成 A**，與
[`28`](28-text-number-rendering.md) §2.1 的換色規則、以及
[`27`](27-list-row-fields.md) §5 的一覽表警示是同一個手法。

## 3. 一個順帶的印證

兩支面板都用 `sub_1062F` 印數字，而 `bx` 的高位元組固定是 `9`：
`0x904`（背景 9、4 位）、`0x906`、`0x903`。
[`28`](28-text-number-rendering.md) §2 讀出的介面是「`bl` ＝ 位數、
`bh` ＝ 背景︰前景」，這裡的 `bh = 0x09` 表示**背景 9、前景 0**，
與一覽表的 `0x90`⋯⋯**不一樣**。

> ⚠ 兩處的 `bh` 位元順序看起來相反（一覽表 `0x90`／面板 `0x09`）。
> `28` §2.1 是從 `sub_1069A` 的 `al = bh & 0Fh`（前景）與 `al = bh >> 4`（背景）
> 讀出來的，那一側是硬證據。所以面板這邊應該讀成**背景 0、前景 9**。
> 兩種面板的底色本來就不同（一覽表有底色、詳情欄畫在既有背景上），
> 這個差異合理，但**沒有實跑截圖之前不下定論**。
