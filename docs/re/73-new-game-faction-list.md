# 73 — 新遊戲怎麼選君主：先一張清單，再一張卡

**狀態：整條流程解出來了。⭐ 君主卡上沒有「換勢力」的熱區——
換勢力是退回上一層的**勢力清單**（`sub_17B3C`）。清單的視窗、五個欄位、
候選條件與一頁列數全部定案。**

- 日期：2026-08-24
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 工具：`workplace/ida/dosv/KI.EXE.asm` 逐段閱讀 ＋ 直接從 `KI.EXE` 取原始 bytes
- 位址空間：IDA DOS/V linear address（`cs:XXXX` ＝ linear `0x1XXXX`）

## 1. `sub_11AC3`：新遊戲的四層迴圈

```asm
sub_11AC3:
  call sub_12078
.top:
  si=98C8h / dx=0D0h / bx=80h / di=28h
  call sub_18DC8                  ; ＹＥＳ／ＮＯ
  and ax, ax / jnz → sub_18B40 …  ; 選「否」那一支
.slot:
  call sub_18B12  / jb → .top     ; 劇本／初始化
.list:
  call sub_17B3C  / jb → .slot    ; ★ 勢力清單
.card:
  call sub_18E5A  / jb → .list    ; ★ 君主卡
  and al, al / jz → 定案
  call sub_18FC9 / jmp .card      ; al≠0 ＝「自定」→ 命名，回來再問一次
```

⭐ **每一層的 CF=1 都退回上一層**，而**君主卡退回去的是清單**——
這就是「怎麼換勢力」的答案（[`53`](53-lord-select-window.md) §5 原本掛著這一條）。
卡片本身只有兩個熱區（確定／自定），其他位置的點擊一律被
`jb short loc_18E70` 丟回等待迴圈。

定案之後 `loc_11AF8` 做三件事：軍師欄不是 `0x7F` 就把該勢力的
`+0x18`（武將數）減一、把選中的武將 `+0x17` 職務清 0、
把勢力寫進 `cs:word_10CFD`／`byte_10CFF`（玩家勢力），
最後 `sub_12151(ax=14h, cx=0Ch)` 把鏡頭移到首都 −(20,12)。

## 2. `sub_17B3C`：勢力清單

```asm
mov dx, 88h / mov bx, 68h / mov cx, 0B18h
call sub_181C0                   ; ★ 視窗 (136, 104) 384×176
mov ds, cs:word_10D52
mov ax, 7B6Fh / mov bx, 7B90h    ; 兩個 callback
mov si, 7AC6h / mov di, 7B12h    ; 標題字串 ／ 欄位表
xor cl, cl
call sub_1820E
```

### 2.1 ⚠ 這是**唯一**不在 (24, 88) 的一覽視窗

`sub_181C0` 全庫八個呼叫端，**七個**是 `dx=18h, bx=58h`（24, 88），
只有這一個是 `dx=88h, bx=68h` ＝ **(136, 104)**。
尺寸 `cx=0B18h` 與其餘七個相同（24 格 × 11 格 ＝ 384 × 176）。

`sub_17B3C` 不是戰略層的指令，是新遊戲殼層的一頁——**它與那七個共用引擎，
不共用位置**。要抄一覽表的幾何到別的畫面時，抄的是尺寸與列距，不是左上角。

### 2.2 callback A（`cs:7B6F`）＝ 建清單

```asm
xor si, si / mov di, si / xor ah, ah
.loop:
  cmp byte [si], 80h / jb .skip   ; ★ 勢力記錄 +0x00 ≥ 0x80 ⇒ 存在
  mov [bp+di], si                 ;   收進結果陣列（存的是記錄位移）
  inc ah / inc di / inc di
.skip:
  add si, 40h                     ; 勢力記錄 64 B
  cmp si, 580h / jnz .loop        ; 0x580 ÷ 0x40 ＝ 22 個勢力
retn                              ; ah ＝ 筆數
```

⭐ **候選條件只有一條：勢力存在。** 沒有「不能選自己」那一類的過濾——
新遊戲時還沒有玩家勢力。22 個全掃，一個不漏。

### 2.3 callback B（`cs:7B90`）＝ 畫一頁

```asm
call sub_18607                   ; 清清單區
dx = cs:word_181AE + 18h         ; ★ 視窗 X ＋ 24
bx = cs:word_181B0 + 10h         ; ★ 視窗 Y ＋ 16（標題那一列在上面）
si = ax × 2                      ; 捲動位置 → 陣列位移
ax = 0Ah                         ; ★ 一頁 10 列
.loop:
  call sub_17BC0                 ; 畫一列
  si += 2 / bx += 10h            ; 列高 16
  dec ax / jnz .loop
```

## 3. `sub_17BC0`：一列長什麼樣

空槽（陣列值 `0FFFFh`）直接畫 `cs:7AEBh` 的樣板，屬性 `0x9000`。
否則 `di` ＝ 勢力記錄，畫五欄：

| 欄 | 相對列首的 X | 來源 | 畫法 |
|---|---:|---|---|
| 君主名 | 0 | `+0x01` → 武將記錄 `+2` | `loc_10701`，屬性 `0x9001` |
| 軍師名 | 64 | `+0x02` → 武將記錄 `+2` | 同上 |
| 武將數 | 144 | `+0x18` | `sub_1062F`，`bx=9003h` |
| 據點數 | 192 | `+0x23` | 同上 |
| 首都名 | 256 | `+0x03` → 據點記錄 `+2` | `loc_10701`，屬性 `0x9001` |

⚠ **兩個數字欄的 X 是用 VRAM 位移算的**，與三個名字欄不同路：
`di = Y × 80 + X ÷ 8 + 12h`，第二個再 `+6`。換回像素就是列首 `+144` 與 `+192`，
所以**畫面上的順序是 君主／軍師／武將數／據點數／首都**，
不是機器碼裡的書寫順序。

## 4. 標題、分隔線與欄位表（原始 bytes）

三塊資料都在 `sub_17B3C` 附近，IDA 把它們反組譯成垃圾指令
（它們只被立即值參考，沒有交叉參考可以定型）。直接從 `KI.EXE` 取
（linear − `0x10000` ＋ 512 ＝ 檔案位移）：

| 位址 | 內容 |
|---|---|
| `cs:7AC6` | `勢力名　軍師名　　武將　據點　　首都`（NUL 結尾，37 B）|
| `cs:7AEB` | `－－－　－－－　　 --　　-- 　　－－－`（38 B）|
| `cs:7B12` | 欄位表 |

⭐ **`cs:7AEB` 一物二用**：它既是欄寬定義的分隔線（[`26`](26-list-window-engine.md) §4.1
的規則：`－` 16 px、`-` 8 px，一段連續的就是一欄），
也是 §3 空槽那一列**直接照印**的樣板。

欄位表是「筆數 ＋ 每筆四個 word」：

```
05 00                                   ; 5 欄
18 00  06 02  01 00  76 00              ; X=24   屬性 0206  欄位 +01  型別 76
58 00  06 02  02 00  76 00              ; X=88   屬性 0206  欄位 +02  型別 76
A8 00  04 02  18 00  73 00              ; X=168  屬性 0204  欄位 +18  型別 73
D8 00  04 02  23 00  73 00              ; X=216  屬性 0204  欄位 +23  型別 73
18 01  04 02  03 00  76 00              ; X=280  屬性 0204  欄位 +03  型別 76
```

**兩條獨立的證據對上了**：欄位表的 X（24／88／168／216／280）與 §3 從
`sub_17BC0` 逐行算出來的（0／64／144／192／256，再加列首的 +24）完全相同。
型別 `0x76` 配名字欄、`0x73` 配數字欄。
