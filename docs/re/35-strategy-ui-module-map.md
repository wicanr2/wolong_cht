# 35 — 戰略 UI 模組全圖：108 支函式的叢集歸屬

**狀態：叢集歸屬 confirmed（呼叫圖是精確的，不是啟發式）。
各叢集的角色標籤是強證據——來自「它呼叫哪些已定案語意的共用常式」，
不是逐行讀出來的。標「未讀」的欄位表示還沒逐行驗過。**

- 日期：2026-08-14
- 範圍：只驗松崗 DOS/V，位址 `17800`–`19800`
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：**IDAPython** `tools/ida_module.py`（模組級掃描）
- 位址空間：IDA DOS/V linear address，segment base `0x10000`

戰略 UI 是 [`21`](21-function-census.md) 量出來單一模組最大的缺口
（54 支未讀、2,988 bytes）。逐支讀太慢，而這一款的 UI 函式**幾乎全部由
「呼叫哪些共用常式」決定角色**——共用常式的語意已經定案
（[`33`](33-shared-draw-helpers.md)、[`24`](24-unread-function-catalogue.md) §2）。

所以這一份不逐行讀，改成**把整個模組的呼叫圖攤開**，
讓每支函式至少有明確的歸屬與證據，再挑真正需要逐行讀的。

## 1. 方法與它的界線

`tools/ida_module.py` 對指定區間內每支函式抽四種證據：

| 證據 | 精確度 |
|---|---|
| 呼叫者、被呼叫者 | **精確**（IDA 的 cref，不含間接分派）|
| 碰到的表基址 | 精確，但**是函式層級**（[`34`](34-corps-status-bits.md) §2.4）|
| `INT` 與 I/O 埠 | 精確 |
| 傳給共用常式的立即值 | **啟發式**——同一暫存器可能被覆寫、分支可能跳過賦值 |

> **叢集歸屬（誰呼叫誰）是硬的，角色標籤是軟的。**
> 下表的「叢集」欄可以直接引用；「做什麼」欄是推論，要當結論用得回去讀那一段。

## 3. 這一輪學到的形狀

1. **「無直接呼叫者」在這個模組出現六次**，全部是 callback 或間接分派目標，
   沒有一支是死碼。與 [`21`](21-function-census.md) §6 的結論一致。
2. **極小的函式（2–15 B）幾乎都是薄分派或擦除框**。
   它們讓 T4 的「支數」看起來很多，但只佔 2,988 bytes 裡的一小部分。
3. **畫面函式有固定形狀**：一支鋪框與熱區、一支畫內容、一支擦除、
   一支等輸入。認出這個形狀，一個畫面四支函式可以一起判定。
