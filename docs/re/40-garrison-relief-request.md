# 40 — 據點求援與援軍派遣

**狀態：整條鏈 confirmed（每一支都逐行讀過）。
`sub_140C9` 的距離算式裡有一處**位移不對稱**，照抄不修正（§4）。**

- 日期：2026-08-14
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：**IDAPython** `tools/ida_dump.py`
- 位址空間：IDA DOS/V linear address；`si` 是**據點位移**（編號 × 32），
  所以 `[si+840h]` ＝ 據點 `+0x00`、`[si+857h]` ＝ 據點 `+0x17`，依此類推

`sub_13EFD` → `sub_13F74` 這一叢在 [`38`](38-strategy-core-module-map.md) §2 只標了
「事件產生器」。逐行讀完之後它是一個完整機制：**據點感覺到威脅 → 求援 → 把
附近的軍團調過去**。

## 1. `sub_13F74`：每個據點跑一次

```asm
sub sp, 10h / bp = sp
es = ss / di = bp / cx = 8 / ax = 0FFFFh / rep stosw   ; 16 B 全填 FFFF
sub_13FA9                       ; ← 填那個緩衝
[si+854h] = ch                  ; 據點 +0x14
sub_14028                       ; 有敵人貼著 → 立刻求援
jnb → 結束
sub_14057                       ; 否則走機率路徑
```

**堆疊上的 16 bytes 是「四個 word 對」**，初值 `0xFFFF` ＝ 空。
`sub_13FA9`（127 B）把附近的威脅填進去，後面兩支都以 `[bp+0] < 0xFEh` 判斷「有東西」。

## 2. `sub_14028`：貼身的威脅，立刻求援

```asm
and byte [si+840h], 3Fh         ; 清據點 +0x00 的 bit 6、7
al = 80h
cmp byte [bp+0], 0FEh
  jb → al |= 40h                ; 威脅有具體目標（[`44`](44-threat-and-reinforcement-ai.md) §2.1）→ 同時設 bit 6
  jz → 直接設                    ; 剛好 0xFE
  ja → [si+857h] = 0 / 結束      ; 沒有威脅 → 清冷卻並結束
or [si+840h], al                ; 寫回 bit 7（＋bit 6）
cmp byte [si+858h], 1 / jnb → CF=1 結束
sub_140C9(al=1) / sub_140B3
```

**據點 `+0x00` 的 bit 7 ＝ 受威脅、bit 6 ＝ 威脅有具體目標**
（＝ 對方是本勢力的侵攻目標，[`44`](44-threat-and-reinforcement-ai.md) §2.1）。
低 4 位是「哪幾個鄰居是敵方」（[`44`](44-threat-and-reinforcement-ai.md) §5），
所以這個欄位是「地形 ＋ 狀態」共用的位元集合。

`+0x18`（`[si+858h]`）≥ 1 就不求援——它是**停在該據點那一格的軍團數**
（[`44`](44-threat-and-reinforcement-ai.md) §1）。

## 3. `sub_14057`：沒有貼身威脅時的機率路徑

```asm
cmp byte [bp+0], 0FEh / jnb → 結束      ; 連遠處都沒有威脅
sub_1ECE0 / al &= 3                     ; 亂數 0–3
di = bp
loop: cmp byte ss:[di], 0FEh / jnb → 重抽
      dec al / jz → 選中
      di += 4 / jmp loop                ; ← 四個 word 對，每對 4 B
cmp byte [si+858h], 1
  jbe → ① 求援
  ja  → ② 派兵
```

**從最多四個威脅裡隨機挑一個**（跳過空槽）。接著分兩條：

### ① `+0x18 ≤ 1`：求援

```asm
al = [si+854h] + 2 − [si+858h]          ; 據點 +0x14 ＋ 2 − +0x18
jbe → 結束                               ; 不夠就不求
cl = cs:byte_10CFF
cmp cl, [si+841h] / jz → 結束            ; ← 玩家自己的據點不走這條
sub_140C9 / sub_140B3
```

### ② `+0x18 > 1`：直接派兵

```asm
and al, al / jnz → 保持 ; al = 1        ; 至少 1
cl = ss:[di]                            ; 選中的威脅（目標據點編號）
ch = 0 / dl = al / dh = [si+858h]
sub_14155                               ; ← 派援軍
[si+857h] = 0                           ; 清冷卻
```

## 4. `sub_140C9`：求援的兩種表現

```asm
cmp byte [si+857h], 0 / jnz → retn      ; 冷卻中就不重複求援
cl = cs:byte_10CFF
cmp cl, [si+841h] / jnz → 非玩家
  ; ── 玩家的據點：出聲 ＋ 跳訊息 ──
  di = si + 840h / push di / di = sp
  sub_10CDE                             ; PC 喇叭（[`37`](37-graphics-and-runtime-module-map.md) §1）
  sub_18810(cx=26h)                     ; #38「{2}前來請求援軍。」
  sub_1ECE0 / al &= 0Fh / al += 18h     ; 冷卻 ＝ 亂數(0–15) ＋ 24
  jmp 寫入
非玩家:
  ; ── AI 的據點：算它離首都多遠，距離就是冷卻 ──
  bx = [si+841h] × 64                   ; 所屬勢力記錄
  sub_14575                             ; 取該勢力的某個目標；CF=1 → 不做
  bx = [si+3] × 32                      ; 勢力 +0x03 ＝ 首都 → 首都的據點記錄
  ax = |[di+848h] − [bx+848h]|          ; 據點 X − 首都 X
  dx = |[di+84Ah] − [bx+848h]|          ; 據點 Y − 首都 X   ← §4.1
  ax = (ax + dx) >> 3
  cmp ax, 1Eh / jbe → 保持 ; ax = 1Eh   ; 上限 30
寫入:
[di+857h] = al                          ; 據點 +0x17 ＝ 冷卻
```

**`+0x17` 是求援冷卻計時器**，[`../formats/08`](../formats/08-sinario-save.md)
原本記「192 筆全 `0`，未解」——開局全 0 是因為**還沒有人求過援**。

玩家的據點求援會**發出 PC 喇叭聲**，這是模組裡少數幾個直接用喇叭的地方之一。

### 4.1 一處位移不對稱

第二行減的是首都的 `+0x08`（X），不是 `+0x0A`（Y）：

```asm
mov ax, [di+848h] / sub ax, [bx+848h]   ; 據點 X − 首都 X   ← 對稱
mov dx, [di+84Ah] / sub dx, [bx+848h]   ; 據點 Y − 首都 X   ← 不對稱
```

兩行的來源都對（`+0x08` X、`+0x0A` Y，[`../formats/08`](../formats/08-sinario-save.md)
已 confirmed），差別只在減數。**曼哈頓距離的 Y 分量因此是 `|Y − 首都X|`。**

**照抄，不要修正。** remake 的職責是重現原版行為，不是修它
（`CLAUDE.md` §1「不做玩法設計改動」）。影響是可量的：
冷卻值會偏離真正的距離，而冷卻只決定**多久之後可以再求援一次**，
上限 30、下限由算式決定——所以這個不對稱不會讓遊戲壞掉，只會讓
「離首都越遠、越久才能再求援」這個意圖在某些座標下失真。

**兩版對照已經裁決：這不是松崗移植時打錯的。** 用同一組指令 bytes
（`8B 85 ?? ?? 2B 87 ?? ?? 73 02 F7 D8 8B 95 ?? ?? 2B 97 ?? ??`）掃兩版執行檔，
各命中一處，位移完全相同：

| 版本 | 檔案位移 | 算式 |
|---|---|---|
| 松崗 DOS/V | `0x4327` | `ax = [di+848] − [bx+848]`、`dx = [di+84A] − [bx+848]` |
| PC-98 日文原版 | `0x4AFB` | **完全相同** |

所以它出自 1994 年的原始程式碼。**是不是作者的筆誤無法從程式碼判斷**，
但「remake 要照抄」這件事不受影響——它是原版行為的一部分。

> 推論等級：**指令與兩版一致是 confirmed**；「作者本來想寫 `84Ah`」仍是假說，
> 而且是**不可驗證的假說**——沒有任何一手資料能告訴我們作者的意圖。
> 文件到此為止，不要再往下推。

## 5. `sub_14155`：把附近的軍團調過去

```asm
dh -= dl
di = 2240h                              ; 軍團表
bx = si >> 2                            ; 據點位移 ÷ 4 ＝ 編號 × 8
loop:
  cmp bx, [di+0Eh] / jnz → 下一支         ; 軍團「目前據點編號×8」相符？
  cmp byte [di], 80h / jb → 下一支        ; 軍團存在？
  and dh, dh / jz → 派
    sub_1ECE0 / cmp al, 40h / jnb → 派    ; 亂數 ≥ 0x40（75%）才派
    dec dh / jmp 下一支                    ; 否則跳過這一支
  派:
  test byte [di], 4 / jz → 下一支         ; 軍團 +0x00 位元 2（[`34`](34-corps-status-bits.md)）
  cmp byte [di+23h], 8 / jnb → 下一支     ; 軍團 +0x23 < 8
  [di+20h] = cl                           ; ← 目標據點
  [di+23h] = ch
  dec dl / jz → 結束                       ; 派滿 dl 支就停
下一支: di += 40h
```

三件事定案：

1. **只調「人已經在這個據點」的軍團**（`+0x0E` 相符）——援軍不是憑空生的，
   是把守軍調去別處。
2. **`dl` 是要派幾支、`dh` 是可以跳過幾支**，每支有 25% 機率被跳過
   （`亂數 < 0x40` 且 `dh > 0`）。
3. **軍團 `+0x23` 有上限 8**，[`30`](30-corps-formation-ui.md) §9 原本標「未解」——
   它至少是一個有上限的計數，而且求援會寫它。

> ⚠ **這裡只寫 `+0x20`，沒寫 `+0x14`。** 而 `sub_142AB`（玩家下行軍令）
> 是兩個都寫的（[`27`](27-list-row-fields.md) §7）。
> 兩支對同一組欄位的處理不同，**表示 `+0x20` 與 `+0x14` 不是單純的同一個值的兩種縮放**。
> 這一點與 [`../formats/08`](../formats/08-sinario-save.md) 的「`+0x20` 恆等於
> `+0x14 ÷ 8`」有張力，**要在同一份存檔上實測才能裁決**。
