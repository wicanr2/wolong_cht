## 1. 最大的四支未讀函式就是逐列繪製

[`26`](26-list-window-engine.md) §8.2 的畫列 callback 只是十次迴圈，
真正的工作在它呼叫的那一支。四個家族各一支：

**軍團那一支只有位址沒有符號名**：它只被間接參考（畫列 callback 本身也只被
間接呼叫），IDA 的自動分析不會在那裡建函式。要讀它得先 `add_func`，
而那只在資料庫副本上做（[`26`](26-list-window-engine.md) 的工具註記）。

| 家族 | 逐列常式 | bytes | 在 [`21`](21-function-census.md) §5 的排名 |
|---|---|---:|---|
| 軍團 | `0001727D` | 242 | — |
| 武將 | `sub_1770C` | 226 | **第 2 大** |
| 勢力 | `sub_1799C` | 222 | **第 3 大** |
| 據點 | `sub_1748F` | 193 | 第 9 大 |
| 開局選勢力 | `sub_17BC0` | 174 | 第 13 大 |

T4 清單裡最大的幾支原來是同一件事的五個版本。這印證了
[`24`](24-unread-function-catalogue.md) §4 的下手順序：
**不要用大小排優先度**——大不代表獨立，這五支解一支就懂了其餘四支。

四支的骨架相同：

```asm
cmp word [bp+si], 0FFFFh      ; 空槽
jnz →
  si = <該家族的「－－－」字串>
  ax = 9000h / sub_1F6DC      ; 畫空列
  jmp end
si = [bp+si]                  ; 記錄位址（陣列存的是位址，見 26 §8.1）
… 逐欄取值、算座標、呼叫繪製 …
```

`ax` 的高位元組是顏色屬性（正常 `0x90`），低位元組是模式。
數字欄走 `sub_1062F(ax=值, bx=顏色:位數, di=位置)`，
文字欄走 `loc_10701(ds:si=字串, ax=屬性)`。

## 3. 兵力的顯示單位是 ×10

軍團總兵數與據點城兵在畫面上都先乘 10：

```asm
; 0001727D，總兵數
mov ax, [si+4] / mov dx, 0Ah / mul dx / call sub_1062F
; sub_1748F，城兵
mov al, 0Ah / mul byte ptr [si+13h] / call sub_1062F
```

**記錄裡存的是人數 ÷ 10。** 這與說明書推導出來的
「一點兵力 ＝ 10 人，滿編 100 ＝ 1,000 人」一致
（remake 的 `internal/state/corps.go` 早就照這個單位實作），
本節是機器碼側的獨立確認。

戰鬥端**不做這個換算**：`sub_14F8A` 合成守城部隊時
`al = [di+13h]` 直接取存值再除以 6 分進六槽。
所以 ×10 純粹是顯示，內部一律用存值——remake 目前的做法正確。

## 4. 外交關係的六個等級

勢力一覽的「外交」欄不是直接印數字，而是查一張 7 byte 一筆的表
（段內 `0x7844`，每筆 3 個全形字 ＋ 1 byte 顏色）：

| 偏移 | 文字 | 顏色 |
|---:|---|---|
| 0 | `交戰　` | `0x0A` |
| 7 | `最惡　` | `0x03` |
| 14 | `險惡　` | `0x00` |
| 21 | `普通　` | `0x00` |
| 28 | `良好　` | `0x00` |
| 35 | `親密　` | `0x05` |
| 42 | `－－　` | `0x00` |

繪製時 `ah = [si+6] | 0x90`，所以顏色 byte 是屬性的低半部——
**交戰那一筆的 `0x0A` 會讓整欄變色**，是畫面上的警示。

### 4.1 換算：`sub_17A7A`

`sub_17906`（勢力一覽）是八個一覽表裡**唯一**在開視窗前先呼叫別的常式的。
`sub_17A7A` 掃 22 個勢力，把玩家對它們的交友度換成上表的偏移，
寫進各自的 `+0x3F`：

```asm
si = 玩家在交友度矩陣裡的列
di = 3Fh / cx = 16h            ; 22 個勢力，記錄 64 B
loop:
  dl = 0                        ; 預設「交戰」
  al = [si]
  cmp al, 80h / jb → 寫 0        ; 最高位元 0 ＝ 交戰中
  and al, 7Fh
  dl = 2Ah                      ; 預設「－－」
  cmp al, 64h / ja → 寫 42       ; > 100
  jb → skip / dec al            ; == 100 → 99
  ah = 0 / dh = 14h / div dh    ; ÷ 20
  inc al / ah = 7 / mul ah      ; (商 + 1) × 7
  dl = al
  [di] = dl
  si++ / di += 40h
```

得到的對照：

| 交友度 | 顯示 |
|---|---|
| 最高位元未設 | **交戰** |
| 0–19 | 最惡 |
| 20–39 | 險惡 |
| 40–59 | 普通 |
| 60–79 | 良好 |
| 80–100 | 親密 |
| > 100 | `－－`（自己那一格）|

「最高位元 1 ＝ 和平、0 ＝ 交戰中」與
[`08-hourly-update.md`](08-hourly-update.md) §3 已記載的一致。
**新的是 20 一級的五段切分**——它給了原本只有數值的交友度一組語意名稱，
說服理由「交友關係惡い／良い」的門檻可以對照這組來讀
（[`../mechanics/70-ai.md`](../mechanics/70-ai.md) §1.3）。

### 4.2 訂正：`+0x3F` 是顯示快取，不是「軍師編號的備份」

[`../formats/08-sinario-save.md`](../formats/08-sinario-save.md) §1.5 原本記
「`+0x3F` 與 `+0x02` 相同｜未解（軍師編號的備份？）」。

劇本檔裡兩者確實相同（四個劇本、兩版都是），但那是**沒有意義的初值**：
`sub_17A7A` 每次開勢力一覽都整欄覆寫。**這一格在執行期是外交關係的顯示偏移。**

教訓：**欄位在資料檔裡的值不代表它的用途。** 兩個欄位長期相同很容易讀成
「備份」，但決定語意的是寫入端——這一格的寫入端只有 `sub_17A7A`。

## 5. 三條換色規則

畫面上會變色的欄位，各自有明確的門檻：

| 欄位 | 條件 | 顏色 |
|---|---|---|
| 軍團總兵數 | `< 0x12C`（＝ 3,000 人，半編）| `bh = 0x9A` |
| 軍團士氣值 | `< 100` | `bh = 0x9A` |
| 據點上昇率 | 存值 `== 100`（＝ 實際成長 0）| `bh = 0x9A` |
| 勢力外交 | 交戰中 | 表內 `0x0A` |

三者都是「值得注意」的狀態，不是錯誤。remake 的一覽表可以直接照這三條做。
**換色的機制是改前景色**（`bh` 的低 4 位由 0 變成 A），
不是換整個屬性，見 [`28`](28-text-number-rendering.md) §2.1。

## 7. 軍團 `+0x00` bit 2 ＝ 委任中（confirmed）

一覽表最右端會印「委任」或兩個全形空白，由 `+0x00` 的 bit 2 決定
（`test byte ptr [di], 4`）。這一位元的寫入端在行軍指示裡：

```asm
; sub_17FDB，玩家選完目的地與作戰方式之後
cmp al, 1
jz  → or  byte ptr [si], 4      ; 委任
ja  → mov byte ptr [si+23h], 0Bh ; 解體
      and byte ptr [si], 0FBh    ; 戰鬥指揮：清掉 bit 2
```

三處獨立對上：一覽表印的字是「委任」、寫入端在選「委任」那一支、
而 [`../mechanics/10-strategy.md`](../mechanics/10-strategy.md) §4 由說明書記下的
兩個選項正是「戰鬥指揮／委任」。

### 7.1 行軍指示的完整流程

```asm
sub_18853(cx=3)        ; #3「請指示行軍目標之據點。」
sub_1703C              ; 選目的地據點；CF=1 取消
sub_18853(cx=15h)      ; #21「向{2}移動下。請下達戰鬥指示。」
al = 2                 ; 兩個選項
bl = 勢力的首都（[si+1] → 勢力記錄 +0x03）
cmp bl, <目的地> / jnz →
  al = 3               ; ← 目的地就是首都時才有第三個選項
sub_1804E              ; 彈出選單，回傳 al
al == 0 → 清 bit 2     ; 戰鬥指揮
al == 1 → 設 bit 2     ; 委任
al >= 2 → [si+23h] = 0Bh  ; 解體
[si+0Bh] = 1           ; 移動計時器 ← 1，下一 tick 就走
[si+20h] = 目的地
```

**第三個選項只在目的地等於勢力首都時出現**，與
[`../mechanics/10-strategy.md`](../mechanics/10-strategy.md) §4 第 6 點
「目的地是首都時多一個『解體』」相符。

### 7.2 `+0x20` ＝ 目標據點（confirmed）

`sub_142AB` 一次寫兩個欄位，直接示範它們的關係（⚠ 它是**行進中掉頭**那一支，不是玩家下令的寫入端，見 [`86`](86-march-turnback-at-peace.md)）：

```asm
mov [si+14h], bx        ; 目標據點 × 8
shr bx,1 / shr bx,1 / shr bx,1
mov [si+20h], bl        ; ← 同一個值的無縮放形式
or  byte ptr [si], 2
```

**`+0x20` ＝ `+0x14` ÷ 8。** 原版把同一個概念存成兩份：
`+0x14` 給移動用（×8 是為了配合座標換算），`+0x20` 給顯示與判斷用。

三個寫入端因此一致：

| 寫入處 | 寫什麼 | 為什麼一致 |
|---|---|---|
| 編成（`sub_16F26`）| 勢力首都 | **編成只能在首都**，所以「目標 ＝ 所在地 ＝ 首都」|
| 行軍指示（`00018043`）| 玩家選的目的地 | 目標就是目的地 |
| 遷都（`sub_14502`）| 目標是舊首都的改成新首都 | 首都搬了，回家的軍團跟著改 |

**兩份不能合併成一個欄位**：遷都會讓它們暫時不一致。`sub_14502` 先把
`+0x20` 從舊首都改成新首都，接著只在 `+0x14 == 新首都×8` 時才把 `+0x14`
改成舊首都×8——兩個條件不會同時成立，所以合併之後那一段會自我抵銷。
