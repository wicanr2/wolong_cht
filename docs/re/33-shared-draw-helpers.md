# 33 — 共用繪圖層：字串包裝、肖像快取、小地圖上色

**狀態：六支共用常式 confirmed。肖像快取的替換策略、小地圖的座標換算與
據點標記的畫法都定案。實際載入 bytes 的 `sub_1E38C` 是共用讀檔入口，
見 [`50`](50-city-info-window.md) §3.1。**

- 日期：2026-08-14
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：IDA Pro 9.4，`tools/ida_draw_helpers.idc`（唯讀副本，跑完雜湊未變）
- 位址空間：IDA DOS/V linear address，segment base `0x10000`

挑這五支的依據不是直覺，是**呼叫點數**——認出一支共用常式，
所有呼叫它的未讀函式同時多一條證據（[`24`](24-unread-function-catalogue.md) §2.1）。

## 1. 兩支字串包裝各只有一行

```asm
sub_106F5:  call sub_1F6DC / retn      ; 9 個呼叫點
sub_106FD:  call loc_10701 / retn      ; 24 個呼叫點
```

被包起來的兩支在 [`28`](28-text-number-rendering.md) 已經解過：

| 包裝 | 實體 | 行為 |
|---|---|---|
| `sub_106F5` | `sub_1F6DC` | **NUL 結尾的變長字串**，全形／半形自動判斷，屬性 bit 2 ＝ 陰影 |
| `sub_106FD` | `loc_10701` | **固定三個全形字**，不看結束符，用在所有名稱欄 |

介面一致：`si` ＝ 字串、`dx`／`bx` ＝ 座標、`ax` ＝ 屬性。

> 為什麼要包一層？`loc_10701` 不是乾淨的函式（它有自我修改碼，
> IDA 在那一區建不出函式邊界，見 [`28`](28-text-number-rendering.md) §3）。
> **`sub_106FD` 存在的意義就是給那段程式碼一個可以被 `call` 的入口。**

`sub_188B0`（28 B，3 個呼叫點）再包一層，專門畫**勢力名**：

```asm
ah = [si+1] / al = 0 / ax >>= 3 / ax += 4242h   ; 勢力 +0x01 ＝ 君主編號 → 武將名
al = 1
call sub_106FD
```

**勢力沒有自己的名字欄位——畫面上的「勢力名」就是君主的姓名。**
這解釋了為什麼 [`31`](31-faction-picker-screen.md) 的勢力一覽每列都是三個全形字：
它畫的是武將記錄 `+0x02` 的姓名欄。

## 2. `sub_107D2`：武將肖像的四格快取

115 B，7 個呼叫點（`sub_1075B`、`sub_15EB7`、`sub_16DFD`、`sub_1807B`、
`sub_18EA0` ×2、`sub_1915B`）。`al` 是武將編號。

```asm
; ── 查快取：cs:846h 起四個 byte 是目前住在快取裡的武將編號 ──
bx = 0
loop: cmp al, [bx+846h] / jz → 命中
      inc bx / cmp bl, 4 / jb loop

; ── 未命中：載入 ──
bl = cs:byte_10845                    ; 下一個要被換掉的槽
[bx+846h] = al                        ; 記下新住戶
bh = (bl + 1) & 3 / cs:byte_10845 = bh   ; 指標前進，模 4
si = 槽 × 8
bx = cs:word_10D40                    ; 圖庫所在的段
ax:cx = 武將編號 × 2048               ; ← 檔案位移（32 位）
di = 800h                             ; ← 讀 2,048 bytes
call sub_1E38C

; ── 命中或載入完：畫 ──
si = 槽 × 8
ds = cs:word_10D40
ax = 4004h
call sub_1FA37                        ; 圖塊 blit
```

三件事定案：

1. **每張肖像 2,048 bytes**，而 `KAOGRF` 是 64×64 的 4bpp planar
   （[`../formats/03-grf-images.md`](../formats/03-grf-images.md)）——
   `64 × 64 ÷ 2 = 2,048` ✅ 對上。位移就是 `編號 × 2048`，沒有索引表。
2. **快取只有四格，替換策略是 round-robin 不是 LRU。**
   `byte_10845` 是一個模 4 的環形指標，命中不會把它往前推——
   所以「剛用過」不會延長壽命。
3. **快取的鍵是武將編號，存在 `cs:846h` 起的四個 byte，初值 `FF FF FF FF`。**
   `0xFF` 不是合法武將編號（0–126），所以開機後四格都必然未命中，
   不存在假命中。round-robin 指標 `cs:845h` 初值 `00`。
   （`cs` 位址 ＋ `0x200` ＝ `KI.EXE` 檔案偏移，直接讀出來的。）

> **為什麼要快取？** 每張 2 KB，DOS 下從檔案讀一次不便宜；
> 而軍團面板、人事畫面、編成畫面都會反覆畫同一批武將。
> remake 一次把 150 張全載入記憶體（`internal/assets/gfx`），
> **這是 remake 差異，但不影響規則**——差別只在載入時機。

## 3. `sub_15CE0`：小地圖上色

57 B，2 個呼叫點（`sub_14CF3`、`sub_15CC6`）。`si` 是據點記錄。

```asm
bl = [si+1]                           ; 所屬勢力
ah = 0Fh  / cmp bl, 18h            / jz → 畫    ; 中立
ah = 0ACh / cmp bl, cs:byte_10CFF  / jz → 畫    ; 玩家自己
ah = 0F3h / cmp bl, cs:byte_198A7  / jz → 畫    ; 目前選中的勢力
ah = 83h                                        ; 其他勢力
dx = [si+8]  >> 1 + 1B6h              ; X ÷ 2 ＋ 438
bx = [si+0Ah] >> 1 + 26h              ; Y ÷ 2 ＋ 38
call sub_15D19
```

### 3.1 四種顏色，順序就是優先序

| 條件 | 屬性 | 說明 |
|---|---|---|
| `+0x01 == 0x18` | `0x0F` | **中立**（[`32`](32-strategy-detail-panels.md) §2.1）|
| `== cs:byte_10CFF` | `0xAC` | **玩家自己** |
| `== cs:byte_198A7` | `0xF3` | **勢力一覽裡選中的那一個** |
| 其他 | `0x83` | 其他勢力 |

**比較是依序短路的**，所以「玩家自己」永遠贏過「選中」——
玩家在勢力一覽裡不能選自己（[`31`](31-faction-picker-screen.md) §2.2），
兩條規則互相配合。

### 3.2 小地圖是大地圖的一半

`X ÷ 2`、`Y ÷ 2` 把 384×256 的大地圖座標壓成 **192×128**，
再加上畫面偏移 `(0x1B6, 0x26)` ＝ `(438, 38)`。

**192×128 正是 `ICONGRF` 段 2 的尺寸**
（[`../formats/03-grf-images.md`](../formats/03-grf-images.md)）——
那一段先前只知道「是縮小地圖」，現在知道**據點的點是即時畫上去的**，
不是燒在圖裡。所以 `ICONGRF` 段 2 是底圖，`sub_15CE0` 一格一格補上顏色。

### 3.3 `sub_15D19`：據點標記是 4×4 的雙色小方塊

162 B，兩個呼叫者（`sub_12B3C`、`sub_15CE0`）。`dx`／`bx` 是螢幕座標，
`ah` 是 `sub_15CE0` 挑好的屬性。

```asm
ds = 0A0C8h                    ; VRAM 段，與 28 §1 相同
cl = dl & 7                    ; 像素在 byte 內的位移
dx >>= 3                       ; X ÷ 8
bx = Y × 16 / dx += bx / bx <<= 2 / bx += dx
                               ; ＝ Y × 80 ＋ X ÷ 8
out 3CFh, ah                   ; 前景色
ax = 6000h >> cl → 寫 [bx+50h]、[bx+51h]、[bx+0A0h]、[bx+0A1h]
out 3CFh, ah >> 4              ; 另一色（屬性的高 4 位）
ax = 0F000h >> cl → 寫 [bx]、[bx+1]、[bx+0F0h]、[bx+0F1h]
ax = 9000h >> cl → 寫 [bx+50h]、[bx+51h]、[bx+0A0h]、[bx+0A1h]
```

- **列距 80 bytes**（`Y × 80 + X ÷ 8`），與
  [`28`](28-text-number-rendering.md) §1 從文字繪製讀到的一致——第二個來源。
- 位移 `0`／`0x50`／`0xA0`／`0xF0` 是四條掃描線，所以標記高 4 像素；
  每條寫兩個 byte（`+0` 與 `+1`）是為了讓 `>> cl` 之後跨 byte 的部分不掉。
- **上下兩列用 `0xF0` 圖樣（實心 4 像素）、中間兩列用 `0x60` 與 `0x90`**，
  兩色分別來自屬性的低 4 位與高 4 位——所以據點標記是**外框一色、內部一色**。
- `mov ch, [bx+…]` 是 EGA 寫入前的 dummy read（[`28`](28-text-number-rendering.md) §1），
  只是這裡用 `ch` 當丟棄暫存器。
