## 1. ⭐ 參數對應：`dx` 是 X，`bx` 是 Y

整個戰略層的繪圖與熱區常式共用同一組暫存器約定。**三支常式各自的解碼運算元
都指向同一個答案**，不是從呼叫端的參數順序反推的：

| 常式 | 證據 | 結論 |
|---|---|---|
| `sub_1E3D7`（登記熱區）| `shr dx,1 ×3` → 欄；`and bl,0F8h` 後 ×10 → 列 | `dx` ＝ X、`bx` ＝ Y |
| `sub_1E41B`（清熱區）| 同一組位移，`dx>>3` ＋ `10×(bx & 0xF8)` | 同上 |
| `sub_1F6DC`（畫字串，`sub_106F5` 只是薄包裝）| 每畫完一個字 `add dx, di`，`di` ＝ 16（全形）／8（半形）| **`dx` 隨字寬前進 → `dx` 是 X** |

`sub_1E453`（讀熱區）反過來吃 `cx` ＝ X、`dx` ＝ Y，
與 [`22`](22-strategy-command-tree.md) §2 的定址式一致。

單位：`sub_1E3D7` 的座標是**像素**，尺寸 `cx` 是 **8 px 格**
（`cl` ＝ 寬、`ch` ＝ 高）。`sub_1895D` 的座標與尺寸則是 **16 px 粗格**，
而且**內部把 Y 加 2 格**（`si = bx + 2`，[`46`](46-strategy-chrome-cell-layer.md) §2）
——也就是所有用它畫的框都自動落在 32 px 高的橫幅底下。

> 這條「Y ＋2 格」是主畫面版面的關鍵：呼叫端寫 `bx = 0` 看起來像畫在畫面頂端，
> 實際落在 `y = 32`。橫幅高度 32 px 因此不是量出來的，是從這裡算出來的。

## 2. 橫幅與五個開關：`sub_18755`

`sub_119CA`（主畫面重繪）先 `sub_1E3C0` 重置整張熱區圖，再叫 `sub_18755`：

```asm
sub_1E3D7(al=6, bx=0, dx=0, cx=0450h)      ; 整條橫幅 640×32 → 熱區 6
mov cx, 5 / mov dx, 150h / mov al, 1
loop:                                       ; 五次
  sub_1E3D7(al, bx=0, dx, cx=0404h)         ; 32×32
  inc al / add dx, 20h
```

| 熱區 | 矩形 | `off_159D2` 對應 | 視窗 |
|---:|---|---|---|
| 6 | (0, 0, 640, 32) | `nullsub_1` | 橫幅本身，點了不做事 |
| 1 | (336, 0, 32, 32) | `sub_1614A` | **命令** |
| 2 | (368, 0, 32, 32) | `sub_15E1E` | **自勢力情報** |
| 3 | (400, 0, 32, 32) | `sub_15A3A` | **縮小地圖** |
| 4 | (432, 0, 32, 32) | `sub_15FAA` | **系統** |
| 5 | (464, 0, 32, 32) | `nullsub_1` | **登記了但沒接東西** |

先登記 640×32 再用五個 32×32 蓋掉一段，是「整條橫幅預設不可點、
只有這五格例外」的寫法。**第五格是空的**——說明書說四個開關，
機器碼登記五格，差額不是漏讀，是表上真的接 `nullsub_1`
（`00159DC`）。

## 3. 開與關：左鍵 `sub_159A6`、右鍵 `sub_159B7`

主迴圈 `sub_11BE0`：

```asm
call sub_11F7F                 ; bx bit0 ＝ 左鍵、bit1 ＝ 右鍵；cx/dx ＝ 游標
call sub_1E453                 ; al ＝ 熱區編號
and al, al / jz  → 沒點到
and bx, bx / jz  → 沒按鍵
cmp bx, 1  / jnz → sub_159B7   ; 不是單獨左鍵 → 關
             jz  → sub_159A6   ; 左鍵 → 開
```

兩支都只做「熱區編號 ×2 當索引查表再 call」：
`sub_159A6` 查 `off_159D2`（畫），`sub_159B7` 查 `funcs_159C0`（擦），
擦完再 `sub_11C8D` 補回被蓋住的地圖。**與說明書的「左で表示、右でクリア」逐字對上。**

`byte_198A6` 是「哪幾個視窗開著」的位元集：bit 0–3 對應上表的熱區 1–4，
各視窗的繪製常式自己 `or` 上去、擦除常式自己清掉
（`sub_1614A` 開頭的 `or ds:98A6h, 1`）。`sub_119CA` 全畫面重繪時照這個位元集
重跑一次 `off_159D2[2..8]`，所以視窗狀態跨重繪保得住。

每個視窗都是一對常式，**位元由它們自己維護**：

| 視窗 | 位元 | 畫（`off_159D2`）| 擦（`funcs_159C0`）|
|---|---:|---|---|
| 命令 | 0x01 | `sub_1614A`：`or ds:98A6h, 1` | `sub_161B6`：`and ds:98A6h, 0FEh` |
| 自勢力情報 | 0x02 | `sub_15E2D`：`or …, 2` | `sub_15E4C`：`and …, 0FDh` |
| 縮小地圖 | 0x04 | `sub_15A3A`：`or …, 4` | `sub_15AA2`：`and …, 0FBh` |
| 系統 | 0x08 | `sub_15FAA` | `sub_1613B` |

擦除就是**用樣式 0 再畫一次同一個矩形**（`sub_1895D(al=0, 同樣的 bx/dx/cx)`），
四支擦除常式的座標與對應的繪製常式逐字相同。之後 `sub_159B7` 再叫
`sub_11C8D` 把地圖補回來——它不帶裁切矩形，只是重跑一次
`sub_1D615 / sub_11CC9 / sub_1D66A`（§3.2）。

### 3.1 `sub_11F7F` 的兩條路徑

它先用 INT 33h `AX=5`（`BX=0` 左、`BX=1` 右）取按鍵，再用 `AX=3` 取座標，
然後分兩條：

- **座標與上一次相同** → 回傳 `bx` ＝ 按鍵遮罩，並設 `byte_198A3` bit 7。
- **座標不同** → 更新記錄，走大地圖捲動（`cx` 減 `ds:9882h`、上限 `0x27F` ＝ 639）。

也就是**游標一邊移動一邊按下去不算點擊**：要先停住，下一次取樣才會分派。

### 3.2 ⭐ 大地圖是 640×368，四個視窗蓋在它上面

`sub_1D615` 的迴圈把答案寫死了：

```asm
bx = 2 / dx = 17h / cx = 28h        ; 23 列 × 40 欄
loop:
  al = es:[di]                      ; 地圖圖塊編號
  ah = al
  xchg al, [bx+si]                  ; 與格子記錄 +2 的舊值交換
  cmp al, ah / jz → 跳過
  or byte ptr [si], 60h             ; 變了 → 標記這一格要重畫
  si += 8 / di++ / loop
  di += 158h                        ; 換列
```

**40 欄 × 23 列的 16×16 格 ＝ 640 × 368**，也就是橫幅以下的整個畫面。
`sub_11F7F` 的捲動上限 `cmp cx, 27Fh`（639）也是照 640 寬算的。

所以**主畫面不是「左邊地圖、右邊面板」的分割版面**，
而是**整片地圖 ＋ 疊在上面的四個視窗**。關掉視窗時看到的不是空白，
是本來就在下面的地圖。

這也回答了 [`46`](46-strategy-chrome-cell-layer.md) §4 掛著的
「`cs:word_1D84E` 那張表怎麼變成像素」——**它不變成像素**，
它是每格 8 bytes 的**格子屬性表**（40 欄、列距 `0x140` ＝ 40×8），
第 0 個 byte 是旗標：

| 位元 | 誰寫 | 意思 |
|---|---|---|
| `0x10` | `sub_1D5D4`：**繪製時 `or 10h`、擦除時 `and 0EFh`** | 這一格**不歸地圖管** |
| `0x60` | 擦除時 `or 60h`；`sub_1D615` 發現圖塊變了也 `or` | 這一格髒了，要重畫 |
| `0x80` | 繪製時 `and …, 7Fh` 清掉 | 未解 |

`sub_1895D` 進來時 `ah = 0`，**只有樣式 0（擦除）才 `ah = 1`**，
而 `sub_1D5D4` 是 `and ah,ah / jnz` ——所以 `ah=1`（擦除）走清 `0x10` ＋ 設 `0x60`，
`ah=0`（繪製）走設 `0x10` ＋ 清 `0x80`。

地圖迴圈 `sub_1D66A` 的第一句就是 `test dl,10h` ⇒ **設起來就跳過這一格**。
所以開視窗 ＝ 設 `0x10`（地圖不再重畫這幾格，視窗蓋得住）；
關視窗 ＝ 清 `0x10` ＋ 設 `0x60`（下一輪地圖就把它補回來）。
**髒格機制是原版的效能手段**，remake 每幀重畫，不需要移植這一層——
需要移植的是「地圖 640×368、視窗是疊層」這個結構。

### 3.3 ⭐ 新遊戲的初值是「四個全關」

`sub_11A6E`（新遊戲流程，`sub_1005B` 呼叫）的**最後一行**：

```asm
sub_1D615(dx=0AAh, bx=62h)     ; NEW GAME 對話框背後那張地圖的相機 (170, 98)
sub_11AC3                      ; 選劇本／選君主，寫 word_10CFD ＝ 玩家勢力
…
mov cs:byte_198A6, 0           ; ← 四個視窗全部關掉
retn
```

所以**原版一進主畫面是滿版地圖，四個視窗都要玩家自己點開**。
PC-98 實跑看到的正是這樣（[`../playtest/23`](../playtest/23-main-screen-geometry.md) §1），
機器碼與實跑兩條獨立證據對上。

說明書第 3.1 節那張「四個都開著」的主畫面圖，以及參考影片的畫面，
都是玩家開過之後的狀態，不是初始狀態。

## 4. 四個視窗的矩形

全部由 `sub_1895D(al=樣式, bx=Y, dx=X, cx=(高<<8)|寬)` 取得，
單位 16 px、Y 再加 2 格（§1）：

| 視窗 | 呼叫端 | 參數 | 像素矩形 |
|---|---|---|---|
| 命令 | `sub_1614A` | `bx=0 dx=0 cx=021Bh` | **(0, 32, 432, 32)** |
| 縮小地圖 | `sub_15A3A` | `bx=0 dx=1Bh cx=0A0Dh` | **(432, 32, 208, 160)** |
| 自勢力情報 | `sub_15E2D` | `bx=0Ah dx=1Bh cx=0D0Dh` | **(432, 192, 208, 208)** |
| 系統 | `sub_160CC` | `bx=5 dx=0Dh cx=0C0Dh` | **(208, 112, 208, 192)** |

三個常駐視窗**剛好鋪滿右上到右下**：`32 + 160 + 208 = 400`。
系統視窗是置中的模態框，不在右欄——與說明書「開著系統視窗時時間停止」相符。

### 4.1 命令列：字在 x=32，不是 x=64

```asm
sub_1895D(al=0Bh, bx=0,    dx=0,    cx=021Bh)   ; 框 (0,32,432,32)
sub_106F5(si=6181h, bx=28h, dx=8, ax=0F01h)     ; 字串：X=8、Y=40
sub_1E3D7(al=0Ch,  bx=28h, dx=18h, cx=0230h)    ; 熱區 (24,40,384,16)
sub_161CA: 索引 ＝ (x − 24) ÷ 48；寬 40、節距 48、高 16
```

`cs:6181h` 是**一整串**（[`46`](46-strategy-chrome-cell-layer.md) §1）：
開頭「　 」是全形 ＋ 半形共 24 px，詞與詞之間一個全形空格。所以

```
字串起點 8 ＋ 開頭空白 24            → 第一個詞在 x = 32
節距 48（詞 32 ＋ 全形空格 16）      → 第 n 個詞在 x = 32 + 48n
第八個詞結束 32 + 7×48 + 32 = 400
尾端「 　」再 24                      → 424 < 432 ✔ 落在框內
```

**「落在框內」本身就是檢查**：把起點讀成 40 的話尾端會算到 456，
超出框寬 432——一條算式就分得出兩種讀法哪一個對。

熱區 (24, 40, 384, 16) 與 `sub_161CA` 的 `x < 24` 下限、
`x ≥ 408` 上限完全一致，是第二條獨立證據。

### 4.2 自勢力情報視窗的內部

`sub_15E1E` ＝ `sub_15E2D`（框 ＋ 底圖）＋ `sub_15E80(al=0x0F)`（四個欄位）。
`sub_15E80` 把 `al` 逐位右移，四個位元對四支常式，所以那四支可以單獨重畫。

| 元件 | 位置 | 來源 |
|---|---|---|
| 靜態層（標籤、方塊、圖示）| 原點 (440, 200) | `sub_15E2D` → `sub_10337(al=0)`，是一份顯示清單而不是一張圖（[`48`](48-window-display-list.md)）|
| 君主名 | (576, 208) | `sub_15EB7` → `sub_106FD(dx=0x240, bx=0xD0)` |
| 首都名 | (576, 224) | 同上，`bx=0xE0` |
| 軍師名 | (576, 240) | 同上，`bx=0xF0` |
| 信賴度**量條** | (456, 292) | `sub_15F27` → `sub_10AAA(dx=0x1C8, bx=0x124, ax=0x0A00)` |
| 資金（7 位）| (560, 312) | `sub_15F5D` → `sub_1062F(di=0x61C6, bx=0x0F07)` |
| 預備兵 ×3（6 位）| (568, 328 / 344 / 360) | `sub_15F7F` → `di=0x66C7`，每列 `di += 0x500` |

`di` 是 VRAM 位移，一列 80 bytes：`0x66C7 ÷ 80 = 328 … 71` → (568, 328)，
`0x500 = 1280 = 16 列 × 80` → 列距 16 px。**兩個數字互相印證**：
資金 7 位與預備兵 6 位都右對齊在 x=616。

三件值得單獨記的事：

- **信賴度是量條不是數字。** 長度 `= (信賴度 × 100 + 0x9F) ÷ 0xA0`，
  滿長 160（`sub_15F27` 給 `div` 用的 `ch = 0A0h` 沒有重載，
  於是 `cx` ＝ 總長<<8 ｜ 已填長度）。`sub_10AAA` 分兩段畫：
  已填用 `ah = 0x0A`（紅），未填把 `ah` 換成 `al = 0x00`（黑），
  **兩段都是 `ch = 2`，也就是量條只有 2 px 高**。
- **資金是 32 位**（`[si+0x20]` 的 u16 ＋ `[si+0x22]` 當高位），
  而且**負數換色**：`dh ≥ 0x80` 時把顏色從 `0x0F` 改成 `0x0A`。
- ⭐ **預備兵顯示時乘以 10**（`mov dx, 0Ah / mul dx`）：勢力記錄
  `+0x04/+0x06/+0x08` 存的是**點**，一點 10 人。
  `sub_14698`（AI 編成）把同一個 `ax` 從預備兵 `sub es:[bx], ax` 扣掉、
  再 `mov [si+1], al` 寫進軍團槽——**軍團槽的兵數是 1 byte、上限 100**，
  與預備兵同單位。所以乘 10 只發生在顯示，狀態層不動
  （說明書 5.5 的「一點 ＝ 10 人」、4.1 的 1:10 換算是同一件事）。

## 6. 主畫面收得到點擊——但游標的座標空間會換

松崗 DOS/V 上這五格點得開（[`../playtest/38`](../playtest/38-window-parity.md)）。
會以為點不到，是因為**進到大地圖之後 INT 33 的範圍換成整個世界**：

```asm
sub_120D6:
  ax=7 / cx=0 / dx=17FFh      ; 水平 0–6143 ＝ 384 格 × 16
  ax=8 / cx=0 / dx=101Fh      ; 垂直 0–4127
  ; 然後把游標設到「鏡頭原點 ＋ 螢幕座標」
```

`sub_11F7F` 再把原始座標減掉鏡頭原點、夾在 0–639／0–399，
**夾的同時把原點也拉過去——這就是大地圖的捲動**。所以：

1. 一個主機像素 ≈ **9.6 個遊戲像素**（640 個主機像素攤在 6144 上），
   32 px 的開關只剩 3.3 個主機像素寬。
2. **游標一移動就會捲動地圖**，而且送過去的座標與螢幕座標不是同一件事。
3. `sub_11F7F` 對「座標與上次不同」那一次**只更新座標不分派**（§3.1），
   所以 `mousemove` ＋ `click` 不算點擊——要停住之後再按一次。

實務上先把游標推到左上角（`click:0,0`）讓原點歸零，之後 x 就算得出來。

⚠ **PC-98 那一側仍然沒點開過**（`tools/dosboxx.sh`，游標走到 (353,16)
等四個點都沒反應）。上面這三條足以解釋它，但沒有在 PC-98 上重驗過；
那一版的 `WOLONG_MOUSE_EMU` 預設是 `never`，也可能根本沒送出座標。

> 順帶一提，主畫面上**游標是隱藏的**（`sub_120D6` 結尾 `ax=2`）。
> 這讓「點了沒反應」與「根本沒點到那裡」在截圖上長得一樣——
> 排這類問題要先確認送出去的座標對映是什麼。
