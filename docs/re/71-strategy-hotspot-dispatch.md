# 71 — 戰略層的兩張熱區分派表，以及點縮小地圖會發生什麼

（點縮小地圖）＝ 把大地圖鏡頭捲到那一格，`0x17` ＝ 開勢力選擇視窗。
勢力選擇視窗的版面也一起解了（§4）。**

- 範圍：只驗松崗 DOS/V

## 1. 分派點在主迴圈，不在指令列

`sub_11BE0`（主畫面主迴圈）每輪讀一次游標下的熱區：

```asm
00011C24  call sub_1E453          ; al ＝ 熱區碼、bx ＝ 按鍵
00011C29  and al, al / jz →       ; ★ al == 0 ⇒ 沒踩到熱區
00011C2D  and bx, bx / jz →       ; 沒按鍵
00011C31  cmp bx, 1 / jnz →
00011C36    call sub_159A6        ; ★ 左鍵
00011C3B    call sub_159B7        ; ★ 右鍵
…
00011C46  cmp bl, 1 / jnz →
00011C4B  call sub_11E46          ; ★ 沒踩到熱區的左鍵 ⇒ 點大地圖
```

⭐ **「點大地圖」是熱區的 fallback**，不是一個熱區——熱區碼 0 才走到那裡。

兩支分派器都只是「碼 × 2 當位移查表」：

```asm
sub_159A6:  bl = al / bh = 0 / bx <<= 1 / call word ptr [bx+59D2h]
sub_159B7:  bl = al / bh = 0 / bx <<= 1 / call sub_101B4
                                          call funcs_159C0[bx]
                                          call sub_11C8D / sub_101DB
```

**右鍵那一支多包了 `sub_101B4`／`sub_101DB`**（繪圖前後的成對常式，
[`42`](42-leaf-functions.md) §2）與 `sub_11C8D`——因為右鍵的 handler 都在擦東西。

## 2. 左鍵表 `cs:0x59D2`（`off_159D2`）

索引就是熱區碼，32 筆 word，預設 `0x59D0` ＝ `nullsub_1`（不做事）。

| 碼 | handler | 做什麼 | 出處 |
|---|---|---|---|
| `0x01` | `sub_1614A` | 指令列 | [`46`](46-strategy-chrome-cell-layer.md) §1 |
| `0x02` | `sub_15E1E` | 自勢力情報視窗 | [`47`](47-main-screen-window-registry.md) |
| `0x03` | `sub_15A3A` | 縮小地圖視窗 | [`62`](62-strategy-minimap.md) §1 |
| `0x04` | `sub_15FAA` | 系統選單 | [`55`](55-system-menu-window.md) |
| `0x0C` | `sub_161CA` | 指令列的八個指令（[`22`](22-strategy-command-tree.md) §3）| 同左 |
| **`0x16`** | **`sub_15AB6`** | **點縮小地圖 → 捲鏡頭**（§3）| 本份 |
| **`0x17`** | **`sub_15AD1`** | **開勢力選擇視窗**（§4）| 本份 |
| `0x1B` | `sub_161B6` | 關指令列（清 `byte_198A6` 位元 0）| [`42`](42-leaf-functions.md) §2 |
| `0x1C` | `sub_15E4C` | 關自勢力情報（清位元 1）| 同上 |
| `0x1D` | `sub_15AA2` | 關勢力一覽（清位元 2）| 同上 |
| 其餘 26 筆 | `nullsub_1` | — | — |

⭐ **`0x05` 是 `nullsub_1`**——[`47`](47-main-screen-window-registry.md) §4 的
「熱區 5 (x 464–496) 登記了但不接任何常式」不是漏讀，**表裡就是預設值**。
remake 照樣不做事是對的。

### 2.1 ⚠ 右鍵表與左鍵表重疊 9 個 word

`funcs_159C0` 在 `cs:0x59C0`，`off_159D2` 在 `cs:0x59D2`——**只差 `0x12` ＝ 9 個 word**。
逐筆比對之後：

```
funcs_159C0[i] == off_159D2[i − 9]      對所有 i ≥ 9 成立
```

而 `funcs_159C0[0x00]`–`[0x08]` 那九筆指向 `0x197FF`、`0x15A06`、
`0x1C6E8`（落在 `sub_1C6BF` 中段）、`0x1E8C2`、`0x1A811`、`0x1C88C`、
`0x1D88E`、`0x1C08E`、`0x190C3`——**沒有一筆是函式起點**。

⚠ **不要據此宣稱「右鍵表只有 9 筆」或「右鍵與左鍵共用 handler」。**
兩種讀法都說得通，而**靜態影像分不出來**：

| 讀法 | 說得通嗎 |
|---|---|
| 右鍵表只涵蓋碼 `0x00`–`0x08`，之後越過表尾 | 說得通，但那九筆不是函式起點，等於右鍵表整張都沒有有效 handler |
| 兩張表刻意重疊，右鍵碼 `C` 走左鍵碼 `C−9` 的 handler | 算術上成立（右鍵 `0x1F` → 左鍵 `0x16`、右鍵 `0x1D+9=0x26` 越界）|

**要裁決得看實際會用到哪些熱區碼配右鍵**，那要動態取樣。
與 [`31`](31-faction-picker-screen.md) §1.2 的 `cs:6056` 是同一個形狀：
**沒有上界檢查的表，表長只能由「實際出現的索引值域」決定，不能從程式碼推。**

## 3. ⭐ 熱區 `0x16`：點縮小地圖就是捲鏡頭

`sub_15AB6`（27 B）：

```asm
00015AB6  cx -= 1B8h        ; 440 ＝ 地圖區左緣，借位就夾成 0
00015ABE  dx -= 28h         ;  40 ＝ 地圖區上緣，同樣夾 0
00015AC5  cx <<= 1          ; ★ 1 px ＝ 2 格（[`62`](62-strategy-minimap.md) §1）
00015AC7  dx <<= 1
00015AC9  bx = dx / dx = cx ; 交換 ⇒ dx ＝ 世界 X、bx ＝ 世界 Y
00015ACD  call sub_121B2
```

`sub_121B2` 就是**設鏡頭**：

```asm
000121B4  ax = 14h / cx = 0Ch / call sub_12151   ; ★ 中心 −(20, 12) 當左上角
000121BD  ax = word_19882 + word_19886           ; 游標跟著移到新的鏡頭原點
000121C9  dx = word_19884 + word_19888
000121D4  ax = 4 / call sub_20000                ; INT 33 設游標位置
000121DC  word_1988A = 0FFFFh                    ; 標記「鏡頭動過」
```

⭐ **`ax = 20`／`cx = 12` 與開局鏡頭是同一組立即值**
（[`../spec/52`](../spec/52-main-screen-camera-and-banner-date.md)：
開局鏡頭是首都 −(20,12)）——所以「點縮小地圖」與「開局定位」
走的是同一支置中常式。

> [`62`](62-strategy-minimap.md) §5 當時寫「合理猜測是把大地圖捲到該處，
> 但**沒驗**」。**猜對了**，而且連夾制與游標同步都在同一支裡。

## 4. 勢力選擇視窗的版面（`sub_15AFC`）

熱區 `0x17` → `sub_15AD1` → `sub_15AFC`。**這就是
[`31`](31-faction-picker-screen.md) §1.2 找不到的進入路徑**：
`sub_15AD1` 不在 `off_159D2` 的**前幾筆**裡，它在第 `0x17` 筆。

### 4.1 幾何

```asm
00015B00  al = 1Fh / dx = 20h / bx = 0Ah / cx = 0D08h / call sub_1895D   ; 開框
00015B0E  al = 20h / dx = 208h / bx = 0D8h / cx = 160Eh / call sub_1E3D7 ; 熱區 0x20
00015B1C  dx = 208h / bx = 0C8h / si = 277h / di = 0D7h / ah = 7 / sub_1F1A3
00015B2D  dx = 208h / bx = 0D8h / si = 277h / di = 187h / ah = 9 / sub_1F1A3
00015B42  si = cs:5C04 / dx = 220h / bx = 0C8h / ax = 7001h / sub_106F5  ; 標題
```

`sub_1895D` 的座標與尺寸是 **16 px 粗格**，而且內部把 Y 加 2 格
（[`46`](46-strategy-chrome-cell-layer.md) §2）；`sub_1E3D7` 的座標是**像素**、
尺寸是 **8 px 格**；`sub_106F5` 的 `dx`／`bx` 直接是像素
（[`47`](47-main-screen-window-registry.md) §1）。代進去：

| 項目 | 值 | 怎麼算的 |
|---|---|---|
| 外框 | **(512, 192, 128 × 208)** | `dx=0x20`×16、`(bx=0x0A + 2)`×16；`cx` 高 byte `0x0D`×2×8 ＝ 208 高、低 byte `0x08`×2×8 ＝ 128 寬 |
| 標題列底色 | (520, 200)–(631, 215)，色 **7** | `sub_1F1A3` 的四個角 |
| 清單底色 | (520, 216)–(631, 391)，色 **9** | 同上 |
| 標題文字 | (544, 200)，屬性 `0x7001` | `cs:5C04` ＝ **「勢力一覽」** |
| 熱區 `0x20` | **(520, 216, 112 × 176)** | `cx = 0x160E` → 寬 `0x0E`×8 ＝ 112、高 `0x16`×8 ＝ 176 |

⭐ **三塊互相印證**：外框 (512,192)–(639,399)，兩塊填色與熱區都剛好**四邊各內縮 8 px**
（520 ＝ 512+8、631 ＝ 639−8、200 ＝ 192+8、391 ＝ 399−8）。
那 8 px 就是框邊，與訊息框的內縮同一個數
（[`66`](66-message-box-geometry.md) §2）。

### 4.2 逐列：兩欄各 11 列

`sub_15C14(al ＝ 勢力編號, ah ＝ 屬性)`：

```asm
00015C15  bh = al / bl = 0 / bx >>= 2      ; si ＝ 編號 × 64 ⇒ 勢力記錄
00015C1F  dx = 20Ch                        ; 左欄 X ＝ 524
00015C26  cmp bl, 0Bh / jb →
00015C2B    dx = 244h                      ; ★ 右欄 X ＝ 580
00015C2E    bx -= 0Bh                      ; ★ 右欄從第 11 個開始
00015C31  bx <<= 4                         ; 列 × 16
00015C39  bx += 0D8h                       ; Y ＝ 216 + 列×16
00015C3D  cmp byte [si], 80h / jb →
00015C42    call sub_188B0                 ; 勢力存在 → 畫勢力名
00015C4C  ax = 9001h / si = cs:5C0D / sub_106F5   ; 空槽 → 畫「－－－」
```

| 項目 | 值 |
|---|---|
| 左欄 X | **524** |
| 右欄 X | **580** |
| 第 n 列的 Y | **216 + (n mod 11) × 16** |
| 每欄列數 | **11**（22 個勢力 ÷ 2）|
| 空槽 | `cs:5C0D` ＝ **「－－－」**，屬性 `0x9001` |

三種屬性（[`62`](62-strategy-minimap.md) §4.2 已記）：一般 `0x90`、
自勢力 `0x9A`、目前選中 `0x93`。

### 4.3 點選與離開

```asm
00015B7B  ax = 5 / bx = 1 / sub_20000 / bx != 0 → 關掉      ; ★ 右鍵離開
00015B8A  ax = 5 / bx = 0 / sub_20000 / bx == 0 → 繼續等    ; 左鍵
00015B9A  sub_1E453 / cmp al, 20h / jnz → 忽略              ; 要點在自己的熱區上
00015BA3  dx -= 0D8h                                        ; 相對清單頂端
00015BA7  cmp cx, 240h / jb → / dx += 0B0h                  ; ★ X ≥ 576 ⇒ 右欄，列 +11
00015BB1  dx >>= 4                                          ; ⇒ 列號 0–21
00015BB9  si = 列號 << 6                                    ; ⇒ 勢力記錄
00015BBD  cmp [si], 80h / jb 忽略                           ; 勢力要存在
00015BC2  cmp al, cs:byte_10CFF / jz 忽略                   ; ★ 不能選自己
          舊的重畫成 0x90 → byte_198A7 = al → 新的重畫成 0x93
          sub_15DBB（圖例）→ sub_15CC6（192 個標記全部重畫）
```

**欄的分界是 X = 576**，正好把 112 px 的清單切成兩個 56 px。
文字畫在 524 與 580，各離欄的左緣 4 px。

⭐ **開窗前 `sub_12078`、關窗後 `sub_120D6`**——那兩支是切換 INT 33 的座標範圍
（[`../playtest/37`](../playtest/37-main-screen-parity.md)：進大地圖之後
INT 33 的範圍會變成整個世界）。**視窗開著時滑鼠回到螢幕座標**，
所以視窗裡的座標判斷才可以直接用像素比。
