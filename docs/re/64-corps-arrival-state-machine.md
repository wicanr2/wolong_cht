# 64 — 軍團抵達時的狀態機：`+0x23` 的分派表與解體

**狀態：分派表的結構、索引算式與 Stage 8–11 的語意 confirmed。
⭐ 解體的消費端找到了——`Stage 11` → 回首都 → `sub_14651` 解散，
五個動作全部解出。非玩家的四個 entry 在
[`65`](65-ai-march-decision-chain.md)。**

- 日期：2026-08-16
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 分析時的 `KI.EXE.i64` SHA-256：`8a8fd7d528e0498000fd04282300588b637fbcb8aa48deb09242f1f41f532691`
- 工具：**IDAPython** `tools/ida_dump.py`、`tools/ida_disp_users.py`、
  `tools/ida_range.py`；分派表由原始 bytes 直接解（`0x14358`，檔案位移 `0x4558`）
- 位址空間：IDA DOS/V linear address；`si` 是**軍團記錄**

[`45`](45-corps-command-mode.md) §5 掛著「`+0x23 = 0x0B` 之後由誰處理解體，
消費端沒找」。答案不在 `0x0B` 的比較裡——**沒有任何一支比較它**，
因為它是**跳表的索引**。

## 1. `sub_14325`：抵達目標時的分派

`sub_12662`（行軍主流程）在「現在節點 ＝ 目標節點」時呼叫它
（[`08`](08-hourly-update.md) §6），`sub_17F90` 也呼叫一次。

```asm
ah = [si+20h] / al = 0 / ax >>= 3 / ax += 840h   ; ax = 目標據點的記錄位址
bl = [si+23h] / bh = 0 / bx <<= 1                ; bx = Stage × 2
cmp bx, 10h / jnb → 分派                          ; Stage ≥ 8：不分玩家
cl = cs:byte_10CFF                                ; 玩家的勢力編號
cmp cl, [si+1] / jz → 分派                        ; 是玩家的軍團：不加
bx += 8                                           ; ← 非玩家往後挪四個 entry
分派: call cs:funcs_1434F[bx]
```

**`+0x20` 是目標據點編號（無縮放）**，`<<8` 再 `>>3` 就是 `×32`，
正好是據點記錄的大小（[`../formats/08`](../formats/08-sinario-save.md)）。

### 1.1 `funcs_1434F` 有 12 筆

從原始 bytes 直接解（`0x14358` 起 12 個 LE word）：

| entry | 目標 | 誰會走到 |
|---:|---|---|
| 0–3 | `sub_14370` ×4 | **玩家**的軍團，Stage 0–3 |
| 4 | `sub_1439D` | 非玩家 Stage 0（[`65`](65-ai-march-decision-chain.md) §2）|
| 5 | `sub_143AF` | 非玩家 Stage 1（[`65`](65-ai-march-decision-chain.md) §3）|
| 6 | `sub_1440F` | 非玩家 Stage 2（[`65`](65-ai-march-decision-chain.md) §4）|
| 7 | `sub_14466` | 非玩家 Stage 3（[`65`](65-ai-march-decision-chain.md) §5）|
| 8 | `sub_14483` | Stage 8（不分玩家）|
| 9 | `sub_14499` | Stage 9 |
| 10 | `sub_144A9` | Stage 10 |
| 11 | `sub_144D6` | Stage 11 |

⭐ **玩家的四個 Stage 走同一支**——玩家自己下命令，不需要 AI 的四段決策。
這也解釋了為什麼寫入端只見過 0／1／2／3／8／9／`0x0A`／`0x0B` 八個值：
**4–7 是「非玩家」那一半的 entry 編號，不是 Stage 值**。

## 2. Stage 的語意

| Stage | 名稱 | 抵達時做什麼 |
|---:|---|---|
| 0–3 | 一般行軍 | 玩家：`sub_14370`；非玩家：AI 決策鏈（§6）|
| 8 | **等士氣** | `sub_14483`：軍團 `+0x06` 士氣 < 勢力 `+0x1D` 基準就留著不動，達標才轉 Stage 1 |
| 9 | **在首都補兵** | `sub_14499`：`sub_1461D`（退回 ＋ 重新分配）→ `sub_16FD2`（重算派生值）→ Stage 3 → 重畫狀態畫面 |
| 10 | **回首都補兵的路上** | `sub_144A9`：目標不是首都就改成首都並設 `+0x00` 位元 1；已在首都就轉 Stage 9 |
| 11 | **解體** | `sub_144D6`：同上先回首都，到了就 `sub_1463E` → `sub_14651` 解散（§3）|

**8–11 是「回首都做一件事」的家族**，三支的骨架相同：
先把目標校正成首都，再用 `sub_14548` 問「到了沒」。

### 2.1 `sub_14548`：設目標，順便回報到了沒

```asm
ax = [bx+8] / dx = [bx+0Ah]        ; 據點的 X／Y
bx = (bx − 840h) >> 2              ; → 據點編號 × 8
比 [si+10h]（X）、[si+12h]（Y）、[si+0Eh]（現在節點）
  三者全同 → STC          否則 → CLC
[si+16h] = ax / [si+18h] = dx / [si+14h] = bx   ; 不論如何都寫目標
```

**CF 是「已經在那裡」**，不是錯誤旗標。四個呼叫端
（`sub_14370`／`sub_1439D`／`sub_144A9`／`sub_144D6`）都靠它分流。

### 2.2 玩家的軍團抵達首都會自動補兵

`sub_14370`（玩家 Stage 0–3）：

```asm
[si+23h] = 0                       ; 先歸零
bx = ax / sub_14548 / jnb → retn   ; 還沒到就只是設目標
cmp word [si+4], 258h / jnb → retn ; ★ 兵力 ≥ 600（6,000 人）就不補
ax = (bx − 840h) << 3              ; ah = 據點編號
bx = cs:word_10CFD                 ; 玩家的勢力記錄
cmp ah, [bx+3] / jnz → retn        ; ★ 這裡是首都嗎
[si+23h] = 9                       ; → Stage 9，下一次抵達處理就補兵
```

⭐ **玩家不必下「補兵」指令**：把未滿編的軍團開回首都，抵達當下就轉 Stage 9，
下一輪把預備兵池的兵補進來。`0x258` ＝ 600 點 ＝ 六槽滿編
（[`49`](49-corps-formation-window.md) §5）。

## 3. ⭐ 解體：`Stage 11` → 回首都 → 五個動作

`sub_144D6` 與 `sub_144A9` 只差最後一句（一個解散、一個轉 Stage 9）：

```asm
bx = 勢力 × 64 / bh = [bx+3]        ; 首都據點編號
cmp [si+20h], bh / jz → 已在首都
  [si+20h] = bh / or byte [si], 2   ; 改目標成首都，設位元 1
已在首都:
bx = 首都的據點記錄
sub_14548 / jnb → retn              ; 還沒走到就等下一次
sub_1463E                           ; ← 解散
```

`sub_1463E` ＝ `sub_14651` ＋（是玩家的話）重畫狀態畫面 `sub_15E80(al=8)`。

`sub_14651`（56 B）做**五件事**：

| # | 指令 | 意思 |
|---:|---|---|
| 1 | `sub_14689` → `dec [勢力+14h]` | 勢力的**軍團數 −1** |
| 2 | `di = 勢力×64 + 4` ／ `sub_14717` | **六個槽的兵員全部退回預備兵池**（同編成畫面那一支，[`30`](30-corps-formation-ui.md) §4）|
| 3 | `mov byte ptr [si], 0` | 軍團記錄 `+0x00` 歸零 ＝ **這支軍團不存在了** |
| 4 | `[di+4257h] = 0`（`di` ＝ 武將位移）| 主將的 `+0x17` 職務 ＝ **無職** |
| 5 | `les di, [si+1Ah]` ／ `dec es:[di]` | 大地圖**佔用圖 −1** |

⭐ **兵不會憑空消失**：走的是編成畫面同一支 `sub_14717`，
所以解體等於「把這支軍團拆回預備兵」。
而「解體只在目標是首都時才出現」（[`45`](45-corps-command-mode.md) §2）
與 `sub_144D6` 的先回首都互為冗餘保護——選單擋一次、狀態機再擋一次。

## 4. 三個指令模式在狀態機裡的位置

| 玩家選 | 寫入 | 抵達時 |
|---|---|---|
| 戰鬥指揮 | `and [si], 0FBh`（清委任位元）、`+0x23 = 0` | `sub_14370`：到了首都且未滿編 → Stage 9 補兵 |
| 委任 | `or [si], 4`、`+0x23 = 0` | 同上（委任只改**誰指揮戰鬥**，不改行軍狀態機）|
| 解體 | `+0x23 = 0x0B` | `sub_144D6` → 回首都 → 解散 |

**委任不影響抵達處理**——它只在遭遇戰時決定要不要跳「戰鬥指揮／委任」選單
（[`09`](09-combat.md) §2 的 `test byte ptr [si], 4`）。
