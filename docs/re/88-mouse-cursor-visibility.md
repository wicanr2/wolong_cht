## 1. 原版不用滑鼠驅動畫游標

`KI.EXE` 全庫只有 **8 條 `INT 33h`**，服務號是
`0`（reset）、`3`（讀位置與按鍵）、`4`、`5`、`7`／`8`（範圍）、
`0Ch`（中斷副程式）、`0Dh`／`0Eh`／`0Fh`。

⛔ **`AH=1`（顯示游標）、`AH=2`（隱藏游標）、`AH=9`（設圖形游標）一次都沒有。**
所以那個紅箭頭是遊戲自己畫上 VRAM 的，不是驅動畫的——
而這也是為什麼它會出現在截圖裡（驅動畫的游標多半不會）。

## 2. `seg002` 是一層 INT 33h 相容包裝

```asm
sub_20000       proc far          ; ★ 功能號在 ax，直接對應 INT 33h 的服務號
                cli
                push si / mov si, ax / shl si, 1
                call cs:funcs_20006[si]
                pop si / sti / retf
```

| `ax` | 常式 | 做什麼 |
|--:|---|---|
| 0 | `sub_2002E` | reset ＋ 設範圍／比例／中斷副程式 |
| **1** | **`sub_20070`** | **顯示**：`byte_20100` 已是 1 就直接回；否則讀 `INT 33h AH=3` 拿座標存進 `word_200FC`／`word_200FE`、設 `byte_20100 = 1`、`cx = 0FFFFh` 呼叫 `sub_20137` |
| **2** | **`sub_2009A`** | **隱藏**：`xchg al, byte_20100` 把旗標清 0，舊值不是 0FFFFh 就呼叫 `sub_20137` 擦掉 |
| 3–8 | `sub_200BD` | 就一條 `int 33h`——功能號已經在 `ax` 裡，直接透傳 |
| 9 | `sub_200C0` | 設 `byte_20100 = 2`（第三種狀態，未讀）|
| 10–14 | `nullsub_4` | 空 |
| 15 | `sub_2002E` | 同 0 |

`sub_20137` 是搬運本體：`ds = 0A0C8h`，先在舊位置還原背景
（`sub_201C6` 算位址 → `sub_20249`），再在新位置存背景並畫
（`sub_201C6` → `sub_202BD` → `sub_201E4`）。
`cx = 0FFFFh` 就跳過「還原舊的」那一半——**第一次顯示沒有舊位置可還原**。

⭐ 這推翻了三個假說（[`../playtest/91`](../playtest/91-general-boast-parity.md) §3）
的共同前提：**它們都在猜「畫面上有什麼」，而變數根本不在畫面上。**
同一張清單、同一個游標位置，旗標可以是 0 也可以是 1——
B 組那兩張連**視窗版面都一模一樣**，差別只有「決定了沒有」。

⚠ **但「決定了就會顯示」也不是規則**：A 組最終同樣是「清單選走 → 台詞
掛著」，旗標卻是 0。**兩組的差別在流程不在畫面**（武將一覽選完留在
原地等關閉，人事任命選完回上一層迴圈），而流程對應到哪一個
hide／show 呼叫點還沒逐一追（§6）。

⚠ **旗標是 0 時移動游標也不會讓它出現。** A 組最終狀態下
`move:200,120`／`move:200,112`／`move:320,240` 各拍一張，
與不動的那張 **0 px**。所以不是「等下一次重畫」，是真的關掉了。

## 5. 對 remake 的意義

**先前的作法是「除了地圖選點以外不自繪游標」**，理由是規則沒解、
自繪會讓已經 0 px 的那幾張變差。現在規則解了一半：
**該不該畫是可觀測的**，所以對拍時不必再猜——
`ipeek:20100:1` 就是答案。

還沒解的是「remake 這一側要把 hide／show 接在哪」：
54 個呼叫點要逐一對應到 remake 的繪圖流程，才會與原版同步。
在那之前，**對拍紀錄要標明那一張的旗標值**，殘差才分得出
「remake 少畫了游標」與「原版根本沒畫」。
