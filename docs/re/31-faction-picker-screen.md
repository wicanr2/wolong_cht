# 31 — 勢力一覽：22 格的兩欄版面與領地重繪

**狀態：版面、命中判定、顏色規則、兩個守門條件與四組介面字串 confirmed。
選中後重畫 192 個據點的那一支（`sub_15CE0`）內部未讀。**

- 日期：2026-08-14
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：IDA Pro 9.4，`tools/ida_corps_next.idc`／`tools/ida_strategy_ui.idc`
  （唯讀副本，跑完雜湊未變）；字串以 `KI.EXE` 原始 bytes 取出
- 位址空間：IDA DOS/V linear address，segment base `0x10000`；
  `cs:XXXX` 是原始程式段位址，**檔案偏移 ＝ `cs` ＋ `0x200`**

`sub_15AFC`（264 B）是 [`21`](21-function-census.md) 的 T4 清單裡**最大的一支**，
先前只有「1 個呼叫者、沒有任何文件提過」這一行結構資料。
畫面標題字串 `cs:5C04` 直接說了它是什麼：**「勢力一覽」**。

## 1. 它不是被呼叫的，是被分派的

```asm
sub_119CA:                             ; 主畫面重繪
  … 清 96 KB VRAM（rep stosw ×2，0x8000 ＋ 0x4000 words）…
  al = cs:byte_198A6 / bx = 2
loop:
  shr al, 1
  jnb → 跳過
    call cs:off_159D2[bx]              ; ← 分派
  bx += 2 / cmp bx, 0Ah / jnz loop
```

**`cs:byte_198A6` 是「哪幾塊要重畫」的位元集合**，`cs:off_159D2` 是對應的常式表。
`sub_15AD1`（勢力一覽的外層）是表裡的一筆——所以它的「呼叫者」在 IDA 看起來是
`sub_119CA`，但實際路徑是位元 → 表 → 常式。

外層很短：

```asm
sub_15AD1:
  sub_15CA4 / sub_19528
  sub_18853(cx=4)                      ; 狀態列 #4「以滑鼠的右鍵回復。」
  sub_15AFC                            ; ← 本體
  sub_18853(cx=0FFFFh)
  test cs:byte_198A6, 2 / jz → …
  sub_15E1E                            ; 重畫狀態畫面 #F
```

狀態列只掛一句「以滑鼠的右鍵回復。」——**這個畫面沒有取消按鈕，
右鍵是唯一的退出路徑**。

## 2. 版面：22 格分兩欄

```asm
al = 0
loop:
  ah = 90h                             ; 一般
  cmp al, cs:byte_10CFF / jnz → ah = 9Ah    ; 玩家自己
  cmp al, cs:byte_198A7 / jnz → ah = 93h    ; 目前選中
  sub_15C14                            ; 畫這一列
  inc al / cmp al, 16h / jb loop       ; 0 … 0x15
```

- **22 列**（`0x16`），與勢力表 22 筆一致。
- `ah` 是 [`28`](28-text-number-rendering.md) §2.1 那種「背景 4 位︰前景 4 位」的屬性：

  | 屬性 | 意義 |
  |---|---|
  | `0x90` | 一般（背景 9、前景 0）|
  | `0x9A` | **玩家自己的勢力**（前景 A，與數值警示同一個換色手法）|
  | `0x93` | **目前選中的勢力** |

- **`cs:byte_198A7` ＝ 目前選中的勢力編號，`0xFF` ＝ 未選**（§3.2）。
  `cs:byte_10CFF` 是玩家勢力編號，已由
  [`../formats/08`](../formats/08-sinario-save.md) 定案。

### 2.1 兩欄是兩個獨立來源各說一次

命中判定（`sub_15AFC`）從座標反推列號：

```asm
sub_1E453                              ; 熱區編號 → al；cx/dx ＝ 座標
cmp al, 20h / jnz → 忽略               ; 整張清單只有一個熱區 0x20
sub dx, 0D8h                           ; 扣掉清單頂端
cmp cx, 240h / jb → add dx, 0B0h       ; 右欄：y 再加 0xB0（＝ 11 列）
dx >>= 4                               ; 每列 16 像素 → 勢力編號
```

畫列（`sub_15C14`）從列號算座標，方向相反：

```asm
dx = 20Ch                              ; 左欄 x
cmp bl, 0Bh / jb →
  dx = 244h                            ; 右欄 x
  bx -= 0Bh
bx = 列號 × 16 + 0D8h                  ; y
```

**`0xB0 ÷ 16 = 11` 與 `cmp bl, 0Bh` 是同一個數字**，一個從像素來、一個直接寫在
比較裡——左欄 11 列、右欄 11 列，合起來 22。列高 16 像素正好是一個全形字高
（[`29`](29-font-service-int15.md) §4.3）。

### 2.2 兩個守門條件

```asm
cmp byte ptr [si], 80h / jb → 忽略     ; 勢力不存在
cmp al, cs:byte_10CFF / jz → 忽略      ; 不能選自己
```

- 勢力存在旗標是 `+0x00 ≥ 0x80`，與
  [`../formats/08`](../formats/08-sinario-save.md) 一致——
  **不是拿君主欄當哨兵**，那條路會把在野武將誤認成君主。
- **點自己的勢力沒有反應**，不是報錯也不是提示。

選中時只動兩列：

```asm
sub_15C14(al=舊的 byte_198A7, ah=90h)  ; 舊的還原成一般色
cs:byte_198A7 = al
sub_15C14(al=新的,         ah=93h)     ; 新的畫成選中色
sub_15DBB                              ; 上方兩個勢力名（§3.2）
sub_15CC6                              ; ← 重畫 192 個據點（§3.1）
```

**只重畫兩列，不重畫整張清單。** remake 整張重畫不會有視覺差異，
但要知道原版沒有全畫面刷新。

## 3. 選一個勢力會發生什麼

### 3.1 `sub_15CC6`：整張地圖的 192 個據點重畫

```asm
ds = cs:word_10D52
si = 840h / cx = 0C0h                  ; 據點表基址、192 筆
loop:
  sub_15CE0
  si += 20h                            ; 記錄 32 B
loop
```

**所以「勢力一覽」不只是一張清單，它同時是領地圖**——
選中一個勢力，地圖上 192 個據點會照新的選擇重畫一次。
`sub_15CE0`（57 B）畫單一據點，內部未讀（§5）。

### 3.2 `sub_15DBB`：上方並排兩個勢力名

```asm
si = cs:word_10CFD                     ; 玩家勢力記錄
sub_188B0(dx=1E0h, bx=0A8h, ah=0AFh)   ; 畫名稱，屬性 AF
ah = cs:byte_198A7
cmp ah, 0FFh / jz → 未選
  si = 選中的勢力記錄
  sub_188B0(dx=240h, bx=0A8h, ah=3Fh)  ; 屬性 3F
  jmp end
未選:
  si = 0 / loop 三次（si += 10h，到 30h）:
    loc_1F75E(cx=0A140h, ax=3301h, dx=240h+si, bx=0A8h)
```

- **`byte_198A7 == 0xFF` ＝ 未選**。這是這一欄的哨兵值。
- 未選時畫的是 **`0xA140` ＝ Big5 全形空白，連畫三個**——
  與 [`28`](28-text-number-rendering.md) §3「名稱欄固定三個全形字」對得上，
  **原版用三個空白字元填欄位，不是不畫**。
- 左邊固定是玩家自己（屬性 `0xAF`），右邊是選中的（`0x3F`）。

## 4. 四組介面字串

`cs` 段位址加 `0x200` 就是 `KI.EXE` 的檔案偏移，直接取出來：

| 位址 | 內容 | 用在 |
|---|---|---|
| `cs:5C04` | **「勢力一覽」** | 畫面標題（`sub_15AFC` 開場的 `sub_106F5`）|
| `cs:5C0D` | **「－－－」** | 勢力不存在時該列顯示的內容（`sub_15C14`）|

`sub_15C14` 的分流因此很明確：**存在的勢力畫名字，不存在的畫三個破折號**，
兩者都佔滿同一格，所以版面不會因為勢力滅亡而塌掉。

（另外兩組 `cs:7DF5`／`cs:7E19` 屬於據點詳情欄，見
[`32`](32-strategy-detail-panels.md) §2。）
