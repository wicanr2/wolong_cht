## 1. 為什麼這一塊之前沒被看見

玩家扮演軍師，唯一能做的事就是進言。這些進言的**判定式**早就解完了——
`docs/mechanics/70-ai.md` §1225 起逐條寫著敵對提案、停戰提案、請求協助的
理由條件與反應碼。

沒解的是**骨架**：玩家怎麼走到那些進言。`sub_161CA`（指令列分派器）、
`sub_18853`（狀態列提示）、`sub_1716D`（選軍團）在此之前
全專案沒有任何一處提過，八個頂層指令有七個也沒有。

[`21-function-census.md`](21-function-census.md) 的全量普查才讓這個形狀顯出來：
月結／經濟／AI 模組 96 支函式有 72 支未觸及。**葉節點解了，走到葉節點的路沒解。**

## 2. 輸入模型：滑鼠熱區，不是鍵盤

戰略層的每一個分派點都是同一個三步：

```
sub_121E7          等待按鍵；CF=1 代表右鍵（取消）
sub_1E453(cx,dx)   以游標像素座標查熱區圖，回傳 al = 熱區編號
sub al, <base>     減掉該畫面的熱區基底，得到索引，再查跳表
```

`sub_1E453` 在 [`13-pc98-numeric-window.md`](13-pc98-numeric-window.md) §3 已記錄為
「回讀點擊格的 byte」。這裡補上它的定址式（`0001E453`–`0001E478`）：

```asm
shr cx, 1 / shr cx, 1 / shr cx, 1   ; cx = x >> 3
and dl, 0F8h                        ; dl = y & 0xF8
shl dx, 1        / add cx, dx       ; cx += 2 × (y & 0xF8)
shl dx, 1 / shl dx, 1 / add cx, dx  ; cx += 8 × (y & 0xF8)
mov bx, cx / add bx, cs:word_1E47B
mov al, [bx]                        ; ds = cs:word_1E479
```

合起來是 `offset = (x >> 3) + 10 × (y & 0xF8)`。y 每加 8 位移就加 80 →
**每列 80 個 byte、每個 byte 管一格 8×8 像素**。80 格 × 8 = 640 像素寬，
50 列 × 8 = 400 像素高，全圖 4,000 bytes。這是 DOS/V 的 640×400，
由定址式獨立推出，不靠畫面觀察。

熱區圖的段與偏移由 `sub_1E3C0` 在 `0001E3C3`／`0001E3C8` 寫入
（`word_1E479` ← `es`、`word_1E47B` ← `di`），另有 `sub_1E3D7`、`sub_1E41B`
兩支寫入端。**`sub_1E41B` 目前沒有任何文件提過**，熱區怎麼登記還沒讀。

`sub_121E7`（`000121E7`）以 `sub_20000(ax=5, bx=1)` 查右鍵、`(ax=5, bx=0)` 查左鍵，
兩者皆無就迴圈等待，左鍵按下時再 `sub_20000(ax=3)` 後 `clc` 返回；
右鍵則 `stc`。這解釋了 `KI.EXE` 的 `ERROR: Mouse driver not install ?`——
**戰略層沒有鍵盤路徑，沒有滑鼠就無法分派任何指令**。

> ⚠ 呼叫端的 `sub al, 20h`／`sub al, 3Dh` 看起來像 ASCII 鍵碼（空白、`=`），
> 而 remake 的鍵盤操作恰好也用 `A`／`M`／`=`。那是巧合：`al` 來自熱區圖，
> 不是鍵盤。**不要拿這些減數當按鍵對照表。**

## 3. 指令列：八個槽位

`sub_161CA`（`000161CA`）由 `sub_119CA` 經 `off_159D2[13]` 呼叫，
輸入 `cx` 是游標的像素 x：

```asm
mov ax, cx / sub ax, 18h / jb  locret   ; x < 24 → 不在列上
cmp ax, 180h            / jnb locret    ; x ≥ 408 → 不在列上
mov cl, 30h / div cl / xor ah, ah       ; 索引 = (x − 24) ÷ 48
...
mov bx, 28h / mov si, 30h / mov di, 10h ; 寬 40、間距 48、高 16
shl ax, 1 / mov bx, ax
call cs:funcs_161FE[bx]
```

`(x − 0x18) < 0x180` 除以 `0x30` → 索引只可能是 **0..7**。
表 `funcs_161FE`（`00016214`）的第 9 筆起落在別的函式中段，
與邊界檢查一致：**表就是 8 筆**，不必猜長度。

幾何：八個按鈕，第 n 個的 x = `24 + 48n`，寬 40、高 16，涵蓋 x 24–408。

### 3.1 進言（#0）

```asm
call sub_187FF
cmp  byte ptr [bx+4257h], 0
jnz  → mov al, 93h / mov cx, 40h / call sub_18810   ; 前置條件不成立
mov  ax, 5 / mov cx, 4Dh / mov dx, 400h / call sub_193E9
```

與 `[bx+4257h]`（君主是否在出征）這個判斷條件正好對上。

### 3.3 軍團（#4）

```asm
mov ax, 2 / mov cx, 4Fh / mov dx, 40Ch / call sub_193E9
al = 0 → 位置確認：sub_18853(cx=16h) → sub_1716D → sub_12151
al = 1 → 行軍指示：sub_18853(cx=2)   → sub_1716D → sub_17F90
```

- TALK #22「將游標移動至軍團的現在位置。」
- TALK #2「請選擇進行行軍指示之軍團。」

位置確認的鏡頭移動是：

```asm
mov ds, cs:word_10D52
mov dx, [bx+10h]      ; 軍團記錄 +0x10 = X
mov bx, [bx+12h]      ; 軍團記錄 +0x12 = Y
mov ax, 14h / mov cx, 0Ch
call sub_12151
```

`sub_1716D` 回傳 `bx` = 選中的軍團記錄位址，CF=1 為取消。
軍團記錄 **+0x10 / +0x12 是 X / Y**，與 `sub_12151` 的參數對上。

> `sub_12151` 的 `cx=0Ch` **不是** TALK 索引。同一輪先把它讀成訊息 #12
> 「要派遣外交官到哪個勢力？」，語意完全不合——`cx` 是 `sub_12151` 的參數，
> 只有 `sub_18853` 與 `sub_18810` 的 `cx` 才是 TALK 索引。
> 判斷一個暫存器是什麼，要看被呼叫的那一支，不能看數值像什麼。

## 4. 兩支配套常式

### `sub_18853(cx)` — 狀態列提示

`00018853`，48 bytes，**48 個呼叫點全部落在指令 handler 內**，
是這一層最密集的共用常式。

```asm
mov al, 93h / mov dx, 0 / mov bx, 12h
xor al, al
cmp cx, 0FFFFh / jz → al 保持 0        ; 清除
mov al, 1Eh                            ; 顯示
mov cx, 510h / call sub_189A4
```

`cx` 是 TALK 訊息索引，`cx = 0xFFFF` 清除提示列。
每個 handler 進入時設提示、離開時以 `0xFFFF` 清掉，成對出現。

### `sub_193E9(ax, cx, dx)` — 彈出選單

`000193E9`，32 bytes。`dx` 的高低位元組先與 `byte_19441`／`byte_19443`
交換，呼叫內層 `loc_19409` 後再寫回——也就是 `dx` 是**位置**，
以全域狀態暫存的方式傳入。`ax` 是項數，`cx` 是選項文字的 TALK 索引，
回傳 `al` = 選中項，CF=1 為取消。

呼叫端有 8 處：`sub_11F0E`、`sub_13B7E`、指令列的四個 handler、`sub_1804E`，
以及 `000160BD`——**最後這個位址沒有函式邊界**，IDA 在該區沒有建出函式，
所以它只有位址沒有符號名。這不代表位址是錯的（`000160BA` 確實參考它），
只代表引用時要寫位址不能寫 `sub_` 名。
