## 1. 決定性的兩行

INT 61h 的初始化 command（`0x10141`）在設完中斷之後做這件事：

```asm
00010154  mov dx, [097Ch]      ; 基底埠 0x220
00010158  add dx, 2            ; ⭐ 0x222 ＝ 第二組暫存器
0001015B  mov ax, 105h         ; 索引 05、值 01
0001015E  call 10890h          ; ⭐ 寫 reg 0x105 ＝ 1
00010161  mov ax, 3F04h        ; 索引 04、值 3F
00010164  call 10890h          ; ⭐ 寫 reg 0x104 ＝ 0x3F
```

`0x105` 是 **OPL3 的 NEW 位元**（不設就退化成 OPL2 相容模式），
`0x104` 是 **4-operator 連接遮罩**，`0x3F` ＝ 六對通道**全部**打開。
這兩個暫存器在 OPL2（YM3812）根本不存在。

**六這個數字對上六個聲軌**，而 OPL3 的 4-op 通道上限正好是六。

### 為什麼不是「兩顆 OPL2」

Sound Blaster Pro 的雙 OPL2 也是 `0x220` ＋ `0x222` 兩組埠，光看埠分不出來。
分得出來的是這三件事：

| 證據 | 位址 | OPL2 解釋得通嗎 |
|---|---|---|
| 寫 reg `0x104`／`0x105` | `0x10154` | ❌ 這兩個暫存器不存在 |
| 一軌寫四個 operator：`0x40`／`0x43`／`0x48`／`0x4B` ＋ 偏移 | `0x1053E` | ❌ 那是通道 `n` 與 `n+3` 的四個 operator，OPL2 沒有把它們串起來的機制 |
| 載波遮罩表 `0AD0` 前的 `0A4Eh` ＝ `08 0A 09 0D` | `0x10649` | ❌ 這四個值正好是 OPL3 四種 4-op 連接型態的載波集合 |

第三條最硬。表的索引是兩個通道的 CNT 位元拼起來，查出來的遮罩是：

| CNT1 CNT2 | 遮罩 | 載波 |
|---|---|---|
| 0 0 | `08` | op4 |
| 0 1 | `0A` | op2、op4 |
| 1 0 | `09` | op1、op4 |
| 1 1 | `0D` | op1、op3、op4 |

**這是 OPL3 4-operator 連接的教科書內容，逐列相符。** 音量常式只對載波加衰減
（§4），所以這張表不是裝飾，錯了聲音就不對。

## 2. 通道配置

`ah` ＝ 聲軌 0–5，`ah ≥ 3` 時 `ah −= 3`、埠 `+2`（`0x106DB`、`0x1062C`、`0x1055C`）。

| 聲軌 | 埠 | 4-op 通道對 | 四個 operator 的暫存器偏移 |
|---:|---|---|---|
| 0 / 1 / 2 | `0x220` | 0＋3 / 1＋4 / 2＋5 | `+0`、`+3`、`+8`、`+0xB`（再加軌內編號）|
| 3 / 4 / 5 | `0x222` | 同上 | 同上 |

音高只寫**通道對的前一個**（`A0+n`／`B0+n`，[`56`](56-bgm-track-events.md) §3.2）——
4-op 模式下後一個通道的頻率暫存器不作用，這與規格一致。

**音效走另外兩個通道。** `0x10828` 用 `0xB6+n`／`0x50+n` 這一組，
也就是**通道 6、7、8**——正好是 4-op 沒用到的那三個 2-op 通道。
六個 4-op ＋ 三個 2-op ＝ OPL3 的全部資源，一格不剩。

## 3. 音色記錄：32 bytes

曲塊 `+0x02` 指向的表（[`23`](23-bgm-resource-format.md) §3 標「內容未解」的那張）
就是音色表，**每筆 32 bytes**，編號 × 32 ＋ 表基址（`0x10552`、`0x10620`）。

| 位移 | 寫到哪 | 內容 |
|---|---|---|
| `+0x00`–`+0x03` | `0x20` 系列 × 4 | AM／VIB／EG-type／KSR／MULT |
| `+0x04`–`+0x07` | `0x40` 系列 × 4 | KSL ＋ TL。**載波的 TL 由音量常式改寫**（§4）|
| `+0x08`–`+0x0B` | `0x60` 系列 × 4 | AR／DR |
| `+0x0C`–`+0x0F` | `0x80` 系列 × 4 | SL／RR |
| `+0x10`–`+0x13` | `0xE0` 系列 × 4 | 波形選擇 |
| `+0x14` | `0xC0+n` | 前一個通道的 feedback／connection ＋ 左右輸出位元 |
| `+0x15` | `0xC0+n+3` | 後一個通道的同一組 |
| `+0x16`–`+0x1F` | — | 驅動不讀。實測多半是 `30` 填滿 |

四個 operator 的順序是 `+0`、`+3`、`+8`、`+0xB`，由表 `0A52h` ＝ `03 05 03 00`
逐步加出來（`0x1068E`）。

`+0x14`／`+0x15` 的高位常見 `0x30` ＝ **左右聲道都開**，那兩個位元也是 OPL3 才有的。

## 4. 音量：0–15 換算成載波的 TL

控制事件把 0–15 存進這一軌的音量（[`56`](56-bgm-track-events.md) §5），
套用時（`0x1060F`）：

```
衰減 = (15 − 音量) × 4 + 全域偏移[0996h]      上限 0x3F
TL   = (音色的 TL 低 6 位 + 衰減)             上限 0x3F，KSL 兩位保留
```

**只有載波改**，調變器直接寫音色原值——這是 FM 合成的正確做法
（改調變器會變音色不是變音量）。

## 5. 時間基準

TSR 掛 INT 8 時重設 PIT（`0x108D7`）：

```asm
mov al, 36h / out 43h, al      ; counter 0、mode 3
mov ax, 100h / out 40h ×2      ; ⭐ divisor ＝ 256
```

所以中斷頻率 ＝ 1,193,182 ÷ 256 ＝ **4,661.65 Hz**。

播放不是每次中斷都走一步：ISR（`0x10913`）用一個分頻計數器，
歸零才呼叫音樂 tick，重載值由速度控制事件算出（`0x10959`）：

```
分頻 N = (255 − 速度參數) × 11 ÷ 8
每秒 tick 數 = 4661.65 ÷ N
```

實測值 160–229 → 35.9–133.2 tick/s。搭配長度表的 192 tick ＝ 全音符
（[`56`](56-bgm-track-events.md) §3.1），速度 184 那一檔的四分音符正好 1.0 秒。

⚠ 同一個 ISR 還會每 16 次呼叫原本的 INT 8 handler（`0x10930`），
**這讓 BIOS 的時鐘變快**。remake 不受影響，但拿 DOSBox 當 oracle 時要記得。

## 6. `SOUND.DAT` ＝ 19 筆 16 bytes 的音效

`0x10828` 讀的記錄，編號 × 16 ＋ 基址。dosv 的 `SOUND.DAT` 是 304 B ＝ **19 × 16**，
整除且無餘。

| 位移 | 寫到哪 | 內容 |
|---|---|---|
| `+0x00`–`+0x07` | `0x20`／`0x40`／`0x60`／`0x80` 各一對 | 兩個 operator 的參數 |
| `+0x08`／`+0x09` | `0xE0` 一對 | 波形 |
| `+0x0A` | `0xC0+n` | feedback／connection |
| `+0x0B`／`+0x0C` | `A0+n`／`B0+n` | 音高：F-Number ＋ block ＋ key-on |
| `+0x0D` | — | **接續播放的音效編號** |
| `+0x0E` | — | 接續前要等幾個 tick |
| `+0x0F` | — | 未用 |

`+0x0D`／`+0x0E` 由 `0x107CF` 每 tick 遞減後觸發，所以一個「音效」可以是一串。
**記錄 #0 是靜音哨兵**（TL ＝ `3F 3F`、RR ＝ `F0`），鏈結指到 0 就是結束；
`0xFF` 才表示「沒有掛任何音效」（`0x107CF` 的 `cmp … 0FFh`）。

實測 #3 → #13 → #0、#7 → #16 → #0，鏈都收得回來。

## 7. 拿真實資料驗

`tools/bgmdump.py` 對兩版全部 26 首曲子（含 `OPEN`／`END`／`OVERBGM.DAT`）：

**每一首用到的音色編號集合都正好是 `0 … N−1`，N ＝ 該曲音色表的筆數，
一次都沒有超出。** 記錄大小若猜錯（16 或 64），筆數就會對不上——
這是「32 bytes 一筆」的獨立檢查，不需要合成出聲音就能做。

⚠ **pc98 也整除，但不能據此說 PC-98 也是這個版面。** 那一版是 YM2203，
容器與事件編碼共用（同一份原始碼的兩次編譯），音色記錄的**內容**必然不同。
兩版同一首曲子的音色筆數也不一樣（例如第 3 曲 dosv 3 筆、pc98 8 筆）。
