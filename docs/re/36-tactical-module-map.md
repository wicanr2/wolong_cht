## 4. 兩棵獨立的樹（無直接呼叫者的根）

`sub_1A6FA`（90 B）與 `sub_1ADC8`（142 B）都沒有直接呼叫者，
卻各自帶著一大叢——**它們是被取址後間接呼叫的**
（[`21`](21-function-census.md) §6 講的那種形狀）。

### 4.1 `sub_1A6FA` 這一棵：對稱的雙方處理

```
sub_1A6FA → sub_1A754 ┐
          → sub_1A785 ┘ 兩支各 ~50 B，呼叫完全相同的五支
                        sub_1A7B7 / sub_1A7FD / sub_1A83F / sub_1A85B
```

**兩支入口、共用五支處理常式**——這是「我方／敵方各跑一次」的形狀。
`sub_1A7B7` 再分派給九支（`sub_1A92E` … `sub_1AA10`），
其中兩支的尾巴掛著 `nullsub_6`／`nullsub_7`（各 1 B）。

再下一層 `sub_1AB7C`／`sub_1AB9C`／`sub_1ABB2` 三支共用
`sub_1ABD2`／`sub_1ABFF`／`sub_1AC55`，而 `sub_1ACD6` 又分派給
四支各 9 B 的常式（`sub_1AD09`／`sub_1AD12`／`sub_1AD1B`／`sub_1AD24`）——
`sub_1ACD6` 的 `call cs:funcs_1ACF6[di]` 是 [`21`](21-function-census.md) §7
列的間接分派之一，**這四支 9 B 的常式就是它的目標**。

### 4.2 `sub_1ADC8` 這一棵：單位更新

```
sub_1ADC8 → sub_1AE56 / sub_1AEA9 / sub_1AED2(147) / sub_1AF69(164)
                                     / sub_1B240(288) / sub_1B360 / sub_1B413(165)
```

`sub_1B240` 是**整個模組最大的函式**（288 B）。
`sub_1AF69` 底下再掛六支（`sub_1B047` … `sub_1B116`），

`sub_1B618`／`sub_1B6BC`／`sub_1B732`／`sub_1B799` 四支也沒有直接呼叫者，
前兩支帶亂數——同樣是間接分派的目標。

## 6. 葉節點逐行讀完的部分

模組裡 37 支葉節點：**19 支是腳本 VM 的 opcode**（[`11`](11-tactical-battle.md) §3.5），
其餘 18 支分成四類。

### 6.1 自我修改碼的入口（`sub_1A04B`）

26 B，八個呼叫點。它只做一件事：push 全部暫存器 → `ds = cs` → `call loc_1A065`
→ pop 全部。`loc_1A065` 正是 [`20`](20-ida-re-coverage-audit.md) §2.2 記的
**每輪改寫自己的那一段**。所以這支是它的安全包裝——**呼叫端不必知道
被呼叫的程式碼會變**。

### 6.2 單位狀態（`sub_1A988`／`sub_1A9D0`／`sub_1A9FB`）

`si` 是單位記錄。

| 函式 | B | 動作 |
|---|---:|---|
| `sub_1A988` | 20 | `al == ah` 就直接走收尾；否則先 `sub_1A8DE(al=3)` ＋ `sub_1A8CC` 再收尾 |
| `sub_1A9D0` | 43 | `or byte [si], 8`（狀態位元 3）；`[si+1Ah] != ah` 時寫 `[si+1Bh] = ah`。`al == 5` 直接跳過整段 |
| `sub_1A9FB` | 21 | **重設**：`[si+10h] = [si+11h] = 0x20`、`[si+12h] = 0`、`[si+14h] = 0x2020`、`[si+1Bh] = 0x0A` |

`sub_1A9FB` 把 `0x20` 寫進三個位置——**`0x20` 是這一層的「中立／靜止」值**。

### 6.3 移動與地形（`sub_1B08B`／`sub_1B0AF`／`sub_1B15D`／`sub_1B186`）

前兩支結構完全相同，只差一個立即值：

```asm
bx = [si+0Ch] / byte [si+5] = 1        ; sub_1B08B
bx = [si+0Ch] / byte [si+5] = 3        ; sub_1B0AF
… 兩者接著都 call sub_1B1B1 …
```

**`[si+05]` 是朝向或動作編號**，`1` 與 `3` 是它的兩個值——
與軍團 `+0x08` 的「0／1 ＝ X 減增、2／3 ＝ Y 減增」同一種編碼。

後兩支也是一對，只差 `es:[bx]` 與 `es:[bx+1000h]`——**同一張地圖的兩層**：

```asm
and byte [si+2], 0F7h                  ; 清狀態位元 3
al = es:[bx]                           ; 或 es:[bx+1000h]
test al, 7Fh / jnz → 回傳 al & 7Fh     ; 有東西擋著
ds = cs:word_1D2F6 / di = bx & 0FFFh   ; ← 換到另一張表，位址取低 12 位
dl = [di]
cmp dl, 0F8h / jb → 回傳 0             ; 地形值 ≥ 0xF8 才擋
```

**地圖每層 `0x1000` bytes（4,096 格）**，而 `and di, 0FFFh` 把位址折回同一層——
所以兩層是**同尺寸疊在一起**的。`0xF8` 是地形的通行門檻。

### 6.4 戰術畫面的小常式（其餘 11 支）

`sub_1C300`（13 B）／`sub_1C30D`（8 B）／`sub_1C39C`（28 B）／`sub_1C3B8`（56 B）／
`sub_1C3F0`（15 B）／`sub_1C4A6`（44 B）／`sub_1C4D2`（40 B）／`sub_1C577`（55 B）／
`sub_1C5AE`（41 B）／`sub_1C74C`（41 B）／`sub_1C775`／`sub_1C78E`／`sub_1CAD1`／
`sub_1D7E7`／`sub_1BF4D`／`sub_1BF70`／`sub_1BF97`／`nullsub_3`。

共同形狀是「設幾何 → 呼叫 `sub_1D9D1`（`ah` ＝ 0 擦／1 畫）→ 註冊熱區
（`sub_1E3D7`／`sub_1E41B`）」：

```asm
sub_1C3F0:  cx = 510h / ah = 1 / call sub_1D9D1     ; 畫
sub_1C39C:  cx = 510h / ah = 0 / call sub_1D9D1     ; 擦 → 再 call sub_1075B 繪訊息
```

`sub_1C3B8` 寫 `cs:[bx-2CDEh] = 0FFFFh` 並讀 `cs:[bx-3C68h]`——
**兩個以 `bx` 為索引的 `cs` 陣列**，`bx` 來自 `cl`。
`sub_1C4A6` 把 `cs:word_1D326` 設成 `0FFFFh` 之後畫一個 `0x40E` 的框、
註冊熱區 `0x1D`——與 `sub_1C407`（[`36`](36-tactical-module-map.md) §3）的熱區相同。

`sub_1C315`（131 B，11 個呼叫點）是這一層被呼叫最多的：碰**武將與軍團兩張表**、
寫熱區，並呼叫 `sub_1C39C`。
