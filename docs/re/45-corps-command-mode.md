# 45 — 軍團的三種指令模式：戰鬥指揮／委任／解體

**狀態：軍團 `+0x00` 位元 2 定案 ＝ **「委任」**（交給電腦指揮）。
`+0x23 = 11` ＝ 待解體。求援只調得動委任中的軍團——
**玩家自己指揮的軍團不會被 AI 搶走**。**

## 1. `sub_17FDB`：玩家對自己的軍團下指令

```asm
cx = 3 / sub_18853              ; #3「請指示行軍目標之據點。」
sub_1703C                       ; 選據點；CF=1 → 取消
[bp+0] = 目標據點編號
cx = 15h / sub_18853            ; #21「向{2}移動下。請下達戰鬥指示。」
bx = [si+1] × 64                ; 所屬勢力記錄
al = 2
cmp [bx+3], [bp+0] / jnz +2     ; 勢力 +0x03 ＝ 首都
  al = 3                        ; ← 目標是首都才有第三項
sub_1804E                       ; 選單；CF=1 → 回去重選目標
al == 0 → and byte [si], 0FBh / [si+23h] = 0
al == 1 → or  byte [si], 4     / [si+23h] = 0
al >= 2 →                        [si+23h] = 0Bh
[si+0Bh] = 1                    ; 計時器 ＝ 1，下一個 tick 就動
[si+20h] = 目標據點編號
```

`sub_1804E` 只是把 `cx = 4Ch` 交給選單常式 `sub_193E9`，
`al` 是項目數（2 或 3），回傳選中的索引。

## 2. 選單就在 `TALK.DAT` #76

```
#76  「　戰鬥指揮　」「　委　　任　」「　解　　體　」
```

三項與三條分支一一對上：

| 選項 | 分支 | 效果 |
|---|---|---|
| 0 **戰鬥指揮** | `and [si], 0FBh` | **清**位元 2，`+0x23 = 0` |
| 1 **委任** | `or [si], 4` | **設**位元 2，`+0x23 = 0` |
| 2 **解體** | — | `+0x23 = 0x0B`（11），位元 2 不動 |

**「解體」只在目標是首都時才出現**（`cmp [bx+3], [bp+0]`）——
解散要把兵還回預備兵池，而池子在首都。

## 3. 位元 2 ＝ 委任，而求援只調委任中的軍團

`sub_14155`（[`40`](40-garrison-relief-request.md) §5）派援軍時的兩道濾網：

```asm
test byte [di], 4 / jz → 下一支         ; ← 必須是委任中
cmp byte [di+23h], 8 / jnb → 下一支     ; ← 解體待處理（11）調不動
```

合起來就是一條清楚的遊戲規則：

> **玩家點名自己指揮的軍團，不會被 AI 的求援調度搶走。**
> 交給電腦（委任）的才會被調去救援，而正在等解體的也不會被調走。

三個設定端因此各有道理：

| 函式 | 動作 | 為什麼 |
|---|---|---|
| `sub_16E8F`（58 B，全讀）| `sub_16EC9` 建記錄 → `sub_16F26` 填欄位 → `sub_1461D` → `sub_16FD2` 算間隔 → `or [si], 4` | AI 自己編的軍團**預設是委任** |
| `sub_17FDB` | 先清後設 | 玩家在選單上選什麼就是什麼 |
| `sub_1699E` | 編完立刻 `and [di], 0FBh` | **君主親征那一支不是委任**——請得動君主出陣，就不該再被別的據點調走 |

`sub_1699E` 順帶印證了 `docs/mechanics/70-ai.md` §1.2 的兩道閘：
`0x0F − [si+28h]`（15 − 好戰等級）× 4 與 `[si+21h]`（資金 >> 8）比、
三種預備兵 `[si+4] + [si+6] + [si+8]` 與 `0x258`（600）比。

## 4. remake 的接線

`Corps.Delegated`（`+0x00` 位元 2）與 `Corps.Stage`（`+0x23`）進了記錄的
載入與寫回，`dispatchGarrison` 兩道濾網照抄。AI 編成的軍團預設 `Delegated = true`。
