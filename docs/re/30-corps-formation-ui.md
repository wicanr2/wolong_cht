# 30 — 軍團編成畫面：兵員池、兵種切換與派生數值

**狀態：編成畫面的主迴圈與三支被它呼叫的常式 confirmed。
兵員池的搬運方向、兵種切換的循環、確定的前提條件與移動間隔的公式都定案。
軍團 `+0x09` 的用途是假說（§6）。**

- 日期：2026-08-13
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：IDA Pro 9.4，`tools/ida_corps_formation.idc`（唯讀副本，跑完雜湊未變）
- 位址空間：IDA DOS/V linear address，segment base `0x10000`

`sub_16C92`（196 B）是 [`21`](21-function-census.md) 量出來的未讀函式之一，
在「月結、經濟、AI」區裡排第三大。它其實是**軍團編成畫面的主迴圈**——
狀態列掛 TALK #1「請下達各部隊編成之指示。」，完成時走
`cx=0x19B` 的八變體「編成完成」（[`25`](25-message-variants-and-personnel.md) §1.2）。

## 1. 進入與退出

```asm
sub_16C5E:                     ; 由 sub_16288（指令列「編成」）進入
  sub_12078                    ; 游標狀態保存
loop:
  sub_18853(cx=0)              ; 狀態列 #0
  sub_17663                    ; 武將一覽選一位 → bx；CF=1 離開
  jb → 退出
  sub_16C92                    ; ← 編成畫面
  sub_15E80(al=8)              ; 重畫狀態畫面 #8
  jmp loop
退出:
  sub_120D6 / sub_18853(cx=0FFFFh)
```

**選武將 → 編成 → 回到選武將**，一次一支軍團。
`sub_17663` 是武將一覽的選取（[`26`](26-list-window-engine.md) §4），
與人事任命用的是同一支。

## 2. 從武將記錄走到軍團記錄

`sub_16C92` 進來時 `bx` 是武將記錄位址，第一件事是換算成軍團記錄：

```asm
si = bx
si -= 4240h                    ; 武將表基址
si <<= 1
si += 2240h                    ; 軍團表基址
```

武將 32 B、軍團 64 B，所以「位移 ×2」就是同索引平行——
**軍團編號 ＝ 主將的武將編號**，與
[`../formats/08-sinario-save.md`](../formats/08-sinario-save.md) 由 `sub_1291A`
得到的換算式互為逆運算。這是第二個獨立來源。

接著：

```asm
al = [bx+1Ch] / [si+1] = al    ; 軍團所屬勢力 ← 武將所屬勢力
ah = [bx+1Ch] / al = 0
ax >>= 2                       ; ax = 勢力編號 × 64
di = ax + 4                    ; ← di 指向該勢力的預備兵三欄
```

`di` 在整個畫面期間就是**這個勢力的預備兵池**：
勢力記錄 `+0x04`／`+0x06`／`+0x08` 三個 u16
（[`../formats/08`](../formats/08-sinario-save.md) §勢力表）。

## 3. 主迴圈：熱區與兵種循環

```asm
draw:
  sub_16DFD                    ; 畫框與六個槽的熱區
  sub_16FD2                    ; 重算派生數值（§5）
  sub_16D6F / sub_16DA8        ; 印數字
  sub_101DB
  sub_121E7                    ; 等待；CF=1 ＝ 右鍵取消
  jb → 取消
  sub_1E453                    ; 讀熱區編號 → al
  sub al, 3Eh
  jb  → draw                   ; 熱區 < 0x3E：不是這個畫面的按鈕
  cmp al, 6
  jz  → 確定                    ; 熱區 0x44
  ; 熱區 0x3E–0x43 ＝ 六個部隊槽
  sub_14717                    ; ← 先把六槽兵員全退回池（§4）
  bl = al / bh = 0 / bx <<= 2  ; bx = 槽索引 × 4
  al = [bx+si+2Ah]             ; 槽的 +2 ＝ 兵種
  inc al
  cmp al, 4 / jb → 保留
  al = 1                       ; 4 → 1，循環
  [bx+si+2Ah] = al
  sub_14698
  jmp draw
```

三件事定案：

1. **熱區 `0x3E`–`0x43` 是六個部隊槽，`0x44` 是確定。**
   槽的排列順序就是主將／前鋒／左翼／右翼／左備／右備
   （[`../mechanics/20-military.md`](../mechanics/20-military.md)）。
2. **點一下槽只做一件事：兵種 +1，`1 → 2 → 3 → 1` 循環。**
   兵種編碼 `1` 騎馬／`2` 弓兵／`3` 步兵在
   [`../formats/08`](../formats/08-sinario-save.md) 已由戰力計算定案，
   這裡是第二個來源——**而且說明了原版沒有兵種選單，只有循環切換**。
3. `[bx+si+2Ah]` ＝ 槽 `0x28 + 4k` 的 `+2`，六個槽正好排到 `+0x3E`。

### 3.1 確定的前提：主將槽必須有兵

```asm
確定:
  cmp byte [si+29h], 0
  jnz → 成立
  sub_18810(cx=3Eh)            ; #62「大將的部隊的兵員不足啊。」
  jmp draw
成立:
  sub_16F26                    ; 實際編成
  di -= 4
  bx = (si − 2240h) >> 1       ; → 武將位移
  sub_18810(cx=19Bh, ah=[bx+425Eh], al=[bx+4241h])   ; 八變體「編成完成」
```

`[si+0x29]` ＝ 槽 0 的 `+1` ＝ **主將槽的兵力**。
**六個槽裡只有主將槽被檢查**——其餘五個可以是空的。

## 4. `sub_14717`：把六槽的兵員退回預備兵池

51 B，四個呼叫者（`sub_1461D`、`sub_14651`、`sub_16C92` ×2）。
**它保留所有暫存器**（開頭 `push ax`、結尾 `pop ax`），
所以呼叫端後面那句 `mov bl, al` 用的是呼叫前的 `al`，不是回傳值。

```asm
cx = 6 / bh = 0 / si += 28h    ; 走六個槽
loop:
  bl = [si+2]                  ; 兵種
  cmp bl, 4 / jz → 下一槽       ; ← 兵種 4 ＝ 空槽，跳過
  bx = (兵種 − 1) × 2          ; 0／2／4
  ax = 0
  xchg al, [si+1]              ; 取出兵力並清 0
  dx = es:[bx+di]              ; 該兵種的預備兵
  sub_155EC                    ; 相加
  es:[bx+di] = ax
  si += 4
loop
```

**這把預備兵三欄從「強證據」升級成 confirmed**，而且順序是被兵種編碼直接決定的：
`bx = (兵種−1)×2` 把 1／2／3 映到 `+0x04`／`+0x06`／`+0x08`，
所以騎馬、弓兵、步兵的排列不是猜的。

**兵種 `4` 是「空槽」**——這是新的值。切換循環永遠落在 1–3，
所以 4 只會來自初始化或解除編成，不會由玩家產生。

### 4.1 兵員的流向

| 動作 | 發生什麼 |
|---|---|
| 點任何一個槽 | **六槽兵員全部退回池**，然後該槽兵種 +1 |
| 右鍵取消 | 六槽兵員全部退回池，離開 |
| 按確定 | **不退回**，走 `sub_16F26` 把軍團建起來 |

也就是說，**兵力不是在這個畫面裡逐槽輸入的**——這一支只切兵種。
玩家改動任何一槽的兵種，整個編成的兵員都會歸零重來。
分配兵力的入口不在 `sub_16C92`，仍未定位（§7）。

## 5. `sub_16FD2`：派生數值重算

86 B，四個呼叫者。每次重畫都跑一次，也被 `sub_14499`、`sub_1474A`、
`sub_16E8F` 呼叫——所以它是「軍團內容變了就重算」的統一入口。

```asm
bx = si + 28h / ax = 0 / cx = 6      ; ch 當旗標、cl 當計數
loop:
  cmp byte [bx+2], 1 / jz →
    or ch, 1                          ; 有非騎馬的槽
  al += [bx+1] / adc ah, 0            ; 16 位累加兵力
  bx += 4 / dec cl / jnz loop
[si+4] = ax                           ; ← 總兵力
inc ch
cmp bx, 12Ch / jbe → 跳過
inc ch
[si+1Eh] = ch                         ; ← 移動間隔
```

兩個公式：

1. **軍團 `+0x04` 總兵力 ＝ 六槽 `+1` 的和**，16 位無號。
   一點 ＝ 10 人，六槽滿編 600 點 ＝ 6,000 人。
2. **軍團 `+0x1E` 移動間隔 ＝ 全騎馬 2、否則 3。**
   `+0x1E` 是「每幾 tick 走一步」，所以**純騎馬編成快 1.5 倍**。
   [`../formats/08`](../formats/08-sinario-save.md) 原本只寫「純騎馬編成較小」，
   這裡是數值。

   > `cmp bx, 12Ch` 那個分支在實務上恆真：迴圈結束時 `bx = si + 0x40`，
   > 而軍團表從 `0x2240` 起，永遠大於 `0x12C`。**所以第二個 `inc ch` 一定執行**，
   > 移動間隔只可能是 2 或 3。這個比較看起來是為某種低位址軍團準備的，
   > 但那種軍團在這份影像裡不存在——城兵用的臨時軍團在 `0x4200`，一樣大於 `0x12C`。

尾段還寫兩個欄位：

```asm
bh = [si+1] / bl = 0 / bx >>= 2      ; bx = 勢力編號 × 64
al = [bx+3Eh]                        ; 勢力 +0x3E ＝ 勢力編號
ah = al / al <<= 2 / al += ah        ; al = 勢力編號 × 5
[si+9] = al
byte [si+0Bh] = 1                    ; 移動計時器
```

## 6. 假說：軍團 `+0x09` ＝ 大地圖圖形的基底

`+0x09` 被寫成**勢力編號 × 5**，而軍團 `+0x08`（朝向）的值域正好是
**5 個**（0／1 ＝ X 減增、2／3 ＝ Y 減增、4 ＝ 靜止）。

> **假說**：`+0x09 + +0x08` 是大地圖上軍團圖形的圖塊編號，
> 每個勢力五個方向各一張。

**可證偽的預測**：某支繪圖常式會同時讀 `[si+8]` 與 `[si+9]` 並相加。
找到那一支就定案，找不到就推翻。**在找到之前不要拿它當結論**，
也不要在 remake 裡按這個假設實作。
