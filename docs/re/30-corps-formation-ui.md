# 30 — 軍團編成畫面：兵員池、兵種切換與派生數值

**狀態：編成畫面的主迴圈與被它呼叫的常式 confirmed。
兵員池的搬運方向、兵種切換的循環、兵力的自動分配、確定的前提條件、
移動間隔的公式與軍團 `+0x09` 的用途全部定案。**

- 日期：2026-08-13
- 範圍：只驗松崗 DOS/V
- 原始 `KI.EXE` SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 原始 `KI.EXE.i64` SHA-256：`7b7c1aa67c47f99062cfdd4439b3423302808c874f929c3ea6f75ec564034c26`
- 工具：IDA Pro 9.4，`tools/ida_corps_formation.idc`（唯讀副本，跑完雜湊未變）
- 位址空間：IDA DOS/V linear address，segment base `0x10000`

`sub_16C92`（196 B）是 [`21`](21-function-census.md) 量出來的未讀函式之一，
在「月結、經濟、AI」區裡排第三大。它其實是**軍團編成畫面的主迴圈**——
狀態列掛 TALK #1「請下達各部隊編成之指示。」，完成時走
`cx=0x19B` 的八變體「編成完成」（[`25`](25-message-variants-and-personnel.md) §1.2）。

## 1. 進入與退出

```asm
sub_16C5E:                     ; 由 sub_16288（指令列「編成」）進入
  sub_12078                    ; 游標狀態保存
loop:
  sub_18853(cx=0)              ; 狀態列 #0
  sub_17663                    ; 武將一覽選一位 → bx；CF=1 離開
  jb → 退出
  sub_16C92                    ; ← 編成畫面
  sub_15E80(al=8)              ; 重畫狀態畫面 #8
  jmp loop
退出:
  sub_120D6 / sub_18853(cx=0FFFFh)
```

**選武將 → 編成 → 回到選武將**，一次一支軍團。
`sub_17663` 是武將一覽的選取（[`26`](26-list-window-engine.md) §4），
與人事任命用的是同一支。

## 2. 從武將記錄走到軍團記錄

`sub_16C92` 進來時 `bx` 是武將記錄位址，第一件事是換算成軍團記錄：

```asm
si = bx
si -= 4240h                    ; 武將表基址
si <<= 1
si += 2240h                    ; 軍團表基址
```

武將 32 B、軍團 64 B，所以「位移 ×2」就是同索引平行——
**軍團編號 ＝ 主將的武將編號**，與
[`../formats/08-sinario-save.md`](../formats/08-sinario-save.md) 由 `sub_1291A`
得到的換算式互為逆運算。這是第二個獨立來源。

接著：

```asm
al = [bx+1Ch] / [si+1] = al    ; 軍團所屬勢力 ← 武將所屬勢力
ah = [bx+1Ch] / al = 0
ax >>= 2                       ; ax = 勢力編號 × 64
di = ax + 4                    ; ← di 指向該勢力的預備兵三欄
```

`di` 在整個畫面期間就是**這個勢力的預備兵池**：
勢力記錄 `+0x04`／`+0x06`／`+0x08` 三個 u16
（[`../formats/08`](../formats/08-sinario-save.md) §勢力表）。

## 3. 主迴圈：熱區與兵種循環

```asm
draw:
  sub_16DFD                    ; 畫框與六個槽的熱區
  sub_16FD2                    ; 重算派生數值（§5）
  sub_16D6F / sub_16DA8        ; 印數字
  sub_101DB
  sub_121E7                    ; 等待；CF=1 ＝ 右鍵取消
  jb → 取消
  sub_1E453                    ; 讀熱區編號 → al
  sub al, 3Eh
  jb  → draw                   ; 熱區 < 0x3E：不是這個畫面的按鈕
  cmp al, 6
  jz  → 確定                    ; 熱區 0x44
  ; 熱區 0x3E–0x43 ＝ 六個部隊槽
  sub_14717                    ; ← 先把六槽兵員全退回池（§4）
  bl = al / bh = 0 / bx <<= 2  ; bx = 槽索引 × 4
  al = [bx+si+2Ah]             ; 槽的 +2 ＝ 兵種
  inc al
  cmp al, 4 / jb → 保留
  al = 1                       ; 4 → 1，循環
  [bx+si+2Ah] = al
  sub_14698
  jmp draw
```

三件事定案：

1. **熱區 `0x3E`–`0x43` 是六個部隊槽，`0x44` 是確定。**
   槽的排列順序就是主將／前鋒／左翼／右翼／左備／右備
   （[`../mechanics/20-military.md`](../mechanics/20-military.md)）。
2. **點一下槽只做一件事：兵種 +1，`1 → 2 → 3 → 1` 循環。**
   兵種編碼 `1` 騎馬／`2` 弓兵／`3` 步兵在
   [`../formats/08`](../formats/08-sinario-save.md) 已由戰力計算定案，
   這裡是第二個來源——**而且說明了原版沒有兵種選單，只有循環切換**。
3. `[bx+si+2Ah]` ＝ 槽 `0x28 + 4k` 的 `+2`，六個槽正好排到 `+0x3E`。

### 3.1 確定的前提：主將槽必須有兵

```asm
確定:
  cmp byte [si+29h], 0
  jnz → 成立
  sub_18810(cx=3Eh)            ; #62「大將的部隊的兵員不足啊。」
  jmp draw
成立:
  sub_16F26                    ; 實際編成
  di -= 4
  bx = (si − 2240h) >> 1       ; → 武將位移
  sub_18810(cx=19Bh, ah=[bx+425Eh], al=[bx+4241h])   ; 八變體「編成完成」
```

`[si+0x29]` ＝ 槽 0 的 `+1` ＝ **主將槽的兵力**。
**六個槽裡只有主將槽被檢查**——其餘五個可以是空的。

## 4. `sub_14717`：把六槽的兵員退回預備兵池

51 B，四個呼叫者（`sub_1461D`、`sub_14651`、`sub_16C92` ×2）。
**它保留所有暫存器**（開頭 `push ax`、結尾 `pop ax`），
所以呼叫端後面那句 `mov bl, al` 用的是呼叫前的 `al`，不是回傳值。

```asm
cx = 6 / bh = 0 / si += 28h    ; 走六個槽
loop:
  bl = [si+2]                  ; 兵種
  cmp bl, 4 / jz → 下一槽       ; ← 兵種 4 ＝ 空槽，跳過
  bx = (兵種 − 1) × 2          ; 0／2／4
  ax = 0
  xchg al, [si+1]              ; 取出兵力並清 0
  dx = es:[bx+di]              ; 該兵種的預備兵
  sub_155EC                    ; 相加
  es:[bx+di] = ax
  si += 4
loop
```

**這把預備兵三欄從「強證據」升級成 confirmed**，而且順序是被兵種編碼直接決定的：
`bx = (兵種−1)×2` 把 1／2／3 映到 `+0x04`／`+0x06`／`+0x08`，
所以騎馬、弓兵、步兵的排列不是猜的。

**兵種 `4` 是「空槽」**——這是新的值。切換循環永遠落在 1–3，
所以 4 只會來自初始化或解除編成，不會由玩家產生。

### 4.1 兵員的流向

| 動作 | 發生什麼 |
|---|---|
| 點任何一個槽 | **六槽兵員全部退回池** → 該槽兵種 +1 → **`sub_14698` 重新分配** |
| 右鍵取消 | 六槽兵員全部退回池，離開 |
| 按確定 | **不退回**，走 `sub_16F26` 把軍團建起來 |

**玩家從頭到尾沒有輸入過任何兵力數字。** 改完兵種之後緊接著的 `sub_14698`
（「各兵種剩餘預備兵分配到同型槽位，每槽最多 100」，
[`07`](07-monthly-settlement.md) §AI 編成表已定案）會把池裡的兵自動攤到
同兵種的槽上。所以編成畫面的操作只有一種：**點到兵種組合對為止**。

`sub_1461D`（33 B）就是「退回 ＋ 重新分配」這一對的封裝，
AI 編成（`sub_16E8F`）走的是同一支——**玩家與 AI 的兵力分配規則相同**。

## 5. `sub_16FD2`：派生數值重算

86 B，四個呼叫者。每次重畫都跑一次，也被 `sub_14499`、`sub_1474A`、
`sub_16E8F` 呼叫——所以它是「軍團內容變了就重算」的統一入口。

```asm
bx = si + 28h / ax = 0 / cx = 6      ; ch 當旗標、cl 當計數
loop:
  cmp byte [bx+2], 1 / jz →
    or ch, 1                          ; 有非騎馬的槽
  al += [bx+1] / adc ah, 0            ; 16 位累加兵力
  bx += 4 / dec cl / jnz loop
[si+4] = ax                           ; ← 總兵力
inc ch
cmp bx, 12Ch / jbe → 跳過
inc ch
[si+1Eh] = ch                         ; ← 移動間隔
```

兩個公式：

1. **軍團 `+0x04` 總兵力 ＝ 六槽 `+1` 的和**，16 位無號。
   一點 ＝ 10 人，六槽滿編 600 點 ＝ 6,000 人。
2. **軍團 `+0x1E` 移動間隔 ＝ 全騎馬 2、否則 3。**
   `+0x1E` 是「每幾 tick 走一步」，所以**純騎馬編成快 1.5 倍**。
   [`../formats/08`](../formats/08-sinario-save.md) 原本只寫「純騎馬編成較小」，
   這裡是數值。

   > `cmp bx, 12Ch` 那個分支在實務上恆真：迴圈結束時 `bx = si + 0x40`，
   > 而軍團表從 `0x2240` 起，永遠大於 `0x12C`。**所以第二個 `inc ch` 一定執行**，
   > 移動間隔只可能是 2 或 3。這個比較看起來是為某種低位址軍團準備的，
   > 但那種軍團在這份影像裡不存在——城兵用的臨時軍團在 `0x4200`，一樣大於 `0x12C`。

尾段還寫兩個欄位：

```asm
bh = [si+1] / bl = 0 / bx >>= 2      ; bx = 勢力編號 × 64
al = [bx+3Eh]                        ; 勢力 +0x3E ＝ 勢力編號
ah = al / al <<= 2 / al += ah        ; al = 勢力編號 × 5
[si+9] = al
byte [si+0Bh] = 1                    ; 移動計時器
```

## 6. 軍團 `+0x09` ＝ 大地圖圖塊的基底（confirmed）

`+0x09` 被寫成**勢力編號 × 5**，而軍團 `+0x08`（朝向）的值域正好是
**5 個**（0／1 ＝ X 減增、2／3 ＝ Y 減增、4 ＝ 靜止）。
畫軍團的是 `sub_12B2A`（18 B，由 `sub_12AF4` 呼叫）：

```asm
mov dx, [si+10h]        ; X
mov bl, [si+12h]        ; Y
xor bh, bh
mov al, [si+9]          ; 勢力編號 × 5
add al, [si+8]          ; ＋朝向
call sub_1D4C7          ; 畫
```

**每個勢力五張圖，四個方向 ＋ 靜止**，22 個勢力共 110 張。

> 這一條的找法值得記下來。先掃「同時出現 `+8]` 與 `+9]` 的函式」，
> 結果是零——而那正是**相鄰兩欄被當成一個 word 讀走**時會有的樣子。
> 改掃「所有碰 `+9]` 的指令」才找到 `sub_12B2A`，它是分兩次讀的。
> **零命中要先問掃描條件對不對。** 而且這一輪的第一版掃描
> 根本不是零命中，是崩潰（§8）。

## 7. 順帶解出的三支

### 7.1 `sub_16F86`：把軍團放進首都那一格

由 `sub_16F26` 呼叫，`di` 是首都的據點記錄。

```asm
ax = [di+8] / bx = [di+0Ah]          ; 據點的 X、Y
cx = (di − 840h) >> 2                ; ← 據點編號 × 8
[si+0Eh] = [si+14h] = cx             ; 目前／目標：據點編號×8
[si+10h] = [si+16h] = ax             ; 目前／目標：X
[si+12h] = [si+18h] = bx             ; 目前／目標：Y
bx = Y × 24 + cs:word_19872          ; 佔用圖該列的段位址
[si+1Ah] = ax / [si+1Ch] = bx
ds = bx / inc byte [ax]              ; ← 佔用圖那一格 +1
```

- **據點表基址 `0x840`、記錄 32 B**：`(位址 − 0x840) ÷ 4` 直接得到「編號 × 8」，
  省掉一次乘法。
- `Y × 24` 是以 paragraph 計的列距——佔用圖每列 384 bytes ＝ 24 paragraph，
  與 384×256 的尺寸對得上（`word_19872`，見 `CONTEXT.md` 的推翻表）。
- **建立軍團時佔用圖就 +1**，不是等到開始移動。

### 7.2 `sub_155EC`：預備兵的飽和加法

13 B，被 `sub_14717`（退兵回池）與 `sub_153C6`（徵兵，三個兵種各一次）呼叫。

```asm
add ax, dx
jb → 飽和
cmp ax, 0FFDCh / jbe → 回傳
飽和: ax = 0FFDCh
```

**預備兵上限是 `0xFFDC` ＝ 65,500 點 ＝ 655,000 人**，不是 65,535。
進位與超過門檻兩條路都夾到同一個值，所以**不會溢位回繞**。

### 7.3 `sub_16EC9`：AI 編成的試算是在堆疊副本上做的

`CS:6C4C` 的六槽 × 三候選兵種表與 `0x32` 門檻已由
[`07`](07-monthly-settlement.md) 定案並接入 remake。這裡補一個容易寫錯的細節：

```asm
sub sp, 6 / bp = sp
cx = 3 / loop: [bp] = [bx+4]         ; ← 把勢力的預備兵三欄複製到堆疊
…
sub word [bp+di], 32h                ; ← 扣的是副本
```

**試算全程不動勢力記錄**，六槽都湊齊才回 CF=0，真正的扣款發生在後面的
`sub_14698`。remake 的 `formAICorps` 用 `probe := f.Reserves` 取副本，
方向是對的——這裡只是把「為什麼必須是副本」寫下來：
**任何一槽湊不到就整個編成失敗，中途扣掉的必須不算數。**

## 8. 掃描工具的一個坑

第一版的位移掃描用 `get_func_qty()` 枚舉函式，而**這個 IDC build 沒有這個函式**。
腳本一碰就中止，`fopen` 的緩衝連同已寫的內容一起消失，
而 `idat` 的 exit code 仍然是 0——看起來就像「掃完了，零命中」。

**所以掃描腳本一律要帶正對照**：印一條已知必中的結果。
本輪加的是 `GetDisasm(0x1701A)`（`sub_16FD2` 的 `mov [si+9], al`），
它不出現就代表掃描本身壞了，而不是「沒有人用這一欄」。
改用 `get_next_func(0)` 迭代之後掃到 16 處。
