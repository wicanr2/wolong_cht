## 1. 視窗與靜態層

```asm
sub_17E1F:                       ; 呼叫者 sub_11E46／sub_162FB／sub_163BF
  ds = cs:word_10D52
  si += 840h                     ; ← 據點編號 → 據點記錄
  sub_17F61                      ; 框 ＋ 顯示清單場景 3
  sub_17E4A                      ; 名字、城主、四個數值（§2）
  sub_17F1A                      ; 左半那張 96×96 圖（§3）
  sub_121E7 (loop)               ; 等到右鍵
  sub_17F81                      ; 擦掉
```

`sub_17F61` 的兩句：

```asm
al = 3Dh / dx = 0 / bx = 0Fh / cx = 810h
sub_1895D                        ; 框 (0, 272) 256×128
al = 3 / dx = 8 / bx = 118h
sub_10337                        ; 場景 3，原點 (8, 280)
```

視窗 **(0, 272, 256, 128)** ——貼著畫面左下角。

| 元件 | 座標 | op |
|---|---|---|
| 值框 | (128, 320) 112×64 | 03 |
| 「城兵數」「生產力」「上昇值」「防災值」 | (128, 320／336／352／368) | 08，色 `0x09` |

**左半 128 px 是空的**——那是 §3 那張圖的位置。

## 2. `sub_17E4A`：名字、城主與四個數值

| 值 | 座標 | 位數 | 色 | 來源 |
|---|---|---|---:|---|
| 據點名 | (128, 288) | — | `0x0F` | 據點 `+0x02` |
| 據點類型 | (192, 288) | — | `0x0F` | `cs:7DF5` 的字串表（§2.1）|
| 城主名 | (192, 304) | — | `0x0F` | 該勢力 `+0x01` 的武將名；勢力 `24` 走 `cs:7E19`「中立」|
| 城兵數 | (208, 320) | 4 | `0x09` | 據點 `+0x13` **× 10** |
| 生產力 | (192, 336) | 6 | `0x09` | 據點 `+0x0E` |
| 上昇值 | (208, 352) | 4 | `0x09`，**負數換 `0x0A`** | 據點 `+0x10` **− 100** |

⭐ **上昇值畫面上顯示的是 `+0x10` 減 100**：存檔裡的 100 在畫面上是 0。
`cwd` ＋ `cmp dh, 80h` 那兩句就是為了負值換紅色。

⭐ **城兵數乘 10**，與預備兵、編成的六個槽同一個單位
（[`../spec/21`](../spec/21-corps-formation-reserves.md) §1）。

### 2.1 類型字串表 `cs:7DF5`

每筆 6 bytes（兩個全形字，不足補全形空格）：

| 索引 | 位移 | 字串 |
|---:|---|---|
| 0 | `7DF5` | 大都市 |
| 1 | `7DFB` | 中都市 |
| 2 | `7E01` | 小都市 |
| 3 | `7E07` | 關卡　 |
| 4 | `7E0D` | 戰場　 |
| 5 | `7E13` | 首都　 |
| 6 | `7E19` | 中立　 |

索引 ＝ `[si+16h] & 0x0F`，**但如果這個據點就是該勢力的首都就改用 5**：

```asm
al = [si+16h] & 0Fh / ax *= 6
bx = 勢力編號 × 64
dx = (si − 840h) << 3            ; ← dh 直接等於據點編號
cmp dh, [bx+3]                   ; 勢力 +0x03 ＝ 首都據點編號
jnz → 用原本的
ax = 1Eh                         ; 30 ＝ 第 5 筆「首都」
```

`dx = (si − 0x840) << 3` 這一步值得記：據點記錄 32 B，所以
`(位址 − 基址) × 8` ＝ 編號 × 256，**高位元組剛好就是編號**，省掉一次除法。

索引 6「中立」不從低 4 位來——它是城主欄無主時借用的同一份字串（`cs:7E19`）。

## 3. ⭐ `sub_17F1A`：左半那張圖來自 `KYOGRF.DAT`，張號在 `+0x16` 高 4 位

```asm
al = [si+16h] >> 4               ; ← 高 4 位
ah = 0 / dx = 1200h / mul dx     ; ax = 張號 × 0x1200
cx = 0
ds = cs / dx = 0DFAh             ; ← "KYOGRF.DAT"
bx = cs:word_1987C               ; 目的段
si = 0 / di = 1200h              ; 段內位移 0、長度 0x1200
sub_1E38C                        ; 讀檔（§3.1）
ds = cs:word_1987C / si = 0
ax = 6006h / bx = 5A02h
sub_1FA37                        ; 貼到 VRAM
```

- `0x1200` ＝ 4,608 bytes ＝ **96×96 的 4bpp 圖**。
  [`../formats/03`](../formats/03-grf-images.md) §3 早就從這一支解出尺寸
  （`ax = 6006h` → 96 列 × 每列 12 byte）並算出 15 張；
  **這一份補的是「張號從哪來」**。
- `bx = 5A02h` → VRAM 位移 23,042 ＝ 80×288 ＋ 2 → **(16, 288)**，
  96 px 寬落在 16–112，正好是 §1 說的那半塊空白。

**所以據點 `+0x16` 的高 4 位是 `KYOGRF.DAT` 的張號**，
[`../formats/08`](../formats/08-sinario-save.md) 原本標「高 4 位 0–14 未解」。

⭐ **值域只到 14 是算術逼出來的**：位移用 `mul dx` 算完之後 `cx` 被清 0，
高 16 位丟掉，等於位移只有 16 位。張號 15 會算到 `0x10E00` 而溢位成 `0x0E00`，
指到第一張的中間。**15 張正好用滿 0–14，再多一張這個寫法就壞了。**

### 3.1 `sub_1E38C` 是「讀檔並重試」的共用入口

21 個呼叫點，參數 `dx` ＝ 檔名字串位址、`bx` ＝ 目的段、`si` ＝ 段內位移、
`cx:ax` ＝ 檔內位移、`di` ＝ 長度。失敗時 `int 50h` 之後**重跑自己**
（原版的「請放入磁片」重試迴圈）。

呼叫者裡有 `sub_107D2`——那就是武將頭像的載入端，
所以頭像與據點圖走的是同一條路，差別只在檔名與張號。
