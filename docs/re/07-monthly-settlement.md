# 07 — 月結：`sub_15358` 與它的九支子程式

**狀態：經濟公式全部讀出來，confirmed。**

- 日期：2026-08-08
- 輸入：`workplace/ida/dosv/KI.EXE.i64`
- 位址對映見 `docs/re/06` §0（ds 偏移 ＋ 0x10000 ＝ IDA 線性；ds 偏移 ＋ 0x200 ＝ 檔案）
- 機制說明見 `docs/mechanics/40-economy.md`

## 1. 主流程的順序（confirmed）

`sub_15358` 在換月的當下被時鐘呼叫（`docs/re/06` §5），
對 22 個勢力逐一跑：

```asm
mov  ax, [si+1Ah] / mov dl, [si+1Ch]   ; 本月累計支出（24 位）
call sub_1563B                          ; ① 先扣支出
call sub_153C6                          ; ② 據點結算 → 收入留在 ax:dl
call sub_15609                          ; ③ 收入入帳
xor  ax, ax / mov [si+1Ah], ax / mov [si+1Ch], al   ; ④ 累計支出歸零
call sub_15828                          ; ⑤ 資金為負 → 扣預備兵
```

> **這解掉了 `docs/mechanics/40-economy.md` §3 標成「假說」的月結順序。**
> 實際是「先扣支出 → 再算收入與募兵 → 收入入帳 → 赤字懲罰」。
> 募兵發生在 ② 裡，**在赤字懲罰之前**——所以赤字時是「先募到再被扣掉」。

跑完 22 個勢力之後，最後做 4 個 word 的複製
（`cs:0D10h` → `cs:0D08h`，＝「次月末生效」，`docs/re/06` §5）。

## 2. 資金是有號 24 位元，上下限對稱

| 程式 | 作用 | 邊界 |
|---|---|---|
| `sub_1563B` | 資金 −= ax:dl | **下限 `0xF60168` ＝ −655,000** |
| `sub_15609` | 資金 += ax:dl | **上限 `0x09FE98` ＝ +655,000** |

```asm
; sub_1563B（扣款）
sub  [si+20h], ax
sbb  [si+22h], dl
cmp  dl, 0F6h / jg ok / mov dl, 0F6h / jl clamp
cmp  ax, 168h / ja ok
clamp: mov ax, 168h
```

**±655,000 是一組漂亮的整數**，也反證了「資金 ＝ `+0x20` 的有號 24 位元」
這個解讀是對的（`docs/formats/08` §1.5）。

## 3. `sub_153C6`：據點結算

```asm
mov  bh, [si+3] / xor bl, bl / shr bx,1 ×3 / add bx, 840h
mov  si, bx          ; si → 首都的據點記錄（基址 840h，每筆 32 B）
mov  di, 840h        ; di → 據點表開頭
mov  ch, 0C0h        ; 192 筆
loop:
  cmp cl, [di+1]     ; 該據點的所屬勢力 == 目前勢力編號？
  jnz skip
  call sub_154FC     ; 算距離係數 → bx
  call sub_15538     ; 累計收入
  call sub_15547     ; 累計募兵
  inc  byte ptr [bp+3]   ; 據點數 +1
skip:
  add di, 20h / dec ch / jnz loop
…
mov  [si+23h], dh    ; ★ 據點數寫回勢力記錄 +0x23
```

**這在機器碼裡直接確認了三件事**：據點表基址 `840h`、每筆 32 B、
`+1` 是所屬勢力、勢力記錄 `+0x23` 是據點數。

### 據點記錄的三個欄位（confirmed）

| 偏移 | 內容 | 驗證 |
|---|---|---|
| `+8` | **X 座標** | 值域 4–370（大地圖寬 384）✅ |
| `+0Ah` | **Y 座標** | 值域 9–248（大地圖高 256）✅ |
| `+0Eh` | **生產力** | 值域 142–20,714 |

## 4. ⭐ `sub_154FC`：離首都越遠，收入越少

```asm
mov  ax, [si+8]  / sub ax, [di+8]  / jnb .1 / neg ax    ; |Δx|
mov  bx, [si+0Ah]/ sub bx, [di+0Ah]/ jnb .2 / neg bx    ; |Δy|
cmp  ax, bx / jnb .3 / mov ax, bx                       ; max → 切比雪夫距離
and  ah, ah / jz .4 / mov al, 0FFh                      ; 夾到 255
.4: xor bx, bx
.loop:
  mov ah, cs:[bx+5535h]      ; 除數表
  cmp al, cs:[bx+5532h]      ; 門檻表
  jbe found
  inc bx / jmp .loop
found: mov bl, ah / xor bh, bh
```

兩張表就在 `ds:5532h` 與 `ds:5535h`：

```
門檻 ds:5532h:  50 c8 ff      →  80, 200, 255
除數 ds:5535h:  02 03 04      →   2,   3,   4
```

| 與首都的距離（切比雪夫） | 除數 |
|---|---:|
| ≤ 80 | **2** |
| 81 – 200 | **3** |
| 201 – 255 | **4** |

**遠方據點的收入只有近處的一半。**
說明書完全沒提這件事，但它讓「遷都」變成一個真正的經濟決策——
不只是說明書寫的「只能遷到生產力更高的據點」，
更重要的是**把首都移到領土重心可以整體提升收入**。

## 6. ⭐⭐ `sub_15547`：募兵的地域配比

```asm
mov  ax, [di+0Eh] / xor dx, dx / div bx    ; 生產力 ÷ 距離除數
shr  ax, 5                                  ; ÷ 32   →  設 a = 結果
mov  bx, [di+0Ah]                           ; ← 據點的 Y 座標
cmp  bx, 96h / jnb .南                      ; y ≥ 150
cmp  bx, 50h / jnb .中                      ; 80 ≤ y < 150
.北: …
.中: …
.南: …
.store:
add  [bp+4], ax   ; 騎馬
add  [bp+6], cx   ; 弓兵
add  [bp+8], dx   ; 步兵
```

把三個分支的移位序列展開（分母統一成 32）：

| 區域 | Y 座標 | 騎馬 | 弓兵 | 步兵 |
|---|---|---:|---:|---:|
| **北方** | `y < 80` | **19/32**（59%） | 1/32（3%） | 12/32（38%） |
| **中部** | `80 ≤ y < 150` | 4/32（12.5%） | 4/32（12.5%） | **24/32**（75%） |
| **南方** | `y ≥ 150` | 1/32（3%） | **16/32**（50%） | 15/32（47%） |

三欄的分數加起來都正好是 32/32。**但整數運算的行為三支不同**：

| 區域 | 實作方式 | 三份合計 |
|---|---|---|
| 北方 | 先算弓與步，**剩下的全給騎馬** | 正好 ＝ a |
| 中部 | 先算騎馬與弓，**剩下的全給步兵** | 正好 ＝ a |
| 南方 | 三份各自從 a 移位得到 | **＝ a 去掉最低位**（奇數時少 1） |

⚠ **這裡不能寫成 `a * 19 / 32` 這種分數式。**
北方與中部是「兩份 ＋ 餘數」，餘數被第三份吸收；分數式三份各自捨去，
總和會少。實測分岔案例：`a = 33` 的北方，原版給 `(20, 1, 12)`，
分數式給 `(19, 1, 12)`。

南方少掉的那個奇數位是原版的實際行為，**照抄，不要「修好」它**。

### 這正是說明書那句話的精確版本

> **騎馬は北方でよく集まり、弓は南方でよく集まります。**

北方騎馬 59%、南方弓兵 50%，而**中部是步兵的天下（75%）**——
中部那一條說明書沒寫。

分區只看 **Y 座標**，與 X 無關；門檻是 80 與 150（地圖高 256）。
劇本 1 的 192 個據點分佈：北方 36、中部 76、南方 80。

## 7. `sub_1548F`：玩家的稅率與募兵上限

```asm
mov  al, cs:byte_10D08      ; ← 今月生效的稅率
mul  word ptr [bp+1] / mov bx, 64h / div bx     ; × 稅率 ÷ 100（24 位分兩半做）
…
mov  si, bp / add si, 4     ; → 三兵種的募兵累計
mov  di, 0D0Ah              ; → 三兵種的募兵數設定
mov  cx, 3
loop:
  mov ax, cs:[di]
  cmp ax, ss:[si] / jnb keep
  mov ss:[si], ax           ; ★ 取較小者
keep: si += 2 / di += 2 / loop
```

```
收入 = Σ(生產力 ÷ 距離除數) × 稅率 ÷ 100
募兵[t] = min(可募量[t], 募兵數設定[t])
```

**募兵數設定是上限，不是目標**——正好是說明書那句：

> 集まった兵数がこれに満たない場合など、必ず集まるとは限りません。
> が、**これを越えることはありません**。

### `cs:0D08h` 這一組的佈局也確定了

| ds 偏移 | 內容 |
|---|---|
| `0D08h` | **今月生效**的稅率 |
| `0D0Ah`／`0D0Ch`／`0D0Eh` | 今月生效的募兵數（騎馬／弓／步） |
| `0D10h` 起 4 word | **來月**的同四項（玩家在財政視窗改的就是這裡） |
| `0D02h`（24 位） | 顯示用：本月收入 |
| `0D05h`（24 位） | 顯示用：本月支出（＝勢力記錄 `+0x1A`／`+0x1C`） |

## 8. `sub_15456`：AI 勢力

```asm
shr  byte ptr [bp+2], 1 / rcr word ptr [bp+0], 1   ; 收入 ÷ 2
```

**AI 不使用稅率欄位，固定除以 2（等於稅率 50%）。**

接著掃 127 筆軍團記錄（段內 `2240h`，每筆 32 B），
累加自己那些軍團的 `[bx+4]`，再與收入比較，
用 CF 回報「這個月要不要募兵」。

```asm
mov  ax, si / shl ax,1 / shl ax,1 / mov al, 80h   ; ah = 勢力編號、al = 80h
mov  cx, 7Fh / mov bx, 2240h
loop:
  cmp [bx], al       ; 軍團存在？
  jb  skip
  cmp [bx+1], ah     ; 屬於這個勢力？
  jnz skip
  add dx, [bx+4]
skip: add bx, 20h / loop
mov  al, dh / xor ah, ah
add  ax, [si+1Bh]
shl  ax, 1
cmp  ax, [bp+1] / jnb .no
clc / retn          ; 募兵
.no: stc / retn     ; 不募兵
```

**AI 的募兵是有節制的**：軍團兵力太多相對於收入就停止募兵。
這是原版政略 AI 目前唯一被讀出來的決策式。

## 10. ⭐ `sub_15828`：赤字懲罰

```asm
mov  dx, [si+21h]        ; 資金 >> 8
cmp  dh, 80h / jb ret    ; 資金 ≥ 0 → 不做
mov  bx, si / add bx, 4  ; → 預備兵三兵種
neg  dx
shl  dx,1 ×4             ; dx = (|資金| >> 8) × 16
mov  cx, 3
loop:
  call sub_1ECE0         ; 亂數
  and  ax, 1Fh           ; 0–31
  add  ax, dx
  sub  [bx], ax / jnb ok
  mov  word ptr [bx], 0  ; 借位 → 歸零
ok: bx += 2 / loop
```

```
每個兵種每月扣：(|資金| >> 8) × 16 + rand(0..31)
```

`>> 8` 之後再 `× 16` 等於 `÷ 16`，所以實際是 **|資金| / 16**。
資金 −16,000 時，三個兵種每月各扣約 1,000 人。

**這是說明書「これがマイナスになると予備兵が減少します」的公式。**
而且注意它是**每個兵種各扣一次**，總損失是三倍。

## 11. ⭐⭐ `sub_15695`：生產力與上昇值

尾段批次呼叫的第一支，掃全部 192 個據點（不分勢力）。

```asm
mov  si, 840h / mov cx, 0C0h
loop:
  mov bl, [si+10h] / xor bh, bh
  sub bx, 64h                 ; 上昇值 ＝ 存值 − 100
  mov ah, cs:byte_10CFF       ; 玩家的勢力編號
  cmp ah, [si+1]              ; ★ 這個據點是玩家的嗎？
  jnz .skip
  mov al, cs:byte_10D08       ; 稅率
  xor ah, ah
  sub ax, 1Eh                 ; ★ 稅率 − 30
  sub bx, ax                  ; ★ 上昇值 −= (稅率 − 30)
.skip:
  xor ah, ah
  mov al, [si+0Fh]            ; ← 生產力的**高位元組** ＝ 生產力 >> 8
  and al, al / jnz .ok
  mov al, 1                   ; 0 當成 1
.ok:
  imul bx                     ; ax = (生產力>>8) × 有效上昇值
  mov dx, [si+0Eh]            ; 生產力
  cmp ah, 0 / jl .neg
  sar ax, 1 / add ax, dx      ; 正 → 生產力 += ax/2
  jmp .clamp
.neg:
  neg ax / xchg ax, dx / sub ax, dx
  jnb .clamp / xor ax, ax     ; 負 → 生產力 −= |ax|，下溢歸 0
.clamp:
  cmp ax, [si+0Ch] / jbe .st  ; ← +0Ch ＝ **生產力上限**
  mov ax, [si+0Ch]
.st:
  mov [si+0Eh], ax
  call sub_1ECE0 / and ax, 0Fh
  sub bx, ax                  ; ★ 上昇值 −= rand(0..15)
  cmp bx, 64h   / jle .lo  / mov bx, 64h      ; 上限 +100
.lo:
  cmp bx, 0FF9Ch/ jge .st2 / mov bx, 0FF9Ch   ; 下限 −100
.st2:
  add bx, 64h / mov [si+10h], bl
  add si, 20h / loop
```

### 據點記錄再解出兩個欄位

| 偏移 | 型別 | 內容 | 驗證 |
|---|---|---|---|
| `+0Ch` | u16 | **生產力上限** | 值域 300–42,800，**沒有任何據點的生產力超過它** ✅ |
| `+10h` | u8 | **上昇值 ＋ 100**（實際值 −100…+100） | 存值 10–179 → 實際 −90…+79 |

### 公式

```
有效上昇值 r = 上昇值 − (稅率 − 30)     ← 稅率修正只套用在玩家的據點
d = (生產力 >> 8) × r        （生產力 >> 8 為 0 時當 1）

r ≥ 0 :  生產力 ← min(生產力 + d/2, 上限)
r < 0 :  生產力 ← max(生產力 − |d|, 0)

上昇值 ← clamp(r − rand(0..15), −100, +100)
```

**變化量與生產力本身成正比**（因為乘了 `生產力 >> 8`）——
正好是說明書那句「大きい数値の方が変化が大きくなります」。

### ⭐ 稅率的中性點是 30%

`sub ax, 1Eh` 那一行把稅率換算成上昇值的修正量：

| 稅率 | 對上昇值的影響 |
|---:|---|
| < 30% | **加**（據點繁榮） |
| ＝ 30% | 無 |
| > 30% | **減**（據點荒廢） |

而且**這個修正會寫回上昇值本身**，不只影響當月的生產力計算——
所以高稅率是**累積**的，越拖越糟。這就是說明書那句的機制：

> 高いほど拠点が荒廃していき、低いほど繁栄していきます。

### ⭐ 上昇值每月自然衰減 rand(0..15)

期望值 7.5，所以真正的平衡稅率大約是 **22.5%**：

```
上昇值的月變化期望 = 30 − 稅率 − 7.5 = 22.5 − 稅率
```

稅率低於 22.5% 時上昇值會自己長回來，高於就一路往下掉。
**這解釋了攻略章 10.3 為什麼只說「通常は税率を下げるだけで、
内政の必要はありません」**——調低稅率本身就是內政。

⚠ 稅率修正**只對玩家的據點生效**（`cmp ah, [si+1]`）。
AI 的據點不受稅率影響，與 AI 收入固定除以 2 是同一種簡化。

## 14. ⭐ `sub_155A6`：武將的「評價」

```asm
mov dx, 7Fh / mov si, 4240h        ; 127 筆武將
loop:
  cmp byte ptr [si], 80h / jb skip
  mov bx, si / add bx, 0Eh
  xor ax, ax / mov cx, 3
.a: mov al, [bx] / shr al,1 ×4      ; ÷16
    add ah, al / inc bx / loop .a   ; +0Eh, +0Fh, +10h
  mov cx, 2
.b: mov al, [bx] / shl al, 1        ; ×2
    add ah, al / inc bx / loop .b   ; +11h, +12h
  mov [si+1Fh], ah                  ; ← 評價
```

```
評價 = (適性₁ + 適性₂ + 適性₃) + 2 × 武術 + 2 × 統率
```

### ⭐ 這證實了說明書 10.5

> 基本的には、**武術と統率はその合計が同じであれば強さは同じ**です。

**兩者的權重都是 ×2**，所以只有和有意義。而**政治（`+13h`）完全不計入**——
與說明書「政治は内政、外交に関係する」一致。

用公式算劇本 1 的排名（存檔裡 `+1Fh` 開局是 0，這個值是**載入時算的**，
不存在檔案裡）：

| 武將 | 評價 | 武術 | 統率 | 政治 |
|---|---:|---:|---:|---:|
| 呂布 | 66 | 15 | 11 | 1 |

## 15. `sub_15715`：內政官每月要錢

```asm
mov si, cs:word_10CFD / mov ch, cs:byte_10CFF   ; 玩家勢力
mov di, 840h / mov cl, 0C0h                      ; 192 個據點
loop:
  cmp ch, [di+1] / jnz skip          ; 是玩家的據點嗎
  mov bh, [di+19h]                   ; ← 據點 +19h ＝ **派駐的內政官**
  cmp bh, 0FFh / jz skip             ; 沒派 → 跳過
  xor bl,bl / shr bx,1 ×3
  cmp byte ptr [bx+425Ah], 0 / jnz skip   ; 武將 +1Ah != 0 → 已在要錢中
  xor dx, dx
  mov al, 0B4h / sub al, [di+10h] / jbe .1 / add dx, ax   ; 180 − 上昇值
.1: mov al, 0B4h / sub al, [di+11h] / jbe .2 / add dx, ax ; 180 − +11h
.2: mov al, [di+12h] / sub al, [di+13h] / jbe .3 / add dx, ax  ; +12h − +13h
.3: shr dx, 1 / mov ax, 32h / mul dx      ; ÷2 × 50
    …call sub_12FBF(al=4)                 ; 事件：內政官要錢
```

```
要求金額 = ((180 − 上昇值)⁺ + (180 − 防災值)⁺ + (城兵上限 − 城兵數)⁺) ÷ 2 × 50
```

**離「理想狀態」越遠，要的錢越多。** 三個目標值：上昇值與防災值都是
存值 180，城兵數的目標是該據點的上限。

### 據點記錄再解出四個欄位

| 偏移 | 內容 | 開局值 | 等級 |
|---|---|---|---|
| `+11h` | **防災值**（目標 180） | **全部 192 個據點都是 100** | 強證據 |
| `+12h` | **城兵數上限** | 0–254 | 強證據 |
| `+13h` | **城兵數** | 0–177，**192 個據點全部 ≤ `+12h`** ✅ | 強證據 |
| `+19h` | **派駐的內政官**（武將編號，`0xFF` ＝ 無） | 全部 `0xFF` ✅ | confirmed |

⚠ `+11h` 是否與上昇值一樣帶 −100 偏移**還沒驗**
（沒看到任何一處做 `sub …, 64h`）。若不帶偏移，
開局的防災值就是 100，符合說明書「這個數值只要 ≥ 1 就完全擋住災害」。

## 16. `sub_1578F`：外交官每月要錢

```asm
mov di, 0 / mov cl, 16h              ; 22 個勢力
loop:
  cmp si, di / jz skip               ; 自己跳過
  mov bh, [di+2Ah]                   ; ← 勢力 +2Ah ＝ **派駐該勢力的外交官**
  cmp bh, 0FFh / jz skip
  …武將 +1Ah != 0 → 跳過…
  call sub_130CB / mov dl, al        ; 交友度（我方 → 對方）
  xchg si, di / call sub_130CB / xchg si, di   ; 交友度（對方 → 我方）
  cmp al, dl / jbe .1 / mov al, dl   ; **取兩個方向的較小者**
.1: mov ah, 64h                      ; 100
    cmp al, 80h / jnb .2 / mov ah, 7Dh   ; 125
.2: and al, 7Fh / sub ah, al
    mov al, 0C8h / mul ah            ; × 200
    …call sub_12FBF(al=5)
```

```
v    = min(交友度(我→對方), 交友度(對方→我))
base = 125 若 v 的最高位為 0，否則 100
要求金額 = (base − (v & 0x7F)) × 200
```

**交友度取兩個方向的較小者**——這與說明書「交友關係是單向的」
（`docs/mechanics/50-diplomacy.md` §1）並不衝突：
顯示是單向的，但**外交官的工作量是看比較差的那一邊**。

`0x80` 那個位元是旗標（很可能是交戰狀態），會讓基準從 125 降到 100。

**勢力記錄 `+0x2A` ＝ 派駐該勢力的外交官**（開局全部 `0xFF`）——
本文件先前標成「恆 `FF`，未解」，現在解掉了。

## 17. ⭐⭐ `sub_12286`：火災與暴動

```asm
mov si, 840h / mov cx, 0C0h        ; 192 個據點
loop:
  call sub_1ECE0 / cmp al, 18h / jnb .b     ; 亂數 < 24 → 24/256
  call sub_1ECE0 / and al, 3Fh              ; 0–63
  cmp al, [si+11h] / jb .b                  ; ← 與**防災值**比
  …call sub_12FBF(ax=010Ch)                 ; ★ 火災
  jmp next
.b:
  call sub_1ECE0 / cmp al, 18h / jnb next   ; 再一次 24/256
  call sub_1ECE0 / and al, 3Fh              ; 0–63
  cmp al, [si+10h] / jb next                ; ← 與**上昇值（存值）**比
  …call sub_12FBF(ax=020Ch)                 ; ★ 暴動
next: add si, 20h / loop
```

每個據點每個月各擲一次：

```
火災 P = (24/256) × max(0, 64 − 防災值) / 64
暴動 P = (24/256) × max(0, 64 − 上昇值存值) / 64
```

### ⭐ 免疫門檻是 64，不是 1 也不是 0

比較用的亂數是 `and al, 3Fh` ＝ 0–63，所以：

| 參數 | 完全免疫的條件 | 開局值 |
|---|---|---|
| 防災值 | **≥ 64** | 100（全部 192 個據點） |
| 上昇值存值 | **≥ 64**（＝實際上昇值 ≥ −36） | 100 附近 |

說明書的兩句話因此都是**簡化過的**：

> 火災：防災値が 0 に近づくほど発生率が高くなります。 ✅ 方向正確
> 暴動：上昇値がマイナスになると発生率が高くなり、**プラスの場合は発生しません**。

「正的時候不會發生」是對的，但**門檻其實更寬鬆**——
實際上昇值只要 ≥ −36 就完全免疫。
說明書把安全區講得比實際小，對玩家是保守的建議。

最高機率是 24/256 ＝ **9.4%／據點／月**，在防災值或上昇值歸零時達到。

## 18. ⭐ `sub_122DB`：暴風雨

```asm
call sub_1ECE0 / test al, 1 / jz ret        ; 1/2
call sub_1ECE0 / cmp al, 0C0h / jnb ret     ; al < 192 → 3/4，al ＝ 據點編號
mov bh, al / xor bl, bl / shr bx,1 ×3       ; bx = 據點編號 × 32
cmp byte ptr [bx+848h], 0C0h / jnb .go      ; ← 據點 X 座標
call sub_1ECE0 / test al, 1 / jz ret        ; 否則再擲 1/2
.go:
…call sub_12FBF(ax=0Bh)…
mov ax, [bx+848h] / cmp ax,0Ah / jl .1 / sub ax,5
.1: word_10D22 = ax / word_10D26 = ax + 0Ah      ; X 範圍 [X−5, X+5]
mov ax, [bx+84Ah] / …同樣處理…                    ; Y 範圍 [Y−5, Y+5]
```

每月最多發生一次，**隨機挑一個據點**（編號 0–191 均勻），
然後在該據點周圍圈出一塊 **11 × 11 格**的區域
（`word_10D22`／`10D24` 是左上角，`10D26`／`10D28` 是右下角）。

```
暴風雨 P = 1/2 × 3/4 × (1 若「靠海」，否則 1/2)
        = 37.5% 靠海 ／ 18.75% 內陸
```

### ⚠ 「靠海」的判定是原版的 bug

`cmp byte ptr [bx+848h], 0C0h` 只比 **X 座標的低位元組**，
但 X 的值域是 **4–370**（大地圖寬 384）。

| 條件 | 據點數 |
|---|---:|
| 程式實際判定為「靠海」（`X mod 256 ≥ 192`） | **52** |
| 真正的東半部（`X ≥ 192`） | 101 |
| 其中 `X ≥ 256`，低位元組繞回而被判為內陸 | **49** |

**最東邊的 49 個據點——也就是最靠海的那些——被當成內陸。**
說明書寫的是「発生率は海側がわずかに高くなっています」，
可見原意是東部加成，而 `byte ptr` 讓它只對 X ∈ [192, 255] 的一條帶狀區域生效。

remake 要決定照抄還是修正。**預設照抄**（`CLAUDE.md` §8：
原版行為優先），但要在程式裡標明這是刻意保留的原版 bug。

## 19. ⭐⭐ `sub_14194`：內政官的實際效果，以及 1872 次暴動的正解

### 節奏：`sub_13EFD` 每 tick 處理**一個**據點

```asm
sub_13EFD:                       ; ← 主迴圈 sub_11CD0+43
    mov si, word_10D1E           ; 據點游標（單位是段內偏移）
    …
    cmp byte ptr [si+841h], 18h / jz .1
    call sub_13F74
.1: call sub_14194               ; ★ 內政官
    call sub_14269
    add si, 20h                  ; 下一個據點
```

192 個據點輪一圈 ＝ 192 tick，而**一天是 216 tick**——
所以「每個據點大約每天被處理一次」。這一層先前完全沒被掃到，
因為它掛在主迴圈上，不在時鐘的進位鏈裡。

> ⚠ `si` 是**據點編號 × 32**，基址 `0x840` 被折進了立即值：
> `[si+841h]` ＝ 據點 `+1`（所屬勢力）、`[si+859h]` ＝ `+0x19`（內政官）、
> `[si+850h]` ＝ `+0x10`（上昇值）、`[si+851h]` ＝ `+0x11`（防災值）、
> `[si+852h]` ＝ `+0x12`／`+0x13`（城兵上限、城兵）。
> **grep `840h` 找不到這一支**，這就是它躲過前幾輪搜尋的原因。

### `sub_14194` 的邏輯

```
cl = 8, dl = 4                          ; 預設（AI 的據點、以及沒派官的）
if 玩家勢力 == 據點+1:
    cl = 5, dl = 1                      ; ★ 玩家的據點基準反而**更差**
    bh = 據點+19h（內政官）
    if bh != 0FFh and 武將+1Ah（經費）!= 0:
        dec 武將+1Ah                    ; ★ 花掉 1 點經費
        cl += 武將+13h（政治）
        dl += 武將+11h（武力）; dl >>= 1

ch = max(1, cl − 15)

① rand(0..15) ≤ cl  →  上昇值 += ch          ，上限 200
② rand(0..15) ≤ cl  →  防災值 += (ch>>1)+1   ，上限 200
③ 城兵 < 上限 且 rand() < 24（≈9.4%）：
      上昇值 −= dl（下限 0）；城兵 += dl      ; 徵兵傷民
```

### ⭐ 這就是「120 個月 1872 次暴動」的正解

模擬跑出的偏差是「AI 據點的上昇值每月被扣 `rand(0..15)` 卻沒有東西補回來」
（`CONTEXT.md` §7.0）。**補回來的就是這一支，而它沒有被實作。**

AI 的據點走預設分支 `cl = 8`：每天有 **9/16** 的機率上昇值 `+1`
（`ch = max(1, 8−15) = 1`），一個月期望 `+16.9`，
而每月衰減的期望是 `−7.5`——**淨值是正的**，所以 AI 的據點本來就不該崩。

### ⚠ 一個反直覺的設計：玩家的據點基準更差

`cl` 的預設是 8，但**只要據點屬於玩家就降到 5**，要靠內政官的政治值補回來
（政治 15 的內政官 → `cl = 20`，`ch = 5`，遠優於 AI）。

也就是說：**不派內政官的玩家據點比 AI 的據點還糟**。
這讓「人事」這個指令有實質意義，也解釋了為什麼要錢的金額公式
（§15）用「離理想值多遠」來算。

**照抄，不要「修正」成對稱的。** 兩個分支的常數都是直接讀出來的。

## 20. ⭐⭐ `sub_12BD9`：月結時的 AI 決策回合（2026-08-08）

月結尾段最後一支沒讀的。它做兩件不相干的事，而**第一件跟 AI 無關**。

### ① 事件佇列的月度壓縮

```asm
mov cs:word_10D20, 0             ; 佇列游標歸零
mov cs:byte_131AD, 7             ; 「每 10 次處理一筆」的計數器重設成 7
mov ds/es, cs:word_10D56         ; 事件佇列的段
xor di,di / mov si, 100h / mov cx, 180h / rep movsw   ; ★ 把 0x100 之後搬到 0
mov cx, 80h / rep stosw                               ; 尾端 256 B 清 0
```

`0x100` ＝ 第 64 格。`sub_12FBF` 只用前 64 格（`bx < 0x100`），
所以這一段的意思是：

> **每個月把最舊的 64 格事件整批丟掉**，其餘往前搬，尾端補空。

⚠ **這不是「處理完」而是「丟掉」。** 沒被處理到的事件會在月結時消失——
`sub_131AE` 每 10 次呼叫才處理一筆，一個月 216 × 30 tick 裡
輪不到的就作廢。remake 照抄時**不能改成無損佇列**，
那會讓積壓的事件在月初一次爆出來。

### ② 22 個勢力的局勢評估與侵攻起意

```asm
mov es, cs:word_1987C / xor di,di / mov ax, 0FFFFh / mov cx, 210h / rep stosw
                                  ; 1,056 B 的表整片填 0xFFFF（＝「無」）
mov cx, 16h / mov si, 0 / xor di, di
loop1:  cmp byte ptr [si], 80h / jb .skip
        call sub_12C52            ; 局勢評估 → 每勢力 0x30 的緩衝區
        call sub_12D3A            ; ★ 侵攻起意
.skip:  add di, 30h / add si, 40h / loop
loop2:  call sub_12D58            ; 決策鏈（22 個勢力再跑一次）
```

**`sub_12C52`** 掃 192 個據點，把屬於該勢力的（`cmp ah, [di+1]`）
累加進那塊 `0x30` 的緩衝區 —— 所以那塊是**該勢力所有據點的彙總**。

### ⭐ `sub_12D3A`：沒有侵攻目標的勢力，每月 25% 起意

```asm
cmp byte ptr [si+19h], 0FFh      ; 已經有侵攻目標 → 什麼都不做
jnz ret
call sub_1ECE0 / cmp al, 40h     ; ★ rand(0..255) < 64 → 25%
jnb ret
mov al, 8 / mov dx, 0FFFFh / mov bl, dl / call sub_12FB1   ; 發事件 8
```

**這是 AI 侵攻的起點**，而且與已知的兩條規則接得起來：

- 起意之後 `+0x19` 被填上目標勢力編號（`sub_12E33`／`sub_13526`／`sub_135AB`）
- 財政撐不住時每小時的 `sub_13E11` 會把它清回 `0xFF`（`docs/re/08` §1）

所以 AI 的侵攻是**「每月 25% 機率起意 → 每小時檢查養不養得起」**的循環。
「敵が疲弊中」之所以是提停戰的好時機，是因為疲弊的敵人**剛被取消侵攻，
而且下個月才有機會再起意**。

`sub_12D58` 的決策鏈（`sub_12DB8`／`sub_12DF3`／`sub_12E33`／`sub_12E89`／
`sub_12EFB`）還沒逐支讀 —— **玩家的勢力走 `sub_12DF3`，其餘走 `sub_12DB8`**
（`cmp si, cs:word_10CFD`），這個分岔本身就值得先記下來。
