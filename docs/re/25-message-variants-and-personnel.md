## 1. 訊息索引 ≥ `0x196` 會展開成八個變體

`sub_1075B`（`0001075B`）在取偏移之前先做一次索引換算：

```asm
0001075B  push ds / push si / push ax
0001075E  mov  ds, cs:word_10D38
00010763  cmp  cx, 196h
00010767  jb   short loc_1077C        ; < 0x196：cx 就是索引
00010769  sub  cx, 196h
0001076D  shl  cx, 1 / shl cx, 1 / shl cx, 1   ; ×8
00010773  add  cl, ah                  ; ← ah 選組內第幾個
00010775  adc  ch, 0
00010778  add  cx, 196h
0001077C  shl  cx, 1                   ; ×2 → 偏移表
0001077E  mov  si, cx / mov si, [si]
```

也就是：

```
索引 < 0x196 → 直接用
索引 ≥ 0x196 → 0x196 + (索引 − 0x196) × 8 + ah
```

`0x196`（＝406）之後的訊息因此不是一則一格，而是**八格一組**，
`ah` 從 0 走到 7 選一個。這解釋了為什麼直接查 `TALK.DAT` 第 `0x19C` 格會看到空的——
那一格根本不是訊息，是**組編號**。

## 2. `sub_18810` 不決定訊息索引

`sub_18810`（`00018810`，67 B，59 個呼叫點）本身只做四件事：

```asm
sub_1895D(al=1Eh, dx=0Ah, bx=8, cx=510h)   ; 畫框
sub_1075B(dx=0Ah, bx=0Ah, ax, cx)           ; 排版並繪出訊息
loc_1222B                                    ; 等待
sub_1895D(al=0,  dx=0Ah, bx=8, cx=510h)     ; 擦掉
```

索引語意在 `sub_1075B`。**先前把門檻記在 `sub_18810` 上、寫成 `cx ≥ 0x100`
並推測是 `−0x20` 偏移，兩者都不成立**：門檻是 `0x196`，機制是 ×8 展開。
推翻紀錄見 `CONTEXT.md` §6。

## 3. 人事：四個指令

由指令列 #1「人事」（`sub_16265`）經 `funcs_16279` 分派，
四支的骨架完全相同（見 [`22`](22-strategy-command-tree.md) §3.2）。

| 指令 | handler | 狀態列 | 選什麼 | 目標欄位 |
|---|---|---|---|---|
| 內政官任命 | `sub_16A9B` | #11「要派遣內政官到哪個據點？」 | `sub_17400` 選據點 | 據點 `+0x19` |
| 內政官解任 | `sub_16B08` | #13「要解任哪個據點的內政官？」 | 同上 | 同上 |
| 外交官任命 | `sub_16B71` | #12「要派遣外交官到哪個勢力？」 | `sub_17906` 選勢力 | 勢力 `+0x2A` |
| 外交官解任 | `sub_16BE3` | #14「要解任哪個勢力的外交官？」 | 同上 | 同上 |

**內政官派駐到「據點」，外交官派駐到「勢力」**——與
[`../mechanics/60-personnel.md`](../mechanics/60-personnel.md) 由說明書記下的一致，
現在有機器碼側的對照。

任命的流程（以 `sub_16A9B` 為例）：

```asm
sub_18853(cx=0Bh)                  ; 狀態列提示
sub_17400                          ; 選據點 → bx；CF=1 取消
cmp byte [bx+19h], 0FFh
jnz → sub_18810(al=93h, cx=34h)    ; 已有人：訊息 #52「{2}已有{1}大人前去赴任了。」
si = bx
sub_18853(cx=9)                    ; #9「請選擇任命之武將。」
sub_17663                          ; 選武將 → bx；CF=1 取消
mov byte [bx+17h], 2               ; 武將職務 ← 內政官
ax = (bx − 4240h) << 3
mov [si+19h], ah                   ; 據點 ← 武將編號
sub_18810(cx=19Ch, ah=[bx+1Eh], al=[bx+1])
```

`ax = (bx − 0x4240) << 3` 取 `ah`，等於 `(bx − 0x4240) ÷ 32`——
**武將表基址 `0x4240`、記錄長度 32 B**，與
[`../formats/08-sinario-save.md`](../formats/08-sinario-save.md) §3 已記載的相同。
這是獨立驗證，不是新結論。

解任走 `sub_16B4F`（內政官）／`sub_16C2A`（外交官），失敗時顯示
#54「是否有所差錯？{2}並未派遣任何人。」。兩支本體未讀。

## 4. 兩個欄位

### 4.1 武將記錄 `+0x17` 是職務列舉，不只是「出陣中」

既有記載是「編成軍團時寫 1、被俘時寫 4、釋放時歸零」。這一輪補上中間兩個值：

| 值 | 意義 | 寫入處 |
|---:|---|---|
| 0 | 無職務 | 釋放時歸零 |
| 1 | 出陣中 | `sub_16F26` 編成軍團 |
| **2** | **內政官** | **`sub_16A9B`（`00016AD8`）** |
| **3** | **外交官** | **`sub_16B71`（`00016BB3`）** |
| 4 | 捕虜 | `sub_129C3` |

五個值互斥，所以這是一個**職務列舉**。一個武將同時只能有一個身分——
這解釋了為什麼派了內政官就不能編進軍團。

### 4.2 武將記錄 `+0x1E` 選訊息變體

`sub_16A9B`／`sub_16B08`／`sub_16B71`／`sub_16BE3` 四支都以
`mov ah, [bx+1Eh]` 取它當 §1 的組內索引。值域必須落在 0–7（組只有八格）。

**這是一個口吻／性格欄位**：同一件事（接受任命），八個值對應八種說法。
推論等級 **強證據**——四個呼叫點一致，而且展開後的八則訊息語意上構成一組。

**未解**：為什麼 0–2 恆為空。可能是那三個值不會出現在武將資料裡，
也可能是原版就留了空槽。要把 127 筆武將的 `+0x1E` 值分佈掃出來才知道，
本輪沒做。
