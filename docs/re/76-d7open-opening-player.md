## 1. 它是誰

`YNVSHELL.COM` 在遊戲本體之前跑它，六幕放完就 `int 10h ax=3` 回文字模式
並離開。整支只有 4,734 B，`start` 是一串直線呼叫：

| 呼叫 | 做什麼 |
|---|---|
| `sub_106F9` | `int 21h ah=48h bx=7E92h` 配 518,432 B 工作區；失敗印 `Error: Memory not enough !` |
| `sub_10789`／`sub_1072A` | 音源與計時器（`int 61h`，`YNSOUND.COM` 的介面）|
| `sub_106D4` | 讀 `OPENPAL.BRG` 進色盤緩衝、取 DOS/V 字型（`sub_10E8B`）、全螢幕塗黑 |
| `sub_1079E`／`sub_10493`／`sub_107C1` | 中斷向量、鍵盤與滑鼠的跳出鉤子 |
| **`sub_10056`** | **第 1 幕** |
| **`sub_102E4`／`sub_102FC`／`sub_1031A`** | **第 2／3／4 幕** |
| **`sub_1033A`** | **第 5 幕** |
| **`sub_104CA`** | **第 6 幕** |

畫面是 VGA 640×480 十六色平面模式，而遊戲的座標原點在
**`0A0C8h:0`**（VRAM 位移 `0xC80` ＝ 40 列 × 80 B）——
400 列的畫面在 480 列的顯示區裡上下各留 40 列。`sub_10B86`（填矩形）
把座標夾在 `< 0x280` × `< 0x190`，也就是 **640 × 400**。

## 2. 六個檔名是一張定長表

`sub_105F3(al = 幕號)`：

```asm
mov     ah, 0Dh
mul     ah              ; ax = al × 13
add     ax, 817h        ; seg000:0817 ＝ "OPEN_S1 .DAT"
mov     dx, ax
mov     bx, cs:word_107FC   ; 工作區段
xor     si, si              ; 一律載到工作區的 0
call    sub_10A14
```

每筆 13 byte（`"OPEN_S1 .DAT\0"`），所以 **`al` ＝ 0–5 → `OPEN_S1`–`OPEN_S6`**。

| 位址 | 內容 |
|---|---|
| `seg000:07FF` | `OPENPAL.BRG` |
| `seg000:080B` | `OPENBGM.DAT` |
| `seg000:0817` ＋ 13 × n | `OPEN_S1 .DAT` … `OPEN_S6 .DAT` |
| `seg000:0865`–`09F6` | 旁白 402 B（§4）|
| `seg000:09F7` | `Error: Memory not enough !` |

## 3. ⭐ `OPENPAL.BRG` 的第 n 組配第 n＋1 幕

`sub_10615(al = 組, ah = 階)` 的 `si = al × 48`，48 ＝ 16 色 × 3 byte，
所以 288 B 正好 **6 組**。每一幕載完自己的圖之後就用同號的組淡入：

| 幕 | 常式 | 載入 | 色盤組 |
|---:|---|---|---:|
| 1 | `sub_10056` | `sub_105F3(al=0)` | `xor al, al` → **0** |
| 2 | `sub_102E4` | `al=1` | `mov ax, 1001h` → **1** |
| 3 | `sub_102FC` | `al=2` | `ax = 1002h` → **2** |
| 4 | `sub_1031A` | `al=3` | `ax = 1003h` → **3** |
| 5 | `sub_1033A` | `al=4` | `ax = 1004h` → **4** |
| 6 | `sub_104CA` | `al=5`（在 `sub_1047A` 之後）| `ax = 1005h` → **5** |

亮度那一階走 `sub_10AE0`，算式與 [`02`](02-palette-routine.md) §4 的同一條
（`(v << 4) × 亮度 + 0x80 >> 8`，亮度 0–16）。
`sub_1064B`／`sub_10692` 是同一張表的另兩種寫法：前者把 8 個色寫進
`c` 與 `c+8` 兩個位置，後者一次讀兩組（`[si]` 與 `[si+18h]`）做兩組之間的交叉淡。

### 4.1 版面：一行 20 字，右半換色

`sub_10288`／`sub_102B3` 逐字推進：

| 變數 | 初值 | 規則 |
|---|---:|---|
| `word_10282` | `0865h` | 字的位址，每字 `+2` |
| `word_10284` | `170h` | x，每字 `+10h`；`≥ 180h` 就回 `40h` |
| `word_10286` | `20h` | y，換行時 `+20h` |

## 5. `[HARD]` ⭐⭐ 檔案前 4 byte 是解壓長度，載入器 `LSEEK` 跳過它

`sub_10A14` → `sub_10D96`（開檔 ＋ RLE 迴圈）→ `sub_10E04`：

```asm
sub_10E04:
        mov     bx, ax
        mov     ax, 4200h       ; LSEEK，從檔頭起算
        xor     cx, cx
        mov     dx, 4           ; ⭐ 位移 4
        int     21h
        mov     bx, 800h        ; 32 KB 讀取緩衝
```

**同一段程式碼在三個執行檔裡都有**：`KI.EXE` 的 `sub_1F655`
（`sub_1F5E7` 的開檔子程序，SHA-256 `fffeba98…d43868`）、
`D7END.EXE`、`D7OPEN.EXE` 的 `sub_10E04`。所以這是格式的一部分，
不是某一支的怪癖。

跳過的那 4 byte 是**小端 u32 ＝ 解壓後的長度**。實測兩版各 20 個檔
（`END_S1`–`S12`、`GAMEOVER.DAT`、`MMAP.MAP`、`OPEN_S1`–`S6`）
宣告值與跳頭解出來的長度**逐檔相等**：

| 檔 | 宣告 ＝ 實得 |
|---|---:|
| `MMAP.MAP` | 98,304 ＝ 384 × 256 |
| `OPEN_S1` | 78,016 |
| `OPEN_S2`／`S3`／`S4` | 384,000 |
| `OPEN_S5` | 288,000 |
| `OPEN_S6`／`END_S2`–`S12`／`GAMEOVER` | 128,000 |
| `END_S1` | 91,200 |

⚠ **`END_S13`／`S14`／`S15` 不在這一族**——那三個是字型與人名字（
[`29`](29-font-service-int15.md)、[`../formats/10`](../formats/10-end-s15-namechars.md)），
前 4 byte 不是長度，走的也不是這條載入器。

### 5.1 為什麼從 0 開始解也「幾乎」對

`MMAP.MAP` 的頭是 `00 80 01 00`——四個 byte 裡沒有相鄰重複，
RLE 的狀態機因此原樣吐出它們、而且**沒有跑掉相位**：
`decode(檔案)[4:]` 與 `decode(檔案[4:])` 逐 byte 相同。
所以把那 4 byte 當成「解壓後開頭的長度欄」也會得到正確的地圖。

過場圖沒有這個運氣。`OPEN_S2` 的頭是 `00 dc 05 00`，解到某一處相位就跑掉，
結果**長度短 22 B、內容整體位移**。位移的形狀很好認：
一張 320 px 寬的圖會在 x ＝ 160 出現一條垂直接縫，左右兩半互換。
判準是**長度**——跳頭之後解出來一定等於宣告值，差一個 byte 都是錯的。

## 6. 第 1 幕：捲動的背景 ＋ 26 幀的疊圖 ＋ 逐字旁白

`OPEN_S1` 解出 78,016 B，工作區裡分成三塊：

| 位移 | 用途 | 誰讀 |
|---:|---|---|
| 0 – 47,999 | 捲動背景，**只有平面 0／1**（四色），每列 80 B ＝ 兩個平面各 40 B | `sub_1016C` |
| 48,000 起（`+0BB8h` 段）| 疊圖層，**只有平面 2**，320 px 寬 | `sub_101B4` |
| 59,200 起（`+0BB8h+2BCh`）| 動畫格，每格 672 B ＝ 56 列 × 12 B（96 × 56 px）| `sub_10242` |

`sub_1016C` 把 400 列貼到 `di = 22h`（x ＝ 272），來源從呼叫端給的 `si` 起算；
`sub_10056` 的主迴圈每步 `add si, 50h`（一列）直到 `si` 到 `3E80h`——那就是捲動。
`sub_10242` 把第 `byte_10241` 格蓋進疊圖層的 `di = 0CECh`；
`sub_10203` 讓它在 0／1／2 之間循環（第三次回傳 CF＝1 當作一輪結束），
`sub_10230` 則一路數到 `1Ah` ＝ **26 格**。

## 7. ⭐ 第 2–4 幕：12 幀的 320 × 200 動畫

這一段回答「`OPEN_S2`–`S4` 的 384,000 B 是什麼」：
**384,000 ＝ 12 × 32,000**，一幀 320 × 200 × 四平面。

`sub_10586` 是貼一幀：

```asm
mov     ax, 0A0C8h / mov es, ax
mov     di, bx          ; bx = 1914h → 螢幕 (160, 80)
mov     bx, 0C814h      ; bh = 200 列，bl = 20 word = 40 B = 320 px
… 每列：平面 0／1／2／3 各 rep movsw 20 word，
        平面之間 si += 1F18h（湊成 8,000），第四個平面後 si -= 5DC0h、di += 28h
```

所以一幀之內**平面在前、列在後**：平面 p 的第 y 列在 `p × 8000 + y × 40`。

`sub_10538` 是播放器：

```asm
mov     bx, 1914h
mov     cx, 18h         ; 24 次
loop:   test cl, 3 / jnz +      ; cl 是 4 的倍數就把 ds 拉回工作區起點
        call sub_10586
        ds += 7D0h              ; 下一幀（2000 段 ＝ 32,000 B）
        延遲 4 個計時單位
mov     cx, 0Ch         ; 再 12 次，這一輪不重設
```

**先把第 0–3 幀循環六遍，再把 0–11 幀走一次。**
量幀間差異可以看出同一個結構：`f0` 與 `f4` 只差 3 個 byte，
`f1`↔`f5`、`f2`↔`f6`、`f3`↔`f7` 差 3.6k–4.1k，
而 `f0`↔`f1` 差 6.0k——**四個相位 × 三個階段**，
前八幀幾乎只有旗幟在動，最後四幀才推進劇情。

## 8. 第 5 幕：CRTC 硬體捲動

`sub_1033A` 先把工作區 `+4650h`（288,000）之後的 1,920 B 清成 0，
載入 `OPEN_S5`（288,000 B），然後跑 200 次：等垂直同步 →
`sub_103B5` 寫 CRTC `0Ch`／`0Dh`（顯示起始位址）與 `18h`（line compare）
→ `sub_103EF` 把新的一段補進 VRAM。
`word_10338` 每次前進 `78h` 段（1,920 B ＝ 24 列），
到 `+4650h` 就停——**整段是硬體捲動，不是逐幀重畫**。

## 9. 第 6 幕

`sub_104CA` 不再載檔，直接從工作區 `+5DC0h`（384,000）與 `+6D60h`（448,000）
兩塊各貼一次 `ax = 0C828h` 到 `bx = 0` 與 `bx = 3E80h`——
與 [`70`](70-d7end-ending-player.md) 的整張貼圖同一種（上下兩半各 200 列）。
色盤走第 5 組，淡入之後停 `190h` 個計時單位再淡出。
