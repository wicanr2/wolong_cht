# 04 — `.MAP`／`.SCH`／`.MCH`：兩種完全不同的東西

**狀態：容器格式的索引層 READY，壓縮演算法未解。**

- 日期：2026-08-07
- 推論等級：**索引結構 confirmed**（六個檔的末端與檔案長度完全相符）

## 1. ⚠ 同一組副檔名被用在兩種用途上

| 檔案 | 是容器嗎 | 誰的 |
|---|---|---|
| `PASS.MAP`／`PASS.SCH` | **是** | 松崗（防拷，PC-98 沒有） |
| `INSTALL.MAP`／`INSTALL.SCH` | **是** | 松崗（安裝程式） |
| `MOUSE.MCH`／`MOUSE.SCH` | **是** | 松崗（滑鼠游標，PC-98 沒有） |
| `MMAP.MAP`／`MMAP.MDL`／`MMAP.MCH` | **不是**，裸資料 | 原版 |
| `BATTLE.MAP`／`BATTLE.MDL`／`BATTLE.SCH` | **不是**，裸資料 | 原版 |

**分野與副檔名無關，與「誰做的」有關。** 松崗自己加的檔案用他們自己的
容器格式；原版的 `MMAP`／`BATTLE` 是裸資料。

> 這一條很容易踩錯：看到 `PASS.MAP` 與 `MMAP.MAP` 同副檔名就假設同格式，
> 會在 `MMAP.MAP` 上白解半天。**先問這個檔是哪一版才有的。**

## 2. 容器格式

```
0x000 ┌──────────────────────────────┐
      │ 索引：(offset u32, length u32) │  最多 64 對，0,0 結束
0x200 ├──────────────────────────────┤
      │ 資料：壓縮過的片段，依索引排列    │
      └──────────────────────────────┘
```

- 第一筆的 offset 固定是 **`0x200`**（＝ 512，索引區的大小）。
- 片段**首尾相接**：`offset[i] + length[i] == offset[i+1]`。
- 最後一筆的 `offset + length` **等於檔案長度**。

六個檔全部符合，沒有例外：

| 檔案 | 大小 | 片段數 | 末端 |
|---|---:|---:|---:|
| `PASS.MAP` | 32,594 | 1 | 32,594 ✅ |
| `PASS.SCH` | 14,281 | 10 | 14,281 ✅ |
| `INSTALL.MAP` | 30,831 | 1 | 30,831 ✅ |
| `INSTALL.SCH` | 11,041 | 8 | 11,041 ✅ |
| `MOUSE.MCH` | 588 | 2 | 588 ✅ |
| `MOUSE.SCH` | 864 | 2 | 864 ✅ |

`MOUSE.MCH` 的索引是 `[(512, 31), (543, 45)]` —— 兩個很小的片段，
對得上「滑鼠游標的圖形與遮罩」。

## 3. 壓縮：還沒解

`PASS`／`INSTALL` 那四個檔的熵是 **7.54–7.68 bit/byte** → 壓縮過。
`MOUSE` 的兩個太小（1.22／3.83），不能從熵判斷。

**不要猜演算法**（`CLAUDE.md` §8 第 10 條：猜三次沒中就停手）。
正路是從 `YNFONT.EXE`（66 個函式，已進 IDA）與 `INSTALL.EXE` 反追解壓常式。
兩支都是 Borland C++ 1991 編譯的，且**只有松崗版有** ——
所以這是松崗自己選的壓縮，不是原版的。
