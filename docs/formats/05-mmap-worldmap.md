## 1. `MMAP.MDL`：256 塊 16×16 地形圖塊（confirmed）

32,768 ÷ 128 ＝ **256 塊**，餘 0。像素格式與 `*GRF.DAT` 相同
（4 bpp plane-major，見 `docs/formats/03` §1）。

兩條獨立證據：

1. **算術**：128 B／塊正是 16×16 4bpp，整除無餘數。
2. **視覺**：解出來是草地、河流與海岸、山地、道路、城牆、建築物，
   與 PC-98 實機大地圖畫面的地形完全吻合。

繪製常式對 16×16 圖塊用 `ax = 1001h`（`ah`＝16 列、`al`＝1 → 每列 2 byte
＝ 16 px），與 `docs/re/03` §3 的參數拆法一致。

## 2. 地圖尺寸：384 × 256 格（confirmed）

`sub_1E4CE` 的掃描迴圈：

```asm
loc_1E4E2:
        mov     al, es:[di]
        …
        inc     di
        inc     cx
        cmp     cx, 180h        ; ← 一列 384 格
        jnz     short loc_1E4E2
        add     bp, 18h         ; ← 下一列：段 +0x18 ＝ +384 byte
        add     dx, 18h
        inc     ah
```

- 一列 **384 格**，每格 **1 byte**。
- 列跨距 384 byte → 格與 byte 一對一，沒有 padding。
- 展開後的緩衝區是 **98,304 B**（`sub_119CA` 用 `rep stosw` 清 0x8000＋0x4000 words）。
  98,304 ÷ 384 ＝ **256 列**。

**所以世界地圖是 384 × 256 格 ＝ 6,144 × 4,096 pixel。**
與社群資料說的「大中小城池、戰場、關口近 300 處，道路交錯複雜」對得上。

> 這也解釋了為什麼 `MMAP.MAP` 只有 80,716 B 卻要展開成 98,304 B：
> **檔案是編碼過的，`sub_1E48A` 負責展開。** 編碼方式未解（§4）。

## 3. 自動連接：道路與河流會依鄰格換圖塊（confirmed）

`sub_1E57F` 與其後的程式碼在掃描每一格時會看左右鄰格：

```asm
        mov     al, es:[di-1]       ; 左鄰
        cmp     al, 0B8h
        jb      …                    ; 不在 [0xB8, 0xDD] 就跳過
        cmp     al, 0DDh
        ja      …
        mov     al, 80h             ; 命中 → 換成連接用圖塊 0x80
        call    sub_1E68C
        …
        mov     al, es:[di+1]       ; 右鄰
        …
        mov     al, 81h             ; → 0x81
```

也會看 `[di-2]`（隔一格）。

| 值域 | 意義 |
|---|---|
| `0xB8`–`0xDD` | **可連接的一族**（道路／河流／海岸），鄰格落在這裡就要接邊 |
| `0xCB`–`0xD3` | 其中 9 種要走 `sub_1E57F` 的完整處理，並累計 `byte_1E47F` |
| `0x80`／`0x81`… | 替換後的連接圖塊 |

**remake 要照做。** 地圖不是「查表畫圖塊」那麼單純——
同一個地形值在不同鄰居旁邊會畫成不同的圖塊。
直接照抄 `MMAP.MAP` 的值去查 `MMAP.MDL`，road 與河流的接邊會是斷的。
