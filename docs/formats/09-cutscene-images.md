## 1. 外層：與 `MMAP.MAP` 同一種 RLE

`D7END.EXE` 的 `sub_114E9` 與 `KI.EXE` 的 `sub_1F5E7` 是**同一個演算法**
（[`06`](06-mmap-rle.md)）：沒有逃脫字元，連續兩個相同的 byte 之後那一個
是「再重複幾次」，次數 0 表示那兩個就只是字面值。

⭐ **這一條是整個格式的鑰匙。** 先前 `END_S*` 被當成未解，是因為
播放器裡三個 consumer 的來源位移（`0`／`0xBB8`／`0xE74` 段）換成 byte 之後
**比檔案本身還大**——那些位移指的是**解壓後**的緩衝區。

十八個檔的解壓長度：

| 檔 | 壓縮 | 解壓 |
|---|---:|---:|
| `END_S1` | 40,999 | 91,118 |
| `END_S2` | 64,331 | 127,926 |
| `END_S3`–`S11`（多數）| 10,637–40,806 | **127,749** |
| `END_S12` | 81,596 | 127,987 |
| `OPEN_S1` | 51,403 | 77,934 |
| `OPEN_S2`–`S4` | 212,513–319,264 | ≈ 384,000 |
| `OPEN_S5` | 55,506 | 287,886 |
| `OPEN_S6` | 71,150 | 127,749 |

⚠ **128,000 是上限不是實際長度**：檔案只編到最後一個有內容的 byte，
尾巴那幾百個 byte 沒有編進去。解碼端補 0 就好——原版那一塊在整張貼圖前
已經被上一幕蓋掉。

## 2. 內層：640 × 400、16 色、EGA 四平面

一張畫面 128,000 B ＝ 640 × 400 ÷ 8 × 4。版面來自 `sub_10293` 的兩次貼圖：

```asm
ds = 影像段        / si = 0     / bx = 0      / ax = 0C828h / sub_1178A
ds = 影像段+0FA0h  / si = 0     / bx = 3E80h  / ax = 0C828h / sub_1178A
```

- `0xFA0` 段 ＝ **64,000 B**；`0x3E80` ＝ 16,000 ＝ 200 列 × 80 B
- 所以是**上下兩半各 200 列**，各 64,000 B

一半之內是**平面優先**：四個平面各 16,000 B（200 列 × 80 B）依序排。
`sub_1178A` 對「enable set/reset」依序寫 `0x0E`／`0x0D`／`0x0B`／`0x07`
（＝ `~1`／`~2`／`~4`／`~8`），所以**來源的第 n 塊就是平面 n**，
色號 ＝ 四個平面同一位元湊出來的 0–15。

```
色號(x, y) = Σ  bit(  buf[ half(y) + p×16000 + (y mod 200)×80 + x÷8 ],  7 − x mod 8 ) << p
             p=0..3
half(y) = 0（y < 200）或 64,000
```

## 3. 色盤：一幕一組

`ENDPAL.BRG` 是 192 色 ＝ **12 組 × 16**，而結局正好 12 幕。
`sub_1035F(al = 幕號, ah = 淡入階)` 的 `al` 就是幕號——
**第 n 幕用第 n 組**。實測：`END_S2`（第 1 幕，從 0 起算）配第 1 組
才是暖色的山景，配第 0 組會變成藍白色。

格式與 `GAMEPAL.BRG` 相同（[`02`](02-brg-palette.md)）。
