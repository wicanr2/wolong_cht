## 怎麼錄的

⭐ **不錄螢幕，直接把每一幀寫出來。** X11 擷取要跟畫面搶時間，錄出來的幀率
不穩、還會抖；逐幀輸出是確定性的——同一個 seed 跑兩次得到同一批圖。

操作也不送 xdotool 點擊：時間軸寫在 [`mobile/wolong/demo.go`](../../mobile/wolong/demo.go)
的 `demoTimeline`，第幾幀做什麼一目了然，而且**與畫面更新同一條時間線**，
不會發生「點下去時畫面還沒到那一格」。

⚠ **時間軸的幀號是「畫出來的第幾張圖」，不是遊戲的 tick 數。** Ebiten 在慢速的
軟體算圖下會跳過 Draw（Update 照跑）：第一次用 tick 當時間軸，2,400 個 tick 只
畫出 778 張，動作也落在別的位置。一張圖 ＝ 一個影片幀 ＝ 1/30 秒。

腳本與剪接看**同一份標記**（`marks.txt`）：`demo.go` 標記段落起點，
`promo_android.sh` 照它切段並套標題。改時間軸不必改剪接腳本。

## 素材界線

- 畫面全部是 remake 自己算出來的，**沒有原版影片、截圖或錄音**。
- 配樂是 [`tools/promo_score.py`](../../tools/promo_score.py) 產生的原創合成音，
  不讀 `BGM.DAT`／`SOUND.DAT`。
- 片中的中文來自 `TALK.DAT` 與遊戲畫面；**原版資料檔本身不隨影片散布**。

## 踩過的坑

| 症狀 | 成因 |
|---|---|
| 2,400 個 tick 只輸出 778 張，動作對不上 | Ebiten 會跳過 Draw；時間軸要用畫出來的張數 |
| 只切出兩段，第二段內容還是錯的 | `ffmpeg` 在 `while read` 迴圈裡**把還沒讀的標記行吃掉**了。要加 `-nostdin` |
| 六格裡兩格顯示 0 | 那是示範腳本自己把兵種點成「空」（循環是騎馬→弓兵→步兵→空）。不是缺陷，但推廣片上看起來像，所以改成點兩下換兵種 |
| 縮圖看起來每一格都是 0 | 抽樣拼圖縮到一半，兩位數糊成一位。**看全解析度的那一張**再下結論 |
