## 1. 原版做什麼

主畫面是**整片 640×368 的大地圖，加上疊在上面的四個視窗**。
四個視窗各自可以開關，開關在橫幅右側：

```
熱區 1 (336,0,32,32) → 命令         (0,  32, 432,  32)
熱區 2 (368,0,32,32) → 自勢力情報   (432,192, 208, 208)
熱區 3 (400,0,32,32) → 縮小地圖     (432, 32, 208, 160)
熱區 4 (432,0,32,32) → 系統         (208,112, 208, 192)
熱區 5 (464,0,32,32) → 沒有接東西（nullsub_1）
熱區 6 (0,0,640,32)  → 橫幅其餘部分，點了不做事
```

**左鍵開、右鍵關**（`sub_11BE0` 的 `cmp bx, 1`）。狀態存在 `byte_198A6`
的 bit 0–3，各視窗的繪製／擦除常式自己維護。

兩個容易讀漏的點：

1. **地圖是 640×368，不是右欄左邊那塊 432×336。** `sub_1D615` 的迴圈是
   40 欄 × 23 列的 16×16 格，捲動上限也是 639。視窗只是蓋在上面，
   關掉就露出底下的地圖。
2. **系統視窗開著時時間停止**（說明書 3.1）。另外三個不停。

## 2. remake 做了什麼

實作在 `cmd/wlgame/strategyhud.go`（`hudWindow`、`hitTestHUDSwitch`、
`hudOpen`／`hudSet`）與 `cmd/wlgame/main.go`（輸入分派、時鐘閘）。

### 2.1 資料

```go
type hudWindow uint8  // hudCommand / hudFaction / hudMinimap / hudSystem
g.hud hudWindow       // 開著的視窗集合，對應原版 byte_198A6 的 bit 0–3
```

系統視窗也佔一個位元。**`g.hud` 是主畫面視窗狀態的唯一來源**（§2.5）。

初值：**四個全關**（`g.hud = 0`）。這是原版數值——新遊戲流程
`sub_11A6E` 的最後一行是 `mov cs:byte_198A6, 0`（`docs/re/47` §3.3），
PC-98 實跑進到主畫面看到的也是滿版地圖。

說明書那張四個都開著的主畫面圖、以及參考影片的畫面，
都是玩家自己點開之後的狀態。

### 2.2 繪製順序

```
1. 大地圖 → (0, 32, 640, 368) ＝ 40×23 格
2. 橫幅   → (0, 0, 640, 32)，含五格開關圖示
3. 依 g.hud 由後往前疊四個視窗
```

地圖與視窗**不共用裁切**：視窗是不透明的疊層，蓋住哪就看不到哪，
與原版的格子屬性表（`docs/re/47` §3.2）等價。原版的髒格機制
**不移植**——那是為了避免整片重畫，remake 每幀重畫。

### 2.3 輸入

| 事件 | 行為 |
|---|---|
| 左鍵點熱區 1–4 | 開對應視窗（已開就維持） |
| 右鍵點熱區 1–4 | 關對應視窗（已關就維持） |
| 左／右鍵點熱區 5、6 | 不做事 |
| 點命令列（視窗開著時）| 照 [`12`](12-strategy-chrome.md) §2 分派 |

**視窗關著時它的內容不可點**：命中判定要先看 `g.hud`。
原版靠熱區圖自動達成（擦除時 `sub_1895D` 樣式 0 會把熱區清掉），
remake 直接在命中判定裡檢查。

### 2.4 時間

系統視窗開著時暫停時鐘。閘在主迴圈推進 tick 之前，與 `speed == 0`
（remake 的明示暫停）同一個判斷。

### 2.5 ⭐ 舊的 `g.open[]` 那一套整個拿掉（2026-08-15 裁定）

先前 remake 有**兩套主畫面視窗實作同時在畫**：

| | 舊：`g.open[4]` ＋ `windowRect` | 新：`g.hud` ＋ `drawNaturalStrategyHUD` |
|---|---|---|
| 命令 | 垂直選單 (208,112,208,192) | **命令列 (0,32,432,32)**，出自 `sub_1614A` |
| 自勢力情報 | (168,48,240,264) | **(432,192,208,208)**，出自 `sub_1895D` |
| 縮小地圖 | 靠右 (424,48,208,176) | **(432,32,208,160)** |
| 系統 | (208,112,208,192) | 同左（新舊都對）|
| 開關 | 鍵盤 1–4 | 橫幅五格，左鍵開右鍵關 |

三個矩形舊的都不是原版值，而畫面上兩套會疊起來——自勢力情報因此出現在
(172,50)。**使用者裁定：只留 `g.hud` 那一套。**

拿掉的東西：`windowKind`／`winCommand`／`winFaction`／`winMinimap`、
`windowRect`、`drawWindow`、`drawFactionWindow`、`lineWriter`、
`residentWindows`、`g.open`。

**唯一要搬過來的是系統設定面板的內容**（五列 ＋ 綠底值格）——
那是顯示清單場景 2，新那套只畫了框沒畫內容。搬進
`drawSystemWindow`，由 `hudSystem` 控制。

鍵盤 1–4 保留，但改成切 `g.hud` 的四個位元（remake 差異，見 §3）。

### 2.6 系統選單的版面（2026-08-15）

視窗 `sub_1895D(cx=0C0Dh)` → **(208, 112, 208, 192)**，
內容是顯示清單場景 2，原點 (216, 120)。座標見
[`docs/re/55`](../re/55-system-menu-window.md) §2。

| 元件 | 座標 |
|---|---|
| 標題 | (228, 124)，前景 `F` |
| 水平線 | (216, 142) 長 191 |
| 標籤的黑底 ×6 | (222, 150 + 24k) 128×20 |
| 標籤 ×6 | (232, 152 + 24k)，前景 `9` |
| 值格的兩圈框 ×6 | (350, 150 + 24k) 52×20 與 (351, 151 + 24k) 50×18 |
| 值 ×6 | (352, 152 + 24k)，**黑字綠底** |
| 熱區 `0x20`–`0x25` | (352, 152 + 24k) 48×16 |

六列：**資料儲存／畫面模式／音　　效／戰略速度／戰術速度／遊戲結束**。
原版第 1 列與第 6 列的值就是清單裡寫死的「 ＯＫ 」，中間四列由程式填。

remake 沿用這個形狀，把還沒接的功能寫成值（「未接入」）——
**不要因為沒做就把列拿掉**，那會讓缺口從畫面上消失。
先前 remake 只有五列，漏掉「遊戲結束」。

⚠ 值格**只有框沒有底**：底色是「 ＯＫ 」那個字串自己帶的
（`arg2` ＝ `5001`，[`docs/re/55`](../re/55-system-menu-window.md) §3）。

## 3. 不做的事

- **不移植髒格重畫**（§2.2）。
- **不改鍵盤路徑**：鍵盤 1–4 照舊可以開關，只是改成切 `g.hud` 的位元。
  原版的戰略層完全沒有鍵盤（[`docs/re/22`](../re/22-strategy-command-tree.md) §2），
  remake 的鍵盤是既有的 remake 差異，這一輪不動它。
