## 1. 單位：一點 ＝ 10 人

勢力記錄 `+0x04/+0x06/+0x08` 的三個 u16 存的是**點**，不是人數：

| 證據 | 內容 |
|---|---|
| `sub_14698` | 從預備兵扣掉的 `ax` 與寫進槽位的 `[si+1]` 是**同一個數** |
| 槽位寬度 | `[si+1]` 是 **1 byte**，而 `cmp ax, 64h` 把它夾在 100 以內 |
| `sub_15F7F` | 顯示時 `mov dx, 0Ah / mul dx`——**乘 10 只發生在畫面上** |
| `sub_155EC` | 池的上限 `0xFFDC` ＝ 65,500 點 ＝ 655,000 人 |
| 說明書 5.5 | 「一點 ＝ 10 人，滿編 100 ＝ 1,000 人」 |

所以一個滿編槽 ＝ 100 點 ＝ 1,000 人，六槽滿編 ＝ 600 點 ＝ 6,000 人。

## 2. 分配：`sub_14698`

編成畫面**不讓玩家指定每槽多少兵**。玩家只切兵種，兵力由這一支重算：

```asm
si += 28h                       ; → 六個槽，每槽 4 bytes：+1 ＝ 兵力、+2 ＝ 兵種
第一輪：數出每個兵種各佔幾個槽（兵種 4 ＝ 空槽，不算）
第二輪：對每個非空槽
  ax = 池[兵種]
  dx = ax mod 剩餘同型槽數 ; ax = ax div 剩餘同型槽數
  剩餘同型槽數 −−
  ax = ax + dx              ; **餘數全給第一個槽**
  if ax > 64h: ax = 64h     ; 上限 100 點
  池[兵種] −= ax
  [si+1] = al               ; 槽的兵力
```

三件事直接跟著這段走：

- **不會「兵不夠就編不出來」。** 池裡有多少就分多少，一點也算數。
- **餘數給第一個同型槽**，之後的槽再對剩下的重分。
- 上限是**每槽 100 點**，不是「每槽固定 100 點」。

## 3. 退兵：`sub_14717`

點任何一個槽都會先把六槽的兵**全部退回池**（`xchg al, [si+1]` 取走並歸零，
再 `sub_155EC` 加回去並夾在 65,500），然後那一槽的兵種 `+1`（1→2→3→1），
最後重跑 `sub_14698`。右鍵取消也是先全退再離開。

**退回是一點對一點**，沒有損耗。

## 4. 唯一的守門條件

`sub_16C92` 按「確定」時只檢查一件事：

```asm
cmp byte ptr [si+29h], 0    ; 槽 0（主將）的兵力
jnz → 成立
mov al, 93h / mov cx, 3Eh / call sub_18810   ; 否則出訊息，退回編成畫面
```

**只看主將槽**，其餘五槽可以是空的。這與壞滅判定同一個欄位
（`sub_1474A` 看 `[si+29h]`，[`docs/re/09`](../re/09-combat.md) §5）。

## 5. remake 要改什麼

`internal/state/corps.go` 的 `distributeReserves` 照 §2 實作，
`FormCorps` 呼叫它並只在主將槽是 0 時回錯誤。

先前那一版**扣 1000、放 100**——同一次編成從池裡扣掉的是放進槽裡的十倍。
劇本 0 曹操的池是 400／600／1000 點，照那個算法連一支軍團都編不出來。

現行行為：

| 項目 | 新行為 |
|---|---|
| 每槽兵力 | 照 `sub_14698` 分配，上限 100 點 |
| 扣池 | 扣掉**實際放進槽裡的點數** |
| 兵不足 | 不再是錯誤；分到多少算多少 |
| 錯誤條件 | **只剩一個**：分配完主將槽是 0 |

`army.MenPerUnit` 保持 1000（它的語意是「一個滿編槽幾個人」），
但 `FormCorps` 不再拿它當扣減量。
