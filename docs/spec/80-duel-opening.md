## 1. 觸發閘（`byte_1D34B`）

戰場初始化 `sub_19A33` 依**戰場編號**分類：

| 戰場編號 | `byte_1D34B` | 意義 |
|---|---:|---|
| `< 0xC0`（攻城＝據點編號）| 0 | 無單挑開場 |
| `0xC0`–`0xD0`（野戰，平原配對表前段）| **1** | **開場走單挑流程** |
| `≥ 0xD1`（其餘野戰＋水域）| 2 | 無單挑開場 |

主迴圈開頭 `sub_1A1C5` 等 50 tick，`byte_1D34B == 1` 才繼續。

## 2. 氣勢評估（`sub_1A34F`，帶亂數）

每側各算一次：

```
core = 大將戰力（單位記錄 +0x18，sub_19B6D 由軍團士氣寫入）
       × 大將體力（+0x03，開場＝士氣）                ；實質是士氣的平方
threshold = max(0, 大將武術×3 − 大將統率) ÷ 2      ；武術、統率取自武將記錄
if rand(0..7)+8 > threshold: core = 0               ；武人氣質門檻
氣勢 = core + rand(0..7)×256
```

⚠ `+0x18` 讀成「兵數」是被推翻的第一版（`CONTEXT.md` 推翻表）：
兵數多的一側永遠先挑戰，與實機兩輪錄影（氣勢＝士氣高的呂布先喊）相反。

高側為「強側」（同分不換，攻方在前）。

## 3. 流程（`sub_1A1C5` 逐條，2026-08-25 第二輪精讀定版）

```
每一場戰鬥開頭先空跑 50 tick（cx=32h 的 sub_1A04B 迴圈——實體照常更新，
但腳本直譯器與玩家輸入都在主迴圈裡，主迴圈還沒開始）
byte_1D34B ≠ 1 → 直接返回，主迴圈（腳本＋輸入）開始

強側氣勢 < 0x12C0（4800）           → 無事發生，正常開打
強側 ≥ 0x12C0：
  sub_1A398：強側喊組 0x1B7、**目標座標**寫成己側單挑位
  （攻 (0x18,0x20)／守 (0x28,0x20)）、**大將本人**下一命令＝8、等 40 tick
  腳本 PC += 6（跳過開頭「message／wait 15／message」，§3.2）
  弱側 < 0x12C0 或 < 強側一半：
      弱側喊 0x1B9（拒戰）、等 20、強側回 0x1CC → 立即清命令，正常開打
  否則（應戰，loc_1A341）：
      sub_1A398：弱側喊 0x1B8、目標＝己側單挑位、大將命令＝8、等 40
      兩側大將命令＝8、round＝0 → 回合迴圈：
      round r（情境碼上限 4，**迴圈本身無上限**，只有體力能結束它）：
        互嗆 pair（sub_1A3C3）：r==0 → 0x1BA/0x1BB、先講的是**強側**；
          r≥1 → 0x1BC+(r−1)×4、先講的是**體力高側**（差 < 0x14 再 +2）
          第一句 → 等 10 tick → 第二句 →
          **兩大將目標＝同一格 (0x20,0x20)**（會合點）
        對打段（sub_1A298）：計時 0x50；剩餘 ≥ 0x30 純等；
          之後每 tick 機率 0x20/256 把**兩大將目標**改成同一隨機格
          （先抽 y = rand&7 + 0x1C、再抽 x = rand&0xF + 0x18）
          每 tick 檢查任一大將體力 < 0x46（70）→ 決著
        歸位（loc_1A202）：兩大將目標＝各自單挑位、等 20 tick
          （每 tick 檢查體力）→ r++ 回到互嗆
決著（loc_1A23F）：
  體力低的一方為敗方；敗方目前命令≠5（退卻）才喊 0x1CC 並清命令
  等 20 → 勝方喊 0x1CD → 等 20 → 兩側清命令，主迴圈（腳本）開始
```

三個 2026-08-25 第二輪推翻第一輪的點，證據都是機器碼＋實機錄影
（`parity-duel1` 抽中應戰全程，d0–d11）：

1. **沒有任何瞬移。** `sub_1A398`／`sub_1A3C3`／`sub_1A298`／`loc_1A202`
   寫的全是單位記錄 `+0x10/+0x11/+0x14`（目標座標），大將**騎過去**——
   d2 挑戰喊話時已在半路、d5 兩騎會合、d7 對打段兩騎繞場互追。
2. **「開場凍結」的機制是腳本沒開始，不是實體凍結。**
   `sub_1A04B` 就是 `loc_1A065`（全實體更新）的包裝——實體每 tick
   照常更新；兩軍靜止是因為**初始命令 0（陣形）已就位**，而會下令的
   腳本直譯器（`sub_1A426`）在主迴圈裡，`sub_1A1C5` 沒返回它一步都不跑。
   玩家輸入同理被擋——**整段單挑是不可打斷的 modal**。
3. **命令 8 只掛大將本人**（`[si+1Bh]`＝側記錄 0／0x600 那一筆的
   下一命令），不是整隊。隊員維持命令 0 站在陣形位。

## 3.2 `word_1D311 += 6`＝抑制腳本自帶的開場喊話

`word_1D311` 是戰場腳本直譯器（`sub_1A426`）的 PC。BATTLE.DAT 的
**32 段腳本全部**以「message／wait 15／message」三個 2-byte 指令開頭
（實測 `workplace/parity/battle_prologue.py`）；挑戰成立時
`add cs:word_1D311, 6` 跳過它們——單挑已經喊過話，
腳本的開場對白不再重複。**confirmed**。

## 4. 命令 8 ＝「單挑中」：大將不聽別的、傷害走一般碰撞

隊長命令跳表 `funcs_1A7E1[8]` 與隊員表 `funcs_1A827[8]` 都是
**nullsub**——命令 8 的意義是「這個大將的目標座標由單挑碼控制，
命令分派不做事」。**移動與接觸命中都在命令分派之外的共通路徑**：
朝 `+0x10` 目標走一格的移動碼是每 tick 都跑的，而走進的格子
有敵人就打（`loc_1B5A1` → 兵 `sub_1B618`／大將 `sub_1B6BC`）。
所以兩大將被指到同一格時互相碰撞、用**一般命中公式**互砍——
單挑不需要任何專用傷害公式，`playtest` 錄影裡 4800 兵力差距下
夏侯惇照樣被磨到 0x46 以下敗陣。
