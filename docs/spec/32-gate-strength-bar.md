- 日期：2026-08-16

- 推論等級：confirmed

## 1. 原版做什麼

城壁或城門挨打時，**戰場區上緣**跳出「門強度」＋一條進度條，
顯示那個實體的剩餘耐久；20 幀之後自己收掉，右鍵也能提前收掉。

它不是常駐的 HUD——**不挨打就不存在**。

| 階段 | 位址 | 動作 |
|---|---|---|
| 建立 | `0001C43C`–`0001C479` | **開一個 (256,0,224×32) 的視窗**、清內容區 (264,8)-(471,23)、註冊熱區 `0x1D` 同一個矩形、畫「門強度」於 (264,8) 色 15 |
| 更新 | `0001C47B`–`0001C495` | `[di+0x18] < word_1C405` 才更新最小值、重畫條，並把到期時刻設成 `word_1D318 + 0x14` |
| 收掉 | `sub_1C4A6` | `word_1D326 ← 0xFFFF`、清熱區與顯示旗標 |

**只在更小的值出現時重畫**，所以這條只會往下掉，不會回升——
即使之後打到的是另一段耐久更高的城壁。

## 2. 演算法

```
# 挨打時（每個實體各呼叫一次）
if 到期時刻 == 未設定:                 # word_1D326 == 0xFFFF
    建立版面
    已畫過的最小值 = 未設定             # word_1C405 ← 0xFFFF
if 實體耐久 < 已畫過的最小值:
    已畫過的最小值 = 實體耐久
    畫條(實體耐久)
    到期時刻 = 目前幀 + 0x14           # 20 幀

# 每幀
目前幀 += 1
if 目前幀 == 到期時刻: 收掉

# 畫條（sub_1C4D2 → sub_10AAA）
長 = 0
if 實體記錄[+0x00] >= 0x80:            # 這一格有實體（0x0180 城壁／0x0280 門）
    長 = min(耐久 >> 4, 0x97)
在 (320, 16) 畫 0x97 ＝ 151 px 長、2 px 高：
    前 長 px 用調色盤索引 11，其餘用索引 0
```

⭐ **這條其實從來不顯示門的耐久。** 呼叫端 `0001B601` 有兩道閘：

```asm
0001B601  cmp cs:byte_1D34B, 0 / jnz 出   ; 只有攻城戰
0001B609  cmp byte ptr [di+1], 1 / jnz 出 ; ★ 只有實體類型 1 ＝ 城壁
0001B60F  call sub_1C407
```

所以上限 151（對應耐久 2,416）是為**城壁**設計的——攻城的城壁耐久是
`(據點 +0x13 + 50) × 10`，動輒上千。門的耐久只有 80，但它根本走不到這裡。
標籤寫「門強度」而顯示的是城壁，**照抄，不要改名也不要改倍率**。

⚠ `word_1D318` 是 **byte**，會在 256 回繞；到期判定用的是**相等**不是「≥」。
remake 的幀計數不回繞，而每幀固定 +1，所以相等判定等價。

### 2.2 ⭐ 那個矩形是一個**視窗**，不是裸露的黑底

三個矩形擺在一起就看得出來：

| 來源 | 矩形 |
|---|---|
| `sub_1D9D1(dx=0x10, bx=0, cx=0x20E)` 佔的顯示格 | (256, 0) 224 × 32 |
| `sub_1E3D7` 註冊的熱區 `0x1D` | (256, 0) 224 × 32 |
| `sub_10BCD` 清掉的範圍 | (264, 8)–(471, 23) |

外圈與內圈**每一邊都差 8 px**，而 8 正是外框圖塊的邊長
（`internal/assets/gfx` 的 `ChromeTile`）。也就是說清空的那一塊是
**視窗的內容區**，外面那一圈是標準外框——實機截圖上看得到那圈龍紋
（[`../playtest/49`](../playtest/49-parity-retest-20260827.md) §3.1）。

熱區與視窗同一個矩形，也解釋了 §2.1 那個「熱區比條大得多」：
它不是刻意放寬，**就是這個視窗本身**。

## 2.1 右鍵提前收掉：戰場區的右鍵熱區層

原版的熱區碼有**兩張分派表**（[`../re/60`](../re/60-tactical-sidebar.md) §10）：
左鍵 `cs:0xC048`、右鍵 `cs:0xC086`，索引都是熱區碼。
⭐ **左鍵表裡 `0x1B`／`0x1C`／`0x1D` 全是預設值（不做事）**——
點門強度條沒有反應，**要右鍵才有**（`TALK.DAT` #4「以滑鼠的右鍵回復。」）。

右鍵表只有四筆有 handler：

| 碼 | 原版 handler | remake |
|---|---|---|
| `0x1B`／`0x1C` | 雙方大將的名牌 → `sub_1C3B8` 收掉 | **不適用**：remake 沒有大將名牌 |
| **`0x1D`** | **`sub_1C4A6`：門強度條收掉** | 本節要做的 |
| `0x1F` | `sub_1C300` | **不適用**：那個碼**沒有註冊點**（[`../re/60`](../re/60-tactical-sidebar.md) §12：兩張表裡都有 handler，但找不到 `sub_1E3D7` 的呼叫點）|

所以這一層目前只有一格。**照原版的幾何做成一張表**，不要寫死成
「右鍵就收掉」——右鍵表本來就是按熱區碼分派的，之後補別的碼才不用重寫。

| 項目 | 值 | 出處 |
|---|---|---|
| 熱區 `0x1D` 的矩形 | **(256, 0, 224 × 32)** | `0001C43C`–`0001C479` 的註冊 |
| 動作 | 收掉門強度條（同 20 幀到期那條路）| `sub_1C4A6` |
| 熱區在什麼時候存在 | **只有條在顯示時**——建立版面時才註冊，`sub_1C4A6` 會清掉 | 同上 |

⚠ **矩形比條本身大得多**：條畫在 (320, 16)、151 × 2 px，而熱區涵蓋
(256,0)–(479,31) 整塊。**照抄矩形，不要縮到條的大小**——
原版讓玩家點那一帶就收掉，不必瞄準那條 2 px 高的線。

### 4.1 ⭐ AI 打不打得到城壁：兩件事各擋一半

拿據點 82 的攻城圖（軍團 81 攻、39 守，玩家站守方）跑 1,500 幀量過：

| | 現況 |
|---|---|
| 城壁（x ＝ 27，耐久 1,660）| **第 148 幀開始挨打**，之後幾乎每幀掉 1–3 點 |
| 條 | 第 148 幀亮起，之後一直被刷新 |
| 四道門（x ＝ 31、34）| 一次都沒被打到——攻方走的是城壁那一段 |

⭐ **兵撞到的東西不一定有實體。** x 38–45 是**抬高的地形**不是城壁，
而地形不會壞——`hitStructure` 被呼叫的次數遠多於實際造成傷害的次數，
這是正常的，不是缺口。

⚠ **攻方要走到城壁下需要 148 幀**，而條只亮 `0x14`（20 幀）。
沒有把取樣點對準這個窗口的截圖會什麼都拍不到，
而那看起來與「條壞掉了」一模一樣（[`../playtest/49`](../playtest/49-parity-retest-20260827.md) §3.1）。
