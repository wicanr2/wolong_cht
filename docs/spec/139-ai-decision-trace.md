## 1. 為什麼不能比數值

上一輪學到的（[`138`](138-state-table-parity.md) §4.1）：天災與內政帶亂數，
兩邊各自擲骰，**動態欄位只在同一個時刻可比**。跑幾天之後的資金、
生產力、城兵一定不同，而那不是規則分歧。

決策軌跡不一樣：它記的是「哪個勢力在哪一天推了哪一種事件、對象是誰」。
亂數只影響**時機**與**選中的對象**，**種類與產生條件**是規則決定的。
所以可比的是：

| 可比 | 不可比 |
|---|---|
| 哪些事件碼會出現（**一邊從不出現就是缺口**）| 出現的確切時刻 |
| 每種事件在一個月裡出現幾次（同一數量級）| 逐筆一一對應 |
| 發起方的分布（誰在動、誰不動）| 選中的對象 |
| 參數的形狀（對象是勢力還是據點、`0xFF` 哨兵）| 參數的值 |

⭐ **最有價值的是負結果**：某個 producer 在 remake 一次都不觸發，
就是一條沒接上的規則——`sub_12BD9` 的開局呼叫點漏接就是這樣被抓到的
（[`83`](83-initial-strategy-pass.md)）。

## 2. 原版側

```
tools/dosgolem.sh out "wait;click:320,200;click:300,151,300000;eventwatch;until:196/5/3"
```

`eventwatch` 在 `sub_12FBF` 裝 `OnCall`，每次推送印一行：

```
196年4月20日 7時 事件01 發起 13 對象  0 第二255 槽255（第 21437890 道指令）
```

| 欄 | 來源 |
|---|---|
| 事件碼 | `al` |
| 發起方 | `ah`（`sub_12FB1` 由 `si×4` 的高位元組組出來 ＝ 勢力編號）|
| 對象 | `dl` |
| 第二參數 | `dh`，`0xFF` ＝ 無 |
| 槽 | `bl`，`0xFF` ＝ 由 `sub_1ECE0` 亂數挑起點 |

⚠ **要在遊戲跑起來之後才裝**：事件佇列的段（`cs:word_10D20`）
開場之前還沒配好。

⚠ **預算要開大**：一個遊戲月約兩億道指令，預設 4,000 萬跑不完
（`WOLONG_DOSGOLEM_BUDGET`）。

## 3. remake 側

`World.queueEvent`／`queueFullEvent` 加一個可掛的回呼 `World.OnEvent`，
由 `cmd/wlsim -log-events` 開。**wlsim 不 import Ebiten**，
長跑不需要顯示器。

## 4. 驗證

| 方式 | 證據 |
|---|---|
| 種類覆蓋 | 兩邊出現的事件碼集合要相同；只在一邊出現的都要有解釋 |
| 次數量級 | 每種事件在同一段遊戲時間內的次數要同一數量級 |
| 發起方分布 | 有動作的勢力集合要相同 |

第一輪的結果在 [`../playtest/78`](../playtest/78-ai-decision-trace.md)：
`08`／`01`／`0C` 三種都出現、參數形狀完全相同、全部在月結觸發，量級一致。
