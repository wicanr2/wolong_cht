# 75 — 完整版要出得了聲

**狀態：CONFORMED。完整版收 32 個 ogg，`wlgame` 沒給 `-audio` 時會自己找執行檔旁邊的 `audio/`。**

- 日期：2026-08-23
- 出處：不適用（**這是發行與預設值的缺口，不是原版規則**）。
  音訊本身早就解完並與原版錄音比對過，見 [`29`](29-audio.md)
- 推論等級：不適用（工具／發行規格）

## 1. 問題

`cmd/wlgame` 的旗標是：

```go
audioDir := flag.String("audio", "", "ogg 音檔目錄（先跑 tools/bgm2ogg.sh 產生；留白＝靜音）")
```

**留白就是靜音**，而完整包裡一個 ogg 都沒有——`gamedata/` 是原版資料、
`fonts/` 是點陣字，音檔在 `workplace/audio/`（239 MB，gitignore）。
所以玩家解開就跑會**完全沒有聲音**，而且不會看到任何警告：
`-audio` 沒給就連「找不到音檔」都不會印。

⚠ **這是本專案第 21 條教訓的形狀**：沉默的成功比失敗難發現。
`sound.Open("")` 回一個可用的靜音物件，一切正常，只是沒有聲音。

## 2. 兩件事要一起改

**一、包裡要有音檔。** 完整版（`WOLONG_BUNDLE_DATA=1`）多收一個 `audio/`，
與 `gamedata/`／`fonts/` 同級（[`72`](72-bundled-game-data.md) §2）。

⚠ 音檔是**原版音樂的合成渲染**，屬於原版衍生資產——所以**只有完整版收**，
可散布批次一個都不收。這與 `gamedata/` 同一條界線。

**二、找得到就自己用。** 照 `resolveDataDir` 的形狀（[`72`](72-bundled-game-data.md) §3）：

```
resolveAudioDir(值):
    值 != ""                  → 值      # 明講一律優先
    <exe 目錄>/audio           → 它
    <exe 目錄>/../audio        → 它
    <exe 目錄>/../share/wolong-remake/audio → 它
    否則                       → ""      # 維持靜音，行為不變
```

⚠ **預設值是空字串不是路徑**，所以判準與 `-orig` 那支不同：
`-orig` 是「預設路徑不存在才找」，這裡是「**沒給才找**」。
兩支不要硬湊成一支——判準不同，湊在一起會讓其中一邊在某個情況下錯。

### 2.1 ⭐ 「留白＝靜音」是一道柵欄，不是疏漏

旗標旁邊本來就寫著：

> Ebiten 的音訊錯誤沒有可查詢的 API，沒有音效裝置時 `RunGame` 會**直接帶著
> ALSA 的錯誤結束**——無頭驗收與 CI 全部會掛。

第一版改動只做了「找得到就自己用」，於是完整包一裝好，
`tools/release_smoke.sh` 立刻掛掉：容器裡沒有音效卡，
遊戲開音訊 → `RunGame` 回錯 → `log.Fatal`，一張截圖都沒有。

⭐ **拆柵欄之前要先重建它擋住了什麼。** 這一次是照著「預設值看起來很蠢」
就動手，而那個預設值正是唯一擋住無頭環境的東西。

**第三件事**因此加進來：**驗收模式一律靜音**。

```
flag.Parse 之後：
    if -shot != "" 或 -frames-dir != "" → audioDir = ""
```

判準是**用途**不是環境：要截圖或錄影就不需要聲音，關掉沒有代價。
不用「有沒有顯示器」（Xvfb 有 DISPLAY 卻沒有音效卡），
也不猜 `/dev/snd`（那是平台細節）。
