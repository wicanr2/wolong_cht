# 87 — 半形語系的畫面調整（清單以外）

**狀態：CONFORMED（2026-08-26 實作並實跑驗過）。**

- 日期：2026-08-26
- 出處：這是 **remake 差異**，不對應原版機制。清單四家的欄界已在
  [`85`](85-latin-list-layout.md) 定案，本規格處理**其餘畫面**。
  語系機制見 [`84`](84-multilanguage.md)、執行期切換見 [`86`](86-runtime-language-switch.md)。
- 推論等級：版位是 remake 的設計決定；**可用寬度與撞號數是量出來的**（§4）。

## 2. A 類：原版美術上的中文**不翻**

下列中文是**原版圖庫的像素**，不是程式畫的字：

| 位置 | 出處 |
|---|---|
| 頂欄的「年」「月」「日」 | 橫幅圖，`drawBannerNumber` 只把數字填進去 |
| 金額鍵盤的「取消／最大/決定」 | 原版 96×64 資源；`amountPanelButtonLabel` 只在資源缺失時頂替 |
| 戰場六個指令鈕、下方六個編成格 | 原版側欄與指令列圖 |
| 將旗上的「軍」 | 將旗圖 |

翻譯它們等於**重畫原版美術**。這是保存專案（`CLAUDE.md` §1），
不重畫原版美術，所以英文版就是「介面英文、原版圖上的字保持原樣」。
**這一條要寫進英文版的說明**，否則看起來像沒做完。

## 3. B 類：程式畫得出來但詞表沒有

掃描 `cmd/wlgame`／`internal/ui`／`internal/rules` 的字串常數（排除旗標
說明與日誌），**65 條**沒有英文。其中會出現在畫面上的：

| 來源 | 內容 |
|---|---|
| `rules/speed` | 五個速度檔位（`最高速`…`最低速`）——系統選單的值欄 |
| `rules/persuasion` | 三個進言指令 ＋ 十一條理由 |
| `rules/tactical` | 四個兵種、五個指令、`門`、`被打壞了`、兩則勝負句 |
| `rules/diplomacy` | 七級外交關係 |
| `rules/economy` | 四種災害 |
| `rules/clock` | 四季 |
| `rules/army` | `先鋒` |
| `cmd/wlgame` | 遭遇視窗的三條、`ＳＡＶＥ　ＤＡＴＡ`／`ＬＯＡＤ　ＤＡＴＡ`、`Ｎ　Ｏ` |
| `cmd/wlgame` | **空欄記號** `－－－`／`－　　`／`－－　`。原版用全形破折號（48 px），英文欄位是半形排的，混一個全形進去會把欄界撐開——武將一覽的「身分」欄最明顯 |

處置：補進 `ui-en.json`（`ja`／`zh-hans` 一併，缺哪個補哪個）。

⚠ **語言選單的四個名字不進詞表**：`繁體中文`／`简体中文`／`日本語` 要
維持各語言自己的寫法（`86` §4）。詞表裡有它們就會在英文版被換掉。

## 4. C 類：組出來的字串查不到

`Drawer` 的翻譯鉤子是**整句**查表，而狀態列與遭遇視窗是**拼出來的**：

```go
line := who + " 對 " + against          // corps.go
g.lastEvent = lord + " 對我方宣戰"
g.lastEvent = g.adviseCmd.String() + " 成立"
```

名字先被 `big5()` 換成羅馬拼音，接縫的「 對 」留在原地——
所以畫面上是 `YUAN-YIN 對 CAO-CAO`。逐句表永遠不會命中，因為那一句
每次都不同。

**處置：詞表加一層「片語」。** `ui-<lang>.json` 新增 `phrases` 區塊；
`Convert` 在逐句與 `%d` 樣板都沒中之後，用**最長優先**把片語逐一替換掉，
有換到才回新字串。

```json
"phrases": { " 對 ": " vs ", " 對我方宣戰": " declares war on us", " 成立": " approved" }
```

三條約束：

1. **只動明列的片語**，不做任何自動切詞——這一層的風險全部來自
   「換到了不該換的地方」，把清單握在手上是唯一的控制方式。
2. **母本不做**（`ZhHant` 直接原樣回傳，與現在相同）。
3. 片語替換在字級表（zh-Hans）**之前**做，否則簡體字形已經換過，
   片語鍵（繁體）就對不上了。

## 5. D 類：戰場側欄的半形版位

標題格是 **128×32**（原版 (496,8)–(623,39)），兩行、每行 16 個半形格。
原版三段各三個全形字：`壽春`／`作戰`／`曹操`／`對`／`袁術`。

羅馬化之後放不下：地名最長 12 字、君主名最長 11 字，
「地名 ＋ 作戰」與「君主 ＋ 對 ＋ 君主」都超過 16 格，於是三段互相蓋掉
（`SHOUCHBNttle`、`CAO-CAOsYUAN-S`）。

**半形語系改成兩行的對戰列**：

| 行 | 內容 | 最長 |
|---|---|---|
| 0 | `<我方君主>` | 11 |
| 1 | `vs <對方君主>` | 3 ＋ 11 ＝ 14 |

**地名在半形語系不顯示**。三段擠不進兩行時，會撞名的那兩段優先——
君主名裁掉會讓兩個不同的人長得一樣，地名不顯示只是少一個資訊，
而戰場本身就畫在眼前。這一條記進 §7。

### 5.1 將旗上的主將名

名字欄原版是 `x=32, w=48`（三個全形字）。半形語系裁到 6 個字母時
**36 個名字會與別人撞號**（343 筆裡）；往左挪到 `x=16, w=64`（8 個字母）
之後降到 **10 個**——而 12 個字母（完整）的地板是 8 個
（同音不同字，裁不裁都一樣）。所以半形語系用 `x=16, w=64`。

再往左會蓋到旗子的 `▶`，再往右會蓋到「軍」，64 px 是這面旗上的上限。

## 6. E 類：TALK 變數的 key 用錯（真 bug）

`Part.Marker` 的值是 **ASCII `'1'`–`'7'`**（原版寫的是 `\` ＋ 數字，
`internal/assets/text/talk.go` §Part）。`marchmode.go` 傳的是：

```go
g.talkLines(0x15, map[byte]string{2: dest})   // ← 2 不是 '2'
```

於是 `Lines` 找不到變數、**fail-closed 回 false**，畫面退回內建的中文
`marchModePromptFallback`。**繁中看不出來**——那段 fallback 與 TALK #21
的中文一字不差。英文版才讓它現形：fallback 的中文被片語層換掉半句，
成了「向XUCHANG移動下。請下／battle orders.」。

`battletalk.go:209` 的 `map[byte]string{6: "", '6': ""}` 是同一個錯誤的
殘留（多寫了一個永遠用不到的 key），一併清掉。

> **教訓寫成規則**：**fallback 與正解長得一樣時，fallback 就是隱形的。**
> 退路要能被看見——測試要釘「這一則走的是 TALK 不是 fallback」，
> 不能只釘「畫面上有字」。
