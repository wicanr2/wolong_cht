| 值 | 座標 | 位數 | 色 | 來源 |

## 2. 互動

| 熱區 | 位置 | 作用 |
|---:|---|---|
| `0x3E`–`0x43` | (200, 192 + 16k) 24×16 | 六個槽，點一下**兵種 +1，1→2→3→1 循環**，然後全退回池重新分配 |
| `0x44` | (280, 272) 88×16 | 確定 |

**熱區與兵種圖示逐格重合**——與財政視窗同一種設計（[`14`](14-finance-window.md) §2）。
標籤與數字不可點。

## 3. remake 要做什麼

`cmd/wlgame/corps.go` 的 `drawForm` 照 §1 畫，`updateForm` 照 §2 收滑鼠。

| 項目 | 作法 |
|---|---|
| 視窗 | `chrome.Window(144, 112, 240, 192)` |
| 靜態層 | 照 §1.1 逐項畫；圖示用 `library.DOSVResourceIcon` |
| 動態層 | 照 §1.2；三處乘 10 用 `strategyReserveMenPerPoint` |
| **武將頭像** | `library.Portrait(General.Portrait, 季)` 貼在 (152, 120)。原版走 `sub_107D2` 的四格快取（[`docs/re/33`](../re/33-shared-draw-helpers.md) §2），remake 一次全載入，**只差在載入時機** |
| 兵種圖示 | 綠色組；**空槽要新的位移 `0x21A0`** |
| 士氣值 | 讀 `Faction.MoraleBase`，不是軍團的 `Morale`（軍團還沒建出來）|
| 總兵力 | 六槽已分配的兵力和，**照分配結果算**而不是「幾槽 × 1000」|
| **滑鼠** | 六個槽 (200, 192+16k) 24×16 點一下**兵種 +1 循環**（空槽 4 也在循環裡，`4 → 1`）；確定鈕 (280, 272) 88×16；**右鍵取消**（原版 `sub_121E7` 回 CF=1）|
| **背景的武將一覽** | 原版是「選武將 → 編成 → 回到選武將」的迴圈（[`docs/re/30`](../re/30-corps-formation-ui.md) §1），編成視窗畫在一覽表**上面**，一覽表不會被擦掉。remake 照做：編成畫面開著時一覽表留在背景且不吃輸入，編成完或取消就回到一覽表繼續選下一位 |
| **主將沒兵** | 走 TALK **#62**「大將的部隊的兵員不足啊。」的訊息框（原版 `sub_18810(cx=3Eh)`），不是自畫一行紅字 |
| 選取框 | 原版沒有選取狀態。remake 保留鍵盤上下選槽，**選取框只在用過鍵盤之後才畫**——滑鼠操作時畫面與原版一致 |
| 兵種切換 | remake 保留 `1`／`2`／`3` 直接指定 ＋ 空白切空槽；原版是點一下 +1 循環。**兩者到 state 的結果相同**（都是設定槽的兵種再重跑分配）|

⚠ **總兵力這一格會暴露分配式有沒有接對。** 原版顯示的是六槽 `+1` 的和 ×10，
所以兵不夠時它會小於「槽數 × 1000」——[`21`](21-corps-formation-reserves.md)
修好之前這裡永遠顯示滿編，看不出差別。

**畫面上不放操作提示。** 原版的六個槽與確定鈕都是滑鼠熱區（§2），
鍵盤是 remake 加的便利，不需要在版面裡佔一個框說明它。
