# 204：年份上界在 999 與 1000 間交替

**狀態：CONFORMED。Go 年份修正通過冷測與全部 65,536 個 16-bit 年份入口對照。**

- 日期：2026-10-08
- 原版 KI.EXE SHA-256：`fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`
- 工具與位址：IDA 9.4 線性 `0x11DAA`–`0x11DBC`；dosgolem 原始 `sub_11D8E`
- 檔案偏移：`0x1FAA`–`0x1FBC`，右界不含
- 原始 bytes：`813ef60ce803 7206 c706f60ce603 ff06f60c`

## 1. 證據與審查

`cmp year,0x3E8; jb` 在年小於 1000 時跳過重設，之後仍執行 INC。
所以 999 合法增為 1000。年已達 1000 或以上才寫 998，再 INC 到 999。

| 初始年份 | 原版換年 | 修改前 Go |
|---:|---:|---:|
| 998 | 999 | 999 |
| 999 | 1000 | 999 |
| 1000 | 999 | 999 |
| 1001 | 999 | 999 |
| 65535 | 999 | 999 |

original probe 使用原始 137 bytes，四個 callee 換為明示 RET fixture，入口 12/31、23 時、
子刻 8、速度 0。probe 記於 `workplace/matching-decompilation/c-clock/year-probe.json`。
此隔離只量進位與呼叫，沒有正常玩家或 callee 行為的完成聲明。

## 2. 規則變更

Go `MaxYear` 表示可觀察最高年 1000。`Advance` 換年時，入口年份 `>=1000` 先設 998，
再增為 999；999 則增為 1000。保留二月 28 日與其餘日期規則。
這是原版對齊，不新增年份設計或隱藏更換完成標準。

## 3. 驗證

單元測試要比 999→1000→999 的連續兩次換年，以及 1001／65535 的入口處理。
C 時鐘對照已枚舉全部 16-bit 年份入口；原版、C 與修改後 Go 均相同。
