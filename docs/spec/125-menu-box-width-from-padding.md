# 125 — 選單框的寬度要用**沒有切掉補位空白**的那一行

**狀態：CONFORMED。** 框寬 ＝（那一行有幾個全形字 ＋ 1）格，
而原版把每一列補到等寬——**補位的全形空白就是版面**。
`text.Decode` 為了定長欄位把行尾的全形空白切掉，於是
`TALK #79` 的「　位置確認　」變成 5 個字，框窄了 16 px。

- 日期：2026-09-03
- 實機證據：`workplace/promo-live/parity-tap5/menu.png`
  （選單框佔遊戲座標 x 192–303 ＝ **112 px**，`docs/playtest/60`）
- 出處：[`45`](45-advise-scene-layout.md) §2.2（`loc_19409` 數字數、
  `sub_19479` 換成框）
- 推論等級：**confirmed**（算式在反組譯裡，寬度逐像素量到）
- 相關：[`124`](124-menu-highlight-xor.md)（同一張截圖抓到的另一件事）

## 1. 原版做什麼

```asm
loc_19409:  ; 數第一列有幾個全形字
        mov ax, [di] / inc di / inc di / inc cl
        and al, al / jnz →          ; 一次兩個 byte，數到低位元組是 0
        dec cl                      ; cl ＝ 全形字數（含補位空白）
sub_19479:
        inc cl / inc ch             ; 寬 (字數+1) 格、高 (列數+1) 格
```

`TALK #79`（軍團的兩項）存的是：

```
　位置確認　      ⇒ 6 個全形字 ⇒ 框寬 (6+1) × 16 = 112
　行軍指示　
```

⭐ **兩邊各一個全形空白是為了置中**，不是排版噪音——
`#77`（進言五項）、`#102`／`#166`／`#230`（說服理由）、`#82`（據點兩項）
全部補到 6 個字（[`45`](45-advise-scene-layout.md) §2.2 的 ⭐ 已經寫過這一條）。

## 2. remake 錯在哪

兩層各錯一次，疊起來讓框窄了 32 px：

| 層 | 問題 |
|---|---|
| `cmd/wlgame/corps.go` | `corpsMenuLabels` 是**寫死在 Go 原始碼裡**的 `{"位置確認", "行軍指示"}` ——沒有讀 `TALK #79`，也就沒有補位空白（4 字 ⇒ 80 px）。這同時違反「玩家看得到的文字不進 Go 原始碼」（`CLAUDE.md` §6）|
| `internal/assets/text` | 就算讀了，`Decode` 的 `TrimRight(…, "\x00　 ")` 會把行尾那一格切掉（5 字 ⇒ 96 px）|

⭐ **第二層特別難發現**：`internal/ui/talkmenu` 的註解本來就寫著
「⛔ 不要 trim，那些全形空白是版面的一部分」——**意圖寫對了，
而上游一層默默把它做掉了**。四則既有的選單剛好都有一列沒有補位
（`#77` 的「請求君主出陣」是滿滿 6 個字），取所有列的最大值就繞過去了，
所以錯了很久都沒有症狀。`#79` 兩列都補位，繞不過去。

## 3. remake 怎麼改

| 項目 | 位置 |
|---|---|
| 不切補位空白的解碼 | ✅ `text.DecodeKeepPad`（只切 NUL）|
| 不切補位空白的取行 | ✅ `text.Table.MenuLines` |
| 選單標籤 | ✅ `talkmenu.MenuLabels`（保留補位）／`talkmenu.Labels`（切掉，給「把標籤接進另一段文字」的地方用）|
| 軍團兩項 | ✅ `game.corpsMenuLabels()` 讀 `TALK #79`，fallback 也補位 |
| 差異 | 無 |

⚠ **兩支不能合併。** 手機版的標題是 `名稱 + "：選對象"`，
帶著補位空白會多出一個洞——那裡要的就是切過的版本。
**「切不切」由用途決定，不是由資料決定。**
