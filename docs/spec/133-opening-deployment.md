# 133 — 開場擺位：邊界那一欄 ＋ 亂數 Y

**狀態：CONFORMED。** 算式與值域都有機器碼出處，另有執行期逐兵量測當正對照；
`Battle.Spawn` 已實作、接上遊戲路徑，四支測試。
量到的形狀與原版一致：**X 全在邊界那一欄、Y 落在 16–47、44 個兵重疊**。

- 日期：2026-09-05
- 出處：[`../re/87`](../re/87-opening-deployment.md)（`sub_19C45`）、
  [`../re/11`](../re/11-tactical-battle.md) §3.6（`+0x06`／`+0x08`）
- 推論等級：**confirmed（靜態 ＋ 執行期）**

## 1. 原版怎麼做

每個兵在開場被放到**戰場邊界那一欄**：

```
X ＝ 側 0 → 1；側 1 → 0x3E（62）      ← 兩個寫死的立即值
Y ＝ rnd() & 0x1F + 0x10             ← 16–47 均勻分佈
+0x07／+0x09（上一格）＝ 同值
不查佔用：同一格可以有好幾個兵
這一隊沒人可派時 +0x00 ← 0（空格），有人就 −1 並寫 0x80
```

之後他們**自己走進陣形位置**（命令預設是陣形）。
[`../playtest/73`](../playtest/73-opening-deployment-parity.md) 量到：
節拍 0 時側 0 全部在 `X=1`、節拍 9 已經散到 `X 1..5`。

## 2. remake 要做什麼

| 項目 | 作法 |
|---|---|
| 新增 `Battle.Spawn(rng)` | 照 §1 擺位：`X` 依側寫死、`Y = rng&0x1F + 0x10`、不查佔用 |
| `Place()` **保留** | 它是「直接放到陣形位置」，測試與無頭模擬繼續用——**兩支不要合併**，它們回答不同的問題 |
| 呼叫端 | `internal/state/tactical.go` 的 `beginTactical` 由 `Place()` 改成 `Spawn()` |
| **擺哪一邊** | ⚠ **看陣形線，不看側的編號**，見 §3.5 |
| 走進去 | 沿用既有的「命令＝陣形 → 走到 `formationSpot`」那一段，不必新增 |

## 3.5 ⚠ 擺哪一邊要看陣形線，不看側的編號

原版的**側 0 恆為玩家**，而且玩家守城時整個戰場轉 180 度
（[`../re/11`](../re/11-tactical-battle.md) §3.6、[`56`](56-battlefield-rotation.md)），
所以「側 0 → `X=1`」在原版的座標框裡永遠成立。
**remake 的 `Sides[0]` 恆為攻方**，照側號擺會把兩邊各丟到**對面那一端**。

⇒ 判準是**那一側的陣形線在哪一端**（`Sides[i].Line`）。

### ⚠ 這個錯誤的症狀是「攻城戰打不完」

第一版照側號擺，`TestSiegeFixtureTerminates` 從「第 1,192 幀結束」變成
**跑滿 60,000 幀還沒結束**，而且**剩餘兵數一個都沒變**（588／500）。

⭐ **當時的第一個假說是錯的**：以為是「同一格疊了好幾個兵、`tryMove`
彼此讓不開」。實際上把每個兵的狀態印出來就看到——他們的目標在
**59 格外**，走到一半**體力歸零**（`力0`）就停住了。
**「卡死」的第一個假說最貴**：它指向移動層，而真正的錯在一行擺位。
判法很便宜：印五個兵的 `座標 → 目標 令 體 力`，一眼就看出目標在對面。

## 3.6 判準：亂數沒同步時看值域，同步了就看全等

`Y` 是亂數。**兩邊的亂數流同步得起來**——`wlgame` 的 `-battle-exact`
吃 `-rng-state`（原版 `0x19C45` 擺位前的 258 byte），
[`../playtest/114`](../playtest/114-focus-and-same-battle.md) 用它逐槽核對過
**兩案例各 96 槽的座標與體力都相同**。

所以判準分兩種：**同步了就要全等**；沒同步（一般的 `-open-battle`／
`-open-siege` fixture）就只能看值域與落點，硬對只會逼出一個假的 seed 對齊：

| 檢查 | 門檻 |
|---|---|
| `X` | **全部**等於 1（側 0）／62（側 1）|
| `Y` | **全部**落在 16–47 |
| 重複 | **允許**（原版不查佔用，同一格會有好幾個兵）|
| 空格 | 那一隊人數不足 8 時，多出來的槽 `Alive = false` |

⭐ 沒同步亂數時，逐兵**全等**只在「兩邊都已經走進陣形」之後才有意義——
那時位置由陣形表決定，與亂數無關。

## 6. 同一亂數流的逐槽順序（CONFORMED，2026-09-08）

使用者指定完整同狀態戰況，不跑全局通關。dosgolem 的新收據
`workplace/same-battle-20260908/original-siege-2/` 保留執行期存檔區塊、
258 byte RNG、96 筆單位與完整 32 byte 原記錄。
工具版本與原始 KI.EXE 身分沿用 re/87；位址為 IDA DOS/V linear。

證據審查：`rng-calls-initialized.json` 中，前 96 次 RNG 呼叫的返回位址均為
`19C5B`，SI 從 `0000` 每次加 `20h` 到 `0BE0`：玩家 48 槽先於對方 48 槽。
re/87 的 `19C58` 也證明取亂數先於 `19C81` 的待機數判定，空槽仍消費一次。
新初始化原記錄的 `+1A/+1B` 全為 `01/00`，第一拍才套用待處理的陣形令。
上述屬已證實；不能把原本「不同亂數源無法逐兵全等」的限制套用到已搬入同一 RNG 的實驗。

實作契約：Spawn 依玩家側、對方側順序掃各 48 槽，空槽亦取數；
在場者初始化為目前攻擊令、待處理陣形令。陣形線仍決定 X，不改攻守索引。
不得搜尋 seed 或任意跳過亂數來湊畫面；旗幟使用既有 BannersFor 的實際掃描與共享 RNG。
驗收須比 96 筆開場座標、命令、體力與 RNG；後續移動及結算分歧另外列出，不能冒稱全場一致。
