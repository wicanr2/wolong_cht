## 1. ⭐ 日文不是翻譯，是原版

PC-98 日文原版與松崗繁中版是同一份程式的兩次編譯（`CLAUDE.md` §4.05），
`TALK.DAT` 逐則對應、`SINARIO.DAT` 逐槽對應。所以日文語系包的作法是
**把原版讀出來**，不是把中文翻回日文：

| 東西 | 來源 |
|---|---|
| 1,022 則訊息 | `workplace/orig/pc98/TALK.DAT`（Shift-JIS → UTF-8）|
| 人名與地名 343 筆 | `workplace/orig/pc98/SINARIO.DAT` 的武將 `+2`／據點 `+2` |
| UI 詞 | PC-98 `KI.EXE` 的日文字串（`拠点`／`軍団`／`信頼度`…）|

⚠ **變數標記的順序與中文不同不是錯**：`{1}的兵馬向{2}進攻` 在日文是
`{2}に{1}の軍勢が`。驗收要比**集合**不是序列（`tools/langpack.py` 的
`marker_set`）——比序列會得到一則假警報。

### 1.1 ⭐ PC-98 的外字：靠兩版對齊反推

日文人名裡有 34 個 **Shift-JIS 未定義的碼**（`0xEC40`–`0xEC65`）。
那是 PC-98 的外字區：`汜`、`瓚`、`繡`、`傕`、`廮` 這些三國專用字不在
JIS X 0208 裡（多數只在 JIS X 0212，`傕`／`廮` 兩者皆無），原版自己帶字形。

**外字碼本身不帶語意**，但兩版逐槽對應——同一個位置，繁中版是什麼字，
那個外字碼就是什麼字。343 個名字逐字對齊，**34 個碼全部反推出來、
零衝突、零對不上**（`tools/namepack.py ja`，表存在 `names-ja.json` 的
`gaiji` 欄）。

呈現時這些字交給字型鏈：JIS 字型沒有 → 退到倚天 Big5 字型（§2）。

## 2. 一個語系由四樣東西組成

| 元件 | zh-Hant（母本） | zh-Hans | ja | en |
|---|---|---|---|---|
| talk 表（1,022 則）| `talk-dosv-corrected.json`（cp950）| `talk-zh-hans.json`（OpenCC t2s ＋ `corrections-zh-hans.json` 校訂）| **`talk-ja.json`（PC-98 原版）** | `talk-en.json`（逐則英譯）|
| 人名地名（343）| 原版 Big5 | 字級 t2s 表 | **`names-ja.json`（PC-98 原版＋外字反推）** | `names-en.json`（漢語拼音）|
| UI 詞（377）| 原文即母本 | 字級 t2s 表 | `ui-ja.json`（**取自 PC-98 `KI.EXE` 的原版用詞**）| `ui-en.json` |
| 全形字型 | 倚天 `STDFONT`＋`SPCFONT` | `HZK16` → 倚天 | `JISKAN16` → 倚天 | 半形 `ASCFONT` ＋ 倚天 |

### 2.1 三個決定

**一、字型是鏈不是單一來源。** 語系的字集不等於一份字型的字集：
日文名裡的外字不在 JIS X 0208 但在倚天 Big5 裡有，所以
`JISKAN16 → 倚天` 這條鏈才畫得全（`textdraw.Chain`）。
字型一律**使用者自備**（與倚天同一個政策），缺檔時退下一份、
再缺就畫空心方框——**缺字要看得出來**。

**二、語系轉換掛在「畫的那一刻」與「解碼的那一刻」兩個出口。**
介面字串散在幾十個檔案的 literal 裡，一個一個包起來一定會漏：

| 出口 | 涵蓋 | 位置 |
|---|---|---|
| `textdraw.Drawer.Draw` 的 `translate` | 所有畫出去的 UI 詞 | `SetTranslator` |
| `cmd/wlgame` 的 `big5()` | **人名、地名、君主名**（69 個呼叫點）| `uiLang.Convert` |

代價是**版面已經先用原文算好了**——英文比中文窄，框會偏大不會破版；
真正要重算版面是後續工作（§6）。

**三、數值欄位要用樣板查。** UI 的數字是 `Sprintf("兵 %d", n)` 先組好才畫的，
畫到語系層時看到的是 `兵 300`，逐句詞表查不到。`uitext` 把數字抽回 `%d`
查樣板、命中再依序填回去；`%d` 個數對不上就放棄（寧可顯示原文，
也不要把數字擺錯位置）。

### 2.2 踩到的三個坑

| 症狀 | 成因 |
|---|---|
| 日文有字形但整片糊掉 | PCF 的**每一列補齊到 glyph pad**（16 寬用 int 對齊 ＝ 一列 4 byte、一個字 64 byte）。照 32 byte 硬讀＝每列只取前半 |
| `struck {2}.` 顯示成 `struckXUCHANG.` | `text.Decode` 對 Big5 要切掉定長欄位的補位空白，**但 UTF-8 語系包的尾端空白是內容** |
| 英文被切成 `STRATEGI` ＋ `ST` | 折行對中文是逐字斷，拉丁字母不行——要退回最後一個空白（單字本身超過一列時才硬切）|

## 4. 人名怎麼羅馬化

使用者裁定（2026-08-26）：**用三國人物名稱的拼音**。實作規則：

| 規則 | 例 |
|---|---|
| 大寫，姓與名以連字號分隔 | `曹操` → `CAO-CAO`、`劉備` → `LIU-BEI` |
| 複姓當成一個整體 | `諸葛亮` → `ZHUGE-LIANG`（不是 `ZHU-GE-LIANG`）、`司馬懿` → `SIMA-YI` |
| **地名不分隔**，且用詞組讀音 | `成都` → `CHENGDU`、`長安` → `CHANG'AN`（不是 `ZHANGAN`）|
| 隔音符號 | 後一個音節以 a／o／e 起頭時加 `'`：`西安` → `XI'AN` |
| 姓氏與地名的專讀逐條覆寫 | `樂進` → `YUE-JIN` 但 `樂成` → `LECHENG`；`會稽` → `KUAIJI`；`劉禪` → `LIU-SHAN`；`孫乾` → `SUN-QIAN` |

⚠ **pypinyin 的詞組字典是簡體鍵**：繁體字串查不到詞組會逐字退回常用讀音
（`長安` 變 `ZHANGAN`）。先轉簡體再查拼音，key 仍保持繁體。
