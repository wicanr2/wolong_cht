## 1. `sub_14D63` 逐行

```asm
00014D63  cmp byte [si+19h], 0FFh / jz →   ; 沒有內政官就什麼都不做
00014D6F  mov bh, 0FFh / xchg bh, [si+19h] ; ★ 據點的內政官槽清成 0xFF
00014D74  bx = 武將 × 32 + 4240h
00014D7E  mov byte [bx+17h], 0             ; ★ 那名武將的「出陣中」歸零
00014D86  call sub_10CE7                   ; 變數表 ＝ [武將記錄, 據點記錄]
00014D89  cx = 44h  / al = 93h  / sub_18810 ; TALK #68，一般通知的肖像
00014D93  cx = 1A6h / ah = [bx+1Eh] / al = [bx+1] / sub_18810
```

兩個欄位、兩則訊息，沒有別的效果——**內政官不會被降職或處分**，
只是回到「沒有職務」的狀態。

## 2. 第二則不是 #422

`cx = 0x1A6` 落在八格變體的範圍裡，實際索引是

```
0x196 + (0x1A6 − 0x196) × 8 + 變體 ＝ 534 + 變體
```

（[`../re/66`](../re/66-message-box-geometry.md) §4.1）。534–541 那一組正是
內政官的懊悔：537「至今的投資全都白費了！！」、
538「如果多調派兵馬，也許就不會淪陷了．．．」、
539「好不容易所做的內政．．．真叫人不甘心！！」、540「真不甘心．．」、
541「無法徵集到守備兵力是我的責任，實在抱歉之至．．．」。

⚠ **把 `cx` 當成「第幾則」會落在 #422「．．．．」**——
而 `0x1A6` 的十進位正好就是 422，所以**組編號與那個誤讀的索引長得一模一樣**，
只能靠算式分辨、不能靠看數字。誤讀的結果語意上還說得通（一句省略號），
錯了不會有人發現。
變體索引是**武將 `+0x1E` 的原始值 0–7**，不是說話型那個折過的 0–2。
