# 146 — 大地圖上會飄的雲：物件 type 0，而且型別表整體差一格

**狀態：CONFORMED。** 大地圖上一直有 **16 朵會飄的雲**（`MMAP.MCH` 物件 type 0，
16×9 格），記錄存在劇本／存檔區塊的 `0x21C0`，由 `sub_12459` 每次
map-loop 推進、`sub_12533` 繪製。remake **完全沒有畫它們**。
順帶抓到一個真的缺陷：**物件型別查表整體位移了一格**，
所以 remake 把火災畫成雲的圖形、把暴動畫成火災的圖形。

## 1. ⚠ 型別表的 base 是 type 0，不是 type 1

`sub_12533` 的查表算式：

```asm
mov bl, [si+0Eh]        ; bl = 物件 type
xor bh, bh / shl bx,1 ×3 ; bx = type × 8
mov al, [si+0Fh]        ; al = 相位
add bl, al              ; bx = type × 8 + 相位
mov bl, cs:[bx-67A6h]   ; ← type 0 相位 0 ⇒ 0 − 0x67A6 ＝ cs:985Ah
```

`bx = 0` 時位址就是 `cs:985Ah`，**所以 `985Ah` 那八個 byte 是 type 0**：

| type | `cs:985Ah` 起 | MCH pattern | 尺寸 | 語意 |
|---:|---|---|---|---|
| **0** | `+0` | `18 19 1A 1B 1C 18 19 1A` | **16×9 格** | **雲**（常駐 16 個）|
| 1 | `+8` | `20 21 22 23 20 21 22 23` | 5×5 格 | 火災（`sub_134B1` 的 `ah=1`）|
| 2 | `+16` | `28 29 2A 2B 28 29 2A 2B` | 5×5 格 | 暴動（`ah=2`）|
| 3 | `+24` | `00 00 00 00 00 00 00 00` | 3×3 格 | 未見產生端 |

[`../re/14`](../re/14-mmap-mch-objects.md) §4 把這張表整體標成 type 1／2／3，
`internal/assets/world/mmapmch.go` 的 `ObjectPatternIndex` 照著寫成
`(objectType-1)*8+frame`。**結果是火災畫成 16×9 的雲、暴動畫成火災的 5×5 圖。**

## 2. 那 16 朵雲

物件表在段內 `0x2040`，**32 筆 × 16 B**（區塊位移 `0x20C0`，
＝ 段內位移 ＋ `0x80`）。前 16 筆給 `sub_123FF` 配置火災／暴動，
**後 16 筆（段內 `0x2140`／區塊 `0x21C0`）是雲，永遠是啟用的**。

`SINARIO.DAT` 劇本一的 `0x21C0` 起：

```
80 00 1B 00 0B 00 00 00 00 00 00 00 01 10 00 00
80 00 6C 00 41 00 00 00 00 00 00 00 01 10 00 00
…共 16 筆
```

| 位移 | 語意 |
|---|---|
| `+0x00` | 旗標，bit 7 ＝ 存在、bit 0 ＝ 這一幀要換相位 |
| `+0x02` | X（有號 word，地圖格）|
| `+0x04` | Y |
| `+0x08`／`+0x0A` | 漂移的固定點累加器（`sub_124FF`）|
| `+0x09`／`+0x0B` | 同一個 word 的高 byte ＝ 方向 |
| `+0x0C` | 倒數計時器 |
| `+0x0D` | 計時器重載值（雲是 `0x10`）|
| `+0x0E` | 物件 type（雲是 **0**）|
| `+0x0F` | 相位 0–7 |

**`sub_12459` 每次 map-loop 對 32 筆各減一次計時器**；歸零就重載、設
bit 0，而且 **`si ≥ 0x2140`（後 16 筆）才另外呼叫 `sub_1248A` 移動**。
`sub_1248A` 把座標夾在暴風雨矩形 `word_10D22`–`10D28` 內並反向——
沒有暴風雨時那個矩形是 `(−16,−16)`–`(400,400)`，也就是整張地圖，
所以雲平常在全圖飄，**起了暴風雨才被關進那 11×11 格**。

繪製在 `sub_12533`：左上角 ＝ `(X − 寬/2, Y − 高/2)`，MCH 圖塊自帶 mask，
所以雲是**半透明的網點**——奇數列蓋灰白、偶數列留地形，
這正是逐像素對拍時看到的樣子。

## 3. 現場證據

`root-saveb` 第 1 槽跑到 196 年 4 月 21 日 8 時，`peek:2754:2140:256` 讀出
16 筆全部 `+0x0E = 0`（type 0），其中**只有一筆落在畫面內**：

```
80 00 15 01 A4 00 00 00 0A 02 F2 00 0E 10 00 00
        └ X=0x0115=277  └ Y=0x00A4=164        └ type 0, 相位 0
```

用專案自己的解碼器把 pattern `0x18` 疊到鏡頭 (271,153) 的地形上、
中心格 (277,164)，再與同一刻的原版畫面逐點比：

| | 與原版不同的像素 |
|---|---:|
| 只畫地形 | 11,712 |
| **地形 ＋ 那朵雲** | **358** |

剩下的 358 是 `RenderWorld` 不畫的據點與軍團標記（同一份基準的空白對照
是 346）。**位置、尺寸、置中、mask 一次全對。**

| 檔案 | 改了什麼 |

| `cmd/wlgame/main.go` | `drawDisasterOverlay` 依快照的 `TypeCode` 取 pattern 並以 `(X−寬/2, Y−高/2)` 畫；雲不掛在據點上 |

⚠ **火災／暴動的圖形會跟著換**（5×5 而不是 16×9）——那是修正不是回歸，
既有截圖若有火災要重拍。
