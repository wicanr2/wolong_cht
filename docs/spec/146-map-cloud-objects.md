# 146 — 大地圖上會飄的雲：物件 type 0，而且型別表整體差一格

**狀態：CONFORMED。** 大地圖上一直有 **16 朵會飄的雲**（`MMAP.MCH` 物件 type 0，
16×9 格），記錄存在劇本／存檔區塊的 `0x21C0`，由 `sub_12459` 每次
map-loop 推進、`sub_12533` 繪製。當時 remake 完全沒有畫雲，已依 §4 接上；
讀檔後火災／暴動的呈現缺口另由 §7 修正。
順帶抓到一個真的缺陷：**物件型別查表整體位移了一格**，
所以 remake 把火災畫成雲的圖形、把暴動畫成火災的圖形。

## 1. ⚠ 型別表的 base 是 type 0，不是 type 1

`sub_12533` 的查表算式：

```asm
mov bl, [si+0Eh]        ; bl = 物件 type
xor bh, bh / shl bx,1 ×3 ; bx = type × 8
mov al, [si+0Fh]        ; al = 相位
add bl, al              ; bx = type × 8 + 相位
mov bl, cs:[bx-67A6h]   ; ← type 0 相位 0 ⇒ 0 − 0x67A6 ＝ cs:985Ah
```

`bx = 0` 時位址就是 `cs:985Ah`，**所以 `985Ah` 那八個 byte 是 type 0**：

| type | `cs:985Ah` 起 | MCH pattern | 尺寸 | 語意 |
|---:|---|---|---|---|
| **0** | `+0` | `18 19 1A 1B 1C 18 19 1A` | **16×9 格** | **雲**（常駐 16 個）|
| 1 | `+8` | `20 21 22 23 20 21 22 23` | 5×5 格 | 火災（`sub_134B1` 的 `ah=1`）|
| 2 | `+16` | `28 29 2A 2B 28 29 2A 2B` | 5×5 格 | 暴動（`ah=2`）|
| 3 | `+24` | `00 00 00 00 00 00 00 00` | 3×3 格 | 未見產生端 |

[`../re/14`](../re/14-mmap-mch-objects.md) §4 把這張表整體標成 type 1／2／3，
`internal/assets/world/mmapmch.go` 的 `ObjectPatternIndex` 照著寫成
`(objectType-1)*8+frame`。**結果是火災畫成 16×9 的雲、暴動畫成火災的 5×5 圖。**

## 2. 那 16 朵雲

物件表在段內 `0x2040`，**32 筆 × 16 B**（區塊位移 `0x20C0`，
＝ 段內位移 ＋ `0x80`）。前 16 筆給 `sub_123FF` 配置火災／暴動，
**後 16 筆（段內 `0x2140`／區塊 `0x21C0`）是雲，永遠是啟用的**。

`SINARIO.DAT` 劇本一的 `0x21C0` 起：

```
80 00 1B 00 0B 00 00 00 00 00 00 00 01 10 00 00
80 00 6C 00 41 00 00 00 00 00 00 00 01 10 00 00
…共 16 筆
```

| 位移 | 語意 |
|---|---|
| `+0x00` | 旗標，bit 7 ＝ 存在、bit 0 ＝ 這一幀要換相位 |
| `+0x02` | X（有號 word，地圖格）|
| `+0x04` | Y |
| `+0x08`／`+0x0A` | 漂移的固定點累加器（`sub_124FF`）|
| `+0x09`／`+0x0B` | 同一個 word 的高 byte ＝ 方向 |
| `+0x0C` | 倒數計時器 |
| `+0x0D` | 計時器重載值（雲是 `0x10`）|
| `+0x0E` | 物件 type（雲是 **0**）|
| `+0x0F` | 相位 0–7 |

**`sub_12459` 每次 map-loop 對 32 筆各減一次計時器**；歸零就重載、設
bit 0，而且 **`si ≥ 0x2140`（後 16 筆）才另外呼叫 `sub_1248A` 移動**。
`sub_1248A` 在座標超出 `word_10D22`–`10D28` 時，對速度高byte加上±1，
逐步調整漂移。沒有暴風雨時，這四個global仍是`(−16,−16)`–`(400,400)`。
座標另依固定界線回繞：X為−16／400，Y為−16／272；暴風雨邊界不立即夾制座標或反轉速度。

**2026-10-10：物件速度與座標回繞勘誤。** 原先立即夾制、反向及關進11×11格的說法撤回。
固定IDA指令與原生C證據見[re/128](../re/128-c-city-tick-restoration.md)。
無storm時四個global為−16／−16／400／400的既有契約仍保留。

繪製在 `sub_12533`：左上角 ＝ `(X − 寬/2, Y − 高/2)`，MCH 圖塊自帶 mask，
所以雲是**半透明的網點**——奇數列蓋灰白、偶數列留地形，
這正是逐像素對拍時看到的樣子。

## 3. 現場證據

`root-saveb` 第 1 槽跑到 196 年 4 月 21 日 8 時，`peek:2754:2140:256` 讀出
16 筆全部 `+0x0E = 0`（type 0），其中**只有一筆落在畫面內**：

```
80 00 15 01 A4 00 00 00 0A 02 F2 00 0E 10 00 00
        └ X=0x0115=277  └ Y=0x00A4=164        └ type 0, 相位 0
```

用專案自己的解碼器把 pattern `0x18` 疊到鏡頭 (271,153) 的地形上、
中心格 (277,164)，再與同一刻的原版畫面逐點比：

| | 與原版不同的像素 |
|---|---:|
| 只畫地形 | 11,712 |
| **地形 ＋ 那朵雲** | **358** |

剩下的 358 是 `RenderWorld` 不畫的據點與軍團標記（同一份基準的空白對照
是 346）。**位置、尺寸、置中、mask 一次全對。**

## 7. 讀檔後依物件槽恢復火災與暴動

**狀態：CONFORMED。** READY 契約先於實作封存。修正已存在的 MCH 物件被呈現層略過的缺口，不猜補 runtime 災害種類，也不改規則、物件時鐘或存檔格式。

- 輸入為松崗 DOS/V `KI.EXE`，SHA-256 `fffeba985231cda4d636e93d10f598470b1f691d00275e4aa38e285893d43868`；原版使用 dosgolem `f79eab6db8c64a524a06535e53e5d32b0bbcf7c8`。以下位址為 IDA Pro 9.4 database linear，現成指令匯出為 `c-overlay/ida/ida-probe.json`，原始閉包見 [spec235](235-c-world-overlay.md)。
- `sub_12533` 於 `0x1253B`／`0x1253E` 巡覽 32 槽，以 `0x12541` 的存在旗標為閘。`0x12546`／`0x12551` 取 type／舊 phase，`0x12583`／`0x1258E` 讀物件自己的座標，`0x12595` 推入矩陣。此路徑不查據點 ID 或據點 `+0x15`，推論等級為 **confirmed**。
- `LoadBlock → loadMapObjects` 已還原存在旗標、TypeCode、Phase、X／Y。據點 `+0x15` 只還原強度，未存入檔案的 runtime 災害種類仍是 NoDisaster。舊 `drawDisasterOverlay` 只有 type 0 直接畫，type 1／2 先按據點去重再查 runtime 種類，因此讀檔後消失。
- 正式繪製以 active 物件快照的槽序為準，全部交既有 `drawMapObject`，使用物件自己的座標與相位；不依據點配對或種類決定是否繪製，不合併同城物件，也不因只有傷害強度就補造 MCH 動畫。
- 素材缺漏時保留既有 runtime 火災／暴動的向量提示；這項 fallback 不稱原版 parity。型別 3 仍只依既有 raw 格式處理，不新增自然產生條件或語意。
- 垂直鏈為原始 SAVE `+0x20C0` → typed 物件 → 呈現快照 → 原版／縮放／HD 共用地圖路徑 → 相位寫回與存讀檔。傷害強度、事件佇列、規則 RNG、觸發條件及保存格式不變。
- 驗收採原版十案、每案兩次 `1D483 → 11C8D` 重畫，涵蓋火災／暴動兩個初始相位、強度零、非據點座標、同城兩種槽序、雲與只有強度而無物件。執行前固定完整 258-byte RNG，量測不改原始指令或結果。remake 直接使用正式 `LoadBlock`，兩次繪製間存檔再載入，不注入 runtime 種類；100% 比完整地圖與物件表，50%／200% 抽驗呈現及寫回，舊 renderer 必須被拒絕。

重跑程式、原版 source／兩次重畫、正對照與來源雜湊保存在[本機抽驗目錄](../../workplace/scratch/closeout-disaster-load-20261117/)。正常玩家讀檔另驗可見動畫，不把受控 renderer 說成自然災害觸發或完整生命週期驗收。大量物件疊加的每格容量、長程雲軌跡、音效及跨平台實機不由此一併完成。

驗證：十案兩次重畫的完整 640×368 地圖均 0 差異像素；三種縮放共 40 圖、60 次完整 512-byte 物件表寫回與原版相同，繪製未改動物件表以外的持久資料。槽序正對照交換兩個物件後差 294 像素。舊 renderer 在八個災害案例的兩次重畫皆失敗，共 16 個畫面反例。正式滑鼠由標題 LOAD DATA 載入，再停手觀看、儲存與重讀火災／暴動，合計 28 項／12 張成功畫面；兩種動畫皆自行前進並於重讀後保留。共用規則／renderer 冷測、縮放 GPU、HD GPU、`go vet` 與建置通過。
