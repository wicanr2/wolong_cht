# 183 — 佔用圖是增量維護的，據點 `+0x18` 從它抄

**狀態：CONFORMED（結構）。** 原版有一張 384 × 256 的單位佔用圖
（`cs:word_19872`），每格一個 byte 的計數器。據點 `+0x18` 不是「數一數
站在那一格的軍團」，而是 `sub_13EFD` 每 tick 從那張圖抄一格
（`al = es:[bx] & 7Fh`）。

- 日期：2026-09-10
- 出處：`KI.EXE`（松崗 DOS/V，`workplace/ida/dosv/KI.EXE.i64`，
  SHA-256 `6deb8e9c…e5dd62`）`sub_13EFD`（IDA 線性 00013EFD）、
  `sub_12662`（00012662）的 `loc_12697`／`loc_126F5`、
  `sub_16F86`（00016F86）、`sub_12977`（00012977）
- 推論等級：confirmed（四個維護點逐條讀出）
- 實測：[`../playtest/119`](../playtest/119-rng-pace-comparison.md) §42

## 1. 四個維護點

| 時機 | 指令 | 位置 |
|---|---|---|
| 軍團輪到移動、真的走了一步 | `dec byte [di]` → 走 → `inc byte [di]` | `sub_12662` 的 `loc_12697`／`loc_126F5` |
| 編成 | `inc byte ptr [bx]`（設完 `+0x1A`／`+0x1C` 之後）| `sub_16F86` |
| 敗走 | 佔用圖 −1 | `sub_12977` |
| **停在目標上** | **兩邊都不做** | `sub_12662` 的 `loc_1266A` 直接 `retn` |

⇒ 圖上的值是**歷史**，不是現況的函數。

## 2. remake 怎麼建模

`World.occupancy`（座標 → 計數）＋ `enterCell`／`exitCell`。
載入與快照還原時 `rebuildOccupancy` 從位置重建——存檔沒有這張圖，
只能假設「每一支活著的軍團都在自己那一格上」。

⚠ **對拍期間不要再呼叫 `rebuildOccupancy`**：那等於把記帳換回掃描，
兩者在原版分岔的地方會給出不同答案。

⚠ 測試如果直接寫 `w.Corps[i] = Corps{…}` 擺場面，要自己呼叫
`rebuildOccupancy`——外力擺的軍團不會出現在圖上，原版也一樣。

### 1.1 第五個維護點：整張重建

`sub_189F0` 對 192 個據點跑 `sub_18A1E`、對 127 個軍團跑 `sub_18AEA`，
而後者就是「從軍團的座標 `inc` 一格」：

```asm
sub_18AEA:
        cmp byte ptr [si], 80h / jb retn      ; 不活著就跳過
        ax = [si+12h]（Y）× 24 + word_19872
        es = ax / bx = [si+10h]（X）
        mov [si+1Ch], ax / mov [si+1Ah], bx   ; 順便重設佔用圖位址
        inc byte ptr es:[bx]                  ; ★ +1
```

⚠ **它不先清空**。所以這是「開始遊戲／載入存檔時建一次」，
不是可以隨時重跑的。remake 的 `rebuildOccupancy` 對應它。

⛔ **佔用圖也只有八個讀取端**（`tools/ida_var_writers.py` 掃 `word_19872`），
全部讀出來之後可以確定：`sub_12708` 與 `sub_127A2` 只更新
`+0x1A`／`+0x1C`，`inc`／`dec` 只發生在上表那四處。

## 3. 現況：快照沒有帶這張圖

同局面拍 3,415 的據點 122（座標 `(304,158)`）站著三支軍團
（34／72／114，`+0x1A`／`+0x1C` 都指向同一格），而原版的圖是 **2**、
remake 是 **3**。

五個維護點全部照抄之後還是差一，而根因不在維護——**在起點**：

- **原版側是同一次執行繼續往下跑**，圖是從開新遊戲以來累積的**歷史**。
  中途沒有人再呼叫 `sub_189F0`，所以圖上任何一次「漂掉」都會留著。
- **remake 是從快照重建**（`rebuildOccupancy`），得到的是「每一支活著的
  軍團都在自己那一格」這個**理想值**。

⇒ 兩者在快照當下就可能不同，只是要等到那一格被 `sub_13EFD` 重算
（每 192 拍一次）才顯現。

**要修就得讓快照帶著這張圖**：`tools/orig_snapshot.py` 多 `peek` 軍團
所在的那幾格，`tools/rng_pace.go` 用它初始化 `World.occupancy`。
那是夾具層的工作，不是規則層的。

那一格的差傳到據點 129 的威脅量（`+0x14`），再傳到求援調兵的 `want`：

| | 佔用數(129) | 威脅量(129) | want | skip | 取幾次亂數 |
|---|---:|---:|---:|---:|---:|
| 原版 | 3 | **2** | 1 | 2 | 1 |
| remake | 3 | **3** | 2 | 1 | 2 |

⇒ 這是目前逐拍對拍的第一個分歧。**拍 3,415 之前四張表逐 byte 相同。**

## 4. 驗證

`tools/parity_ck.sh` 二十個檢查點（拍 200 … 3,400）：據點、勢力、軍團、
全域四張表全部 0 個 byte。

## 5. 未解

- **快照要帶佔用圖**（§3）。在那之前，同局面對拍的可信範圍是拍 3,415
  之前——196 年 4 月 16 日 16 時起算的十七天。
- 原版的圖為什麼會「漂」（那一格少一支）還沒查。候選：某支軍團曾經
  被 `dec` 到別格（`+0x1A` 過期），或 `sub_12977` 的 `dec` 與
  `loc_12697` 的 `dec` 在同一輪重複。
