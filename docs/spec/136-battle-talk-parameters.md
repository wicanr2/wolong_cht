# 136 — 對白框的參數是一條共用串流：`\6` 也吃一個，變體用原始的 0–7

**狀態：CONFORMED。** 戰場對白框（`sub_1C315`）掛框時傳的是
**兩個參數：`[對手, 說話者]`**，而 `\6` **會吃掉一個**——
所以有 `\6` 的變體 `\1` 拿到說話者，沒有的拿到對手。
變體用武將 `+0x1E` 的**原始值 0–7**，不是進言那條路的「模 3 收成 0–2」。

## 1. 症狀：同一個 `\1`，兩張原版畫面代入不同的人

| 原版畫面 | 訊息 | `\1` 代入 |
|---|---|---|
| 野戰開場挑戰（`workplace/promo-live/parity-field14/b0.png`）| #671 `{6}下賤的奸賊！我{1}親自來打倒你！！` | **說話者**（呂布）|
| 攻城開場勸降（`workplace/dosgolem/siege/settled.png`）| #855 `{1}啊，現在還可饒你一命！…` | **對手**（夏侯惇）|

兩則都走 `sub_1C315`，參數順序不可能不同。差別在**前面那個 `\6`**。

## 2. 原版做什麼

```asm
cmp dl, 1 / jnz .no
xchg bx, di          ; bx ＝ 說話那一側的主將記錄、di ＝ 對手
.no:
push bx              ; ← 後被讀到
push di              ; ← 先被讀到
mov  di, sp          ; ★ di 指向這兩個 word
mov  ah, [bx+1Eh]    ; ★ 變體 ＝ 說話者的**說話類型原始值**（0–7）
```

`sub_1075B` 的每支標記 handler 都是 `mov ax, ss:[di] / inc di / inc di`
（[`../re/79`](../re/79-talk-marker-handlers.md) §2）——**一條共用的游標**。
所以參數串流是：

```
參數[0] ＝ 對手的主將記錄位址
參數[1] ＝ 說話者的主將記錄位址
```

⭐ **`\6` 不是純排版控制，它也消耗一個參數**（`inc di / inc di / sub dx, 30h`）。
於是同一組八個變體裡：

| 變體長相 | `\1` 拿到誰 |
|---|---|
| `{6}…{1}…` | `\6` 先吃掉「對手」⇒ `\1` ＝ **說話者** |
| `{1}…`（沒有 `\6`）| `\1` ＝ **對手** |

這也回答了 [`../re/79`](../re/79-talk-marker-handlers.md) §5 的「`ah ≠ 0xFF`
的直接位址形式誰在用」：**就是 `sub_1C315`**——它推進去的是
`0x4240 + 32 × 主將編號` 這個**記錄位址**，不是武將編號，所以走那條直接路。

⭐ 那個位址是從**軍團**記錄算出來的：`(軍團偏移 − 0x2240) >> 1 + 0x4240`。
軍團表 64 B、武將表 32 B，換算成立的前提是**軍團編號 ＝ 主將的武將編號**
（remake 的 `FormCorps` 也是這樣編的）。

## 3. 變體：原始 0–7，不是 0–2

`mov ah, [bx+1Eh]` 直接用，沒有任何收斂。
「模 3 收成 0–2」是**進言那條路**（`sub_13C99`）的作法，
兩者不能共用一支函式。

實證：攻城開場守方那一句是 #866 ＝ 組 `0x1CF` 的**變體 4**，
而夏侯惇的 `+0x1E` 就是 4。收成 0–2 會得到變體 1（#863
「很有趣！看我把你打回去！！」）——畫面上一眼就看得出不同。
