# 116 — 城裡與城牆上的兵退卻時走不出去

**狀態：DRAFT。** 現象、範圍與判準都量到了，成因收斂到「尋路找不到出城的路」，
**但還沒定位到是哪一段少了什麼**，所以還不能照著實作。

- 日期：2026-09-02
- 出處：`KI.EXE`（SHA-256 `fffeba98…d43868`）的 `sub_1AAED`（退卻的出口座標）、
  `sub_1AED2`（走不動時算繞路）、`sub_1A6FA`（勝負判定）
- 推論等級：**現象 confirmed（決定性重現）**，成因**假說**
- 相關：[`94`](94-retreat-path-not-cleared-every-frame.md)（同一族的前一次）、
  [`../playtest/51`](../playtest/51-siege-deadlock.md)、
  [`115`](115-soldier-power.md)（把它推到檯面上的那一步）

## 1. 現象

`TestNormalScenarioTacticalBattleTerminates`（濮陽攻城，固定種子 17）
在雙方各剩一批兵時完全停住：

```
[probe] 10 萬幀：攻方 97 守方 26 done=false
[probe] 20 萬幀：攻方 97 守方 26 done=false
```

**10 萬幀之內兩側的剩餘兵數一個都沒變。** 攻方大將體力 49 < 50，
`checkGeneralRetreat` 已經讓全軍轉成退卻；但 7 個退卻中的兵原地不動，
`Remaining()` 因此永遠不到 0，`checkVictory` 不成立。

## 2. ⭐ 判準：卡住的兵在**空場**上也找不到路

在失敗當下對每個 `Cmd == Retreat` 的兵，用**當時的戰場**（門已經打破）
呼叫 `Field.FindPath`，而且把佔用成本設成 0（當作場上沒有別人）：

| 兵 | 位置 | 出口 | 空場路徑 |
|---:|---|---|---:|
| 18 | (23, 34, 1) | (62, 34, 0) | **0 點** |
| 24 | (19, 34, 1) | (62, 34, 0) | **0 點** |
| 25 | (19, 28, 1) | (62, 28, 0) | **0 點** |
| 28 | (23, 30, 1) | (62, 30, 0) | **0 點** |
| 38 | (27, 16, **5**) | (62, 16, 0) | **0 點** |
| 46 | (27, 20, **5**) | (62, 20, 0) | **0 點** |
| 47 | (26, 38, **5**) | (62, 38, 0) | **0 點** |

⭐ **所以不是擠在一起走不動**（那是 [`94`](94-retreat-path-not-cleared-every-frame.md) 修過的那一種），
**是地形層面就沒有路**。兩群各自的形狀很清楚：

- **x = 19–23、站立層 1**：在城裡，門在 x = 25，出口在 x = 62（城外）。
- **站立層 5**：在城牆頂上。下牆只有門那一格（[`../re/63`](../re/63-ground-plane-map.md) §4）。

`replan` 在 `FindPath` 落空之後會改叫 `FindPathForcing`（可以撞破的格子
當成可通行），但攻方那 20 萬幀裡城壁的耐久從頭到尾停在 1,870——
**他們連撞都沒撞到**。

## 3. 原版怎麼寫的

`sub_1AAED`（下退卻令）與 remake 的形狀一樣：

```asm
[si+1Bh] = 舊命令 / [si+1Ah] = 5（退卻）
al = 1（si < 600h，第 0 側）或 3Eh ＝ 62（第 1 側）
ah = clamp([si+8], 10h, 2Fh)          ; Y 夾在 16–47
[si+14h] = ax  /  [si+10h] = ax       ; 最終目標與這一步的目標
[si+12h] = 0                          ; Z ＝ 0
[si+16h] = 0                          ; ⭐ 繞路點清單歸零（只在下令這一刻）
…
if [si+6] == al: sub_1B4B8(ah=0)      ; 走到出口 → 離場（算生還）
```

⭐ **原版也是「一路走向邊界」**，靠 `sub_1AED2` 在走不動的那一刻算繞路。
所以差別不在退卻規則，在**繞路算得出來算不出來**。

## 4. 還要查什麼

| 問題 | 怎麼查 |
|---|---|
| 破掉的門有沒有反映到尋路用的地形 | `Field` 是 `NewFieldFromTiles` 一次建好的；門破掉之後規則層換了圖塊版本（[`66`](66-broken-walls-repaint.md)），要確認 `FindPath` 讀的是換過的那一份 |
| 站立層 5 的兵怎麼下牆 | `FindPath` 的 `canClimb` 有沒有模型化「只在門那一格上下」（[`../re/63`](../re/63-ground-plane-map.md) §4）。目前的判準是 `standZ`，不是路徑搜尋的一部分 |
| `FindPathForcing` 為什麼也落空 | 它靠 `breakableAt` 決定哪些格子可以硬穿。城牆本體（結構 0，`kind=1`）在不在裡面 |
| 原版真的走得出來嗎 | 這一份假設「原版不會卡」，但沒有實機證據。DOSBox 打一場攻城到大將退卻為止，看兵有沒有離場 |

## 5. 為什麼現在才看得見

remake 先前把兵的戰力接成軍團士氣（100–200），而 `sub_1B618` 的
命中值是 `rand(0..127) + 戰力`、傷害就是戰力——**士氣當戰力等於一擊必殺**，
兵還沒退卻就死了，這條路一年都走不到。

接回原版的算式（戰力約 18，[`115`](115-soldier-power.md)）之後，
兵要挨十幾下才倒、掉到 100 以下就排退卻，同時退卻的人數跳一個量級，
這個死鎖就穩定重現了。

⭐ **所以 [`115`](115-soldier-power.md) 沒有切**，等這一份修好再一起上。
