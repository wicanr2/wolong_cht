# 176 — 事件佇列游標要從存檔還原（區塊 `+0x30`）

**狀態：CONFORMED。** 存檔區塊 `+0x30` 是 `cs:word_10D20`，也就是
**事件佇列的派發游標**（byte offset，stride 4）。remake 載入時寫死 0，
於是從佇列頭重跑一遍，把幾個月前早就派發過的宣戰事件再派發一次。

- 日期：2026-09-10
- 出處：`KI.EXE`（松崗 DOS/V，`workplace/ida/dosv/KI.EXE.i64`，
  SHA-256 `6deb8e9c…e5dd62`）`sub_131AE`（IDA 線性 000131AE）、
  `sub_12BD9`（00012BD9）、`sub_12FBF`、`sub_1301C`、`sub_1304E`
- 推論等級：confirmed（`docs/re/15` §2.1／§3.3 已把 `word_10D20` 定為
  佇列 byte offset；`docs/re/07` §21 的月結段落把它與 `byte_131AD` 一起重設。
  位址換算 `0x10D20 − 0x10CF0 = 0x30`，與同一區塊的 `word_10D1E → +0x2E`
  同一套）
- 實測：[`../playtest/119`](../playtest/119-rng-pace-comparison.md) §37
- 相關：[`162`](162-city-cursor-from-save.md)、[`168`](168-corps-and-hour-cursors.md)

## 1. 原版做什麼

`sub_131AE` 每「時」被呼叫一次：

1. `byte_131AD` 遞減；**不等於 1 就直接返回**（＝每 10 次才處理一筆）。
2. 到期時從 `word_10D20` 取 4 byte，游標 `+= 4` 寫回，`byte_131AD` 設 `0x0A`。
3. 事件碼 0 就返回，否則走 `funcs_131E8` 的 handler。

月結的 `sub_12BD9` 把 `word_10D20` 歸零、`byte_131AD` 設 7，並把佇列
第 64 格之後整批搬到開頭（`docs/re/07` §21）。**所以游標只在月結歸零**，
月中載入存檔時它是一個非零的續跑位置。

## 2. remake 錯在哪

`internal/state/state.go` 的 `Load` 對三個輪轉游標（據點 `+0x2E`、
軍團 `+0x28`、每時勢力 `+0x2C`）都從區塊讀，唯獨 `eventCursor` 寫死 0、
`eventDelay` 寫死 7——那是**月結後**的初值，不是月中的續跑值。

後果不是「差一格」：佇列前段留著的是**這個月已經派發過**的事件，
再派發一次會重新設勢力的侵攻目標（`+0x19`），連帶觸發回頭宣戰、
邊境據點的威脅旗標、求援與救援軍團的編成。

同局面對拍（快照 16 時）量到的形狀：

| | `+0x30` | 已派發 |
|---|---:|---:|
| 快照 | `0x94` | 37 筆 |
| 原版拍 200 | `0x9C` | 39 筆 |
| 原版拍 700 | `0xB4` | 45 筆 |
| remake 拍 200／700 | `0x94` | **37（一筆都沒走，內部另從 0 起算）** |

remake 內部游標從 0 起跑，81 時內派發了佇列索引 2（勢力 7 → 8）與
索引 6（勢力 4 → 3）。加上 `applyQueuedDeclaration` 的回頭宣戰，
四個勢力 3／4／7／8 的 `+0x19` 全被填上，各抽 200 × 3 預備兵編出一支
救援軍團（軍團 52／79／110／119）。

## 3. 要改哪幾支

| 檔案 | 改什麼 |
|---|---|
| `internal/state/state.go` | 加 `eventCursorOffset = 0x30`；`Load` 從區塊讀進 `eventCursor`；`writeBlock` 把它寫回 |

`byte_131AD`（節拍計數）在程式碼段 `0x131AD`，**不在存檔區塊裡**，
所以 `eventDelay` 沒有可還原的來源，維持初值。它造成的相位差最多 10 時，
量得出來就另外處理（§5）。

## 4. 驗證

`TestEventCursorRestoredFromBlock`（正對照＋反對照＋round-trip）與
`TestEventCursorSkipsAlreadyDispatched`（游標非零時取不到已派發的那一筆，
歸零就取得到）。

同局面對拍（快照 16 時、5,480 拍）：

| | 不一致／可比 | 第一個分歧 |
|---|---|---|
| 修之前 | 305 / 5,480 | 拍 781 |
| **修之後** | **169 / 5,480** | **拍 2,455** |

五個檢查點（`tools/parity_ck.sh`）：**200／700／1,200／1,600 逐 byte 完全一致**，
拍 1,900 只剩軍團 50 的一個位元（`../playtest/119` §37.3／§37.5）。
修之前最壞的一個是 445 B／189 座。

## 5. 未解

- `eventDelay`（`byte_131AD`）的相位。存檔裡沒有這個欄位，
  原版載入存檔時它是什麼值還沒查。若拍 700 之後仍有一筆事件的
  派發時機差 10 時以內，就是它。
