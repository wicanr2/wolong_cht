## 1. 鏡頭：首都 −(16, 12)

```
camX = clamp(首都X − 16, 0, 344)      344 = 384 − 40
camY = clamp(首都Y − 12, 0, 233)      233 = 256 − 23
```

上下限出自 `sub_12151` 的 `cmp ax, 158h` 與 `cmp ax, 0E9h`，
與可視範圍 40×23 格算得出來的值一致。

## 2. 橫幅的日期

橫幅本身（`ICONGRF` 段 0）已經印好「年 月 日」，遊戲只填數字。

| 項目 | 原版 | remake（修前）|
|---|---|---|
| 顏色 | 調色盤 **色 9** ＝ `#F3D392` | 硬寫 `#F0F0E6` |
| 字模 | `ICONGRF` 段 3 `+0x840`，8×16、墨水 14 列 | 倚天 ASCII，墨水 9 列 |
| 「年」的數字右緣 | x **496** | 494 |
| 「月」 | x **528** | 526 |
| 「日」 | x **560** | 560 |

⭐ **三個右緣等距 32 px** —— 這是「量對了」的算術檢查。

⚠ 中間有一版把三個右緣一律 +2，因為當時是拿倚天字模的墨水邊界去量的。
**換了字模就要重量**：字寬相同不代表墨水的左右留白相同，
而右對齊對齊的是**格子**不是墨水。

## 4. 數字字模在 `ICONGRF` 段 3 裡

`sub_100DF` 開機時把 `ICONGRF` 段 3（檔案 `0x9700`、長 `0x23A0`）
切成五塊，各塊長度加起來剛好等於段長——這是「切對了」的算術檢查：

| 段內位移 | 長度 | 變數 | 是什麼 |
|---|---:|---|---|
| `+0x0000` | 0x6C0 | — | 未解 |
| `+0x06C0` | 0x180 | `word_10D4A` | 未解 |
| **`+0x0840`** | **0x0B0** | **`word_10D54`** | **數字字模：11 格 × 16 列** |
| `+0x08F0` | 0x0B0 | `word_10D4C` | 另一組 11 格（未解，可能是別的字重）|
| `+0x09A0` | 0x1A00 | `word_10D50` | 外框圖塊 ＋ 視窗底紋（`../formats/03` §5.5）|

`docs/re/28` §2 的數字常式 `sub_1062F` 就是拿 `cs:word_10D54` 當字型段，
一列一個 byte、每格 16 列、**寬固定 8**（`dec di` 退一個 byte ＝ 8 px），
第 10 格是負號。

⭐ **11 × 16 ＝ 176 ＝ 0x0B 個 paragraph**，與配置的長度逐 byte 對上。

墨水落在第 1–14 列，所以畫的時候格子頂端放在 y=8，墨水就在 y 9–22。
