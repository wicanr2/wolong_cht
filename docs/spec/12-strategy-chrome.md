**狀態：READY。主畫面的四個常駐視窗矩形、指令列版面與縮小地圖／勢力篩選鈕的
位置全部由機器碼定死（[`docs/re/47`](../re/47-main-screen-window-registry.md)），
不再有「從影片量的」版面常數。外框的圖塊來源與貼法也已解出（`ICONGRF` 段 3）。
剩下的差異在各視窗**內部**的排版與自繪色標。**

- 日期：2026-08-15
- 出處：[`docs/re/47`](../re/47-main-screen-window-registry.md)（`sub_18755`／`sub_1E3D7`／`sub_1895D`／`sub_11BE0`）、
  [`docs/re/46`](../re/46-strategy-chrome-cell-layer.md)（框線圖塊）

## 1. 主畫面是「橫幅 ＋ 四個可開關的常駐視窗 ＋ 大地圖」

原版預設**四個視窗都可以關掉**，關掉時大地圖佔滿 640×368。
四個開關是橫幅右側的 32×32 格，左鍵開、右鍵關。

| 元件 | 矩形 | 來源 |
|---|---|---|
| 橫幅 | (0, 0, 640, 32) | `sub_18755` 的熱區 6 |
| 開關 1–5 | (336 + 32n, 0, 32, 32) | `sub_18755` 的迴圈；第 5 格接 `nullsub_1` |
| 命令視窗 | **(0, 32, 432, 32)** | `sub_1614A` → `sub_1895D(cx=021Bh)` |
| 縮小地圖視窗 | **(432, 32, 208, 160)** | `sub_15A3A` → `sub_1895D(cx=0A0Dh)` |
| 自勢力情報視窗 | **(432, 192, 208, 208)** | `sub_15E2D` → `sub_1895D(cx=0D0Dh)` |
| 系統視窗（模態）| (208, 112, 208, 192) | `sub_160CC` → `sub_1895D(cx=0C0Dh)` |
| 大地圖（四窗全開）| (0, 64, 432, 336) | 上面三個常駐視窗的補集 |

右欄三段相加 `32 + 160 + 208 = 400`，**剛好鋪滿畫面高度**——
這是「矩形讀對了」的算術檢查，不是巧合。

## 2. 指令列

```
框    sub_1895D(樣式=0x0B, X=0,    Y=0→32, 尺寸=0x021B)   → (0, 32, 432, 32)
文字  sub_106F5(字串=cs:6181h, X=8, Y=40, 屬性=0x0F01)
熱區  sub_1E3D7(編號=0x0C, X=24, Y=40, 尺寸=0x0230)       → (24, 40, 384, 16)
分派  sub_161CA: 索引 ＝ (x − 24) ÷ 48；高亮寬 40、節距 48、高 16
```

`cs:6181h` 是**一整串**，不是八個標籤：

```
　 進言　人事　財政　編成　軍團　據點　武將　勢力 　
↑全形 ↑半形    ↑ 兩個字之間沒有空格；詞與詞之間才有一個全形空格
```

| 項目 | 值 |
|---|---:|
| 字串起點 X | 8 |
| 開頭空白 | 24（全形 16 ＋ 半形 8）|
| **第 n 個詞的 X** | **32 + 48n** |
| 詞寬 | 32 |
| 節距 | 48 |
| 文字列 Y | 40（高 16）|
| 第 n 格命中範圍 | x ∈ [24 + 48n, 72 + 48n)，y ∈ [40, 56) |

驗算：`8 + 24 + 8×32 + 7×16 + 24 = 424 < 432`，落在框內。

## 3. 縮小地圖視窗的內部

| 元件 | 矩形 | 來源 |
|---|---|---|
| 縮小地圖本身 | (440, 40, 192, 128) | `sub_15A3A` 的熱區 `0x16` |
| 勢力篩選鈕 | (536, 168, 96, 16) | 同上的熱區 `0x17` |

`sub_15C58` 把世界座標換算成畫面座標的式子是 `X = 世界X ÷ 2 + 440`、
`Y = 世界Y ÷ 2 + 40`，與上表的縮小地圖左上角一致，是第二條獨立證據。

篩選鈕只有右半格有熱區，對應說明書 3.4 的
「ウインドウ**右下の青いボタン**を押すことにより、特定勢力の拠点のみ…」。

## 3.1 自勢力情報視窗的內部

| 元件 | 位置 | 來源 |
|---|---|---|
| 底圖（頭像 ＋ 各欄標籤）| (440, 200) | `sub_15E2D` → `sub_10337` |
| 君主／首都／軍師 名 | (576, 208 / 224 / 240) | `sub_15EB7` |
| 信賴度量條 | (456, 292)，長度 `(信賴度×100 + 0x9F) ÷ 0xA0` | `sub_15F27` |
| 資金（7 位，右端 616）| (560, 312) | `sub_15F5D` |
| 預備兵 ×3（6 位，右端 616）| (568, 328 / 344 / 360) | `sub_15F7F` |

三個規則層面的細節：**信賴度是量條不是數字**、**資金是 32 位且負數換色**、
**預備兵顯示時乘以 10**。最後一項與 remake 現行的
「`Reserves` 就是人數」互相矛盾，處理方式見 §7。

## 4. 外框怎麼畫

```
上下邊（sub_10C60）：每個 16 px 粗格貼兩塊 si=0x00 的 motif
左右邊（sub_10C77）：si=0x20 柱頭 → 迴圈 si=0x40／0x60 柱身 → si=0x20 柱頭
四個 si 是段 3 的 0x06C0／0x06E0／0x0700／0x0720（docs/formats/03 §5.4）
blit 走 sub_1F9B0 → EGA Set/Reset → VRAM 0A0C8h
```

`sub_1895D` 另外還寫一張以格為單位的屬性表（`cs:word_1D84E`），
**與框線像素無關**，內容未讀（[`docs/re/46`](../re/46-strategy-chrome-cell-layer.md) §4）。

## 7. 未解

| 項目 | 現況 |
|---|---|
| **四個視窗的開關** | remake 固定顯示四個視窗，原版可以逐個開關。這是**未實作**，不是 remake 差異——實作前要先決定關掉時大地圖怎麼放大 |
| **預備兵的單位** | 原版顯示時乘 10（§3.1），remake 把 `Reserves` 當人數直接用於編成。兩者只能有一個對，**在找到原版編成的扣減端之前不動**——現在只改座標不改數值 |
| 信賴度的呈現 | 原版是量條，remake 是數字。改成量條之前要先確定顏色與底圖，否則會畫出一條沒有背景的裸色塊 |
| 底圖與標籤 | 「君主／首都／軍師」等標籤在原版是底圖的一部分（`sub_10337`），remake 用文字畫。標籤的 X 因此沒有機器碼證據 |
| 勢力色標 | 原版怎麼畫未讀（`sub_15CE0` 是小地圖的四色點，不是這一列）|
| `cs:word_1D84E` 每格 8 bytes | 內容意義未讀，消費端未找 |
| 樣式碼的值域 | 只確定 `0`＝擦除、`0x0B`＝命令、`0x0Bh`／`0x10h`／`0x15h`／`0x1Fh` 各自出現在哪個視窗已知，完整值域未列 |
