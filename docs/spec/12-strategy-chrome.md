## 1. 原版做什麼

指令列 ＝ **一個框 ＋ 一串文字 ＋ 一個熱區**，沒有按鈕圖：

```
sub_1895D(樣式=0x0B, X=0, Y=0, 尺寸=0x021B)   框
sub_106F5(字串=cs:6181h, X=0x28, Y=8, 屬性=0x0F01)  八個指令名
sub_1E3D7(熱區=0x0C, X=0x28, Y=0x18, 尺寸=0x0230)
```

框由三層寫成，**三層都不碰圖庫**：格子屬性表（`cs:word_1D84E`，
每格 8 B、40 欄）、框線層（`cs:word_10D4A`，四條邊分開畫）、熱區。

座標單位：呼叫端傳 16 px 的粗格，內層轉成 8 px 格再轉像素。
指令列的 `0x021B` 換算後是 **432 × 32 pixel**，在畫面左上角。

### 1.1 ⭐ 八個指令名是**一整串**，不是八個標籤

`cs:6181h`（檔案位移 `0x6381`）的 cp950 內容：

```
　 進言　人事　財政　編成　軍團　據點　武將　勢力 　
↑全形 ↑半形    ↑ 兩個字之間沒有空格；詞與詞之間才有一個全形空格
```

由此定出版面，**全部是原版數值不是量出來的**：

| 項目 | 值 | 來源 |
|---|---:|---|
| 起點 X | 40 | `bx = 0x28` |
| 起點 Y | 8 | `dx = 8` |
| 開頭空白 | 24 | 全形（16）＋ 半形（8）|
| 詞寬 | 32 | 兩個全形字 |
| 節距 | 48 | 詞 32 ＋ 全形空格 16 |
| 屬性 | `0x0F01` | `ax` |

驗算：`40 + 24 + 8×32 + 7×16 = 432`，**與框寬完全相同**。

## 2. 演算法

```
上下邊（sub_10C60）：每個 16 px 粗格貼兩塊 si=0x00 的 motif
左右邊（sub_10C77）：si=0x20 柱頭 → 迴圈 si=0x40／0x60 柱身 → si=0x20 柱頭
四個 si 是段 3 的 0x06C0／0x06E0／0x0700／0x0720（docs/formats/03 §5.4）
blit 走 sub_1F9B0 → EGA Set/Reset → VRAM 0A0C8h
```

**`cs:word_1D84E` 那一層（①）與框線像素無關**，是另一張以格為單位的表，
內容未讀（[`docs/re/46`](../re/46-strategy-chrome-cell-layer.md) §4）。

## 3. remake 實作

| 項目 | 位置 |
|---|---|
| 呈現層 | `cmd/wlgame/strategyhud.go` 的 `drawNaturalStrategyHUD`、`internal/ui/chrome` |
| 外框 | **照原版素材做的**：`internal/ui/chrome` 貼段 3 的三塊圖塊，順序與 `sub_10C77` 一致（柱頭在最上最下、柱身在中間）|
| 指令列 | **已改成原版版面**（起點 40／開頭空白 24／節距 48／詞寬 32）。先前是「起點 8／節距 52」而且每個詞中間硬插一個全形空格（`進　言`），八個詞累積偏移，畫面上看起來像被切錯位 |
| 自繪的部分 | 勢力色標（`vector.DrawFilledRect` ＋ 硬寫 RGBA）、底色 fill |
| 右欄版面常數 | 來源仍是「影片 `af6xqcicXoI` 的 478×360 影像經黑邊還原」——**壓縮過的參考影片**。這是目前最可疑的一項 |

**指令列這一項倒是結構對的**：原版就是「框 ＋ 文字」，remake 也是。
不對的是框怎麼畫，以及字的來源（原版取 `cs:6181h`，remake 用自己的字串陣列）。
