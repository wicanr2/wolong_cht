## 1. 路線：解格式 → OPL2 合成 → ogg

使用者裁定（2026-08-15）：**不跑原版錄音，解 `BGM.DAT` 的格式。**

錄音那條路的可行性驗過了（[`docs/playtest/25`](../playtest/25-audio-capture-feasibility.md)），
但它有三個永久缺點：錄到的是 DOSBox 的 OPL 模擬而非資料本身、
逐曲觸發要另外解一段 RE、輸出無法隨曲子的迴圈點調整。
**解格式之後這些都不存在**——而且音樂資料本身就是保存的對象。

現在的進度：

| 層 | 現況 |
|---|---|
| 事件編碼 | ✅ 已解（[`docs/re/56`](../re/56-bgm-track-events.md)）：2 bytes 一筆，音名／八度／長度／連音 |
| 控制事件 | ⬜ 低 byte ≥ `0x80` 的語意未讀（音色、音量候選）|
| 音色 | ⬜ OPL operator 參數由誰寫、寫什麼未讀 |
| OPL2 合成 | ⬜ 沒開始。**另一個專案 `~/cht/rich2/` 已經走過同一條路**：從 ymfm 手動移植的純 Go YM3812（BSD-3，不引入 CGO）（那個專案自己的 OPL2 核心選擇規格裡有授權與移植條件的完整討論） |
| ogg 匯出 | ⬜ 沒開始 |

⭐ **DOS/V 版寫的就是 OPL 的 `A0`／`B0` 暫存器對**（`docs/re/56` §3.2），
所以「用 OPL 合成」不是近似，是照原版的暫存器語意重放。

## 2. 還缺什麼

| 項目 | 現況 |
|---|---|
| 控制事件 | 低 byte ≥ `0x80` 的分派在 `0x1045B`，**未讀**。音量、音色、段落都在裡面（[`docs/re/56`](../re/56-bgm-track-events.md) §5）|
| 音色 | OPL 的 operator 參數（`20`／`40`／`60`／`80`／`C0` 那幾組）由誰寫、寫什麼未讀。**沒有音色就只能發出正弦波**，不是原版音響 |
| tick 速率 | 192 tick ＝ 全音符已定案，但一個 tick 幾秒未解（INT 8 的 PIT divisor 沒讀）|
| 兩組埠 | 聲軌 3–5 走 `基底+2`。OPL3 第二 bank 還是雙 OPL2，沒有證據 |
| `SOUND.DAT` | 音效資料的格式未解。戰術三個 effect code 已知（[`docs/re/17`](../re/17-dosv-audio-tsr.md) §3）|

## 3. 做的順序

1. **控制事件與音色**——沒有這兩個，合成出來的東西不是原版音響。
2. **OPL2 核心**：從 ymfm 移植 YM3812 到純 Go（`~/cht/rich2/` 的做法），
   **不要引入 CGO**——跨平台建置與 Android 的代價比寫核心大。
3. **離線渲染**：一支新的 `cmd/` 工具把一首曲子渲染成 PCM 再轉 ogg。
4. **remake 播放層**：Ebiten 的 `audio/vorbis`。

## 4. remake 播放層

| 項目 | 作法 |
|---|---|
| 解碼 | Ebiten 的 `audio/vorbis` |
| 檔案來源 | **玩家自己從原版產生**（§5）|
| 缺檔案時 | 靜音跑，系統選單顯示「未接入」——**不要 fallback 到自製音樂** |
| 開關 | 系統選單第 3 列 |

## 5. `[HARD]` 權利邊界

WAV 與 ogg 都是**原版衍生物**：`workplace/` 已 gitignore，
**不進版控、不進發行包**（`CLAUDE.md` §9）。
發行包裡只有擷取腳本與說明，玩家拿自己的原版跑一次。

## 6. 驗證

| 方式 | 內容 |
|---|---|
| 每首的中介資料 | 來源檔 SHA-256、觸發步驟、WAV 與 ogg 的 SHA-256、長度、循環點 |
| 不是靜音 | **分段** RMS（只錄到片頭的話後段是 0，總 RMS 看不出來）|
| 下游吃得下 | 拿 **Ebiten 自己的解碼器**跑一次，不要用別的播放器代替 |
