## 1. ⭐ 為什麼是「錄音」不是「解格式」

`BGM.DAT` 的**聲軌事件編碼完全未解**：音高、長度、迴圈、包絡都還沒讀
（[`docs/re/23`](../re/23-bgm-resource-format.md) §5）。沒有這個就寫不出播放器，
也就沒辦法「把原版格式轉成 ogg」——**轉檔需要先能解讀**。

所以走另一條：**讓原版自己播，錄下來，轉 ogg**。
這也符合「配樂用原版，不自產」的素材鐵則。

代價要講明白：錄下來的是 **DOSBox 的 OPL 模擬**，不是真實硬體。
音色與真機的差異沒有對照組（[`docs/playtest/25`](../playtest/25-audio-capture-feasibility.md) §4）。

## 3. 階段 B：逐曲觸發缺什麼

11 首曲子要**逐首、可重現**地觸發。「錄一長段再切」不算——
切點與循環點全靠手工，而且下一次重跑不會得到同一份輸出。

原版的介面已知一半（[`docs/re/17`](../re/17-dosv-audio-tsr.md) §2）：

| `AH` | 作用 | 證據 |
|---:|---|---|
| `0x05` | 播放效果，`AL` ＝ 效果碼 | 已證實 |
| `0x06`／`0x07` | 交出資源指標／初始化 | 已證實 |
| `0x0A` | 查旗標 | 已證實 |
| **？** | **播放第 N 曲** | ⬜ **未解**——`sub_10210` 用 `AH=0x00`／`0x02`／`0x03`，作用未定案 |

解出來之後，觸發手段是**寫一支 20 行的 `.COM`**：載入 `YNSOUND.COM`、
呼叫 INT 61h 播第 N 曲、等 N 秒、退出。這樣不必玩到那個場景，
而且每一首的錄音都可重現。

⚠ **不要改原版執行檔**來觸發——那樣錄到的嚴格說不是原版行為。

## 4. 階段 C：remake 播放層

| 項目 | 作法 |
|---|---|
| 解碼 | Ebiten 的 `audio/vorbis`（ogg 原生支援，不必自己解）|
| 檔案來源 | **玩家自己從原版產生**（§5），與原版資產同一個處理方式 |
| 缺檔案時 | 靜音跑，並在系統選單顯示「未接入」——**不要 fallback 到自製音樂** |
| 音效 | 戰術三個 effect code 已知（`re/17` §3），錄法同音樂 |
| 開關 | 系統選單第 3 列，目前寫「未接入」|

## 5. `[HARD]` 權利邊界

WAV 與 ogg 都是**原版衍生物**：`workplace/` 已 gitignore，
**不進版控、不進發行包**（`CLAUDE.md` §9）。
發行包裡只有擷取腳本與說明，玩家拿自己的原版跑一次。

## 6. 驗證

| 方式 | 內容 |
|---|---|
| 每首的中介資料 | 來源檔 SHA-256、觸發步驟、WAV 與 ogg 的 SHA-256、長度、循環點 |
| 不是靜音 | **分段** RMS（只錄到片頭的話後段是 0，總 RMS 看不出來）|
| 下游吃得下 | 拿 **Ebiten 自己的解碼器**跑一次，不要用別的播放器代替 |
