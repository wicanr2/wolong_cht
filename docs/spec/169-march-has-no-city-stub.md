## 2. 差在頭尾

`withCityEnds` 在中段前後各補一段**逐格直線**：

```
城中心 → 節點格 → 城門格   ＋   中段   ＋   城門格 → 節點格 → 城中心
   （StubA 格）                              （StubB 格）
```

原版沒有這兩段。軍團在據點上時 `[si+0Eh]` 是**據點編號 × 8**，
一走起來 `sub_12708` 直接把座標寫成路徑表的第一筆：

```asm
sub_12708:
        mov     di, es:[bx]          ; bx ＝ [si+0Ch]，路徑點的位址
        …
        mov     [si+10h], di         ; X ← 路徑點的 X
        mov     [si+12h], al         ; Y ← 路徑點的 Y
```

進城端同理：走到最後一筆（旗標 `04`）之後 `sub_127A2` 換節點，
是據點就整個換成**據點記錄的座標**：

```asm
sub_127A2:
        mov     [si+0Eh], bx
        cmp     bx, 600h
        jnb     short .end           ; 不是據點就不動座標
        shl     bx, 1 / shl bx, 1
        mov     ax, [bx+848h]        ; 據點 +0x08 ＝ X
        mov     bx, [bx+84Ah]        ; 據點 +0x0A ＝ Y
        mov     [si+10h], ax
        mov     [si+12h], bx
```

⇒ **出城與進城各只花一拍**，位置直接跳過去（實測跳 2 格）。

### 3.1 另一端的城門格從來不會被停留

進城端還有一件容易漏的事：`sub_12708` 走到路徑表的最後一筆之後，
`sub_127A2` 是在**同一拍**裡換節點並把座標改寫成據點中心的。
也就是說最後那一筆路徑點（另一端的城門格）**只是換節點的觸發條件，
它的座標一次都不會出現在 `[si+10h]`／`[si+12h]` 上**。

所以 remake 的格子序列是「路徑點去掉最後一筆，再接上據點中心」，
長度仍然等於路徑點數。同一條邊的兩個方向各自成立——
反向走時被吃掉的是另一端的那一筆。

### 3.1.1 ⚠ 被吃掉的是**前進方向那一端**，所以兩個方向不一樣

旗標分得出兩端：路徑點 `+03` 含 `40h`（`44`）是 **A 那一端**，
只含 `04` 是 **B 那一端**。`sub_12708` 只在「旗標那一端 ＝ 自己前進的
方向」時才換節點：

| 走法 | 起點格 | 中段 | 收尾 |
|---|---|---|---|
| A → B（步進 `4`）| `p0` | `p1` … `p(n-2)` | 走到 `p(n-1)` 的同一拍換成 **B 中心** |
| B → A（步進 `0FCh`）| `p(n-1)` | `p(n-2)` … `p1` | 走到 `p0` 的同一拍換成 **A 中心** |

⇒ **兩個方向各吃掉自己終點那一格**，長度都是 n。
反向的序列**不是正向序列的倒轉**：倒轉會以 B 中心開頭、以 `p0` 結尾，
而正確的是以 `p(n-1)` 開頭、以 A 中心結尾。

⚠ 這個差別在畫面上看不出來——中段完全相同，只有頭尾各差一格，
而**路徑指標 `+0x0C` 照樣對得上**。症狀是「同一個 `+0x0C`、
座標差一格」（docs/playtest/119 §30）。

⚠ 這一格的位移可以大於 1（城門格到城中心），
**路徑連續性的檢查要把最後一格排除**，否則會誤判成「列邊界繞行」的指紋
（`TestRoadPathIsContiguous`、`TestMarchFollowsRoads`、
`TestHuiJiZhangAnEdgeIsRealNotWrapAround` 三支都豁免了這一格）。

## 3. 量到的差

同局面對拍，軍團 39（劉備，據點 82 → 88）：

| | 拍 56 | 拍 80 | 拍 104 | 拍 128 | 拍 152 | 拍 176 | 拍 200 |
|---|---|---|---|---|---|---|---|
| 原版 | 不動 | (206,116) | (206,117) | (207,117) | (208,117) | (209,117) | (210,117) |
| remake | (207,115) | (208,116) | (209,117) | (210,118) | (211,119) | (212,120) | (213,120) |

原版那一串**就是路徑表的前六筆**（`0x4388` 起，`+4` 一筆）。
remake 走的是 `straight()` 產生的對角線——它從據點中心 (206,114) 斜著切到城門格，
於是整條路的相位與形狀都偏掉。

路徑總長：改之前的 remake **5,852** 格，原版 **5,526** 格。
**每條邊平均長 1.3 格**，行軍時間跟著多 5.9%。

## 4. remake 要改什麼

`internal/assets/world/roads.go` 的 `withCityEnds`：

```go
// 原版沒有「城中心 → 節點格 → 城門格」那一段：軍團從據點座標
// **一步跳到路徑表的第一筆**，到站時也是一步跳回據點座標。
out := make([][2]int, 0, len(cells))
// ⭐ 另一端的城門格不會被停留（§3.1）：最後一筆只觸發換節點，
// 那一拍的座標已經是據點中心。
for _, c := range cells[:len(cells)-1] {
    out = append(out, cellXY(c))   // cells[0] 就是城門格，要留著
}
out = append(out, to)              // 終點是據點中心
return out, 1, 1                   // StubA／StubB 各一格
```

`straight`／`between` 只剩 `withCityEnds` 之外的用途；沒有呼叫端就一併刪掉
（`tools/phantom_scan.py` 不會擋死碼，但 `go vet` 會）。

⚠ **`Steps` 會跟著變短**，而它是路由的成本。那是對的——原版的距離就是
路徑點數（連結記錄 `+0x04`）。

## 5. 怎麼驗

1. `tools/dump_roads.go` 的輸出與 `tools/orig_roadtable.py` 的路徑表比：
   **每條邊的完整序列**（不再只有中段）要逐格相同，總長 5,526。
2. 同局面對拍：軍團 39 在拍 80 之後的位置要與原版逐拍相同。
3. `internal/assets/world` 既有測試維持綠燈；`TestRoadPathIsContiguous`
   會抓到「跳格」——⚠ **那道檢查要跟著改**，因為原版本來就跳。

remake 拍 56 (206,116)   80 (206,117)  104 (207,117)  128 (208,117)  152 (209,117)

## 7. ⚠ 對拍工具本來沒掛道路圖

`rng_pace.go` 只呼叫 `state.LoadScenario`，沒有 `SetRoads`——
而**規則層不讀檔案，道路圖要由呼叫端注入**（`internal/state/corps.go`）。
少了它 `w.step` 走的是直線退路，軍團的每一格都與原版不同。

症狀是**看起來像規則差異**：軍團斜著切出城、整條路的相位偏掉，
而畫面、存檔欄位、測試全部正常。⭐ **量測工具的預設狀態不是「什麼都沒設」，
是「一個沒宣告的設定」**——`SetRoads` 沒呼叫時 `w.roads` 是 nil，
既不報錯也不警告。
