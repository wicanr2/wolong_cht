# 200 — 開場的兵晚一拍才走

**狀態：DRAFT。** 逐拍對拍把攻城的第一個分歧釘在**拍 2**：原版的兵在拍
0／1／2 一格都沒動、拍 3 才開始走；remake 拍 2 就走了。**把 remake 的取樣
往後錯一拍，拍 0–2 的 96 槽完全相同、拍 3–5 只差 2 個兵**——所以這是單一
一拍的相位，不是移動規則整個不同。

⚠ **設定端還沒找到，所以是 DRAFT**：移動那一側的閘已經讀出來了，
但「誰讓開場多等那一拍」還沒定位。**不要照這一份實作**——
照現象把某個計時器設成 1 會讓數字對上，那是調參數不是還原規則。

## 1. 實測：第一個分歧在拍 2

原版 `runto:19FA0` 之後逐拍 `ticks:1;units`，remake 逐 `-battle-steps N -list-units`
（兩個推進旗標都明寫，`-shot-frames 0`）：

| 拍 | 原版移動的兵 | remake 移動的兵 |
|---:|---:|---:|
| 1 | 0 | 0 |
| 2 | **0** | **87** |
| 3 | 87 | 90 |
| 4 | 91 | 90 |
| 5 | 90 | 84 |

把 remake 的拍 N 對原版的拍 N+1：

| 拍 | 座標不同 / 96 | 最大位移 |
|---:|---:|---:|
| 0–2 | **0** | 0 |
| 3 | 2 | 2 |
| 4 | 2 | 4 |
| 5 | 2 | 6 |

## 2. 原版那三拍在做什麼

側 0 隊 0 第 0 個兵（`+0x1A` 命令／`+0x1B` 下一個命令／`+0x00` 旗標）：

| 拍 | 座標 | 令 | 旗 |
|---:|---|---|---|
| 0、1 | (1,25) | `01→00` | `80` |
| 2 | (1,25) | **`00→00`** | **`88`** |
| 3 | (2,25) | `00→00` | **`A8`** |

⇒ **拍 2 套用了命令（`01`→`00`）但沒有移動**，拍 3 才走。
旗標同步從 `80` → `88`（bit 3）→ `A8`（bit 3 ＋ bit 5）。

## 3. 移動那一側的閘（已讀出）

```asm
sub_1ADC8:
0001ADE7  mov  ax, [si]        ; al ＝ 旗標 +0x00、ah ＝ +0x01
0001ADE9  cmp  al, 80h
0001ADEB  jb   loc_1AE00
0001ADED  test al, 40h
0001ADEF  jnz  loc_1AE26       ; bit 6 ⇒ 整個跳過
0001ADF1  and  ah, ah
0001ADF3  jz   loc_1AE1A       ; ★ +0x01 ＝ 0 ⇒ 呼叫移動常式 sub_1AF69
0001ADF5  dec  byte ptr [si+1] ; ★ 非零 ⇒ 遞減，**這一拍不移動**
0001ADF8  jnz  loc_1AE26
0001ADFA  and  byte ptr [si+2], 1
```

`+0x01` 是一個倒數：非零就遞減並跳過移動。remake 已經有這個欄位
（`Soldier.Stun`，[`63`](63-hit-stun.md)），移動端也接上了
（`internal/rules/tactical/soldier.go`）——**缺的只是開場那一次的設定**。

## 4. ⛔ 「開場設了一個計時器」這個假說已經被否證

`tools/ida_disp_users.py` 掃全庫「位移 ＝ 1 的寫入」，**兵記錄那一段的
每一個寫入端都是命中或發射**：

| 位址 | 指令 | 什麼時候 |
|---|---|---|
| `0001AD67`／`0001ADB1` | `mov byte ptr [si+1], 2` | `sub_1AD2D`／`sub_1AD7F` 發射投射物 |
| `0001B66E`／`0001B69D` | `2`／`4` | `sub_1B618` 被打中（[`63`](63-hit-stun.md)）|
| `0001B6F0` | `2` | `sub_1B6BC` |
| `0001B9F5`／`0001BA1D` | `2`／`4` | `sub_1B97E` |

**沒有一支在開場設它。** 所以那兩拍不是靠 `+0x01` 擋下來的。

⭐ 而 [`159`](159-tactical-command-movement-order.md) 早就寫過另一半：
「移動常式返回後，非零體力扣一，**沒有檢查是否位移成功**；
原版首拍兩側位置未變，體力均 128 → 127」——**首拍有呼叫移動常式，
只是沒走成**。

⇒ 方向要換：不是「被計時器擋住」，是**前兩拍算不出可以走的一步**
（中繼目標或路徑還沒就緒）。下一個要讀的是移動常式 `sub_1AF69` 與
陣形 handler 尾端的 `sub_1AA2C`（中繼目標），
[`159`](159-tactical-command-movement-order.md) 的「中繼目標追查補記」
已經列了四支相關函式。
