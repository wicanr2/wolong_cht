# 200 — 開場的兵晚一拍才走

**狀態：CONFORMED。** 機制兩層都有證據：移動閘是靜態 confirmed、開場值 ＝ 1 是執行期 confirmed（`WOLONG_DOSGOLEM_WATCH` 攔 `sub_1AF69`）。⚠ 仍未定位的是**哪一行寫的**——那不影響「開場要等一拍」這個規則本身，但接上之後要拿逐拍 96 槽驗，不能只看畫面。 逐拍對拍把攻城的第一個分歧釘在**拍 2**：原版的兵在拍
0／1／2 一格都沒動、拍 3 才開始走；remake 拍 2 就走了。**把 remake 的取樣
往後錯一拍，拍 0–2 的 96 槽完全相同、拍 3–5 只差 2 個兵**——所以這是單一
一拍的相位，不是移動規則整個不同。

⚠ 第一版把這一份標成 DRAFT 並寫「不要照這一份實作」，理由是
「設定端沒找到，照現象設 1 是調參數」。**執行期攔截之後那個顧慮消失了**
（§4）：拍 1 移動常式零呼叫、拍 2 第一次呼叫時 `+0x01` 已經是 0，
⇒ 開場值就是 1。這不是從畫面反推的參數，是量到的欄位值。

## 1. 實測：第一個分歧在拍 2

原版 `runto:19FA0` 之後逐拍 `ticks:1;units`，remake 逐 `-battle-steps N -list-units`
（兩個推進旗標都明寫，`-shot-frames 0`）：

| 拍 | 原版移動的兵 | remake 移動的兵 |
|---:|---:|---:|
| 1 | 0 | 0 |
| 2 | **0** | **87** |
| 3 | 87 | 90 |
| 4 | 91 | 90 |
| 5 | 90 | 84 |

把 remake 的拍 N 對原版的拍 N+1：

| 拍 | 座標不同 / 96 | 最大位移 |
|---:|---:|---:|
| 0–2 | **0** | 0 |
| 3 | 2 | 2 |
| 4 | 2 | 4 |

## 2. 原版那三拍在做什麼

側 0 隊 0 第 0 個兵（`+0x1A` 命令／`+0x1B` 下一個命令／`+0x00` 旗標）：

| 拍 | 座標 | 令 | 旗 |
|---:|---|---|---|
| 0、1 | (1,25) | `01→00` | `80` |
| 2 | (1,25) | **`00→00`** | **`88`** |
| 3 | (2,25) | `00→00` | **`A8`** |

⇒ **拍 2 套用了命令（`01`→`00`）但沒有移動**，拍 3 才走。
旗標同步從 `80` → `88`（bit 3）→ `A8`（bit 3 ＋ bit 5）。

## 3. 移動那一側的閘（已讀出）

```asm
sub_1ADC8:
0001ADE7  mov  ax, [si]        ; al ＝ 旗標 +0x00、ah ＝ +0x01
0001ADE9  cmp  al, 80h
0001ADEB  jb   loc_1AE00
0001ADED  test al, 40h
0001ADEF  jnz  loc_1AE26       ; bit 6 ⇒ 整個跳過
0001ADF1  and  ah, ah
0001ADF3  jz   loc_1AE1A       ; ★ +0x01 ＝ 0 ⇒ 呼叫移動常式 sub_1AF69
0001ADF5  dec  byte ptr [si+1] ; ★ 非零 ⇒ 遞減，**這一拍不移動**
0001ADF8  jnz  loc_1AE26
0001ADFA  and  byte ptr [si+2], 1
```

`+0x01` 是一個倒數：非零就遞減並跳過移動。remake 已經有這個欄位
（`Soldier.Stun`，[`63`](63-hit-stun.md)），移動端也接上了
（`internal/rules/tactical/soldier.go`）——**缺的只是開場那一次的設定**。

## 4. dosgolem 攔截：那兩拍不是同一件事

`WOLONG_DOSGOLEM_WATCH=1AF69`（攔移動常式）跑 `runto:19FA0` 之後四個 `ticks:1`：

| 拍 | `sub_1AF69` 呼叫數 | 讀到什麼 |
|---:|---:|---|
| 1 | **0** | 整個區間一次都沒呼叫 ⇒ 移動閘走了 `dec byte ptr [si+1]` 那條，**`+0x01` 非零** |
| 2 | 96 | 第一次呼叫 `AX=0088`（`al` ＝ 旗標 `88`、`ah` ＝ `+0x01` ＝ **0**），**而座標沒變** |
| 3 | 91 | 才真的走 |

⇒ **那兩拍不是同一個機制**：

- 拍 1 被 `+0x01` 擋掉（開場值是 **1**，那一拍遞減成 0）
- 拍 2 有呼叫移動常式，**但沒走成**——與
  [`159`](159-tactical-command-movement-order.md) 記的
  「移動常式返回後扣體力，**沒有檢查是否位移成功**」一致

remake 目前只缺第一層。

⚠ `sub_1AF69` 開頭 `or byte ptr [si], 20h`（bit 5）、多條出口 `and byte ptr
[si], 0DFh` 清掉它——**bit 5 是常式執行中的暫時標記**，不是持久狀態。
拍 3 的旗 `A8` 留著 bit 5，表示那一拍走的是不清它的那條出口。

## 5. ⛔ 靜態掃描沒找到設定端——而它確實存在



`tools/ida_disp_users.py` 掃全庫「位移 ＝ 1 的寫入」，**兵記錄那一段的
每一個寫入端都是命中或發射**：

| 位址 | 指令 | 什麼時候 |
|---|---|---|
| `0001AD67`／`0001ADB1` | `mov byte ptr [si+1], 2` | `sub_1AD2D`／`sub_1AD7F` 發射投射物 |
| `0001B66E`／`0001B69D` | `2`／`4` | `sub_1B618` 被打中（[`63`](63-hit-stun.md)）|
| `0001B6F0` | `2` | `sub_1B6BC` |
| `0001B9F5`／`0001BA1D` | `2`／`4` | `sub_1B97E` |

**沒有一支在開場設它。** 但 §4 的執行期攔截證明開場值就是 1——
⇒ **掃描有洞**：設定端不是 `[reg+1]` 這種寫法（可能是 word 寫入，
位移算成 0；或 `rep stos` 整段填）。這正是
[`filter-has-a-hole`](../lessons.json) 那條教訓的形狀。

⚠ 也查過 `sub_19752`（掃描清單裡唯一位址接近擺位段的那一筆）：
它是 **EGA 繪圖**（`out dx, al` 到 `3CFh`、每列 `add di, 50h`），不是兵記錄。

⇒ 下一步是掃「對兵記錄整筆寫入」的寫法（word 或 `rep stos`），
而不是再掃位移 1。
