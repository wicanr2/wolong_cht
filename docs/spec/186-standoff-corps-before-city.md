# 186 — 擋路判定的順序：先問軍團，再問據點

## 1. 原版做什麼

```asm
sub_12708:
        mov di, es:[bx] / mov ax, es:[bx+2]      ; 下一個路徑點的 X／Y ＋ 屬性
        cx = Y × 24 / ds = cx ＋ cs:word_19872   ; 佔用圖那一列
        cmp byte ptr [di], 0 / jz loc_1273C      ; ★ 那一格的佔用數
          ds = cs:word_10D52 / dx = di / xor ah,ah
          call sub_12831                         ; ★ ① 撞軍團
          jb  loc_1273C                          ; CF ＝ 1 ⇒ 沒擋，往下問
          retn                                   ; 擋住 ⇒ 這一拍不動
loc_1273C:
        ds = cx ＋ cs:word_10D44 / mov al, [di]  ; 那一格的地圖圖塊
        ds = cs:word_10D52
        test byte ptr [si], 1 / jz loc_1275F     ; ★ 位元 0 ＝ 0 ⇒ 跳過據點判定
        cmp al, 0CEh / jb loc_1275F
        cmp al, 0DDh / ja loc_1275F              ; ★ 圖塊要落在 0CEh–0DDh
        call sub_12880                           ; ★ ② 撞據點
        jb  loc_1275F
        retn
loc_1275F:  … 真的走進去 …
```

### 1.1 `sub_12831`：那一格上有沒有敵方軍團

```asm
        di = 2240h / cx = 7Fh
loop:   cmp byte ptr [di], 80h / jb 下一支        ; ★ 位元 7（活著）
        cmp ax, [di+12h] / jnz 下一支             ; Y
        cmp dx, [di+10h] / jz  找到               ; X
        di += 40h / loop
        jmp STC                                   ; 沒找到 ⇒ 不擋
找到:   cmp [si+1], [di+1] / jz STC               ; ★ 同勢力 ⇒ 不擋
        or byte ptr [si], 20h                     ; 設對峙位元 5
        cmp byte ptr [si+3], 1
          ja → sub_102F5(al=3)（音效）            ; > 1：倒數中
          jz → sub_14A7B                          ; ＝ 1：結算（**野戰**）
          else → [si+3] ← 0Ch                     ; ＝ 0：第一次撞上
        CLC                                       ; 擋住
```

**找到第一支就停。** 是自己人就整個放行（不繼續往後掃），
而放行之後 `sub_12708` **會繼續問據點**。

### 1.2 `sub_12880`：這條連結通往的據點是不是別人的

```asm
        di = [si+0Eh]
        cmp byte ptr [si+0Ah], 4 / jnz .b
        di = es:[di+8] / jmp .c                   ; 步進 4 ⇒ 連結的這一端
.b:     di = es:[di+6]                            ; 否則另一端
.c:     di <<= 2
        cmp [di+841h], [si+1] / jz STC            ; ★ 是自己的據點 ⇒ 不擋
        …（倒數三支，與 sub_12831 相同）
          jz → di += 840h / sub_14ADE             ; ＝ 1：結算（**攻城**）
        CLC
```

⚠ 它看的是**連結的端點據點**，不是「下一格是不是據點」。

## 2. remake 錯在哪

`World.blockerAt`（`internal/state/corps.go`）先問據點再問軍團，
而且刻意不照抄位元 0 的閘。原本的理由寫在註解裡：

> 原版一個據點佔 `0CEh`–`0DDh` 一整段圖塊，軍團站在自家城裡時下一格
> 往往還在自己的據點圖塊上，位元 0 是用來擋掉那一步的；remake 的據點
> 只佔一個點，出城第一步永遠踏在道路格上，沒有這個情況。

**「據點只佔一個點」恰恰讓順序更要緊**：據點那一格上站著敵方軍團時，
原版先被 `sub_12831` 攔下走野戰，remake 卻先看到據點走攻城。

同局面拍 4,910（原版側 4,939）：軍團 1（勢力 11）對峙倒數走完，
擋著它的那一格是據點 2，而軍團 11（勢力 14）正站在上面。

| | 原版 | remake |
|---|---|---|
| 判定 | `sub_12831` 攔下 → `sub_14A7B` → `sub_15130(al=1)` | `siegeAt` → `sub_15130(al=0)` 那一路 |
| 場合 | **野戰**（地形係數列 1、適性 `+0x0F`、不加城兵）| **攻城**（列 3／0、適性 `+0x0E`、守方加城兵）|
| 結果 | 軍團 1 敗，掉 116 兵 | 軍團 1 勝，攻下據點 2、消滅軍團 11 |

⇒ 兩邊的**戰力算式選了不同的表**，勝負因此相反。

## 3. ⭐ 真正的根因：問的是**路徑點**，不是走到的格子

只把順序倒回來會全面退步（拍 4,910 從 0 個 byte 變成 414 個）——
因為 remake 的「下一格」是**據點中心**，守軍就站在上面，
於是每一場攻城都被軍團那一條搶走。

原版的下一格與 remake 差一筆：

```
格子序列    … p(n-2)  p(n-1)=據點中心      ← march.Edge.Path
路徑點序列  … p(n-2)  BGate=城門格          ← sub_12708 問的是這個
```

`march.Edge.Path` **刻意不含城門格**（走到它的同一拍就換成據點中心了），
所以 `nextCell` 一路回格子序列，最後一步直接從城門格前一格跳到據點中心。

同局面拍 4,910：軍團 1 在 (246,17)，城門格是 (246,16)、據點 2 在 (246,15)，
而**軍團 73 正站在 (246,16)**。原版問城門格 → 撞到軍團 73 → 野戰；
remake 問據點中心 → 撞到據點 2 → 攻城。

⇒ 兩個修正是**配套**的，少一個就退步：

| 改動 | 對應原版 |
|---|---|
| `march.CellMark` 加 `Point`（＝ `cellMarks` 已經算出的 `pts[k]`），`nextCell` 回它 | `sub_12708` 的 `mov di, es:[bx]`／`mov ax, es:[bx+2]` |
| `blockerAt` 先掃軍團表（用**路徑點**），沒被擋才問據點（用**格子**）| `sub_12831` → `sub_12880` |
| 同勢力的軍團擋在那一格時**繼續問據點**（不是整個放行）| `sub_12831` 的 `jz STC` ＋ `sub_12708` 的 `jb loc_1273C` |
| 據點那一條只在「路徑點已經是城門格」時成立 | `test byte ptr [si], 1` ＋ 圖塊 `0CEh`–`0DDh` |

### 3.1 兩個明示的 remake 差異

1. **缺道路圖時據點先問。** `routes` 是空的、沒有城門格這回事，
   `nextCell` 回的是逼近目標的那一步 ＝ 據點中心，守軍必然站在同一格上；
   照原版順序問會把每一場攻城都變成野戰。
2. **`Point` 是零值時退回逐格問據點。** 那表示這一段沒有道路表的標記
   （`cellRoute` 補的零值 `CellMark`），沒有城門格可比。
