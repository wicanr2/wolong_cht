## 1. 這份規格要解決什麼

戰略層的主畫面已經逐像素對完（[`../playtest/37`](../playtest/37-main-screen-parity.md)、
[`39`](../playtest/39-system-window-parity.md)）。戰場這一層要的是同一件事，
但難處不同：[`../playtest/20`](../playtest/20-tactical-layout-parity.md) 是拿
不同戰況的錄影幀量幾何，只能證明版面骨架，證明不了畫得對。
**要證明畫得對，兩邊得站在同一個局面上**——這一份規定分區怎麼切、
同狀態怎麼湊。

## 2. 分區

| 區 | 矩形（x, y, w, h）| 來源 |
|---|---|---|
| `field` | 0, 0, 480, 368 | 側欄從 x=480 起、底列從 y=368 起 |
| `bottom` | 0, 368, 480, 32 | 六格 × 80 px（`cs:0xD2EA` 的 X 表）|
| `sb-title` | 480, 0, 160, 48 | 側欄七帶之一（`31` §1）|
| `sb-enemy` | 480, 48, 160, 32 | 對方將旗格 |
| `sb-minimap` | 480, 80, 160, 128 | 小地圖 |
| `sb-self` | 480, 208, 160, 40 | 我方將旗格 |
| `sb-formation` | 480, 248, 160, 32 | 十六個陣形 |
| `sb-command` | 480, 280, 160, 96 | 六列指令面板 |
| `sb-arrow` | 480, 376, 160, 24 | `▶▶` 列 |

側欄七段相加 `48+32+128+40+32+96+24 = 400`，剛好鋪滿高度——
這是矩形讀對了的算術檢查，同 `90` §3 右欄那一條。

⭐ **側欄要切成七段不是為了好看**：其中三段（`sb-formation`、`sb-command`、
`sb-arrow`）是**純美術，不隨戰況變**。它們在「兩邊戰況還沒對上」的階段
就該 PASS，所以能把「圖庫解錯」與「狀態沒對上」分開——
整條側欄比成一塊的話，這個訊息會被上面兩格的兵力條洗掉。

## 3. 同狀態怎麼湊

戰略層開局兩邊天然同狀態（`90` §2 那個「用不到存檔」的好處），戰場沒有。
三個難處，逐個對策：

| 難處 | 對策 |
|---|---|
| 原版要**玩到**開戰 | 全程滑鼠腳本：編成 → 選武將 → 確定 → 軍團 → 行軍指示 → 選軍團 → 選目的地。**`sub_1716D`（選軍團）是清單視窗不是地圖點選**（[`../re/22`](../re/22-strategy-command-tree.md) §3.3），所以整條路徑都在 ×1.2 的選單座標系裡，只有指令列那兩下要用地圖模式的 ÷9.6 |
| 開戰之後畫面**每幀都在動** | 戰術速度調到最慢；原版側的截圖時機以「剛進戰場」為準——那一刻雙方還在初始佈陣 |
| 兩邊的**部隊組成**要一樣 | `-siege-corps` 直接拿存檔裡現成的兩支軍團開戰，兵種、人數、主將都照存檔（[`90`](90-same-state-parity.md) §2.3）。攻守由參數指定，不看 `-siege-defend` |

**先求靜態層**：`sb-formation`／`sb-command`／`sb-arrow`／`bottom` 四區
不吃戰況，是最先能驗收的一組。
