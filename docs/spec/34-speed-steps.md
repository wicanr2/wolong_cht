## 1. 原版做什麼

系統選單第 4、5 列是**兩個獨立的速度設定**，各五檔，
共用同一組標籤（`ds:6033h`，每筆 7 byte）：

```
最高速 ／  高速  ／  普通  ／  低速  ／ 最低速
  0        1        2        3        4
```

點一下就 `+1`，到 5 繞回 0（`sub_16062`，**只有一個方向**）。
值存在 `ds:0CFAh`（戰略）與 `ds:0CFBh`（戰術）。

兩層都是同一種節流：**推進一步之後，等 N 個計時中斷**。
中斷是音效驅動發的，**291.3 Hz**，量子 3.43 ms。

| | 等幾個中斷 | 一步是什麼 |
|---|---|---|
| 戰略 | `ds:0CFAh` | 一個**子刻**（216 個 ＝ 一個遊戲日）|
| 戰術 | `ds:0CFBh` **× 16** | 一個**戰場幀** |

| 設定 | 值 | 戰略：一個遊戲日 | 戰術：戰場幀率 |
|---|--:|--:|--:|
| 最高速 | 0 | 不等待 → 機器上限 | 不等待 → 機器上限 |
| 　高速 | 1 | 0.74 秒 | 18.2 fps |
| 　普通 | 2 | 1.48 秒 | 9.1 fps |
| 　低速 | 3 | 2.22 秒 | 6.1 fps |
| 最低速 | 4 | 2.97 秒 | 4.6 fps |

**出廠預設兩個都是 0（最高速）**（`ds:0CF8h` 起四個 byte 的初值
`00 01 00 00` ＝ 畫面模式 1６色／音效 TYPE 1／戰略最高速／戰術最高速）。
1994 年的機器跑不到上限，所以預設放最快是合理的；
**在現代機器上照抄會得到一個快到不能玩的遊戲**。

## 2. ⭐ 這一份要修的偏差

remake 先前把兩個設定都當成「每個畫面更新推進幾步」，戰術預設 4：

| | remake（舊） | 原版 |
|---|--:|--:|
| 戰場幀率 | 4 × 60 ＝ **240 fps** | 最快 18.2 fps（最高速時看機器）|
| 一個遊戲日 | 216 ÷ 240 ＝ **0.9 秒** | 0.74 ～ 2.97 秒 |

戰略層大致在範圍內，**戰術層快了一個數量級以上**。
這不只是手感問題：攻城的計時器是 550 幀
（[`../playtest/28`](../playtest/28-siege-breach-measurement.md) §1），
在 18.2 fps 是 30 秒，在 240 fps 是 2.3 秒。
**所有以「幀」為單位的戰術規則都被壓縮了 13 倍。**

## 3. remake 怎麼換算

原版的量子是 3.43 ms，remake 的畫面更新是 16.7 ms，除不盡。
用整數「每畫面幾步」最好也只能差兩成，所以改成**定點累加器**——
與原版同一條規則，只是把「等 N 個中斷」換成「攢滿 N 個中斷單位」。

```
每個畫面更新：累加器 += 2913          # 291.3 ÷ 60，放大 600 倍
一步的成本   ：檔位 × 600             # 戰略
             ：檔位 × 600 × 16        # 戰術
while 累加器 >= 成本: 累加器 -= 成本; 推進一步
```

放大 600 倍是為了讓 291.3/60 ＝ 4.855 變成整數 2913，
**誤差 0.001%**，而且不需要浮點數（存檔與重播要位元一致）。

| 檔位 | 戰略：子刻／秒 | 一個遊戲日 | 戰術：戰場 fps |
|---|--:|--:|--:|
| 1 高速 | 291.3 | 0.74 秒 | 18.2 |
| 2 普通 | 145.7 | 1.48 秒 | 9.1 |
| 3 低速 | 97.1 | 2.22 秒 | 6.1 |
| 4 最低速 | 72.8 | 2.97 秒 | 4.6 |

### 最高速（檔位 0）是 remake 差異

原版這一檔是「不等待」，速度由機器決定，**沒有可抄的數字**。
remake 給它一個固定上限，取先前 remake 的最快值，
讓「最高速」至少不比舊版慢：

| | remake 的上限 |
|---|--:|
| 戰略 | 每畫面 16 子刻（960 子刻／秒，0.225 秒一日）|
| 戰術 | 每畫面 4 幀（240 fps）|

⚠ **標成 remake 差異**，不要寫進機制文件當原版行為。

### 預設值也是 remake 差異

原版預設兩個都是最高速；remake 預設**普通**（檔位 2），
理由同上——現代機器上最高速等於沒有節流。
`-speed`／`-tactical-speed` 兩個旗標改成收檔位 0–4。

### 暫停

舊的 `speed == 0 ＝ 暫停` 拿掉——0 在原版是最快，不是暫停。
戰略層的暫停照原版規則走「開非常駐視窗就停」
（[`../mechanics/15-realtime.md`](../mechanics/15-realtime.md) §2），
**戰術層沒有暫停**（說明書 4.1）。

## 4. 改哪幾支 Go

| 檔案 | 改什麼 |
|---|---|
| `cmd/wlgame/strategyhud.go` | `speedTicks`／`speedLevel` 拿掉；`g.speed`／`g.tacticalSpeed` 直接存檔位 0–4；`cycleSpeed` 變成 `(檔位+1) mod 5`；`adjustSpeed` 改成調檔位（＋ ＝ 更快 ＝ 檔位 −1）|
| `internal/rules/speed`（新）| `Throttle` 累加器 ＋ `Steps()` ＋ 五個檔位的字。**桌面版與手機版共用** |
| `cmd/wlgame/main.go` | 主迴圈用累加器決定這一畫面推進幾個子刻；旗標改收檔位 |
| `internal/ui/phone/session.go` | 手機版的 `Tick()` 用同一個累加器；檔位在系統面板調 |
| `cmd/wlgame/battle.go` | 戰場迴圈用累加器（乘 16）決定推進幾幀 |

`internal/state` **不動**——節流不改任何規則，規則層照舊以 tick 驅動。

⚠ 節流器本身放在 `internal/rules/speed` 而不是某個呈現層底下：
**手機版也要用同一份**。兩個 UI 各寫一份累加器必然會長出差異，
而時間流速的差異是最難查的一種（`CLAUDE.md` §7 第 6 條）。
