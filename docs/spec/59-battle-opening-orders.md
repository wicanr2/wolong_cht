# 59 — 開場的常令：腳本那一側不要先下「攻擊」

**狀態：CONFORMED。** 原版兩側都是**站在陣形上等**，動作由腳本第一批指令發起；
remake 先前一律先下一發「攻擊」，於是**開局第一個 tick 兩側就都衝出去了**。
改成「玩家側與腳本側都下命令 0（陣形）」之後，小地圖上玩家側的部隊點
與原版**完全相同**。

- 日期：2026-08-18
- 出處：`BATTLE.DAT` 的段（[`../formats/07`](../formats/07-battle.md) §6、
  [`../re/11`](../re/11-tactical-battle.md) §3.5）、實機截圖（§3）
- 推論等級：**強證據**（腳本內容 confirmed，開場常令由畫面反推）

## 1. 原版做什麼

AI 那一側由 `BATTLE.DAT` 的一段驅動，段編號 ＝ 武將 `+0x16` × 4 ＋ 戰場類別。
張遼（`+0x16` ＝ 2）在攻城那幾段的開頭是：

```
msg  …            開場對白
wait 15
msg  …
line 0            陣形線
form 1            ⭐ 換成陣形 1
order 全軍 命令0   ⭐ 命令 0 ＝ 走到陣形指定的座標
wait 35
…
```

**第一個動作指令是「走到陣形」不是「攻擊」。** 玩家那一側也一樣——
實機截圖上玩家的兵整齊站在陣形線上沒有動。

## 2. remake 先前怎麼做

`internal/state/tactical.go` 的 `beginTactical` 對**兩側**都先
`b.Order(side, -1, tactical.Attack)`，理由寫在註解裡：
「腳本第一個指令通常是查詢，免得沒有腳本的那一場開局所有人都站著不動」。

代價是：有腳本的那一側在腳本跑到 `order` 之前就已經在衝鋒，
等腳本說「走到陣形」時人已經散開，**再也回不到原版那張圖**。

## 3. 證據：小地圖上的部隊點

拿同一個局面對拍（[`../playtest/40`](../playtest/40-tactical-parity.md) §5），
把小地圖的部隊點還原成戰場座標（`workplace/scratch/minidots.py`）：

| | 原版 | remake（開場 0 步）|
|---|---|---|
| 玩家側（色 10）| X ∈ {3, 5}、Y 7–55 | **完全相同** |
| 腳本側（色 3）| X ∈ {56, 57, 59, 60}、Y 19–44 | X ∈ {58, 60}、Y 7–55 |

腳本側那個 4 欄 × 12 列的形狀在十六個陣形裡是**唯一**的：
陣形 1 的 `dx ∈ {−2,−1,1,2}`、`dy −13..12`（`workplace/scratch/forms.py`）
——與腳本裡的 `form 1` 對上。

## 4. remake 實作

| 項目 | 位置 |
|---|---|
| 開場常令 | `internal/state/tactical.go` `beginTactical`：**玩家側**與**腳本側**都下命令 0（`tactical.Form`）；沒有腳本的**非玩家**側維持「攻擊」|

⚠ **沒有腳本的非玩家側不要一起改。** 那一側代表「規則層自己跑的 AI」，
把它改成站著不動會讓野戰 fixture 永遠打不完（既有的長跑測試會卡住）。
