## 1. 原版做什麼

AI 那一側由 `BATTLE.DAT` 的一段驅動，段編號 ＝ 武將 `+0x16` × 4 ＋ 腳本槽；四槽對應沿上節訂正。
張遼（`+0x16` ＝ 2）在攻城那幾段的開頭是：

```
msg  …            開場對白
wait 15
msg  …
line 0            陣形線
form 1            ⭐ 換成陣形 1
order 全軍 命令0   ⭐ 命令 0 ＝ 走到陣形指定的座標
wait 35
…
```

**第一個動作指令是「走到陣形」不是「攻擊」。** 玩家那一側也一樣——
實機截圖上玩家的兵整齊站在陣形線上沒有動。

## 2. remake 先前怎麼做

`internal/state/tactical.go` 的 `beginTactical` 對**兩側**都先
`b.Order(side, -1, tactical.Attack)`，理由寫在註解裡：
「腳本第一個指令通常是查詢，免得沒有腳本的那一場開局所有人都站著不動」。

代價是：有腳本的那一側在腳本跑到 `order` 之前就已經在衝鋒，
等腳本說「走到陣形」時人已經散開，**再也回不到原版那張圖**。

## 6. ⭐ 連帶抓到的規則 bug：陣形線查表用了側編號

`lineX` 那兩組常數（玩家 5／28／48、腳本 58／36／16）綁的是
**玩家與腳本**，不是攻方守方，也不是 remake 的側編號——
原版的 side 0 永遠是玩家（[`56`](56-battlefield-rotation.md) §1）。
而 remake 的 side 0 是**攻方**，玩家守城時兩者剛好相反。

所以腳本的 `line` 指令要查**角色**那一列：`LineFor(b.Role(side), arg)`。
用側編號查的話，玩家守城時腳本會把自己的陣形線設成 X=5（玩家那一條），
整支軍團往對面走——症狀在小地圖上一眼可見，敵方的部隊點從 X=58 一路掉到 38。

接對之後腳本側走完 `line 0` → `form 1` → `order 全軍 命令0`，
在第 40 步站定，與原版**只差 8 個像素**。

| 步數 | `sb-minimap` |
|---:|---:|
| 0 | 1.60% |
| 24 | 1.09% |
| **40** | **0.04%（NEAR）** |
| 56 | 0.04% |
