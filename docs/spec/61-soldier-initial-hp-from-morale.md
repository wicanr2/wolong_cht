## 1. 原版做什麼

編一隊上場時（`sub_19B6D`），八個兵的記錄一次寫齊：

```asm
00019B73  mov ah, [bx+6]            ; ★ 軍團摘要的 +0x06 ＝ 士氣
...
00019BBA  mov cx, 8                 ; 一隊八個兵
00019BBD  mov es:[di+3], ah         ; ★ 體力 ← 士氣
00019BC1  mov es:[di+4], al         ; 兵種 × 18
00019BC5  mov es:[di+18h], dl       ; 戰力（另一條算式）
00019BC9  mov byte ptr es:[di+19h], 80h
00019BCE  mov word ptr es:[di+1Ah], 1
00019BD4  add di, 20h / loop
```

`word_1D30A:+0x06` 開打時由 `sub_19E70` 從軍團記錄抄進來
（[`../re/11`](../re/11-tactical-battle.md) §3.9），也就是大地圖上看得到的
那個士氣值。**士氣高的軍團，每個兵開場血就厚。**

### 1.1 100 是回復上限，不是開場值

`sub_1B97E` 的 `cmp [bx+3], 64h` 把**回復**擋在 100
（[`../re/11`](../re/11-tactical-battle.md) §5）。兩件事不衝突：
士氣 200 的軍團開場每個兵 200 點，掉到 100 以下才開始回，
回也只回到 100。

### 1.2 側欄那條體力條讀的是大將

`sub_1C6F6` 用 `word_1D30E:+0x03`（我方）與 `+0x603`（對方），
也就是**每側第 0 個單位**的體力，畫成 `值 × 3 ÷ 4`、上限 124
（[`../re/60`](../re/60-tactical-sidebar.md) §5）。上限 124 對應到值 165，
所以士氣 200 的軍團開場那條是滿的。

## 2. 演算法

```
Deploy(側, 隊, 兵種, 兵數):
    每個兵.體力 ← 該側的軍團士氣          # 不是 100
```

## 5. ⛔ 擋住這一條的是戰鬥迴圈，不是這一條

把開場體力改成士氣（士氣 200）之後，戰術戰鬥**不會結束**：
跑 95 萬 tick，場面一個 byte 都沒動。

重現（0.01 秒一輪，改回 `HP: MaxHP` 就正常結束）：
劇本 0、`rng.NewFixed(5)`、雙方君主各編一支滿編軍團互相進攻，
`SyntheticFormations()` ＋ 全 0 的平地戰場，開到戰術畫面後 `Run`。

卡住的樣子：

| | 側 0 | 側 1 |
|---|---|---|
| 存活 | **2**（大將 ＋ 一名騎馬，都在 X=3、命令「就位」、HP 滿 200）| 48 |
| 待機 | 0 | 84–90 |
| 大將 HP | 200（一次都沒被打到）| 189 |

側 1 的 48 個兵全部鎖定側 0 的兵 8、目標座標 (3,28)，其中至少一個
（兵 17）就站在 (3,29)——**曼哈頓距離 1、同一層**，`doAttack` 的
命中條件成立，卻連續 95 萬 tick 沒有造成任何傷害。

⭐ **為什麼開場 100 時看不到**：`applyHit` 的退卻閘是 `e.HP < MaxHP`。
開場剛好等於 100 時，第一次挨打就低於門檻、第二次就排退卻，
受傷的兵很快走光，`Remaining()` 歸零，戰鬥就結束了——
**是「大家都很快退場」蓋住了打不到人這件事**。開場 200 的兵要挨滿
100 點才會排退卻，於是留在場上，缺陷才浮出來。

原版沒有這個問題：`sub_1AE56` 的門檻是大將體力 < 0x32 → 全軍退卻，
而原版的兵真的會被打死。
