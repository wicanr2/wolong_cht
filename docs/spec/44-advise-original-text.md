`{6}` ＝ 排版標記（空字串）。

## 3. 說服迴圈：再往後 16 則

君主回答「聽你這麼說，看來是有勝算囉？」（結果碼 2）之後，
`sub_13830` 做 `add word ptr [bp+0], 10h` 才呼叫 `sub_13B5A`。
**所以說服那一段全部相對於 `base + 16`**——而 `base + 16` 那一則
正好是五行的選單，也就是 [`../playtest/32`](../playtest/32-talk-layout-fit.md) §2
標出來的四則五行訊息之三：

| 指令 | `base+16` | 選單五列 |
|---|---:|---|
| 敵對 | **102** | 外交關係惡劣／我國較有利／敵正侵攻他國／敵勢力疲乏／撤回進言 |
| 停戰 | **166** | 對我國較不利／我正在防禦戰／敵正侵攻他國／我國力疲乏／撤回進言 |
| 協力 | **230** | 外交關係良好／協力國強大／侵攻對象強大／我正在防禦戰／撤回進言 |

⭐ **選單的列序就是索引算式吃的「位置」**，理由本身的編號無關。
`persuasion.Options(c)` 的順序因此是資料，不是排版選擇。

以 `b` ＝ `base + 16`、`p` ＝ 位置（0–4，4 是撤回）：

| 誰說 | 索引 | 敵對那一組的例子 |
|---|---|---|
| 軍師說出那一列（`sub_13B5A`）| `b + p + 1` | #103「必然將會與之敵對，我想先下手為強．．．」|
| 君主：理由不成立 | `b + p×9 + 6` ＋ 變體 | #108「{4}！！你連個外交也無法掌握嗎！！」|
| 君主：湊夠了 | `b + p×9 + 9` ＋ 變體 | #111「嗯，也許正如你所說。好，馬上開始進攻。」|
| 君主：還要再一個 | `b + p×9 + 12` ＋ 變體 | #114「又憑這點理由就要開戰的話嘛．．．．．．．」|
| 君主：撤回 | `b + 42` ＋ 變體 | #144「輕率行動又怕會失策啊．．現在不是那種時機。」|
| 君主：同一個理由講第二次 | `b + 45` ＋ 變體 | #147「別再說了！光是這樣，不能准許出兵進攻！」|

君主那幾則一樣**每個位置佔三則**（說話型變體）；軍師那五則各一則。

### 3.1 塊長 64 是一個免費的交叉檢查

一個指令用掉 16（§2）＋ 1 ＋ 5 ＋ 36 ＋ 3 ＋ 3 ＝ **64 則**，
而 86 ＋ 64 ＝ 150、150 ＋ 64 ＝ 214 —— 正好是另外兩個起點。
**三個獨立取得的立即值把版面算式封死了**，不必逐則去猜哪一格屬於誰。

## 4. remake 改了什麼

`cmd/wlgame/advise.go` 先前用的是**改寫過的中文**，而且三個指令共用一組。
對照第一句就看得出來：

```
remake  「不可答允，別平白增加敵人。」
原版    「無法答允！別平白增加敵人。」
```

⚠ 更嚴重的是**停戰與協力顯示的是敵對那一組的措辭**——原版三組各不相同。

改法：`adviseTalkBase(cmd)` ＋ `adviseTalkIndex(base, 位置, 變體)`，
全部改成 `g.talkLines(...)` 查 `TALK.DAT`。
玩家看得到的文字**不再寫在 Go 原始碼裡**（`CLAUDE.md` §6）。

說服迴圈同樣：`adviseReasonBase` ＋ `adviseReasonSlot` ＋ `adviseReasonReply`，
選單五列由 `adviseReasonLabels` 直接讀 `TALK.DAT` 的那一則五行訊息。

**保留的 remake 差異**：進言仍走清單視窗（有一份對話紀錄），
不是原版「插圖 ＋ 兩個框輪流講話」的模態流程，所以每一行前面留
「君主：」「軍師：」當說話者標記——那個視窗沒有肖像可以分辨。
