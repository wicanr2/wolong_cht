## 1. 原版做什麼

投影本身是 2:1 等角：

```
欄 col = X + Y
列 row = (Y − X) sar 1 + 0x20 − Z        ; sar ＝ 算術右移，負數往下取整
```

鏡頭原點由 `sub_1DC9D` 用**同一條式子**算出來，存成
`word_1E160`（欄）與 `word_1E162`（列）。

⭐ **但顯示格上的位置有兩條路，而且兩條不等價：**

| 誰 | 怎麼算 | 出處 |
|---|---|---|
| **地形** | 從鏡頭那一格開始**走**：交替 `di += 40h`（Y+1）與 `di += 1`（X+1），每走一步顯示格前進一格（`si += 20h`）| `sub_1DC9D` 的兩層迴圈（外 30 列、內 15 次 × 2 ＋ 1 ＝ 31 格）|
| **物件**（兵／旗／投射物）| 各自投影，再減掉鏡頭原點：`col − word_1E160`、`row − word_1E162` | `sub_1DAAA`，呼叫者 `sub_1B240`／`sub_1B360`／`sub_1B3B2` |

## 2. ⭐ 座標框：原版的 Y 比地形列號大 1

繪圖端用**整塊 4,096 B** 的線性索引定址（`di = Y × 64 + X`，邊界檢查是
`cmp di, 1000h`），而每張戰場的前 64 B 是表頭——所以**原版的 `Y = 0`
指的是表頭那一列**，第一列地形是 `Y = 1`（[`../formats/07`](../formats/07-battle.md) §2.1）。

remake 的格子陣列 `Tiles(n)` 只含 62 列地形，列號從 0 起算，兩個框差 1。

**換算只做一次，做在投影的入口**（`isoProject`／`cellOffset` 收到地形列號
之後加 `originalRowBias`）。鏡頭、游標十字、縮圖點選公式**全部照抄原版的框**，
不必逐個減：

| 誰 | 框 | 值 |
|---|---|---|
| 鏡頭 `camWorldX/Y` | **原版** | 初值 `sub_199F3` 的 `(0x24, 0x0E)` |
| 縮圖點選 `((滑鼠x − 0x1F0) >> 1 \| 1) − 0x13` | **原版** | 照抄 |
| 游標十字 | **原版** | `X − 4`、`Y + 0x13`（`0001C106`／`0001C103`）|
| `Tiles()`、規則層、小地圖、存檔 | **地形列號** | 從 0 起算 |
| `isoProject`／`cellOffset` 的參數 | **地形列號** | 入口加 1 |

X 不受影響（表頭佔的是一整列），所以陣形原點（`word_1D33C` ＝ 5、
`word_1D33E` ＝ 58）、城門 X、圖塊值的換算都照抄。

⚠ **不能改成「把鏡頭減 1」了事。** 地形那條式子（走訪）只看 `Y − camY`，
兩邊各減 1 會抵消；**物件那條抵消不掉**——它是「各自 `floorDiv2` 再相減」，
而 `floorDiv2` 不是線性的，兩邊各差一列會讓**一半的物件比腳下的地形低一列**
（§3 是同一個非線性的另一種表現）。

## 3. 兩條路差在哪

走訪那一條等價於

```
dcol = (X + Y) − (camX + camY)
drow = floorDiv2( (Y − X) − (camY − camX) ) − Z
```

推導：第 r 列從 `(camX − r, camY + r)` 起走（`di -= 390h`／`dec bp` 那兩行），
第 s 格的半列位移 `h = (Y−X) − (camY−camX) = 2r + (s mod 2)`；
而 s 與 h 恆同奇偶，所以 `r = floorDiv2(h)`。

投影那一條是 `floorDiv2(Y−X) − floorDiv2(camY−camX) − Z`。

⭐ **`floorDiv2(a) − floorDiv2(b) ≠ floorDiv2(a − b)`**：`b` 是偶數時兩者相同，
**`b` 是奇數時對一半的格子差一列**（差的正是 `s` 為奇數、也就是 anchor 那一半）。

⚠ **奇數不是邊角情況。** 縮圖點選的公式

```
camY = (((滑鼠x − 0x1F0) >> 1) | 1) − 0x13      ; ← | 1 把它強制成奇數
camX = (((0xCF − 滑鼠y) >> 1) & ~1) + 4
```

那個 `| 1` 保證**玩家一點縮圖，鏡頭的 Y 就是奇數**（原版的框）。初值
`sub_199F3` 的 `(0x24, 0x0E)` 是偶數，所以「只在初始畫面驗」會完全看不到
這個差別。奇偶看的是 `camY − camX` 的奇偶，而 §2 的兩個 −1 同時作用在
列號與鏡頭上，所以換到 remake 的框不會改變它。

（23.19% vs 23.11%），但那是拿狀態差當背景雜訊在比——
**照抄原版的兩條路，不要為了對稱把它們合併。**
