## 1. 原版做什麼

投影本身是 2:1 等角：

```
欄 col = X + Y
列 row = (Y − X) sar 1 + 0x20 − Z        ; sar ＝ 算術右移，負數往下取整
```

鏡頭原點由 `sub_1DC9D` 用**同一條式子**算出來，存成
`word_1E160`（欄）與 `word_1E162`（列）。

⭐ **但顯示格上的位置有兩條路，而且兩條不等價：**

| 誰 | 怎麼算 | 出處 |
|---|---|---|
| **地形** | 從鏡頭那一格開始**走**：交替 `di += 40h`（Y+1）與 `di += 1`（X+1），每走一步顯示格前進一格（`si += 20h`）| `sub_1DC9D` 的兩層迴圈（外 30 列、內 15 次 × 2 ＋ 1 ＝ 31 格）|
| **物件**（兵／旗／投射物）| 各自投影，再減掉鏡頭原點：`col − word_1E160`、`row − word_1E162` | `sub_1DAAA`，呼叫者 `sub_1B240`／`sub_1B360`／`sub_1B3B2` |

## 2. 兩條路差在哪

走訪那一條等價於

```
dcol = (X + Y) − (camX + camY)
drow = floorDiv2( (Y − X) − (camY − camX) ) − Z
```

推導：第 r 列從 `(camX − r, camY + r)` 起走（`di -= 390h`／`dec bp` 那兩行），
第 s 格的半列位移 `h = (Y−X) − (camY−camX) = 2r + (s mod 2)`；
而 s 與 h 恆同奇偶，所以 `r = floorDiv2(h)`。

投影那一條是 `floorDiv2(Y−X) − floorDiv2(camY−camX) − Z`。

⭐ **`floorDiv2(a) − floorDiv2(b) ≠ floorDiv2(a − b)`**：`b` 是偶數時兩者相同，
**`b` 是奇數時對一半的格子差一列**（差的正是 `s` 為奇數、也就是 anchor 那一半）。

⚠ **奇數不是邊角情況。** 縮圖點選的公式

```
camY = (((滑鼠x − 0x1F0) >> 1) | 1) − 0x13      ; ← | 1 把它強制成奇數
camX = (((0xCF − 滑鼠y) >> 1) & ~1) + 4
```

那個 `| 1` 保證**玩家一點縮圖，鏡頭的 Y 就是奇數**。初值 `sub_199F3` 的
`(0x24, 0x0E)` 是偶數，所以「只在初始畫面驗」會完全看不到這個差別。

## 3. remake 實作

| 項目 | 位置 |
|---|---|
| 地形（顯示格）| `cmd/wlgame/battleview.go` `cellOffset` — **相對鏡頭算，不要各自投影再相減** |

**兩條路都要留著。** 把物件也改走 `cellOffset` 量起來差不多
（23.19% vs 23.11%），但那是拿狀態差當背景雜訊在比——
**照抄原版的兩條路，不要為了對稱把它們合併。**
