# 94 — 退卻的繞路點不可以每幀清掉

**狀態：CONFORMED。** 兩處各自都會讓退卻的兵鎖死：`doRetreat` 每幀清掉
繞路點，以及 `replan` 看到「手上有路」就直接返回。修好之後那條攻城
fixture 在第 **1,416 幀**結束（守方勝，攻方全部退出畫面）——在那之前
跑到 12,000 幀還是 `Done=false`，而且從第 1,600 幀起一個 byte 都沒變。

- 日期：2026-08-27
- 出處：[`../re/11`](../re/11-tactical-battle.md) §5.8k（`sub_1B00D` 的繞路點清單）、
  §5.8g（`sub_1AAED` 的退卻出口座標）、§5.16（`sub_1B732` 對調的四道閘）
- 推論等級：confirmed（原版的繞路點存在兵記錄裡由 `sub_1B00D` 逐點消費，
  退卻的每幀處理沒有清它的動作）

## 1. 原版做什麼

繞路點清單在 `0x1800 + 兵編號 × 128`，由 `loc_1BD46` 在**走不動的那一刻**
算一次，`sub_1B00D` 每次抵達目前的中繼點才消費下一個
（[`../re/11`](../re/11-tactical-battle.md) §5.8k）。
退卻（命令 5）的每幀處理只寫出口座標，**不碰那張清單**。

對調（`sub_1B732`）有四道閘，其中一道是**擋路的正在退卻就不能換**
（`[di+1A] == 5`）。所以一排退卻中的兵彼此穿不過去——
**能繞開是靠繞路點，不是靠對調。**

## 2. remake 現況與症狀

```go
func (b *Battle) doRetreat(side, k int) {
    s.Path = nil        // ← 每一幀都清
    s.PathAt = 0
    ...
}
```

一幀之內的順序是 `doRetreat` → `moveToward`（用繞路點）→ 走不動 → `replan`（算繞路點）。
清除發生在最前面，所以 `replan` 算好的路**下一幀開頭就被丟掉**，
`moveToward` 永遠只看得到終點。

量到的死鎖（據點 82、`SAVE-E.DAT`、軍團 81 攻 39 守，seed 7）：

| frame | 側 0（攻方）|
|---:|---|
| 1200 | 活 48、兵 600、大將體力 80 |
| 1600 | 活 23、兵 197、大將體力 40 → **全軍退卻**（`sub_1AE56` 的門檻 50）|
| 2000–4000 | **一個 byte 都沒變**：活 23、兵 197、位置完全相同 |

逐幀追大將：位 (22,32)、目標 (62,32)、**步 (62,32)**，而繞路點是 (22,31)。
(22,31) 空著、地面層 0、上方沒東西——**它走得過去，只是從來沒有被叫去走**。
擋住它的是 (23,32) 的同伴，命令 5，對調被閘擋下。

`s.PathAt = 0` 還讓 `replanInterval` 的 30 幀節流失效，
48 個兵每幀各跑一次波前擴散。

### 2.1 第二處：`replan` 看到「手上有路」就返回

改掉每幀清除之後，兵從 X 22 前進到 X 43，然後**又卡住**：

```
位(43,30) 目標(62,30) 步(55,30) 命令5 ── 而 (43,29) 空著
```

`replan` 開頭是 `if s.Path.Len() > 0 || b.Frame-s.PathAt < replanInterval`。
兵抱著一條「直線走到 (55,30)」的舊路，路上站著一個退卻中的同伴，
對調被閘擋下——**而它永遠不會重算**，因為它「有路」。

`replan` 只在 `moveToward` 的出口被呼叫，也就是**這一幀走不動或撞到地形**時。
所以「有路又走不動」代表那條路現在不通，原版也是三軸都走不動才重算
（`sub_1AED2`）。那個條件要拿掉，節流留著。

## 3. 演算法

```
doRetreat：
    edge = 這一側的出口 X
    if 目前這條路不是通往 edge 的（含沒有路）:
        丟掉這條路              # 攻擊時算的舊路會把兵留在城門附近
    設定退卻目標 (edge, clamp(Y, 0x10, 0x2F), 0)
```

判準用「**這條路的終點是不是出口**」，不是「有沒有路」——
退卻的繞路點終點一定是 `edge`，攻擊時算的不會是。
這樣既保住原本要擋的東西（舊的攻擊路徑），又讓退卻的繞路點活得下來。

⚠ 退卻目標的 Y 會跟著兵移動而變（它是 `clamp(s.Y)`），
所以**不能拿目標相等當判準**——那會在繞路走 Y 的時候把路清掉，等於沒改。
