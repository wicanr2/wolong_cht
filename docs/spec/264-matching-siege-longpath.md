## 為什麼還要跑（SHA 全同還跑什麼）

與 spec/262 同理：整檔 SHA 同不證明重建產物在戰術路徑上跑得起來。
政略互動已由 spec/262 背書；戰術畫面的載入、擺兵與節拍推進走的是
另一組常式，本片補這一截。**本片不宣稱邏輯相等**（SHA 背書），
只背書「跑得起來且與原版在同一時間軸上逐步一致」。

## 參數定案過程（全部實測，2026-10-14）

1. **舊參數不能抄。** 新遊戲在 4/8 只有 1 支在籍軍團，
   `siege:35,82`（SAVE-B 的舊參數）開不了戰（`runto:11B5A`
   跑滿 8,000 萬道未進戰場）。
2. **玩家勢力要先量。** spec/262 的孫策開局（勢力 1）只有 1 城，
   4/20 無自家軍團，攻其首都直接判定滅亡離開（exit 1）；
   且該勢力不打也會在 5 月初被 AI 滅掉。本片改選**曹操**
   （勢力清單第 0 列，`click:320,132`／`320,140`，列帶 y 128..143
   由熱區圖與反白截圖實測）。
3. **城兵守城不開戰術。** `siege:35,74`（打曹操的城 74）結果是
   訊息「陳留受到呂布兵馬的攻擊，被攻陷了！！」——無駐軍軍團的
   據點直接被攻陷，只留一則事件訊息。戰術畫面要求**玩家軍團**
   是攻方或守方。
4. **玩家軍團靠編成。** 玩家勢力（任一勢力）開局都不自動部署
   軍團——部署是軍師進言／編成流程。沿 playtest/67 §5 六步
   （指令列 → 編成 → 武將一覽點兩次 → 編成面板確定），
   實測編出軍團 **37**（勢力 0、主將 37、兵 600）駐許昌（82）。
5. **攻城參數：** `siege:37,76`。據點 76 是呂布（勢力 13）的城，
   軍團 35 駐守；玩家為攻方。原版側實跑：`runto:11B5A` 命中、
   戰場開出（權陽作戰，曹操對呂布）、`units` 兩側單位在場。

⚠ 本片開局與 spec/262 不同（勢力列點 132/140 而非 144/152），
兩片的 `boot`..`list` 截圖本來就不該相同；本片只要求**本片的時間軸
在原版／重建兩側逐步全同**。

## 時間軸（兩側同一串）

1. 開局段：開機 → 第一章 → 曹操列（132/140）→ 命名 → 開局 →
   右鍵關進言 → 指令列 → 財政（`shot:fin`）→ 人事清單
   （`shot:list`）→ `steps:3000000` 讓事件訊息出現 → 右鍵關閉 →
   `until:196/4/12`。
2. 編成段：`sclick:352,15` 開指令列 → `stap:192,47` 編成 →
   `tap:150,112` ×2（反白＋開面板）→ `tap:324,279` 確定 →
   `tap` 關對話 → 右鍵 ×2 離開。
3. 攻城段：`siege:37,76` → `runto:11B5A,80000000` →
   `steps:6000000` → `shot:battle` → `units` → `clock`。

⚠ 即時制：取樣點寫成遊戲日期與流程節點，不寫秒數。
每步 `steps:` 預算兩側相同，截圖同名。

## 驗收

- 同名截圖（`fin`／`list`／`battle`）SHA-256 全同；
  `units`／`clock` 輸出全同；最終累計指令數全同。
- 任一不同即停：先懷疑載入／路徑／座標序列，不懷疑邏輯。
- 產出：playtest 收據、本 spec 升 CONFORMED、CONTEXT 回填。
- 原版素材唯讀；`longpath-rebuilt/` 沿用 spec/262 的本地副本。
