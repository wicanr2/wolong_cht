## 1. 原版做什麼

```asm
確定:
  cmp byte [si+29h], 0
  jnz → 成立
  sub_18810(cx=3Eh)            ; #62「大將的部隊的兵員不足啊。」
  jmp draw
成立:
  sub_16F26                    ; 實際編成
  di -= 4
  bx = (si − 2240h) >> 1       ; → 武將位移
  sub_18810(cx=19Bh, ah=[bx+425Eh], al=[bx+4241h])
```

- `cx = 0x19B` 是**組編號**不是索引。
- `ah = 武將 +0x1E` ＝ 說話類型，選組內第幾個。
- `al = 武將 +0x01` ＝ 肖像頁，所以框上是**那位主將自己的臉**。

## 2. 演算法

`TALK.DAT` 索引 ≥ `0x196` 是八格一組：

```
索引 = 0x196 + (組編號 − 0x196) × 8 + 說話類型
     = 0x196 + (0x19B − 0x196) × 8 + 說話類型
     = 446 + 說話類型
```

八句實際的內容：

| 說話類型 | 索引 | 內容 |
|---:|---:|---|
| 0 | 446 | （空）|
| 1 | 447 | （空）|
| 2 | 448 | （空）|
| 3 | 449 | 立刻完成編成。 |
| 4 | 450 | 遵命！各位！出陣了！ |
| 5 | 451 | 要開戰了嗎．．好，我這就出陣。 |
| 6 | 452 | 那麼就去進行出陣的準備。 |
| 7 | 453 | 我一定取回敵人的首級。 |

⭐ **0–2 是空的，而 0–2 正是「主公型」**（[`../formats/08`](../formats/08-sinario-save.md) §3
的 `+0x1E`：0–2 主公型／3–7 臣下型）。原版的編成候選排除君主，
所以那三格永遠取不到——**空字串不是資料瑕疵，是那條路走不到**。

⚠ 但 remake **允許把君主編成軍團長**（[`76`](76-lord-not-in-formation.md)，
使用者裁定的差異）。所以 remake 會走到 0–2 那三格。
**取到空字串就不要開框**——原版沒有這個狀態，硬跳一張空框是編出來的行為。

實機對照：張遼的 `+0x1E` ＝ 7 → #453「我一定取回敵人的首級。」，
與 [`../playtest/56`](../playtest/56-lubu-flow-parity.md) §4.4 的原版影格逐字相同。
