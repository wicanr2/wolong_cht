## 1. 原版做什麼

新遊戲是四層，**每一層右鍵退回上一層**（[`../re/73`](../re/73-new-game-faction-list.md) §1）：

```
ＹＥＳ／ＮＯ → 劇本 → 勢力清單 → 君主卡
```

⭐ **君主卡上沒有換勢力的熱區**（[`27`](27-lord-select-window.md) §2.1）——
要換就退回清單。清單是這一份的主題。

### 1.1 視窗

`sub_181C0(dx=88h, bx=68h, cx=0B18h)` → **(136, 104) 384×176**。
尺寸與戰略層那七個一覽表相同，**左上角不同**（[`38`](38-list-windows.md) §1.1 是 (24, 88)）。
框畫在內容區外面，往左上各退 8 px、寬高各多 16 px ⇒ **(128, 96) 400×192**。

| 元件 | 矩形 |
|---|---|
| 欄位標題 | (136, 104) 384×16 |
| 清單本體 | (152, 120) 368×160 |
| ▲ | (136, 120) 16×16 |
| 捲軸槽 | (136, 136) 16×128 |
| ▼ | (136, 264) 16×16 |

### 1.1.1 ⭐ 背景是大地圖，鏡頭固定在 (170, 98)

新遊戲的四層選單**畫在大地圖上**。`sub_11A6E` 在呼叫 `sub_11AC3` 之前先跑：

```asm
mov al, 0 / call sub_10241        ; 調色盤組 0（春）
mov dx, 0AAh / mov bx, 62h        ; ★ 鏡頭 (170, 98) 格
call sub_1D615                    ; 建 40×23 顯示清單（40 欄 × 23 列，跨距 384）
call sub_1D66A                    ; 畫出來
```

`sub_1D615` 的內外迴圈是 `cx=28h`／`dx=17h` ＝ **40×23**，
每列 `add di, 158h`（344 ＝ 384 − 40）——所以 `dx`／`bx` 是**格座標**，
與遊戲中的鏡頭同一個座標系。

⭐ **城池是空白的**：`sub_1D615` **只複製圖塊編號**
（[`../re/67`](../re/67-city-emblem-on-strategy-map.md) §），
歸屬換圖塊（自勢力 −2／他勢力 −1，[`53`](53-city-tile-by-ownership.md)）
與軍團疊圖都不在這條路上。所以據點畫的是 `MMAP.MAP` 的原始圖塊，
沒有勢力徽記——**那不是還沒畫完，是這一層本來就沒有歸屬可畫**。

### 1.2 候選：只看「勢力存在」

callback `cs:7B6F` 掃 22 筆勢力記錄（位移 0 到 `0x580`，步進 `0x40`），
`+0x00 ≥ 0x80` 就收。**沒有別的條件**——新遊戲時還沒有玩家勢力，
所以也沒有「不能選自己」那一類的過濾。

### 1.3 一頁 10 列

callback `cs:7B90` 是十次迴圈，起點 `(視窗X + 18h, 視窗Y + 10h)`、列高 `10h`。
⇒ 第一列在 **(160, 120)**，列首 X ＝ **視窗X ＋ 24**。

### 1.4 五欄

X 是**相對視窗左緣**（＝ 列首再 −24）：

| 欄 | X | 絕對 X | 來源 | 型別 |
|---|---:|---:|---|---|
| 君主名 | 24 | 160 | 勢力 `+0x01` → 武將名 | 名 |
| 軍師名 | 88 | 224 | 勢力 `+0x02` → 武將名（`0x7F` ＝ 無）| 名 |
| 武將數 | 168 | 304 | 勢力 `+0x18` | 3 位數 |
| 據點數 | 216 | 352 | 勢力 `+0x23` | 3 位數 |
| 首都名 | 280 | 416 | 勢力 `+0x03` → 據點名 | 名 |

標題 `cs:7AC6` ＝ `勢力名　軍師名　　武將　據點　　首都`，
分隔線 `cs:7AEB` ＝ `－－－　－－－　　 --　　-- 　　－－－`。
⭐ **標題逐字算出來的落點與欄位表完全一致**（48＋16＝64、48＋32＝144…），
所以標題與列共用同一個列首 X——這一格不必另外找出處。

空槽直接照印分隔線（`sub_17BC0` 開頭那一支）。

| 方式 | 內容 |

| 單元測試 | `TestFactionListPointerRow`：點得到第 n 列；捲動之後對應到正確的勢力；點在標題列或捲軸上不算選列 |
| 單元測試 | `TestLauncherFlowGoesThroughFactionList`：劇本 → 清單 → 卡片，取消各退一層 |
| 單元測試 | `TestLauncherCameraMatchesOriginal`：鏡頭常數就是 `sub_1D615` 的兩個立即值 |
| 截圖 | `WOLONG_SHOT_CMD=wlgame tools/shot.sh <out> KEYS=Return,Return,Return`（**本地產物**）：五欄逐欄對齊標題、捲軸的 ▲▼ 與滑塊、選取列反白 |
| 點擊 | ⛔ **無頭環境送不進去**（§3.1）——命中對應只有單測 |

### 3.1 ⚠ 無頭環境驗不到「點得到」

`tools/shot.sh` 只送按鍵。改用 `xdotool click`／`mousedown`＋`mouseup`
直接對 Xvfb 送，畫面**一格都沒動**——容器裡沒有視窗管理員，
GLFW 的視窗永遠拿不到輸入焦點，滑鼠**按鍵**狀態不會送到 Ebiten。
（滑鼠**移動**送得進去：`ebiten.CursorPosition()` 讀得到，
上一輪抓那個 hover bug 就是靠它。）

⭐ **所以這個專案至今沒有任何一條滑鼠點擊路徑被無頭驗過**——
數值輸入器的 3×6 格、一覽表的列與捲軸、戰場的熱區都一樣，
靠的都是單測把「座標 → 動作」的對應釘住，加上使用者實際玩。
要補這一格得在建置 image 裡加一個視窗管理員，那是另一件事。
