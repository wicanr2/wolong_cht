# 58 — 顯示格的深度範圍與 8 列的帶

**狀態：CONFORMED。** 兩件都接上了，同一個局面的 `field`（扣掉訊息框）
從 **12.8% 降到 3.4%**（[`../playtest/40`](../playtest/40-tactical-parity.md) §6）。

⭐ 城壁面上那排亮邊的真兇是**帶高**：`sub_1E0E1` 一次搬 8 列，
remake 搬了 16 列（§5.1）。深度範圍（§3）是同一支函式的另一半，
照抄之後畫的層數少了一半以上，但**像素幾乎沒變**——被跳過的深度多半是空的。

- 日期：2026-08-18
- 出處：`sub_1DD22`（寫入端與 `+1`／`+2` 的記帳）、
  `sub_1DDB4`（取鄰格高度、兩條路）、`sub_1DE95`（深度迴圈）
- 推論等級：**confirmed（靜態）**

## 1. 顯示格 32 B 的版面

```
+0   旗標
+1   高度（**含物件**）
+2   起始深度：最後一個**小 unit**（< 0x20）的 2z
+3   高度（**只有地形**）——物件擦掉時用它還原 +1
+4   深度 0 的兩個 lane（+4 地形、+6 第二個 producer）
+8   深度 1 …                    7 層 × 4 B ＝ 28 B，加表頭剛好 32
```

⭐ `+1` 與 `+3` 不是同一份的兩個複本：**物件 producer 只抬高 `+1`**
（`sub_1DB34`），**擦除時從 `+3` 還原 `+1`**（`sub_1DB9B`）——
所以物件離開之後深度範圍會自己縮回去。地形存的高度是 `2z`（偶數）、
物件是 `2Z+1`（奇數），那個 byte 同時編碼「第幾層」與「是不是物件」
（[`../re/68`](../re/68-t3-frontier-functions.md) §2.1）。

`sub_1DD22` 每寫完一層 `sub si, 400h`（往上一列）**同時** `sub di, 3FCh`
（＝ −0x400 ＋ 4），所以**第 z 層落在（列 R − z、同一格、深度索引 z）**。
換句話說，一個顯示格的深度 z 收的是**前方第 z 列那一格的第 z 層**——
深度不是同一格的堆疊，是前面幾格的堆疊長進來的部分。

⭐ 每個（格, 深度）**只有一個 producer**：深度 z 的內容固定來自
（列 R+z, 同欄）那一格，不同格對到不同的（格, 深度），不會撞號。

## 2. 記帳：`+1` 與 `+2` 怎麼來的

`sub_1DD22` 進到一格時先 `mov word ptr [si+1], 0` 清掉 `+1`／`+2`
（只清那一格自己的第 0 層那一列），之後逐層：

| unit 值 | 寫什麼 |
|---|---|
| `0` | 什麼都不寫（那一層沒東西）|
| `< 0x20`（小）| `[si+1] = [si+2] = [si+3] = 2z` |
| `≥ 0x20`（大）| `[si+1] = [si+3] = 2z`（**不動 `+2`**）|

因為同一格的各層是**依 z 遞增**寫進來的（深度 z 的來源在走訪的第 R+z 列，
比較晚才走到），所以結果等於：

```
高度   = 2 × max{ z : unit[z] ≠ 0 }              # 沒有就是 0
起始   = 2 × max{ z : 0 < unit[z] < 0x20 }       # 沒有就是 0
```

## 3. ⭐ 要畫哪幾層

`sub_1DDB4` 先把**自己與四個斜鄰格**的高度取**最大值**（`cmp dh, ah / ja`
留大的；被取代時順手設旗標 bit 4），再減掉自己的起始深度：

```
最高 = max(高度[本格], 高度[格−1], 高度[格+1],
           高度[下一列 格−1], 高度[下一列 格+1])
層數 = (最高 − 起始) / 2 + 1          # sub_1DE95 開頭 `inc dx / shr dx,1`，
                                      # 迴圈是 `dec dh / jl` ⇒ 含頭含尾
畫的深度 = 起始/2 … 起始/2 + 層數 − 1
```

意思是：**從這一格自己的地面畫起，畫到自己與鄰居之中最高的那個表面為止**。

- 比自己地面低的深度不畫——那些被自己的地面擋住
- 要畫到最高的鄰居，因為高的鄰居會有半截探進這一格的圖裡

四個鄰格的位移是 `bx-0x20`／`bx+0x20`／`bx+0x3E0`／`bx+0x420`
（格距 `0x20`、列距 `0x400`），與五個貢獻的來源一致。

## 4. 兩條路（本規格暫不動）

```
最高 == 起始 且 起始深度那一層的 unit < 0x20 且 (旗標 & 0x50) == 0
    → sub_1DFBB：跳過遮罩，把那一張 unit 的四個平面直接貼上去
否則
    → sub_1DE95（合成）＋ sub_1DFA6（把 0xE164 的 16×32 貼上去）
```

平坦且不被遮擋的格子走快路徑。**兩條路畫出來的像素在全畫面重繪下相同**
（快路徑那一張本來就不透明），差別是速度與旗標，所以 remake 先不分兩條。

⚠ 合成用的暫存區 `cs:0xE164` **從頭到尾沒有人清空**（全庫只有五處參考它，
四處寫、一處讀）。原版是局部重繪，留著上一格的殘影是刻意的；
remake 每幀全畫，清成黑色與不清實測**逐像素相同**，所以不是差異來源。

### 5.1 ⭐ 一帶是 8 列，不是 16

`sub_1E0E1` 搬遮罩與四個色平面時都是 `mov cx, 8`——**一帶 8 列**。
remake 先前用 `isoRowPx`（16）當帶高，於是每一帶都把下一帶的位置蓋掉一半：

```
      原版                      remake（錯）
帶 1  源 24–31 → 目  0–7        源 24–31 → 目  0–7   （超出 32 列被裁掉，剛好對）
帶 2  源 16–23 → 目  8–15       源 16–31 → 目  8–23  ← 多蓋 8 列
帶 3  源  8–15 → 目 16–23       源  8–23 → 目 16–31  ← 多蓋 8 列
帶 4  源  0–7  → 目 24–31       源  0–15 → 目 24–39  （後半被裁掉）
```

症狀是城壁的面上每一格多出一排亮邊，而且**只有下半格明顯**
（輸出的下半來自帶 3／帶 4）——逐格逐列的差異統計一眼就看得出來：
修之前格內第 8–15 列的差異是第 0–7 列的 2.5 倍，修之後兩者一樣平。
