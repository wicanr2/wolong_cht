## 1. 審查後的契約

原始資料是 DS 相對的日期 bytes、保存的每月天數、月份天數表及速度／等待欄位。
子刻小於 8 只加子刻；否則小時小於 23 只換時，其他情況依日、月、年落下進位。
月份以上進位先重設日期為 0，再呼叫月結；之後日期、小時加成 1。

| 呼叫原始定位 | 順序及當時狀態 |
|---|---|
| `0x15358` | 月結；月已換，日仍為 0，小時／子刻尚未重設 |
| `0x19377` | 季節；日期與小時已進位，子刻為 0 |
| `0x13E11` | 每時世界更新，接在季節之後 |
| `0x11E17` | 日期重畫，接在世界更新之後 |

年份比較是 `<1000`，所以 999 的換年會到 1000；入口年為 1000 或更大時換年回到 999。
此條由原始 bytes 及受控 original probe 支持，不沿用舊「永遠封頂 999」摘要。

## 2. C 介面與可見副作用

適配層收 16-bit 機器狀態與 C callback。所有 DS-relative 讀寫在使用時求有效位址，
callback 的狀態變更會進入後續流程。近呼叫會留下 stack return word，不能只記抽象事件。
比較全部 14 個暫存器／段／FLAGS、日期、等待欄位、完整 callback 順序與可見快照。

callee fixture 使用明示的無副作用 RET 或單純 MOV 寫入；本輪不驗完整月結、季節、AI 或繪圖。
等待 fixture 每次原始 CMP 前提供固定進展，不設定或反推 PIT/DAC wall-clock。
IF/TF=0、偶數且分離的堆疊，月份與日期合法；另枚舉 16-bit 年份上界。

## 3. 驗證閘門

C O0/O2 對照原始 137 bytes；Go 比較限同一日期規則與合法保存狀態。
callback 入口快照必須相同，不能只看最後日期；四個 callee 在 RAM 換為 fixture，
原始函式 bytes 不變。速度 0、已有計數、延後 ready、延後 count 都抽測。
刻意錯的 24 小時、999 上限、呼叫順序與等待門檻版本必須被拒絕。

上述四種突變皆被拒絕，Go 的 292,249 組日期規則對照相同。完整收據、來源身分與
重跑入口見 [`re/93`](../re/93-c-game-clock-restoration.md)。
