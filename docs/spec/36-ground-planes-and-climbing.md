## 1. 原版做什麼

戰場不是一張高度圖，是**兩個平面**：低平面（地面）與高平面（城牆頂）。
每一格每個平面存**一個 byte**：

```
bit 0–2  地面層          bit 3  這一格是門（可以上下）
bit 4 ←  bit 5 →  bit 6 ↑  bit 7 ↓     ← 這四個方向走得通
```

### 1.1 建表（每張戰場一次）

```
每格：
  rec = 圖塊屬性[圖塊]                    # 8 byte：[0] 層數、[1..7] 七層的子圖塊
  if 0xD0 ≤ 圖塊 ≤ 0xDF: rec = 圖塊屬性[圖塊 + 0x10]     # 城壁改讀對應的圖塊
  低 = 層 0–3 裡第一個「子圖塊 ≥ 0x70」的層號，找不到 → 無
  if 低存在 且 圖塊 ≥ 0xF0: 高 = 門標記(8)
  else:           高 = 層 4–6 裡第一個「子圖塊 ≥ 0x70」的層號，找不到 → 無

每格與四個鄰格：
  if 中心高 == 門標記 且 鄰格高 ≤ 6: 中心高 = 鄰格高
  低平面：兩邊都有地面且 |Δ| ≤ 1  → 設方向位元
  高平面：兩邊都有地面且 相等或鄰格是門 → 設方向位元

高平面正規化：
  只統計有門旗標的格子，層 ≤ 4 與 > 4 哪邊多 → 目標高度 4 或 5
  高度不同的格子：是門就改高度；非門只清方向／門旗標，保留高度低3位
```

2026-11-13勘誤：上段為原版`1BC18`契約；remake正規化仍有差異，不由本輪取層修正代證。

### 1.2 尋路

在 **(格, 平面)** 上做 uniform-cost 搜尋：

| 邊 | 條件 | 成本 |
|---|---|---|
| 四方向 | 該方向的位元是 1 | 1 ＋ 佔用成本 |
| 換平面 | bit 3（門）| 兩個平面的地面層差 ＋ 佔用成本 |

**額外成本**是另一張表（`word_1D2FE`）：單兵寫入的值是 **8**。
2026-11-13的原版動態表另見城壁100、門50，舊「其餘0」摘要不完整；來源與生命週期限制見[spec134補記](134-pathfind-wave-order.md)。
同日後續已接入雙平面歷史成本，前153拍8192-byte表吻合；坡地Z不代替平面，舊平面重畫與目前平面移除的差異見該續片。
寫入端是移動落定的 `sub_1B240`，透過 `word_1D2FA` 加 `0x9000` 的位移
寫進去（舊格 0、新格 8，[`../re/63`](../re/63-ground-plane-map.md) §1）。
⇒ **尋路會繞開有兵的格子**，繞路的代價是 8 格。

### 1.3 移動一步（`sub_1B1B1`）

2026-11-13碰撞續片回填：[spec159](159-tactical-command-movement-order.md)區分下方「失敗」摘要的兩種回傳。
普通非結構地形阻擋仍可試其他軸；未破城壁／門碰撞則結束當拍並排尋路，包含守方免傷。
嘗試方向在查詢前更新，沒有位移也會改面向。此片沒有改本節地面層、碰撞形狀或純Z通行判定。

```
目標格任一平面有單位 → 失敗
g = 地面表[格, 平面]
g == 0 → 失敗
低平面：g 的層比自己高 → 升一層；低 → 降一層；相等 → 通過      # 沒有幅度上限
高平面：層必須相等，且目標圖塊不是未破的門（0xF0–0xF7），且命令 ≠ 6
```

### 1.4 上下（`sub_1AF69` → `sub_1B0D3`／`sub_1B116` → `sub_1B186`／`sub_1B15D`）

```
移動順序：先 X、再 Y，兩軸都到位才做 Z
兵種 ≤ 0x12（大將與騎馬）→ 完全不做 Z
往上（sub_1B0D3）：這一格的圖塊 ≥ 0xF0（門）→ 呼叫 sub_1B186
往下（sub_1B116）：同樣的門判定 → 呼叫 sub_1B15D
```

**兩支被呼叫的常式各再擋兩關**（`0001B15D`／`0001B186`，
[`../re/36`](../re/36-tactical-module-map.md) §6.3）：

```asm
al = es:[bx]            ; 往下看低平面；往上是 es:[bx+1000h]
test al, 7Fh / jnz → 失敗            ; ★ 要去的那個平面有兵站著
di = bx & 0FFFh / dl = 地形[di]
xor al, al
cmp dl, 0F8h / jb → 失敗             ; ★ 地形值 < 0xF8 就上不去
clc / retn                            ; ≥ 0xF8 才成功
```

⭐ **`0xF8` 這一關把「門」收成「打破的門」。** 呼叫端只要 `≥ 0xF0`，
被呼叫的這一支要 `≥ 0xF8`，而**兩邊讀的是同一格的同一個 byte**
（`di = bx & 0FFFh` 把平面位元遮掉了）。合起來就是：
**登城只在已經打破的門那一格發生**——城牆本體爬不上去，
未破的門也爬不上去，**撞開它才通**。

⚠ **尋路那邊沒有這一關。** §1.2 的換平面邊看的是導航表的 bit 3，
而建表時 `圖塊 ≥ 0xF0` 就設門標記（§1.1）——所以**原版的路徑會規劃穿過
未破的門，走到那一格才被 `sub_1B186` 擋下**。這個不對稱照抄，不修正。

⚠ 被兵擋住時原版還有一條退路：`loc_1B533`（換位）。`al` 不是 0
（＝ 擋路的是一個兵）才試，成功就算走成功了。

## 2. remake 做什麼

| 項目 | 做法 |
|---|---|
| 資料 | `internal/assets/battle` 多一支 `TileLayers(n)`，回傳那一組圖塊的 `[256][7]byte` 子圖塊表 |
| 建表 | `Field` 多兩張導航表（方向位元 ＋ 門旗標）與兩張地面層表。**層數另外存**：原版靠「整個 byte 是 0」代表沒有地面，而 remake 的 Z 從 0 起算，擠在同一個 byte 會撞號 |
| Z 的意義 | **兵腳下佔的那一層**，與原版同一個座標系（頂面那一層不擋人，兵站在它上面）|
| 每層擋不擋人 | 照子圖塊重算（`sub_1BB6D` 的 0／≥ 0x70 不擋），不再用「堆疊高度以下全實心」|
| 沒有圖塊層資料時 | `NewField(stack)` 這種合成戰場：地面層 ＝ 堆疊高度、堆到 4 層以上算牆頂、有圖塊值就照 `≥ 0xF0` 認門。**同一套演算法，只是輸入退化** |
| 尋路 | `FindPath` 改成在 (格, 平面) 上搜尋，邊照 §1.2 |
| 移動 | `tryMove` 照 §1.3：先查目標格**頭頂那一層**擋不擋（原版 `es:[bx+1000h]`），再讀所在平面的地面層同步高度 |
| 上下 | `Soldier` 多一個 `OnWall`；X／Y 都到位之後才做 Z，且**只在打破的門那一格**（`IsGateCell` ＋ `!GateBlocksHighPlane`）。要去的那個平面有別人也上不去 |
| 兵種閘 | `CanClimb`（兵種 > 0x12）改成**只擋純 Z 移動**，不擋水平移動 |

### 2.1 這修掉什麼

`docs/playtest/28` 量到 remake 的攻方**一次都沒碰到城壁**。
接上之後同一組測量打掉 480 點耐久、最低的一段只剩 20
（[`../playtest/30`](../playtest/30-ground-planes-implemented.md)）。

⚠ **攻城還是打不下來**，但卡點換成「攻方大多數不前進」——
那是攻擊命令的目標選擇，與地形無關。

### 2.2 會翻掉的既有測試

| 測試 | 為什麼 | 怎麼改 |
|---|---|---|
| `TestCavalryCannotClimb` | 它把「騎馬爬不上牆」釘在**水平移動**上，而原版擋的是**純 Z 移動**（`../re/63` §4）| 改成「城壁那一格誰都走不上去」＋ 新的 `TestClimbOnlyAtGateCells` |
| `TestPathUnreachable` | 它假設「一層高的坎擋得住爬不上去的兵」 | 高度差 ≤ 1 的連通與兵種無關，改成兩種兵都過得去 |
| `TestHorizontalStepAdjustsOneLevelForNonClimber` | 用高度差 2 當「跨一層」 | 改成真正的一層 |

**訂正的證據**：`sub_1AF69` 的兵種閘明文只包住 `sub_1B0D3`／`sub_1B116`
那兩支，而 `sub_1B1B1`（水平）整支沒有兵種判斷。
