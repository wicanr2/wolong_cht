## 1. 錢只從四個地方進出

24 位飽和加減的四支常式，`tools/ida_money_flow.py` 列出全部呼叫端：

| 常式 | 動作 | 欄位 | 呼叫端 |
|---|---|---|---|
| `sub_15609` | 資金 `+=` | `+0x20`／`+0x22` | `sub_135ED`、`sub_15358`（月結）、包裝 `0x155F9` |
| `sub_1563B` | 資金 `−=` | 同上 | `sub_135ED`、`sub_139E8`（撥款）、`sub_15358`、包裝 `sub_1562B` |
| `sub_1562B` | 資金 `−=` 的包裝（`dh` ＝ 勢力）| 同上 | **`sub_12600` 兩處** |
| `sub_15673` | 本月支出 `+=` | `+0x1A`／`+0x1C` | **`sub_13E65` 一處** ＋ 包裝 `0x15663` |
| `0x155F9` | 資金 `+=` 的包裝（`dh` ＝ 勢力）| — | **0 個** |
| `0x15663` | 本月支出 `+=` 的包裝（`dh` ＝ 勢力）| — | **0 個** |

⭐ **三個「用勢力編號記帳」的包裝裡只有扣款那一個被用到。**
遊戲從來不用編號給某個勢力加錢，也從來不用編號記支出——
`sub_135ED`（停戰／協力的轉帳）改用 `xchg si, di` 換記錄位移，
根本繞過包裝。

⭐ **「本月支出」只有一個寫入端：`sub_13E65` 的預備兵維持費。**
軍團的軍費走 `sub_1562B`，也就是**當場從資金扣**。

`0x15663` 是「本月支出 `+=`」的勢力編號包裝，**零個呼叫端**——
它與 `sub_1562B` 成對，但只有後者被用到。

## 2. 兩者的差別看得出來

月結會先把「本月支出」扣掉再歸零（[`../re/07`](../re/07-monthly-settlement.md) §1），
所以**一個月的總額兩種記法相同**。差的是月中：

| | 原版 | 記進本月支出的話 |
|---|---|---|
| 資金曲線 | 軍團一動就往下掉 | 月底才一次掉 |
| 侵攻的財政閘（每小時讀資金）| 出兵中的勢力**可能當月就被迫取消侵攻** | 撐到月底 |
| 「資金吃緊」位元 | 同上 | 同上 |

⚠ **`sub_13E11` 的兩道閘讀的是資金 `+0x21`，不是本月支出。**
記錯帳戶不會讓總額變，但會讓 AI 的判斷慢一個月。

## 3. 軍費本身（`sub_12600`，[`../re/09`](../re/09-combat.md) §9）

```
只有「一時」那個小時跑（cs:byte_10CF3 == 1）⇒ 一天一次
在野外（節點 ≥ 256）：資金 −= 兵力 × 3/4      士氣不回
在據點或路上：       資金 −= 兵力 ÷ 32 ＋ 1   士氣 +10，上限 ＝ 勢力基準
```

⭐ **不是啟動成本，是每天照收。** 說明書 10.6 只說「移動を始めると
即座に大きな経費」，從那句話推「啟動成本」是合理的，但機器碼是
**每天按兵力收 3/4**——野外一天的軍費是駐紮的 **24 倍**。

## 4. remake 實作

| 項目 | 作法 |

| 方式 | 內容 |

| 單元測試 | `TestCorpsUpkeepChargesFundsNotExpense`：一天之後資金掉、`Expense` 不動 |

### 5.1 長跑的數字變了很多，而且應該變

一個月的總額兩種記法相同，但長跑的結果差很遠：解體 137 → 388 次。
原因就是 §2 那張表——**每小時的財政閘現在看得到出兵的成本**，
所以撐不住的勢力當月就把軍團收回來，而不是拖到月底。

⚠ `cmd/wlsim` 的玩家不會下任何指令，所以「玩家第 39 個月被消滅」
是**工具的性質**，不是遊戲平衡的結論（`CLAUDE.md` §7 第 14 條同源）。

## 6. `sub_135ED` 是停戰／協力的收尾

四個呼叫端是事件 2／3／6／7 的 handler（`sub_13220`／`sub_13262`／
`sub_13327`／`sub_13388`）。它做兩件事：

```asm
000135F0  cmp al, 1 / jnz →           ; al=0 只釋放俘虜，不轉帳
000135F4  ax = dx / dl = 0
000135F8  call sub_15609              ; si 那一方 資金 +=
000135FB  xchg si, di / call sub_1563B ; di 那一方 資金 −=
00013602  … dx = (si 勢力, di 勢力)、ax ＝ 對調
0001361A  di = 4240h / cx = 7Fh        ; 127 名武將
0001361D  cmp dx, [di+1Ch] / jz →     ; ★ 武將 +0x1C（所屬）＋ +0x1D（俘虜於）
00013622  cmp ax, [di+1Ch] / jnz →       兩個 byte 當一個 word 比
00013627  call sub_150D7              ; 釋放
```

⭐ **兩國一講和，彼此扣押的俘虜全部放回去。** 那個 word 比較是
「屬於 B 而被 A 扣著」與反向兩種情形一次比完。

remake 的 `finishQueuedCeasefire`／`finishQueuedCooperation` 已經照這個做
（轉帳 ＋ `releaseDiplomaticCaptives`）。
