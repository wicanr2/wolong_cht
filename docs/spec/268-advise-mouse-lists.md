## 問題與證據

正常首頁開新遊戲，進言選遷都後，點第二列 `(150,128)` 仍是 `listCursor=0`、`listPhase=0`。
`updateAdvise` 在一般表格分派前就返回，三個進言選取階段只處理已停用的鍵盤與工具列確認。
此為已重現的 remake 缺陷，收據在 `workplace/shots/advise-mouse-20261103/before/`。

原版 `sub_18463` 依熱區算出第一下選取列，`0x184A8` 呼叫 `sub_121E7` 等第二次輸入。
右鍵走 `0x1847E` 清反白並返回列表；左鍵直接以原 `SI` 返回，不再依第二次點擊座標換列。
dosgolem 正常遷都流程已重現第二列反白、右鍵清反白、再次右鍵退出至地圖，以及同列再次左鍵進入判決。
`sub_16909` 的遷都入口與 [spec/49](49-advise-relocate-and-sortie.md) 使用同一份既有規則。
以上推論等級為已證實，範圍限 DOS/V。

進言對話的等待來自 `sub_12216`，右鍵契約及原始 patch 見 [re/111](../re/111-c-input-mouse-restoration.md)。
原版遷都首句之後右鍵會顯示軍師第二句。本規格只接回滑鼠推進，不調整自動等待時間。

## 實作契約

- 進言遷都、協助勢力、目標勢力表格都使用既有 `updateListUI`；排序、捲軸、第一下選取、第二下確認共用一份分派。
- 清單瀏覽中左鍵依熱區選列；反白中左鍵於任何遊戲區位置確認目前列。要改選先右鍵解除反白。
- 反白期間隱藏遊戲游標，右鍵解除反白後恢復；外部工具列仍依 spec266 隔離手勢。
- 遷都列表第二次右鍵關閉進言並返回地圖，不能因背景仍有清單而重新開指令。
- 勢力選取回呼沿用原有外交官與使者閘門；未通過保留原清單，協助方確認後的新目標表格從未反白狀態開始。
- 對話期間右鍵推進目前一句，不能同時取消背景表格或選中理由。工具列確認沿用既有入口。
- 不改君主採納、說服、遷都、外交、亂數與存檔規則；姓名文字輸入範圍不變。
