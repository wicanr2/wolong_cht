## 1. 已證實的原版運算

原版先讀資金的高 16 位，符號為負才做 NEG 與四次 SHL。
對合法資金範圍 -655000 至 -1，基礎扣兵為 `ceil((-Funds)/256) * 16`。
負數先丟掉低 byte 再取負值，與先取正的絕對值再丟低 byte 有不同捨位。

| 資金 | 原版基礎扣兵 | 修改前 Go |
|---:|---:|---:|
| -1 | 16 | 0 |
| -255 | 16 | 0 |
| -256 | 16 | 16 |
| -257 | 32 | 16 |
| -16000 | 1008 | 992 |
| -655000 | 40944 | 40928 |

原版 probe 的首個合法負資金差異為 -654849；原版弓兵剩 24547，Go 剩 24563，
兩側使用相同固定 RNG 表、c/s 初值與三次取數。C 的原始介面及記憶體結果仍與原版相同。
其餘表列結果由已定位原始指令直接導出，完整矩陣將驗高 16 位與不同低 byte。

## 2. 審查後的實作契約

修正 `economy.Settle` 的基礎扣兵為 `((-Funds+255)>>8)*16`，保留三兵種各自
取 `rng.Next() & 31`、三次取數與借位歸零。正式資金在既有上下限內，公式不外推非法資金。
這是已證實原版對齊，沒有更換玩法或引入新處罰。

## 3. 驗證閘門

冷測表列六個邊界、非負資金與固定非零 RNG。原版/C 枚舉全部高 16 位、低 byte
0／1／255，Go 在合法資金範圍對照預備兵與最終 RNG 狀態。
所有比較使用執行前固定的同一 RNG 初值，不挑選或重擲。
