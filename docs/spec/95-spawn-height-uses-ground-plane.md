# 95 — 開場擺兵的高度要用地面層表，不是堆疊高度

**狀態：CONFORMED。** `Place()` 本來用 `StandLevel`（圖塊堆疊高度），
而移動用的是 `GroundLevel`（地面層表）——那條 fixture 的 96 個兵
**每一個**的兩個值都不一樣，於是沒動過的兵停在移動層之上，
攻方走到守方腳下也碰不到他。改用 `standZ` 之後兩軍終於交手。

- 日期：2026-08-27
- 出處：[`../re/63`](../re/63-ground-plane-map.md) §2（`sub_1BCA6` 算地面層）、§5
  （`sub_1B1B1` 移動時讀的就是它）
- 推論等級：**強證據**（兩個表在 remake 內部互相矛盾；原版擺兵寫的是哪一個，
  沒有從機器碼讀出來）

## 1. 兩個表

| 名字 | remake | 內容 |
|---|---|---|
| 堆疊高度 | `Field.StandLevel` ＝ `top[y][x]` | 那一格疊了幾層圖塊（畫面高度）|
| 地面層 | `Field.GroundLevel(x, y, plane)` ＝ `lvl[plane][y][x]` | **移動用的那一層**（`sub_1BCA6`）|

`tryMove` 走一格時把 Z 同步成**地面層**；`doFormation` 算目標高度用的
`standZ` 也是先問地面層。只有 `Place()` 用堆疊高度。

## 2. 症狀

據點 82 的攻城 fixture（`SAVE-E.DAT`、軍團 81 攻 39 守）：

```
側1 兵 0 (3,32)  堆疊 1　地面層 0
側0 兵 0 (60,32) 堆疊 1　地面層 0
側0 兵 2 (60,34) 堆疊 2　地面層 0
96 個兵裡有 96 個的兩個值不一樣
```

**兵一動，Z 就被改成地面層**（`tryMove`）；沒動過的兵停在堆疊高度上。
於是：

| | Z |
|---|---:|
| 走進城裡的攻方 | 0 |
| 站在陣形線上沒動過的守方 | 1 |

`doAttack` 的碰撞條件是 `abs(dx)+abs(dy) <= 1 && s.Z == e.Z`，
`anyoneAt` 也比 Z——**兩邊在同一格卻差一層，永遠打不到對方**。
量到的後果是守方從頭到尾一兵未損
（[`../playtest/51`](../playtest/51-siege-deadlock.md) §3）。

⭐ **這是內部矛盾，不是「哪一個表才對」的問題。** 站著不動的兵與走過來的兵
落在同一格卻不同層，這個狀態在任何一種解讀下都不成立。

## 3. 演算法

```
Place()：
    Z = standZ(兵, x, y)      # 先問自己那一層的地面層，
                              # 沒有就問另一層，再沒有才退回堆疊高度
```

`standZ` 已經存在（`doFormation` 在用），直接共用——
**一條規則只留一份實作**（`CLAUDE.md` §7 第 6 條）。
