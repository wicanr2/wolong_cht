## 1. 為什麼要比狀態不比畫面

畫面相同只證明畫得一樣，**讀得一樣要另外證**——`corps` 那一輪就是這樣
把「兩邊開的不是同一場」從假說變成事實。而且三張表裡有一半的欄位
**畫面上根本看不到**（威脅量、求援冷卻、心向、原主、經費餘額）。

## 2. 段內偏移

```
0x0000  勢力表   22 筆 × 64 B
0x0840  據點表  192 筆 × 32 B
0x2240  軍團表  127 筆 × 64 B   ← 已比過
0x4240  武將表  127 筆 × 32 B
```

## 3. 兩邊怎麼取

| 側 | 作法 |
|---|---|
| 原版 | dosgolem 的 `factions`／`cities[:勢力]`／`generals[:勢力]` |
| remake | `wlgame` 的 `-list-factions`／`-list-cities`／`-list-generals` |

⚠ **名字欄位兩邊都印十六進位。** dosgolem 刻意零相依（`go.mod` 沒有
`require`），Big5 要 `golang.org/x/text`；而對拍腳本在 Python 那一端，
`cp950` 是現成的。**印 hex 讓輸出逐 byte 可比，也不必猜編碼。**

⚠ **補白是全形空格 `A1 40`，不是 ASCII 空白。** 用 `TrimSpace` 砍不掉，
名字後面會拖著看不見的兩個 byte，逐欄比就一路紅。

## 4.1 ⭐ 取樣點要對到「同一個遊戲時刻」

即時制之下**內政每小時都在動幾個據點**，所以兩邊差三個遊戲小時，
逐欄比就會出現一段連續據點的上昇值／防災值／城兵數不同——
**看起來像規則分歧，其實是取樣點**。

- 原版側：`click` 放開之後預設再跑六百萬道指令 ＝ 二十幾個節拍。
  用 `click:X,Y,N` 把 settle 縮短（實測 30 萬落在載入後、內政還沒動）。
- remake 側：`-shot-when clock:年/月/日[/時]` 把取樣點寫成遊戲時刻，
  狀態表跟著那一刻印，不是啟動時印。

⚠ **不要拿「跑幾天之後」的狀態來比。** 天災與內政帶亂數，兩邊各自擲骰，
差異的方向會兩邊互見——那不是規則分歧。動態欄位**只在同一個時刻可比**。

## 4. 兩邊語意不同的欄位

remake 在載入時就把幾個欄位換算過了，比對時要換回去：

| 欄位 | 原版存值 | remake |
|---|---|---|
| 據點 `+0x10` 上昇值 | 實際值 ＋ 100 | `Growth` ＝ 實際值 |
| 據點 `+0x13` 城兵數 | 人數 ÷ 10 | `Garrison` ＝ 存值（**沒有** ×10）|
| 武將 `+0x0E`–`+0x10` 適性 | 高半位元組 | `Aptitude` ＝ 已經 `>>4` |
| 勢力 `+0x20` 資金 | **有號 24 位元** | `Money` ＝ int |

⭐ 資金那一欄的坑：直接讀三個 byte 當無號，負債會變成一千六百萬。
