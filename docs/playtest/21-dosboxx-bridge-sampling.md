# 21 — DOSBox-X AI Bridge：第一次動態取樣

**狀態：三條斷言全部取到證據。`+0x00` 低 4 位 ＝ 敵方鄰居遮罩（192/192，
對照讀法只對 12/192）；`+0x18` 與 `+0x14` 在**場上有 21 支軍團、
12–13 個據點非零**的狀態下 0/192 不符。**

- 日期：2026-08-14
- 範圍：**只驗 PC-98 日文原版**。松崗 DOS/V 也跑得起來（密碼頁空白確認就會過，[`18`](18-dosv-password-verification.md)），
  這一輪選 PC-98 只是因為既有的 oracle 腳本都在那一版上
- 工具：`tools/dosboxx_bridge.sh`、`tools/dosboxx_probe.py`
- 上游：`DOSBox-X-MCP-Debugger`，submodule 釘在 `5fcf624b`（`pmanyeh/dosbox-x`）。
  **只用它的 Native AI Bridge，不用 MCP 那一層**——bridge 的協定是
  newline-delimited JSON，腳本直接講就好，不必為了取樣重啟 session

## 1. 這套東西是什麼

```
tools/dosboxx_probe.py ──TCP 127.0.0.1:9876──> debug_ai.cpp（DOSBox-X 內）
```

`debug_ai.cpp` 掛在 DOSBox-X 原生除錯器上，**不是第二顆模擬器**：斷點、單步、
暫存器與記憶體都走原生機制。MCP 那一層只是把工具呼叫轉成
newline-delimited JSON。

上游還有一層 MCP server 把這些包成 agent 工具，**本專案不用**：
取樣要的是可重跑的腳本，而 MCP 那一層得重啟 session 才載入。

## 2. 三個坑

| 症狀 | 實際原因 |
|---|---|
| 編譯到 `dos_programs.cpp` 掛掉 | 缺 `GL/glu.h`，補 `libglu1-mesa-dev` |
| build 明明成功卻被 Dockerfile 擋下 | **我自己的驗收條件是錯的**：`grep "Debugger" build.log` 那個字樣根本不在 log 裡。改成看 `config.h` 的 `C_DEBUG`／`C_HEAVY_DEBUG` |
| 每個 `memory.read` 都回 `DEBUGGER_NOT_STOPPED` | **除錯器的 UI 是 ncurses，開在控制終端上**，而 DOSBox-X 是看自己的 stdout 判斷有沒有終端。容器要 `-t`，而且 dosbox-x 的輸出**不能重導向**——接了 `\| tee` 或 `> log` 就不是 TTY 了 |

第三個最值得記：log 裡有一行
`Debugger is not available unless you start DOSBox-X from a terminal`，
但 bridge 本身照樣接受連線、`debug.status` 照樣回 `ok:true`。
**「連得上」不等於「用得了」**——健康檢查要問的是能不能讀到記憶體，
不是 port 開了沒。

## 3. 怎麼找到據點表：不猜 DS

據點表是從 `SINARIO.DAT` 的劇本區塊整段載進來的，所以拿本機解析出來的
記錄當簽章，在 guest 的 640 KB 裡搜：

```
據點表在 linear 0317D0（317D:0000），掃了 655,360 bytes
```

⚠ **簽章只能用執行期不會變的欄位。** 第一版拿檔案的原始 bytes 整段比對，
遊戲一跑起來就落空——上昇值、防災值、城兵、所屬、`+0x14`／`+0x18` 全都在變。
症狀是「明明表就在那裡，卻回沒找到」。改成比對連續 16 筆的 X／Y
（`+0x08`／`+0x0A`），等於 32 個 u16 同時對上。

這比「假設 DS ＝ 某個值」可靠，也**避開了跨版本外推**——
`CLAUDE.md` §7 第 9 條禁止拿 DOS/V 的程式碼位址推 PC-98，
但資料的版面是同一份原始碼編出來的，可以先靜態驗：

| 不變量 | 松崗 DOS/V | PC-98 |
|---|---|---|
| X 落在 4–370 | 192/192 | 192/192 |
| Y 落在 9–248 | 192/192 | 192/192 |
| 生產力 ≤ 上限 | 192/192 | 192/192 |
| 城兵 ≤ 上限 | 192/192 | 192/192 |
| 類型 0–4 | 192/192 | 192/192 |
| 所屬 ≤ 24 | 192/192 | 192/192 |

兩版的 `SINARIO.DAT` 大小同為 88,832、內容不同（城市名一個 Big5 一個
Shift-JIS），但**版面是同一套**。

## 4. 取樣結果

### 4.1 ⭐ 據點 `+0x00` 低 4 位：裁決了

[`../re/44`](../re/44-threat-and-reinforcement-ai.md) §5 把這四位從
「哪幾個方向有鄰接」改成「哪幾個鄰接槽屬於別的勢力」。
guest 記憶體裡的 192 筆全部符合新讀法：

```
+0x00 低 4 位與鄰居實況不符：0 / 192
+0x1B 與遮罩位元數不符：      0 / 192
```

**先做正對照**，否則「符合」可能只是兩個假說剛好給同一個答案：

| 假說 | 命中 |
|---|---|
| A「哪幾個槽屬於別的勢力」 | **192/192** |
| B「哪幾個槽有鄰居」 | 12/192 |

**兩個假說在 180 筆上給不同答案**，所以這是可分辨的檢定，不是同義反覆。

`+0x1B` 的分佈也有內容（不是常數）：0 有 77 筆、1 有 70、2 有 36、3 有 8、4 有 1。

### 4.2 ⭐ `+0x18` 與 `+0x14`：補上了真證據

第一次取樣停在 `NEW GAME` 對話框，兩欄全 0——**那時的「相符」不構成證據**，
它與「欄位語意完全是別的東西」相容。所以把遊戲開進本體（196 年 4 月 1 日，
曹操），讓它跑到場上有 21 支軍團，再取樣：

```
活著的軍團：21 支
+0x18 不符：0 / 192（非零的有 13 筆）
+0x14 不符：0 / 192（非零的有 12 筆）
```

**12–13 個據點是非零的**，所以這不是 0 對 0 的同義反覆。

### 4.3 四次不符，四次都是驗證器漏了原版的濾網

值得記的不是最後的 0，是中間那幾輪：**每一筆不符最後都指回一條靜態解出來、
而我沒寫進驗證器的規則**。

| 輪次 | `+0x14` 不符 | 原因 |
|---:|---:|---|
| 1 | 10 | 驗證器把「所有非我方鄰居」都算進威脅 |
| 2 | 4 | 補上「中立不算威脅」與「交友度 bit 7 ＝ 和平不算威脅」（`sub_13FA9` 的兩道濾網）|
| 3 | **0** | 再補上「中立據點根本不做威脅判斷」（`sub_13EFD` 的 `cmp [si+841h], 18h / jz` 直接跳過 `sub_13F74`）|

剩下的那四筆全部是 `owner = 24`（中立），一條規則就掃掉。

`+0x18` 那一欄的不符則是**掃描週期造成的**，不是模型錯：
連續取樣裡不符的據點會換人（0、8 → 無 → 183、188），
而某一次直接是 0/192。`docs/re/44` §1 說它「每 tick 從佔用圖抄一次、
192 tick 輪一圈」，所以剛有軍團進出、又還沒輪到的據點必然短暫落後。
第二輪最後一次取樣留下一筆 `據點 177：+0x14 ＝ 2，實際 1`，同一個道理。

> **這一節本身就是證據等級的說明**：「0 不符」之所以有意義，
> 是因為它是在**先把假不符一條條追出來源**之後才出現的，
> 不是一開始就對。

## 5. 怎麼重跑

```sh
tools/dosboxx_bridge.sh start      # headless DOSBox-X ＋ PC-98 原版，bridge 在 9876
tools/dosboxx_bridge.sh health     # 正對照：回 {"ok":true} 才算活著
# 除錯器要先停住，memory.read 才服務得到
printf '{"id":1,"method":"execution.pause"}\n' | nc 127.0.0.1 9876
python3 tools/dosboxx_probe.py locate
python3 tools/dosboxx_probe.py sample 317D0    # 只看據點表的三條不變量
python3 tools/dosboxx_probe.py verify 317D0    # 再拿軍團表對 +0x18／+0x14
tools/dosboxx_bridge.sh stop
```

`locate` 的位址**不要寫死**：每次開機的載入位置可能不同，重跑一次比較便宜。
