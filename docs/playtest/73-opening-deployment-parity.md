# 73 — 逐兵對拍：開場布陣 0/48 相同，而畫面看不出來

**狀態：抓到缺陷。** 同一場仗（[`72`](72-same-battle-parity.md)）的開場，
把兩邊場上 96 個兵的座標逐一比：**一個都沒對上**。

> **原版**：所有兵開場都擠在戰場最外側那一欄（側 0 `X=1`、側 1 `X=62`），
> `Y` 在 16–47 之間**分散而且會重複**（同一隊出現三個 `(1,25)`），
> 之後才散開——第 9 個節拍已經到 `X 1..5` ／ `58..62`。
> **remake**：開場就把每個兵放在**陣形位置**（`Place()`），
> 六隊各佔一欄（`X=3,5,…` ／ `60,58,…`），`Y` 對稱排列 `32,30,34,28,36,26,38,24`。

⚠ **`field` 那 0.10% 完全沒有涵蓋部隊。** 攻城戰的預設鏡頭對著城牆，
而開場兩軍都在戰場的兩端——**一個兵都不在畫面上**。
`72` 那七個 0 px 驗的是版面、地形與側欄，不是部隊。

## 1. 兩邊的開場（節拍 0）

| | 側 0（原版＝玩家／守方）| 側 1（原版＝對方／攻方）|
|---|---|---|
| 原版 | `X` 全部 **1**，`Y` 16–47 | `X` 全部 **62**，`Y` 17–47 |
| remake（對應側）| `X` 3／5／…（六隊各一欄），`Y` 24–38 對稱 | `X` 60／58／…，`Y` 同上 |

⚠ **側的編號兩邊不同**：原版**側 0 恆為玩家**（[`../re/11`](../re/11-tactical-battle.md) §3.6），
remake 的 `Sides[0]` 恆為**攻方**。這一場玩家是守方，所以要拿
原版側 0 對 remake 側 1。**不比對編號、比 `X` 的落點**才不會配錯。

原版側 0 第 0 隊的八個兵：`(1,28) (1,18) (1,40) (1,24) (1,17) (1,34) (1,44) (1,31)`
——**同一欄、Y 亂序**。第 1 隊有三個兵在同一格 `(1,25)`。
⇒ 原版是**先把人放到邊界那一欄**（可以重疊），再讓他們走進去。

remake 側 1 第 0 隊：`(3,32) (3,30) (3,34) (3,28) (3,36) (3,26) (3,38) (3,24)`
——**已經站在陣形位置上**（`Place()` → `formationSpot`）。

## 2. ⚠ 這同時修正了 [`70`](70-dosgolem-tactical-commands.md) §3 的兩個推論

那一輪拿 `field` 與 `sb-minimap` 的像素推了兩件事，**兩件都要改**：

| 當時寫的 | 實際 |
|---|---|
| 「`sb-minimap` 會隨時間變，不是穩定區」| 會變是因為**部隊在動**。它不是雜訊，是那一區**唯一看得到全部部隊**的訊號 |
| 「原版前 45 個節拍兩軍幾乎不動」| **不成立**。當時的判準是 `field` 只差 209 px，而那一場的鏡頭裡**本來就沒有兵**。實際上節拍 0 到 9 之間側 0 就從 `X=1` 散到 `X 1..5` |

⭐ **「畫面沒變」不等於「什麼都沒發生」**——要先確認那件事在畫面上看得到。
這一條與 `CLAUDE.md` §7 第 13 條（畫面 bug 測試看不到）是同一個形狀的反面。
