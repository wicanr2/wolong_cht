## 2. ⚠ 進到遊戲之後，畫面座標不等於滑鼠座標

`sub_11F7F`（IDA `0x11F7F`）→ `loc_11FD0`：

```
畫面座標 ＝ 滑鼠座標 − 捲動原點        （夾在 0..27Fh × 0..18Fh）
推到負的 → 原點跟著減、游標貼到 0、**地圖往那個方向捲**
```

原點在 `ds:9882`／`ds:9884`，算出來的畫面座標在 `ds:9886`／`ds:9888`。
**這是遊戲自己實作的「游標推到邊緣就捲地圖」**；選單畫面不走這一層
（`sub_121E7` 直接拿原始游標查熱區）。

⇒ **同一個座標在兩種畫面代表不同的東西，而兩邊都不會報錯。**
症狀是「送畫面座標，游標不會到那裡，地圖反而捲走了」——
而地圖本來就會捲，所以畫面看起來完全正常。

⭐ 這順帶解釋了既有擷取腳本裡那個看不懂的 `click:0,0`：
它是在**把捲動原點推回 0**，後面的座標才是畫面座標。

dosgolem 那一側對應的動作是 `sclick`／`stap`（先歸零再點）與 `origin`（讀值）。

## 3. ⭐ 熱區圖讀得出來：「點了沒反應」不必再一格一格試

`sub_1E453` 查的那張圖（80×50 格、每格 8×8 像素，[`../re/22`](../re/22-strategy-command-tree.md) §2）
的段與偏移在 `ds:E479`／`ds:E47B`，所以整張圖讀得出來：

```
LOAD DATA 畫面：
  #  4  x 432..463  y   0.. 31   ← 系統開關
  # 31  x  96..399  y  80..319   ← 視窗本體
  # 32  x 256..375  y 144..159   ← 存檔格 1
  # 33  x 256..375  y 192..207   ← 存檔格 2 …
```

第一次點存檔格點不中，是因為送的 x 是 **250** 而熱區從 **256** 才開始。

⭐ **`#4 x 432..463` 與 [`39`](39-system-window-parity.md) §1 記的
「系統開關的熱區是 x 432–463」一字不差**——兩個獨立來源對上。

## 4. 那 435 點是時序漂移

兩件事支持：

| 實驗 | 結果 |
|---|---|
| 同一個局面多跑 **400 萬道指令**再截一張 | 五區 **0 px**。系統選單開著時畫面完全凍結，我們這一側不是「還沒畫完」|
| 把到達路徑多跑 **60 萬道指令**（約三個遊戲小時）| 同一個取樣點差 **5,013 點** |

435 點對應的時間差比 60 萬道指令小一個量級，而且差異全部落在右下角
（隨時間變的地圖物件）。**這是「兩邊停在不同時刻」，不是繪圖錯。**

## 5. 順帶：半形字模路徑通了

SAVE DATA 視窗會用到半形字模：**全形 304 次、半形 44 次，讀不到字模 0 次**。
開機那幾格用不到，是因為數字走遊戲自己的 8×16 點陣字
（[`../re/28`](../re/28-text-number-rendering.md) §2）。
