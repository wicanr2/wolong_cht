# 03 — 補驗紀錄：哪些結論撐得住，哪些撐不住

**狀態：持續累加。專記驗證與失敗的驗證嘗試。**

**這份專門記「驗證」而不是「發現」。** 包含失敗的驗證嘗試。

- 日期：2026-08-07
- 起因：兩輪內連續推翻自己的兩條結論（`docs/formats/05` 的 autotiling 誤讀、
  地形類型 5 的誤判），其中一條已經被寫進 Go 程式碼的註解當設計約束。
  **產出速度超過驗證速度**，先停下來還債。

## 1. ✅ 成功：地形類型的空間關係檢查

方法：把整張 384×256 地圖依**地形類型**（不是圖塊）上色，做四鄰接統計。
背景值——任一格鄰接水域的比例是 **22%**。

| 檢查 | 結果 | 判定 |
|---|---|---|
| 類型 1 鄰接水 | **159/159 ＝ 100%** | 升 confirmed |
| 類型 2 鄰接水 | **53/53 ＝ 100%** | 升 confirmed |
| 類型 8 鄰接水 | 624/634 ＝ 98.4% | 升 confirmed |
| 類型 5 鄰接水 | 623/1809 ＝ **34.4%** | **推翻「河岸」判讀** |

**為什麼這個方法有效**：空間關係不是判讀時能安排的。
我當初看圖塊縮圖猜名字，猜不出「橋一定跨水且零例外」這種結構。

## 2. ❌ 失敗：想用縮小地圖當獨立對照

**假設**：`ICONGRF` 段 2 的縮小地圖是 192×128，正好是世界地圖 384×256
的一半，所以它應該是世界地圖的 2:1 降採樣，可以拿來交叉驗證地形分類。

**做法**：把世界地圖每 2×2 格取多數地形類型，對上縮小地圖同位置的
調色盤索引，看兩者的對應關係有多乾淨。

**結果——不成立**：

```
我判定的地形類型 → 縮小地圖用哪些索引畫
  平原  11119 格 → idx9:33% idx13:14% idx0:11% idx2:10%
  山地   6948 格 → idx9:30% idx13:20% idx12:18% idx2:9%
  林地A   483 格 → idx9:35% idx13:20% idx2:12% idx12:12%
  水域   5775 格 → idx0:24% idx9:17% idx8:16% idx4:12%
```

平原、山地、林地**用的是同一組索引、比例也差不多**——沒有分辨力。
只有水域略有特徵（`idx0` 24%、`idx8` 16%），而 `idx8` 反過來看有 96.6%
落在水域，代表對齊沒錯，但覆蓋率太低。

**結論：縮小地圖不是世界地圖的降採樣，是另外畫的一張圖。**
整體輪廓像，是因為畫的是同一塊土地；**逐格對應不成立**。

### ⚠ 連帶訂正一句話

`docs/formats/06` §4 原本寫縮小地圖「是獨立的第二個對照」。
那句話**說過頭了**：它驗證的是**大輪廓**（河網走向、海岸位置），
不是逐格的地形分類。已改。

## 3. 目前撐不住的結論（誠實清單）

下面這些還停在**強證據**，本輪沒能升級：

| 結論 | 為什麼升不上去 |
|---|---|
| 類型 3 ＝ 山地 | 只有圖塊外觀 ＋ 分佈在西部。沒有結構性檢查能區分「山地」與「丘陵／荒地」 |
| 類型 4、5 ＝ 林地 | 同上。兩者為何分成兩類也不知道 |
| 類型 0 ＝ 平原 | 同上。它是 fall-through 的預設值，本來就包山包海 |
| 類型 7（`0xA8`）| 400 格，71% 貼水，圖塊是純藍網點。**用途仍未明** |
| 768 筆表 ＝ 行軍路網 | `sub_1E717` 建出來的東西被誰用還沒查 |

**要升級這幾條，需要的是原版實機證據**：進到戰鬥看野戰地形長什麼樣，
或在說明書裡找到地形說明。兩件都還沒做。

## 4. 這一輪學到的方法論

1. **結構性檢查 > 外觀判讀。** 「橋 100% 鄰水」這種零例外的統計，
   比「看起來像橋」硬一個等級，而且是免費的——資料已經在手上。
2. **要設背景值。** 34% 看起來不低，但背景值是 22%，所以它幾乎沒有訊息量。
   沒有背景值的百分比不能下判斷。
3. **縮圖不足以判讀圖塊。** 類型 5 的誤判就是在 16×16 縮圖上做的。要放大。
4. **失敗的驗證也要記。** 「縮小地圖不能當對照」這件事，
   不寫下來的話下一輪還會再試一次。
