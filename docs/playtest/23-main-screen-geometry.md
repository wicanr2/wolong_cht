# 23 — 主畫面幾何：從機器碼定死，第一次逐區對拍

**狀態：版面常數全部換成機器碼算出來的值（外框四項 ＋ 右欄內部一整組）。
橫幅的位移掃描落在 (0,0)，幾何對齊。**
⭐ **這一份當時缺的原版素材後來拿到了**：松崗 DOS/V 的主畫面點得動、
五區逐像素相同（[`37`](37-main-screen-parity.md)），三窗開著與系統選單開著
也各做了一次（[`38`](38-window-parity.md)／[`39`](39-system-window-parity.md)）。
本檔保留當時用 PC-98 對幾何的過程。

- 日期：2026-08-15
- 原版側：PC-98 日文原版實跑（`tools/dosboxx.sh`，`noopen` 模式），
  196 年 4 月 1 日 曹操，`workplace/dosbox/shots/q5-main-t20.png`
- remake 側：`tools/wlgame_live_capture.sh`，seed 17、speed 0、劇本 0、勢力 0
- 工具：`tools/parity_diff.py`（逐區）、`tools/parity_offset.py`（位移掃描，新增）

## 1. 原版主畫面預設長什麼樣

實跑第一次看到的畫面推翻了一個一直沒被質疑的假設：
**原版預設不顯示命令列與右欄**。

```
196年 4月 1日、曹操
┌──────────────────────────────────────────┐
│ 橫幅 640×32：臥竜伝 ＋ 龍 ＋ 五格開關 ＋ 日期        │
├──────────────────────────────────────────┤
│                                          │
│              大地圖 640×368                │
│                                          │
│ ┌─────────────┐                          │
│ │ 據點情報：許昌 │  ← 選中首都時出現         │
│ └─────────────┘                          │
└──────────────────────────────────────────┘
```

命令／自勢力情報／縮小地圖／系統是**四個可以逐個開關的視窗**
（說明書 3.1、[`../re/47`](../re/47-main-screen-window-registry.md)），
開新遊戲時四個都是關的。說明書那張主畫面圖與參考影片都是玩家開過之後的狀態。
開關的實作與驗收見 [`24`](24-window-toggles.md)。

## 2. 四項常數換掉了

| 項目 | 舊值（影片估）| 新值（機器碼）| 出處 |
|---|---:|---:|---|
| 命令列第一個詞的 X | 64 | **32** | `sub_106F5(dx=8)` ＋ 開頭空白 24 |
| 縮小地圖視窗高 | 152 | **160** | `sub_1895D(cx=0x0A0D)` |
| 自勢力情報視窗 Y／高 | 176／224 | **192／208** | `sub_1895D(cx=0x0D0D)` |
| 系統視窗 Y／高 | 114／194 | **112／192** | `sub_1895D(bx=5, cx=0x0C0D)` |

命令列的命中判定也一併改成原版的 `索引 ＝ (x − 24) ÷ 48`：
八格之間**沒有間隙**，先前每格右緣留的 2 px 死區是自己加的。

### 2.1 右欄內部也全部換掉了

自勢力情報視窗的內容分兩層：**靜態那一層是一份顯示清單**
（`sub_10337(al=0)` 的場景 0，[`../re/48`](../re/48-window-display-list.md)），
動態欄位由四支常式畫。兩份資料互相獨立，而座標逐列對得上：

| 元件 | 座標 | 來源 |
|---|---|---|
| 標籤「君主／首都／軍師」| (512, 208/224/240) | 顯示清單 op 08 |
| 對應的名字 | (576, 208/224/240) | `sub_15EB7` |
| 標籤「信賴度」／量條的槽 | (448, 272)／(448, 288) 176×10 | op 08／op 03 |
| 量條 | (456, 292)，長度 `(信賴度×100 + 0x9F) ÷ 0xA0` | `sub_15F27` |
| 資金／預備兵的黑底 | (448, 304) 176×80 | op 03 |
| 標籤「資金」「預備兵」| (456, 312/328) | op 08 |
| 四張 24×16 圖形 | (528, 312/328/344/360) | op 09 |
| 資金 7 位／預備兵 6 位 | (560,312)／(568, 328/344/360)，右端都在 616 | `sub_15F5D`／`sub_15F7F` |

視窗內部的水平邊在原版幀與 remake 上也對得起來：文字列在 210／226／242，
量條在 292–296。

三條算術檢查同時成立，所以這組值不是各自湊出來的：

- 右欄三段 `32 + 160 + 208 = 400`，鋪滿畫面高度
- 命令列字串尾端 `8 + 24 + 8×32 + 7×16 + 24 = 424 < 432`（框寬）
- 熱區 `(24, 40, 384, 16)` 的左右界與 `sub_161CA` 的 `x < 24`／`x ≥ 408` 一致

## 3. 對拍結果

只有 `banner` 是這一輪可比的區——原版側四個視窗都關著，
其餘四區在原版那邊是地圖像素，比出來的數字沒有意義。

| 區 | 不同像素 | 佔比 | 判定 | 說明 |
|---|---:|---:|---|---|
| `banner` | 10161 / 20480 | 49.61% | FAIL | 見下 |
| `command` | 13619 / 13824 | 98.52% | — | 原版側是地圖 |
| `map` | 140127 / 145152 | 96.54% | — | 相機位置不同 |
| `minimap` | 33145 / 33280 | 99.59% | — | 原版側是地圖 |
| `faction` | 42188 / 43264 | 97.51% | — | 原版側是地圖 |

### 3.1 ⭐ 橫幅：幾何對齊，差的是顏色

`tools/parity_offset.py` 把 −4…+4 的整體位移全掃一遍：

```
最小不同比例 49.61% 落在 dx=+0 dy=+0
鄰格（±1）都在 64–72%
```

**(0,0) 是一個明顯的谷**，所以橫幅的位置與大小是對的。
剩下的 49.6% 不是版面問題：原版側是 **PC-98 類比 RGB**，
remake 對的是松崗 DOS/V 的調色盤，兩者本來就不同色；
龍那一段又是大面積 dither，一個色階差就整片不同。

> 這正是位移掃描要解決的事：**逐區差分只回答「差多少」，
> 不回答「是不是整片平移」**，而這兩件事的處置一個是改常數、
> 一個是換素材。

三條橫幅並排（原版／remake／差分）：
[`parity/main-banner-pc98-vs-remake.png`](parity/main-banner-pc98-vs-remake.png)。
兩張完整畫面：[`parity/main-pc98-windows-closed.png`](parity/main-pc98-windows-closed.png)、
[`parity/main-remake.png`](parity/main-remake.png)。

> ⭐ **三件當時卡住的事都通了**：主畫面收得到點擊（送 `click:x,y;press`
> 成對，[`38`](38-window-parity.md) §1）、松崗 DOS/V 側的主畫面拍得到、
> 同版本同調色盤的對拍做完了（五區全 PASS，[`37`](37-main-screen-parity.md)）。
> 當時 `banner` 那 49.6% 的成因是**調色盤刻度差 4%**，不是版面
> （[`../spec/51`](../spec/51-vga-dac-palette-scale.md)）。
> §4.1 的鑑別測試留當時的推理過程。

## 4. 缺什麼

| 缺口 | 現況 |
|---|---|
| 四張 24×16 圖形的內容 | 顯示清單指到圖庫位移 `0x1200`／`0x12C0`／`0x1380`／`0x1440`，還沒畫出來看；remake 先用同位置同尺寸的色塊佔位 |
| 其他 10 個顯示清單場景 | 同一支直譯器有 11 個呼叫端，只讀了場景 0（[`../re/48`](../re/48-window-display-list.md) §5）|

### 4.1 當時的鑑別測試（結論後來被推翻）

> ⭐ **主畫面收得到點擊。** 送法是 `click:x,y;press` **成對**送，
> 而且進到大地圖之後 INT 33 的範圍變成整個世界
> （一個主機像素 ≈ 9.6 個遊戲像素，[`38`](38-window-parity.md) §1、
> [`37`](37-main-screen-parity.md)）。下面留的是當時怎麼推到
> 「收不到按鍵」的過程——**單點的按下事件沒有配對的放開，原版收不到**。

原本的假設是「PC-98 的開關座標與 DOS/V 不同」。改點畫面右下那座
敵方據點 (600,290)——那不經過橫幅熱區——**據點情報視窗仍然停在許昌**。
所以主畫面上任何位置的左鍵都沒有效果，與開關座標無關。

範圍很窄：同一輪裡選劇本、選君主、按「決定」全部有效，而且時間有在走
（日期 4 月 1 日 → 4 月 3 日）。選單與主畫面讀按鍵的常式是兩支
（`sub_121E7` 與 `sub_11F7F`），差異出在後者拿不到按鍵遮罩
（[`../re/47`](../re/47-main-screen-window-registry.md) §6）。

> **主畫面上原版會把游標藏起來**，閉迴路 `clickat` 因此回
> 「畫面上找不到游標」並停在原地。前幾輪有幾次點擊其實落在別處，
> 而截圖上與「點到了但沒反應」完全一樣——這一節的結論是在
> 確認 `gotoxy` 印出到站座標之後才下的。
