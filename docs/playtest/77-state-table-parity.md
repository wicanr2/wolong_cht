# 77 — 勢力表／據點表／武將表逐欄對拍：5,502 個欄位全部相同

**狀態：通過。** 同一份存檔載入後的同一個遊戲時刻（196年4月16日 10時），
原版**執行期記憶體**裡的三張表與 remake 的狀態逐欄比，
**5,502 個欄位一個都不差**。

- 日期：2026-09-06
- 規格：[`../spec/138`](../spec/138-state-table-parity.md)
- 存檔：`workplace/dosgolem/root-saveb/SAVE.DAT`（劇本 1，曹操）
- 原版側：`click:300,151,300000` → `clock;factions;cities;generals`
- remake 側：`-list-factions -list-cities -list-generals`
- 比對：`tools/py.sh tools/state_diff.py 原版.log remake.log`

## 1. 比了什麼

| 表 | 列 × 欄 | 欄位 |
|---|---|---:|
| 勢力 | 22 × 13 | 286 |
| 據點 | 192 × 17 | 3,264 |
| 武將 | 122 × 16 | 1,952 |
| | | **5,502** |

⭐ 有一半的欄位**畫面上根本看不到**：周邊威脅量、求援冷卻、心向的勢力、
原主勢力、經費餘額、好戰等級、戰場腳本編號。畫面相同只證明畫得一樣。

⭐ 兩個**衍生值**也對上了，那是比欄位更強的證據：

- **評價**（武將 `+0x1F`）：檔案裡是 0，載入時由 `sub_155A6` 算出來。
  兩邊各自算，122 個人**全部相同**。
- **旗標 byte**（`+0x00`）：remake 把它拆成四個 bool（在場／主公型／
  心向已滅退場／不事二主），這裡再組回去比——組得回來表示拆對了。

## 2. ⭐ 取樣點差三個遊戲小時，就會看起來像規則分歧

第一次比得到 **272 個不同欄位**，全部集中在**編號 118–141 這一段連續據點**
的上昇值、防災值與城兵數。成因不是規則：

> `click` 動作放開之後預設再跑 **六百萬道指令**，對即時制來說是
> **二十幾個遊戲節拍**——內政的巡迴游標已經掃過二十幾個據點了。

改成 `click:300,151,300000`（settle 30 萬）之後兩邊都停在 **4月16日 10時**，
差異歸零。

⚠ **不要拿「跑幾天之後」的狀態來比。** 推到 4月18日再比得到 582 個不同欄位，
而且**差的方向兩邊互見**（有的原版大、有的 remake 大）——那是
天災與內政帶亂數，兩邊各自擲骰，不是規則分歧。
**動態欄位只在同一個時刻可比；跨時刻要比的是規則，不是數值。**

## 3. 為此加的四樣東西

| 東西 | 做什麼 |
|---|---|
| dosgolem `factions`／`cities[:勢力]`／`generals[:勢力]` | 讀原版執行期的三張表 |
| dosgolem `click:X,Y,N` | 第三個參數是**放開之後再跑多久**，預設六百萬太長 |
| `wlgame -list-factions`／`-list-cities`／`-list-generals` | remake 側 |
| `wlgame -shot-when clock:年/月/日[/時]` | 取樣點寫成遊戲時刻 |
| `tools/state_diff.py` | 逐欄比，附 `--selftest` 正對照 |

⭐ 名字欄位**兩邊都印十六進位**：dosgolem 刻意零相依（`go.mod` 沒有
`require`），解不了 Big5；印 hex 讓輸出逐 byte 可比，`cp950` 由對拍腳本
那一端解回來顯示。

## 4. 自我測試抓到的第一個 bug

`state_diff.py` 的第一版把 log 的時間戳寫成「砍掉前兩個 token」，
於是**沒有時間戳的那一邊**被砍掉「勢力  0」，一列都解不出來——
而比對照樣回「零差異」。`--selftest` 的第一項（同一份輸入必須解出三列）
當場擋下來。**「永遠回零差異」的壞工具會讓所有對拍看起來全過**，
所以正對照要驗的不只是「相同回相同」，還有「解析真的解到東西」。
