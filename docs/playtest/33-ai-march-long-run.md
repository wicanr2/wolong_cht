# 33 — AI 行軍鏈接上之後的長跑觀察

**狀態：量完了。世界會動了——43 個月裡勢力從 22 個減到 15 個，
軍團有生有滅（3.5 年 18 次解體），不變量全程成立。
⚠ 三件事被這一跑照出來：`wlsim` 遇到「等玩家決定」會空轉、
玩家勢力的預備兵會被抽乾、閒置的玩家會在半年內被吃掉。**

- 日期：2026-08-17
- 工具：`tools/go.sh run ./cmd/wlsim`
- 對照：同一顆種子在 [`../re/65`](../re/65-ai-march-decision-chain.md) 接上之前後各跑一次

## 1. 接上之前與之後

| | 接上前 | 接上後 |
|---|---|---|
| AI 軍團 | 走到第一個目標之後**不再動** | 領待辦、出擊、補兵、解體，一直循環 |
| 12 個月的據點易主 | 0 | 28（前 4 個月）|
| 勢力數（3.5 年）| 22 | **15** |
| 玩家（劇本 1、勢力 0、完全不操作）| 12 個月後仍有 11 個據點 | **4 個月後歸零** |

⭐ **「玩家不動就被吃掉」是正確的**，先前的安穩是 AI 停在原地換來的。

## 2. 三個被照出來的問題

### 2.1 `wlsim` 遇到「等玩家決定」會空轉

`World.tick` 對戰術戰鬥、遭遇選單、外交提案、撥款請求四種狀態
**直接回傳**，`ev.Settled` 永遠是 false，而 `wlsim` 的迴圈條件是
「跑滿 N 個月」——**月數加不上去就永遠不會結束**，
表現是 100% CPU、零輸出。

處置：`wlsim` 現在遇到遭遇一律**委任**、外交與撥款一律**拒絕**，
其餘等待印一行說明就停。**這是這支程式的政策，不是原版規則**——
長期經濟量測要的是「玩家不介入時世界怎麼走」，
而拒絕是唯一不花錢、不改變勢力關係的答案。

> 空轉之所以難查，是因為它**看起來像在算**。
> 「跑很久」與「永遠不會結束」在外面長得一樣，
> 分辨的方法是先問「終止條件靠什麼遞增」，不是加大 timeout 再等一次。

### 2.2 結局定案之後 Tick 不再有副作用

`outcome != InProgress` 時 `tick` 直接回傳（對應原版 `sub_11CB1`
之後離開主循環）。任何「跑滿 N 個月」的迴圈都要自己看結局，
否則就落進 2.1 的空轉。

### 2.3 不操作的玩家勢力，預備兵會歸零——這是規則不是缺陷

劇本 1、勢力 11、完全不操作：

| 年月 | 預備兵（騎／弓／步）| 資金 |
|---|---|---:|
| 197/4 | 800 / 3,200 / 4,800 | 50,727 |
| 198/4 | 0 / 203 / 1,779 | **−16,471** |
| 199/4 | 0 / 0 / 0 | 17,746 |

三條已解的規則接起來就是這個結果：

1. **預備兵要養**：每次輪到該勢力（每 22「時」一次，約一天）
   累計支出加「三種預備兵總和 ÷ 32」（[`../re/08`](../re/08-hourly-update.md) §2）。
   8,800 個預備兵 ≈ 每月 9,000，而 15 個據點在 18% 稅率下的月收入約 6,500。
2. **赤字要罰**：資金為負時月結扣預備兵，每種扣
   `|資金|÷16 ＋ 亂數(0–31)`（[`../re/07`](../re/07-monthly-settlement.md)）。
3. **募兵上限開局是 0**：四個劇本的 `+0x1A`／`+0x22` 全部是 `0, 0, 0`，
   所以**玩家不去設定就一個兵都不募**。

⭐ 池子歸零之後維持費也歸零，資金隨即回正（199/4 的 +17,746）。
**這是一個自我修正的迴路**，不是漏洞——它在提醒玩家「養兵要花錢，
而募兵數要自己設」。

## 3. 不變量

`-check`（每個 tick 掃一遍）在整段跑完之前沒有任何違反。
會動到的三個計數器——勢力的據點數、武將數、軍團數——
都與實際數出來的一致。

## 4. 怎麼重跑

```sh
tools/go.sh run ./cmd/wlsim -years 5 -every 12 -player 11
tools/go.sh run ./cmd/wlsim -years 1 -every 3 -check     # 慢很多，但會逐 tick 驗
```

種子固定（`-seed`，預設 1），同一組參數逐字重現。
