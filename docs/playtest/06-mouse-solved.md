# 06 — PC-98 oracle 的滑鼠通了

**狀態：可以自動操作遊戲。** `docs/playtest/04` 記了六次失敗、
結論是「滑鼠事件從來沒有進入 guest」。那個結論不成立——
事件進得去，卡住的是**另外三件互相遮蔽的事**。

- 日期：2026-08-08
- 工具：`tools/dosboxx.sh`（新增 `until` / `goto` / `clickat` / `xkey` / `probe`）

## 0. 三個原因疊在一起，所以每一次單獨修都沒有效果

| # | 原因 | 為什麼會看起來像「滑鼠壞了」 |
|---|---|---|
| 1 | **一半的實驗跑在開場動畫裡** | 開場長度每次不同（實測 104 s、>114 s、126 s），`wait:110` 有時到選單有時沒到。沒到的那幾次畫面上根本沒有游標，怎麼送都沒反應 |
| 2 | **餵的是絕對定位，遊戲讀的是相對位移** | PC-98 用**匯流排滑鼠**（`YNSHELL.COM` 會載 `YNMOUSE.COM`），本質是相對裝置。`autolock=false` ＋ `mouse_emulation=never` 走的是 INT 33h 的絕對路徑，**跟遊戲讀的不是同一條** |
| 3 | **大跳躍會被截掉** | 匯流排滑鼠每次回報的位移是帶號 8 bit。送 600 px 實際只走 1 px，看起來就像「游標不動」 |

任何一個沒解，畫面都是「游標紋風不動」。**症狀相同讓三個原因互相偽裝成同一個**，
而 `docs/playtest/04` 的六次嘗試全部在調第 2 項的參數。

## 1. 先把觀測做出來，再談原因

`[log] mouse = true` ＋ 每一步印指標位置，一輪就把範圍縮死：

| 觀測 | 值 |
|---|---|
| 視窗位置／大小 | `(320,312)` `640x400` |
| **鍵盤焦點視窗** | `2097161` ＝ **就是 DOSBox-X 視窗** |
| `move:100,100` 後指標 | root `(420,412)`，底下的視窗 = DOSBox-X |
| `move:520,340` 後指標 | root `(840,652)`，底下的視窗 = DOSBox-X |
| DOSBox-X 的 mouse log | **只有** `MOUSE:INT 33H emulation enabled` |

指標走到了正確的絕對位置、壓在視窗上、視窗握有焦點——然後滑鼠子系統一個事件都沒記。
**唯一一行 log 說的是 INT 33h**，而遊戲讀的是匯流排滑鼠。第 2 項就是從這裡看出來的。

## 2. 到站訊號：認畫面，不要數秒

固定 `wait:` 靠不住（原因 1）。試過的兩種替代：

| 做法 | 結果 |
|---|---|
| `settle`：連續三張截圖相同就算到站 | **被騙**。開場每張插圖會定格好幾秒，96 s 就誤判到站 |
| `until:<md5>`：等畫面的 md5 等於指定值 | **可靠**。選單畫面跨執行 pixel 相同，md5 是固定的 |

```
until:98ed3eed36bfac231dbe0762b0164698,260   # NEW GAME 對話框
until:b5c8f6ede8e2889935697f0b6d388ba0,40    # 劇本選單
```

實測穩定在 126 s 到站。

> 「等它安靜下來」是很自然的寫法，但**安靜相容於太多世界**：
> 到站了、當掉了、動畫定格了。認畫面把三者分開。

## 3. 鎖住滑鼠：用鍵盤繞過滑鼠

`Ctrl+F10` 是 DOSBox-X 的擷取滑鼠快捷鍵，而**鍵盤路徑一直是通的**。
鎖住之後 SDL 進入相對模式（指標每次被拉回視窗中心 `(640,512)`，
`probe` 看得到），DOSBox-X 才會把相對位移餵給匯流排滑鼠。

送鍵改走 XTEST（`xkey`，不帶 `--window`）而不是 XSendEvent 合成事件——
視窗確實握有鍵盤焦點（§1），所以 XTEST 送得進去，而 DOSBox-X 自己的
mapper 對合成事件不一定買帳。

## 4. 閉迴路移游標

第 3 項的截斷讓開迴路不可能準。實測對得上模型：

```
clip(-2000) + clip(600) = -128 + 127 = -1     實測位移 (-1, -1) ✔
```

所以 `goto:x,y` 改成看著截圖逼近，一次最多送 60 px：

```
截圖 → 找游標 → 算差 → 送 min(|差|, 60) 的相對位移 → 重來，最多 16 步
```

實測 6 步就從預設位置走到 `YES`，誤差 ≤ 2 px。

### 游標偵測：純紅只有游標在用

`#FF0000` 在整張 640×400 畫面**剛好出現 56 次，全部在游標框內**。
所以認色就夠，不必做樣板比對：

```sh
convert cur.png -fill black +opaque '#FF0000' -format '%@' info:-
# → 12x12+349+215
```

`+opaque` 把非純紅的像素全塗黑，`%@` 直接給邊界框。
比掃 `txt:` 快 20 倍（38 ms vs 768 ms）——16 步的閉迴路差半分鐘。

## 5. ⚠ 一個與 DOSBox 無關的坑：註解裡的反引號

腳本把 DOSBox 那一段包在 `bash -c "…"` 裡。**雙引號內的反引號是命令替換**，
所以這行註解會被宿主真的執行：

```sh
# 用 `xdotool mousemove --window` 送相對座標它收不到
```

症狀是輸出開頭莫名其妙冒出 `mousemove: option '--window' requires an argument`，
而且它**不屬於任何一步**，怎麼比對時間軸都對不起來。

抓到它的方法是把所有 `xdotool` 包進一個會印出完整命令列的函式，
再看剩下那條沒有署名的——`tools/dosboxx.sh: 列 62` 一出現就破案了：
報錯的是**宿主的行號**，不是容器裡的。

> 教訓：**分不出「誰發的」的錯誤訊息，值得先花一步讓它自報身分**，
> 比對著它猜三輪便宜。
