## 2. 四個缺陷

**一、任命的候選清單沒排除君主。** 原版三條流程（內政官任命、外交官任命、
編成選武將）**呼叫同一支 `sub_17663`**，四個條件一次講完：存在 ∧ 玩家勢力 ∧
職務 0 ∧ 不是君主。remake 寫成兩份，編成那份有君主那一關、人事那份沒有，
於是候選第一列是曹操，而原版是夏侯淵。收成 `candidateGenerals()`
（[`148`](../spec/148-shared-candidate-filter.md)）。

⭐ 同一支讀完還解掉兩個「看起來缺的過濾」：原版沒有「俘虜」也沒有「軍師」
那一關——俘虜被職務 4 擋掉、軍師整筆不在武將表裡。**兩個都由別的機制吃掉。**

**二、上一輪的 `KeepSelected()` 蓋到了下一張清單。** 人事任命的 callback
會**換上另一張清單**（選完據點換成武將一覽），而反白被帶了過去，
於是新清單第一下點擊就直接決定——**兩段式少了一段**。
修法是先記住 `Confirm()` 之前是哪一張，指標沒變才擺回去。

⚠ 這個 bug 是[`90`](90-formation-second-step.md) 那一輪修反白列時進來的，
**單元測試全綠、編成那一張也還是 78 px**。抓到它的是「fixture 走了三層列號
卻停在第一層」這個對不上的畫面。

**三、台詞還掛著就已經回到下一步。** 原版 `sub_18810` 是**擋住的**：
訊息在畫面上時流程停在原地，所以那一刻是**武將一覽 ＋ 狀態列 #9**。
remake 的訊息是佇列式的，照抄呼叫順序就變成「訊息還掛著、底下已經是
據點一覽 ＋ #11」。加了 `afterTalk(fn)` 把續行掛在那一則上。

**四、清單選完之後跟著狀態變了。** 原版的清單只在開啟與捲動時畫，
選完留在畫面上的是**殘影**：`+0x17` 已經寫成 2，那一列的身分欄還是「－－－」。
remake 逐幀重繪，所以要在**動手之前**快照（凍在 callback 之後就晚了一步，
303 → 95 px 就是這個差別）。

## 3. ⭐ 一般訊息框的名字換色補上了

內政官解任那一張（TALK #54「是否有所差錯？`\2` 並未派遣任何人。」）
量到原版把「濮陽」畫成 `(243,162,0)`＝色 `0x0B`，remake 是白的——150 px。

成因：換色與定寬先前只做在左下角的狀態列。**但那是標記的性質不是框的性質**
——五支 handler 都在 `sub_1075B` 底下，而 `sub_1075B` 同時被 `sub_18853`
（狀態列）與 `sub_18810`（一般訊息框）呼叫。兩個框收成同一支之後，
`map` 從 321 掉到 171（[`../spec/119`](../spec/119-talk-marker-fields.md) §3.1）。
