## 2. 抓到的分歧：解任不先過濾

原版「內政官解任」開的清單是**全部十座城**，即使一個內政官都沒派
（`內政官` 那一欄整排破折號）。remake 先前先過濾候選，沒有人派駐時
**連清單都不開**，只在事件列丟一句「沒有派駐中的內政官」。

機器碼（`sub_16B08` ＋ `sub_16B4F`，[`142`](../spec/142-personnel-dismiss-flow.md)）：

```asm
loc_16B11:  cx = 0Dh / sub_18853        ; 狀態列 #13
            sub_17400                   ; 選據點——★ 不過濾
            si = bx / sub_16B4F         ; bh = 0FFh / xchg bh,[si+19h]
            CF=1 → cx = 36h / sub_18810 ; #54「是否有所差錯？{2}並未派遣任何人。」
            jmp loc_16B11               ; ★ 回去再選
```

⭐ **先寫再檢查**：`xchg` 無條件寫 `0FFh`，才看舊值是不是 `0FFh`。
選到沒人的那一格等於寫了一次同樣的值，沒有副作用——照抄。

外交官那一支逐行同形，只差四個立即值（狀態列 `0Eh`、選勢力用
`sub_17906`、失敗訊息 `37h` ＝ #55、成功的變體組 `1A3h`）。

## 3. ⚠ 兩個 fixture 上的坑

**一、`-open-command-menu` 只停在選單。** 要比「選完之後」的畫面得再走一步，
所以這一輪把它加上 `:第幾列`——**走真實流程**（`dispatchPopupMenu`），
選單框才會照原版留在清單上緣。

**二、修之前那兩張根本拍不出來。** `personnel:1`／`personnel:3` 的
fixture 跑完什麼都沒開（過濾之後候選是空的），`-shot-when` 到期就失敗離開。
⭐ **那個失敗本身就是分歧的第一個訊號**——`-shot-when` 的
「條件不成立就不截圖而且回非零」（[`../spec/118`](../spec/118-shot-when-condition.md) §2.2）
在這裡替我擋下了一張「看起來正常但拍到別的東西」的圖。

## 4. 同一輪把迴圈與官員台詞也接上了

人事那四條在原版是**同一個迴圈**（`sub_16A9B`／`sub_16B08`／`sub_16B71`／
`sub_16BE3` 的 `jmp` 回開頭）：不論成功、那裡已經有人、還是選武將時取消，
都回到清單繼續選，**右鍵才離開**；成功時那位官員還會自己說一句
（八格一組，由武將 `+0x1E` 選組內第幾個、肖像取 `+0x01`）。

remake 四條先前都是「選一次就收掉」，也沒有那一句。都接上了
（[`142`](../spec/142-personnel-dismiss-flow.md)），四張重拍**數字一個都沒變**
——那是預期的：迴圈與台詞要按下去才看得到，這四張拍的是清單剛開的那一刻。
