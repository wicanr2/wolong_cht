# 39 — 系統選單開著時的對拍：五區裡四區 PASS，選單本身也 PASS

**狀態：通過。** 系統選單原版那六列所佔的 208×182 矩形**逐像素相同**，
同一張截圖的命令列／大地圖／縮小地圖／自勢力情報**四區也全部 PASS**。
remake 在原版六列之後多了兩列，視窗因此高 240 而不是 192——
那 208×58 的一塊是**已知的 remake 差異**（§0）。
⭐ **這是目前最乾淨的對拍狀態**——系統選單開著時原版**時間停止**，
所以連天候物件那種會隨時間長出來的東西都不會出現。

## 0. remake 的選單比原版多兩列

使用者裁定加了兩個開關：「主君編成」（[`../spec/76`](../spec/76-lord-not-in-formation.md)）
與「損害報告」（[`../spec/89`](../spec/89-siege-damage-report-toggle.md)），
所以 `sysWinH = 192 + 2 × 24 = 240`。

⭐ 兩列都**加在原版六列的後面**，不是插進去——那六列的座標一格都沒動。
量到的結果正是這個形狀：

| 比較範圍 | 結果 |
|---|---:|
| 原版視窗的上 182 列 `(208,112,208,182)` | **0 px** |
| 原版視窗的完整 192 列 `(208,112,208,192)` | 1,688 px ＝ 下緣那 10 列的外框，remake 移到了 48 px 之下 |
| `map` 區 | 11,423 px，**全部落在 (208..415, 294..351)** ——就是多出來的兩列加下緣外框；框外一點不差 |

**所以「多兩列」是 `map` 區 7.87% 的唯一成因**，不是天候物件、也不是地圖畫錯。

- 日期：2026-08-17（版面與四件修正）、**2026-09-03**（八列版重量）
- 出處：[`../re/55`](../re/55-system-menu-window.md)（版面與四列設定值）
- 原版側：`workplace/promo-live/parity-sys/s1-system.png`（松崗 DOS/V，196年4月9日）
- remake 側：`tools/parity_shot.sh out.png -direct -scenario 0 -player 0
  -seed 7 -open-window -3 -cam 0,0 -audio workplace/audio -shot-frames 1`

## 1. 怎麼拍到

沿用 [`38`](38-window-parity.md) §1 的點法，最後多送一組
`click:46,0;press`（系統開關的熱區是 x 432–463）。

⚠ **`-audio` 要給**：沒給的話「音　效」那一格顯示 remake 才有的
「未接入」，那一列會差 272 點。給了就顯示原版的「TYPE 1」。
先跑 `tools/bgm2ogg.sh` 產生 `workplace/audio/*.ogg`。

⭐ **機器沒有音效裝置也照樣給。** `-shot` 與 `-frames-dir` 走的是
**靜音模式**（[`../spec/29`](../spec/29-audio.md) §5.1）：不碰音效裝置，
但 `Available()` 與選單顯示照舊。這一道是 2026-08-27 補的——
在那之前驗收路徑直接把音檔目錄清空，於是給了 `-audio` 也沒有用
（[`49`](49-parity-retest-20260827.md) §2）。

⭐ **`banner` 的 158 px 與 2026-08-17 那次逐點相同**——同樣的三段
（x 442..558）。橫幅這一區沒有隨這半個月的改動漂移。

⭐ **`map` 這一區在 [`38`](38-window-parity.md) 還差 7.26%（天候物件），
這裡歸零**——因為系統選單開著時時間停止（說明書 3.1），

所以原版這一張的橫幅上多了一個紅色游標，remake 沒有——
**那是原版的游標不是版面差**。

## 3. 改出來的四件事

| 項目 | 原版 | remake（修前）|
|---|---|---|
| 值格的字 | 「 ＯＫ 」的空白是**半形**，整串剛好 48 px | 全形空白 ＋ `+2` 偏移，字往右擠 10 px |
| 立體框的角 | **左下角亮、右上角暗** | 兩個角都暗 |
| 音效的選項字串 | `ds:6010h` 的 ＯＦＦ／TYPE 1／2／3／4 | 自己編的「開／關」 |
| 音效的第三種狀態 | 沒有——原版永遠有 YNSOUND | 「未接入」（remake 差異，保留）|

### 3.1 ⭐ 立體框的角是畫的順序決定的

`op 04` 的兩個顏色是「上左」與「下右」（[`../re/48`](../re/48-window-display-list.md) §2），
但**兩個角歸誰沒寫在參數裡**——它是四條邊誰先畫誰後畫的結果。
實機上量到的是**左下角亮、右上角暗**，所以順序是
「上 → 下 → 右 → 左」：上先鋪、右覆蓋掉右上、下先鋪、左覆蓋掉左下。

反過來畫的話六個值格的左下角**各差兩點**——12 個像素，
在 39,936 個像素裡佔 0.03%，肉眼完全看不出來。
**這種差異只有逐像素對拍找得到。**

### 3.2 值格的字用半形空白排

值格是 48 px（`sub_1E3D7(dx=160h, cx=206h)`）。
「ＯＫ」是 32 px，兩邊各補**一個半形空白**（8 ＋ 16 ＋ 16 ＋ 8 ＝ 48）；
「普通」同理。用全形空白會變成 64 px。

⚠ **這件事在畫面上看起來只是「字沒對齊」**，很容易當成偏移調一調就好。
真正的規則是「補到剛好 48」，而 48 是熱區的寬度——**版面數字要回去看熱區**。
