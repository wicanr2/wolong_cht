# 106 — 啟動殼層的前三頁：背景 0 px，三個版面都是 remake 自己設計的

**狀態：進行中（已歸因）。** `-shot` 本身會觸發直啟，所以啟動殼層的畫面
**一直拍不到**；本輪加了 `-open-launcher` 之後第一次比。
**背景地圖與橫幅 0 px**，三個視窗的**版面各自不同**——那不是幾個常數的偏差，
是 remake 的殼層從一開始就照自己的設計走。

- 規格：[`../spec/90`](../spec/90-same-state-parity.md) §5.1（`-open-launcher`，本輪新增）、
  [`../spec/79`](../spec/79-new-game-faction-list.md)（勢力清單）、
  [`../spec/25`](../spec/25-slot-select-window.md)（四槽視窗）
- 原版側：`WOLONG_DOSGOLEM_GAMEDIR=dosgolem/root-noclouds tools/dosgolem.sh
  workplace/parity/naming "wait;shot:s0;click:320,200;steps:600000;shot:s2"`
  （`s0` ＝ NEW GAME ＹＥＳ／ＮＯ、`s2` ＝ LOAD DATA）
  ＋ `"wait;click:320,176;steps:600000;shot:n1"`（劇本選擇）
- remake 側：`tools/parity_shot.sh out.png
  -save-file workplace/dosgolem/root-noclouds/SAVE.DAT -open-launcher 階段`

  那一頁有槽位資料可讀。

## 2. 三個版面都不一樣

| 頁 | 原版 | remake |
|---|---|---|
| `title` | **ＮＥＷ　ＧＡＭＥ ＹＥＳ／ＮＯ 兩項**，框 (208,128,224,88) | 三項選單 `NEW GAME`／`LOAD DATA`／`LANGUAGE`，框 (112,56,416,288)。⭐ **維持三項**（§2.2）|
| `scenario` | 標題 `NEW GAME` ＋ **四章各兩列**（「第一章．「呂布歸天」之卷」／「196年 4月 1日」）| ⭐ **同一份視窗**（§2.3）|
| `load` | `sub_18B5D` 的四槽視窗：副標「第一章勢力：曹操　軍師：荀彧」＋ 四列日期 | 自己的一份：「第 1 槽　196年4月16日　曹操」／「第 2 槽　空白槽位」 |

### 2.3 ⭐ `scenario` 也是同一個視窗——答案早就寫在 `docs/re/52` §2

[`../re/52`](../re/52-slot-select-window.md) §2 一直寫著
「**原版沒有獨立的選劇本畫面**：新遊戲時這四個槽是 `SINARIO.DAT` 的四個
劇本，讀取／儲存時是 `SAVE.DAT` 的四個存檔……同一份版面讀兩個檔」。
remake 卻另外畫了一頁「選擇劇本」。

指到 `drawSaveUI` 之後（標題 `ＮＥＷ　ＧＡＭＥ　`、資料源換成
`SINARIO.DAT`）**視窗內 95 / 72,960**，只剩原版游標。路上兩個缺陷：

**一、劇本讀錯了檔。** `state.LoadScenario(loadPath, i)` 的 `loadPath`
在有 `-save-file` 時是**存檔**，所以四章的標題讀出來是
「第一章勢力：曹操　軍師：荀彧」那種存檔摘要。要用 `path`（`SINARIO.DAT`）。

**二、日期擺在「能不能選」的檢查後面。** `inspectLauncherSlots` 的
`validLauncherPlayer` 是給存檔用的（存檔要有合法的玩家勢力），
而劇本沒有玩家——於是四列日期全是 `0年 0月 0日`。
原版畫的是**區塊裡的值**，與那一槽能不能選無關
（[`../spec/25`](../spec/25-slot-select-window.md) §1.2）。

### 2.2 ⭐ `title` 維持三項（使用者裁定 2026-09-07）

原版只有 ＹＥＳ／ＮＯ 兩項，remake 多一個 `LANGUAGE`。
**裁定：維持三項**——remake 支援四個語系
（[`../spec/84`](../spec/84-multilanguage.md)），啟動時就要選得到，
不能只靠遊戲中的 F9。

這是 `CLAUDE.md` §1「還原 ＋ 現代化外殼」允許的那一類改動，
**標記為 remake 差異**（[`../spec/86`](../spec/86-runtime-language-switch.md) §4）。
所以這一頁的殘差**不會收斂到 0 px**，對拍時只比背景與橫幅。

### 2.1 ⭐ `load` 收成一份實作之後，一次就對上

那一頁與遊戲中的四槽視窗在原版是**同一支常式**（`sub_18B5D` →
`sub_18B7C`，只有標題三選一），而
[`../playtest/99`](../playtest/99-slot-window-parity.md) 已經把遊戲中那一份
對到 0 px——包括「空槽照畫日期，不寫『空白槽位』」。
remake 的殼層是**第二份實作**，所以那一輪的修正沒有跟過來
（違反 `CLAUDE.md` §7 第 6 條「一條規則只留一份實作」）。

改成殼層走到那一頁時 `beginSaveUI(saveRead)`、畫面交給 `drawSaveUI`
（[`../spec/25`](../spec/25-slot-select-window.md) §2.9）之後，
**視窗內 95 / 72,960 ——只剩原版游標，一個修正都不必再做**。
⭐ 這就是「一條規則只留一份實作」的價值：第二份不會自己跟上。

## 4. ⭐ 背景的調色盤組是 1，不是 0——而 `sub_10241` 根本不是調色盤

初版量到背景差五成，±160 px 的平移搜尋最佳解仍是 (0, 0)
⇒ **不是鏡頭偏了**。顏色直方圖一比就看出來：原版最多的
`(81,162,16)` 這個綠**在 remake 一次都沒出現**。

四個組各拍一張，只有 **組 1** 的背景左半 **0 / 35,328**（其餘三組各差 934）。

⚠ 錯的來源是一句讀錯的組語：`sub_11A6E` 開頭
`mov al, 0 / call sub_10241` 被記成「調色盤組 0（春）」——
**那一支是播曲**。同一支在 `sub_13D09` 之後是 `mov al, 6`
＝ 進言場景的第 6 曲（[`../spec/45`](../spec/45-advise-scene-layout.md) §1，
那裡一直記得是對的）。

⭐ **同一個常式在兩份文件裡有兩種語意時，先 grep 那個符號。**
`sub_10241` 在 `docs/spec/45` 早就標成 BGM，而 `docs/spec/79` 標成調色盤——
兩份都 CONFORMED，衝突卻沒有人比對過。

## 3. 這不是「差幾個常數」

三頁的框矩形、欄位數、每一列的內容都不同，
**逐像素的數字（`map` 七萬多）在這個階段沒有資訊量**。
要對得先有一份「原版殼層版面」的規格（框、列距、每一列印什麼），
再讓 remake 照著重畫——那是一份新的 `docs/spec/`，不是這一輪的修補。

⭐ 但 `load` 那一頁是例外——它的規格早就有了（[`../spec/25`](../spec/25-slot-select-window.md)），
所以只要**指到同一份實作**就對上（§2.1）。
