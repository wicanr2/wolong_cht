# 52 — 攻城的時間序列對拍：原版七張影格 vs remake 的規則層

**狀態：進城的機制對得上，差的是速度。**
⭐ 攻城計時器：大將體力兩邊都線性下降，六段之間沒有系統性漂移。
⭐ 進城方式也一樣——**兩邊都是打穿 y 29–31 那三格城壁**：t1 的畫面上
攻方已經散在許昌城內，也就是**牆在 t1 之前就破了**，門強度條只活 20 幀，
早就到期。⚠ 唯一的殘差是**破牆花多久**：remake 從第 ~260 幀打到第 ~1,100 幀；
原版在 t1 時已經進城，但 t1 是第幾幀**回推不出來**（見 §7），
所以只能說「比 remake 早」。**這一項要收掉需要新的原版擷取。**
順著這條線讀機器碼修掉了三處（[`../spec/97`](../spec/97-climb-when-both-axes-blocked.md)、
[`98`](../spec/98-climb-into-a-gate-hits-it.md)）。

- 日期：2026-08-27
- 規格：[`../spec/91`](../spec/91-tactical-parity.md)（分區與同狀態）、
  [`../spec/36`](../spec/36-ground-planes-and-climbing.md) §1.4（登城的四個條件）
- 原版側：`workplace/promo-live/parity-battle4/` 的 `t1`–`t16`
- fixture：**同一次擷取存下來的 `SAVE-L.DAT`**（196年5月10日）

## 1. ⭐ 這一組的價值：存檔與影格出自同一次擷取

[`51`](51-siege-deadlock.md) 用的是 `probe-march/e10.png`，而那一次擷取
**沒有存檔**——只能拿另一天（5月10日）的存檔去對 5月20日的畫面，
於是三個計量條的**基準值全部未知**：城壁耐久是 `(城兵數 + 50) × 10`
（[`../re/11`](../re/11-tactical-battle.md) §5.11），而城兵數十天之內會變；
攻方體力的初值是軍團士氣，也會變。**差異的數字要配基準值才有語意。**

`parity-battle4` 沒有這個問題。它的時間線是：

```
… savefile:SAVE-L.DAT; rclick…; wait:6; wait:6;
shot:t1; wait:6; shot:t2; … wait:6; shot:t16
```

**存檔先落地，然後每隔一個 `wait:6` 拍一張。** 基準值就在手上：

| | 值 |
|---|---|
| `SAVE-L.DAT` | 196年5月10日 |
| 攻方 軍團 35 呂布 | 兵 600、士氣 200 |
| 守方 軍團 39 夏侯惇 | 兵 600、士氣 200 |
| 許昌 城兵 | 116 → **城壁耐久 1,660** |

`t1` 的側欄寫著「許昌 作戰／曹操 對呂布」「呂布 軍」「夏侯惇軍」——
與存檔對得上。

## 4. 對得上的：攻城計時器

用攻方體力當時鐘（它由 `sub_1AE56` 每 10 幀扣 1，是兩邊都確定的機制）：

| | 體力條 100 → 75 |
|---|---|
| 原版 | t1 → t7，六個 `wait:6` |
| remake | 約第 662 → 1,000 幀，**338 幀** |

⇒ **一個 `wait:6` ≈ 56 個 remake 幀**，六段之間沒有系統性漂移。
斜率對得上——**攻城計時器這一條是通的**。

## 5. 進城的方式一樣，破牆的速度不一樣

把同樣那 338 幀擺在一起：

| | 原版（t1→t7）| remake（f662→f1000）|
|---|---|---|
| 門強度條 | 一次都沒出現 | 一路顯示（54 → 10）|
| 城壁 | — | 877 → 163 |
| 攻方位置 | **已經在城內**（t1 的畫面上散在許昌的屋瓦與迴廊之間）| 還在城外敲牆 |
| 兩軍接觸 | t6 就交手（守方大將體力 124→37）| 一次都沒有 |

⭐ **門強度條沒出現不是「沒打過城壁」，是「早就打完了」。** 那個條在
最後一次挨打之後只活 `0x14` ＝ 20 幀（[`../spec/32`](../spec/32-gate-strength-bar.md)），
而 t1 已經是開戰後約 670 幀（用攻方體力回推，§4）——**牆在那之前就破了**，
攻方已經進城。t1 的截圖直接看得到：藍色的兵散在城內的屋瓦上。

所以兩邊的進城機制是同一個：**打穿 x=27、y 29–31 那三格城壁**。
那三格是這張圖上唯一可破壞的城壁段（其餘 x 27–34 是走不通的地形），
而 y 29–31 正好是穿過城牆帶的那條走廊：

```
x     22..38
y29   .................    ← 走廊（城壁那三格就在 x=27）
y30   .................
y31   .................
y32   ...#####.########
```

**差的是速度**，而 remake 這一側量得很乾淨：

| frame | 城壁 | 這 100 幀掉了 | 貼在破口前的兵 |
|---:|---:|---:|---:|
| 300 | 1,540 | 120 | **3** |
| 600 | 973 | 191 | **3** |
| 900 | 369 | 209 | **3** |
| 1,100 | 0 | 163 | 2 |

破口只有三格（x=27、y 29–31），所以**最多就是三個兵貼著打**，
實測每幀掉約 2 點——1,660 點要磨 830 幀，從第 ~260 幀打到第 ~1,100 幀。

⚠ **原版那一側回推不出精確的幀。** 用攻方體力當時鐘的前提是
「體力只被攻城計時器扣」，而體力**挨打也會掉**（`sub_1B618`）。
t1 的體力條 100 px ＝ 體力 133，這 67 點裡有多少來自計時器、多少來自
挨打，單張畫面分不出來。所以只能說原版比 remake 早進城，
說不出早多少。

## 6. 讀了機器碼之後## 6. 讀了機器碼之後：修掉三處，而 fixture 沒有變

`tools/ida.sh script dosv tools/ida_range.py` dump 了移動分派與登城那幾支，
對出三個 remake 與原版不一樣的地方，都改掉了：

| # | 原版 | remake（修前）| 出處 |
|---|---|---|---|
| 1 | 純 Z 移動的觸發只要「X 與 Y 這一幀都沒走成」 | 還要求 X、Y **已經等於目標** | `sub_1AF69` 的 `jb` 鏈 |
| 2 | 命令 3 的目標 Z 取**高平面**那一格的地面層（牆頂）| 取腳下的地面層 | `loc_1AB39` 的 `bh \|= 10h` |
| 3 | 爬不上去時若上一層有實體 → 走碰撞處理**打它** | 直接放棄 | `sub_1B0D3` 的 `and al, al / jnz loc_1B533` |

⚠ **三處都修好之後，這條 fixture 的每一個數字都沒有動。** 成因在別處：

| 這張圖的門 | 位置 |
|---|---|
| 未破的門（`0xF0`–`0xF7`，攻方那一側）| **4 格**：(34,6)、(31,20)、(31,41)、(34,54) |
| 已破／可爬（`0xF8`+，城內）| 8 格：x ＝ 24 或 26，y 4–56 |

而**登城部隊的 Y 全部落在 28–35**（`form 4`／`5`／`6` 這三個陣形的 Y 帶），
命令 3 的目標又是 **(登城點 X, 自己的 Y)**——Y 不會變。
**所以沒有一個兵走得到門格**，而 x ＝ 27 那一欄在 y 29–31 正好是城壁，
於是撞上去、把它磨穿。

⭐ **那三處是真的對錯了，只是不是這一條的成因。**

## 7. 未解

|---|---|---|
| ⭐ **破牆速度** | remake 量得很乾淨（§5）：三個兵貼著打、每幀約 2 點、第 ~1,100 幀破。**原版那一側量不出來**——體力同時被攻城計時器與挨打扣，單張畫面分不開 | ⛔ **要新的原版擷取**：從存檔載入之後在開戰的**前兩百幀密集取樣**（現有的 `wait:6` 一格就跨掉五十幾幀）。這是這一項唯一的路，靜態讀機器碼補不上 |
