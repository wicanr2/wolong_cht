# 85 — 武將職務 `+0x17`：原版逐值實跑確認，remake 攤開

**狀態：通過。** 在 dosgolem 上把原版整條走完（人事 → 內政官任命 →
選據點 → 選武將 → 解任），逐步讀武將記錄，確認 `+0x17` 是**職務值**
而不是布林：任命寫 `2`、解任回 `0`，武將一覽的身分欄直接拿它查字串表。
remake 的 `General.Posted bool` 因此攤成 `General.Duty int`。
順帶解掉一個掛著的缺口：**軍師不在清單裡是因為他整筆被移出武將表**，
不是因為有人替他寫了職務（§5）。

- 日期：2026-09-06
- 規格：[`../spec/143`](../spec/143-general-duty-field.md)
- 原版側：`WOLONG_DOSGOLEM_GAMEDIR=dosgolem/root-saveb tools/dosgolem.sh
  workplace/parity/duty "wait;click:320,200;click:300,151;until:196/4/20;
  sclick:352,15;stap:96,47;steps:400000;press;steps:600000;
  stap:200,112;steps:400000;stap:200,112;steps:800000;
  stap:200,112;steps:400000;stap:200,112;steps:1200000;
  peek:2754:46E0:32;generals:0"`
- remake 側：`internal/state` 與 `cmd/wlgame` 的單元測試（§4）

## 1. 怎麼開到那個狀態

清單是**兩段式選取**——第一下反白、第二下才決定，所以每一層都是
`stap` 兩次。四層依序是：

| 步驟 | 動作 | 到哪 |
|---|---|---|
| `sclick:352,15` | 開指令列 | 八格 |
| `stap:96,47` | 人事 | 四項彈出選單 |
| `press` | 第 0 列 | 內政官任命 |
| `stap:200,112` ×2 | 據點第 0 列 | 濟陰 |
| `stap:200,112` ×2 | 武將第 0 列 | 夏侯淵 |

⚠ **官員說完那一句要 `sclick` 才收得掉，`stap` 收不掉**——瞬按沒被
訊息框那一層讀到。這一點在人事迴圈裡會連續踩到，因為每成功一次就有一句。

## 2. 原版的記錄長什麼樣

資料段由 `cs:word_10D52` 取（實測 `0x2754`），武將表在段內 `4240h`、
stride 32，所以夏侯淵（編號 37）的記錄是 `peek:2754:46E0:32`。

```
任命後  80 3E AE4C AB4A B257  AE4C AB4A B257  00 40 20 0C 06 03 02 00 01 [02] 00 FF 00 00 00 FF 07 2A
解任後  80 3E AE4C AB4A B257  AE4C AB4A B257  00 40 20 0C 06 03 02 00 01 [00] 00 FF 00 00 00 FF 07 2A
                                                                          ↑ +0x17
```

**整筆只有 `+0x17` 變了。** `+0x11`／`+0x12`／`+0x13` ＝ 12／6／3
與畫面上的武術／統率／政治對得起來，確認讀的是同一個人。

`generals:0` 在同一時刻的輸出（`職` 那一欄就是 `+0x17`）：

```
任命後   武將 37 …… 勢 0 職2 武12 統 6 政 3 ……   ← 夏侯淵，內政官
         武將 39 …… 勢 0 職1 武11 統 6 政10 ……   ← 夏侯惇，軍團長（本來就有）
解任後   武將 37 …… 勢 0 職0 武12 統 6 政 3 ……
```

## 3. 身分欄是直接查表，而且職務優先

任命之後開武將一覽（`stap:336,47`）：

| 武將 | `+0x17` | bit 6 | 身分欄 |
|---|---|---|---|
| 曹操 | 0 | 立起 | `君主　` |
| 夏侯淵 | 2 | — | `內政官` |
| 夏侯惇 | 1 | — | `軍團長` |
| 其餘 | 0 | — | `－－－` |

與 `sub_1770C` 的三行完全一致（[`../spec/143`](../spec/143-general-duty-field.md) §1）：
`al = [si+17h]`，只有 `al == 0` 才去看 bit 6 換成 5。
⭐ **順序是職務優先、君主墊底**——君主若也編了軍團會顯示「軍團長」。
remake 先前從 `Factions[].Lord` 反查，那一格會反過來。

官員自己那兩句也順帶確認了（[`../spec/142`](../spec/142-personnel-dismiss-flow.md)）：
任命「我立刻前往。」、解任「那我這就回京城。」——夏侯淵 `+0x1E` ＝ 7，
所以取的是組 `0x19C`／`0x1A2` 的第 7 個。

## 4. remake 改了什麼

`General.Posted bool` → `General.Duty int`（0–4）＋ `Posted()` 方法；
任命／解任收進 `internal/state/personnel.go` 的四支
（`AssignGovernor`／`DismissGovernor`／`AssignDiplomat`／`DismissDiplomat`），
身分欄改成直接讀 `Duty`。四組測試：

| 測試 | 擋什麼 |
|---|---|
| `TestGeneralDutyRoundTripsAllValues` | 0–4 逐值 round-trip。**灌進原始 bytes 才驗得出來**——四個劇本的初始值全是 0，只比劇本存檔的話「2／3／4 被壓成 1」看不出來 |
| `TestAssignAndDismissGovernor`／`…Diplomat` | 任命寫兩格、解任清三格（含經費歸零）|
| `TestGeneralRankFollowsDutyFirst` | 君主兼軍團長顯示「軍團長」 |
| `TestFormCandidatesExcludeAppointedOfficials` | 派出去的官員不在編成候選裡；解任後回來 |

## 5. 順帶解掉的：軍師為什麼不在清單裡

這一輪把兩張清單並排看，**編成與人事任命用的是同一支 `sub_17663`**
（同一個建清單 callback `0x176A0`），逐列相同：

```
編成           夏侯淵 許褚 荀彧 徐晃 曹洪 曹純 曹仁 程昱 典韋 …
人事·內政官任命 夏侯淵 許褚 荀彧 徐晃 曹洪 曹純 曹仁 程昱 典韋 …
```

少的只有君主（曹操）與軍團長（夏侯惇）。**荀彧在列**——
而 [`../spec/76`](../spec/76-lord-not-in-formation.md) §2 原本記著
「軍師（荀彧）不在候選裡，是執行期有人把身分寫進 `+0x17`，寫入者未讀」。

真正的原因讀出來了，而且不在 `+0x17`：

```
勢力  0 君 16 師 62 …… 將 11 ……
武將 62  2754:4A00 = [00] 79 …   ← +0x00 ＝ 0，整筆不在武將表上
武將 63  2754:4A20 = [80] 45 …   ← 荀彧，正常（他不是這一局的軍師）
```

新遊戲定案時 `loc_11AF8` 寫的是**記錄 `+0x00`**
（`mov byte ptr [si+4240h], 0`），存在旗標一起沒了，
所以每張清單的第一個條件 `[si] ≥ 0x80` 一次擋掉
（[`../spec/144`](../spec/144-advisor-leaves-general-table.md)）。
那一局的軍師是 62 不是 63，所以荀彧當然在列——
**先前的觀察沒錯，錯的是歸因**。

remake 接上之後，勢力表的武將數與原版逐格相同：

| | 原版（`root-saveb`，曹操局）| remake `-player 0` | remake `-player 1` |
|---|---:|---:|---:|
| 勢力 0 將 | 11 | **11** | 12 |
| 勢力 1 將 | 12 | **12** | 11 |

**減一只發生在玩家自己的勢力**，換玩家就換一格——這一條要兩個方向都跑，
只跑一邊的話「永遠減勢力 0」也會通過。

## 6. 未解

| 項目 | 現況 |
|---|---|
| **解任把 `+0x1A` 歸零沒有實跑正對照** | 機器碼是 `mov byte [bx+1Ah], 0`（[`../re/25`](../re/25-message-variants-and-personnel.md) §3.1，confirmed），但這一輪那位官員的經費本來就是 0，**實跑等於沒比**。要撥過款再解任才驗得到 |
| 身分欄的畫面對拍 | 原版擷取有了（§3），remake 同狀態的還沒拍——要讓 remake 也走到「已任命」再開武將一覽 |
| `sub_13771` 讀 `+0x17` 的分支 | 語意未解（[`../spec/143`](../spec/143-general-duty-field.md) §8）|
| 自定軍師時原版那個越界寫 | `loc_11AF8` 在 `+0x02 ＝ 0x7F` 時照樣寫 `[0x7F×32 + 4240h]`，落在武將表尾端之後；寫進去的是什麼欄位沒查，remake 不照抄 |
