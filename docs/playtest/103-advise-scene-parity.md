## 2. ⭐ 插圖座標：格座標與 VRAM 位址兩種單位混在一起

[`../spec/45`](../spec/45-advise-scene-layout.md) 記的是 (64, 144)。
逐像素量出來的最佳位移是 **(−8, −8)**，而機器碼給的是位址不是格：

```asm
sub_13D68:
    dx = 3 / bx = 8 / cx = 0C13h / call sub_10C14   ; (48, 128) 304×192 的底
    bx = 2A87h / ax = 0B012h / call sub_1FA37       ; ★ 貼圖
```

`0x2A87 ÷ 80 = 136` 餘 `7` ⇒ **(7 × 8, 136) ＝ (56, 136)**，
尺寸 `ah = 176`／`al = 18 × 16 = 288`。

⭐ **(64, 144) 是拿 16 px 粗格去湊位址的結果**：那個底 (48, 128) 304×192
正好比插圖大 8 px 一圈，只看粗格會把插圖對齊到下一個格線上。
**同一份規格裡混用兩種單位，差的就是半格。**

## 3. ⭐ 進說服場景之前一定先清狀態列

三條進言（敵對 `sub_16405`／停戰 `sub_164F1`／請求協助 `sub_16623`）
在呼叫 `sub_13830` 之前都做同樣兩件事——隱藏游標、`cx = 0FFFFh` 清狀態列。

⚠ **不能靠「被場景蓋住」**：場景只蓋掉 (0, 32, 432, 336)，
而狀態列在 (0, 320, 256, 80)，**下緣 32 px 蓋不到**。
remake 先前留著那個框，於是畫面底部多一條。

⭐ 同一段還證實了游標的隱藏（[`../re/88`](../re/88-mouse-cursor-visibility.md)）：
`ipeek:20100:1` 在這一張讀出來是 **0**，畫面上也確實沒有游標。
