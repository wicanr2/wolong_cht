## 正常場景

從首頁開第一章曹操，編成軍團37，向袁術12提出敵對提案並選「我國較有利」，
交戰成立後正常下令攻汝南100。先擊退城兵、讓37走進城中心，再留守等軍團3反攻。
沒有執行 `siege:`、跳入常式、改座標、改交友度或注入勝負。

原版於196/4/8 6時子刻5，汝南已歸玩家0，37在 `(216,137)`。
軍團3仍按原AI行軍；4/9 18時子刻0，首次完整碰撞拍停在 `(219,137)`，
連結 `0x10B0`、路徑點 `0x4D4C`、倒數11。37仍守城中心。
這條路徑從城門進攻，不是軍團間野戰。

位址採IDA Pro9.4 database linear，base `0x10000`。執行期軍團基址為 `DS:2240`，
軍團3是 `DS:2300`，37是 `DS:2B80`；存檔區塊另有 `0x80` 的位移。

| 原版停點 | 指令數與觀測 |

| `0x14ADE` 攻城入口 | 381,275,913；4/10 5時子刻5；SI=`2300`、DI=`14C0`，軍團3攻據點100 |
| `0x11B5A` 戰術入口 | 381,381,065；SI=`2300`、BX=`2B80`，3攻37守 |

## 入戰排程差異與未解

原版在軍團更新的中途進入 `0x14ADE/0x11B5A`，時鐘停在子刻5。
Go目前在 `tickCorps` 建立待戰後，仍完成該軍團尾段、其餘軍團、MCH及 `Clock.Advance`，
第96次更新返回時是子刻6。因此本篇只把開戰前95點與角色選擇列為通過，
沒有把Go完整更新後的快照當成原版函式入口的同相位快照。

現行 [ResolvePending](../../internal/state/tactical.go) 結算後沒有部分世界更新的續跑機制。
原始排程與Go呼叫位置可回查 [state.go](../../internal/state/state.go)、[corps.go](../../internal/state/corps.go)。
只擋最後一次時鐘進位會遺漏軍費、倒數、輪轉游標及剩餘軍團的順序問題。
這項排程差異仍在Issue #30範圍內，尚未修正；需驗證戰鬥返回後的續跑與存檔邊界，
不在本輪工具或測試裡猜補規則。
完整戰鬥結果、野戰碰撞、MCH動畫、音效及完整戰役亦不由本片代證。
dosgolem仍報一項未建模 `int61 AH0A/AL03`，本片不作音訊或硬體時序聲明。
