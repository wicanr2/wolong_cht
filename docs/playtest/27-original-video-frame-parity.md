# 27 — ⭐ 拿原版實錄影片對版面：主畫面與戰術畫面的幾何都落在 3 px 內

**狀態：主畫面與戰術畫面的**幾何** parity confirmed（誤差 ≤ 3 px）。
⭐ 這是**第一次**在原版的實際遊戲畫面上核對機器碼讀出來的版面常數。
戰術側欄的內容組成已逐項解出並接進 remake（§7.3）；
仍未做的是同一場戰鬥的逐格對拍。**

- 日期：2026-08-16
- 原版側：`workplace/promo-live/original-video/original.mp4`
  （956×720、30 fps、9 分 27 秒，來源網址與 SHA-256 見同目錄的
  `source-metadata.txt`）
- remake 側：`tools/shot.sh` ＋ `wlgame -direct -scenario 0 -player 0 -open-window -2`
- 工具：`tools/parity_frame.py`（新增）

## 1. 為什麼這條路走得通

主畫面的版面常數是從 `KI.EXE` 讀出來的（[`../re/47`](../re/47-main-screen-window-registry.md)），
但**一直沒有辦法在原版畫面上核對**：模擬器裡主畫面收不到點擊
（[`23`](23-main-screen-geometry.md) §4.1），所以進不到四窗全開的狀態。
`CONTEXT.md` 因此把「同狀態對拍」列為做不到的事。

**實錄影片繞過那個閘**——它本來就是那個狀態。

⚠ **這不是逐像素 parity。** 影片是再編碼過的：956×605 的內容由 640×400
放大而來（垂直還多拉約 1.1%），色彩經過 4:2:0 取樣。
能比的是**幾何**：邊界落在哪一格。

## 2. 對齊方式

原版影格的遊戲區在 `x 0–955`、`y 56–660`（量非黑內容的外框），
最近鄰重取樣成 640×400。**不做內插**——內插會把 1 px 的框線抹掉，
而框線正是要量的東西。

量法：沿 x 與 y 各算相鄰像素差的行／列平均。版面框線是整條直線，
會形成尖峰；地圖與人物的紋理是散的，平均之後壓不過框線。

| 畫面右緣 | 639 | 637 | 2（框線內緣）|
| **縮小地圖上緣** | 40 | **40** | **0** |
| 縮小地圖圖例線 | 168 | 167 | 1 |
| 自勢力情報內緣 | 200 | 199 | 1 |

命令列八個指令的文字起點：

| | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|--:|--:|--:|--:|--:|--:|--:|--:|

⭐ 命令列的節距曾經是照影片猜的、後來改成讀 `cs:6181h`
（[`../re/47`](../re/47-main-screen-window-registry.md) §4.1）。**這次的量測是那次訂正的獨立驗證。**

## 5. 怎麼重跑

```sh
# 1. 抽影格（每 15 秒一張）
docker run --rm --network none -v "$PWD/workplace:/w" linuxserver/ffmpeg \
  -y -i /w/promo-live/original-video/original.mp4 -vf fps=1/15 /w/parity/orig/f%03d.png
# 2. 轉 PPM（工具只吃 P6，標準函式庫沒有 PNG 解碼器）
docker run --rm --network none -v "$PWD/workplace/parity:/p" linuxserver/ffmpeg \
  -y -i /p/orig/f008.png -pix_fmt rgb24 /p/f008.ppm
# 3. 對齊並量地標
tools/py.sh tools/parity_frame.py workplace/parity/f008.ppm --crop 0,56,956,661 \
  --cols 440,630 --out workplace/parity/f008-640.ppm
# 4. remake 側
WOLONG_SHOT_CMD=wlgame tools/shot.sh workplace/parity/remake.png \
  -direct -scenario 0 -player 0 -open-window -2 -seed 1
```

⚠ **中間產物含原版畫面，一律留在 `workplace/`（已 gitignore），不進版控**
（`CLAUDE.md` §9）。這一份只記數字。

## 6. 未解

| 項目 | 現況 |
|---|---|
| 逐像素 parity | 影片是再編碼的，這一份做不到。**後來回到模擬器做成了**——主畫面五區、系統選單與戰場九區裡六區都逐像素相同（[`37`](37-main-screen-parity.md)–[`40`](40-tactical-parity.md)）。「主畫面的點擊閘」也不存在，是座標算錯（[`38`](38-window-parity.md) §1）|
| 色彩 | 這一份只比了幾何。**後來解出來是調色盤刻度差 4%**——DOS/V 走 VGA 的 6 bit DAC（[`../spec/51`](../spec/51-vga-dac-palette-scale.md)），改完主畫面就逐像素相同了 |
| 戰術側欄的逐格對拍 | ✅ **做了**：`-siege-corps` 讓兩邊站同一個局面，側欄六區裡四區逐像素相同（[`40`](40-tactical-parity.md)）|
| 戰場圖塊組 | ✅ §7.4：同一張戰場（濟陰）逐項相符，先前的差異是拿兩張不同戰場比出來的 |
| 門強度條 | §7.5。已解並實作（[`../re/60`](../re/60-tactical-sidebar.md) §11、[`../spec/32`](../spec/32-gate-strength-bar.md)）；**remake 側沒有截圖**——這條只亮 20 幀 |
| 一覽表視窗 | 影片裡有武將／據點／財政的實錄，**還沒量** |

### 7.4 ⭐ 戰場本體：同一張戰場逐項相符（2026-08-16 驗）

拿原版影格 `workplace/parity/orig/f023.png`（**濟陰**的攻城，側欄標題
「濟陰　作戰／呂布　對曹操」）對 remake 的同一張戰場
（`-open-siege -siege-node 56`，濟陰的據點編號是 56）：

| 元件 | 原版 | remake |
|---|---|---|
| 城壁 | 灰白磚 ＋ 橘褐勾縫，階梯狀 | 相同 |
| 草地 | 綠底 ＋ 黃色小花 | 相同 |
| 河與橋 | 藍色河、木紋橋面 | 相同 |
| 河岸 | 深色柵欄 | 相同 |
| 門強度條 | 畫面頂端 | 相同 |

**顏色沒有問題。** 早先「remake 把城壁畫成灰色柵欄」的說法是拿
**兩張不同的戰場**比出來的——remake 那時開的是壽春，而且把河岸的柵欄
看成了城壁。要比地形就得先讓兩邊開同一張戰場，`-siege-node` 就是為此加的。

⚠ 仍然不同的是**相機的初始位置**（原版城牆佔畫面上半，remake 在右側），
那是視角不是地形。

### 7.5 攻城才有的東西

原版攻城時頂端有「**門強度**」＋ 進度條。

原版怎麼畫已經解出來了（[`../re/60`](../re/60-tactical-sidebar.md) §11）：
`sub_1C407` 把「門強度」三個字放在 (264,8)，`sub_1C4D2` 在 x 320 起畫一條
151 px 長、2 px 高的條，長度 ＝ `城門實體 +0x18 >> 4`，色 11／空白色 0，
而且**只在比已畫過的最小值更小時才重畫**——這條只會往下掉。
它還會在 `0x14` 幀後自己收掉。

remake 已照這一套實作（[`../spec/32`](../spec/32-gate-strength-bar.md)）。
**沒有 remake 截圖**：量過真實攻城圖 2,000 幀，這條只亮 21 幀，
單張截圖抓不到。
