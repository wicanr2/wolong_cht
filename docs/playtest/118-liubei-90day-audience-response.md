# 118 — 劉備 90 天無人值守：君主召見用右鍵推進，選項用移動次數

**狀態：通過。** 玩家＝劉備、除了回應召見什麼都不做，原版
**196/4/16 → 7/16 整整 90 個遊戲日跑得完，一輪 26 秒**，
同一條時間軸兩次逐 byte 相同。

- 日期：2026-09-09
- 規格：[`../spec/161`](../spec/161-liubei-idle-longrun-parity.md)
- 存檔：`workplace/dosgolem/root-liubei/`（`tools/parity_save.py --player 2`

## 1. 「什麼都不做」跑不完 90 天

第 25 天（196/5/11 17 時）時鐘停住，畫面是

> 「孫乾　大人，主公有事召見。」

孫乾正是劉備的軍師，也就是玩家扮演的人（`CLAUDE.md` §3.2）。
**君主會召見軍師，遊戲停下來等回應**——所以無人值守的前提要修正成
「只回應召見，其餘什麼都不做」。

[`../spec/131`](../spec/131-dosgolem-oracle.md) §7 對曹操那條線記過同一種
天花板（首都被攻的訊息），這裡是同一件事的另一個入口。

## 2. 原版在等右鍵，不是左鍵

卡住時 `profile:20000000` 取樣 206,186 次，兩段佔 99.8%：

| 段 | 佔比 | 是什麼 |
|---|---:|---|
| `20000–200FF` | 55.42% | 滑鼠驅動分派器 `sub_20000`（[`../re/01`](../re/01-first-recon.md)）|
| `12200–122FF` | 44.35% | `sub_12286` 火災與暴動（[`../re/07`](../re/07-monthly-settlement.md) §17）|

攔 `sub_20000` 看功能號，卡住時**只呼叫一種**：

```
2990 次（最後 3000 行的全部）  AX=0005  BX=0001  來自 近=22255
```

`int 33h AX=5` 是「讀按鍵**按下計數**」，而 **`BX` 是輸入——問的是哪一顆鍵**。
`BX=1` ＝ **右鍵**。⭐ 這解釋了先前四種左鍵操作為什麼全部無效，
也解釋了為什麼 `sub_20070` 的座標快取（`cs:word_200FC`）一個 byte 都沒變：
**遊戲根本沒問座標**（`AX=3` 在這個狀態下一次都沒被呼叫）。

## 3. 回應序列

```
rclick:287,199 ; steps:500000      ← 推進召見對話（兩次）
rclick:287,199 ; steps:500000
[move:96,220 ; steps:100000] × N   ← 選第 N 列（移動次數＝列號，spec/131 §3.5）
press
steps:2000000
[rclick:287,199 ; steps:500000] × 3 ← 推完君主的回應
```

召見的內容是**曹操的使者請求協助**，君主問軍師的意見，選項三列：

| 列 | 選項 |
|---:|---|
| 1 | 無條件同意 |
| 2 | 提供資金 |
| 3 | **絕**（拒絕）|

選第 3 列之後軍師回答「呂布　令人顧慮，我想此事還是拒絕為宜。」——
⭐ **選項的效果看得到**，這條路可以拿來控制劇情分支。
