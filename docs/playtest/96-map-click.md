# 96 — 大地圖點擊接上：兩項選單 112×48 逐像素 0 px

**狀態：通過（框與內容）／受限（整張畫面）。** 原版的大地圖左鍵是一條完整的
分派（`sub_11E46`），remake 先前**點地圖什麼都不做**。接上之後那張
「據點／軍團」兩項選單與原版**逐像素相同**（112×48 全 0 px）。
整張畫面比不了——原因寫在 §3。

- 日期：2026-09-06
- 規格：[`../spec/151`](../spec/151-map-click.md)
- 原版側：`…;sclick:352,15;stap:288,47;steps:200000;press;steps:900000;
  rpress;steps:400000;tile:206,114;steps:200000;press;steps:900000;shot:orig-mapclick`
  （先用「據點 → 首都確認」把鏡頭帶到許昌，右鍵關掉情報卡，再點那一格）
- remake 側：`-open-command-menu city:0 -map-click 206,114`
  （`-map-click` 本輪新增）

## 1. 結果

| 比什麼 | 不同像素 |
|---|---:|
| 兩項選單框（112×48，對齊之後）| **0 / 5376** |

框的左緣兩邊都落在 x ＝ 328（錨點 `col × 16 ＝ 320` ＋ 8 px 框邊），
兩列字「　據　　點　」「　軍　團　」與反白列的顏色逐點相同。

## 2. ⭐ 那一格上的軍團**不分敵我**

建表 callback（線性 `0x17217`）讀了玩家勢力卻**從頭到尾沒比對它**：

```asm
    xor ah, ah
    al = cs:byte_10CFF        ; ← 讀了，之後 al 沒有再被用到
.loop:
    cmp byte [si], 80h    / jb next   ; 軍團存在
    cmp <游標列>, [si+10h] / jnz next
    cmp <游標行>, [si+12h] / jnz next
    …
```

所以點得到別人的軍團——「別人的」由 `sub_17F90` 用狀態列 #4 處理
（[`../spec/149`](../spec/149-march-target-map-picker.md) §1.3）。
⚠ 那一行 `mov al, …` 很像過濾條件，**只有把整段讀完才知道它是死的**。

## 3. 整張畫面比不了：鏡頭是格級的

原版走到這一步時鏡頭已經被邊緣捲動帶走，落在非 16 倍數的位置，
而 remake 的鏡頭以**格**為單位（[`../spec/149`](../spec/149-march-target-map-picker.md) §4）。
兩張的地圖背景因此差一整片，逐區比沒有意義——所以這一份只比那個框，
而框的位置是**兩邊各自算出來**的（`col × 16`），不是對齊過的。

⭐ 同一個限制在 [`93`](93-status-bar-sweep.md) §4（狀態列 #21）也遇到過。
**要拍邊緣捲動之後的畫面就得先把鏡頭改成像素級**，那是一項獨立的工作。
