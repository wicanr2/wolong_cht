（`256×80`）三塊都與原版擷取**逐像素相同**。順帶把 `\2` 代入的名字
換成色 `0x0B` 並補足定寬三格——那正是最後 530 px 差異的來源。

- 日期：2026-09-06
- 規格：[`../spec/39`](../spec/39-march-order-menu.md) §3.7、

- remake 側：`tools/parity_shot.sh … -open-march-mode [-march-to 58]`

## 1. 怎麼比

原版的選單開在**游標所在的格**，headless 截圖的指標停在 `(0,0)`
（`tools/parity_shot.sh` 刻意把它移開，`../playtest/42` §3），所以兩張的
選單**位置不同、內容應該相同**。比法因此是「各自裁一塊同樣大小的矩形再逐點比」，
不是整張相減——整張比只會得到一個被地圖差異淹掉的數字。

| 塊 | 原版位置 | remake 位置 | 大小 |
|---|---|---|---|
| 選單（三項）| `(320,160)` | `(0,0)` | 112×64 |
| 選單（兩項）| `(320,160)` | `(0,0)` | 112×48 |
| 狀態列框 | `(0,320)` | `(0,320)` | 256×80 |

⭐ **位置本身另外驗**：`marchModeAnchor` 的兩道夾制有單元測試
（`TestMarchModeAnchorClamps`），而夾制的上限值就是「右／下緣剛好貼齊
640／400」——位置與大小是同一組立即值推出來的。

## 3. 中間那一版：530 px 全在同一件事上

框、肖像、四列字的位置都對之後，狀態列框還差 **530 px（2.59%）**，
第一個不同點在 `(133, 336)`：原版是黑的、remake 是白的。

那是**整行往左位移了一個全形字**——原版畫的是「向許昌　移動下。請下」，
remake 畫的是「向許昌移動下。請下」。

原因不在版面，在代入：`\2` 的 handler 是 `al = 3` 再 `call loc_10701`
（[`../re/79`](../re/79-talk-marker-handlers.md) §2），也就是
**照欄位寬度畫滿三個全形字**；「許昌」只有兩個字，第三格是補白，
而原版把補白也畫出來。remake 的 `text.Decode` 對定長欄位做 `TrimRight`
（對武將一覽的欄位是對的），於是少了那一格。

補上定寬之後 0 px。
