# 75 — 原版尋路會繞出隊列：小地圖那 8 px 是一個越不過大將的兵

**狀態：通過。** 逐兵比座標找出小地圖那 8 px 的來源——
**96 個兵裡只有一個站錯**，而原因是 remake 的尋路把繞路成本當成裝飾。
照 [`../spec/134`](../spec/134-pathfind-wave-order.md) 改成波數佇列之後，
**96 個兵逐槽全等，`sb-minimap` 0 px**。

- 日期：2026-09-05
- 那一場：呂布軍（#35）攻許昌（82），夏侯惇軍（#39）守（同
  [`72`](72-same-battle-parity.md)）
- 原版側：`siege:35,82` → `runto:11B5A` → `ticks:4` × 18，每次印 `units:1/0`
- remake 側：`-open-siege -siege-corps 35,39 -siege-node 82 -battle-steps 70 -list-units`

## 1. 先逐兵比，再看畫面

小地圖一個兵佔 2×2 px，8 px 就是**兩格**——一個兵離開舊格、站上新格。
逐槽比 96 個兵，對不上的只有一個：

```
1/0/1  原版 (60,30)   remake (60,33)
```

側 1 第 0 隊第 1 位（攻方呂布軍）。其餘 95 個逐槽全等。

## 2. ⭐ 原版怎麼過去的：繞出那一欄

第 0 隊的陣形是一列縱隊（`dx` 全是 −2，`dy` ＝ 0, −2, +2, −4, +4, −6, +6, −8），
**大將站在正中間的 (60,32)**。出生點在大將另一側的隊員必須越過那一格，
而大將是不能對調的（[`../re/11`](../re/11-tactical-battle.md) §5.16 的四道閘之一）。

用 dosgolem 的 `ticks:4` ＋ `units:1/0` 逐拍取樣，看到的是：

| 拍 | 位 2 | 位 3 | 位 6 |
|---:|---|---|---|
| 12 | (61,29) | (60,34) | (60,44) |
| 16 | (60,31) | (60,34) | (60,43) |
| 20 | **(59,33)** | **(61,34)** | **(59,43)** |
| 24 | (60,34) | **(62,31)** | (59,39) |
| 28 | (60,34) | (61,28) | (60,38) |
| 32 | (60,34) | (60,28) | (60,38) |

⭐ **它們走出那一欄（X 59／61／62）再走回來。** 不是穿過去，是繞過去。

## 3. remake 為什麼不繞

`FindPathForcing` 用的是純先進先出佇列，而且**一碰到終點就收工**。
在那個順序下，直線一定比繞路先碰到終點——於是「有兵的格子 +8」
這個成本從來沒有影響過任何一條路。

原版是**波數佇列**：成本還沒被波數追過的格子會被推回佇列
（`loc_1BE00` 的 `cmp dx,[bx] / ja`），有兵的格子等於多躺八波。
細節與機器碼在 [`../spec/134`](../spec/134-pathfind-wave-order.md)。

## 5. 為 dosgolem 加的兩個動詞

| 動詞 | 做什麼 |
|---|---|
| `ticks:N` | **以戰術節拍為單位**推進 N 拍（讀 `cs:word_1D318`）。一拍不是固定指令數，`steps:` 只能估 |
| `units:側/隊` | 只印那一隊的八個兵，逐拍取樣時輸出才看得完 |
