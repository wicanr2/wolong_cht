## 發現與修正

從軍團選單進行軍清單，選夏侯惇，再在地圖選陝。dosgolem 的戰鬥指揮與委任
分支都回到軍團清單，右鍵離開清單後回地圖。v.1.0.7 只留下軍團情報面板，
系統／存檔點擊被獨佔輸入的面板擋住。原版證據在
`workplace/march-restart-20260908/original-command/` 與 `original-return/`；
修正前 AppImage 在 `app/`。

最初只看 sub_17F90 返回而推斷地圖入口沒有父清單，這是錯誤：規格 151 的
sub_11E46 呼叫迴圈及 `direct-original/` 正常重播，證明地圖入口也先開
「該格上的軍團」清單。保留此訂正；v.1.0.8 候選包不能作為完成收據。
以上位址都是既有 IDA dosv 線性位址的索引，沒有另做推測性改名或跳入執行。

規格增補 READY 後，桌面以 marchReturn 保存呼叫入口。下令或取消目的地後回到
原父清單；最後退出清單時一併關掉情報面板。地圖入口保留該格的篩選範圍，
不改開全軍清單。面板只是流程背景時，也不再顯示誤導的 ESC 關閉提示。
指揮方式選單右鍵回目的地的規則保留。

## 正常操作結果

正式 AppImage 從首頁載入，僅用滑鼠選單、選列、地圖點選、右鍵與等待。
未使用 direct-entry、旗標編軍、座標注入或改寫存檔 fixture。
原版 tile 控制器只透過滑鼠移動定位；彈出選單依 re/84 的 100–131 帶狀輸入操作，
不能把驅動座標當成 AppImage 視窗座標。

| 路徑 | 結果與收據 |
|---|---|
| 指令列 → 全軍清單 → 下令 | 回全軍清單；右鍵退出後可開系統。verification/march/ |
| 地圖 → 該格軍團清單 → 下令 | 回該格清單；右鍵退出後可開系統。verification/direct/ |
| 兩種返回畫面 | 軍團情報矩形各 0 px；清單矩形各 95 px 差異。verification/return-diff.json |
| 行軍中存第二槽 | 夏侯惇由許昌 (206,114) 移至 (198,114)，剩 28 個路線座標，目的地陝 (187,107)。 |
| 新程序首頁讀第二槽，再存第三槽 | 位置、目標、指揮模式與 28 個剩餘路線座標完整保留。verification/reload/ |
| 再開新程序讀第三槽並繼續運行 | 抵達陝 (187,107)，剩餘路線清空，再由正常選單存第四槽。verification/arrival/ |

verification 指 `dist-all/v.1.0.9-20260908/verification/`。軍團索引 39，
目的地據點索引 73；不是把存檔手改到路上，而是正常下令及世界更新產生。
先前 v.1.0.7 的試驗只證明「已下令但尚未移動」的 36 點路線保存，
收據 `workplace/march-restart-20260908/restart-check.json` 不替代本輪行軍中驗證。

短按腳本曾漏掉系統選單點擊，已改為單次按下、150 ms 後放開再乾淨重跑。
v.1.0.8 的 6 秒等待已走到目的地，不能證明行軍中恢復；正式收據改在仍有路線時儲存，
再分開驗證重啟與抵達。這兩項是驗證方法訂正，不是存檔資料修補。

## 邊界與後續

本輪證明行軍流程返回、原生路線保存與重啟後繼續移動，不宣稱兩端同時鐘／同亂數，
也未把整張背景畫面或行軍速度當成完全相同。清單 95 px 差異仍保留量測結果，
不將未逐點歸因的差異直接歸零。

Windows／macOS 只完成交叉建置與封包查核，原生操作待驗；已詢問可用測試環境。
地圖捲動、戰後返回及實體短按延遲仍是後續驗收項目。
