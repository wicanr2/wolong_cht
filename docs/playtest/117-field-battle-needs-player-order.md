# 117 — 野戰打不完的成因是 fixture 缺了玩家命令，不是規則層回歸

**狀態：通過。** `TestFieldBattleTerminates` 補上「單挑結束後玩家下命令」
之後，第 **339** 幀結束、勝方側 0。原本的「8000 幀 600 對 600」是
**正確的原版行為**——玩家不下令，玩家那一側就站在陣形線上不動。

- 日期：2026-09-09
- 領域事實（使用者提供）：進入野戰與攻城、單挑結束之後，**命令由玩家下達**；
  **除非「突擊」，大將不會主動出擊**。野戰的單挑**依武將個性自動觸發**。
- 程式碼佐證：`internal/state/tactical.go` 對玩家那一側只下
  `tactical.Form`（「原版的兵站在陣形線上等玩家下令」）；
  `internal/rules/tactical/tactical.go` 的命令表寫著
  `Attack = 1 // 攻擊：大將以外的兵攻擊`、`Charge = 2 // 突擊`

## 1. 三個場景

同一份 fixture（`workplace/parity/SAVE-FIELD.DAT`，玩家＝守方）：

| 玩家的動作 | 結果 |
|---|---|
| 不下命令 | 8000 幀不結束，剩 600／600 |
| 單挑後下**攻擊** | **339 幀結束**，勝方側 0，剩 600／159 |
| 單挑後下**突擊** | 339 幀結束，剩 600／159 |

## 2. 為什麼舊的寫法會通過

HEAD 版本這一場是 309 幀結束的，但逐幀對照顯示結束的方式是
**玩家側的大將自己走到戰場中央（28,32）被打到 HP 18 而退卻**——
玩家沒有下過任何命令，那一步不該發生。測試原本的註解已經指出
「只因 AI 比較方向錯誤、誤下退卻才通過」。

⭐ **所以這是一個「錯誤的理由得到正確的結果，然後通過檢查」的案例**
（`CLAUDE.md` §7 第 18 條）。修掉那個缺陷之後，測試露出來的不是新的回歸，
是它本來就沒有在測「野戰會不會打完」。

## 3. 排除過的原因

逐項在 worktree 上二分（不動工作區），都**不是**成因：

| 候選 | 結果 |
|---|---|
| `combat.go` 委任戰力混合（[`../spec/158`](../spec/158-delegated-leader-mix.md)）| 通過 |
| `duel.go` 單挑位依玩家側（[`../spec/80`](../spec/80-duel-opening.md)）| 通過 |
| 碰撞格表擋路（把 `at()` 改成永遠回 −1）| 仍不結束 |
| `doFormation` 的隊長／隊員分支（[`../spec/159`](../spec/159-tactical-command-movement-order.md)）| 仍不結束 |
| 命令／移動批次分離（同上）| 仍不結束 |

## 4. 未解

| 項目 | 現況 |
|---|---|
| **野戰單挑的觸發判定** | 原版依武將個性自動觸發，`Tactic`（武將 `+0x16`）同時也選 `BATTLE.DAT` 的腳本段。remake 還沒解觸發條件，fixture 是無條件武裝單挑 |
| AI 側腳本在這一場下了什麼命令 | 只觀察到開場的 `Form`；腳本後續有沒有下攻擊還沒逐指令追 |
| 攻擊與突擊在這一場結果相同 | 兩者都是 339 幀、600／159。大將出不出擊的差異在這個局面看不出來，要另找場景 |
