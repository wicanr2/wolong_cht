# 70 — 戰術指令真的下得下去，而開場對白在第 50 個 tick 才出現

**狀態：通過。** 用 dosgolem 的快照分岔，在同一個局面上分五支跑三千萬道指令：
**突擊／攻擊改變兵的走位、退却直接結束戰鬥、守陣與不下令逐像素幾乎相同、
只選部隊不下令什麼都不改**。同一輪量到戰術節拍是
**每 tick 約 333,000 道指令**，而**開場對白在第 50 個 tick 才出現**——
在那之前兩軍幾乎不動。

- 日期：2026-09-05
- 出處：[`../re/60`](../re/60-tactical-sidebar.md) §6（六個指令的熱區與命令碼）、
  [`../spec/60`](../spec/60-battle-talk-duration.md)（對白 60 tick 到期）
- dosgolem 側：`workplace/dosgolem/tac3/`、`tac4/`
- 分區：[`../spec/91`](../spec/91-tactical-parity.md) §2

## 1. 怎麼做的

走到戰場要 **4.57 億道指令**，所以 `save:b` 之後每一支分支
`restore:b` 回同一個起點，各花三千五百萬。
⭐ **基準那一支也要燒掉一次點擊的指令數**（`tap` 固定 4,200,000），
否則「差別」裡混著時間。

## 2. 六個指令的效果

與「什麼都不做」跑同樣久的那一張逐區比：

| 分支 | `field` | 其他 | 判讀 |
|---|---:|---|---|
| **突擊** | 3,254 px | `bottom` 834 | 兵的走位變了 |
| **攻擊** | 2,346 px | `bottom` 930 | 變了，而且與突擊不同 |
| **退却** | **155,472 px** | 九區全變 | ⭐ **戰鬥結束，離開戰術畫面** |
| **守陣** | 95 px | `bottom` 1,002 | 與不下令**幾乎逐像素相同** |
| 只選部隊不下令 | 95 px | `bottom` 446 | 只有選取框，行為不變 |

⭐ **「守陣」與「不下令」跑三千萬道指令之後只差 95 px**（那 95 px 是游標），
所以**開場的預設狀態就是守陣**。`bottom` 那一千個像素是六格的命令圖示——
指令有寫進去，只是兵的行為沒變。

⭐ **退却那一支把整條鏈跑完了**：戰鬥結束 → 許昌陷落 → 回到大地圖，
荀彧跳出來說「首都被攻陷了！儘速遷都到洛陽　。」
一次驗到戰術結算、據點易手與遷都建議三件事。

## 3. 節拍與開場對白

每兩百萬道指令讀一次 `cs:word_1D318`（戰術節拍計數器）：

| 進場後 | 節拍 |
|---:|---:|
| +0.5M／+2.5M | 0 |
| +4.5M | 2 |
| +6.5M | 8 |
| +8.5M | 14 |
| … | 每 200 萬道指令 **＋6** |
| +28.5M | 80 |

⇒ **一個戰術 tick ≈ 333,000 道指令**，而且開頭有約 300 萬道指令的
建場期（節拍還沒開始跳）。

到期時刻讀 `cs:word_1D322`／`word_1D324`（[`../spec/60`](../spec/60-battle-talk-duration.md)：
顯示時寫「目前節拍 ＋ 60」）：

| 取樣 | `word_1D322`（側 0）| `word_1D324`（側 1）|
|---|---|---|
| 進場 … 節拍 50 | `FFFF`（沒有）| `FFFF` |
| 節拍 80 | `0x7F` ＝ 127 | `0x6E` ＝ 110 |

倒推顯示時刻：**側 1 在節拍 50、側 0 在節拍 67**。

⚠ **前 45 個節拍兩軍幾乎不動**（`field` 只差 209 px）。
所以「剛進戰場」不是一個取樣點，是**兩個**：

| 取樣點 | 畫面 |
|---|---|
| 節拍 0–45 | 雙方在出發線上，**沒有對白框** |
| 節拍 50 起 | 呂布的挑釁對白，接著才開始動 |

⇒ 對拍要指定的是**節拍數**，不是「開場」。

## 4. 順帶：行軍三選一的原版版面量出來了

同一輪的另一支分支把游標指到**許昌自己**（玩家首都）再按下去，
於是第三項「解體」出現——與 [`../re/45`](../re/45-corps-command-mode.md) §1 的
`cmp [bx+3], [bp+0]` 對上，這是**第二個沒有預先安排的正對照**
（第一個是指到宛時只有兩項）。

兩張擷取相減量出框：

| 項目數 | 框 |
|---:|---|
| 2 | `(320, 160, 112, 48)` |
| 3 | `(320, 160, 112, 64)` |

框的左上角**就是游標所在的 16 px 格**，大小是 `112 × (項目數+1)×16`——
而 `sub_1804E` 的兩個夾制值（欄 ≤ 33、列 ≤ 24 − 項目數）把這件事
自己證完了（[`../spec/39`](../spec/39-march-order-menu.md) §3.6）。

⚠ **remake 這一段還是自己的版面**：選單固定在 `(168,128)`，
而且把訊息 #21 併進選單框當標題——原版的訊息走**左下角的 TALK 訊息窗**，
與選單是兩個獨立視窗。兩項差異都記在 `spec/39` §3.6 與 §4。
