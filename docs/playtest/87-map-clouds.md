# 87 — 大地圖上會飄的雲：原版一直有，remake 一朵都沒畫

**狀態：通過。** 追一片「原版有、remake 沒有」的灰白網點，追出兩件事：
大地圖上**常駐 16 朵會飄的雲**（`MMAP.MCH` 物件 type 0，16×9 格，
座標存在劇本與存檔裡），以及**物件型別查表整體差一格**——
所以 remake 先前把火災畫成雲的圖形。接上之後，用專案自己的解碼器
合成的畫面與原版差 **358 px**（只剩據點與軍團標記）。

- 日期：2026-09-06
- 規格：[`../spec/146`](../spec/146-map-cloud-objects.md)
- 起點：[`86`](86-general-faction-cells-parity.md) §4 的殘差

## 1. 怎麼追到的

| 步驟 | 觀察 | 排除了什麼 |
|---|---|---|
| 逐點比原版與 remake | 只有奇數列不同 | 不是換圖塊，像一層 50% 網點 |
| 不開任何視窗、純捲動到同一處 | 還在 | 不是視窗殘影 |
| 256 塊圖磚 × 4 個 bank 逐塊比對那 16×16 | 沒有一塊對得上 | 不是圖塊，也不是季節調色盤 |
| `RenderWorld(bank 0)` 逐點比兩張畫面 | 與 remake 差 346、與原版差 11,712 | **remake 忠於檔案，原版多畫了一層** |
| 差異落在哪些格 | (271–283, 160–168) | 一塊方形 |
| 跑到 196/5/6 再拍同一處 | **整片消失** | 是暫時的 |
| `ipeek:10D22:8`（暴風雨矩形）| `F0 FF F0 FF 90 01 90 01` | ⭐ **那是「沒有暴風雨」的預設值** |
| `peek:2754:2140:256`（物件表後半）| 16 筆全部啟用、`+0x0E = 0` | 是 **type 0** 物件 |

⭐ **「跑到 5/6 消失」差一點把我帶去暴風雨。** 一開始的假說是
「原版把暴風雨的 11×11 格填成網點」，而那塊區域的中心剛好落在
據點 126 (278,164)，看起來完全吻合。**推翻它的是矩形本身**——
`word_10D22`–`10D28` 讀出來是重設值，根本沒有暴風雨在跑。
巧合的中心其實是**一朵雲剛好飄到那裡**。

## 2. 那 16 朵雲

物件表在段內 `0x2040`、32 筆 × 16 B。**後 16 筆是雲**，永遠啟用，
而且**存在劇本與存檔區塊裡**（區塊位移 `0x21C0`）——不是執行期生成的。

196/4/21 8 時那一刻，16 筆裡只有一筆落在鏡頭 (271,153) 的畫面內：

```
80 00 15 01 A4 00 00 00 0A 02 F2 00 0E 10 00 00
        └ X=277        └ Y=164              └ type 0、相位 0
```

用專案自己的解碼器把 pattern `0x18` 疊到同一片地形上、中心格 (277,164)：

| | 與原版不同的像素 |
|---|---:|
| 只畫地形 | 11,712 |
| **地形 ＋ 那朵雲** | **358** |

剩下的 358 是 `RenderWorld` 不畫的據點與軍團標記（空白對照是 346）。
**位置、尺寸、置中、mask 一次全對。**

## 3. 型別表差一格

`sub_12533` 的 `bx = type × 8 + 相位`，`bx = 0` 就是 `cs:985Ah`，
所以那八個 byte 是 **type 0**。[`../re/14`](../re/14-mmap-mch-objects.md) §4
初版標成 type 1，`ObjectPatternIndex` 因此寫成 `(objectType-1)*8+frame`：

| | 原版 | remake（修正前）|
|---|---|---|
| type 0（雲）| `0x18`–`0x1C`，16×9 | 查不到 |
| type 1（火災）| `0x20`–`0x23`，5×5 | `0x18`–`0x1C`，**16×9** |
| type 2（暴動）| `0x28`–`0x2B`，5×5 | `0x20`–`0x23` |

⚠ **火災的圖形會跟著換**（5×5 而不是 16×9）——那是修正不是回歸。

## 4. remake 接上之後

`-cam 118,138 -shot-frames 1`（載入當下、雲還在檔案裡那個位置），
與離線合成的「地形 ＋ 16 朵雲」逐點比：

| | 與 remake 第 1 幀不同的像素 |
|---|---:|
| 只畫地形（別的鏡頭當負對照）| 95,472 |
| **地形 ＋ 雲** | **72** |

那 72 是據點與軍團標記。**載入 → 座標 → 置中 → 圖形 → 季節調色盤 → 鏡頭，
整條管線一次驗完。**

### 原版對 remake：四區 0 px、`map` 71 px

真正的兩邊對拍也做了。原版載入後只跑 17,600,000 道指令就拍
（`wait;click:320,200;click:300,151;steps:200000;origin;shot`，鏡頭 (186,102)、
196/4/16 14 時），remake 同一份存檔、同鏡頭、`-shot-frames 1`：

| 區 | 不同像素 | |
|---|---:|---|
| `banner` | **0** | |
| `command` | **0** | |
| `map` | **71** | 0.05%——原版那 17.6M 道指令裡雲已經漂了 ±1 格 |
| `minimap` | **0** | |
| `faction` | **0** | |

peek 出來的位移正好對得上：slot 16 的 X 由 −13 變 −14、slot 17 由 140 變 141、
slot 18 由 126 變 125，相位由 0 走到 2。**71 px 就是這幾格的差。**

## 5. ⚠ 同時鐘的對拍會**變差**，那是預期的

雲每次移動要抽兩個亂數（`sub_124FF`），與整條亂數流共用。
兩邊載入時位置相同，**跑久了必然分開**——分開之後同一張畫面上會出現
「原版的雲」與「remake 的雲」兩片，殘差因此**加倍**：

| 鏡頭 (271,153)、196/4/21 8 時 | `map` 不同像素 |
|---|---:|
| remake 沒有雲時 | 11,420 |
| remake 有雲、但位置各自漂 | 22,210 |

**這不是回歸。** 要在同一時刻比雲，得先解出原版亂數流的全部消費端；
在那之前，含雲的畫面只能在**載入當下**逐像素比。
