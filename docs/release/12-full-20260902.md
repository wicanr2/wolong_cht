## 4. ⭐ 出貨的那一顆 AppImage 自己驗過，不是靠推論

[`../playtest/57`](../playtest/57-appimage-20260902-reverify.md) 對拍用的是重打包流程
（`tools/release_appimage.sh`）產出的中途版本，那一顆已經被本批取代。
所以**拿現在 `dist-all` 裡這一顆重跑一次**，三個關卡的數字沒有變：

| 關卡 | rect | 結果 |
|---|---|---:|
| 勢力清單本體 | `152,104,368,160` | 0 / 58,880 PASS |
| 君主卡 | `160,112,240,192` | 0 / 46,080 PASS |
| 指令列 | `0,32,432,32` | 0 / 13,824 PASS |

包裡的 `usr/bin/wlgame` SHA-256 是
`cb9b2a6937406d906e882f91ada04ab3232158196a7a87b2bf566129a3871698`，
**與 `verification/BUILD-ABI.md` 記的 linux-amd64 執行檔、以及對拍時那一顆完全相同**。

⚠ **AppImage 的外層雜湊會變，裡面的執行檔不會。** squashfs 帶時間戳，
同一份輸入重打兩次得到不同的 AppImage 雜湊——所以「這顆包驗過沒有」要看
**裡面那支執行檔**的雜湊，不是看包的雜湊。這一條在下一次重打包時仍然成立。

## 5. 舊批次怎麼消失的

`release_all.sh` 最後一步 `promote` 把 `dist-all` 更名成 `.dist-all.previous`、
再把 `dist-all.staging` 更名成 `dist-all`，成功之後 `rmtree` 掉備份。
所以 `20260830` 的六個產物是**被整批替換**，不是逐檔刪除——
中途任何一步失敗都會把備份換回來。

⛔ 這一批與上一批一樣**不可外流**：四個桌面包與 APK 裡都內嵌了原版資料
與倚天字型。要交付給別人的版本得另外建：

```sh
WOLONG_BUNDLE_DATA=0 tools/android_build.sh
WOLONG_BUNDLE_DATA=0 WOLONG_RELEASE_STAGING=$PWD/dist-public.staging \
  tools/release_all.sh 20260902
```

`dist-public/` 目前仍是 `20260830` 那一批（GitHub Release `v20260830` 用的就是它），
**這一輪沒有重建可散布批次，也沒有動 GitHub Release**。
