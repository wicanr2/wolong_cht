## 4. ⛔ 這一批修掉的兩個發行流程問題

**一、批次號會因為容器時區而不一致。**
`release_all_fs.py` 的 APK 檔名取自檔案 mtime（刻意如此——APK 是另一條
管線建的，重打包未必重建），而容器預設 UTC。台北時間 09-06 早上七點建的
APK 因此被戳成 `20260905`，同一批裡五個檔是 `20260906`、APK 是 `20260905`。

⭐ **最貴的地方是檔案內容完全正確**，只有名字在說謊——逐檔比雜湊也發現不了。
修法是把主機時區傳進容器（`tools/py.sh`、`tools/release_all.sh`、
`tools/release_smoke.sh` 都加 `-e TZ`）。

**二、發行閘寫在註解裡，但沒有跑。**
`release_all.sh` 的註解說「staging 完成編譯、封裝、雜湊與 deny-list 後才
交換到正式目錄」，而腳本裡**沒有任何一行跑 deny-list**。

而且就算跑了也擋不住：**deny-list 看不進 tar.gz／AppImage／APK**。
對著 `dist-all` 掃會印「掃了 19 個檔、通過：沒有原版資產」——
而那六個包裡塞滿原版資產。把同一個包解開再掃，它**立刻擋下來**
（`gamedata/TALK.DAT`、`YNSOUND.COM`、`STR.EXE`…）。

三處都修了：

| 修 | 怎麼修 |
|---|---|
| 閘沒跑 | `release_all.sh` 在**打包之前**跑 deny-list 掃 staging 樹 |
| 完整版會被擋 | 只對 `WOLONG_BUNDLE_DATA=0` 跑，**跳過時在 log 明講**——否則「沒跑」與「跑了沒中」長得一樣 |
| 掃錯地方看不出來 | `denylist.py` 遇到目錄裡有封裝檔就印一行「有 N 個封裝檔，沒有掃進去」|

## 5. 可散布批次 `dist-public`：那道閘實跑過了

同一天用 `WOLONG_BUNDLE_DATA=0` 建了一批 `dist-public`
（不含原版資產，六個包從約 30 MB 掉到約 10 MB），
**新接上的閘在那條路徑上真的攔過東西**：

| 事件 | 結果 |
|---|---|
| 第一次建：APK 還是內嵌版 | ⛔ **擋下來**：「可散布批次收到一顆內嵌原版資料的 APK（106 個檔，例如 `assets/gamedata/audio/bgm-0.ogg`）」|
| 重建乾淨 APK 後再建 | ✅ deny-list 掃 `.work/stage` 的 35 個檔，通過 |
| 抽驗：解開 linux 包 | ✅ 只有四支執行檔 ＋ `translations` ＋ `LICENSE` ＋ `README-RELEASE.md` |
| 反向：完整版 `refresh` 收到乾淨 APK | ⛔ **擋下來**：「完整版批次收到一顆**沒有**內嵌原版資料的 APK」|

⚠ **兩條管線寫同一個路徑。** `tools/android_build.sh` 的內嵌與否由它自己的
`WOLONG_BUNDLE_DATA` 決定，而它每次都覆蓋
`android/app/build/outputs/apk/debug/app-debug.apk`——建了乾淨版就蓋掉內嵌版。
所以 `check_apk_matches_batch` **兩個方向都擋**，不是只擋外洩那一邊。

⚠ APK 的建置**不可重現**（zip 裡有時間戳），重建之後雜湊必然改變。
上表的 APK 雜湊是最後一次重建後、`refresh` 對齊過的值。

## 6. ⛔ 那道閘自己也踩了一次「掃了等於沒掃」

第一版把 deny-list 放在 `finalise` 之後，因為 APK 是那一步才複製進來的。
結果它印：

```
deny-list：掃了 14 個檔（dist-public.staging）
通過：沒有原版資產
```

**14 個檔是最上層那幾個。** `finalise` 結尾會 `rmtree(.work)`，
攤開的平台目錄早就被清掉了——**一道什麼都沒檢查的閘，輸出跟通過一模一樣**。

兩處都修了：

- 閘移回 `finalise` **之前**，明確指向 `.work/stage`（掃到 35 個檔）；
  APK 改由 `check_apk_matches_batch` 讀 zip 目錄擋，不靠 deny-list。
- `denylist.py` 現在**掃不到東西就回非零**：目標不存在、或掃了 0 個檔，
  都印「這不是通過，是掃錯地方」。
