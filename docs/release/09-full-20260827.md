## 4. 建置映像要能從 repo 重建

打包前 `wolong-go-android:20260820`、`wolong-android-emulator:20260820`、
`wolong-osxcross-go:20260811-event10-r4` 三顆都不在機器上——**使用者清掉的**
（這台機器同時放著多個專案的映像，清理是常態）。基底映像
（`rich2-go-android:20260809`、`u5cht/osxcross:latest`、`golang:1.25-bookworm`）
都還在，所以三顆都重建得回來：

```sh
docker build --network host -t wolong-go-android:20260820 docker/android
docker build --network host -t wolong-android-emulator:20260820 - < tools/android-emulator.Dockerfile
docker build -q -t wolong-go:20260809 docker/go            # osxcross 的 Go 來源
docker build --network=none -t wolong-osxcross-go:20260811-event10-r4 \
    -f docker/osxcross-go/Dockerfile docker/osxcross-go
```

⚠ 三顆的重建成本差很多：`wolong-go-android` 只要重下 Go 1.25.12（約 80 MB）
＋ ebitenmobile，`wolong-osxcross-go` 幾乎只是 COPY，而
**`wolong-android-emulator` 要重下 `android-34;google_apis;x86_64` 的
system image（重建後 13.7 GB）**。前兩顆隨手重建沒關係，第三顆要先問值不值得。

> **教訓寫成規則**：**建置映像要能從 repo 裡的 Dockerfile 重建，不能只存在於機器上。**
> 映像被清掉是常態，重建不了才是問題。三顆裡有一顆
> （`wolong-osxcross-go`）的 Dockerfile 寫著 `FROM wolong-go:20260809`，
> 而那個 tag 也是本機映像——**指向另一顆本機映像的 Dockerfile，
> 鏈上任何一環被清掉就重建不了**。這次能救回來是因為 `docker/go` 建出來的
> Go 版本剛好還是 1.25.12，不是因為鏈是完整的。
