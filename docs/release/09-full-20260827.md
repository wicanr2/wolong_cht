## 4. 建置映像要能從 repo 重建

打包前 `wolong-go-android:20260820`、`wolong-android-emulator:20260820`、
`wolong-osxcross-go:20260811-event10-r4` 三顆都不在機器上——**使用者清掉的**
（這台機器同時放著多個專案的映像，清理是常態）。基底映像
（`rich2-go-android:20260809`、`u5cht/osxcross:latest`、`golang:1.25-bookworm`）
都還在，所以三顆都重建得回來：

```sh
docker build --network host -t wolong-go-android:20260820 docker/android
docker build --network host -t wolong-android-emulator:20260820 - < tools/android-emulator.Dockerfile
docker build -t wolong-osxcross-go:20260827 -f docker/osxcross-go/Dockerfile docker/osxcross-go
```

⚠ 三顆的重建成本差很多：`wolong-go-android` 只要重下 Go 1.25.12（約 80 MB）
＋ ebitenmobile，`wolong-osxcross-go` 幾乎只是 COPY，而
**`wolong-android-emulator` 要重下 `android-34;google_apis;x86_64` 的
system image（重建後 13.7 GB）**。前兩顆隨手重建沒關係，第三顆要先問值不值得。

### 4.1 macOS 那一顆的 `FROM` 換成公開映像

`docker/osxcross-go/Dockerfile` 原本第一層是 `FROM wolong-go:20260809`
——只存在於本機的映像。那顆被清掉之後，這一份就建不起來，
**而發行流程要跑到 macOS 那一段才會發現**。

改成釘死的公開 tag `golang:1.25.12-bookworm`，兩層 `FROM` 都能從零取得。
`tools/release_all.sh` 的 `MAC_IMAGE` 預設同步改成 `wolong-osxcross-go:20260827`。

原本那一份的註解寫著「直接用通用 Go image 交叉重建 darwin 標準庫
會得到重複宣告」。**量過之後不成立**：同一份工作區、同一組旗標，
新舊兩顆映像各建一次，四支執行檔逐位元組相同。

| 執行檔 | 舊映像與新映像 |
|---|---|
| `darwin-amd64/wlgame` | `27c416109af9e89c8d4ef37f8cc3a73acbfa8826c7baea56ba2def694736eb21`（相同）|
| `darwin-arm64/wlgame` | `375c48b277f84752a1ebfdcb08d2cfff1bb761a863ee7bb893c674bf9e6ef35a`（相同）|
| `darwin-amd64/wlsim` | `bbec23ad087d9183db1ce66fdfce225ad84c0622330a143e3b4d56c44f39ac79`（相同）|
| `darwin-arm64/wlsim` | `5281592d5477a66f2dc9366040e2e88dac69d6d8eff909d60537b35c245ebcef`（相同）|

（前兩列與後兩列取自兩次不同時點的比對，所以工作區狀態不同、
兩組雜湊不互通；每一列自己「舊 ＝ 新」才是判準。）

⭐ 換基底本身**不改變輸出**。真正改變 macOS 執行檔的是下一節。

> **教訓寫成規則**：**建置映像要能從 repo 裡的 Dockerfile 重建，不能只存在於機器上。**
> 映像被清掉是常態，重建不了才是問題。`FROM` 指向另一顆本機映像的 Dockerfile，
> 鏈上任何一環被清掉就整條建不起來——而**那個「不能換基底」的理由本身沒有被驗過**。
> 一句沒有證據的註解會讓人不去質疑它，壞掉的相依鏈就一直留著。

### 4.2 只有 macOS 的執行檔帶著 VCS 戳記

量到的：第一次打出來的 `darwin-amd64/wlsim` 記著
`vcs.revision=9b462f7a…` 與 **`vcs.modified=true`**，而 Linux 的同一支是
`(devel)`、沒有戳記。成因是 `docker/go` 有 `ENV GOFLAGS=-buildvcs=false`，
而 osxcross 那一顆**只 COPY GOROOT，不繼承環境變數**。

後果不是美觀問題：**macOS 執行檔的雜湊會跟著工作區乾不乾淨而變**，
同一個 commit 也重現不出來。osxcross 的 Dockerfile 補上
`GOFLAGS=-buildvcs=false` 之後，四個平台一致。

重打驗過的兩件事：

- 新的 `darwin-amd64/wlsim` 只剩 `mod … (devel)`，沒有任何 `vcs.*`。
- **Linux 的執行檔逐位元組沒變**（`wlsim` 前後都是 `74508e5f…`）
  ⇒ 這一次只有 macOS 端改變。tarball 的雜湊全變是打包時間戳造成的，
  不是內容變了。

⚠ 所以 §2 的雜湊表是**重打之後**的。APK 沒有重建（內容未變），
雜湊與重打前相同。
