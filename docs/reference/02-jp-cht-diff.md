# 02 — 日中對照：`TALK.DAT` 第一批發現

**狀態：全量 1,022 則的**變數標記**對照已做完（12 則不一致，見 §9）；
文意層面的全量對照未做。**

- 日期：2026-08-07
- 輸入：`translations/extract/talk-dosv.json`（cp950）、`talk-pc98.json`（cp932）
- 方法：兩版索引一一對應（各 1,022 則），逐則比對變數標記與內容
- 推論等級：標在每一項

## 1. 為什麼這條線這麼便宜

PC-98 日文原版與松崗繁中版的 `TALK.DAT` **索引完全一一對應**——
同一個索引就是同一則訊息的兩種語言。**不需要做句子對齊**，
`talkdat.py diff` 直接就能跑出差異。

這是 §3.10（`CLAUDE.md`）「23 檔 byte-for-byte 相同」那條發現的延伸：
松崗版是移植不是重寫，連訊息表的槽位順序都照搬。

## 2. 變數標記不一致的 12 則（confirmed 有差異）

`talkdat.py diff` 跑出來 1,022 則裡有 12 則的變數標記集合不同。
**每一則都是實質的翻譯缺陷**，不是排版差異。

### 2.1 中文漏掉變數，台詞變成沒有主詞（6 則）

`#718`、`#720`、`#721`、`#723`、`#724`、`#751`

```
日  まだまだこれからだっ ／ {1}覚悟！！！！
中  才剛要開始呢！覺悟吧 ／ ！！！！
```

日文是「{武將名}，覺悟吧！」，中文把名字整個丟掉。
戰場上五則不同武將的台詞因此變成同一句。

`#751`：

```
日  {6}なんの！ ／ これしきのことで参る ／ {1}では無いわ！
中  {6}沒什麼！我可不會這樣 ／ 就輸的！
```

日文是「我{1}可不是這種程度就會倒下的人」，中文同樣丟掉了名字。

### 2.2 中文漏掉勢力／據點名（3 則）

| 則 | 日文 | 中文 |
|---|---|---|
| `#290` | それでは引続き**{2}**の内政を行います。 | 那麼我就繼續進行內政了。 |
| `#195` | うむ、今ならば**{3}**も断りはしまい。 | 事到如今，不答應也不行了 |
| `#321` | **{6}**外交資金が底を尽きました。金{6}{7}程掛かりそうなのですが | 外交資金以用完了，大約需要金額{6}{7}左右。 |

`#321` 的中文還有一個錯字：「以用完了」應為「已用完了」。

### 2.3 變數編號被換掉（1 則）

`#223`：日文用 `{4}`，中文用 `{3}`。

```
日  それは明案だ！{4}殿ならばきっと協力してくれるに違いない
中  這是好提案！{3}大人必定會出力協助。
```

**這一則要特別驗。** 如果 `{3}` 與 `{4}` 指的不是同一個東西，
中文版在這裡會顯示錯誤的名字。變數語意還沒解（`docs/formats/01` §7），
先掛著。

### 2.4 中文多出變數 / 內容被搬走（2 則）

`#192`、`#322`。`#192` 見下一節。

## 5. 已排除的誤判

### `#225` 不是錯字

第一版用 Python 的 `big5` 解碼，`#225` 出現 `這哪<f9>堿O什麼好策略？`，
看起來像松崗版打錯字。實際上 `F9D8` 是 Big5 罕用字區的**「裏」**，
原文是「這哪裏是什麼好策略？」，完全正確。

**錯的是解碼器不是原版。** 改用 `cp950` 之後正常。
細節見 `docs/formats/01` §4。

## 9. ⭐ 全量對照：變數標記（2026-08-08）

先前的 15 則是**手工**找出來的。變數標記這一項可以機械化——
它不需要懂日文，只要比「兩版用到的 `{n}` 集合一不一樣」：

```
python3 tools/talkdat.py diff \
    workplace/orig/pc98/TALK.DAT shift_jis \
    workplace/orig/dosv/TALK.DAT cp950
```

**1,022 則全掃，12 則不一致。** 分成三類：

### ① 漏掉變數（6 則）——會顯示成缺主詞的句子

| # | 日文 | 繁中 | 漏掉 |
|---|---|---|---|
| 290 | 引続き**{2}**の内政を行います | 那麼我就繼續進行內政了 | `{2}`（據點名） |
| 718, 720, 721, 723, 724 | **{1}**覚悟！！！！ | 才剛要開始呢！覺悟吧！！！！ | `{1}`（武將名） |

⚠ 718/720/721/723/724 **五則內容完全相同**——那是同一句台詞的五個槽位
（不同戰況各一份）。松崗五則都漏了同一個變數，**是系統性的，不是筆誤**。

### ② 變數換號（2 則）——會插進錯的名字

| # | 日文 | 繁中 |
|---|---|---|
| 223 | **{4}**殿ならばきっと協力してくれる | 這是好提案！**{3}**大人必定會出力協助 |
| 322 | 金**{6}{7}**程かかりますが | 約需金額**{7}**左右 |

322 同時是換號與漏字：日文的金額是 `{6}{7}` 兩段，繁中只留 `{7}`。
321 是同一組訊息的另一則，漏的是開頭的 `{6}`。

### ③ ⚠ 兩則根本不是同一句（192、195）

| # | 日文 | 繁中 |
|---|---|---|
| 192 | 他国と交戦中？そのような報告は入っておらぬぞ！ | 現在停戰的話，就能賣個人情給{3}吧，好，准許停戰 |
| 195 | うむ、今ならば{3}も断りはしまい。よし停戦を許可する！ | 事到如今，不答應也不行了，停戰就停戰吧！ |

**錯位只發生在 `#192`–`#195`，到 `#196` 自己接回去**——不是整段偏移。
把 `#188`–`#199` 兩版並排就看得出來：

| # | 日文 | 繁中 |
|---|---|---|
| 190 | 他国と交戦中？ | 正和他國交戰？ ✅ |
| 191 | 他国と交戦中だと？ | 你說正和他國交戰？ ✅ |
| **192** | 他国と交戦中？（**第三份**） | **現在停戰的話…**（＝ 日文 193） |
| 193 | 今、停戦すれば{3}に借りを作れる | 嗯，現在的話，{3}也不至於拒絕（＝ 日文 195） |
| 194 | 同上 | 同上 |
| **195** | うむ、今ならば{3}も断りはしまい | 事到如今，不答應也不行了（**沒有對應的日文**） |
| 196 | 他国と交戦中ならば… | 若是正在和他國交戰的話… ✅ 接回去了 |

### 原因：兩版的**重複槽位數不同**

日文這一段是「同一句話放好幾份」的結構（不同狀況各一份）：

```
日文：交戰 ×3（190,191,192）　停戰A ×2（193,194）　停戰B ×1（195）
繁中：交戰 ×2（190,191）　　　停戰A ×1（192）　　　停戰B ×2（193,194）＋1（195）
```

**松崗把重複的份數重新分配了**（3+2+1 → 2+1+2+1），
於是從 `#192` 起錯開一格，到重複結束的 `#196` 自然對回。

### ⚠ 這是實質缺陷，不是風格差異

遊戲是**按槽位編號取訊息**的。所以在「對方正與他國交戰」那個狀況下，
繁中版會顯示**准許停戰**的台詞——**答非所問**。

> 這一則是全量掃描才看得到的：手工抽樣不會剛好抽到相鄰兩則去並排，
> 而單看任何一則都像「翻得比較自由」。

### 這一項的可信度

只驗**變數標記**，不驗文意。所以：

- 12 則是**下限**不是全部——文意層面的缺陷（漏名詞、語氣走樣）掃不出來；
- 反過來，掃出來的 12 則**幾乎確定有問題**，因為變數是機器插入的，
  兩版的插入點集合沒有理由不同。

先前手工找的 15 則裡「漏變數 6、變數換號 1」正好被這一輪全量涵蓋並補上
（漏變數實際是 6 則、換號 2 則）。
