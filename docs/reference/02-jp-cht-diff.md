## 1. 為什麼這條線這麼便宜

PC-98 日文原版與松崗繁中版的 `TALK.DAT` **索引完全一一對應**——
同一個索引就是同一則訊息的兩種語言。**不需要做句子對齊**，
`talkdat.py diff` 直接就能跑出差異。

這是 §3.10（`CLAUDE.md`）「23 檔 byte-for-byte 相同」那條發現的延伸：

### 2.1 中文漏掉變數，台詞變成沒有主詞（6 則）

`#718`、`#720`、`#721`、`#723`、`#724`、`#751`

```
中  才剛要開始呢！覺悟吧 ／ ！！！！

```

```
中  {6}沒什麼！我可不會這樣 ／ 就輸的！
```

`{1}`，成為「沒什麼！我{1}可不會這樣就輸的！」。這個插入位置是強證據而非

## 9. ⭐ 全量對照：變數標記（2026-08-08）

先前的手工清單是**人工**找出來的。變數標記這一項可以機械化——
它不需要懂日文，只要比「兩版用到的 `{n}` 集合一不一樣」：

```
tools/py.sh tools/talkdat.py diff \
    workplace/orig/pc98/TALK.DAT shift_jis \
    workplace/orig/dosv/TALK.DAT cp950
```

**1,022 則全掃，12 則不一致。** 分成三類：

### ① 漏掉變數（6 則）——會顯示成缺主詞的句子

| # | 日文 | 繁中 | 漏掉 |
|---|---|---|---|
| 290 | 引続き**{2}**の内政を行います | 那麼我就繼續進行內政了 | `{2}`（據點名） |
| 718, 720, 721, 723, 724 | **{1}**覚悟！！！！ | 才剛要開始呢！覺悟吧！！！！ | `{1}`（武將名） |

⚠ 718/720/721/723/724 **五則內容完全相同**——那是同一句台詞的五個槽位
（不同戰況各一份）。松崗五則都漏了同一個變數，**是系統性的，不是筆誤**。

### ② 變數換號（2 則）——會插進錯的名字

| # | 日文 | 繁中 |
|---|---|---|
| 223 | **{4}**殿ならばきっと協力してくれる | 這是好提案！**{3}**大人必定會出力協助 |
| 322 | 金**{6}{7}**程かかりますが | 約需金額**{7}**左右 |

322 同時是換號與漏字：日文的金額是 `{6}{7}` 兩段，繁中只留 `{7}`。
321 是同一組訊息的另一則，漏的是開頭的 `{6}`。

`#321` 不會出現在上面的「標記集合」12 則裡：日文與繁中都仍含 `{6}`、`{7}`，
但日文有兩個 `{6}`、繁中只有一個，集合比較看不出**重複次數**。formatter 的
IDA 證據已證實 `{6}` 會消耗一個參數，因此這不是可省略的排版差異；校訂已寫入
`translations/corrections.json`。

### ③ ⚠ 兩則根本不是同一句（192、195）

| # | 日文 | 繁中 |
|---|---|---|
| 192 | 他国と交戦中？そのような報告は入っておらぬぞ！ | 現在停戰的話，就能賣個人情給{3}吧，好，准許停戰 |
| 195 | うむ、今ならば{3}も断りはしまい。よし停戦を許可する！ | 事到如今，不答應也不行了，停戰就停戰吧！ |

**校訂前的錯位只發生在 `#192`–`#195`，到 `#196` 自己接回去**——不是整段偏移。
把 `#188`–`#199` 兩版並排就看得出來：

| # | 日文 | 繁中 |
|---|---|---|
| 190 | 他国と交戦中？ | 正和他國交戰？ ✅ |
| 191 | 他国と交戦中だと？ | 你說正和他國交戰？ ✅ |
| **192** | 他国と交戦中？（**第三份**） | **現在停戰的話…**（＝ 日文 193） |
| 193 | 今、停戦すれば{3}に借りを作れる | 嗯，現在的話，{3}也不至於拒絕（＝ 日文 195） |
| 194 | 同上 | 同上 |
| **195** | うむ、今ならば{3}も断りはしまい | 事到如今，不答應也不行了（**沒有對應的日文**） |
| 196 | 他国と交戦中ならば… | 若是正在和他國交戰的話… ✅ 接回去了 |

### 原因：兩版的**重複槽位數不同**

日文這一段是「同一句話放好幾份」的結構（不同狀況各一份）：

```
日文：交戰 ×3（190,191,192）　停戰A ×2（193,194）　停戰B ×1（195）
繁中：交戰 ×2（190,191）　　　停戰A ×1（192）　　　停戰B ×2（193,194）＋1（195）
```

**松崗把重複的份數重新分配了**（3+2+1 → 2+1+2+1），
於是從 `#192` 起錯開一格，到重複結束的 `#196` 自然對回。

### ✅ IDA 已證實直取規則

`sub_13C99` 的 `add cx, ax` 直接把變體索引加到訊息基底，後續呼叫
`sub_1075B` 顯示該槽位；因此遊戲確實按槽位編號取訊息。在「對方正與他國
交戰」的狀況下，校訂前的繁中版會顯示**准許停戰**的台詞——**答非所問**。

> 這一則是全量掃描才看得到的：手工抽樣不會剛好抽到相鄰兩則去並排，
> 而單看任何一則都像「翻得比較自由」。

### 這一項的可信度

只驗**變數標記**，不驗文意。所以：

- 12 則是**下限**不是全部——文意層面的缺陷（漏名詞、語氣走樣）掃不出來；
- 反過來，掃出來的 12 則**幾乎確定有問題**，因為變數是機器插入的，
  兩版的插入點集合沒有理由不同。

先前手工清單裡「漏變數 6、變數換號 1」正好被這一輪全量涵蓋並補上
（漏變數實際是 6 則、換號 2 則）。

`corrections.json`，不符就 fail-closed；輸出是新的 JSON，不會覆寫原版 `TALK.DAT`。

的可重現估算，行數變更仍要做畫面抽樣，不能當成原版排版 parity。

```sh
tools/py.sh tools/talkdat.py correct \
  translations/extract/talk-dosv.json translations/corrections.json \
  /tmp/talk-dosv-corrected.json
tools/py.sh tools/talkdat.py build /tmp/talk-dosv-corrected.json cp950 \
  /tmp/TALK-corrected.DAT
```

本批目前可套用 16 筆，`#192`–`#195` 的槽位、`#257/#258` 的內容對調與 `#751` 的變數插入
均已定案；M7 文意層的 1,022 則逐句審查與畫面抽樣仍未完成。

`-talk-json translations/talk-dosv-corrected.json` 載入它；`-talk-json ""` 才會明確回到 raw
`TALK.DAT`。`internal/assets/text.LoadJSON` 只在呈現層把 UTF-8 行編回 cp950 `Part`，不會
改寫 `workplace/orig/` 或取代 raw `Parse` 的 byte-for-byte round-trip。

`tools/talkdat_selftest.py` 會將暫時重建的 JSON 與這個版控檔逐 byte 比對，再做校訂後
`TALK.DAT` round-trip；因此 60 筆已定案 fix 的資料來源與遊戲載入物保持一致。工具仍會報出
行數／行寬變更警告（例如 11 格行），這些警告要等畫面抽樣與原版排版證據後才能收斂，不能
當成已完成的 PC-98 formatter／翻頁 parity。

## 14. ⚠ `#406` 之後不能單獨判讀（2026-08-13）

`sub_1075B` 對索引 ≥ `0x196`（406）的訊息做 ×8 展開：真正的索引是
`0x196 + (索引 − 0x196) × 8 + ah`，也就是**八格一組，由呼叫端的 `ah` 選一個**
（機制與證據見 [`../re/25-message-variants-and-personnel.md`](../re/25-message-variants-and-personnel.md) §1）。

同一組的八則是**同一個情境的八種說法**，由武將記錄 `+0x1E` 決定用哪一種。
所以判斷一則譯得對不對，要連同同組另外七則一起看——只看一則會漏掉：

- 這一組整體的語氣範圍（從恭敬到不情願）
- 同組是否已有相同譯法（八則譯成同一句就等於失去變化）
- `{N}` 變數在同組其他則的用法（插入位置的最強旁證）
