# 05 — 松崗版的中文字型是倚天字型

**狀態：confirmed。`END_S14.DAT` 與倚天 `ascfont.15` byte-for-byte 相同；
`END_S13.DAT` 的漢字區與倚天 `stdfont.15` 逐 byte 相同。**

- 日期：2026-08-13
- 範圍：松崗 DOS/V 繁中版。PC-98 日文版不適用（靠字型 ROM）
- 方法：`docs/re/29` 解出取字模常式的索引式後，照式子取字模去比對倚天字庫
- 對照樣本：倚天中文系統 3.53（`ET353S.iso`）解出的 `stdfont.15`（392,820 B）
  與 `ascfont.15`（3,840 B）

技術鏈在 [`../re/29-font-service-int15.md`](../re/29-font-service-int15.md)。
這一份只講「字型是誰的」以及這件事證明了什麼。

## 1. 證據

### 半形：完全相同

```
END_S14.DAT   3,840 B  SHA-256 1d0cf09d0a319a9e…
ascfont.15    3,840 B  SHA-256 1d0cf09d0a319a9e…
→ byte-for-byte 相同
```

256 個字 × 15 B（8×15 點陣）。**連檔案長度都沒改**，就是原封不動搬過來換個檔名。

### 全形：漢字區完全相同，前面補了符號區

```
END_S13.DAT[0     : 12240]  = 408 格符號區字模（來源不是 stdfont.15）
END_S13.DAT[12240 :      ] = stdfont.15[0 : 392752]     ← 逐 byte 相同
                             stdfont.15 尾端 68 B（2.3 格）未收進來
```

`12240 = 408 × 30`。而 **408 正是 `STR.EXE` 取字模常式索引式第二段的基底**
（`ax = (ch-0xA4) × 157 + 408`）。組語裡的一個立即值，和兩個字型檔對齊之後
算出來的偏移量，是同一個數字——**兩個獨立來源給出同一個答案才算對上**。

倚天 `stdfont.15` 本來就從 `0xA440`（Big5 漢字區起點）開始，
松崗只要在前面補上 408 格符號字模，索引就直接對齊整個 Big5。

十五個抽樣字（一國龍虎牢關君主軍師資金稅率兵）照索引式取出的 30 B 字模，
在 `stdfont.15` 裡全部找得到，**序號一律差 −408**，零例外。

## 2. 這件事說明了什麼

**一、中文化的工具鏈血緣。**
`INSTALL.EXE`、`LOGO.EXE`、`YNFONT.EXE` 三支都引用
`STDFONT.24`／`ASCFONT.24`／`ASCFONT.15`——全是倚天中文系統的檔名。
松崗做這款中文化時，整套字型基礎設施就是倚天那一套；
`END_S13/S14.DAT` 只是把它換了個檔名塞進遊戲資料夾，
好讓玩家不必先裝倚天也能看到中文。

**二、字高 15 不是 16 的原因在這裡。**
DOS/V 的字型服務介面宣告的是 8×16 與 16×16（`sub_1F720` 傳 `DX=0x0810`／`0x1010`），
但實際檔案每個字只有 15 列，第 16 列由取字模常式補 0。
**因為倚天的 `.15` 字庫本來就是 15 列的。** 松崗把一套倚天規格的字型
接到 DOS/V 規格的介面上，接縫就留在那一列空白裡。
remake 的行距若照 16×16 設計，會與原版差一列——這一點記在 `../re/29` §8。

**三、改名是為了避開結局播放器。**
`D7END.EXE` 的字串表是 `END_S1..S12.DAT`，把字型放進 `END_S13/S14`
剛好躲開結局圖的編號範圍。**但 `STR.EXE` 裡寫死的檔名是 `END_S10/S11`**——
那兩個編號正好還在結局圖範圍內，也確實被結局圖佔著。
這個矛盾還沒裁決（`../re/29` §6），但它暗示字型檔的編號**改過至少一次**。

## 3. 對本專案的約束

`END_S13.DAT`／`END_S14.DAT` 是**倚天字型的衍生物**，
CLAUDE.md §9 的「不得散布倚天字型」對它們一樣適用。
`tools/denylist.py` 已經三層擋住（副檔名、原版檔案的內容雜湊、倚天檔名），
不必另外加規則——但**不要因為它叫 `END_S13.DAT` 就以為它是遊戲資料**。

remake 走自己的字型路徑（`internal/assets/cjk`，`-font` 由玩家指定），
不依賴也不散布任何倚天字庫。

## 4. 順帶推翻的

| 原斷言 | 現況 |
|---|---|
| `YNFONT.EXE` 自帶中文字型 | 字型在 `END_S13/S14.DAT`，`YNFONT.EXE` 全檔 `INT 15h` 出現 0 次 |
| `END_S13/S14/S15` 是中文版加的結局段 | S13／S14 是字型。**`END_S15` 仍未解** |
| `STR.EXE` 是過場播放器 | 是 DOS/V 字型服務 TSR |

三條都源自同一個推論方式：**看檔名、看誰顯示中文，而不是看誰讀那份資料**。
