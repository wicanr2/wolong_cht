`YNVSHELL.COM` 內含這串 8.3 補空格的檔名表，就是它要依序叫起的程式：

```
YNFONT  .EXE   STR     .EXE   YNSOUND .COM   LOGO    .EXE
```

### 2.2 編譯器：三支確定，四支未解

`LOGO.EXE`／`YNFONT.EXE`／`INSTALL.EXE` 都有
`Borland C++ - Copyright 1991 Borland Intl.` banner。
**`KI.EXE`、`STR.EXE`、`D7OPEN/END/OVER.EXE` 沒有這個 banner**，
也沒有 PKLITE／LZEXE 指紋。可能是組語寫的、或編譯選項不同。
**未解，不要憑「同一份專案應該用同一個編譯器」外推。**

### 2.3 `SINARIO.DAT` 與 `SAVE.DAT` 同一結構（強證據）

兩者**大小完全相同：88,832 B**，`cmp -l` 只差 12,566 個 byte。
`SINARIO.DAT` 位移 `0x40` 起是 Big5 的「第一章」「呂布歸天」。

> **推論**：`SINARIO.DAT` 是初始劇本存檔，`SAVE.DAT` 是玩家存檔，同一份 layout。
> 這對 remake 很划算——**兩份檔案 diff 就能定位欄位**，
> 不必先把整個存檔結構讀懂。

`SAVE.DAT` 裡已經看得到 Big5 據點名：
氾水關（`0x1022`）、函谷關（`0x1142`）、虎牢關（`0x11c2`）、五丈原（`0x1222`）、
陽平關（`0x1482`）、白水關（`0x1502`）、葭萌關（`0x15a2`）、濡須口（`0x18e2`）。
間距不固定（`0x80`／`0x60`／`0xa0`／`0x260` 都出現過）——
**不要急著斷定記錄長度**，先把 192 個城池全掃出來再看分佈。

### 2.4 即時制：`KI.EXE` 裡的 Big5 UI 詞已經洩漏了系統輪廓

`KI.EXE` 位移 `0x18xx`–`0x1axx` 是一段 Big5 明文的介面詞表，照原序：

```
君主 首都 軍師 信賴度 資金 預備兵 資金 收入 支出 今月底 次月 稅率 徵兵數
資料儲存 畫面模式 戰略速度 戰術速度 遊戲結束
城兵數 生產力 上昇值 防災值
將軍 君主 首都 總兵力 士氣值
主將 前鋒 左翼 右翼 左備 右備 預備兵數
君主 軍師 武將數 據點數 自定 確定 軍師名 重來 繼續 上一頁 下一頁
```

三條**強證據**（還沒到 confirmed，要在反組譯裡驗）：

1. **`戰略速度` 與 `戰術速度` 是兩個獨立設定** → 大地圖與戰場各有各的時間流速，
   佐證維基說的即時制。**remake 的規則層要以 tick 為單位設計，不是回合。**
2. **部隊編成有六個位置**：主將／前鋒／左翼／右翼／左備／右備，
   外加預備兵數。這與部落格說的「依陣型對戰」對得上。
3. **經濟欄位**：資金、收入、支出、稅率、徵兵數、生產力、上昇值、防災值
   → 有內政循環與月結（`今月底`／`次月`）。

`防災值` 這個詞值得單獨追——**代表有天災事件**，這在攻略裡沒被提到。

#### 日文說明書已 confirmed 的四項（第 3.5 節「システムウインドウ」，PDF p.14）

| 項目 | 原文 | 定案 |
|---|---|---|
| データセーブ | 「4カ所のどこにでもセーブが可能」 | **存檔槽是 4 個** |
| 画面モード | 「アナログカラーと8階調液晶とを切り替えます」 | PC-98 的類比彩色 ↔ **8 階調液晶**（筆電）。`KI.EXE` 的「畫面模式」就是這個 |
| サウンド | 「BGMのストップとFM音源とSSG音源のバランスを変更します」 | **音源是 FM ＋ SSG**（PC-98 的 YM2203／OPN），見 §3.9 |
| 戦略速度 | 「選択されている速度が機械の速度を超えるといくら速い速度を設定してもそれ以上速くなりません」 | **原版沒有固定 tick rate**，速度上限跟著機器跑 |

> **⭐ 最後一項對 remake 是硬約束。** 原版的「即時」是「跑多快算多快」，
> 不是每秒固定 N tick。直接照抄會得到一個在現代機器上快到不能玩的遊戲。
> remake 必須自己定義一個固定時間基準，**並把它明確標記為 remake 差異**，
> 同時記錄原版在什麼機器上大約是什麼速度（`docs/mechanics/15-realtime.md`）。

### 2.5 `TALK.DAT` 訊息表：**已全解，READY**

完整規格見 **[`docs/formats/01-talk-dat.md`](../formats/01-talk-dat.md)**。
兩版都 byte-for-byte round-trip 通過（`tools/talkdat.py`）。

```
0x000–0x7FF  1024 筆 uint16 LE 偏移表（[1022] 是哨兵，[1023] 未使用）
0x800–       1,022 則訊息，每則是若干個 NUL 結尾的行
變數插入     ASCII `\1` `\2` `\3` `\4` `\6` `\7` 六種（沒有 \5）
編碼         dosv 用 cp950、pc98 用 cp932
```

**兩版索引一一對應**，同一個索引就是同一則訊息的兩種語言 →
日中對照表已經產出，第一批發現見
[`docs/reference/02-jp-cht-diff.md`](./02-jp-cht-diff.md)。

#### 三個踩過的坑，寫死在這裡

1. **不能用 regex 找 `\N`。** Big5 與 Shift-JIS 的**第二個 byte 都可能是 `0x5C`**，
   regex 會把中文字切一半。必須逐字掃描。
2. **不能用 `big5`／`shift_jis`，要用 `cp950`／`cp932`。**
   前者解不開 `F9D8`（「裏」），會讓人誤判成原版錯字。
   **宣告原版有錯之前，先確認自己的工具是對的。**
3. **訊息結尾的空行是資料。** 有的訊息沒有、有的有兩個。
   把它「正規化」掉就寫不回去了。

> **⚠ 推翻紀錄見 `CONTEXT.md` §6**（訊息的變數插入機制）。
> 教訓：**用「掃描掃出一堆短片段」反推機制是間接證據。**
> 結論碰巧對，不代表推導過程站得住——格式要從讀取它的程式碼定案。

### 2.6 中文字型

`KI.EXE` 用 DOS/V 的 `INT 15h AH=50h` 向常駐服務要字模，服務由 `STR.EXE`
（916 B 的 TSR，`"DOSV"` 簽章）提供，字模來自 `END_S13.DAT`（全形 16×15）
與 `END_S14.DAT`（半形 8×15，與倚天 `ascfont.15` byte-for-byte 相同）。
玩家不必自備 `STDFONT.24`／`ASCFONT.24`／`ASCFONT.15`——那三個檔名只出現在
`INSTALL.EXE`／`LOGO.EXE`／`YNFONT.EXE`，是轉檔或 fallback 路徑。
全鏈見 [`../re/29-font-service-int15.md`](../re/29-font-service-int15.md)。

兩版的字型架構差異：

| | PC-98 日文版 | 松崗 DOS/V 版 |
|---|---|---|
| 字型程式 | `YNFONT.COM` **843 B** | `YNFONT.EXE` **60,888 B** ＋ `STR.EXE` 916 B |
| 字型資料 | `FONTGRF.DAT` 1,216 B | `END_S13.DAT` 404,992 B ＋ `END_S14.DAT` 3,840 B |
| 存取方式 | 字型 ROM | `INT 15h AH=50h` |

PC-98 有字型 ROM，843 B 的驅動加 1,216 B 的特殊字圖就夠；DOS/V 沒有 ROM，
所以整套字型連同存取服務都要自己帶。`YNFONT.EXE` 不走 `INT 15h`
（全檔 0 次），它畫防拷畫面的那條路徑仍未解，與本鏈無關。

remake 走自己的字型路徑（`internal/assets/cjk`，`-font` 指定）。
**倚天字型不隨本專案散布**，`END_S13.DAT` 是倚天字型的衍生物，同樣適用。

### 2.7 圖像與調色盤

`.BRG` 調色盤四個，都是 3 byte 一組：

| 檔案 | 大小 | 色數 |
|---|---|---|
| `GAMEPAL.BRG` | 384 | 128 |
| `OPENPAL.BRG` | 288 | 96 |
| `ENDPAL.BRG` | 576 | 192 |
| `OVERPAL.BRG` | 48 | 16 |

觀察到的通道值域是 `0x00`–`0x0f`（4 bit）。
`OVERPAL` 的前 16 byte 與 `GAMEPAL` 相同、`OPENPAL` 的前 16 byte 與 `ENDPAL` 相同
→ **強證據**：這些調色盤共用同一組色序，短的是長的前綴。

**假說**：副檔名 `BRG` 就是通道順序 **B, R, G**。
拿一張已解的圖用兩種順序畫出來，跟 DOSBox 截圖比對就能定案——**先驗再用**。

圖庫四個：

| 檔案 | 大小 | 推測 |
|---|---|---|
| `KAOGRF.DAT` | 307,200 | 頭像（日文「顔」）。**假說**：307,200 ÷ 2,048 = **150 張 64×64 4bpp**，而武將 146 人 + 4 → 對得起來，但**這是算術巧合等級的證據，要驗** |
| `IVENTGRF.DAT` | 76,032 | 事件圖（`IVENT` 是 `EVENT` 的拼法） |
| `KYOGRF.DAT` | 69,120 | 未解 |
| `ICONGRF.DAT` | 47,776 | 圖示 |

### 2.8 地圖族：`.MAP` / `.MDL` / `.SCH` / `.MCH`

```
BATTLE.MAP  877,056    BATTLE.MDL  194,560    BATTLE.SCH  115,200   BATTLE.DAT  8,192
MMAP.MAP     80,716    MMAP.MDL     32,768    MMAP.MCH     43,058
PASS.MAP     32,594    PASS.SCH     14,281
MOUSE.MCH       588    MOUSE.SCH       864
INSTALL.MAP  30,831    INSTALL.SCH  11,041
```

`MMAP` = 大地圖（main map）、`BATTLE` = 戰場、`PASS` = 關隘、`MOUSE` = 游標。
**同一組副檔名跨四個用途重複出現 → 這是四種通用容器格式，不是四個一次性檔案。**
解通一個就解通全部，優先度很高。

> **⚠ `file(1)` 對 `INSTALL.MAP`／`INSTALL.SCH`／`PASS.*`／`MOUSE.*` 報
> 「Atari DEGAS Elite bitmap 640×400」——那是 magic 誤判，不是線索。**
> DEGAS 的 magic 只是開頭一個 0/1/2 的 word，這批檔案剛好也以小數字開頭。
> 別拿它當「640×400」的證據。

### 2.9 音訊

`BGM.DAT` 20,826、`OPENBGM.DAT` 3,424、`ENDBGM.DAT` 2,218、`OVERBGM.DAT` 684、
`SOUND.DAT` 304。加上 `YNSOUND.COM`（3,463 B，疑似 TSR）。

**PC-98 側的音源已由日文說明書定案：FM 音源 ＋ SSG 音源**
（第 3.5 節「サウンド」，§2）。那就是 PC-98 標準的 **YM2203／OPN**——
FM 3 聲 ＋ SSG 3 聲，埠 `0x188`／`0x18A`。

**DOS/V 側未解。** `dosbox.conf` 開了 `sb16` 與 `oplmode=auto`，
但那是打包者的設定，不是原版需求。
候選：AdLib／OPL2（`0x388`／`0x389`）、SB（`0x220` 族）、PC speaker。

> **⚠ 這是「不要跨檔案外推」（§8 第 9 條）的教科書案例。**
> 兩版的 `YNSOUND.COM` 大小不同（3,463 B ↔ 4,553 B），
> 五個 `*BGM.DAT`／`SOUND.DAT` **每一個都大小不同**——
> 音訊是兩版差異最大的一塊。**PC-98 是 OPN 不代表 DOS/V 也是。**
> DOS/V 的音源要自己從 `KI.EXE`／`YNSOUND.COM` 找 I/O 埠寫入來定案。
>
> 但 OPN 與 OPL 同屬 Yamaha FM 家族，**樂曲資料很可能同源**——
> 先比對兩版 `BGM.DAT`（20,790 ↔ 20,826，只差 36 B）的結構，
> 這是最省力的切入點。

### 2.10 PC-98 日文原版：`[HARD]` 這是本專案最重要的一項資產

使用者提供了 **PC-98 版的五片磁片映像**（`.fdi`，各 1,265,664 B
＝ 4,096 B 檔頭 ＋ 1232 KB 2HD 裸映像）。已全部抽檔完成，工具是
`tools/fdi_extract.py`（只用標準函式庫，不裝套件）。

磁片是 **FAT12，1024 byte/sector**，只有開機磁區的 OEM 欄位被換掉：
A／B 片是 `FGDOS1.0`（自製載入器，boot sector 內有
`* FGDOS Ver 1.00 Loading module version 1.2 * Copyright(C)1993`），
C／D 片是 `YN  1.00`，E 片是 `NEC  5.0`（原廠 MS-DOS 5.0 系統片）。

| 片 | 內容 |
|---|---|
| A | 遊戲本體：`KI.EXE`、`MMAP.*`、`KAOGRF`／`ICONGRF`、`SINARIO`／`SAVE`、`TALK.DAT`、`YN*` 工具鏈 |
| B | 開場：`D7OPEN.EXE`、`OPEN_S1..S6.DAT`、`ROGO.EXE`／`ROGO0`／`ROGO1` |
| C | 戰場與音樂：`BATTLE.MAP/MDL`、`BGM.DAT`、`SOUND.DAT`、`IVENTGRF`、`KYOGRF` |
| D | 結局：`D7END.EXE`、`END_S1..S12.DAT`、`HDINST.EXE`（硬碟安裝） |
| E | MS-DOS 5.0 系統片 |

#### ⭐ 23 個檔在兩版之間 byte-for-byte 完全相同

```
BATTLE.MAP  BATTLE.MDL  BATTLE.SCH        ← 戰場三件全套
MMAP.MAP    MMAP.MDL    MMAP.MCH          ← 大地圖三件全套
KAOGRF.DAT  KYOGRF.DAT  ICONGRF.DAT  IVENTGRF.DAT   ← 四個圖庫全部
GAMEPAL.BRG  OPENPAL.BRG  ENDPAL.BRG  OVERPAL.BRG   ← 四個調色盤全部
OPEN_S1..S6.DAT                           ← 整段開場動畫
END_S1.DAT  END_S2.DAT  END_S12.DAT
```

**推論（強證據）**：松崗版是移植不是重寫，資料檔原封不動搬過去。
**這對專案是三個層級的好消息**：

1. **圖像、地圖、調色盤格式解一次通吃兩版。** 而且 PC-98 是 640×400
   的固定規格，比 DOS/V 那邊少一層猜測——**格式反推從 PC-98 側入手更省事**。
2. **哪些素材裡燒了文字，diff 直接告訴你。** `END_S3`–`END_S11` 兩版大小全不同、
   `END_S1`／`S2`／`S12` 完全相同 → **那九張結局過場的圖裡燒了日文，
   中文版重繪過**；開場 `OPEN_S1..S6` 六張全相同 →
   **開場沒有燒字，文字是疊繪上去的**。這是一個免費的「燒字偵測器」，
   省掉逐張目視檢查。
3. **松崗版多了 `END_S13`／`S14`／`S15`**（PC-98 只到 `S12`）→
   中文版動過結局段。**這是 remake 必須查清楚的差異**，不能默默選一邊。

#### 大小相同但內容不同的三個：最好的 diff 對象

`BATTLE.DAT`（8,192）、`SAVE.DAT`（88,832）、`SINARIO.DAT`（88,832）。
**結構相同、內容不同 → 兩版逐 byte diff 就能定位「哪些欄位是字串」**，
不必先把整份結構讀懂。`SINARIO.DAT` 兩版 diff 尤其划算：
同一個劇本、同一份初始狀態，差的只有語言。

#### 只在單邊存在的檔

| 只在 PC-98 | 意義 |
|---|---|
| `FGDOS.SYS`／`STARTUP.SYS`／`CCP.EXE`／`STARTUP.CMD` | 自製 DOS。**防拷的候選位置，M0 要查**（§3.11） |
| `FONTGRF.DAT`（1,216 B）／`YNFONT.COM`（843 B） | 字型（§3.6 已解） |
| `YNMOUSE.COM`／`YNSHELL.COM` | `YN*` 工具鏈；DOS/V 版是 `YNVSHELL.COM` |
| `ROGO.EXE`／`ROGO0.DAT`／`ROGO1.DAT` | 開機 logo（「ロゴ」的羅馬字）；DOS/V 版換成 `LOGO.EXE` |
| `HDINST.EXE` | 硬碟安裝 |

| 只在松崗 DOS/V | 意義 |
|---|---|
| `END_S13/S14/S15.DAT` | 中文版加的結局段 |
| `PASS.MAP`／`PASS.SCH`／`MOUSE.MCH`／`MOUSE.SCH` | **PC-98 沒有**。關隘與游標，移植時新增或改名 |
| `INSTALL.EXE`／`INSTALL.MAP`／`INSTALL.SCH`／`SHOW.O`／`STR.EXE`／`LOGO.EXE`／`YNFONT.EXE` | 移植方（松崗）自己寫的安裝與外殼 |
| `DISK1`–`DISK4`／`LABEL.$$$`／`PLAY.BAT` | 磁片標記 |

> **⚠ `YN` 是開發方的工具鏈前綴**（`YNSHELL`／`YNFONT`／`YNSOUND`／`YNMOUSE`），
> 兩版都有。NEO･GETEN 的其他作品可能共用同一套——查到別的作品時，
> 這組檔名是最好的比對特徵。

#### 反組譯：兩版都已進 IDA

```
workplace/ida/dosv/KI.EXE.i64   松崗繁中版  67,099 B  732 函式
                                sha256 fffeba98…3868
workplace/ida/pc98/KI.EXE.i64   PC-98 日文版 65,823 B  725 函式
                                sha256 061917f9…81e8
```

兩版載入位址都是 `10000h–2041Bh`。函式數只差 7 →
**同一份原始碼的兩次編譯**（強證據）。
**兩版對照本身就是一種 oracle**：某段程式碼在兩版都存在且相同，
代表那是遊戲邏輯；只在單邊存在的，多半是平台相關的繪圖／字型／音源。
