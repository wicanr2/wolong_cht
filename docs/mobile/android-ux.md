# Android UX 規格

**狀態：主畫面、四個入口、進言流程與戰場都已實作。** 手機版**不照原版版面**，
只共用規則層（決定與理由見 [`android-plan.md`](android-plan.md) §1）。

- 日期：2026-08-20
- 前提：橫向、`minSdk 29`、只有 Docker 模擬器可驗
- 實作：`internal/ui/phone`（版面、面板、進言、存讀檔）、`mobile/wolong`（平台殼）
- 驗收：`tools/phone_shot.sh`（桌面截圖，約 30 秒一輪）、`tools/android_smoke.sh`（模擬器）

## 1. 設計前提

原版是 **640×400 的滑鼠式視窗 UI**：命令列一格 16×16、一覽表一列 16 px 高、
戰場的兵一格 16×16。這些熱區在 5 吋螢幕上約 2–3 mm，**手指按不準**。
所以手機版重畫版面，但有三條不能動：

| 不能動的 | 為什麼 |
|---|---|
| 規則層 | 時鐘、事件、數值、存檔格式一律共用；便利操作只能在輸入層做 |
| 原版美術 | 地圖圖塊、人物、戰場子圖塊、肖像全部沿用原版解碼結果 |
| 原版文字 | `TALK.DAT` 的 1,022 則與校訂表共用，不另寫手機文案 |
| **介面配色與外框** | 底色查 `GAMEPAL.BRG`、外框是 `ICONGRF.DAT` 的 8×8 圖塊，都走 `internal/ui/chrome`（[`../spec/70`](../spec/70-phone-chrome.md)）|

哪一塊算原版的哪一種視窗：狀態列與指令列是**命令列**（色 0 純黑，沒有龍紋）、
一覽與選對象是**清單視窗**（米色底黑字）、小卡與對白與擋住世界的決定是
**選單／情報視窗**（深藍 ＋ 龍紋、白字）、選中的一列是**反白條**（色 5）。

⭐ **重畫的是「怎麼擺、怎麼按」，不是「畫什麼」。**

## 2. 主畫面

```
┌──────────────────────────────────────────────┐
│ ☰  196年4月2日  午  ▶▶     資金 12,340  兵 8,200 │  56 dp 狀態列
├──────────────────────────────────────────────┤
│                                              │
│                                              │
│            大地圖（原版圖塊，可縮放拖曳）           │
│                                              │
│                        ╔════════╗            │
│                        ║ 選中的據點 ║            │  點一下→浮出小卡
│                        ╚════════╝            │
├──────────────────────────────────────────────┤
│  ⊕ 進言    ⊞ 一覽    ⚔ 軍團    ⚙ 系統          │  64 dp 指令列
└──────────────────────────────────────────────┘
```

| 區 | 高度 | 內容 |
|---|---|---|
| 狀態列 | 56 dp | 選單鍵、日期與時辰、速度、資金、預備兵。⚠ 全部是**唯讀顯示**，點資金不會開撥款 |
| 主區 | 其餘 | 大地圖或全螢幕 sheet |
| 指令列 | 64 dp | 四個主入口，各自 ≥ 48×48 dp |

安全區（瀏海、手勢列）由 Java 側取得後傳進 Go；**互動元件不得落在安全區外**。

## 3. 大地圖的操作

原版大地圖是 384×256 格、每格 16×16 px。手機上：

| 手勢 | 行為 |
|---|---|
| 單指拖曳 | 平移 |
| 雙指捏合 | 縮放，**只允許整數倍**（1×／2×／3×）——非整數會讓點陣圖糊掉 |
| 點一下據點 | 浮出資訊小卡（名稱、歸屬、生產力、城兵）＋ 該據點可做的事 |
| 點一下軍團 | 同上，小卡換成軍團欄位 |
| 點空白 | 收掉小卡 |
| 長按 | 不使用。⚠ 長按在 Android 上與系統手勢容易打架，而且 2026-08-11 的 `adb tap` 已經證明**瞬間 down/up 會跨幀**——長按當主要操作會讓驗收與實際手感不一致 |

⭐ **點選一律「先選中、再下令」兩段式**：第一段只改選取狀態、不動 `World`；
第二段才送指令。事件性的決定（外交、撥款）維持原版的確認框。

## 4. 指令列的四個入口

| 入口 | 開什麼 | 為什麼是主入口 |
|---|---|---|
| **進言** | 進言 sheet（五項，取自 `TALK.DAT` #77）| 玩家是軍師，這是主要動作 |
| **一覽** | 四張表（武將／據點／勢力／軍團）分頁 | 原版四個一覽表，欄位照 `docs/spec/38` |
| **軍團** | 編成 → 行軍 | 兩個步驟接在一起，原版是分開的視窗 |
| **系統** | 速度、存檔、讀檔、關於 | 對應原版系統選單 |

### 已實作的部分

| 入口 | 現況 | Go |
|---|---|---|
| 進言 | 五項齊全：三個外交提案走完整說服迴圈、遷都與請求出陣走一次驗收。對白取自 `TALK.DAT`，索引算式與桌面版共用 `persuasion.Talk*` | `internal/ui/phone/advise.go` |
| 一覽 | 武將／據點／勢力／軍團四張表，可捲；**唯讀** | `internal/ui/phone/sheet.go` |
| 軍團 | 兩頁：現有（點左半移鏡頭、右半派往地圖上選中的據點）與編成（挑武將、六個位置的兵種循環）| 同上 ＋ `corps.go` |
| 戰場 | 45 度視角、六格編成位置、六個命令、兩軍資訊與縮圖 | `battle.go` ＋ `internal/ui/isoview` |
| 系統 | 速度（原版檔位 0–4）、四個存檔槽、關於 | 同上 ＋ `save.go` |
| 事件訊息 | `TALK.DAT` 的原文，變數展開與桌面版共用 `state.TalkNoticeVars` | `notice.go` |
| 擋住世界的決定 | 遭遇（戰鬥指揮／委任）、外交提案、撥款請求。**不接的話世界會停住** | `modal.go` |

**遷都的順序與原版相反**：原版是先開選單再選城，手機上選單一開就蓋住地圖，
所以改成**先在地圖點目的地、再開進言**。那一列右邊會直接寫出要遷去哪。

**存檔槽一列有兩個動作**：左半存、右半讀，面板底下有一行寫著。
長按沒有用——它在 Android 上與系統手勢打架（§3）。

sheet 一律**全螢幕**，不做浮動小視窗——手機上小視窗的關閉鍵太小。
Android 返回鍵：`關掉 sheet → 收掉小卡 → 離開確認`，**不直接結束**。

## 5. 戰場

戰場沿用原版的 45 度視角與子圖塊（那是資產不是版面），但控制重畫：

```
┌──────────────────────────────────────────────┐
│ 攻 張遼 8,200        vs        守 夏侯惇 6,400   │
├──────────────────────────────────────────────┤
│                                              │
│          45 度戰場（原版子圖塊，可縮放）           │
│                                              │
├──────────────────────────────────────────────┤
│ 左翼 左備 主將 前鋒 右備 右翼   ← 六格，點一格選一隊 │
├──────────────────────────────────────────────┤
│  陣形  突擊  城壁  弓  退卻  就位               │  六個命令
└──────────────────────────────────────────────┘
```

- 上排六格是**編成位置**（原版底列的空間排列：左翼 左備 主將 前鋒 右備 右翼）。
- 下排是六個戰術命令。**畫面順序不是命令碼順序**：原版第 0 列送的是命令 2
  （`sub_1C863` 的熱區碼 − 7，docs/re/60 §6.1）。兩張順序表都在
  `internal/assets/battle`，與桌面版共用。
- ⚠ 即時制**不因為開著選單就暫停**——原版只有系統選單會停時間，
  手機版照這條走，不另外加暫停。

**戰場上不畫底部那四個入口。** 進言／一覽／軍團／系統在戰術畫面上本來就
不作用（原版進戰術畫面時整個畫面都換掉），而省下那 64 px 之後
**原版的 480×368 視野才塞得進來**——裁掉一截會改變玩家看得到多少戰場。
`TestBattleFieldFitsTheOriginalViewport` 守著這一條。

左右剩下的兩塊放原版側欄有的欄位：攻守雙方的主將與兵力（玩家那一側標色）、
戰場縮圖。**等角投影本身與桌面版共用**（`internal/ui/isoview`），
所以美術、深度關係、城壁破壞後的重繪三邊一致。

## 6. 文字

- 訊息框沿用 `TALK.DAT` 與現有的排版層（`internal/ui/textdraw`），
  1,022 則的行寬 guard 已經量過（[`../playtest/32`](../playtest/32-talk-layout-fit.md)）。
- 原版字型是 **16×15 點陣**；手機上只用**整數倍放大**，不做雙線性平滑，
  鋸齒用 Scale2x 補斜角（[`../spec/101`](../spec/101-phone-glyph-scale2x.md)）。
  **倍率定為 2**（使用者裁定 2026-08-28，[`../spec/100`](../spec/100-phone-text-scale.md)）：
  清單一頁 8 列、戰場六格改成「位置 兵數」一行。

## 7. 這些是 remake 差異

按 `CLAUDE.md` §1，外殼現代化要逐項標記：

| 差異 | 原版 |
|---|---|
| 版面重畫（狀態列／指令列／全螢幕 sheet）| 640×400 固定版面 ＋ 四個常駐視窗 |
| 地圖可縮放拖曳 | 固定 27×21 格視窗，靠點縮小地圖換位置 |
| 兩段式點選 | 原版滑鼠是點一下就送 |
| 戰場的六格與六命令固定在下方 | 原版在右側欄與底列 |
| 返回鍵 | 原版沒有這個鍵（ESC 取消、F10 離開）|
| 進言的對白是一列一句、靠邊分辨誰在講 | 上下兩個講話框配肖像（`docs/spec/45`）|
| 遷都先選城再開選單 | 先開選單再選城 |
| 一列兩個動作（存／讀分左右半） | 每個動作各一列 |
| 地圖上選中的據點畫**白圈**（色 15）| 原版沒有「選中的據點」這個東西。反白條的色 5 是綠的，疊在土黃城與草地上分不出來 |
| 事件訊息貼在地圖上緣、六秒自己消 | 彈出訊息框，要按鍵才消（`sub_1084A`）|
| 擋住世界的決定壓在地圖上（半透明）| 各自一個視窗 |
| 外交提案暫時沒有「指定金額」 | 三選一，含指定金額（`sub_17C6E` 的數值輸入器）|

**桌面版一項都不動**——那是對拍基準。

## 8. 第一次啟動

app 的入口是**匯入畫面**，不是遊戲：原版資料與點陣字都要使用者自備
（deny-list 的邊界對手機版一樣成立），沒有它們遊戲開不起來。

```
啟動 → 有 orig/SINARIO.DAT？ ── 有 ──→ 遊戲
                              └─ 沒有 → 選資料夾（系統的 SAF 選擇器）
                                        ↓
                                  複製進 app 私有目錄
                                  （字型自動分到 eten/）
                                        ↓
                                      遊戲
```

⚠ **Ebiten 的 view 一建起來就佔住整個視窗**，之後叫不出系統的選擇器——
所以判斷要在建 view 之前做，這也是入口是匯入畫面的理由。

## 9. 未解

| 項目 | 現況 |
|---|---|
| 點陣字在高 DPI 上要放大幾倍 | 定為 2（§6）；平板或小手機要不要另一檔，得有實機回饋 |
| 小卡要放哪些欄位 | 目前放名稱／歸屬／生產力／防災／城兵五項。原版一覽表的欄位全表在 `docs/spec/38`，還沒逐項比對過取捨 |
| 縮放的下限 | 整張大地圖 384×256 格全塞進手機會小到看不見，最小縮放級距還沒定 |
| 戰場的縮放 | 目前固定 1×（原版的 480×368 剛好塞進主區）。放大之後看得到的格子會變少，**那會改變決策**，所以沒有做 |
| 戰場縮圖的點選 | 原版點縮圖可以移動鏡頭，手機版目前只顯示 |
| 外交提案的「指定金額」 | 要數值輸入器（原版是 `sub_17C6E`，[`../re/13`](../re/13-pc98-numeric-window.md)），手機上沒做。**先不給那一項**——給了會是一個點下去什麼都不會發生的選項 |
| 事件訊息的停留時間 | 六秒是估的。原版沒有這個機制（它要按鍵才消），所以沒有可抄的數字 |
